# R762: can al-runner-v3 run faster, and does LethAL pass the wrong options? (measured 2026-10-25)

Coord task R-762, from an owner request. Binary: the pinned `current`, al-runner 3.0.0-alpha.5+edge (dcdf9e821). No BC
server was used. Raw evidence is in `/coord/handoff/R-762/` (lever1.md, covering-only.md, lever4.md, b-figures.md,
cache-proof/proof.md and proof2.md). Context: [R760](2026-10-25-r760-v3-time.md) showed the tests take milliseconds; the
time goes to cold al-runner calls and LethAL's own work between them.

## The question

The owner asked how v3 tests can run faster, and whether LethAL passes the wrong options to al-runner ("in memory it
should beat BC's NST"). The orchestrator read `al-runner test --help` and `serve` against LethAL's backend and listed
eight levers. Each was a hypothesis. This page gives the result for each.

## Short answer

LethAL was not passing a wrong option. The option the brief suspected most (`--run-selected-only`) saves nothing,
because LethAL already selects exactly the tests it wants to run. The real waste was elsewhere: the contract probe paid
every session, coverage collected on calls that never read it, and LethAL's own per-send file check. Three were built
(R764, R765, R768) and three were handed to other lanes (R766, R767, R769). Three levers were NOT measured (isolation,
threads/parallel daemons, other options).

## Covering-only ceiling

LethAL selects whole codeunits, so 264 of the gift card's 944 test runs (28%) are tests that do not cover the mutant.
Time per test is about 1.25 ms (gift card) and 1.43 ms (D1), an even split of R760's rounded per-call test time (the
reports hold no per-test times). So the non-covering tests cost about 0.33 s in a 20 s run. Even if every test were
free, the D1 total is about 5 s. Selecting only covering tests cannot be a meaningful speed-up.

## Lever 1 detail: why `--run-selected-only` has nothing to skip

- One-shot passes `--codeunit <id>`; serve passes `test: "Codeunit<id>."` (whole codeunit). So every test of the codeunit
  is selected. The option cuts execution only for tests that are selected for reporting but not for running; here there
  are none.
- `--codeunit` plus `--filter` is a union, so adding a filter would not narrow a codeunit selection either.
- BC faithfulness: bcdev runs only the enabled method. With whole-codeunit selection the option and the default run the
  same tests, so neither differs from "run the codeunit's tests". `--isolation test` is the setting that carries the
  per-test rollback (lever 2, not measured).
