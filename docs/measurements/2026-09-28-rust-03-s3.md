**The native fix this stage made, and why.** First run found one real difference: on a broken-snippet
ERROR node, `childForFieldName` returned an identifier on WASM and `null` on native. Cause (tree-sitter
0.25.10, not the grammar): the cursor's field lookup descends into hidden children and can report a
field a hidden child's production supplies, but `child_by_field_id` reads only the node's own
production field map, which is empty on an ERROR node. Fix: the addon sets a new flag,
`FLAG_FIELD_TARGET = 16`, on a child when the parent's actual `child_by_field_id` lookup returns that
exact node; `FlatNode.childForFieldName` now returns the first child carrying both the field and the
flag, matching tree-sitter's own lookup instead of a plain field-name scan. Commit `443c6d3`. Red
checks (removing the flag check on the TS side; setting the flag on every fielded child on the Rust
side) both turned the new tests red and were restored; the rebuilt addon hash matched the one the
corpora above ran on. After the fix, Q1 held with zero differences everywhere, so no AMENDMENT was
needed for Q1 itself.

## Open notes (carried forward, not blocking)

- **An unkillable WASM-side `bun` process.** During Q2's WASM-side census over
  `fixtures/sandbox-coverage-probe`, the `bun.exe` process finished its JSON output but never exited
  (one thread, no CPU; `taskkill` and `Stop-Process` both reported it gone while `Win32_Process`
  still listed the PID). Killing the waiting shell and re-running produced a byte-identical JSON
  (`cmp`), which is the file used in the Q2 numbers above. Native never did this. It may be the same
  shape as S1.3's unexplained `bun -e` hang, also under WASM.
- **The reference capture harness's `childForFieldName` is a first-child field-name scan**, which
  S3.1 found is not what tree-sitter's own lookup does on an ERROR node (the `FLAG_FIELD_TARGET`
  fix above). Every listing in Q1 and Q2 still matched, including whole BaseApp, so no
  spec-generation path on these corpora hit the difference; if a later corpus differs on an ERROR
  node, suspect the reference instrument first, not the native side.
