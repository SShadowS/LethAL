## Decided: what is kept, and what is not
- **Kept, if their checks pass:** F1b (two exact rows, one per report name), F2 (one exact row, 1044 only) and F3 (one exact
  row). That covers 24 of the 34 restarts.
  - Each of these texts is met only under a mutant, never at baseline. So no baseline cut, left-out run or tail route
    moves: `refusedCut`, `leftOutRows` and the R1007 stability pass read baseline rows only.
- **What a row changes (review S1; v1's sentence was wrong):**
  - (a) the daemon stays alive for the requests after the refusing one;
  - (b) the later ENTRIES of the same request now stand on the daemon that refused. Today `requestOne` cuts there, and
    re-sends them on a fresh daemon.
  - The drift guard (`keptRefusalDrift`) checks (a) only, the next request. PR-56's spec records that gap.
  - On DO, (b) is the main shape: 6 of F2's 8 closes were in prefetch requests of 108 to 252 entries. So the check below
    measures (b) directly.
- **Not kept here: F1a** (11 restarts, about 435 s).
  - Its text carries upstream corpus paths with line numbers ("Nearest measured rows differ in: …"). An exact row would break
    on any upstream corpus edit, and a slot over that tail would be a broad pattern. PR-365 left it for the same reason.
  - (v1's other reason, that keeping it would move 68874's cut-mutant routes, was wrong (review L1): the cut would only move
    from the F1a test to the next unkept refusal in 68874. It is withdrawn.)
  - Recorded in R1205 as its own item.
- **Not keepable by nature (R1205), left as they are:**
  - `a test before this one in the codeunit did not pass ... and left ...`;
  - `an earlier test of this codeunit was refused while it ran`.
  - Each refusal exists BECAUSE earlier state was left behind.
- **Earlier rulings this revisits:** PR-74, PR-93, PR-105 and PR-133 left `Report.RunRequestPage` and the placeholder Pdf
  read unkept.
  - Their reason was that no invented cell could produce those texts, or that RunRequestPage was measured only after a Commit
    while DO reaches it inside an open write transaction (PR-133 H1/H2).
  - This check is different: it runs DO's own tests on DO's instrumented build, in the state DO reaches them in.

## The kept-vs-fresh DO check (one per family, `/coord/handoff/PR-411/keepcheck/`, PR-365's kit, hardened)
- **The setup:** PR-190's instrumented DO workspace and the test app.
  - The binary is pinned to main-bf3a3e863, by sha256 and version.
  - Mutants are mapped by the full site key from c4's report onto the workspace manifest; all 43,511 map, with the same ids.
- **68874's entries (review L4):** they are sent with live's `excludeTests` for 68874's UNKEPT baseline refusals: the F1a test
  and the `Record.SetFilter()` by-value test. The kept daemon then does not run past refusals that live closes on or cuts.
- **F2's census first:** 68973's whole entry runs on ONE daemon under every c4 mutant covered by a 68973 test (821), then
  under no mutant.
  - Every request whose answer carries F2's line is listed: the "refusing mutants".
  - **At least one must refuse,** or F2's check is void and F2 is not kept (the empty-vs-empty guard).
- **Plan A, per family, across requests (PR-354's shape):**
  - for each test codeunit the family hits, its whole entry under no mutant;
  - then, for each refusing mutant (F1b's 3; F3's 5; F2's census mutants, at most 8), that codeunit's entry under the mutant,
    followed by the entry under no mutant;
  - all on ONE kept daemon, against a fresh daemon per request.
- **Plan A2, within a request (review S1, PR-54's shape):** for each refusing mutant, ONE request with two entries:
  `[the entry under the mutant, the same codeunit's entry under no mutant]`.
  - On the kept daemon, and on fresh daemons.
  - The NONE entry's rows must equal the fresh run's.
- **Compared by test name** (name, status and message). Rows are sorted by name, because serve streams them in completion
  order (PR-408).
- **The kit's own guards (review S3), each a STOP:**
  - the kept, fresh and planned request counts are all equal;
  - every request has at least one row, and as many rows as its entries' test count;
  - no `ERROR` row;
  - the kept run used ONE daemon pid throughout;
  - the kit writes every answer before it compares (a daemon that dies stops the kit).
- **The positive control, per family:** the kept run must show the family's line under each refusing mutant: F1b 10 rows, F3
  7 rows, F2 at least one per census mutant used. Fewer blocks that family.
- **F2's session state (review L2):**
  - 68973's NONE entry holds readers that do not set the language themselves, among them
    `AWordForABoolean_IsReadInTheLanguageItWasTypedIn` and `ADateTypedTheSessionsWay_IsStoredInTheInvariantForm`. They are
    named from the source before the run.
  - Their rows after a refusing mutant (Plan A's next request, A2's second entry) must equal fresh. This is what shows
    GlobalLanguage 1044 does not cross. PR-53 measured the same for its SetFilter row.
- **The self-test:** each family's compare must catch one planted row difference.
- **The verdict:** a family whose A and A2 are equal, whose positive control holds, whose guards pass and whose self-test
  catches lands its rows. Any other result blocks that family alone, and is filed in R1205.
- **When and where:** these are verdict checks, not timed. They run on CPUs 12-21 at nice 19, one process at a time, with
  nothing timed interleaved. F2's census, the longest, runs first.
