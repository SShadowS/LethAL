# PR-215 measurement, design and pre-commitment: tests that reach Report.RunRequestPage on LethAL's BC path (R1135)

Coord PR-215 (lethal-code, 2026-11-19). Roadmap: R1135. Evidence: `/coord/handoff/PR-215/` (`size.ts`, `tests.tsv`,
`kills.tsv`, `projects.tsv`, and the smoke run in `smoke/`).

## 1. Measured: how many tests reach it, and how they read
- **The parse** (`size.ts`): PR-161's WorkDate sizing, adapted.
  - **What counts:** a test method reaches `RunRequestPage` when it, its `HandlerFunctions`, or same-codeunit helpers to depth 3
    call `.RunRequestPage` on `Report` or on a report variable. Library code and the app under test are not followed, so the
    count is a floor.
  - **The smoke check:** an invented codeunit with a direct call, a call through a helper, a `Report.Run`, and a test with no
    call. The script found exactly the first two.
  - **Scope:** 86 projects (R-975's 83 BC.History projects, DO, DC) and 7,904 test methods.
- **Result: 26 test methods in 3 projects.**
  - `xl`: 20 tests, all refused at v3's stored baseline.
  - `bd`: 2 tests, counted twice because two stores carry the project.
  - `sub`: 2 tests, both passing at v3's baseline. 12 v3 kills rest on one of them.
  - **DO and DC: none.**
  - `Report.Run`/`RunModal` (a request page is possible) reach 70 tests. That is not this item's subject, and is recorded only.
- **How they read on bcdev** (PR-158's bcdev run of `sub` on bc3, `/coord/handoff/PR-158/runs/sub.bc3/`):
  - `DetailedCalculationReportUsesSubcontractorPricing` **fails at the baseline** with "The report request page cannot be used in
    background or server sessions.";
  - `TestSubcontrDispatchingList` is refused before it runs, as a possible TestPage (R-236c).

## 2. Today's handling, read from the code
- **A test that fails at the baseline is dropped from the green set.** So a mutant that only it covers is not scored
  `survived` or `killed`; it reads `no-coverage`. No false verdict comes from this item. In the `sub` case, v3's 12 kills by
  that test would read `no-coverage` on bcdev.
- **What is wrong is the label:**
  - the run counts the test only as a baseline failure ("20 of 231 baseline tests failing");
  - its mutants read as if no test reached them;
  - nothing names the cause.

  The same family already has a named class: `tests-testpage-unsupported` (R57/R58), widened by R909 to Linux BC's plain CLR
  shape.

## 3. The change (the smallest honest one)
- **A third shape of that class.** A baseline failure whose text contains BC's exact words "The report request page cannot be
  used in background or server sessions" is classified `tests-requestpage-unsupported`.
  - It is a new `BaselineClassification` value, so only the stream schema gains an enum value.
  - It uses the same guards as the TestPage classifier: not when the body never ran (`isRunMutantLineCountMessage`), and only
    on a test that did not pass.
- **The report:**
  - the fold puts such tests into the existing `testPageUnsupported` list, under the existing caveat;
  - the block's `diagnosis` is unchanged when no request-page test is present. The TestPage text is pinned in a golden report,
    a snapshot and two frozen campaign reports, and does not move;
  - when one is present, one sentence is appended: "Some of these tests open a report request page (`Report.RunRequestPage`),
    which BC refuses the same way in this session (R1135)";
  - the banner's count line says "a TestPage or a report request page" only when one is present.

  No new report field.
- **Per-mutant notes** use the request-page diagnosis (`REQUEST_PAGE_DIAGNOSIS`) for such a test, as R909's Linux shape does.
- **Not changed:**
  - verdicts and counts;
  - `mutationScore`;
  - every report and event with no request-page failure, byte for byte;
  - every gate: no fixture calls `RunRequestPage`.

## 4. Predictions
- **P1:** a baseline whose only failure carries the request-page text yields a report whose `testPageUnsupported.tests` names
  that test, whose diagnosis carries the appended sentence, and whose caveat set includes `tests-testpage-unsupported`.
- **P2:** a run with only a TestPage failure gives the same report as before, byte for byte (the existing goldens and
  snapshots, unchanged).
- **P3:** a pass, or a line-count answer, carrying the text is not classified.
- **Red checks in both directions:**
  - the matcher removed: P1 goes red;
  - the guard removed: P3 goes red;
  - the sentence appended always: P2's golden goes red.
- **Gates:** none move. VERIFY, and CI.
