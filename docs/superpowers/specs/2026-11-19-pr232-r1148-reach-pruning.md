## 1. How reach is recorded today
**Reach** means "did a test run the mutated statement?".
- **v3:** al-runner attests nothing about the mutant run, so reach comes from the BASELINE: al-runner's own per-test LINE
  coverage, read at the mutant's `reachLine`. The code is `reachFromBaseline` and `baselineReachOf` in `orchestrator.ts`
  (R926). So "not reached" on v3 is a fact about the unmutated baseline run, in the baseline's session order. It is not a
  measurement of the mutant run.
  - For a survivor, both "reached" and "not reached" are kept.
  - For any other verdict, only "reached" is kept; "not reached" becomes undecided.
- **bcdev:** reach is a latch inside the MUTANT run itself (`reachedActive`, attested per test). It measures the actual run.
  But pruning needs reach BEFORE the mutant runs, so on bcdev it too would have to come from a baseline. bcdev's baseline
  reach grain is not measured here (open item O3).
- **Only statement-grain mutants are ever decided.** Out of scope, measured on y3's survivors:
  - 688 enclosing-grain survivors (no marker, R245);
  - 232 statement-grain survivors with no reach facts (missing line evidence, or a codeunit whose isolation mode moved).
  - Pruning must leave both groups exactly as today.

## 2. What pruning would save (upper bound, offline)
`/coord/handoff/PR-231/r1148-bound.txt`:
- 8,965 survivors with reach facts: 130,979 test rows, 5,006 s of own test time;
- naive (drop every non-reaching test): 2,104 s (42.0%);
- **codeunit-order rule** (per codeunit, keep its tests up to and including the last reaching one in run order; drop a
  codeunit with no reaching test): **1,977 s (39.5%)**; 15,579 codeunits dropped whole, 946 cut after their last
  reaching test.
- The wall saving is likely larger, since fewer entries per request means less fixed cost (R1092's about 1.6 s per
  request). It is not measured until an A/B.

## 3. How reliable is "not reached"? (the evidence for decision A)
- **Kills against reach (`kill-vs-reach.txt`, `undecided-kills.txt`).** A kill requires that the mutated statement ran, so
  a kill by a test whose baseline did not reach the site is a counter-example. Positive control: all 11,589 recorded
  (kill, reaching test) pairs are found as hits by the recomputation, and 0 are not found.
  - 5,842 statement-grain kills: the killing test's baseline reached the site.
  - 2 kills: carried state; another test of the killing codeunit reached the site (the codeunit-order case).
  - 5 timeout-kills read undecided, but the killing test's baseline did reach the site. Not counter-examples.
  - **5 kills are counter-examples**, all at one site: `CDOContiniaLicenseMgt.HasExecutePermission` (mutants
    M39566-M39570). The killing test (`CDO Copy Document Tests.PurchaseCopyDocument_WhenHeaderWrittenByOtherExtension…`)
    did not reach the site in the baseline, yet it killed each mutant at position 1, and each kill reproduced.
  - **Mechanism, confirmed by reading the source:** the codeunit is `SingleInstance = true` and caches the answer per
    session in a global dictionary. The mutated lines run only on a cache MISS: the first call for a key in a session. In
    the baseline an earlier test in the same session had filled the cache. In the mutant request the killer ran first.
- **The hazard in its general form (orchestrator, 2026-11-19):** whether a statement runs can depend on session state
  that EARLIER tests left behind. That state can live anywhere:
  - a SingleInstance cache in the mutated codeunit (the measured case);
  - a cache or global in a CALLER or any other codeunit;
  - a setup table an earlier test filled;
  - IsolatedStorage or session settings.
  So the baseline's "not reached" holds only for the baseline's order. A mutant request runs its tests in another order
  and grouping, and can reach where the baseline did not, or the reverse. Excluding SingleInstance sites does not close
  it: a site guarded by another codeunit's cache looks like any other site.
  - The measured rate is 5 of 5,859 decided statement-grain kills (0.085%), all from one cache. That is a floor, not a
    bound: it counts only the sites where the different order happened to be followed by a kill.
- **The 2,835 survivors reached by none of their covering tests** (`latch-crosscheck.txt`, joined on the identity key,
  scheme 48):
  - **0 of 2,835 were killed in any other DO run:** y2 (2,835 rows, all survived); R-984 `dos3` (4 runs, 16,167 rows,
    all survived); R-984 `dos4` (4 runs, 7,941 rows, all survived).
  - This is supporting evidence, NOT proof: those runs share the same grouping habits (the same prefetch and window
    logic), so they need not ever produce the order that opens a guarded path. None of them ran every test against every
    mutant.
  - Not counted: R-974 `fix12` (an incomplete run, 54,776 no-coverage); R-984 `dos`, `dos2` (0 rows matched).
  - **43 of the 2,835 sit in SingleInstance codeunits** (`singleinstance.txt`): `CDOContiniaPerformanceMgt` 26,
    `CDOEDocumentResponse` 7, `CDOContiniaLicenseMgt` 3, `CDOUsageManagement` 3, `CDOPrinterManagement` 2,
    `CDOAzureBlobFolderMgt` 2.
  - Gated state could also live in a non-SingleInstance codeunit that only an SI cache miss calls. That is not counted.

## 5. The two decisions, kept apart
### Decision A: the 2,835 "reached by none" survivors (a labelling question, independent of speed)
- **Today:** `survived` with `guardReached: false`. The report already says no covering test reached the statement; the
  score counts the mutant as a survivor.
- **The case for `no-coverage`:** al-runner's line coverage says no test ran the statement, and 0 of the 2,835 was killed
  in 9 other runs.
- **The case against:** on v3 that "not reached" is the baseline's session order, not the mutant run's (section 3,
  measured at one SI site). If the statement did run in the mutant request and every test passed, `survived` was right.
- **Recommendation:**
  - **Decide reach from the mutant request itself, never from the baseline's order.** The v3 serve protocol already takes
    `perTestCoverage` on any request (`al-runner-server.ts`). With it on for a survivor's mutant requests, each test's
    line coverage in the very run that produced the verdict says whether the mutated statement ran. That is an attested
    in-run fact, the same meaning as bcdev's latch.
  - A survivor whose covering tests ran and none executed the statement **in that run** is truly `no-coverage`. Give it
    its own named reason (for example "unreached in run") so a reader can tell it from "no test covers the procedure".
  - A survivor whose statement ran in that run stays `survived`, whatever the baseline said.
  - Until M1 (section 6) has measured it, **no relabel**: today's `survived` with `guardReached: false` stays.
  - Land it only after the coverage-differential gate against `--mode none` on the fixtures (sandbox-app,
    sandbox-data), with 0 lost kills, and with the DO figure move pre-committed from M1's count.
- **Alternative (no score move):** keep `survived` and only report the subset in the survivor list as "not reached". It
  costs nothing and moves no figure.
- **Rejected:** relabel from the baseline with SingleInstance sites excluded. It misses a site guarded by another
  codeunit's state (the general H2).

### Decision B: pruning (the speed-up; needs A only for the 2,835 dropped whole)
- **Rule:** for a statement-grain mutant with complete baseline reach facts: per covering codeunit, keep its tests up to
  and including the last reaching one, in run order, and drop a codeunit with no reaching test. Everything else runs
  every covering test, as today.
- **Risk:** pruning must decide BEFORE the run, so it rests on the baseline's order, and H2 applies in full.
- **Its bound comes from M1:** in a full unpruned run with in-run reach, count the tests the rule WOULD drop that reached
  the statement in the mutant request. Each one is an H2 instance pruning would have cut. Zero on DO bounds the risk for
  DO's suite; any non-zero count names sites to study.
- **Before landing:** a v3 A/B on a DO slice (pruned against unpruned, the same build and the same tests), compared per
  mutant on the full site key:
  - 0 lost kills;
  - verdicts otherwise equal;
  - covering sets may only shrink to the kept tests;
  - `killingTest` may move only to another kept test.
  - Plus the coverage-differential gate (fixtures, against `--mode none`).
- **Default off** until a ruling, as `--prune-unreached` or similar.

## 6. The measurement that decides both: M1, in-run reach on v3
- **What:** a measure-only, default-off switch that sends `perTestCoverage` on v3's prefetch and live requests, and turns
  each test's line coverage at the mutant's `reachLine` into the existing per-test reach answer (`reachedActive`). The
  orchestrator's GH-24 path then records `guardReached`/`reachedBy` from the run, as it does on bcdev.
  - It is small: the request field exists; the backend maps lines to a yes or no per test. No verdict logic changes.
- **Smoke first:** does al-runner fill `perTestCoverage` on a request with `runSelectedOnly` and an active mutant? It is
  unmeasured; one hand-run request decides it.
- **Run:** the DO scope (or a slice holding all 2,835 plus the 5 `HasExecutePermission` controls) on y3's build.
- **Controls:**
  - M39566-M39570's killing test must read REACHED in-run, where the baseline said not reached. This proves the switch
    sees order-dependent reach.
  - The positive control from section 3 must hold.
- **Outputs:**
  - (A) how many of the 2,835 really ran unreached in their own request, which is the figure decision A moves;
  - (B) how many tests the pruning rule would drop that reached in-run, decision B's bound;
  - the cost of coverage on mutant requests (coverage was 131 s of the 260 s baseline wall).
- **Fallback, if al-runner cannot cover a mutant request:** a bound by parse (orchestrator's suggestion). For each of the
  2,835, does any covering test's path pass a guard on session state (a read of a SingleInstance global, a dictionary or
  list `Get`/`Contains` on a global, IsolatedStorage, a setup-table `Get`) before the site? It is coarser, and it is a
  bound only.
