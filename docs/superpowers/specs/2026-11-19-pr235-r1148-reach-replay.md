## 1. Why a replay, not a switch on the mutant requests
The smoke test (`/coord/handoff/PR-235/smoke.md`, current = `edge-4ebfe7913`):
- a request with `entries` refuses `coverage` and `perTestCoverage` ("coverage is not supported with entries"). Filed
  upstream: https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8506
- a request-level `resources` is an unknown field;
- **rewriting `active-mutant.txt` between PLAIN requests on one daemon works:** `cached: true` (no recompile), the echo
  reads the override, per-test coverage follows the mutant's path, and each plain request starts from fresh session state
  (a SingleInstance cache does not carry over), which is an entry's condition (one codeunit, fresh state, its tests in
  method order).

So in-run reach for (mutant m, covering codeunit c) is one plain coverage request for c with m in the lane's resource
file. That is what the backend's existing R635 §5 `coverageWindow` already does for the §6 Sleep rule: echo, plain
coverage request, echo, row comparison against the entry's rows, NONE restored in `finally`.

## 2. What is built
1. **Switch:** the env var `LETHAL_V3_REACH_REPLAY=<path>`.
   - Unset: nothing changes, and no request, event or file differs from today.
   - Set: the replay runs, and its only output is NDJSON appended to `<path>`.
   - `LETHAL_V3_REACH_REPLAY_ALSO=<file>` (optional) lists extra mutant ids (one per line) to replay whatever their
     verdict: the controls.
2. **Targets, per batch, after that batch's mutant phase and before its teardown or the next deploy:**
   - (a) every statement-grain mutant scored `survived` whose recorded reach is `guardReached: false` (decided from the
     baseline, R926);
   - (b) every id in the ALSO file that belongs to this batch.
   - A target with no `reachLine`, or not statement grain, is written as `skipped` with the reason, never replayed.
3. **Per target, per covering codeunit,** in the covering set's own order: one window through a variant of
   `coverageWindow` that takes the mutant id explicitly (not `lane.lastActivated`):
   - echo before;
   - a plain request with coverage for that codeunit, leaving out the same tests the entry left out;
   - echo after;
   - restore NONE in `finally`.
   - One NDJSON line per window:
     `{type:"reach-replay", batch, mutantId, file, startLine, operator, startIndex, endIndex, reachLine, objectKey, codeunit, verdict, rows:[{test, status}], hits:[test…], echo:"ok"|why, agree: bool, ms}`.
   - `hits` lists the tests whose per-test coverage has `objectKey:reachLine` with hits > 0, resolved through the same
     line map and frame as the baseline's `baselineReachOf` (so the two are comparable).
   - `agree` is whether the window's rows equal the verdict run's for that codeunit:
     - for a survivor: all pass (not-run rows equal);
     - for a killed control: the killer fails.
4. **Lanes:** the targets are spread over the session's lanes; each lane uses its own `active.<k>/`. `inWindow` (today
   one backend-wide flag) becomes PER LANE, so the out-of-window guard (the proof's "holds … not NONE, outside the
   coverage window") keeps refusing a stale file on any lane while another lane's window is open.
5. **No effect on scoring:** the replay runs after every verdict of the batch is recorded. It changes no verdict,
   covering set, `guardReached`, report field, caveat or event that exists today. A window that fails (a transport
   error, a timeout, an echo mismatch) is written as such; it never stops the session, except where today's window would
   (`AlRunnerV3UnprovenBatchError`, a stale resource found).

## 3. NONE is restored on every exit path (red-tested)
The tests must go red when each restore or guard is removed:
- T1: a window whose plain request throws, so the resource file reads NONE after it.
- T2: a window whose echo mismatches, so NONE after it.
- T3: an exception thrown between two windows (the replay loop aborted), so NONE after it.
- T4: the session aborted during a replay (the existing abort or signal path): NONE on every lane's resource file before
  exit. If the existing path does not restore it, the build adds that.
- T5: a lane's resource file left non-NONE while ANOTHER lane is inside a window: the next proof on the first lane
  refuses (the per-lane `inWindow`). Red check: with the flag back to backend-wide, T5 passes the stale file.
- T6: the switch unset: no replay request is sent (a fake daemon counts the requests); it is set: exactly the expected
  windows are sent. Red both ways.

## 4. The DO measurement (decision A), pre-committed
- **Build and source:** `current` = `edge-4ebfe7913` (y3's build); the source `/coord/handoff/R-942/src/do-cloud`; y3's
  config otherwise.
- **Scope:** the 89 files that hold y3's 2,835 baseline-unreached survivors, a run of about 22,180 mutants (51% of y3).
  Under a heavy slot.
- **ALSO file:**
  - the 5 controls at `CDOContiniaLicenseMgt.HasExecutePermission` (y3's M39566-M39570, joined on the full site key in
    this run);
  - a seeded random sample of 50 killed statement-grain mutants from the same 89 files, whose killing test's baseline
    reached the site.
- **Validity: the measurement counts only if all of these hold. Otherwise it is void and nothing is reported as A:**
  - V1: each of the 5 controls killed in this run shows its killing test in `hits` (reached in-run), with `agree` true.
  - V2: at least 48 of the 50 sampled kills show the killing test in `hits` with `agree` true. Every miss is listed and
    explained.
  - V3: `echo` is `ok` on every window; any mismatch voids its window, and more than 1% voids the run.
  - V4: every resource file reads NONE at the end of the session (read by hand after the run).
- **Reported, with no prediction (this is the measurement):**
  - A1: of the baseline-unreached survivors replayed, how many show a hit by any covering test in-run (reached in-run),
    how many show none (unreached in-run), and how many have a void or skipped window;
  - A2: the in-run-reached ones by file and procedure;
  - A3: windows with `agree` false (a survivor whose replay failed a test), listed one by one;
  - A4: cost: windows, the replay's wall, and seconds per window.
- **Join:** this run against y3 on the full site key (file, startLine, operator, startIndex, endIndex). This run's own
  set is the one measured, and the overlap with y3's 2,835 is reported.
