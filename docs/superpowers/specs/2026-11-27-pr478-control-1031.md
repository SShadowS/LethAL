## What 1.0.0.31 adds (on top of 1.0.0.30), and nothing else
1. **`LC Lease."Op Kind"` gains `client-run`.**
   - Every check keyed on `run` is reviewed. These are extended to `client-run`: `TryRenew`'s fast path and its no-shrink
     rule.
   - These are NOT extended:
     - `TryStopHungRun` and `TryStopHungRunAt`: they refuse a `client-run` op (B3; its stop is the gated path below);
     - `IsOwnRunActive`: it answers for the `run` kind only (headless RunMany).
   - The client side (`opKind === "run"` in the lost-answer recovery and the doctor) learns `client-run` in PR-479, not here.
2. **`ActivateForClient(epoch, token, generation, attemptId, opSeq, targetAppId, artifactId, mutantId, runBoundMs)`:**
   - fenced like `TryBeginRun`;
   - claims a `client-run` op;
   - writes the tuple and bumps Generation;
   - records no session id (the session binds itself, item 4);
   - caps the bound like `ExtendRunClaim`;
   - returns the Generation it wrote;
   - ends with the serving OData session's in-memory state reset (B3).
3. **`DeactivateForClient(fence, attemptId, opSeq)`:**
   - the tuple-conditional clear and the fail-closed reset;
   - it tombstones the op ONLY when `Active Session` no longer holds the bound session id. Otherwise it answers
     `client-session-alive` and leaves the op in flight (B3, the overrun ruling).
   - No other path tombstones a `client-run` op.
4. **A small page `LC Client Bind`** opened by the client session.
   - Inside a `client-run` op whose attempt and op seq it is given, and only when `Op Session Id` is blank, it sets
     `Op Session Id := SessionId()`.
   - Nothing else ever sets it for `client-run`.
5. **The attestation table `LC Client Attestation`** (`DataPerCompany = false`), keyed by (attempt id, op seq, codeunit id,
   method). It holds:
   - the Generation and mutant id the session LOADED;
   - `Loaded`;
   - `ObservedAny`, `ObservedIdentityMismatch` and `ObservedActive`;
   - the method's own success;
   - `TestMethodRuns`;
   - the session id;
   - the lease's Server Generation and Database Id.
6. **Two subscribers on Test Runner - Mgt,** both GATED: they act only when this session is the bound session of the
   in-flight `client-run` op (they read `LC Lease` with `InherentPermissions`).
   - `OnBeforeTestMethodRun` resets the observations only. It never touches `ResetSinceLoad`.
   - `OnAfterTestMethodRun` inserts the row. It never reads `LC Mutation Active`; it attests what the session loaded.
7. **In a session outside any op,** loading or refreshing the tuple also sets the expected target and artifact ids from the
   row, so a stale artifact's guard latches a mismatch in a client session (B3).
8. `app.json` 1.0.0.31. `MIN_CONTROL_VERSION` stays 1.0.0.29. The client-mode version gate is PR-479's.

## Amendment 1 (2026-11-27, the Opus build review of 9997b9eb7, before any server call)
The review found the headless path sound (0 moves expected), and three blocking gaps.
1. **"Session gone" must fail CLOSED.**
   - R53 measured that a web-service session cannot see itself, and that the row it saw carried a NEGATIVE id. A filter on
     `Session ID = boundId` alone can therefore read a live session as gone.
   - So `ActiveSessionHolds` treats a row for `boundId` OR `-boundId` as alive.
   - A source pin covers the sense of the check (alive = not empty) and both signs.
   - The Windows-BC probe adds a negative control: a bound, live `/cs` session must read `client-session-alive`.
2. **A self-binding OData action, `BindCallerSession(attemptId, opSeq)`.** It binds the CALLER's own `SessionId()` under the
   same rules as the page (a `client-run` op, a matching attempt and op seq, a blank `Op Session Id`), so it stays
   self-binding (B3).
   - The client session may use either the page or the action.
   - On bc1-bc3, `itest:lease` binds an OData session this way, and covers:
     - bind once only;
     - Deactivate with that live bound session (`client-session-alive`, the op kept);
     - Renew's no-shrink rule;
     - the stop's refusal.
   - "Deactivate after the session is gone" cannot be reached on bc1-bc3, because OData sessions are pooled. It moves to the
     Windows-BC probes.
3. **A fenced read of the rows, `ReadClientAttestation(fence, attemptId, opSeq)`.** It returns every attestation row of
   that op as JSON. Without it, PR-479 would need a 1.0.0.32 and a full re-proof. It reads only; folding it into
   DeactivateForClient is PR-480's optional cut.
- **Should-fix items, folded in:**
  - the gated `OnBeforeTestMethodRun` also calls `NoteTestMethodRun`, so the row's `TestMethodRuns` reads 1..N in a client
    session (otherwise it is a field that can never fail). The R206 pin names this third, gated site;
  - item 3's text: DeactivateForClient clears with `ForceClearActive` (fenced on the attempt and op seq, as `TryRecoverOp`
    does), not the tuple-conditional clear. While a `client-run` marker is in flight, only that op's Activate can have
    written the tuple;
  - a never-bound op is refused with `no-session-id`. That costs a restart and a force reset if a bind ever fails, and
    PR-479 treats a failed bind as `operation-orphaned`;
  - `TryForceResetLease` still clears a `client-run` marker. Its contract requires an NST restart first, which ends the
    session;
  - more pins:
    - `ReadUncommitted` in the gate's lease read (no lock in headless);
    - exactly two subscribers in `LC Client Subscribers`, both gated;
    - Activate's fence order;
  - the "mismatch latch" check is a source pin, not a live test: the OnBefore reset is gated on a bound `client-run`
    session, so a headless RunMutantMany never resets its latch. bc1-bc3 have no way to plant a wrong artifact in the middle
    of a call;
  - `client-session-alive` echoes the bound session id.
- **Nits recorded for PR-479:**
  - require `Bound = true`;
  - require `Loaded Generation` = Activate's generation whenever `Loaded`;
  - accept `Loaded = false` only with nothing observed;
  - expect an `OnRun` row;
  - deactivate only after closing the session;
  - treat `client-session-alive` as "retry later";
  - teach the lost-answer recovery and the doctor about `client-run`;
  - clean up rows after the read.

## Amendment 2 (2026-11-27, the delta review of 87506755b, before any server call)
1. **"Both signs" is not "fails closed".**
   - R53 (`scripts/r53-probe/README.md`) measured that a web-service session could not see another, busy web-service
     session (`visibleBefore:No`). The one row it saw carried `-3187` for session 3188, so the id is not simply negated.
   - So the Active Session check can still read a live session as gone if the caller cannot see it. The code claims only
     the id and its negative. Whether the check works is MEASURED, not assumed:
     - **On bcwin (the proof):** a bound, live `/cs` session must read `client-session-alive` from the OData session that
       calls Deactivate, and must read gone after the client closes it.
     - **If bcwin shows the check cannot see a live `/cs` session:** the overrun proof fails, and PR-479 does not build on it.
       A new mechanism (for example a liveness mark the client session itself renews) needs its own pre-commitment and a
       1.0.0.32 before PR-479.
     - **On bc1-bc3, `itest:lease`'s "Deactivate with a live bound OData session" leg is measure-and-record:** either
       answer is written to the receipt with the session ids. It gates nothing, because a pooled OData session is not the
       topology client mode runs.
     - Bind once only, Renew's no-shrink rule and the stop's refusal stay gating legs.
2. **ReadClientAttestation reads ReadCommitted** on both tables (still no lock), so it neither passes a fence on an
   uncommitted lease change nor returns a half-written row.
3. **BindClientSession refuses `SessionId() <= 0`** (`no-session-id`).
4. **The bind stays unfenced**, as the page is.
   - Another OData caller that wins the bind race only causes `already-bound` for the real client session. PR-479 refuses
     that by name, and it writes no row the driver accepts: the driver requires the rows' session id to be the one its own
     bind reported.
   - So it fails closed.
5. **A client row's `TestMethodRuns` counts methods in that session.** It reads 1..N only in a fresh session (B1 makes it
   fresh). It is not the headless sites' unit; PR-479 does not compare the two.
6. **`{read: true, rows: []}` for a bound op is a failure for PR-479**, never "nothing to object to".
