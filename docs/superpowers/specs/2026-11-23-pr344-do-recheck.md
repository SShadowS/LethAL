`refusedCutTail`'s tail alone calls. Sizing: `/coord/handoff/PR-344/size-recheck.py` and `.txt`, from PR-302's t1/t1b and c2.

## Why two arms, not a comparison with t1 alone
Master has moved since PR-302's t1: PR-340's carry walk is on by default (`LETHAL_V3_CARRY_WALK` unset), and R1178 and
R1179 are fixed. A difference against t1 could come from any of them. So the measurement is **two arms on the same build,
the same config and the same master, differing only by PR-344**. t1 is a sanity reference, not the oracle.
- **Arm A (packed):** master at the run's commit (PR-344 in; PR-365 in if merged by then), `alRunnerV3.refusedCutTail: true`.
- **Arm B (unpacked):** the same commit with PR-344's merge reverted (`git revert --no-commit -m 1 a0c38f5d2`) in a scratch
  worktree. This is uncommitted measurement code only; nothing reaches master. Flag on.
- **Both:** DO (`/work/src/DO`, read-only) with c2's settings and `"ciSessionKind": "client"`. The binary is `current`
  main-bf3a3e863; the config's `alRunnerV3.path` is checked and its sha recorded. Companies CRONUS. Carry walk as master's
  default, the same in both. CPUs 0-11, 6 lanes. A then B, in sequence, on a quiet box. BOOTTIME-MONOTONIC is read at start
  and end.

## Predictions
1. **Verdicts: A equals B per mutant** (verdict and `killingTest`, joined on the full site key). Any difference is a BLOCK on
   PR-344 until explained.
2. **Bound checks:** A makes fewer than B. Per covered tail mutant: A about one send per 16 tail tests (two for mutants with
   more than 16), B one per tail test. On the main case's 150 mutants, B's checks should be near t1's rate for 68874 and 68906
   (about 19 tail calls per affected mutant on t1 overall), and A's near 1-2 per mutant. Reported: A's and B's counts and
   summed bound ms, and the per-check ms.
3. **Pack stats (A only):** packs sent, failed packs, rows served from a pack; failed packs and cuts after entry 0 named per
   mutant (PR-344's Limit 1).
4. **Against t1 (sanity only, not a BLOCK):** per-mutant verdict differences between A and t1 are listed and attributed where
   possible (the carry walk, R1178, R1179, PR-365's keep rows).
5. **Run void** unless the baseline-refusal cut fires in both arms for every in-scope codeunit that was cut in t1 (the
   `al-runner-v3-baseline-refused-cut` notices), and the stability pass reads the same tail tests stable in both.
