## The correction this rests on (verified in code)
- `orchestrator.ts` `reachFinal` (R926, v3) keeps the baseline's reach answer only when it reads REACHED, or when the
  verdict is `survived`. A KILLED mutant whose baseline did not reach its site reads UNDECIDED, never `false`.
- So PR-235's "0 of 12,196 kills unreached" was true by construction. It is corrected in PR-235's `result.md`.
- PR-235's survivor findings stand: the 2,835 read unreached under both baselines, with 0 moves.

## 1. A measure-only raw-reach trace (LethAL code)
- **The knob:** `LETHAL_REACH_TRACE=<file>`. When set, every mutant scored IN THIS SESSION appends one NDJSON row,
  written synchronously:
  - the site key: `file`, `startLine`, `operatorName`, `startIndex`, `endIndex`;
  - `verdict`, `reachGrain`, `reachLine`, `killingTest`;
  - **`reachOverCovering`:** `reachFromBaseline(m, covering, …)` over ALL the mutant's covering tests. That is the
    predicate the built pruning would evaluate.
  - **`reachOverRan`:** the same over `ranRefs` (today's input).
  - **`killerBaselineHit`:** whether the killing test's own baseline coverage hit `reachLine` (`true`, `false`, or `null`
    when unknown or not applicable).
  - **`nullCause`:** when a reach is `null`: `non-statement-grain`, `all-green`, `no-line-evidence`, `mode-moved`,
    `empty-set`, or `other`.
  - **`reachFinal`:** the report's value.
- **Guards** (fail loudly):
  - `--resume` with the knob is refused by name, because carried rows have no reach;
  - at session end the trace's row count must equal the session's scored count, per site key, or the session fails by
    name.
- **Unset:** nothing is written, and verdicts, the report and events are unchanged. No schema field is added.
- **Tests** (red-checked both ways):
  - a killed mutant whose baseline missed its line traces `reachOverCovering: false` while the report stays undecided;
  - a survivor's `reachOverCovering` equals its report value;
  - `reachOverCovering` and `reachOverRan` differ when the kill stopped before a later covering test;
  - `--resume` is refused;
  - a count mismatch fails;
  - unset writes nothing.

## 2. The fixture: `fixtures/sandbox-reach` plus `sandbox-reach-tests`
- **Basics:** ids 75000-75099, runtime 17, compiled by `compile:fixtures`, listed in `fixtures/README.md`, used by no gate.
- **Placement rules:**
  - every site is a single-line statement strictly inside a public procedure's body (never on an `if` line or condition,
    so its grain is `statement`);
  - no triggers, no `local`;
  - one object per file, and no `#if`;
  - every baseline test passes;
  - test methods are declared in their run order.
- **U, planted unreached (8):** statements in a branch no test takes, inside procedures the tests call. U and R lines
  alternate in both orders, to expose an off-by-one in the line map.
- **R, reached twins (8):** the same statements on the taken branch, each asserted.
- **S, reached through an earlier test's SingleInstance state in the same codeunit (4):** the H1 case.
- **No cross-codeunit (X) sites.** Baseline batching is enabled only on builds whose gate record shows
  `batch-no-cross-singleinstance` (PR-114a), and PR-114b measured per-test coverage batched against alone equal for 1,978
  of 1,979 DO tests. So a batched baseline cannot be told apart from an unbatched one on this question.
- **`controls.json`:** written from a dry run BEFORE the scoring run. It holds each site key, its kind, its `reachGrain` and
  its `reachLine`.
- **What the fixture can and cannot prove:** it proves the line map (U against R) and the SAFE direction. No planted site
  yields "baseline missed, mutant killed" without broken attribution. **Decision A rests on §4.**

## 3. The fixture run (P2): `current` pinned by path, `LETHAL_V3_BASELINE_BATCHING=off`, `--workers 1`, a fresh store, trace on
- **Cost:** minutes; no BC; `--peak build`; CPUs 12-21 at nice 10.
- **Bounds (all BLOCK):**
  - **LINE MAP:** every U site traces `reachOverCovering: false`, and every R site `true`.
  - **SAFE:** every R and S site traces `reachOverCovering: true`.
  - **ATTRIBUTION:** no U site is killed.
  - **COMPLETENESS:** at most 2 listed sites trace `null`, each named with its cause. More than 2 void the control.
  - **ROW COUNT:** the trace's rows equal the session's scored mutants.

## 4. The DO re-read (decides A): PR-235's undecided kills, after the combined run frees the box
- **The scope:** PR-235's killed mutants whose report reach is undecided (342), selected by exact site (the `exactSites`
  path, PR-144, or `--lines` per site), on the PR-235 config and build with `current` pinned by path. The baseline is
  unbatched, as pruning would read it. Trace on, a fresh store, heavy-slot `baseapp`.
- **The join to PR-235:** on the full site key, never on mutantId. Kills PR-235 had that this run does not, and the
  reverse, are reported by name.
- **Bounds:**
  - **BLOCK:** 0 kills with `reachOverCovering: false`. Any such kill is one pruning would lose, so A stays off, with the
    kills named.
  - **BLOCK-or-explain:** every kill with `reachOverCovering: null` is listed with its `nullCause`. A null kill is not a
    pass: A may be built only if pruning, as built, would also NOT prune for that cause (for example, it prunes only on an
    explicit `false`).
  - **Reported:** `killerBaselineHit` for every kill (a killer whose baseline missed the line, on a reached site, is
    reported by name).

## Decision A
- **A may be built only if** §3's bounds and §4's BLOCK bounds all hold.
- **Then:** prune a survivor's covering tests only when its site's `reachOverCovering` is explicitly `false` under the
  unbatched (or gate-proven batched) baseline. Never prune on `null`.
