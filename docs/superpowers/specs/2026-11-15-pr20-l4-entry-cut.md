# PR-20: L4, a mutant entry stops after the mutant's last covering test of its codeunit

Status: pre-commitment (coord PR-20, lethal-code, 2026-11-15), reviewed by lethal-bugs. Its DO window is shared with L1:
[2026-11-15-pr18-l1-keep-zip-format-region.md](2026-11-15-pr18-l1-keep-zip-format-region.md).

## The change

Today a mutant's entry for a covering codeunit runs the whole codeunit (`test: "Codeunit<id>."`), minus R998's left-out
trailing run (`mutantLeftOutNames`). L4 adds to that entry's `excludeTests` every test of the codeunit that comes AFTER the
mutant's last covering test in the codeunit's baseline order. The exclusion is per mutant and per codeunit.

Unchanged: the warm-up (NONE over the union), the echo entry, entries of a test run alone (R857 / R896 `isolatedRefs`: one
test, nothing to cut), one-shot calls, and the BC backends.

## Why no verdict can change

1. **A verdict reads only the mutant's covering tests.** The orchestrator's loop over a mutant's call goes over its covering
   refs (`killingTest = ref.method`), and a kill pair (R778) is "the first covering test that FAILED". A row of a non-covering
   test of the same codeunit is read only by the completeness check (`suiteMissing`), the refusal and cut detection
   (`serveDaemonReusable`), and the refusal statistics (`UniformRefusalWatch`).
2. **A test cannot change a test that ran before it.** al-runner runs a codeunit's tests in a fixed order: the run seed "does
   not change the work date, the test order or install code" (`al-runner test --help`, edge-5a58a0f16). The order is the
   baseline's, the one `mutantLeftOutNames` already relies on (R998). State flows only forward: under `testIsolation: test` the
   database is rolled back after each test, and globals that survive (R998 review 2-3) can reach only later tests. Under
   `testIsolation: codeunit` (a codeunit LethAL runs with method isolation, R896, sent as a whole-codeunit entry) state also
   flows only forward. So every covering test, and every test before the last one, runs from exactly the state it runs from
   today; the tests after it are never read for the verdict.
   Paths that could run a later test's code early, checked (lethal-bugs' review):
   - (a) the test codeunit's `OnRun` and any `Initialize` / `IsInitialized` pattern run before or at the FIRST test, which L4
     always keeps;
   - (b) random draws do not depend on the tests after: one request, four entries of one codeunit (whole, without its last
     test, without its last two, whole again); its first test draws the same `Random(1000000)`, `CreateGuid()` and `Time()` in
     all four, with a fresh seed and with `seed: 7` (`/coord/handoff/PR-20/seed-probe/out.txt`, edge-5a58a0f16). The draws
     depend on the request's seed only, which every entry of a request shares, as today;
   - (c) the discovery pass only lists tests; it runs no AL;
   - (d) the CPU limit is per test;
   - (e) R890/R896's isolation mode is chosen per codeunit, from the baseline, never from an entry's test set, so an
     `excludeTests` cannot change it.
   Data (lethal-bugs, t1, t3 and the PR-18 traced run): all 545 kills name a covering test's method, and every `error` verdict is
   a refusal or a cascade OF a covering test; none came from a test after the last covering one.
3. **BC.** L4 changes only the al-runner v3 serve transport. A BC run (bcdev) runs each covering test as today, and the
   verdict there also reads only covering tests, so parity between the backends is unchanged: the excluded tests were never part
   of either side's verdict.

## What changes besides the time

- **Fewer cuts and restarts.** A refusal or a timeout in an excluded test no longer cuts the answer or closes the daemon. That
  is intended: the row would have been read only to throw the daemon away. A refusal of a covering test, or of a test before
  it, still cuts and closes exactly as today.
- **`suiteMissing`** accepts no row for a test in the entry's own `excludeTests` (as it did for R998's run). A row that comes
  back anyway is read as ever. A covering test without exactly one row stays `missing`.
- **Refusal statistics** (`UniformRefusalWatch`) see fewer rows. It decides only whether to stop sending entries after
  uniform refusals; fewer rows can delay that decision, never invent one.
- **The §6 coverage window** leaves out what the entry left out (the entry's own list), as R998 required.

## Where it would not hold, and what L4 does there

- **#8059:** v3 matches `excludeTests` by PREFIX. Excluding `Codeunit5.TestA` also excludes `Codeunit5.TestAB`. So a test is
  added to the exclusion only when no test that must run (a covering test, or any test before the last covering one) starts
  with its name, case-insensitively, the same guard as `leftOutRows`. A tail test that fails the guard runs as today (a cost,
  never a verdict change). The names are full (`Codeunit<id>.<method>`), so another codeunit is never matched.
- **Order not known:** a codeunit with no baseline rows, or a covering or discovered test that is not in them, gets no cut.
- **The answer's order differs from the baseline's:** checked per cut entry. If its rows do not come back in the baseline
  order, the entry is `missing` (the mutant takes today's path), counted in the stats line as `order broken`.
- **A kill pair (R778)** runs a NONE group, then the mutant's group. The NONE group is never cut (it has no covering set), so
  the confirm runs at least every test the mutant's entry ran before the killing test.
- **A ref the orchestrator asks for that the cut left out** (not expected: the orchestrator runs a mutant against the covering
  set it planned) is not read as `missing`: the method joins the mutant's covering set and the call is made live, without that
  cut. Counted in the stats line as `widened`.
- **No covering set known** for a mutant (no prefetch plan, a NONE group): no cut.

## Red checks (both ways)

1. A kill by the LAST covering test stays a kill (the test runs and fails).
2. A test after the last covering test is not run: its name is in the sent entry's `excludeTests`; today's build sends none.
3. #8059: a tail test whose name starts a test that must run is not excluded.
4. `suiteMissing` both ways: no row for an excluded test is not `missing`; no row for a covering test still is.
5. The order check: rows out of baseline order make the entry `missing`.
6. A ref the cut left out runs live and is not read as `missing`.
