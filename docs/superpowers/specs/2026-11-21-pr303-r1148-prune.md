# PR-303 pre-commitment: R1148 survivor pruning, the test CODEUNITS that cannot reach a mutant's site are not run (v3, flag, default off)

Coord PR-303 (lethal-code, 2026-11-21), after PR-298 (decision A passed its pre-committed bounds; the owner: decide A on
that run). An Opus spec-adversary reviewed the first draft (`/coord/handoff/PR-303/spec-review.md`). Its three blocking
findings are folded in, and the draft's in-codeunit "tail cut" is REMOVED: PR-298's own DO trace holds 6 kills whose
killer never reached the site at baseline, because it killed through state an earlier reaching test of the SAME codeunit
left behind.

## The rule
1. **Per covering test, per mutant, explicit false only.**
   - The test's baseline reach of the mutant's site is explicit false only when all of these hold:
     - the mutant is statement grain;
     - the test's baseline row is `pass`, with line evidence for the object, no naming gap, and the codeunit's isolation mode
       unchanged since the baseline (`reachWhy`'s completeness rules);
     - its lines do not include the site's `reachLine`.
   - Anything else counts as reaching: null, enclosing grain, a refused, failed or missing row, mode moved, all-green
     attribution.
2. **Whole codeunits only.**
   - A test codeunit with NO covering test that reaches the mutant's site (every one of its covering tests explicit false)
     is dropped from that mutant's run plan.
   - A codeunit with at least one reaching covering test keeps ALL its covering tests, unchanged. The existing L4 cut
     stays where it is.
3. **Why no verdict moves:**
   - Each entry starts fresh; the O1 leg measures that at every pin.
   - Until the mutated statement first runs, a run under the mutant equals the run under NONE (N13).
   - So inside an entry whose tests never hit `reachLine` at baseline, the mutated statement never runs. Every test passes
     as in the baseline, and no other entry's state is touched.
   - **The known exception, stated:** state carried by a COMMIT across entries. O1 does not measure it, and the A/B is
     the check.
4. **Nothing left to run:** when every covering codeunit is dropped, the mutant is recorded `survived` without running.
   - Its `guardReached` is `false`, from `reachWhy` over the FULL covering set.
   - Its note joins the pruned text ("pruned: no covering test reaches its site") with `survivorNote(fullCovering)`.
     Neither replaces the other.
   - The pruned map KEEPS the mutant's key with an empty list (an absent key reads as uncovered).
   - The empty-plan record is taken BEFORE the `covering.length === 0` (`no-coverage`) branch, and a test pins
     `survived`, not `no-coverage`.
   - On DO this is 3 statement-grain survivors (the review's count).
5. **Baseline mode** (PR-298's condition): pruning applies only under an unbatched baseline. Under any other baseline
   mode the flag is refused by name (a gate-proven batched baseline can be allowed later).
6. **`--resume` across a flag change:** refused. A resumed run whose stored run had the flag in a different state is
   refused by name, so a pruned survivor is never carried into a flag-off run as an ordinary one.

## Which list each part reads (the review's S1)
- **The PRUNED plan map** (built where `perMutantTests` is built): everything that plans or runs.
  - `prefetchPlans`, `cutWindows`, `entriesOf`, `registerPlans` (the L4 `coveringOf`);
  - the loop's `ordered`;
  - the R198 `wanted` set, `useCoveringBudgets` and the R197 ledger order.
- **The FULL map:** everything that reports or diagnoses.
  - `record()`'s `coveringTests`, `survivorNote(covering)`;
  - `reachFinal` and `reachWhy` (a pruned survivor's reach is read over the full set);
  - the trace.
- **Flag off:** the pruned map IS the full map, so there is zero change.

## What is built
- **The predicate:** `pruneCodeunitsForReach(m, covering, baselineReach, isolationOf)`, a pure function returning the
  covering tests to run per rule 2, in their order.
- **The two maps** and the empty-plan record (rule 4).
- **The flag:** `LETHAL_V3_REACH_PRUNE=on`.
  - Unset or empty means off; any other value is refused by name.
  - It is refused on any backend other than al-runner-v3 (the review's S2).
  - The v3 details line names it.
- **Counts:** the TIMING line gives the mutant entries the pruning removed, and the mutants recorded pruned-survived.

## Tests (red-checked both ways; stateful fakes; call counters)
- **The pure function:**
  - a codeunit whose covering tests are all explicit false is dropped;
  - one reaching test keeps its whole codeunit, including its false tests (the B1 shape: Sales reaches, Purchase does not,
    both kept);
  - null, enclosing grain, a refused or failed row, mode moved and all-green each keep their codeunit;
  - the order is kept.
- **The session, flag on:**
  - the dropped codeunit is not in the prefetch plans, nor in the registered L4 cut, nor sent to the fake daemon;
  - `coveringTests` in the report is the full set;
  - a survivor is not `group-coverage-incomplete`;
  - a fully pruned mutant is `survived`, `guardReached: false`, with its note;
  - a killed mutant's `killingTest` equals the flag-off run's.
- **The flag:** off means zero change (the plan map is identical). Each of these is refused by name: a bad value,
  another backend, a non-unbatched baseline, and `--resume` across a flag change.

## Amendment 2 (2026-11-22, after round 1 of the A/B hit BLOCK; the orchestrator's go)

### What round 1 found (`/coord/handoff/PR-303/ab/compare-r1.txt`)
- M1 held, and the head was 6954b1a2a.
- **The kill side was clean:** 887 kills in both arms with the same killingTests, and the B1 control's 5 kills identical.
- **But 120 mutants moved `error` → `survived`,** 86 of them FULLY pruned (recorded survived without running).
- **Each was an R1160 `baseline-refused-cut` error in A:** a covering codeunit holds a test refused at baseline, which
  cannot run under the mutant, so the verdict is not measured.
- **Why pruning dropped it:** pruning read reach only from GREEN covering tests, and the refused test is not one of them, so
  its codeunit read "all explicit false". B's `survived` then claims more than is known: the refused test might reach the
  site. Principle 5: unknown is not no.
- The series was stopped before A2 ran.

### Rule 2 is replaced: only a codeunit whose EVERY test was measured green can be dropped
- **The condition:** a test codeunit may be dropped from a mutant's plan only when EVERY test of that codeunit in the run's
  final test list:
  - had a baseline outcome of `pass`,
  - with line evidence (no naming gap, isolation mode unchanged),
  - and does not hit the site's `reachLine`.
- **Never dropped:** a codeunit holding ANY other test, for example:
  - a baseline-refused test;
  - a PR-250-cut test;
  - a failed, error, skipped, timed-out or unstable baseline test;
  - a test with no baseline row;
  - a green test without line evidence.
- **The mutant is then scored exactly as with the flag off:** a refused-cut `error` stays `error`.
- **Rule 4** (nothing left to run → `survived`) now applies only when every covering codeunit was droppable under this rule.

### Composing with `alRunnerV3.refusedCutTail` (PR-297; PR-302 measures it on DO)
- **What the flag does:** a stable green test after a baseline-refusal cut runs alone under the mutant.
- **Why pruning never touches it:** such a codeunit holds a refused test, so under the replaced rule it is never dropped.
  Its tail tests run alone exactly as with pruning off, and the flag's verdicts are unchanged by pruning.
- **A test pins it:** with both flags on, a codeunit with a refused test plus green tests that are all explicit-false is
  kept, its tail runs alone, and the verdict equals the pruning-off run's.

### Tests (red-going both ways, one per kind)
- **For each kind, the codeunit is kept and the verdict equals flag-off:** refused, PR-250-cut, failed, error, skipped,
  timed-out, unstable, missing row, green without lines.
- **The positive control:** a codeunit with ONLY green, line-evidenced, non-hitting tests is dropped.
- **The refusedCutTail case,** as above.
- **The round-1 shape as a regression test:** a refused-cut `error` stays `error` with the flag on.

### The prediction for the fresh series (written before it runs)
- **Every A `error` stays `error` in B:** B's error count equals A's, and the 120 return to `error`.
- **Verdicts and killingTests are identical in every arm** (BLOCK as before).
- **B still drops codeunits,** but fewer: those with a refused test now stay. The entries B/A will be above round 1's 0.846
  and should stay at or below 0.95.

### Normalisation of the speed bound (replaces "normalised per test" above)
- **The problem:** round 1's per-test normalisation divided by each arm's BASELINE seconds per baseline test. A1 ran under
  load 21 and B1 under load 9, and the baseline phase is short and load-sensitive. That penalised the quiet arm (raw B/A
  0.704, normalised 1.21).
- **The new measure:** normalise by the arm's mutant-phase box speed, the median over its `serve-request-timed` rows
  (prefetch and live) of `timings.testsMs / tests`. That is PR-274's measure, and it rests on thousands of requests.
- **The bound:**
  - per round, `(B.total / B.msPerTest) / (A.total / A.msPerTest)`;
  - the median over the three rounds ≤ 0.95.
- **Reported beside it:** raw B/A and each arm's load. BLOCK is unchanged.
