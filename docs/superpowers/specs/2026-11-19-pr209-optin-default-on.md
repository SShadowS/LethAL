## 1. What is true today (read from master 8ddd1736)
- Three operators are opt-in (`optIn: true`): `swap-workdate-today`, `condition-true` and `blank-argument`. An opt-in
  operator runs only when `--operator` names it (orchestrator.ts, `op.optIn !== true || admittedOperators?.has(...)`).
- There is no profile concept. `--exclude-operator` narrows the set, and the report flags it `operator-narrowed`.
- R868's hang rules (`optin-hang.ts`) apply to these two operators only. They refuse a mutant by name where it could make a
  loop or recursion endless, and they are not in `loop-hazard.ts`, so a default run never asks them today.
- Frozen baseline rows are keyed by site: `astHash | codeunit | procedure | operator | ordinal`, not by mutant code. New
  operators therefore add new keys and leave every existing key as it is.

## 2. The change
1. **`condition-true` and `blank-argument` lose `optIn`.** A default run generates them, with R868's hang rules applied (they
   go wherever the operators go). `swap-workdate-today` stays opt-in.
2. **The profile `slim`:** `--profile slim` on `run` and `campaign` (and the dry run).
   - It means exactly the old default set: every default operator except the two.
   - It is implemented as the same narrowing `--exclude-operator lethal.condition-true --exclude-operator lethal.blank-argument`
     makes, so the report flags it `operator-narrowed` and names what was left out. A slim report never reads as a full one
     (principle 17).
   - `--profile` with `--operator` is refused by name, as `--exclude-operator` with `--operator` is. With `--exclude-operator`
     it adds to the exclusions.
   - An unknown profile name is refused by name.
   - **The help text states the cost difference,** from PR-187: on DO, +12.7% mutants (5,526 on 43,511) at 0.91x the
     per-mutant cost, so about +11.5% wall. On the two BC.History apps, +81 and +154 mutants.
3. **Unchanged:** no verdict rule, no operator's own behaviour, no report field.
   - The new mutants' sites are reported as any default operator's are.
   - `large-fold.ts` already lists both operators.
