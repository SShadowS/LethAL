## Why
- PR-303 built whole-codeunit pruning behind `LETHAL_V3_REACH_PRUNE=on` (default off).
- Its DO slice A/B was safe (BLOCK 0), but the speed is unmeasured. Only one round had equal lanes (normalised B/A 0.994), and
  the slice dropped only about 8% of entries, against the ~30% PR-231's sizing gives for full DO.
- So whether the default can be ON is decided on FULL DO.

## Hard claims (BLOCK)
1. **0 verdict moves and 0 `killingTest` moves** between A and B in every round, joined on the full site key (file, line,
   operator, start and end index). The join must cover every mutant in both reports (equal key sets), or it is a BLOCK.
2. **Errors equal:** the `error` count is the same in A and B.
3. A move between A1 and A2 (when round 2 runs) is reported as A/A nondeterminism. It does NOT excuse an A/B move: any A/B
   move is a BLOCK, and the default stays off until it is explained.
- B's mutants recorded "pruned-survived without running" are counted. Each must be `survived` in A: that is claim 1 applied to
  them.

## The speed bound (PR-303 amendments 1, 2 and 4, unchanged)
- **Per round:** `(B.total / B.msPerTest) / (A.total / A.msPerTest)`.
  - `total` is the whole-run wall (`TIMING: total`, baseline included).
  - `msPerTest` is the arm's median over its `serve-request-timed` rows (prefetch and live) of `timings.testsMs / tests`.
- **Counting rounds:** a round counts only when A and B started the same number of lanes, and neither arm had a suspend inside.
- **The bound:** the median over the counting rounds is ≤ 0.95. With one counting round, that round's value.
- **Reported beside it:** raw B/A, entries sent B/A (`serve-request-timed`, prefetch and live; diagnostic, expected about
  0.70), each arm's load, the pruned-survived count, and the lanes line.
- **If no round counts** (unequal lanes or a suspend), speed is UNMEASURED again, and that is reported as such.

## The decision this feeds
- **Default ON** is proposed only if BLOCK holds AND the speed bound is met.
- **Otherwise:** BLOCK → default stays off, and the moves are the finding; bound missed → default stays off, and the numbers
  are reported.
- The decision itself goes to the orchestrator. No code changes in this task.
