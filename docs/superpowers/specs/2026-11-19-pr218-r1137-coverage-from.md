## 2. The change
1. **The flag** `--coverage-from <al-runner-v3 report.json>`: run only, for BC backends.
   - It reuses `--confirm-from`'s input checks (`confirm.ts`), with their typed errors, and refuses by name:
     - not a report;
     - not a v3 report;
     - a partial report;
     - a different source (`sourceSha256` under PR-177's rule) or identity scheme;
     - a duplicate site key.
   - **The join** is the full site key: file, line, operator, startIndex, endIndex.
2. **For each mutant that no remaining test covers on this run, and that is in (i)'s reach or covered by a left-out method
   in the source:**
   - **(a) Covered by at least one left-out method** in the source's `coveringTests`: **unmeasured**, with the cause
     `left-out-test-coverage`, naming those methods.
   - **(b) Not covered by any left-out method,** where **every** left-out method (i) relates to the mutant **passed** at the
     source's baseline: **`no-coverage`**, with a note saying the left-out tests ran in the named source and did not cover it.
   - **(c) Anything else:** **(i) unchanged** (`left-out-test-reach`). That covers a reaching method that was red, refused or
     absent in the source, and a mutant missing from the source.
   - **A green source test** is a test in the source's `testMethods` that is not in its `unsupportedTests` and not excluded or
     refused. If the report cannot show that, the run refuses by name; it never assumes green.
3. **No verdict moves for a mutant that a remaining test covers.** No change when the flag is absent: (i) exactly as PR-212
   built it.
4. **The report:**
   - the unmeasured list keeps PR-212's shape, with the cause per mutant (`left-out-test-coverage` or `left-out-test-reach`);
   - one line names the source and the counts (a), (b) and (c).

   If PR-212's list has no per-mutant cause field, the amendment adds the smallest one (the CLAUDE.md report ripple applies).
