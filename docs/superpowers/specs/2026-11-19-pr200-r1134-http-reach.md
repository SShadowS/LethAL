  reaching if ANY of its procedures sends; that is the noise this design removes.

## 2. The design
1. **A procedure graph, one index per source:**
   - **Dependency `.app` files** are selected exactly as R565's reader selects them (the same folders in the same order;
     per app id the first folder wins, then the highest version; the same ReadyToRun unwrap). The selection code is
     shared, not copied.
   - **A package with no source** contributes no procedures. Its calls are `unresolved` and counted.
   - **The project's own app** is read from the project's source. A package with the project's app id is skipped.
   - **The test app** is read from the test project's source.
2. **Per procedure or trigger, the index stores:**
   - `sends`: its body holds a call `v.Send|Get|Post|Put|Delete|Patch(...)` where `v` is a local, a global or a parameter
     declared `HttpClient`;
   - its out-edges, each to `(object kind, object name, procedure name)`. Names are normalized (case, quotes).
     Overloads are not told apart: an edge to a name reaches every procedure of that name in the object.
3. **The edges followed** (fixed here, not tuned on DO):
   - **E1:** a bare call `P(...)` → the same object's `P`.
   - **E2:** `v.P(...)` where `v` is declared `Codeunit|Record|Page|Report|Query|XmlPort "X"` → `X.P`. For `Record`,
     also every `tableextension` of `X`; for `Page`, every `pageextension` of `X`.
   - **E3:** `Codeunit.Run(Codeunit::"X" ...)` with a literal → `X.OnRun`. `v.Run()` on a codeunit variable is also
     `X.OnRun`.
   - **E4 (events):** a call to a procedure carrying `[IntegrationEvent]`, `[BusinessEvent]`, `[InternalEvent]` or
     `[ExternalBusinessEvent]` → every `[EventSubscriber(ObjectType::K, K::"X", 'P', ...)]` subscriber to `X.P` in the
     graph.
   - **Not followed, and named in the line:** implicit triggers (`Insert(true)`, `Validate`, table and page triggers
     and their platform events), interface calls, a `Codeunit.Run` with a non-literal id, `RecordRef`/`Variant`
     dispatch, `Report.Run`/`Page.Run` targets, and test handler functions.
4. **The starts and the verdict.**
   - **Starts:** each selected test method of a listed codeunit (open, handler or unread), plus that codeunit's `OnRun`.
   - **Search:** a breadth-first search over the graph, with out-edges in sorted key order, so the path is the
     shortest one and deterministic.
   - **A codeunit is `reaches`** when any of its starts reaches a procedure with `sends`. Its path is one chain
     `Codeunit.Method -> Object.Procedure -> ... -> Object.Procedure (HttpClient.<Method>)`.
   - **Otherwise it is `no path found`.** That is never "safe": the reach is partial by design (item 3).
5. **The cache:**
   - **Location:** `~/.lethal/http-reach/<sha256 of the .app file>.json`, through `homeDir()`.
   - **Contents:** a format version, the app id, name and version, and the procedures with `sends` and out-edges, plus
     publishers and subscribers.
   - **Validation:** a file whose version or sha does not match is rebuilt. A file that does not parse is rebuilt, with
     one stderr note. It is a cache, so a rebuild is the correct answer, never an empty one.
   - **Writes:** atomic (temporary file, then rename).
   - **The project and test sources** are parsed each run and not cached; they change between runs.
6. **The time cap.**
   - The whole reach, cold included, stops at 120 s.
   - On the cap, the line says the reach is `incomplete`, and the list prints unranked, exactly as PR-197 does today.
   - An error inside the reach is the same: unranked, plus one line naming the error. It never stops the run (PR-197's
     rule).
7. **The output** (both the progress renderer and `--dry-run`):
   - PR-197's first line is unchanged.
   - Then: `  K of them have a call path to an HttpClient send (listed first, one path each); the other N-K: no path
     found (the reach follows direct calls, codeunit and record variables, Codeunit.Run on a literal and events; not
     implicit triggers, interfaces or handlers).`
   - The K by name, each with its path, up to 10.
   - Then `  ... and N-K with no path found (the events file lists all)`.
   - **When K = 0** the list stays as today, with the count line.
   - **The event** `tests-discovered.httpPolicy` gains an optional `reach`: per listed codeunit `reaches` plus its path,
     the counts, `incomplete` with its reason, the packages read and without source, the cache hits and misses, and
     `ms`. The stream schema is regenerated.
   - **Never:** the reach does not decide whether the line prints, and it does not touch a verdict, a refusal or the
     report.
8. **Where it runs:** where `httpPolicyOf` runs now (the orchestrator before `tests-discovered`, and the dry run), and
   only when the list is non-empty. The packages are `dependencyPackageDirs` (the backend's own, then the config's).

## 3. Pre-committed predictions (DO, before any build; checked by a dry run against do-lethal's config)
1. **Both hung codeunits are `reaches`:** `CDO Azure Blob Folder Tests` and `CDO ABS Auth Settings Tests`.
   - Also the hung METHODS themselves: a path from each of the two named methods is found. That is measured
     separately, by the same search started from that method alone.
2. **`CDO Data Upgrade Tests` is `no path found`.**
3. **The count:** `reaches` ≤ 56 (half of 113). Above that, the ranking is reported as not useful on DO and does NOT
   land as a default (the line stays as PR-197 made it). This is a stop rule, not a tuning target: no edge rule changes
   after the first DO measurement without a new pre-commitment.
4. **Cost:**
   - with a warm cache, the reach adds ≤ 3 s to DO's dry run (project 814 files plus test 114, parsed each run, plus
     21 cached indexes);
   - cold, ≤ 60 s, once per `.app` sha.
5. **The frozen gates:** no figure moves (the reach changes stderr lines and one optional event field only).

## 4. Tests (each red-checked: revert, the named test goes red, restore)
- Per edge rule E1-E4: a fixture graph where only that edge reaches a send, so the codeunit is `reaches`. Removing the
  rule turns the test red.
- **The negative:** a codeunit whose only path is through a not-followed edge (an implicit trigger) is `no path found`.
- **No overreach:** a procedure in a sending object that does not itself send is not counted. This is the object-level
  noise, pinned.
- **The cache:**
  - a second run reads the cache and parses no package;
  - a changed `.app` sha rebuilds;
  - a corrupt file rebuilds with the note.
- **Robustness:** the cap or an error gives the unranked list plus the reason line, and the run continues.
- **The lines:** the found group first, by name with paths; the rest as a count; K = 0 is unchanged from PR-197.
