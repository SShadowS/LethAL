# Tier-2 Phase 1 Implementation Plan — the first real Tier-2 operators

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ship the four Phase-1 Tier-2 operators from the spec — `RemoveTestField`, `RemoveSetRange`, `RemoveCalcFields`, `SwapModifyFlag` — with a fixture built so a *broken* operator fails, and a frozen live baseline.

**Architecture:** operators live in a new `packages/builtin-tier2`, registered alongside Tier 1 through the existing operator SDK. `dedupeSpecs` already resolves Tier-1/Tier-2 collisions by tier precedence; this is the first work that actually exercises that branch. Nothing in the schemata/runner pipeline changes shape — Phase 0 already made it table-safe.

**Tech Stack:** Bun + TypeScript monorepo, tree-sitter-al AST, `bun:test`, env-gated live gates against a real BC server.

**Spec:** `docs/superpowers/specs/2026-07-25-tier2-mutation-operators-design.md` — §4 defines the operators, §4.1 the receiver rule, §6 the fixture, §7 verification. Read §4.1 before writing any predicate.

## Global Constraints

- No `!` non-null assertions (biome `noNonNullAssertion: error`). Destructure, then check `undefined`. The repo also runs `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` (optional props via `...(v !== undefined ? { k: v } : {})`).
- Typed error classes extend `Error` **directly**, never each other.
- **Fail loudly on caller-contract violations — throw, never return a plausible empty default.** "Empty-vs-empty matches" is this project's signature bug.
- **Matching is case-insensitive.** AL is case-insensitive: `Modify(TRUE)`, `MODIFY(True)`, `Rec.SETRANGE(...)` are the same sites. A lowercase-only predicate silently misses real code.
- **A test that passes for the wrong reason is the recurring hazard.** Red-check every operator predicate: revert it, confirm its specific test goes RED, restore.
- Per-mutant equality is the gate. Aggregate counts matching for the wrong mutants is a failure.
- Build loop, order matters: `bun run typecheck` → `rm -rf packages/*/dist` → `bun test` → `bunx biome check <touched files>`.
- Git bash on Windows; never `2>nul` — use `2>/dev/null`.

## R1 is refuted — there is no trigger/non-trigger split

An earlier draft of this plan split the wave because `SwapModifyFlag` needs a `Modify` (a write), and
writes were believed to fail on the fenced path. **That was wrong**, and the correction matters for
scoping: the deciding factor is the `TestPermissions` property on the *test codeunit*, not the
invocation path. A codeunit that omits it defaults to Restrictive and cannot write on **any** runner;
one declaring `TestPermissions = Disabled` writes fine everywhere, mock installed or not. Real suites
declare it (Continia Document Output: 77 of 77 codeunits, `InherentPermissions` on zero tables).

Our fixture omitted it, and the `InherentPermissions` workaround added to make it pass was hiding a
fixture defect that then got generalised into a platform limitation. Both are now fixed (`769f667`):
the property is declared, the workaround is gone, and `itest:tables` passes per-mutant at the frozen
3/2/2 with the `OnInsert` mutant scoring.

**So build all four operators together.** The only residue is a *reporting* concern, already handled:
when a target suite's test codeunit omits the property, LethAL names the cause on the failure rather
than reporting a bare `unstable`.

### Task 2: the receiver-resolution predicate (shared by every operator)

**Files:**
- Create: `packages/builtin-tier2/src/receiver.ts`, `packages/builtin-tier2/tests/receiver.test.ts`

**Interfaces:**
- Consumes: `ALSyntaxNode`, the semantic context type from `@lethal/engine`.
- Produces: `export function claimsRecordMethod(node: ALSyntaxNode, ctx: SemanticContext, methodName: string): boolean`

This is the single highest-risk unit in the wave: **every operator's correctness rests on it**, and a wrong `true` both mislabels a mutation and, under dedup precedence, suppresses a correct Tier-1 mutant.

- [ ] **Step 1: Write the failing tests — one per rule in spec §4.1**

```typescript
import { describe, expect, it } from "bun:test";
import { claimsRecordMethod } from "../src/receiver";
// Parse helpers: follow packages/builtin-tier1/tests/*.test.ts's existing shape.

describe("claimsRecordMethod", () => {
  it("claims the implicit-receiver form inside a trigger body", () => {
    // `TestField("No.");` with no receiver — Rec is implicit. These ARE the
    // trigger-body sites Tier 2 exists for; a predicate requiring `<rec>.` misses its own purpose.
    expect(claimsRecordMethodFor('TestField("No.");', "TestField")).toBe(true);
  });

  it("claims a qualified record receiver", () => {
    expect(claimsRecordMethodFor('Rec.TestField("No.");', "TestField")).toBe(true);
  });

  it("is case-insensitive on the method name", () => {
    expect(claimsRecordMethodFor('Rec.TESTFIELD("No.");', "TestField")).toBe(true);
  });

  it("REFUSES a receiver that resolves to a non-record in source", () => {
    // `Validator: Codeunit "My Validator"` — a call on it is not the AL record method.
    expect(claimsRecordMethodFor('Validator.TestField(X);', "TestField", { Validator: "Codeunit" })).toBe(false);
  });

  it("REFUSES a name that resolves to a procedure declared in the project", () => {
    // A local `procedure TestField()` shadows the builtin for matching purposes.
    expect(claimsRecordMethodWithLocalProc('TestField(X);', "TestField")).toBe(false);
  });

  it("REFUSES when the receiver cannot be resolved at all", () => {
    // Missing a Tier-2 site costs one operator's signal; claiming a wrong one
    // emits a mislabelled mutation AND can suppress a correct Tier-1 mutant.
    expect(claimsRecordMethodFor("Unknown.TestField(X);", "TestField")).toBe(false);
  });
});
```

Write the small `claimsRecordMethodFor` / `claimsRecordMethodWithLocalProc` helpers in the test file: parse a snippet, build a semantic context, find the call node, call the predicate. Follow how `packages/builtin-tier1/tests/` builds its contexts — do not invent a second convention.

- [ ] **Step 2: Run — expect every case to fail**

Run: `bun test packages/builtin-tier2/tests/receiver.test.ts`

- [ ] **Step 3: Implement**

Resolve in this order, returning `false` at the first uncertainty: (1) the call's method name matches `methodName` case-insensitively; (2) the name is not a project-declared procedure; (3) if there is a receiver, it resolves in the symbol table to a `Record`, and nothing else; (4) if there is no receiver, the enclosing object is a table (implicit `Rec`).

- [ ] **Step 4: Verify, then red-check the refusals**

Run the suite. Then for each of the three REFUSE cases: invert that specific guard, confirm that specific test goes RED, restore. A refusal that isn't load-bearing is the dangerous kind of green.

- [ ] **Step 5: Commit**

```bash
git add packages/builtin-tier2/src/receiver.ts packages/builtin-tier2/tests/receiver.test.ts
git commit -m "feat(tier2): receiver resolution — the rule every operator predicate depends on"
```

### Task 6: `SwapModifyFlag`

**Files:** `packages/builtin-tier2/src/swap-modify-flag.ts` + test; register.

**This one is deliberately NOT statement-position restricted, and that is load-bearing.** It rewrites an argument (`Modify(true)` → `Modify(false)`) rather than deleting, so it is safe in any position. Restricting it would miss `if Rec.FindSet() then Rec.Modify(true);` — a routine BC idiom, and the grammar probe measured exactly that shape in the fixture, where `Modify` was the only targeted call that did *not* reach statement position.

- [ ] **Step 1: Failing tests** — rewrites `Modify(true)` in statement position **and** as an `if`-then-branch; **refuses `Modify(SomeBoolean)`** (literal `true` only); case variants `Modify(TRUE)`, `MODIFY(True)`; refuses a non-record receiver.
- [ ] **Step 2: Run — expect FAIL.**
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run — expect PASS.**
- [ ] **Step 5: Red-check** the then-branch case (restricting to statement position must turn it RED) and the non-literal refusal.
- [ ] **Step 6: Commit** `feat(tier2): SwapModifyFlag — argument rewrite, any position`.

### Task 8: the fixture that makes a broken operator fail

**Files:** extend `fixtures/sandbox-data` (its `InherentPermissions` workaround is already in place — leave it and its comment alone).

Every shape below exists because its absence lets a *broken* operator pass. Build all of them:

- [ ] Out-of-filter **decoy rows** — without them `RemoveSetRange` survives on data starvation and proves nothing.
- [ ] Seeded **related-table rows** — without them the FlowField computes 0 either way and `RemoveCalcFields` is equivalent.
- [ ] **`asserterror` negative tests** — without them `RemoveTestField` survives trivially and the baseline's "real kills" claim is false.
- [ ] A **`Validate()`-driven path**, so `OnValidate` fires from test code.
- [ ] **Negative targets a sloppy predicate would wrongly claim**: a user-defined `procedure Commit()` *plus a call to it*, `Insert(false)`, `SetRange(F)` with no value, `SetLoadFields()` with no arguments, `Modify(SomeBoolean)`.
- [ ] **User-defined methods sharing a builtin name, taking arguments, with observable side effects**: `Loader.SetLoadFields(FieldNo)`, `Validator.TestField(X)`, `Builder.SetRange('A','Z')`. The no-argument negatives do **not** catch a predicate that matches any same-named call with arguments — and under dedup precedence that bug also suppresses a correct Tier-1 mutant.
- [ ] **Implicit-receiver positives inside trigger bodies**: an unqualified `TestField(...)` and `Modify(true)`.
- [ ] **Case variants**: `Modify(TRUE)`, `Rec.SETRANGE(...)`.
- [ ] **Both `TestField` overloads** — a one-argument-only implementation must fail.
- [ ] A **weak positive test** calling `TestField` without asserting, so a genuine survivor sits alongside the `asserterror` negatives.

- [ ] **Verify with an offline `alc` compile** of the instrumented fixture (`al-compile` skill or the `al-compiler` subagent) — the only thing that settles AL member ordering and emitted-AL validity. Commit.
