# Tier-2 Phase 0 Implementation Plan — make the compiler table-safe

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make LethAL able to instrument and attribute mutations inside AL **table** objects, and dedup colliding mutants before they reach the artifact — the three prerequisites Tier-2 operators cannot be built without.

**Architecture:** Three independent deliverables against `packages/schemata` and one coverage-key change in `packages/runner`. No mutation operators are written in this phase. Implements §3 of `docs/superpowers/specs/2026-07-25-tier2-mutation-operators-design.md`.

**Tech Stack:** Bun, TypeScript, tree-sitter-al v3.0.1 (vendored), `alc.exe` for AL verification, live BC container for the gate.

## Global Constraints

- **AL table member ordering is already measured — do not re-derive it.** Against `alc` 18.0.38.8509: `var` before `fields` is a **hard syntax error** (AL0107/AL0104/AL0198, parse does not recover); `var` after `fields`/`keys`/`fieldgroups` compiles clean; `var` as the trailing member with only a field-level `OnValidate` compiles clean. The codeunit strategy ("insert before the first member") is therefore INVALID for tables.
- **v3 grammar shape:** members of both codeunits and tables sit inside a `declaration_body` container; a `code_block`'s statements sit inside `statement_block`; a `var_section`'s declarations sit inside `var_body`. Use `declarationMembers`, `blockStatements`, `varDeclarations`, `isStatementPosition` from `@lethal/engine` — **never hand-roll a parent-kind check.** Seven sites did that during the v3 upgrade and each silently matched nothing.
- **Frozen live baselines:** bcdev **3 killed / 10 survived / 3 no-coverage**, al-runner **3 / 13 / 0**, both per-mutant. A differing verdict is a BLOCK. If a per-mutant baseline flags a difference, prove it per-site before re-recording — see `packages/engine/vendor/README.md` step 5 for the procedure.
- **Unit baseline entering this plan: 623 pass / 0 fail.** Typecheck and biome clean.
- **Build loop (order matters — the dist trap):** `bun run typecheck` (`tsc --build --force`), then `rm -rf packages/*/dist`, then `bun test`. Stale compiled `*.test.js` under `dist` cause ~21 phantom failures.
- **Conventions (CI fails otherwise):** no `!` non-null assertions; `exactOptionalPropertyTypes` (optional props via `...(v !== undefined ? { k: v } : {})`); typed error classes extend `Error` directly; fail loudly on caller-contract violations, never a plausible empty default.
- **AL has no unit-test harness here.** Emitted AL is verified by an offline `alc` compile. `alc.exe` lives under `~/.vscode/extensions/ms-dynamics-smb.al-*/bin/win32/`; symbol packages (including `System.app`, which is required and easy to miss) are in `extensions/lethal-control/.alpackages/`.

```typescript
/**
 * Name of the enclosing `trigger_declaration`, or `undefined` outside one.
 *
 * Trigger bodies have no enclosing `procedure`, so `procedureNameOf` returns
 * `""` for them. That empty string becomes the coverage key `<objectId>::`,
 * which matches no coverage entry and silently classifies every trigger mutant
 * as no-coverage — no error, no failing test, just a tier that appears to have
 * nothing to run.
 */
function triggerNameOf(spec: MutationSpec): string | undefined {
  let current: ALSyntaxNode | null = spec.before;
  while (current !== null) {
    if (current.kind === ALNodeKind.trigger) {
      const nameNode = current.childForFieldName("name");
      return nameNode === null ? undefined : stripQuotes(nameNode.text);
    }
    current = current.parent;
  }
  return undefined;
}
```

```typescript
import type { MutationSpec } from "@lethal/engine";

/**
 * Resolves an operator's tier by name.
 *
 * `MutationSpec` carries no tier — tier is a property of the OPERATOR
 * (`packages/engine/src/operator/interface.ts`), and a spec records only which
 * operator produced it. The caller therefore supplies the mapping rather than
 * dedup inventing one.
 */
export type TierResolver = (operatorName: string) => 1 | 2 | 3 | "custom" | undefined;

/** Identity of an emitted mutation: same site, same replacement text. */
function identityOf(spec: MutationSpec): string {
  return `${spec.before.startIndex}:${spec.before.endIndex}:${spec.after.text}`;
}

function tierRank(spec: MutationSpec, tierOf: TierResolver): number {
  // Specificity, not registration order. `custom` has no defined position and an
  // unregistered operator has no tier at all; both are caller-contract
  // violations rather than precedence questions — see the throws below.
  const tier = tierOf(spec.operatorName);
  return tier === 2 ? 2 : tier === 1 ? 1 : Number.NaN;
}

/**
 * Drop mutants that would emit byte-identical AL at the same site, keeping the
 * more specific operator.
 *
 * Runs BEFORE `assignMutantIds` and before compilation: dropping a mutant only
 * from the manifest would leave it compiled into the dispatch chain holding an
 * ID — an unreported mutation that still exists in the artifact.
 *
 * A `likely-equivalent` mutant never suppresses a scored one. Otherwise an
 * overbroad Tier-2 predicate would replace a fully scored Tier-1 mutant with one
 * excluded from the mutation score, hiding both the real mutant and the bug.
 */
export function dedupeSpecs(
  specs: readonly MutationSpec[],
  tierOf: TierResolver,
): readonly MutationSpec[] {
  const winners = new Map<string, MutationSpec>();
  for (const spec of specs) {
    const id = identityOf(spec);
    const held = winners.get(id);
    if (held === undefined) {
      winners.set(id, spec);
      continue;
    }
    if (tierOf(held.operatorName) === tierOf(spec.operatorName)) {
      throw new Error(
        `dedupeSpecs: operators "${held.operatorName}" and "${spec.operatorName}" both claim the ` +
          `same mutation at ${spec.before.startIndex}-${spec.before.endIndex}; the winner would ` +
          `depend on registration order`,
      );
    }
    const heldHinted = held.equivalenceHint === "likely-equivalent";
    const specHinted = spec.equivalenceHint === "likely-equivalent";
    if (heldHinted !== specHinted) {
      winners.set(id, heldHinted ? spec : held);
      continue;
    }
    const rank = tierRank(spec, tierOf);
    const heldRank = tierRank(held, tierOf);
    if (Number.isNaN(rank) || Number.isNaN(heldRank)) {
      throw new Error(
        `dedupeSpecs: cannot order "${held.operatorName}" against "${spec.operatorName}" at ` +
          `${spec.before.startIndex}-${spec.before.endIndex} — one of them is unregistered or ` +
          `custom-tier, and neither has a defined precedence against a builtin`,
      );
    }
    if (rank > heldRank) winners.set(id, spec);
  }
  return [...winners.values()];
}
```

- [ ] **Step 2: Publish and prove the exit criterion**

Per spec §3.4, ALL of these must hold — a single successful trigger mutant is not sufficient:

1. A table with `fields`, `keys`, an **existing** `var` section and **multiple** triggers instruments and compiles under real `alc`.
2. Both a **table-level** trigger (`OnInsert`) and a **field-level** trigger (`OnValidate`) are proven — they are different insertion contexts and one can work while the other is broken.
3. A trigger mutant carries a non-empty `triggerName` in the manifest (Task 1).
4. A dedup fixture proves a Tier-2 mutant replaces a colliding Tier-1 mutant **before ID assignment** — the suppressed mutant is absent from the emitted artifact, not merely from the manifest (Task 2).
5. Live: **both a kill and a survive** on trigger sites. A kill alone can come from a runtime error unrelated to any assertion.
6. Existing Tier-1 baselines (bcdev 3/10/3, al-runner 3/13/0) re-run and unchanged per-mutant.
7. al-runner's behaviour on table triggers is established — executed, or documented as unsupported.

## Notes for the implementer

- **Task 1 is first on purpose.** If BC does not report coverage for trigger code at all, Tier 2's trigger operators are unreachable and the rest of this plan is premature. Answer it before building anything.
- **The failure mode throughout is silence.** An empty `procedureName`, a `find()` that returns `undefined`, a dedup that runs too late — none of these throw. Each produces a plausible-looking result with fewer mutants. When a step says "confirm it fails for the right reason", that is the reason.
- **Never hand-roll a node-shape check.** Seven sites did during the v3 upgrade and every one silently matched nothing. The helpers are in `packages/engine/src/ast/tree-walks.ts`.
