**Filed 2026-10-22 by lethal-bugs during R-658** (orchestrator ruling D-D on R-658's itest:hang BASELINE-leg
pre-commitment).

**What.** When a live probe or gate's STOP rule fires, the lane:
- keeps that server's coord lease, in a heartbeat-only hold;
- writes a durable marker, `/coord/machine/out-of-use/<server>.md`, giving the server, the time, the reason, the op
  id, and how to clear it;
- tells the orchestrator.

The marker survives a SIGKILL that ends the hold, which the heartbeat does not. The first one is
`/coord/machine/out-of-use/bc3.md`, from R-658's probe.

But nothing reads the marker. If the hold lapses (the session ends, TaskStop, or the OOM killer), the coord lease
expires, and `bun scripts/bc-linux-setup.ts --server <it>` or any BC itest would run against a server that may still
carry a live session under a tombstoned marker. The control-app lease and `lethal doctor` read such a server clean
(R658's D2 reading).

**To close.** `bc-linux-setup.ts`, and the itest server selection (`LETHAL_ITEST_CONFIG` and the `[itest target]`
line), refuse by name when that server's marker exists, and print its reason and how to clear it.
- Decide the override: probably none, because clearing the marker is the step.
- Decide whether `lethal doctor` should report it. It reads no `/coord` path today, so probably not: that is
  machine-local.
- Tests must stub the `/coord` path and never touch the real one.

Evidence: R658; R-658's pre-commitment for the itest:hang BASELINE leg; `/coord/machine/out-of-use/bc3.md`.

**Done 2026-10-22 (R-669, lethal-bugs), code head 9210ba70.** The check lives in `packages/runner/itest/out-of-use.ts`.
- **Which servers.** A server is checked only when it is bc1-bc3, identified by host `192.168.2.157` plus its dev port
  (7049, 7149 or 7249). Other hosts and ports are never checked: Cronus28, envtool and the demo port.
- **A missing `<root>/machine` throws by name** (`OutOfUseRootError`). So a wrong coord root never reads as "no
  marker". The coord root resolution copies the kraken mismatch refusal of `resolveRoot`.
- **`bc-linux-setup.ts`** checks every target server before the login read, the lease or any connect, in every mode.
  One marked server refuses the WHOLE run, by name, and prints the marker. The only way through is
  `LETHAL_OUT_OF_USE_CLEARING=<that exact server>`, for the clearing step, with a loud log line.
- **`scripts/bc-republish.ts`** refuses the same way before its lease. It accepts only the clearing override.
- **Every BC itest** reaches the check through `printItestTarget`. That covers 14 itests, and a source pin enforces
  it. On a marker, the check throws BEFORE the `[itest target]` line is printed, so a script that greps that line
  fails closed.
  - The itests accept only `LETHAL_OUT_OF_USE_OWNER=<token>`. It passes a marker that has exactly one
    `owner: <token>` line, and `<token>` must be 32 lowercase hex. It is meant for a gate's own "in use" marker, from
    a wrapper that makes the token fresh for each run (`openssl rand -hex 16`).
  - Two owner lines, a malformed one, or a STOP-rewritten marker with no owner line all refuse.
- **`lethal doctor`:** no change, by design. It reads no `/coord` path.
- **Tests:** every test uses a temp marker directory. Each guard has a red test in each direction.
- **Review:** the Opus build review's fixes and the orchestrator's belt are applied.
- **Follow-up.** R-658's hang wrapper must adopt the owner token, refuse an existing marker before its lease, check its
  offline call's exit status, and write the owner line only in its in-use marker. That is a delta to R-658's leg
  pre-commitment.
