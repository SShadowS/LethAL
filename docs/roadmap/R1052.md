Found by coord PR-37's Opus review (2026-11-15), invented AL `/coord/handoff/PR-37/review/app/src/Shapes.Codeunit.al` (cases H and
I), dry runs on the PR-37 head. Related: [[R830]], [[R1050]], [[R446]], [[R239]], [[R829]].

**H. A progress call inside an assignment.** `while Pos < N do begin if Go then begin X := AdvE(Pos); end; end;` where the
same-object `AdvE(var P)` moves `P`. R830's `callIsProgress` is asked only of a statement call (`deletedCallHangs`), so neither
`remove-assignment` of `X := AdvE(Pos)` nor `empty-block` of the `if` block (R1050's rule 2 matches the one-by-one refusals, and
there is none) is refused. Deleting the assignment deletes the call; both hang.

**I. A block holding the loop's only exit.** `repeat I += 1; if I > 10 then begin GDone := true; exit; end; until false;` — emptying
the `if` block removes the only way out. No operator deletes an `exit` statement on its own, so nothing refuses the block today
(before and after PR-37). [[R446]] covers a body guard's counter (`remove-assignment`), not emptying the guard's block.

**Why it matters.** Both strand a BC server run without `--stop-hung-sessions` (PR-34's incident class). Neither shape was met in
a corpus run yet; both are cheap to write.

**Possible fix.** H: treat a call anywhere in a statement's right side as that statement's call for R830 (`remove-assignment`, and
rule 2's block test). I: refuse `empty-block` of a block inside a loop when the block holds an `exit`/`break` (or an `Error`) and the
loop's own condition cannot end it (`until false`, `while true`), the R446 shape's block form. Measure the corpus cost first (R1050's
method: dry runs before/after, earlier v3 verdicts of the newly refused sites).
