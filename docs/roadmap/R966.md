Found by lethal-code, 2026-11-13 (coord R-951, a live DO run stopped with SIGTERM). Related: [[R955]].

**What.** R955 made SIGTERM/SIGINT stop a run through the time-budget path, so a stopped run writes its report, and the report is right:
`timeBudget.stoppedBySignal: true` and `baselineStopped {testsRun: 8, testsTotal: 1979}` (`/coord/handoff/R-951/r1run/`). But the
console printed, after 38 minutes of a 3600 s budget:

```
TIME BUDGET REACHED IN THE BASELINE: 8 of 1979 test(s) ran.
TIME BUDGET REACHED: --time-budget 3600 s used up; 43583 mutant(s) left out of this report, ... Run with --resume to continue.
```

The live progress line (`progress-renderer.ts`, the `time-budget-reached` event) and the stderr tail do not separate a signal stop from a
spent budget; R948's memory stop has its own wording, so only the signal case is left. A reader of the console concludes the budget was
too small.

**Wanted.** The progress line and the stderr tail say "STOPPED BY SIGNAL" (and, in the baseline, where) when `stoppedBySignal` is set,
as the report's banner does; a test pins the text for each of the three stop causes (budget, signal, memory).
