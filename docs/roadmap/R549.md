title: "`claimsSystemCall` inside a `pageextension` can claim a bare `Commit()` that binds a procedure of the BASE page"
section: "correctness-risks"
status: "open"

**Found by the R-463 plan review (opus spec-adversary, adversary-r1 finding 1, 2026-10-09).** The same hole
R-463 closed for a `reportextension`, one object kind over.

`claimsSystemCall` (`packages/engine/src/semantic/receiver.ts`) refuses a bare `Commit()` when the enclosing
object, or a project table or tableextension of a record scope there, declares a procedure of that name. A
bare name inside an extension can also bind a procedure of the extended (BASE) object: measured with alc
18.0.43 for a reportextension (`I := Commit();` compiles against a base report's `procedure Commit():
Integer`). A pageextension's base page is usually a dependency this project cannot see, and its implicit
`Rec` has no provable table (so the record-scope half of the guard is skipped). Then `remove-commit` claims a
call that is a project-or-dependency procedure, dedup suppresses Tier-1 `void-method-call` at that site, and
a kill can carry the wrong `write-txn-codeunit-run` label.

R-463 refused every site inside a reportextension (master never claimed there). A pageextension has been
claimable since R30, so refusing there costs real sites: count them first.

**To build it.** Measure with alc whether a pageextension's bare `Commit()` binds a base page procedure of
that name. If it does, refuse inside a pageextension unless the base page is in the project, unique, and does
not declare the name; red-test both directions.

**Measured (R-547 plan, alc 18.0.43, `/coord/handoff/R-547/measure.md`).** A bare `Commit()` in a
pageextension BINDS a visible base page `procedure Commit` (with or without a return value, same app or a
dependency app); a `local` one is invisible. On every corpus all 6 bare `Commit()` in pageextensions are claimed
by master and all are correct (no procedure named Commit anywhere), and 5 of their 6 base pages are
dependencies, so the rule as filed above would have refused 5 correct claims. Ruled: refuse only on project
evidence.

**Built (coord task R-547, branch `lethal/r547`, commit 8ebc888c).** `claimsSystemCall` inside a pageextension
refuses when ANY project base-page candidate declares a visible procedure of that name
(`basePageDeclaresVisible` in `receiver.ts`): every page of the `extends` name, indexed or `#if`-wrapped in any
arm, plus a split-header or unparsed object whose text names a page, the base and the name (the
`identifierTokens` rule). Visible means not `local`; `internal` counts (the base is in this app); a split
procedure is visible if any arm the build keeps is non-local. No candidate keeps the claim. Tests in
`packages/engine/tests/semantic/r549-pageext-commit.test.ts`: refuse (public, internal, ambiguous, undecided
`#if` arm, split header, split procedure with a live non-local arm) and keep (no Commit, local, dependency base,
split procedure whose only live arm is local), each red-checked (`/coord/handoff/R-547/build.md`). Expected
corpus effect 0.

**Residuals (named, not built; each measured at 0 in every corpus, no procedure named Commit anywhere).**
- A public `Commit` on a DEPENDENCY base page is mis-claimed. A mis-claim removes a call to a page procedure:
  still a real mutant, at worst with a wrong `write-txn-codeunit-run` tag, never a false kill.
- A `Commit` declared on the base page's `SourceTable` or its tableextensions.
- A sibling pageextension's public `Commit` (unmeasured whether it binds).

**Over-match, stated (opus build review, finding 4).** The token fallback refuses on ANY split-header or
unparsed object whose text holds the tokens `page`, the base name and `Commit`, whether or not it is that page
and whether or not its `Commit` is local. The safe direction, but looser than a structural read. The re-dump
should confirm BaseApp's `MfgMovementWorksheet` still claims. A pageextension whose `extends` name cannot be
read (parse damage) refuses; pinned by test, red-checked.
