**Found by the R-463 plan review (opus spec-adversary, adversary-r1 finding 1, 2026-10-09).** The same hole
R-463 closed for a `reportextension`, one object kind over.

`claimsSystemCall` (`packages/engine/src/semantic/receiver.ts`) refuses a bare `Commit()` when the enclosing
object, or a project table or tableextension of a record scope there, declares a procedure of that name. A
bare name inside an extension can also bind a procedure of the extended (BASE) object: measured with alc
18.0.43 for a reportextension (`I := Commit();` compiles against a base report's `procedure Commit():
Integer`). A pageextension's base page is usually a dependency this project cannot see, and its implicit
`Rec` has no provable table (so the record-scope half of the guard is skipped). Then `remove-commit` claims a
call that is a project-or-dependency procedure, dedup suppresses Tier-1 `void-method-call` at that site, and
a kill can carry the wrong `write-txn-codeunit-run` label.

R-463 refused every site inside a reportextension (master never claimed there). A pageextension has been
claimable since R30, so refusing there costs real sites: count them first.

**To build it.** Measure with alc whether a pageextension's bare `Commit()` binds a base page procedure of
that name. If it does, refuse inside a pageextension unless the base page is in the project, unique, and does
not declare the name; red-test both directions.
