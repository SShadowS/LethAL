**Filed 2026-10-24 by lethal-preproc during R-725** (opus review, probe P3). Related: [[R725]], [[R720]], [[R521]].

**What.** `declaredType`'s text fallback looks for a declaration only directly under `var_section`/`var_body`. It never
descends into preprocessor nodes. So a CALLEE receiver declared inside a var-section `#if`, or every-arm-ambiguous
(for example `Cap: Codeunit "X"` in both arms), gets no type. `callTargets` and `r570Targets` then return nothing, so
no R570/R572 row is built, and R500 shape 2 and `r696CalleeInserts` do not follow the call either. Measured on R-725's
R572 fixture with `Cap` in those two forms: the stateful callee is NOT refused. A swallowed member is refused,
through R725's own fix.

R521's ruling classes (RecordRef, Variant, parameter, array element, Report/Page, interface) do not include
`#if`-declared receivers, so this is not already ruled.

**To close.** Either let the text fallback descend preprocessor nodes inside var sections, reading every arm (a
receiver typed differently per arm is then "unknown", so all its targets are followed, or it refuses), or rule it with
a measured reach. `declaredType` is a private function of `packages/builtin-tier1/src/loop-hazard.ts`, but every hang
reader there uses it, so measure the cost by parse on all four corpora first.

**Done 2026-10-24 by R-737 (lethal-bugs), code `2cd47ee7`.** Pre-commitment:
`docs/superpowers/specs/2026-10-24-r737-preproc-receiver-precommitment.md`.

- **Cause.** The text fallback of `declaredType` walked only `var_section`/`var_body`, never a preprocessor node. A
  receiver declared in a var-section `#if` got no type, so no follow reader reached its callee.
- **Fix** (behind `r737Seam`; off is master). `declaredTypes` returns every type the receiver may have. The walk
  descends `preproc_*` nodes (not split procedures, whose locals are another procedure's) and skips inactive arms.
  A declaration is certain under no `#if`, or in a live arm of a decided file. A certain local wins alone; else the
  local's uncertain declarations join the object's. An undecided file reads every arm. `declaredType` stays "exactly
  one type, else null". Follow readers (`callTargets`, `r570Targets`, `r531TableProcs`, `r572RunTargets`) use the
  union; `r568StopsAt` and `argWritten` guard an ambiguous receiver (never stops / `unknown`). The guards are untested:
  the census found 0 ambiguous receivers on every corpus (`ponytail:` comments name that ceiling).
- **Tests** (`r725-unknown-readers.test.ts`, T1-T6, seam on and off): each direction goes red when reverted.
- **Census** (parse only, `scripts/r737/reach.ts`): receivers bound to a preprocessor-wrapped declaration: fixtures,
  DO, CDO 0; DC 30; BaseApp 236. Ambiguous: 0 everywhere.
- **Cost** (`scripts/r737/cost.ts`, `/coord/handoff/R-737/cost/`): specs removed / added: fixtures, DO, CDO 0 / 0; DC
  7 / 0 (all in `CDCAllocationAccountMgt.Codeunit.al`); BaseApp 2 / 0 (the callee `ManufacturingSetup.Table.al`
  `IsFeatureKeyFlushingMethodManualWithoutPickEnabled`, reached from loops in `MfgCreateInventoryPutaway` and
  `MfgCreateInvtPickMovement`). Nothing was added. The refusals land in the callee's file, not the caller's, which
  the pre-commitment's C3 wording missed.
