**Filed 2026-10-01 from R387, plan section 2b.** R387 made `alRunner.coverage` reachable from the
config and guarded it, but kept it OFF by default, because turning it on moves verdicts. Without
coverage every mutant runs every green test, so an unreached mutant reads `survived`; with it, the
same mutant reads `no-coverage`. The advisory line R387 added names `coverage` on every al-runner run
until this lands.

## Done (2026-10-11, R-394)

**The flip.** `effectiveAlRunnerTransport` (`packages/runner/src/cli.ts`) now defaults `coverage`
to `"al-runner"`. `"alRunner.coverage": "none"` still turns it off.

**The guard runs on the default (a must-fix the review found).** `applyAlRunnerCoverageGuard`
returned early unless the config SET `"al-runner"`, so a default-on run would have skipped the
R407 frame probe and the R298 wrapped-shape refusal. It now acts on the effective coverage. A
project either guard refuses runs with coverage `"none"` (set explicitly in the returned config)
and one `al-runner-coverage-unsupported` warning. That warning now says al-runner coverage ("on by
default" or "set by" the key) is turned OFF for the run; it no longer says a key the user never set
is IGNORED. The advisory line prints no coverage note under the default; under an explicit
`"none"` it names the key and what it costs (an unreached mutant reads survived, and every mutant
runs every green test). The guard's turned-off line is unchanged. Unit tests in
`packages/runner/tests/cli-al-runner-defaults.test.ts`, red-checked per direction.

**Pre-committed and re-frozen.** `docs/superpowers/specs/2026-10-11-r394-coverage-default-precommitment.md`:
only `itest:alrunner`'s CLI-default leg moves, 3 / 16 / 0 to 3 / 12 / 4, with `SandboxPricing`'s
four mutants `survived` to `no-coverage`, and every row then equal to leg A's. Re-recorded under
R332 (`al-runner.cli-default.baseline.json`); every other leg passed against its unchanged baseline.
The new file records `identityScheme` 40 (master's current scheme; the old file said 38) and
`coverageFiltered` true on the four moved rows. Every key and `mutatedTextSha256` is unchanged. The
pre-commitment's "identityScheme stays" wording did not foresee that a fresh record always writes
the current scheme.

**Measured guard prevalence** (`/coord/handoff/R-394/measure.md`, al-runner f06ee78c). The static
guard keeps coverage on in EVERY project of the three Continia corpora, CDO (6 projects), DC (14)
and DO (7): no multi-object file and no refused wrapped file. On BC.History (w1-28)
it turns coverage off in 15 of 519 projects, all through the `#if`-wrapped refusal and none
through the multi-object rule. 13 of the 15 are off only because of wrapped files holding no
mutant: 42 code-free wrapped objects (R580) and 21 pragma-only wrappers in Power BI Report
embeddings (R579). The frame probe ADMITS on f06ee78c, one-shot and `--server`, so a multi-object
project keeps coverage on with that build.

**A RETRACTED hypothesis: al-runner does NOT miss page triggers under a page handler.** The first
measurement (`measure.md` section 3, a BC.History slice of Simplified Bank Statement Import) saw
one killed page-trigger mutant (`Bank Statement Import Preview` / `OnAfterGetRecord` /
`remove-assignment`) become `no-coverage` with coverage on, and blamed al-runner's coverage for
not counting a page opened under a `[ModalPageHandler]`. A synthetic repro disproved it
(`/coord/handoff/R-394/repro-pagecov.md`): on f06ee78c every page, report, codeunit,
table-trigger and event-subscriber line that runs under a handled modal page is counted. The
"kill" was the odd one out: that mutant SURVIVES when run alone and in a full same-order re-run
with coverage off, its killing test has no handler for that page, and the code that opens the page
shows 0 hits. So the 0 hits were right, the page guard planned for it was dropped, and no upstream
issue was filed. Do not re-chase it.

**The flaky kill is filed as R577** (a non-deterministic al-runner kill, a false kill under
coverage `"none"`). The repro's side finding, a request page under a `[RequestPageHandler]`
failing on al-runner, is R578.
