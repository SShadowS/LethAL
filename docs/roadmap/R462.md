**What.** Filed from R205 point 3 (R-205, 2026-10-05). In the R205 incident a second session
republished the target and its test app to the shared sandbox during batch 1's baseline. Nine
tests passed, the tenth failed with `The metadata object CodeUnit 68986 was not found. The
application might be incompatible with the current compiler`, and every later method lookup
answered `expected exactly one method X, found 0`. R139's detector then refused the session as
`StaleTestAppError` ("the published test app is missing 50 test(s) this project's source
declares").

**Why it matters.** The printed remedy (republish the test app) assumes the app is older than the
source. Here it was not older: it was being replaced while the baseline ran. A user who follows the
remedy republishes and races the other session again.

**Suggested change.** Name the second possibility in the refusal: the test app changed UNDER the
baseline. The transport could tell the two apart by reading the test app's installed version (or
`TargetArtifactRegistry`) at baseline start and again on the first `found 0`.

**Evidence.** R205's body (point 3 and its evidence paragraph).
