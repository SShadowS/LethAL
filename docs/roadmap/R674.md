**Filed 2026-10-23 by lethal-preproc** during R654 S4 (coord R-654d), from the S3 submit's note. Related: [[R018]],
[[R654]], [[R586]].

**What.** [[R018]] (`done (f616885)`) made `--backend al-runner` print a warning when the config has an `envTool`
section, because that section is ignored on a local runner. The warning lived in the .NET al-runner's branch of
`runFromCli`, and R654 S3 (35f3c67f) deleted that branch. `resolveEnvToolSession` (in `cli.ts`) returns early for
every backend other than bcdev. So `--backend al-runner-v3` with an `envTool` section now ignores the whole section
and says nothing.

**Why it matters.** It is the silent no-op R18 was filed to stop. `--keep-env` and `--allow-expiring-env` are
refused by name on every local runner (`isLocalRunner` in `parseCliConfig`), so the section itself should get at
least a warning too. No verdict changes: v3 never used the section.

**Not the same as R654's F2.** F2 (held for the owner) refuses an old `alRunner` section by name. This item is about
`envTool`, which stays a valid section for bcdev.

**To close.** On `--backend al-runner-v3`, warn when the config has an `envTool` section (R18's wording, naming
`al-runner-v3`). A test that fails without the warning, red-checked.

**Done 2026-10-23 (R-674, lethal-bugs), code head e1a8cee8.**
- **Measured before the fix:** `--backend al-runner-v3` with an `envTool` section printed nothing.
- **The fix:** `runFromCli` warns once, right after the config is read, with R18's wording naming the backend:
  `[lethal] envTool is configured but IGNORED: --backend al-runner-v3 has no environment …`. The condition is
  `isLocalRunner(backendKind) && envTool !== undefined`.
- **A warning, not a refusal.** The build review confirmed this: a config is legitimately shared across `--backend`
  choices, and a `bcdev` section is not refused on v3 either.
- **Tests** (`cli-envtool.test.ts`, "R674"): v3 with envTool warns; v3 with no envTool is silent; bcdev is silent.
  - Each direction went red on its own single revert.
  - Each test also pins how its run ends, so an early throw turns all three red (red-checked).
- **Filed separately:** R676. `--dry-run` takes another path (`dryRunFromCli`), where `dryRunCeiling` still resolves
  the env tool for v3.
