**v2's server protocol keeps our wire shape but ignores our second bundle — and returns GREEN EMPTY, not an error.** `ServerTransport` sends `sourcePaths: [sourceDir, testDir]` (`packages/runner/src/al-runner-transport.ts:234`). v2's `runTests` handler uses **`SourcePaths[0]` only** (upstream `AlRunner/Program.cs:1708`; stated in `docs/server-mode.md:34`: "bundle dir(s); uses the first"), so the test app never runs. Measured against the RELEASED 2.0.0 binary 2026-08-05: the response is `{"tests":[],"passed":0,"failed":0,"errors":0,"total":0,"exitCode":0,"cached":false,"changedFiles":["SandboxLogic.Codeunit.al","SandboxPricing.Codeunit.al"]}` — a passing result computed from the wrong bundle, which is this project's own signature bug arriving from upstream. Our decode turns it into "output missing the requested test" (loud), but nothing about the response itself says anything went wrong. **Reported upstream as [#1658](https://github.com/StefanMaron/BusinessCentral.AL.Runner/issues/1658)** — it is a regression against v1 (`AlRunner/Server.cs:313` did `InputPaths.AddRange(request.SourcePaths)`) and against `ServerProtocol.cs`'s own "byte-compatible with v1" claim, the fix upstream is one line, and the workaround here (emit the mutated target to a `.app` per mutant and pass it as a package) pays a full compile per mutant, which is exactly what warm server mode exists to avoid. Until it lands, the adapter must use CLI mode, which aggregates multiple bundles correctly. Everything else about the protocol survived deliberately — `{"ready":true}` handshake, `runTests`/`shutdown`, the response envelope, and `stubPaths` accepted-and-ignored (`ServerProtocol.cs:22-30`) — so this transport is the cheaper one to port. Two v2-only properties to design against: the AL-output cache is keyed on a hash of the `.al` sources (a selector rewrite per mutant is a guaranteed miss, so no staleness risk, but also no free ride), and a warm reload does **not** clear BC's table field-set cache, so a table *shape* change needs a server restart (`docs/server-mode.md` §"Known limitation"). Statement-level mutants are unaffected; a batch swap that changes table fields is not.
