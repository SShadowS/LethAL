**v2's server protocol keeps our wire shape but ignores our second bundle — and returns GREEN EMPTY, not an error.** `ServerTransport` sends `sourcePaths: [sourceDir, testDir]` (`packages/runner/src/al-runner-transport.ts`). v2's `runTests` handler uses **`SourcePaths[0]` only** (upstream `AlRunner/Program.cs:1708`; stated in `docs/server-mode.md`: "bundle dir(s); uses the first"), so the test app never runs. Measured against the RELEASED 2.0.0 binary 2026-08-05: the response is `{"tests":[],"passed":0,"failed":0,"errors":0,"total":0,"exitCode":0,"cached":false,"changedFiles":["SandboxLogic.Codeunit.al","SandboxPricing.Codeunit.al"]}` — a passing result computed from the wrong bundle, which is this project's own signature bug arriving from upstream. Our decode turns it into "output missing the requested test" (loud), but nothing about the response itself says anything went wrong. **Reported upstream as [#1658](https://github.com/StefanMaron/BusinessCentral.AL.Runner/issues/1658)** — it is a regression against v1 (`AlRunner/Server.cs:313` did `InputPaths.AddRange(request.SourcePaths)`) and against `ServerProtocol.cs`'s own "byte-compatible with v1" claim, the fix upstream is one line, and the workaround here (emit the mutated target to a `.app` per mutant and pass it as a package) pays a full compile per mutant, which is exactly what warm server mode exists to avoid. Until it lands, the adapter must use CLI mode, which aggregates multiple bundles correctly. Everything else about the protocol survived deliberately — `{"ready":true}` handshake, `runTests`/`shutdown`, the response envelope, and `stubPaths` accepted-and-ignored (`ServerProtocol.cs:22-30`) — so this transport is the cheaper one to port. Two v2-only properties to design against: the AL-output cache is keyed on a hash of the `.al` sources (a selector rewrite per mutant is a guaranteed miss, so no staleness risk, but also no free ride), and a warm reload does **not** clear BC's table field-set cache, so a table *shape* change needs a server restart (`docs/server-mode.md` §"Known limitation"). Statement-level mutants are unaffected; a batch swap that changes table fields is not.

**RE-MEASURED 2026-08-08 against al-runner 2.1.0.0, and this row's central claim is now false.
The ruling is still "refuse", but for reasons this row did not contain.** Full measurement in
`docs/measurements/README.md` §"al-runner 2.1.0.0 server mode".

**What this row got wrong.** `sourcePaths: [sourceDir, testDir]` no longer ignores the second
bundle. The exact request `ServerTransport` was built to send now answers:

```
{"type":"test","name":"Codeunit79100.ClampPercentRuns","status":"pass","durationMs":24}
{"type":"test","name":"Codeunit79100.OverBudgetDetected","status":"pass","durationMs":3}
{"type":"summary","exitCode":0,"passed":2,"failed":0,"errors":0,"total":2,"cached":true,"protocolVersion":2}
```

Both tests ran, both passed, `total: 2`. Upstream #1658 is closed in behaviour. Order still matters
and the order we sent is the right one: reversed, the test runs and fails with `Codeunit 79000 is
not present in the test assembly or any loaded dependency`, so the earlier bundle supplies the
implementation and the later one the tests.

**What replaced it, and the first item is the one that decides the ruling.**

1. **The server protocol has NO per-test selection.** Sent against one warm server, each of
   `testFilter`, `filter`, `test`, `tests`, `testName` and `pattern` was ignored and ran the whole
   suite (`total: 2` every time). `ExecutionBackend.run()` is called once per TEST, so server mode
   costs T² test executions per mutant where the CLI's `--test <qualified>` costs T. The warm-process
   win is real and measured — 6,980 ms cold, 1,011 ms warm for the same request — and it does not pay
   for a quadratic.
2. **The response shape moved, and the transport this row wanted to keep could not read it.** It is
   streaming NDJSON now, not one aggregate envelope. `ServerTransport.sendLocked` read ONE line and
   looked for a `tests` array; against 2.1.0.0 it would have found none on the first per-test line
   and returned `{kind: "tests", tests: []}`. The empty-green failure this row is named for did not
   go away, it MOVED from upstream's code into ours.

**Ruling: refuse loudly, and delete the dead transport.** `ServerTransport`, `ServerIo`,
`ServerProcess` and `defaultServerIo` are gone, along with the seven tests that exercised them
against a fake process. This row's own preserved-for-later argument ("this transport is the cheaper
one to port") was the thing that made point 2 possible: a decoder nobody runs cannot be wrong in a
way anyone notices. R93 already settled the general case when it deleted the v1 path — a branch
nothing runs is a lie waiting to happen — and this is the same shape.

`AlRunnerBackend`'s constructor still throws on `serverMode: true`, now with
`AL_RUNNER_SERVER_MODE_REFUSED` stating the measured reasons. **The refusal TEST changed too, and
that matters more than the message:** it used to assert the string `1658`, an upstream issue that is
now fixed, so it would have kept a dead cause alive in this suite indefinitely. It asserts the
shipped constant by identity instead.

**What is worth building instead, and it is not this row:** one call per MUTANT rather than one per
test. A single whole-suite server response already carries every verdict that mutant needs, which
turns the missing per-test filter from a cost into a non-issue. Filed as **R126**; it needs the
isolation semantics measured first, which these runs did not touch.

**Still true from the original row:** the AL-output cache is keyed on a hash of the `.al` sources, so
a selector rewrite per mutant is a guaranteed miss (no staleness risk, no free ride) — the summary
line reports `cached: true` only when the sources are unchanged. The table field-set caveat is
untested here.
