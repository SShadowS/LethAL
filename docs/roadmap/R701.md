**Filed 2026-10-24 by lethal-code during R-685**, from the triage of its dropped-dependency check
(`/coord/handoff/R-685/drop-triage.md`, "not blocking"). Older than R-685; reported by review, not measured.

**What.** A permission set holds no code, so the reach walk folds none. But a test app's permission set (one the app
assigns, or one an app permission set includes through `IncludedPermissionSets`) decides which reads and writes a test
may do, so editing it can turn a passing test into a failing one (or back) while the test's digest stays the same.

**Who hits it.** Not measured. A test app that ships its own permission sets and runs tests under them (for example
with `Library - Lower Permissions`).

**To close.** Decide first whether a permission-set edit should make tests new (an orchestrator ruling). If yes: add
every test-app permission set and permission-set extension, by its normalised text, to every digest (the safe, coarse
option), or to the digests of tests that name it.

**Built** (coarse option, on the orchestrator's instruction). `subscriberFold` hashes every test-app `permissionset`
and `permissionsetextension` object (key and whole normalised text) into one `Q <sha>` line in every digest; an app
with none gets no line, so its digests are unchanged. An extension was already in every digest through the `E` line
(extension objects); the `Q` line adds the base set. Tests: "R700/R701".
