**Filed by the R-352 task (2026-10-09).** [[R488]] made the one-shot `run()` select exactly one test without an
exact selector: it excludes, by whole name, every discovered test whose name contains the requested one
(`useDiscoveredTests`), learns any other sibling from a result, re-runs, and refuses a result that still names another
test. Upstream #5439 is now fixed: `v2.12.0-main.c5bbaf89` has `--test-exact NAME` (whole qualified name,
case-insensitive), measured in R488's 2026-10-09 re-check. The container's gate build `43f76177` does not have it
(`Unknown option`, exit 2).

**What could be dropped**, once the pinned gate builds (the container's daily build and the host's pinned source
build) carry `--test-exact`: the discovered-sibling exclude list, the learn-and-re-run step, and with them the shared
-deadline caveat R488 had to reason about. `--test-exact` is refused with `--server`, which needs no selector change
(per-test coverage there is already clean).

**What must stay or be decided:** a refusal of any result that names another test (cheap, and still the defence if a
build regresses); how to detect support (probe `--help` once per session, as R338 reads the build, or a minimum
build); and the fallback for an older build (keep R488's path, or refuse). R488's red tests in each direction must
carry over to whichever path is chosen.

**Not urgent:** the workaround is correct on every build measured. This item exists so the simplification is not lost.
