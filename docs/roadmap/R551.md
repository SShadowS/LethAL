**Filed by the R-352 task (2026-10-09).** [[R488]] made the one-shot `run()` select exactly one test without an
exact selector: it excludes, by whole name, every discovered test whose name contains the requested one
(`useDiscoveredTests`), learns any other sibling from a result, re-runs, and refuses a result that still names another
test. Upstream #5439 is now fixed: `v2.12.0-main.c5bbaf89` has `--test-exact NAME` (whole qualified name,
case-insensitive), measured in R488's 2026-10-09 re-check. The container's gate build `43f76177` does not have it
(`Unknown option`, exit 2).

**What landed (2026-10-09).** Plan `docs/superpowers/plans/2026-10-09-r551-test-exact-probe.md`, pre-commitment
`docs/superpowers/specs/2026-10-09-r551-test-exact-precommitment.md`.
- **A per-session probe** (`AlRunnerBackend.probeExactTestSelector`): one al-runner call, one-shot transport only,
  through the backend's injected spawn, bounded at 30 s:
  `<path> --output-json --test-exact Codeunit0.LethalR551NoSuchTest <empty dir>`. Accepted only on the process's own
  exit 6 with an `--output-json` envelope whose `tests` is `[]` and whose `exitCode` is 6. The decision never reads
  stderr. A rejection's reason is a short code plus the first non-blank stderr line (at most 200 chars).
- **What acceptance shows, and what it does not.** Exit 6 on an empty bundle shows only that the build PARSES the
  flag and counts it in its selection audit; the executor never runs. The whole-name guarantee is `--test X` kept in
  the argv (so a build that ignored `--test-exact` still selects no more than the substring set), plus the refusal of
  any result naming another test.
- **Accepted:** one-shot calls send `--test X --test-exact X` and no `--exclude-test`. A result naming another test
  is refused at once (`outcome: "error"`, `completed-accepted`), never re-run or credited. R491's duplicate-row
  refusal still comes first.
- **Not accepted** (deadline, spawn failure, signal, any other exit, no envelope, rows, another envelope exit code,
  `--server`, or a backend nobody probed): R488's path, byte for byte. It never refuses the session.
- `runSession` probes once, before the baseline, emits one `al-runner-test-selector` warning naming the choice, and
  hands every worker the boolean. A worker without `useExactTestSelector` makes the session throw. `--server` spawns
  no probe.
- If the binary is swapped mid-session for one without the flag, every exact-path call exits 2 and is a loud
  `error`, never a credited result; a swap the other way stays on the R488 path, which is correct.

**Not retired.** R488's path stays as the fallback until every supported build carries the flag: [[R559]]. The
report does not yet record the selector: [[R558]]. Quoted AL test names are a separate, pre-existing gap on both
paths: [[R557]].
