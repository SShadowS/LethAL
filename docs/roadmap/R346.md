**Found while closing R296, 2026-09-29.** Bun builds `err.stack` on the first read, and if a garbage
collection runs between an async throw and that read, the stack header is a bare `Error` with no
message (oven-sh/bun#34398, reproduced on Bun 1.3.14). R296 fixed it for the baseline guard alone, by
reading the stack where `throwOnDiff` and the two refusals make their errors. Every other failure a
live gate throws (an `assert` failure, a runner error, a verdict-table mismatch) is still printed by
the gate's catch as `err.stack ?? err.message`, so on a long live run it can lose its message the same
way. The gates affected: `bcdev`, `al-runner`, `envtool`, `tables`, `hang`, `harden` (`chunked` prints
`console.error(err)`, not checked).

**To close:** one shared formatter for the gates' catch handlers that prints `name: message` from
`err.message` and takes only the frame lines from `err.stack`, used by every gate, with a subprocess
test that forces `Bun.gc(true)` before the print. Or drop it when Bun fixes #34398 and a test pins that.

**Evidence.** `.superpowers/r296-rootcause.md` on lethal/r296 (not committed), and R296.

**Closed 2026-09-29 (4e131268).** `packages/runner/src/format-failure.ts` holds `formatFailure`: it
prints `name: message` read from the error itself, then only the `    at ...` frame lines of
`err.stack`, so a stack that lost its header to a GC still prints the reason. A non-Error throw is
printed as a string, and one `String()` cannot convert falls back to `Object.prototype.toString`.
Routed through it: the catch of all 13 gate entry points with a `main()` (`al-runner`, `bcdev`,
`chunked`, `envtool`, `hang`, `harden`, `lease`, `stale-publish`, `tables`, `test-app-publish`,
`verify`, `verify-agreement`, `verify-scale`; `growth` has no catch), the four `describe` helpers
in `test-app-publish`, `verify`, `verify-agreement` and `verify-scale` that fold a step's error
into the gate's own message, and the CLI's `LETHAL_DEBUG=1` branch, which is where
`lethal campaign freeze` failures are printed (the default branch already printed `err.message`).
Every receipt write and exit code is unchanged, and so is each handler's print-then-await order.
`tests/format-failure.test.ts` pins it three ways: unit cases, an AST wiring test over every
`*.itest.ts` (no `.stack` read anywhere in a gate file, and every console print of the caught value
is exactly `formatFailure(<caught>)`) plus the CLI, and a child process that throws after an await,
forces `Bun.gc(true)`, prints, and asserts the message reaches stderr. Red-checked both: a gate
printing `err.stack` fails the wiring test; a formatter returning `err.stack` alone prints a bare
`Error` plus frames in the child, the live R296 output exactly.

**Bun.** The upstream issue closed 2026-09-19 through oven-sh/bun#43387 (merge commit `26e7a4b3`).
The newest release, `bun-v1.4.2` (2026-09-05), predates it and the merge is 286 commits ahead of
that tag, so no release carries the fix yet; only canary builds do. Bun was not upgraded. Once a
release carries it and the repo moves to it, the GC test above still passes, and the formatter can
stay: it costs nothing and does not depend on the fix.
