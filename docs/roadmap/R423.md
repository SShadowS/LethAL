**Found 2026-10-03, reported by lethal-code during the R-307 merge of a1513b1d.** The PostToolUse
`Edit|Write` hook `.claude/hooks/biome-touched.ts` runs `bunx biome check --write <file>` on every
.ts file an agent edits. During a merge, an agent edits a conflicted file in several steps, so the
hook runs while `<<<<<<<` / `=======` / `>>>>>>>` markers are still in it. biome then "fixes" a
file that is not valid TypeScript, and in `packages/runner/tests/resume.test.ts` it damaged one
test body, which had to be repaired by hand before the commit. lethal-code counts this as the third
merge with code damaged around the hook; the earlier two lost the braces of a `${reason}`
template, which fits the same mechanism.

The damage is silent: nothing reports that the hook rewrote a conflicted file, and a careless
resolution can commit the result.

**To close.** In the hook, skip the file when it contains a line that starts with `<<<<<<< `,
`=======` (alone on the line) or `>>>>>>> `, and say so on stderr. Add a test that feeds the hook a
conflicted file and checks the file is byte-identical afterwards, red-checked against the current
hook. Editing a hook is a harness change: the owner approves it.
