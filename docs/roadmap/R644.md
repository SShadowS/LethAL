**Filed 2026-10-22 by lethal-preproc during R-585** (the R-585 plan review's finding I2,
`/coord/handoff/R-585/review-opus-plan.md`). Related: [[R585]], [[R557]], [[R621]].

**What.** `--skip-known-survivors` lends a prior run's survivors (`priorSurvivorKeys`). A mutant is scored only
against the tests that were GREEN in that run's baseline: a test that failed at baseline is out of the green set and
never runs against a mutant. Today history checks the scheme, coverage mode, test app, symbols and hidden files, and
after R-585 the test scope (the set of tests SENT). But it never checks which tests were actually green at the source
run's baseline.

**Scenario.** The source run's baseline has test X failing. The cause can be data, company state, an environment
glitch, or BC's own refusal of a TestPage test in the fenced session. Its survivors were never checked against X. In
the new session X passes, the test app and scope are equal, and the survivors are lent as known survivors. If X
kills any of them, that is a false survive, carried forward on every later history read.

**What already covers part of it.** R557 C1 refuses the al-runner case where renamed tests read as baseline errors.
Nothing covers the general case. History is decided before this session's baseline runs, so the check cannot simply
compare the two baselines up front.

**To close.** Record each run's GREEN baseline test set (it is in `test_results`), and lend history only for survivors
whose source green set covers this session's green set. That means deciding after this session's baseline, or
re-checking known survivors against tests green now but not then. A red test: a source baseline with X failing, X
green now, and a survivor X kills; the survivor must be re-run, not lent. Measure first how often a real campaign's
baseline has failing tests that later pass.
