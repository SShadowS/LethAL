**Filed 2026-10-22 by lethal-preproc during R-585** (the R-585 plan review's finding I2,
`/coord/handoff/R-585/review-opus-plan.md`). Related: [[R585]], [[R557]], [[R621]].

**What.** `--skip-known-survivors` lends a prior run's survivors (`priorSurvivorKeys`). A mutant is scored only
against the tests that were GREEN in that run's baseline: a test that failed at baseline is out of the green set and
never runs against a mutant. Today history checks the scheme, coverage mode, test app, symbols and hidden files, and
after R-585 the test scope (the set of tests SENT). But it never checks which tests were actually green at the source
run's baseline.

**Scenario.** The source run's baseline has test X failing. The cause can be data, company state, an environment
glitch, or BC's own refusal of a TestPage test in the fenced session. Its survivors were never checked against X. In
the new session X passes, the test app and scope are equal, and the survivors are lent as known survivors. If X
kills any of them, that is a false survive, carried forward on every later history read.

**What already covers part of it.** R557 C1 refuses the al-runner case where renamed tests read as baseline errors.
Nothing covers the general case. History is decided before this session's baseline runs, so the check cannot simply
compare the two baselines up front.

**To close.** Record each run's GREEN baseline test set (it is in `test_results`), and lend history only for survivors
whose source green set covers this session's green set. That means deciding after this session's baseline, or
re-checking known survivors against tests green now but not then. A red test: a source baseline with X failing, X
green now, and a survivor X kills; the survivor must be re-run, not lent. Measure first how often a real campaign's
baseline has failing tests that later pass.

**Done (R-644, plan `docs/superpowers/plans/2026-10-22-r644-lend-only-against-faced-tests.md` r2).**
- The record is per mutant, not per run: a survivor's `covering_tests` is exactly what it was run against, so a test
  red at its baseline is never in it. Measure: `/coord/handoff/R-644/measure.md`.
- `priorSurvivorKeys` also returns each survivor's list (`PriorSurvivors.faced`, by key and by site). NULL, `[]`
  and an ambiguous key or site are "no record". `filterHistory` hands the session CANDIDATES with their lists.
- `runSessionBody` keeps the candidates inside `execute` through the compile bisect, the no-green branch and
  coverage. Just before the resume step (5b) it lends one only when every test covering it now is in its list.
  Otherwise it runs, with `history-tests-not-faced` or `history-survivor-no-record`. A candidate no green test
  covers now is not lent; it reads no-coverage. Candidates' coverage comes from a second `coverageFilter` call that
  emits nothing.
- A lent row keeps the source's list in the store (`ResultsStore.keepFacedTests`), so a chain lends again. The
  report row is unchanged (`coveringTests` empty). No existing refusal or warning is renamed; the run-level checks,
  R585's scope check last, are unchanged.
- Build review I2: a survivor carried by `--resume` (step 5b) used to store the tests covering it NOW, which a later
  history session read as "faced". Its store row now keeps the source row's list (`ResultsStore.keepCarriedFacedTests`);
  the report row is unchanged. The whole-batch replay already kept the stored list.
- Tests: `r644-source-baseline-lend.test.ts` (14), including the build review's plan tests: per mutant, a malformed
  record throws, a resume-carried source survivor, a source refused at run level gets no R644 warning, and an
  ambiguous site match re-runs. Red-checked per direction (`/coord/handoff/R-644/redcheck.md`, 11 checks).
- The warnings are listed in `docs/using-lethal-from-an-agent.md`.
- Not covered here: whether `--resume` itself should carry a survivor that a test green now never faced. That is R646.
