Ten operators guard on `isStatementPosition` (`void-method-call`, `swap-call-arguments`, and every
Tier-2 operator except `swap-rec-xrec`). The predicate measures `false` for a call that IS the body
of an un-braced branch, so

```al
if Cond then Rec.Validate(Level, NewLevel);
```

produces no mutant from any of the ten, even though `if Cond then Rec.Level := NewLevel;` is
perfectly legal AL. `validate-to-assign`'s own header already names this as an accepted cost. What
was never measured is the size of it, or that it is shared.

**Measured on `do-rel2/Cloud`** (554 `.al` files), splitting the refusals by the grammar's own field
names so a call in an `if` CONDITION is never counted as a lost branch body:

| where the refused call sits | count | recoverable? |
| --- | ---: | --- |
| `if_statement.then_branch` | **723** | yes |
| `case_branch.body` | **253** | yes |
| `if_statement.else_branch` | **138** | yes |
| `while_statement.body` | 2 | yes |
| `foreach_statement.body` | 1 | yes |
| `for_statement.body` | 1 | yes |
| `if_statement.condition` | 1,068 | no, correctly refused |
| `for_statement.end` | 35 | no |
| `case_branch.pattern` | 15 | no |
| `foreach_statement.iterable` | 6 | no |
| `while_statement.condition` | 2 | no |

**1,118 recoverable**, against 17,929 call sites in procedure and trigger bodies. For scale: R159's
whole arithmetic operator is 100 sites, and this is a recovery rather than a new operator.

On `validate-to-assign` alone the shape is 22 of its 149 `Validate` sites (13 `then_branch`,
9 `case_branch.body`), so it claims 112 where it could claim 134, a fifth more.

**Why the guard exists, and why "widen the predicate" is the wrong fix.** The compiler's wrap form
(design.md §3.1) replaces the statement with an `if MutationSelector.Active(...) then <mutated> else
<original>`. Splice that into an un-braced then-branch and the emitted `else` binds to the INNER
`if`: the guarded dispatch would silently invert which branch of the OUTER conditional runs. That is
not a compile error, it is a wrong mutant that scores normally, which is the worst failure this
product has. The guard is correct as written.

**What a fix has to do.** Brace the enclosing branch: emit `if Cond then begin <wrapped> end;`. The
duplicate form (§3.3) already shows the compiler emitting `begin`/`end` around a wrapped statement,
so the shape exists. The new part is that the mutation would rewrite the ENCLOSING statement rather
than only the mutant's own span, which today's emit contract does not do, and every operator's
`parentContext` reasoning assumes it does not. So this is an emit-contract change with ten
operators downstream of it, not a one-line predicate edit.

**How it must be verified.** Set-diff the claimed sites before and after, per operator, rather than
comparing counts: R87 is the precedent, and a count that goes up does not prove nothing moved. Then
a live arm whose fixture carries both an un-braced `then` and an un-braced `case` body, with the
per-mutant verdicts pre-committed, because a dangling-`else` regression is invisible in an aggregate.

**CLOSED 2026-08-19, and two things in the row above were WRONG.**

**Wrong 1: "ten operators share the loss." It is six.** Four of the ten read `isStatementPosition`
only to COMPUTE `parentContext`, and `swap-modify-flag` already claimed then-branch sites
deliberately (its own header says adding the guard "must turn the then-branch conformance test
RED"). The six that actually refused are `void-method-call`, `remove-setrange`, `remove-testfield`,
`remove-calcfields`, `remove-commit` and `validate-to-assign`.

**Wrong 2: "the recovery needs the compiler to brace the enclosing branch, which is an emit-contract
change with ten operators downstream."** The compiler ALREADY braces. `wrapIfSingleStatementSlot`
(`packages/schemata/src/compile.ts`) wraps a dispatch chain in `begin ... end` whenever the site is
not a statement-list member, which is exactly the case this row is about, and its comment already
described the dangling-`else` hazard the row re-derived. The refusal was the predicate's alone.

So the fix is `isStatementSlot`, a new predicate kept SEPARATE from `isStatementPosition` rather
than widening it, because the compiler reads the narrow one for the OPPOSITE purpose: widening the
single predicate would have turned the bracing off at the very sites this admits.

**The emitter DID need one fix, found by compiling the output rather than reading it.** A deletion
empties the slot, and since grammar 4.0.0 moved the terminator out of the statement span, three of
the four shapes emitted a dangling `then`/`do` that `alc` rejects with `AL0224: Expression
expected`. Only the `case_branch` body survived, because there the arm's own `;` sits inside the
component root. `emptiedSlotFiller` supplies the empty statement, and only where a `;` does not
already follow within the root. `scripts/r161-emit-proof.ts` compiles all four shapes and keeps a
NEGATIVE control that must be rejected; red-checked, and with the filler neutered it drops to 2/5.
