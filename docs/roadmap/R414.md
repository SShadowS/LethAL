**Found reading the CI runs of `lethal/kraken-move` (kraken-move Task 6, 2026-10-03); it also fails
on master (run 37117690800).** `scripts/snapshot-late-write.test.ts` runs a child `bun test` with
`CI` removed from its env, as the control in which a late snapshot IS written. GitHub runners also
set `GITHUB_ACTIONS=true`, and Bun treats that as a CI environment too, so the child still refuses to
create the snapshot. Measured in the `kraken-lethal:dev` image, Bun 1.4.2: with `GITHUB_ACTIONS=true`
in the outer env the control fails; with only an unrelated runner variable (`RUNNER_OS`) it passes.
It passes on a developer machine, where neither variable is set.

Failing test (both CI jobs, run 37129055253): `R393 late snapshot write > (b) control, CI unset: the
wrong entry IS written under B's key`. Evidence line:

```
##[error]Expected to contain: "A late toMatchSnapshot returned OK"
```

**To close.** The control drops `GITHUB_ACTIONS` as well as `CI`.
