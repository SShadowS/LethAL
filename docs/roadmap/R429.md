**Found by the R-405 part (a) work (lethal-preproc), 2026-10-04.** Source: R378's plan `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md` §1 B5 lists `TypeTable` among the project-wide indexes that read `#if` declarations without arms.

**What is known.** R-405 part (a) made the symbol table, the table-trigger readers and the receiver filter arm-aware (`liveMembers`, R405). It did NOT change `TypeTable`.

**What is NOT known.** Nobody has measured it. It is not known whether `buildTypeTable` sees declarations inside a member-level `#if` at all, or sees them from the arm the build does not compile. If it does, a variable or procedure type could resolve from an inactive arm, so a site could be refused or mis-typed. No wrong verdict has been seen from it.

**What would close it.** Measure first: build a project with a variable or a field declared inside a member-level `#if X` / `#else`, and read what `buildTypeTable` holds under `[]` and `[X]`. If it reads an inactive arm or drops an active one, filter its members by arm the way R405 (a) does with `liveMembers`. Then diff the keys: a newly admitted mutant can move an identity ordinal (see the scheme 8 note in `packages/schemata/src/project.ts`), so a change needs the key diff over the gate projects and possibly another `IDENTITY_SCHEME` bump.
