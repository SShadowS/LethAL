**Found by** coord PR-449 part 2 (lethal-preproc, 2026-11-25): measure-only, over the last 30 task merges into master.
Evidence: `/coord/handoff/PR-449/findings.md`, with `merges.ts`, `merges.json`, `lease-time.py` and `lease-time.json`.

- **What happens:**
  - `selectLegs` (`scripts/agentflow/gate-table.ts`) unions every row a path matches.
  - The `packages/runner/` row selects bcdev, lease, tables, chunked and alrunner-v3 for EVERY runner file.
  - That includes files no BC path loads: `al-runner-server.ts`, `al-runner-v3-*.ts`, and the v3 gate's own itest files
    (`al-runner-v3*.ts`, `alrunner-v3-legs.ts`).
- **Measured (30 merges):**
  - 17 selected BC legs. 3 were needed (an operator, snapshot reuse in store.ts, bcdev-backend). 1 is a mixed 33-file
    change, not judged.
  - **14 (47% of all 30) reached no BC path.**
    - **10 by PATH alone:** PR-442, 431, 428, 411, 419, 408, 403, 396, 267, 393.
    - **4 by CONTENT in shared files** (PR-434 `cli.ts`, PR-410, 395, 402): v3-only hunks in cli/orchestrator/resume/store.
- **Cost where prleg logs exist:**
  - 423 lease-minutes (~7.1 h) over 9 PRs. The path-decidable part alone is 225 min (~3.7 h) over 6 PRs.
  - Each PR waits about its tables leg (16-52 min), and the servers are held from other lanes' legs meanwhile.
- **The lever (not built here):**
  - A row for the v3-only paths that selects only `alrunner-v3`, matched ALONE for those paths (as R-936's test-only row
    is), so the `packages/runner/` row does not union the BC legs back in.
  - A `gate-table` test pins it: each v3-only path selects exactly `alrunner-v3`, and a shared runner file still selects
    all five.
  - The list must be exact and guarded. A test should read the BC code paths' imports, and fail if any BC path (bcdev
    backend, orchestrator, cli for a bcdev run) imports a file on the v3-only list. R-936's guard for test-only files is the
    pattern.
- **Not covered by a path rule:** the 4 shared-file cases. A v3-only hunk in `cli.ts` or `orchestrator.ts` needs the hunk
  read, which a path table cannot do. It stays a per-PR ruling, as PR-401 and PR-434 got.
- **Default-deny is unchanged:** an unmatched path still selects the full set.
- **Related:** R1202 (PR-449 part 1, the `.claude/hooks/` row), R-936, R654, PR-434.

**Closed by measurement, PR-450 (lethal-preproc, 2026-11-25), before any spec.** Evidence:
`/coord/handoff/PR-450/premise.md` and `closure.ts`.
- **CORRECTION of this item's own claim.** The title and the "10 by PATH alone" above are WRONG: these files are not
  "files no BC path loads".
  - **The closure:** walked from the 13 BC itests, plus cli.ts, which they spawn. It counts static imports, re-exports,
    literal `import()`, `require()` and worker URLs. There are no non-literal dynamic imports.
  - **Every one of the 18 `packages/runner/src/al-runner-*.ts` files is inside it.**
  - **BC-path shared modules import from and call into them:** `publisher.ts` <- `al-runner-v3-seed`,
    `webservice-http-text.ts` <- `al-runner-v3-contract`, plus `backend.ts`, `report.ts`, `mutant-windows.ts`,
    `not-run-survivors.ts`, `confirm.ts`, `orchestrator.ts` and `cli.ts`.
  - So a change to a v3 src file can reach a BC path. Whether it does depends on the hunk and the call graph, which a path
    table cannot see.
- **What a sound path rule could cover:** only the v3 gate's itest files (`al-runner-v3.itest.ts`, `-gate.ts`,
  `-tables-known.ts`, `-carry.itest.ts`, `alrunner-v3-legs.ts`) and their baselines.
  - Replayed over the same 30 merges, that drops BC legs for 1 merge (PR-393, ~20 lease-minutes), not 10.
  - Not built (the orchestrator's ruling (b)): too little to pay for a closure guard.
- **What stands:** PR-449's 14 "no BC path reaches it" cases are per-PR readings of each change's hunks. They stay per-PR
  rulings, as PR-401 and PR-434 got, not a table row.
