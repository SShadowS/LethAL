Coord task R-970, from GitHub #51. Related: [[R172]] (equivalence risks), [[R159]] (the blank toggles).

**The report (#51, quoted).** "The full run listed 68 survivors under LIKELY-EQUIVALENT / `value-rewrite`, with the note 'Where
nothing downstream reads that value, the mutant is equivalent'. We read all 68 against the source. 23 of them are
`toggle-blank-temporal` or `toggle-blank-string` where the blank is one side of a comparison, for example
`if (Rec."Effective To" <> 0D) and ...` and `if ListText = '' then begin`. Here the comparison is what reads the value, so
'nothing downstream reads it' can't be the reason these survive." Of the 23: 18 read as equivalent, 1 partly testable, 4 real test
gaps, killed on a rerun once tests were written. The other 35 of the 68 were `remove-assignment`, which the text fits.

**Built.** A new `EquivalenceRisk`, `compared-value`, set PER SITE: `MutationSpec.equivalenceRisk`, which
`toggle-blank-string` and `toggle-blank-temporal` set when the literal's parent is a `comparison_expression` (by parse, both
directions). The manifest entry carries it (`MutantManifestEntry.equivalenceRisk`); the report's per-row `equivalenceRisk` and
`likelyEquivalentSurvivors` use the site's risk before the operator's, so an assigned blank stays `value-rewrite`. Its meaning
text: the comparison reads the value; for `=`/`<>` the branch changes only where the other side equals the original literal or
the substitute, for an ordered comparison (`<`, `>`, `<=`, `>=`, found by the build review) for any value between the two; the
mutant is equivalent only if no such value reaches the comparison. No verdict, score or report field moves; a manifest written
before this has no site risk and keeps the operator's. The manifest gains the key (stream schema regenerated); sandbox-data's and
sandbox-coverage-probe's manifest pins re-pinned, and with the key removed sandbox-data's manifest gives the old pin byte for byte.
`shift-integer`'s comparison operands have the same misfit: [[R984]].
