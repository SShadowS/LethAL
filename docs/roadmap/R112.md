**R90's publish ceiling can be INSPECTED and CLEARED only by a bcdev-shaped config, so on an env-tool project the bracket is reachable only by already holding a refusal message.** `dryRunCeiling` (`cli.ts`) reads `configFile.bcdev?.server` / `?.serverInstance` straight off disk and returns `undefined` — printing nothing at all — when either is absent. For an env-tool config those fields are LEGITIMATELY absent from the file; that is the whole premise of R51. Consequences on a hosted Layer-6C project, i.e. exactly the topology R90's bracket was measured on: `--dry-run` silently prints no bracket, `lethal clear-ceiling` demands literal `--server`/`--instance` the user cannot read off their own config, and `lethal doctor` never names the resolved tier either. The one path that does close the loop is the refusal itself — its message is rendered from the RESOLVED identity and pre-fills the whole `clear-ceiling` invocation including `--db` — so an operator who has hit the ceiling is fine, and an operator trying to inspect it beforehand is not. Note this is a coherence gap in the subsystem rather than a regression: nothing worked before either. Fix: give the ceiling's inspect and clear surfaces the same read-only env-tool resolution `doctor` and `force-reset-lease` gained (see **R111** — do it once, in the extracted helper, rather than a third time). Filed 2026-08-05 from subsystem C's whole-branch review.

**Closed 2026-08-07, on top of R111's extraction exactly as this row instructed.**

Two surfaces, both now able to reach the bracket on a Layer-6C project:

- **`--dry-run`** — when `bcdev.server`/`bcdev.serverInstance` are absent AND an `envTool` section
  is present, the tier is resolved through `prepareBcdevReadOnly` and the measured bracket prints
  as it always did for a directly-configured container. Before this the bracket section was
  silently ABSENT, which is indistinguishable from a tier that had never failed — the reading that
  matters most, and the one it got wrong. The resolution sits inside the existing try/catch, so an
  unreachable environment degrades to the NAMED note the function already had rather than taking
  the whole dry run down: the mutant counts are the command's job, the bracket is additional.
- **`clear-ceiling`** — `--server`/`--instance` may be replaced by `--config <path>`. They remain a
  PAIR (half an identity is refused, since it would clear a tier named partly by a flag and partly
  by a config), explicit flags still win outright (the rule `clear-quarantine` and
  `force-reset-lease` follow: a shared or stale config must not redirect a destructive recovery),
  and when the identity was resolved rather than typed the command PRINTS `resolved tier from
  <config>: <tier>` before it removes anything.

**Red-checked at both call sites**, not at the helper: removing the dry-run resolution reddens the
dry-run test; bypassing `resolveCeilingIdentity` reddens the clear test. Each leaves the other
green, which is what proves they are two independent surfaces rather than one.

**Not done, and stated rather than implied:** `lethal doctor` still does not NAME the resolved tier
in its output. The row lists that as a third consequence. Doctor already resolves the identity (it
has to, for `quarantine` and `control-version`), so this is a rendering change rather than a
resolution one, and it is the only part of this row left open.
