Coord task PR-141 (was PR-69), 2026-11-18. Evidence: `/coord/handoff/PR-137/pr69-input.md` and
`/coord/handoff/PR-137/result.md`. The user-facing reading is in the README, section "When an `al-runner-v3` survivor is a
good lead". Related: [[R1121]], [[R586]].

**The measurement** (coord PR-137): three scopes of one private customer project, 1,494 mutants, each run on al-runner v3 and
on bcdev (BC on Linux), compared per mutant.

| v3 survivor | survivors | BC survived | BC killed (real) | BC killed by the Linux RDLC stub |
|---|---|---|---|---|
| no `[v3-refused-test-nearby]` note | 947 | 945 | 2 (one mutant twice: an al-runner wrong answer) | 0 |
| with the note | 78 | 57 | 10 | 11 |

**The proposal: a two-stage run.**
1. Run the whole scope on `al-runner-v3`.
2. Re-run on `bcdev` only the survivors that carry the note, plus, optionally, a small random sample of the unnoted ones,
   so the agreement rate is re-measured on every project and not assumed from this one.
3. Join the two per mutant into one report that says, for each survivor, which backend measured it.

**Why it may pay:** BC's cost here was spent on 80 mutants to find 10 real kills, all among the 78 noted survivors. On a
project where few survivors carry the note, BC time drops to that set.

**Open questions before building:**
- **How it joins:** `--resume` against another backend's run is refused today, and a report mixes no backends. This needs
  a new run shape (a list of mutant ids for `bcdev`, then a merge), not a flag.
- **The note's reach:** the note marks a codeunit, not a test. It cannot say whether the refused test would have reached
  the mutant, so the BC set is a superset.
- **The sample size** for the unnoted ones, and what disagreement rate stops the flow.
- **Linux BC:** a confirmation run inherits R1121's false kills. Those kills must be read, or screened (R1121's ruling:
  flagged, never re-scored).

**A second measurement (coord PR-155/PR-166, 2026-11-18):** the 50 DO candidates of [[R1116]], `bcdev` on bc4, joined
per mutant (full site key) to the same scope's v3 run (`/coord/handoff/PR-155/{bc,v3}/report.json`).
- v3 left 64 survivors. BC killed **8 of the 35 noted ones and 0 of the 29 unnoted ones**.
- All 8 kills fail on an assertion, with no RDLC stub and no duplicate key.
- Each killing test was refused at v3's baseline, so the mutant was scored on the other covering tests. Two v3
  refusals hid them:
  - an earlier test changed a number sequence that existed before it (`TableSeq32`, Base Application's ledger entry
    sequence);
  - a zip rewritten in place by `Data Compression` (`ZipArchive.Dispose` over an OutStream), whose refused test then
    withheld the next test.
- PR-166 traced both to upstream, with BC 28.4 measuring an invented pair: #8002 (a comment with BC's answer: the
  rollback undoes the `Next`) and #8360 (new; BC returns the zip with both entries).

reports per mutant (`keyOf`) into a `lethal-confirmation` artifact with each row's final verdict and provenance.
