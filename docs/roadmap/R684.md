**Filed 2026-10-23 by coord task R-537** (lethal-code), from the bc2 measurement for [[R537]] and [[R543]]. Never a
false kill: a whole run lost to one test codeunit, with a wrong cause.

**What.** An invented test codeunit whose `OnRun` trigger raises `Error(...)`, with two empty `[Test]` methods, was
run on bc2 (BC 28.4) through LethAL's bcdev path (LethAL Control 1.0.0.23, Microsoft's `Test Suite Mgt.`).
- BC gave the codeunit **no method lines**. Each baseline call answered `RunMutant returned 0 test lines, expected
  exactly 1; server: expected exactly one method AfterThrowingOnRun, found 0`.
- LethAL classified both tests `stale-test-app`, then stopped the run with `StaleTestAppError` ("the published test
  app is missing 2 test(s) this project's source declares"). The remedy it prints (recompile and republish the test
  app) cannot help: the published test app was current.

**Why it matters.** The message sends the user after the wrong cause. A suite with such a codeunit cannot be measured
at all on bcdev. A mutant that makes a test codeunit's `OnRun` raise (when `OnRun` calls target code) may reach the
same path mid-run; that is not measured.

**Evidence.** `/coord/handoff/R-537/measure.md` ("BC 28.4 (bc2)"); `/coord/handoff/R-537/bc/progress.bc2.ndjson`
(the `baseline-batch-finished` event); pre-commitment `docs/superpowers/specs/2026-10-23-r537-bc-probe-precommitment.md`
(delta 3, P3 refuted). v3 refuses the same codeunit as not run, upstream
[#5748](https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5748).

**To close.** Find out what BC records for the codeunit itself when its `OnRun` raises (the codeunit line's result
and message). If it is readable, have LethAL Control report "the codeunit's OnRun failed: <message>" for the requested
method, and have LethAL name that cause instead of a stale test app. Measure the mutant path too.
