**Filed 2026-10-23 by lethal-bugs during R-431**, by the orchestrator's ruling. [[R431]] filed this route for
codeunits, which R-371's bb2ef6a1 had already closed. The same route is open for the other runnable kinds.

**What.** External code can run a report, page, xmlport or query by an integer id (`Report.Run(Id)`, `Page.Run(Id)`,
...). R-371 guards this for codeunits in two places in `packages/runner/src/testpage-scan.ts`:
- `foldIdTargets` folds every test-app codeunit that reached code names as `Codeunit::X`, or by its literal id;
- `passesTestApp` falls back when a codeunit's literal id is handed to an unfollowed call.

Both read `Scanner.byKey`, built from `model.units`, which holds codeunits only. `idRefsIn` keeps only `codeunit::`
names. So for the other four kinds, an edit to the object leaves the test's digest unchanged (the unsafe direction)
when the test:
- hands the object's literal id to external code;
- stores `Kind::X` or the literal id in a variable or a record field, and then calls external code.

Only a direct `Kind::"X"` argument already falls back (it is a test-app object reference).

**Measured** (`/coord/handoff/R-431/measure.md`):
- **The offline probe:** all 5 missed shapes are MISSED for each of the 4 kinds, while codeunits fold or fall back.
- **The census by parse,** over 180 test apps in CDO, DC, DO and BC.History. In BC.History there are 35 such sites in
  2 test apps:
  - System Application Test, Guided Experience: 11 stored page and report names;
  - BaseApp Test, Tests-Report: 24 literal ids of a test report used as record keys.
  - Plus 2 probable coincidences (a page id equal to an ordinary number).
  - CDO, DC and DO have none.

**To close (the ruling).**
- Fold a test-app report, page, xmlport or query that reached code names, by `Kind::X` or by its literal id, as
  codeunits are folded: the object's triggers and what they reach (`foldObject`).
- Fall back when its literal id is handed to an unfollowed call.
- Computed and platform-sourced ids stay [[R390]]'s stated limit.
- This only widens digests: a coincidental literal costs a re-run, never a wrong verdict.
- Red tests per direction per kind, plus an unchanged-digest control.

**Built 2026-10-23 (R-431, lethal-bugs), plan `docs/superpowers/plans/2026-10-23-r684-runnable-object-id-fold.md` r2**
(deep review applied).
- **Tables are included,** by the orchestrator's ruling: `Database::X` or a table's literal id handed out reaches
  `RecRef.Open(Id)` and the table's triggers. The kinds are report, page, xmlport, query and table.
- **The change, in `testpage-scan.ts`:**
  - `idRefsIn` keeps those kinds' references as `<kind>::<name>`;
  - `foldIdTargets` folds the named objects, or the ones with that literal id, with `foldObject`. The object half
    runs even when a test-app codeunit is below 1000; that was the review's critical finding about the old early
    return.
  - `lowObjectIds` folds every such object when one has an id below 1000.
  - One helper, `idOwner`, serves both `int` checks (`passesTestApp`, `traceParam`).
- **Tests and red checks:** 32 tests in `test-digest.test.ts`, the R684 describe. 22 were red before the build. Six
  red-checks, each restored, logged in `/coord/handoff/R-431/red-unit/`:
  - the new reference kinds removed;
  - the object fold removed;
  - `idOwner`'s object half removed;
  - `lowObjectIds` removed;
  - the old early return put back;
  - an over-wide fold that folds every object on any integer, which turns the "only object ids fold" control red.
- **Measured on real suites, every test's digest before and after** (`/coord/handoff/R-431/digest-diff*`):
  - CDO: 1,287 tests, none changed.
  - DC: 49 digests change, but all 1,854 tests were already on the fallback.
  - BC.History, 176 test apps and 48,809 tests: 1,004 digests change in 9 apps, so those tests re-run once.
  - The fallback count goes from 43,760 to 43,862. All +102 are in Guided Experience (2 → 104): a subscriber names a
    test page by id, and that page's `OnAction` hands its own reference to external code.
  - Accepted by the orchestrator's ruling (option a). The narrowing that would recover them is [[R685]].
