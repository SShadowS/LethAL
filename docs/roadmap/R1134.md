Filed by coord PR-197 (lethal-code, 2026-11-19), with R1113's fix 2. Spec: `docs/superpowers/specs/2026-11-19-pr197-r1113-outbound-http-warning.md`
§2 and §6. Evidence: `/coord/handoff/PR-197/proto-do2.tsv` (names and paths only).

**What.** PR-197's pre-run line lists every selected test codeunit whose `TestHttpRequestPolicy` does not block outbound calls.
That fact cannot be missed, but on DO it names all 113, because none sets the policy. It does not say which ones can actually
reach an `HttpClient` send.

**Measured so far (a regex prototype, DO on bc4's package cache).**
- Object-level reach (each codeunit a test names, through to a codeunit that declares `HttpClient`) flags 83 of 113, mostly
  through hub codeunits. That is too noisy to rank by.
- It does find the two Azure codeunits whose tests hung DO's baseline ([[R1113]]), through `CTS-SYS Azure Blob` and then
  `CTS-SYS Http`, a dependency whose source ships inside its `.app`.
- Matching dependency names (Http, Azure, Blob) is wrong: `Temp Blob`.

**To close.**
1. **Procedure-level reach:**
   - **Edges:** bare calls, calls on codeunit- and record-typed variables, `this.`, and `Codeunit.Run` on a literal.
   - **Scope:** into the dependency sources inside the cached `.app` files. The index is cached by each `.app`'s sha256, and the
     walk has a time cap with an "incomplete" line.
   - **Starts:** from the selected test methods and the codeunit's `OnRun`.
2. **Use it to order the list:** codeunits with a found path to `HttpClient` first, each with one path. It never decides
   whether the line prints.
3. **Measure on DO before landing:**
   - for each hung method (`Uniqueness_ThreeWayCollision_Errors`, `ApplyAuthSettings_EarlyValidationFails_SecretsUntouched`),
     whether a path is found;
   - the count flagged;
   - the time with Base Application in the cache (8,135 files).
4. **Measure `AllowOutboundFromHandler` with a handler that lets the request go:** PR-176 measured only the no-handler case.
