Found by coord task PR-28 while checking whether family 5 covers the ledger's #7480 key. Evidence: `/coord/handoff/PR-28/`
(`causes.txt`, `nc/`). Related: [[R1024]] (family 5, no-client, and its BC-check app), [[R890]] (the Bank Deposits suite).

**What.** The ledger key "Business Central Server attempted to issue a client callback to show a confirmation dialog box" has
2,290 standing sightings in 6 stores (R1036's count), all Bank Deposits tests. Those tests bind a `ConfirmHandler` (for example
`PostBankDepositWithLink`, `[HandlerFunctions('GeneralJournalBatchesPageHandler,ConfirmHandler')]`).

**Measured on al-runner edge-5a58a0f16.** Family 5's no-client app, run with and without `--no-client`:
- **without `--no-client`:** C3 (Confirm, handler bound) passes and C7 (StrMenu, handler bound) passes; C4 and C8 (no handler)
  fail "Unhandled UI";
- **with `--no-client`:** all four fail with BC's client-callback text, including C3 and C7, whose handler is bound.

So under `--no-client` al-runner never calls a bound Confirm or StrMenu handler.

**Why it matters.** LethAL passes `--no-client` because BC's web-service path, where LethAL runs tests on BC, has no client
(R1024). Whether BC's test runner calls a bound handler there is not measured:
- **If it does:** al-runner's error is a wrong answer for every handler-bound test, and LethAL loses those tests' coverage on
  al-runner.
- **If it does not:** al-runner matches BC there.

**What else was ruled out.** No BC run measured these Bank Deposits tests: R-882 and R-908's BC runs refused them before
sending (TestPage) or failed on RDLC rendering. #7480 upstream is a different shape (an unhandled Confirm in `OnClosePage`), so the
ledger key now maps to #8028, family 5's issue.

**To close:** lethal-bugs' BC run of family 5's BC-check app (`/coord/handoff/PR-17/bc-check/no-client`, cells C3 and C7, through
the web-service path). Then either file the wrong answer upstream with the measured result, or record that BC matches.
