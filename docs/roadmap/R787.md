**Filed 2026-10-25 by lethal-preproc, from coord task R-783.** Related: [[R614]], [[R783]].

**What was found.** `/work/lethal-wt/r759/fixtures/sandbox-harden-tests/.alpackages` is a symlink into lane-bugs'
worktree (`/work/lethal-wt/lane-bugs/fixtures/sandbox-harden-tests/.alpackages`). Copying it with `cp -r` copies the
link, so a third worktree then points into lane-bugs' worktree too. That happened in R-783's spike worktree; it was
replaced with a real copy before any gate used it.

**Two harms.**
- **Writes reach another lane.** A gate that fills or rewrites a fixture's symbols (`prepareFixtureSymbols`, a test
  app restore, an alc compile into `.alpackages`) writes through the link into another lane's worktree. That lane's
  next gate then reads symbols it did not put there, which is the R56/R614 stale-symbol class.
- **Git does not ignore it.** `.gitignore` says `.alpackages/`. A pattern with a trailing slash matches directories
  only, so a symlinked `.alpackages` shows as untracked (`?? fixtures/sandbox-harden-tests/.alpackages`), and
  `git add -A` commits it.

**Proposed fix.**
- `.gitignore`: add a `.alpackages` line with no trailing slash, so a link is ignored too.
- A gate preflight that refuses a symlinked fixture `.alpackages` by name before any lease or server call, for
  example in `printItestTarget` (`config-path.ts`) or the fixture-symbol check. The message says to replace it with
  a real copy (`cp -rL`). The v3 itest's fixture `.alpackages` check could take the same rule.
- A test per direction: a symlinked folder is refused; a real directory passes.

**Not touched.** lane-bugs' folder, and r759's link. Their owners decide.

**Done (2026-10-25, coord task R-787).** Both harms are closed, at the two places every gate passes through.
- **Refused by name.** `symlinkedAlpackages(root)` (`itest/fixture-symbols.ts`) lists every
  `fixtures/<dir>/.alpackages` and `examples/<dir>/.alpackages` that is a symlink. Two places refuse on it, and the
  message names each link and the fix (replace the link with a real copy of its target):
  - `printItestTarget`, which every BC itest calls right after it picks its config, throws
    `SymlinkedAlpackagesError` before any line, lease or call. It checks this worktree; a unit test passes its own
    `repoRoot`, and a call that passes its own marker options without one checks nothing.
  - `prepareFixtureSymbols`, the v3 gate's and the update gate's symbol preparation, throws
    `FixtureSymbolsRefusedError` (`al-runner-v3-gate-fixture-alpackages-symlink`) before anything is extracted or
    read. So nothing is ever written through a link.
- **Ignored by git.** `.gitignore` now says `.alpackages` (no trailing slash), which matches a link as well as a
  directory.
- **Why here.** These are the shared entry points: every BC gate prints its target line first, and every v3 run
  prepares its symbols first. `scripts/bc-republish.ts alpackages`, the one script that fills a fixture folder,
  already removes the path first (`rmSync` on a link removes the link, not its target), then makes a real directory,
  so it needs no check.
- **Tests** (`fixture-symbols.test.ts`, "R787"), each red with its guard removed:
  - the list holds exactly the links;
  - `prepareFixtureSymbols` refuses and leaves the other folder, the marker and the gate folders untouched; real
    folders still extract;
  - `printItestTarget` refuses a worktree with a link and prints for a real folder;
  - git ignores a non-directory `.alpackages`.
