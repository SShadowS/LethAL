**Filed 2026-11-06 by lethal-code, from R843's plan review.** Related: [[R843]], [[R709]], [[R629]], [[R847]].

**What.** [[R843]] refuses a target whose object has the same kind and id as one in an installed direct dependent. These can still reach
BC on an upgrade, and may leave a target uninstalled the same way:

- a tests `tableextension` field id against a new field in the target;
- an enum value ordinal;
- an installed app that is not a dependent of the target;
- a transitive dependent, which `installedDependents` does not list;
- a test app the env-tool hook publishes before the target's deploy.

Also not measured: whether BC's check matches alc's on kinds other than Codeunit, and on one id across kinds. [[R629]] tried codeunits.

**Not measured whether each one strips a server.** [[R709]] measured a compile break. Extending `scripts/r629-probe` with fresh publishes
would settle the kinds safely, since a fresh publish restores cleanly. The others need an upgrade on a server that can be restarted.

## Fixed (coord task R-845, 2026-11-06)

Built as `docs/superpowers/specs/2026-11-06-r845-field-enum-transitive-precommitment.md` says. The standing rule: a comparison refuses only
on a BC measurement; what only alc backs, warns.

- `packages/runner/src/member-clash.ts` (new): member reading and comparison. The package side reads `TableExtensions[].Fields[]` and
  `EnumExtensionTypes[].Values[]` from `SymbolReference.json`, strictly: a bad `Id`, `Ordinal` (omitted means 0), `Name`, `Properties` or
  `TargetObject` makes the package unreadable, never empty. `TargetObject` is `#<app id>#Name` or a bare name (the declaring app's own
  table or enum; a bare name that app does not declare is named in a warning and not compared). The source side reads fields and values by
  tree, per `#if` arm, and a file whose arms cannot be decided warns.
- Refusal rules, on the SAME table or enum: field id equal; field name equal, EXACTLY (case-only differences are accepted by BC: L5);
  enum ordinal equal; enum value name equal, exactly. The same id, name or ordinal on a different table or enum does not refuse. Page,
  action, report-column and object-name clashes are not compared. On the target's own table or enum the pair refuses. On another
  app's table the pair refuses only if that app is in the target's `app.json` `dependencies` or is one of five Microsoft apps (Base
  Application, System Application, Business Foundation, Application, System); otherwise it warns, since a same-named table may be another
  app's. A qualified `extends Ns.Name` pointing away from the target's namespace is not "own".
- `Moved` (`ObsoleteState = Moved`, `MovedTo`, `MovedFrom`) on either side of a field, enum value or table pair warns, never refuses
  (not measured on BC). R843's (Table, id) comparison got the same exemption.
- Transitive dependents: `walkTransitiveDependents` in `dependents-warning.ts`, breadth first, the tests app's branch first, the target's
  id seeded into the visited set, a failed read of one level warns by name and ends that branch. `checkObjectClashes` reads the package of
  each of them. Bound: 40 apps and 120 s in all, from the start of the walk; at the bound it warns (`object-clash-unchecked`), naming how
  many were not read and the first few, and never refuses or fails. `dependentsWarning` names transitive dependents too (U4).
- Source fallback (the tests package unread): objects compare as in R843; a member clash from the fallback WARNS, never refuses, and a
  tests-app table of the target's name is the tests app's own and is left out.
- `unquote` now turns `""` into `"`.
- One helper, `bcClashText` in `app-version.ts`, names BC's three clash texts ("defined in multiple apps", "can only appear once in the
  table", "Metadata delta application failed"). `UpgradeNotRestoredError` says each in BC's words, `classifyDeployFailure` records no
  publish ceiling for any of them, and `ObjectClashError` carries `memberFindings` with advice to change or remove the field or value, in
  the target or in the named app (rebuilding that app alone fails with AL0206).
- U3 (a clash with an installed app that is not a dependent): BC's text has no restore sentence, so `restoreFailed` did not match and
  `UpgradeNotRestoredError` did not fire. Before this, the run threw the raw `PublishFailedError` with no word on the damage, and for the
  field and enum texts `classifyDeployFailure` recorded a `failed` publish outcome, a false publish ceiling at that guard count. Now
  `upgradeNotRestored` returns the new `UpgradeClashRefusedError` (extends `Error` directly) for a clash text with neither "could not be
  restored" nor "have been restored", which says BC made no restore attempt, what the measurements found, and names the recovery section.
  A clash BC restored cleanly stays the plain `PublishFailedError`.
- Recovery for a user's own server: the section "Recovering a stripped server" in `docs/using-lethal-from-an-agent.md`, named by
  `ObjectClashError`, `UpgradeNotRestoredError` and `UpgradeClashRefusedError`.
- Real alc builds in `scripts/testdata/` (`r845-base.app`, `r845-ext.app`, `r845-moved.app`), digests pinned in
  `scripts/bc-app-content.test.ts`; read through `declaredObjectsOfPackage` in `packages/runner/tests/member-clash.test.ts`.
- Run over every `fixtures/*` pair, source against source, fields and values included: 0 clashes, pinned in
  `packages/runner/tests/object-clash.test.ts`.

**Limits, named.**

- U3, an installed app that is not a dependent (objects, fields and enum values alike): not visible to this check. Filed as [[R847]]
  (a control-app action reading `AllObj` and `Field`).
- A table reached through `propagateDependencies` is not in the target's `dependencies`, so a clash on it only warns.
- One table or enum name in two trusted apps can refuse wrongly: the source side matches on the name and cannot check the owner's app
  (Base Application and Business Foundation share 8 table names).
- An env tool's publish command may use another schema mode, and the hook's own test-app publish runs before this check.
- Report columns and trailing spaces in names: not measured. All 13 object kinds are measured on BC (an upgrade strips on one kind and
  id), and table against page with one id is accepted (K2).
- A transitive member clash cannot exist (alc AL0247: a table extension needs a direct dependency), so the member rule reaches direct
  owners in effect.
- The source side identifies the owner of an extension by name; a header split by `#if` is not read for members (a note says so); an
  unqualified `extends Name` resolves to the target's own table of that name even if a `using` could point elsewhere.
- Fixture targets: recovery is measured on scratch apps.
- A dependent as big as Base is 46 MB: its 15 s read deadline warns, as an unreadable package does today.
