---
id: "R509"
title: "The type table reads `Record \"X\" temporary` as no table, so a field of a temporary record has no type"
section: "correctness-risks"
status: "open, filed 2026-10-08"
order: 1219
---

**Found by** the opus review of the [[R502]] plan (I3).

`recordTableName` in `packages/engine/src/semantic/types.ts` takes the declared type TEXT
(`VarSymbol.typeText`) and matches `^\s*Record\s+(.+?)\s*$`. For `Record "Sales Line" temporary` the captured
name is `"Sales Line" temporary`. That is not one quoted name, so nothing is unquoted, and no table has that
name. `memberType` then answers `null` for every field of a temporary record. The call-return branch of the
same file has the same shape for `Record X temporary` receivers.

The receiver binding does not have this problem. `classifyDeclaredType` (`receiver.ts`) reads the AST, where
`temporary` is a separate token.

**Effect.** It is a missed type, never a wrong one. Type-dependent operators (`swap-call-arguments` and others)
emit nothing where they need the field's type. This is the safe direction (R87 is what a WRONG type costs), but
it loses mutants on code that uses temporary records heavily.

**To close.** Read the type from the AST, or strip a trailing `temporary` keyword before taking the name. Specs
will move, so measure the spec diff on the corpora and ask for an identity scheme. [[R502]] deliberately left
this path unchanged (a text that is not a clean dotted name keeps the old reading), so that the R502 diff stays
about qualified names.
