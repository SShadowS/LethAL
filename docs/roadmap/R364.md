**Found by R-214's pre-commitment (2026-09-30).** The orchestrator's ruling
(q-20260930T062258-5a3574ac) is to file this, not fix it here: R-214 does not change typing.

**The shape.** The semantic layer (symbol table, types) reads the ORIGINAL tree, so it sees every
`#if` arm. The build alc compiles has only the active arm. When a declaration lives in an arm (a
member's header, a `var` line, a whole duplicated member), the operators that consult the
semantic layer (`requiresSemantic` non-empty: `flip-boolean-literal`, `remove-assignment`,
`return-value`, `shift-integer`, `swap-additive`, `swap-call-arguments`, and every Tier-2 operator)
can type a site differently from the compiled build. This is R302's class.

**Measured.** "Twin" is R-214's full twin, the source with every directive line and every inactive
line blanked, which is the text alc compiles. Counts are rows by operator: `twin-only` means the
compiled build has the mutant and master does not; `expected-only` means master has it and the
compiled build does not (`$Q/presence.ts`, `docs/superpowers/specs/2026-09-29-r214-precommitment.md`).

| corpus.set | twin-only (master loses it) | expected-only (master has it, the build does not) |

| dc.0 | flip-filter-literal 3, remove-assignment 2, remove-calcfields 2, remove-setrange 42, remove-testfield 1, swap-additive 2, swap-call-arguments 33, swap-modify-flag 6 | flip-boolean-literal 6 |

Every `expected-only` row is a `flip-boolean-literal` nested inside a Tier-2 row (`swap-modify-flag`
and friends) that the compiled build has and master lacks: Tier 2 displaces the nested Tier-1
flip there (design §3.2). So master's extra typed mutants are displaced Tier-1 mutants, which
compile. Most `twin-only` rows are master LOSSES: a Tier-2 or typed operator declines because the
declaration it needs sits inside a directive.

**Three hand-written repros and an alc check.** The repros are committed under
`packages/runner/tests/fixtures/r364/` (`t1-return-type`, `t2-swap-args`, `t3-dup-member`, each with
its no-directive control under `ctl/`; sets `[]` and `[RSYM]`). The check is
`bun scripts/r364-mut-compile.ts`: for every raw master spec and every set it compiles the copy with
ONLY that mutant applied (alc 18.0.2732683), and separately compiles the copy with that mutant's
span replaced by an undefined identifier. When the second build also compiles, alc never built the
site under that set, so the first result is a trivial pass and proves nothing.

t1, a split header:
```al
codeunit 50021 "T1 Return Type"
{
#if RSYM
    procedure Pick(X: Integer): Integer
#else
    procedure Pick(X: Text): Text
#endif
    begin
        exit(X);
    end;
}
```

t2, a `var` line in an arm:
```al
codeunit 50022 "T2 Swap Args"
{
    procedure Go()
    var
        A: Integer;
#if RSYM
        B: Integer;
#else
        B: Text;
#endif
    begin
        Pair(A, B);
    end;

    local procedure Pair(X: Integer; Y: Integer)
    begin
    end;

    local procedure Pair(X: Integer; Y: Text)
    begin
    end;
}
```

t3, a member duplicated across arms:
```al
codeunit 50023 "T3 Dup Member"
{
#if RSYM
    procedure Sum(A: Integer; B: Integer): Integer
    begin
        exit(A + B);
    end;
#else
    procedure Sum(A: Text; B: Text): Text
    begin
        exit(A + B);
    end;
#endif

```

**No master mutant of these shapes fails to compile.** Of the 12 repro builds, 9 are real tests
(the site is built) and 3 are trivial passes; all 12 compile. In all three repros the typed
operator DECLINES rather than mistypes, which is a loss: the controls show the same operator
firing without the directive (`return-value` in t1, `swap-call-arguments` in t2, `swap-additive` in
t3). In t3 master types only the first arm's member: its `return-value` sits in the `RSYM` arm (a
real test under `[RSYM]`, trivial under `[]`), and the `#else` member, the one `[]` builds, gets
none.

**Not done here.** A typing fix (reading declarations per effective build) is its own design.
The corpus counts above are pinned in R-214's pre-commitment, so a change to them is visible.
