**Filed by** PR-456 (lethal-code, 2026-11-26), on the orchestrator's word. The cost was measured by lethal-bugs on
PR-427: three bc4 restarts in one day voided about 2,800 decided verdicts.

- **Today.** R680 records LethAL Control's server generation and refuses `--resume` and `--resume-run` when it has
  changed (`ServerGenerationChangedError`).
  - R969 added a database id that `force-reset-lease` never touches, so a lease reset on a SURVIVING database carries.
  - A restart that loses the database still refuses. That includes every restart of the Linux BC servers, whose
    databases are in memory.
- **R959's ruling** kept that refusal: re-verifying the published apps (ids, versions, hashes) cannot see company data,
  and a fresh container with the same apps republished would pass it.
- **The new condition** (the orchestrator, 2026-11-26) answers R959's objection with a measurement. Earlier verdicts
  carry only if both hold:
  - the re-setup republished the SAME apps (target, tests, dependencies, control app: ids, versions and hashes);
  - the resume's FRESH baseline equals the stored baseline per test.
  - The baseline measures what the company data does to the tests themselves.
  - Verdicts from a degraded window (R1227) or a lost batch never carry.
