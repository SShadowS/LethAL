**Found by the first Linux run of the unit suite (kraken-move Task 6, 2026-10-03, Bun 1.4.2 in the
`kraken-lethal:dev` image).** `scripts/test-preload.ts` hides the real home by setting `HOME` and
`USERPROFILE` inside the `bun test` process. On Windows `os.homedir()` reads `USERPROFILE` at call
time, so that works. On Linux, Bun's `os.homedir()` keeps the value it had at start: measured in the
image, `process.env.HOME = "/x"` then `os.homedir()` still prints `/home/dev` (Node prints `/x`).

**What it breaks.** Every product default under the home directory (al-runner's two caches, the
quarantine dir, the env-tool state dir, the VS Code extensions dir) resolves to the REAL home in a
Linux unit run, which is what R264 exists to prevent.

Failing test: `unit tests run with the real home directory hidden (R264)`
(`packages/runner/tests/real-home-guard.test.ts`). Evidence line from the capture:

```
Expected: "/tmp/lethal-unit-run-vonahf/home"
Received: "/home/dev"
```

**To close.** Product defaults read the home through one helper that reads `HOME` at call time on
POSIX, and a guard test refuses a direct `homedir()` call in product source.
