**Filed 2026-11-05 by lethal-preproc, from coord task R-813.** Related: [[R658]], [[R598]].

**What.** The wrapper for `itest:hang` takes its coord lease in lane `bugs`, defaults its worktree to
`/work/lethal-wt/r658`, and writes "lane bugs" into the out-of-use marker. Run from another lane, it would lease in
another lane's name, which R598 forbids. So R-783 and R-813 ran `itest:hang` directly, under their own lease.

**What that loses.** The wrapper's safety net. On a STOP or an armed BASELINE leg it holds the lease, heartbeats and
writes the out-of-use marker. R-813's driver (`/coord/handoff/R-813/gate.sh`) copied the hold, not the marker.

**Built (R-823).** `bash scripts/r658-hang-gate.sh bc2|bc3 [--lane <lane>]`.
- **The lane** is `--lane`, else `KRAKEN_AGENT`, else it refuses by name before any lease: R598's rule, as `resolveLane`.
  kraken does not check who calls, so `--lane` can still name another lane, as with `bc-linux-setup.ts`.
- **The worktree** is the one the script lives in.
- **The marker** names the lane. The stop, hold, release and marker logic is otherwise unchanged, line for line.
- **Evidence (from the build review).** All lanes shared `/coord/handoff/R-658/hang-<server>/`, so the next run would have
  overwritten the `hang.log` that `servers.md` cites. Each run now gets its own folder.
- **Red checks:** 18 of 18. The review added three test holes to close: the lane regex's end anchor (it stops a lane
  forging an `owner:` line), the worktree tested from a foreign folder, and the dirty refusal, which had no test.

**Left as it is.**
- A worktree whose imports fail (no `bun install`) dies before `[itest target]`, so the wrapper HOLDs a healthy server.
  It fails safe, and costs an owner's look.
- `/coord/handoff/R-658/run-hang-gate.sh` still calls the old path, which leases as `bugs`. It is lane bugs' file.
