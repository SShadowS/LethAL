**Found 2026-10-05 while planning R458** (coord handoff `R-458`, plan r1 open question 3).

`testpage-scan.ts` `buildUnit` puts `Rec` (typed `Record <TableNo>`) into the unit's `implicit`
map for a codeunit with `TableNo`, and every procedure and trigger of that unit falls back to that
map when a name is not a local or a global. An `alc` 18.0.43 probe (R-458) measured that `Rec`
exists only in the `OnRun` trigger: in any other procedure of the codeunit it is AL0118 (does not
exist). The engine's own rule agrees (`types.ts` `implicitRecordShadowsGlobals`: `OnRun` only).

**Effect.** Not a mutant claim path: it is the call graph the TestPage scan builds. A procedure
other than `OnRun` that uses a name `Rec` can only compile if `Rec` is its own variable, which the
scan reads first, so the wrong binding is reached only through code `alc` rejects or through a
name the scan fails to see as declared. Not measured on a corpus; may be harmless in practice.

**To close.** Restrict the implicit `Rec` to the `OnRun` trigger (the same rule as the engine),
or show it cannot change a scan result; red test per direction (a `Rec.` call in `OnRun` still
typed; one in another procedure not typed through `TableNo`).

**Closed (e47d0b85; prototype 728a9464; R-466).** `testpage-scan.ts`'s `implicitAt` gives a
codeunit's implicit variables to its `OnRun` trigger only, checked by NAME as well as by membership
of the unit's `triggers` (which holds every trigger a codeunit declares, an install codeunit's
`OnInstallAppPerCompany` included; caught by gpt-6.1-sol's review of the first version). Every name
lookup that fell back to `unit.implicit` (receivers, arguments, `typesOf`) reads through it. Other
object kinds are unchanged.
- Tests (`test-digest.test.ts`, "R466"):
  - `Rec.Touch()` in `OnRun` still reaches the table procedure.
  - The same call in a non-`OnRun` procedure does not.
  - The same call in `OnInstallAppPerCompany` does not either.
  - The two negative tests also pin that their procedure or trigger IS reached, so they cannot
    pass because it fell out of the walk.
- RED-CHECKED:
  - without the restriction, the procedure test fails;
  - with membership only, the install-trigger test fails;
  - with no implicit `Rec` in any codeunit, the `OnRun` test fails.
- Measured before landing (coord handoff `R-466`, `measurement.md`; master d0b4117a against the
  prototype): 0 test-digest and 0 TestPage-scan differences over 125 fixture tests, 1,287 CDO tests
  and 48,809 tests in 178 BC.History test projects. No TableNo codeunit in any test project names
  `Rec` outside `OnRun` (text heuristic), so the wrong binding was never reached there. The fix
  needs no `TEST_DIGEST_SCHEME` bump. The measurement ran on the membership-only prototype; the
  final rule is narrower only for a TableNo codeunit with a second trigger, a shape the measured
  test projects do not have.
