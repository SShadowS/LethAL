Filed by coord PR-44 (2026-11-16) on the orchestrator's ruling, as the dropped half of its pre-commitment
(`docs/superpowers/specs/2026-11-16-pr44-t5-hang-shapes.md`, rule B and addendum 1). Evidence: `/coord/handoff/PR-44/measure.md`.
Related: [[R196]], [[R830]], [[R1050]].

**What.** `lethal.remove-assignment` of `X := <value>` in straight-line code before a loop whose exit reads X and whose body does
not write X. Removing it leaves X at its default. In DO window t5, M7544 hung this way: an outer re-query loop ends `until Count <
Size`, and a size of 0 is never above the count.

**Why not built.** As a plain rule (exit reads X, body does not write X), it removes 11 corpus sites and 15 DO sites, about 2 hangs
per 8 scored. It also removes 4 fixture sites that do not hang, moving `itest:hang`'s baseline:
- their loops progress through an event subscriber that the body analysis cannot see (R830's blind spot);
- removing an initial `Counter := 0` leaves the same value.

**Narrowing to build.**
- Refuse only when the default value is what blocks the exit (e.g. the exit needs `X > 0`, `N < X` or `X <> ''`, and the
  assignment gives X a non-default value).
- Skip loops whose exit-read names have an event-subscriber or same-object-callee writer.
- Measure again: corpus, DO and fixtures. No fixture site may move.
