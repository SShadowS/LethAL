Found by coord PR-204 (lethal-bugs, 2026-11-19), y3. Evidence: `/coord/handoff/PR-204/scoring-draft.md`,
`y3.run.events.ndjson` (`recheck-baseline-finished`: 1,161 tests, 2,087,983 ms; `mutant-rechecked`: 516 rows, 46,538 ms in all).

**What it costs.** With the recheck on by default (PR-182), a DO run adds about 1 h (y3: about 3,650 s, +13% on the wall). Its
own baseline is about 2,088 s of that: the targets' covering tests (1,161), each run alone (method isolation, one test per
session), so rules (c) and (e) can judge them. The 516 target rows themselves take 46.5 s.

**Options to measure (none built):**
- **Run only what the rules read.** Rule (c) reads the killing test alone; rule (e) reads every main-baseline-green test of the
  killing test's codeunit. Count how many of the 1,161 those rules actually read for y3's 516 targets: if far fewer, a baseline of
  just those is the saving.
- **Reuse a method-isolation baseline from an earlier run** of the same build and sources (the snapshot/reuse machinery the main
  baseline has), since the recheck baseline depends only on the targets' covering tests, not on the mutants.
- **Run the recheck baseline concurrently** with the main run's tail (it needs no mutant), if memory admits it.
- The main run's batched baseline cannot simply stand in: rules (c) and (e) need each test ALONE, which is the point of the recheck.

About 30 min per DO run is at stake (owner's speed goal). Measure the rule-read count from y3's events first.

**Measured and built (coord PR-225, lethal-code, 2026-11-19).** Spec and pre-commitment, with amendment 1:
`docs/superpowers/specs/2026-11-19-pr225-r1142-recheck-set.md`. Evidence: `/coord/handoff/PR-225/`.
- **Measured on y3:** the 1,161 tests took about 13 s in the batched main baseline but 2,088 s isolated, so the cost is the
  test count. Rules (c) and (e) read 478 of them.
- **Built, option A** (the owner's yes, q-20261119T134404-d37c858b):
  - the recheck baseline runs each withheld kill's candidate killers (its covering tests that did not pass under the
    mutant in the main pass, read from the run's own store), plus every main-baseline test of their codeunits;
  - on y3 that is 497 tests, about 20 minutes less per DO run;
  - rules (a) to (e) are unchanged, and unmeasured is never a kill.
- **Amendment 1** (found by the Opus build review, before any live run): the nested run executes only the set, so a row can
  also gain a measured kill through a candidate that meets every rule. At most 12 of y3's 409 recovered rows are lost.
- **Reporting:** a kept row whose covering tests the set left out says how many of them ran, and that the rest are
  unmeasured.
- **Option B** (reuse across runs) is filed as [[R1143]], not built.
- **Still owed:** the live check on the next recheck-bearing DO run: all 516 targets per mutant, with gains and their
  killers, and losses and their notes.
