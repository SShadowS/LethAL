Found by coord task R-932 (2026-11-12) with [[R939]]'s close counts (`/coord/handoff/R-932/crypto.run.*`, `findings.md`). Related:
[[R612]] (the keep list), [[R939]].

**What.** On al-runner edge-42af5d384, Cryptography Management's 1,389 mutants took a 1,955 s mutant loop, 849 s of it in daemon
warm-ups, over 250 early closes, all of reason `refusal`. The families are .NET-helper refusals inside mutated code: 70 "raised the
.NET exception ..." (a `MemoryStream`, `StreamReader`, RSA or certificate call given a value the mutation broke), and the rest
"member ... not found", "... is an instance member and the variable holds no object" and similar. None is in
`V3_SERVE_SAFE_REFUSALS`, so each closes the daemon.

**To find out.** Whether a .NET-helper refusal leaves al-runner's runtime state trusted (the helper runs out of process, so an
exception there may not touch the AL session), measured as R612's keep-list entries were: a probe that runs a refused .NET call and
then a test that reads state, on one daemon and on a fresh one, per family. Only measured families join the keep list. Until then
the restarts are correct, and the cost is named in the report (`v3DaemonCloses`).

**Measured (coord R-937, `/coord/handoff/R-937/probe/README.md`, invented AL, al-runner edge-42af5d384).** One refuser per family
and per .NET exception type; per refuser 20 refused requests on one serve daemon, each next reader equal to the reader after a
passing test that made the same writes, and 20 rounds on a fresh daemon each giving the same answer; the pid unchanged; no panic
text. Sensitivity: inside one run under isolation "disabled" the reader does see a leaked row, IsolatedStorage key and
NumberSequence, and there a refused test always left less than (rows, IsolatedStorage) or the same as (NumberSequence) a passing one,
never more. Across requests nothing crossed under any isolation, Commit included. Not measurable: .NET process state in the
helper (`SetEnvironmentVariable` is refused by policy). Clean: a .NET exception of eight types (Format, ArgumentOutOfRange,
ArgumentNull, Argument, NullReference, Cryptographic, OpenSslCryptographic, XPath), a call on a variable that holds no object, an
assembly that is not there at all, a member or overload not found, a stream never created, and `System.TimeZoneInfo.Local`'s policy
refusal. `ObjectDisposedException` was also clean but is left out with every type not listed (a timeout, a cancellation, out of
memory, a failed type initializer could mean the helper itself is not clean); `TimeoutException` could not be reached. "InStream
method on an unassigned Variant" was never produced, so it still closes.
- Seen on the way (not a keep-list question): after a "stream never created" refusal, the next test of the SAME codeunit still runs
  (a plain pass or fail), where every other family marks it notRun (the cascade). The writes before the refused statement are the
  ones BC would also have made before its error, so this may be by design; no difference from BC was measured.

**Fixed (bc2e48ab; pre-commitment f4f09cdd).** Seven entries in `V3_SERVE_SAFE_REFUSALS`, each anchored at both ends, the exception
types by name (`DOTNET_CLEAN_EXCEPTIONS`), free-text tails behind `SAFE_TAIL`; red both ways in `al-runner-serve-rule.test.ts`.
They are not in the update gate's `serve-keep-reasons` fact (it runs without the .NET helper): a reworded text only stops matching
and the daemon closes again. Cryptography Management on edge-42af5d384 (both runs on that build; the after-run's config names it
explicitly), master 6abd6109 against bc2e48ab: all 1,389 verdicts and every baseline test identical; early daemon closes 344 -> 35
(pre-committed: at most 40); warm-ups 1,209 s -> 192 s; the session 2,475 s -> 1,192 s. The 35 left are families never measured
(a cascade after one, an unassigned XmlElement, a stream on an unassigned Variant, and others). The full v3 gate passed on bc2e48ab,
pinned to the same build; no gate figure moved. Evidence: `/coord/handoff/R-937/`.
