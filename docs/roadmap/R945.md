Found by coord task R-932 (2026-11-12) with [[R939]]'s close counts (`/coord/handoff/R-932/crypto.run.*`, `findings.md`). Related:
[[R612]] (the keep list), [[R939]].

**What.** On al-runner edge-42af5d384, Cryptography Management's 1,389 mutants took a 1,955 s mutant loop, 849 s of it in daemon
warm-ups, over 250 early closes, all of reason `refusal`. The families are .NET-helper refusals inside mutated code: 70 "raised the
.NET exception ..." (a `MemoryStream`, `StreamReader`, RSA or certificate call given a value the mutation broke), and the rest
"member ... not found", "... is an instance member and the variable holds no object" and similar. None is in
`V3_SERVE_SAFE_REFUSALS`, so each closes the daemon.

**To find out.** Whether a .NET-helper refusal leaves al-runner's runtime state trusted (the helper runs out of process, so an
exception there may not touch the AL session), measured as R612's keep-list entries were: a probe that runs a refused .NET call and
then a test that reads state, on one daemon and on a fresh one, per family. Only measured families join the keep list. Until then
the restarts are correct, and the cost is named in the report (`v3DaemonCloses`).
