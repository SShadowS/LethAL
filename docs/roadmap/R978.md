(item 3, last bullet).

**What happened.** Microsoft's Recurrence Schedule tests (System Application, 29 tests, baseline 29 green). 76 of 280 mutants are
`error`, all with al-runner's refusal `a test before this one in the codeunit did not pass (<test>: failed (Assert...)) and could
draw random numbers, and this test draws random numbers: the shared sequence is not BC's; this failure is not trusted`. Example
M0007 (`CreateWeekly`, swap-call-arguments): `killingTest` none, 11 covering tests; the note names `TestWeeklyMonday` as the earlier
failure. The failing assertions are DateTime values off by exactly one day.

**Not settled.**
- Whether the earlier failing test is one of the mutant's covering tests. If it is, its failure is a measured kill and LethAL should
  score `killed`, not `error` (the refused LATER test cannot undo it); if it is not, the mutant's own tests were all refused and
  `error` is right.
- Whether the one-day offsets come from the random sequence (al-runner's reason) or from a date or time-of-day dependency in the
  tests (the run was at about 21:30 UTC).
**Next:** read the per-test rows of a few of the 76 (the store keeps test results) and decide; then a fix in the verdict rule or a
note that `error` is right.

**Decided (coord R-967, pre-commitment master 128d782b): dropped kills, fixed.** In all 76 the named failing test is one of the
mutant's own covering tests and the call's first row that did not pass (every earlier row passed). The store shows why LethAL scored
`error`: its covering loop asks tests in its own order, met the refused LATER test first and stopped, never reaching the failure.
The fix flags such a refusal as a cascade (`refusedAfterStop`, as R639 does for a timeout) when the call's first non-passing row is a
plain failure (status fail, no refusal marker, not a timeout); the loop goes on and the failure's own row decides. Red both ways in
`al-runner-v3-backend.test.ts` (R978 C1-C7). The one-day offsets were the mutants' effect on dates, not flakiness: the baseline and
the 54 survivors' covering tests passed in the same window.
**Measured (Recurrence Schedule re-run on the branch, same pool, onprem, edge-c8fe56e05):** exactly the 76 moved error -> killed, each
killed by its named test; killed 92 -> 168, error 77 -> 1 (CalcDate), survived 54 and no-coverage 57 unchanged, baseline rows
identical. Three mutants killed in both runs name another first killing test (M0102, M0203, M0204: `TestWeeklyMonday` now, a
`...WillNotRun` test before): LethAL orders covering tests by measured baseline time, which varies run to run, and both tests fail
under these mutants; the fix does not touch them (no refused row). The pre-commitment's "every other killing test unchanged" was
too strict for that reason.
