**Found 2026-10-21** by the Opus build review of [[R586]] (`/coord/handoff/R-586/review-build-opus.md`, "Checked
and holds", `kind`).

**What.** T15 (`packages/runner/tests/r586-backend-kind.test.ts`, "every backend-identity read in src is
classified") scans `packages/runner/src` for every `.authoritative` read and every compare against a backend
string, and fails on an unclassified site. Today every site is classified, and both directions of the scanner are
tested. It would MISS, in future code:
- a `switch` label, `case "bcdev":`;
- a comparison split across two lines;
- `.includes(...)` on an array of backend names;
- any file in a subfolder of `src` (none exist today).

**Effect.** A new backend-identity branch in one of those shapes could treat `al-runner-v3` as v2 (or bcdev)
without T15 noticing: the class of mistake R586's C1 fixed.

**To close.** Extend the scanner to those shapes, recurse into `src` subfolders, and give each new shape a
fixture line that the scanner must flag (red-going) and a classified one it must accept.

**Since R654 (2026-10-23).** The .NET al-runner was deleted in R654 S3 (35f3c67f), and `BackendKind` (in
`backend.ts`) is now `"bcdev" | "al-runner-v3"`. The mistake to catch is now treating `al-runner-v3` as bcdev, or a
leftover compare against the retired `"al-runner"` string. The blind spots above are unchanged.
