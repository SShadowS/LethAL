Filed by coord PR-212 (lethal-preproc, 2026-11-19). Spec: `docs/superpowers/specs/2026-11-19-r1113-company-warning.md` §2c
(ruled: (i), with (iii) when a store with those tests' coverage is given). Related: [[R1113]], [[R745]], R1122's
`--confirm-from`.

**What is built (i).**
- On BC backends, a default run leaves company-writing test methods out ([[R1113]]).
- A mutant that no remaining test covers, and that sits in a target object those methods (or their one-hop test-app helpers)
  name, is reported unmeasured (`error`, cause `left-out-test-reach`), never no-coverage or survived.
- On DO this marks 1,346 of y2's 26,829 no-coverage mutants (5.0%). The largest contributors are `CDO Data Upgrade` 378,
  `CDO Subscribers` 298 and `CDO Setup` 280.
- It is an over-approximation: a hub object marks every one of its no-coverage mutants.

**What (iii) needs** (the builder's survey):
- a flag such as `--coverage-from <v3 report or store>`, with the same scope and source checks `--confirm-from` runs
  (`confirm.ts`);
- a join on the full site key;
- a per-mutant map of which left-out tests cover each mutant, reaching the `record()` hook;
- flag ownership, the dry run, docs, and tests both ways.

**To close:** given a coverage source where the left-out tests ran (al-runner v3 runs them), only the mutants those tests
actually cover read unmeasured; without one, (i) as now. Measure DO's count both ways.
