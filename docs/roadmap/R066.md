**The `TestPermissions` refusal detector is English-only.** `PERMISSIONS_REFUSAL_RE` (`packages/runner/src/permission-canary.ts`) anchors on BC's English clause "current permissions prevented the action", so on a non-English server every permissions refusal is a silent miss: the tests appear only under `unsupportedTests`, `SessionReport.permissionsRefused` is absent, and the reader is sent to debug tests whose fix is one property. Direction is safe (a miss, never a wrong answer) and the limitation is now TESTED rather than assumed — `packages/runner/tests/permissions-refused.test.ts` pins both the English hit and the Danish miss. Closing it needs a language-independent signal MEASURED against a localized server, not reasoned about: candidates are AL-side `GetLastErrorCode()` inside `RunMutant` (needs an AL change, and a protocol bump if it becomes a new field) and the structural `(TableData <id> <name> <op>: <suite>)` parenthetical, whose tokens are AL keywords rather than prose — the second is cheap but unproven, and a false positive here would tell a user to add a property they already have. Discovered while closing R35.

## Superseded status

**UNBLOCKED 2026-07-31 — the premise was wrong and BOTH candidate signals are now measured.** The row said closing this needs "a language-independent signal MEASURED against a localized BC server". No localized server is needed: BC selects error-message resources by SESSION LANGUAGE, and AL sets that from inside a test body with `GlobalLanguage(1030)`. The existing DK containers already carry the Danish resources. Measured on Cronus281 through the fenced path, one session, ONLY the language differing (`fixtures/sandbox-probes/src/LangRefusalProbe.Codeunit.al` + `LangRefusalRunner.Codeunit.al`, a codeunit that deliberately OMITS `TestPermissions = Disabled` so its write is genuinely refused): **English (1033)** — `code=[DB:ClientInsertDenied]`, text `Sorry, the current permissions prevented the action. (TableData 79201 Rec XRec Probe Insert: LethAL Sandbox Probes)`. **Danish (1030)** — `code=[DB:ClientInsertDenied]`, text `De aktuelle rettigheder forhindrede handlingen. (TableData 79201 Rec XRec Probe Insert: LethAL Sandbox Probes)`. So (a) **`GetLastErrorCode()` returns the SAME `DB:ClientInsertDenied` in both languages** — the language-independent signal this row asked for, now a measurement rather than a candidate; and (b) **the structural `(TableData <id> <name> <op>: <suite>)` parenthetical survives translation byte-identically**, which is the cheap route: it is already inside the text the client receives, so it needs no AL change and no protocol bump, unlike surfacing the error code (which would mean adding a field to `RunMutant`'s result and moving `MIN_CONTROL_VERSION`). **What is still NOT proven:** one locale on one container. `TableData` and the operation names are AL keywords and are very unlikely to localize, but that is an expectation, not a measurement, for the other ~25 languages BC ships. The English regex's MISS is already pinned by `packages/runner/tests/permissions-refused.test.ts`; a structural matcher needs its own red-check plus a test that a NON-refusal message carrying a similar parenthetical is not matched, because a false positive here tells a user to declare a property they already have. **Method note worth keeping:** the first two versions of this probe measured THEMSELVES — the platform refuses `INSERT` (and `COMMIT`) inside a `[TryFunction]` under `RunTests`, so the captured text described the wrapper, not permissions. `Codeunit.Run` is the catch idiom that works. That is R26's mistake, hit twice more in one session.
