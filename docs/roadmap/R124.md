**al-runner v2.0.1.0 dies with an unhandled .NET exception, not a named failure, when two positional
bundle dirs share a basename.** Measured 2026-08-07 on this Windows machine while building R123's
contract probe, which passed the same directory twice as the obvious way to say "run this one broken
bundle":

```
Unhandled exception. System.ArgumentException: An item with the same key has already been added. Key: broken3
   at System.Collections.Generic.Dictionary`2.TryInsert(...)
   at System.Linq.Enumerable.ToDictionary[TSource,TKey,TElement](...)
   at AlRunner.Reporter.SerializeJsonOutput(IReadOnlyList`1 buckets, Int32 exitCode)
      in AlRunner/Reporter.cs:line 180
   at Program.<Main>$(String[] args) in AlRunner/Program.cs:line 1665
```

Exit **127** when run directly; **82** when the process was reaped through a different path. The
tests themselves had already finished — the crash is in report SERIALISATION, keying a dictionary on
the bundle's basename, so the run's actual results are lost after the work was done.

**LethAL is not exposed.** `buildAlRunnerArgv` sends a target dir and a test dir, which in every
real configuration are different directories. The probe was corrected to send a broken target beside
the real test bundle — which is the shape a live run meets anyway — so nothing here is a defect in
our adapter.

**Why report it rather than adapt around it.** R93's adapt-first policy says something goes upstream
only if a capability is genuinely gone with no equivalent, it is a regression against a compat
promise, or **it is a crash or silent failure against their own loud-failure rule**. This is the
third: al-runner's `--help` and its own guide make a point of failing loud and named (an unavailable
BC version "fails loud", an unknown option prints `Unknown option '...'`), and an unhandled
`ArgumentException` with a raw stack trace is the opposite of that. The fix upstream is small —
either dedupe the input paths, or key the report dictionary on the full path rather than the
basename. Note two DIFFERENT directories with the same basename (a plausible `app/src` layout under
two roots) would hit the same thing without any duplication by the caller, which is the case worth
mentioning in the report.

Filed upstream 2026-08-07: **https://github.com/StefanMaron/BusinessCentral.AL.Runner/issues/1692**.
The report leads with the two-different-directories case (`appA/src` + `appB/src`), since that needs
no mistake by the caller, and names both candidate fixes — de-duplicate the resolved input paths, or
key the report dictionary on the full path rather than the basename. Evidence: `docs/measurements/README.md` §"al-runner v2", the
"Passing the same bundle dir twice CRASHES the runner" subsection. Filed 2026-08-07 alongside R123.
