Found by coord PR-21 (2026-11-15) while proving [[R1033]]. Evidence: `/coord/handoff/PR-21/precommit/` (serve) and
`/coord/handoff/PR-21/oneshot/` (one-shot), both `report-diff A B2`: 2 differences of 222. Related: [[R192]], [[R926]], [[R975]].

**What happens.** A session that reuses a baseline snapshot on `--resume` (R192) attributes coverage from the snapshot's rows, but
R926 (a statement's reach from baseline line coverage) and R975 (trigger mutants placed by line) trust line coverage only from rows
that ran in this session (`ranHere`). So two trigger mutants of `Get Service Declaration Lines` `OnRun` (`flip-boolean-literal`,
`remove-not`) are `no-coverage` in an uninterrupted run and `survived` after a resume that reused its baseline: the resumed run sent
them against `ServDeclWithMixOfSalesAndPurchaseLines`, which a fresh run's line evidence had shown never reaches the statement.

**Fixed for serve by [[R1033]]:** a reused snapshot that passed L5's re-check counts as line evidence. **Still open:** the one-shot
transport's R192 reuse, which re-checks nothing. Options: give it the same re-check, or trust a reused snapshot's line coverage as
R192 already trusts its covering sets. Either moves verdicts of resumed runs (toward a fresh run's), so it needs its own
pre-commitment and a look at `itest:lend`'s frozen figures.
