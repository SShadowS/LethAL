Found by lethal-code, 2026-11-11 (coord R-914, EmailLogging on al-runner v3). Related: [[R912]], [[R272]].

**What happened.** The mutants phase said `estimate: 655 covered mutant(s), about 5.9 h of covering-test time`; the phase took
1577 s. Summing each covered mutant's covering tests' own baseline times gives 1194 s. The store recorded every baseline test at
60094 ms: on al-runner a test verdict's `durationMs` is the whole call's time (the whole suite on serve, plus a compile on
one-shot), and the estimate summed it. `cutWindows` shares the same cost, so R912's 600 s windows were cut about 13 times too
small (more, smaller prefetch requests; verdicts unaffected). Separately, the progress line read `median 0.0s` all run: it timed
the 910 no-coverage mutants, which report 0 ms and never ran (the real median was about 48 s).

**Invented repro.** A suite of one codeunit, 10 tests of 5 ms each, run by one al-runner call of 60 s: every test's `durationMs` is
60 000 ms, so a mutant covered by all 10 is estimated at 600 s instead of 0.05 s.

**Fix.** The estimate and the window cut read `measuredDurationMs ?? durationMs` per green test (`measuredDurationOf` in
orchestrator.ts); the timeout budgets keep `durationMs`. The progress median skips `no-coverage`, `known-survivor` and any verdict
recorded with no covering test (an `error` for a failed deploy or an invalid baseline).

**More evidence (coord task R-913, lethal-bugs, 2026-11-11; `/coord/handoff/R-913/<key>.stderr.txt`).**
- Excise Taxes on serve: "about 2.3 h ... That is long: narrow the run" for 535 covered mutants; the mutant phase took about 435 s
  wall, 19x less.
- Error Messages with Recommendations: the estimate is printed TWICE when serve falls back at the warm-up (R916). First for serve,
  "about 9.2 h ... That is long: narrow the run (--only, --lines)"; then, after the one-shot fallback, "about 1.5 h" for the same 330
  mutants. The mutant phase took 2,821 s: the first line was 11.7x off and told the user to narrow a run that did not need it. The fix
  should also make the line printed before a fallback say it is provisional, or print it only once the transport is settled.
- On one-shot the estimate was closer: Enforced Digital Vouchers 6.1 h against about 2.3 h implied by its pace, Payment Links to
  PayPal 8.7 h against about 2 h for 890 recorded.
