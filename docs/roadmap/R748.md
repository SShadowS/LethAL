**Found while building R747 (2026-10-24).** R747 judges `fenced-coverage-no-procedure-lines` per object: it warns for an
object with a naming gap and NO member row in the test. An object with member rows AND gap rows stays quiet.
- That is the likeliest real signature of a 1-2 line base-line shift: most rows still land in a procedure, a few fall
  just outside it.
- Pinned as a known blind spot by the unit test "one object with a member row AND a gap row is quiet".

**To close.** Add a separate warning code for it (the existing code means "no member at all"), with its own observe pass
over every fenced gate first: trigger-heavy objects will show gap rows legitimately (the field declaration line, a var
section), so the rule needs measuring before it is pinned.
