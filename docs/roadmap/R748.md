**Found while building R747 (2026-10-24).** R747 judges `fenced-coverage-no-procedure-lines` per object: it warns for an
object with a naming gap and NO member row in the test. An object with member rows AND gap rows stayed quiet.
- That is the likeliest real signature of a 1-2 line base-line shift: most rows still land in a procedure, a few fall
  just outside it.
- It was pinned as a known blind spot by a unit test; R748 flips that test.

**Built (phase 1, warning only; attribution unchanged).** A new code, `fenced-coverage-gap-beside-members`, in
`warnOnThinFencedCoverage`.
- **The rule, per test, per declared and unrefused object (keyed by type AND id):** at least one row is a naming gap
  (`isNamingGap`: in no procedure span and no trigger span, line above 0) AND at least one row of that object named a
  member. One has-member set splits the gap objects into the two codes, so an object is never in both.
- **The message** carries the test name, `Type:id`, the object-relative line numbers (sorted as numbers), and the count
  of member rows. No AL source. Caps: 5 objects, 8 lines per object, `+N more` on each. It says the lines are
  object-relative, in the instrumented source.
- **The dump.** Each JSONL record of `LETHAL_FENCED_COVERAGE_DUMP` gains `gaps`: every naming-gap row of that test,
  uncapped, as `{objectType, objectId, lineNo, besideMembers}`. The observe pass reads the dumps (one dump path per
  gate), because observe mode keeps only the first message per code. Map the lines to files with the probe.

**Measured (observe pass, 2026-10-25, head 1eaab53d, logs and dumps in `/coord/handoff/R-748/observe/`).** Every fenced
leg ran with its own dump: bc1 bcdev, bcdev-names, bcdev-wrapped, tables, chunked, harden, lend, verify, testapp and
agreement, and bc3 hang. 416 records (4,917 coverage rows on bc1 alone) and **zero naming-gap rows**. Neither code
fired, and every warning set equals its `GATE_WARNINGS` pin, so no pin moves.
- The plan's fear (field declaration lines, var sections) did not show: BC reports executable statement lines only
  (also measured from R-746's raw rows), and those lines all sit inside a procedure or trigger span.
- **Fires: unit-proven only (the 1-2 line shift test); no live positive case.**
- **Quiet: proven on the fixtures only.** The fenced legs never reach the kinds listed under the blind spots below.

**Blind spots (the fixtures cannot show them).** "Nothing fires" proves the rule on the fixtures only.
- Page field source, report or query column, and runtime property expressions appear in no fixture.
- An R318 renamed split member with no coverage name sits in `unnamed`, which `isNamingGap` does not consult. Such a
  row counts as a gap, so beside a named member of the same object it gave a FALSE new warning. Fixed in the
  warnings only by [[R753]] (`LineMap.inUnnamedSpan`); `isNamingGap` and `namingGaps` are unchanged.
- A 1-2 line shift that lands every row in trigger spans stays quiet.
