**Filed 2026-10-21 by lethal-bugs during R-389.** This is the merge review's M2
(`/coord/handoff/R-389/review-build-merge.md`).

**What.** `planVerify` takes the test digests under the guard's answer at verify time (R389's
`closedWorldGuard`, the control app's `DependentCount`). The source run may have recorded
`closedWorld` as `none` or not at all. That happens for:
- an env-tool session, which never asks the guard;
- a run recorded before the guard existed;
- a run against a server with an older control app.

If verify's guard then answers closed, every test's `W` line differs from the recorded digest. So
every test reads as new, with cause `closed-world`. Verify then re-runs the whole suite, or refuses
with `too-many-new-tests`. For env-tool runs this is permanent, not a one-time cost after the
upgrade.

**Safe but costly.** An open-world digest is never unsafe, because the closure falls back to the
whole-app line. So no edit is missed; only work is repeated.

**Candidate fix.** When the source run's recorded tag is open (or absent), verify digests under that
open tag instead of the server's current answer. Use closed only when both answers are closed with
the same flags. Every safety property is kept, and the penalty goes away.

**Evidence.** `planVerify` and `closedWorldGuard` in `packages/runner/src/verify.ts` and
`packages/runner/src/closed-world.ts`; the env-tool session stays open-world (R389, orchestrator
ruling 2026-10-21).

## Done by R-600 (2026-10-24)

`planVerify` reads the recorded digest parts where it builds the digest inputs. Tag `none`: the
guard is not asked and the digests are open-world. Tag `public` or `public+internal`, or no parts:
the guard is asked, as before. Any other tag throws in `parseDigestParts`, so a malformed parts row
now fails a verify that would have passed. Safety rests on the `W` line (an open and a closed digest
never match), so a wrong tag can only re-run more.

Tests: the `R600` describe in `packages/runner/tests/verify.test.ts` (four tests) and the env-tool
verify test in `packages/runner/tests/orchestrator.test.ts`. Red checks: `/coord/handoff/R-600/redcheck.md`.
