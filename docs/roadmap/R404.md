**Found by the R-378 lane (lethal-preproc), 2026-10-02**, from the plan review (`H:/lethal-coord/reviews/R-378-plan/review-r1.md`, finding 1). Plan: `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md` §1 B4.

**What happens.** `packages/runner/src/line-map.ts` (`:370-419`) spans every member it finds, in every arm, so that covered lines can be attributed to members. Split members are handled on purpose (R301, R316, R318): "a line belongs to the member whichever arm was compiled". A member declared only in an inactive arm gets a span. That is harmless, because compiled code puts no covered line there.

The case nobody has measured is two WHOLE-member arms that declare the same name in one object (`#if X procedure Foo() ... #else procedure Foo() ... #endif`). Both are spanned under one name, and the coverage attribution that verdicts depend on (no-coverage) has not been checked against it.

**What would close it.** Measure the shape on both backends first: build with each arm, then look at the coverage rows and the attributed member. Change the span builder only if a verdict moves. If it does, it can use the target's arm ranges (R378's `armOf`), because the line map reads the target.

**Closed 2026-10-02 by ruling (measured, nothing moves).** The pre-commitment is `docs/superpowers/specs/2026-10-02-r404-same-name-arms-precommitment.md` (r2, 5db55749), committed before any live run.

**Fixture.** A scratch fixture (in `H:/lethal-scratch/R-404/`, never a gate) has two same-name pairs in one codeunit:
- Foo: its covered arm is the FIRST (`#if LETHALX`), and its `#else` twin is longer.
- Bar: its covered arm is the SECOND (`#else`), and its `#if` twin is longer.
- Plain: covered in both builds.

**Result.** 9 deployed mutants per build. Measured on al-runner (the pinned c39ad5de build, `coverage: "al-runner"`) and on bcdev on Cronus28 (fenced coverage), under `[]` and `[LETHALX]`. **All 36 predictions matched, per mutant and killing test:**
- **Covered arms:** every mutant in a covered arm is killed or survived, never `no-coverage`. That includes Bar's SECOND arm, which is the case where resolving the name to the first span would have lost coverage.
- **Uncovered twins:** every mutant in an uncovered twin is `no-coverage`, although `Plain` covers the object.
- **The two survivors:** Bar `X > 1000` under `[]` and Foo `X > 1000` under `[LETHALX]`. Each reads `executionProven: true` with `attribution: "exact"` in `lethal explain`, on both backends, so attribution is member-level whichever arm is compiled.

**Gates, on all four runs:**
- the baseline is green;
- the report's `preprocessorSymbols` equals the build;
- `coverageMode` is `al-runner` / `fenced`;
- the dry run reported 9 deployed.

**Why it holds.** The mutated arm's own node gives the manifest member span, and coverage lines from the compiled arm can only fall inside that arm's span. The twin's span carries the same name but receives no compiled line.

**Limits.**
- Raw per-line coverage rows were not extracted separately. The attribution evidence is the per-mutant covering tests and `executionProven`/`attribution`, which are what verdicts are computed from.
- One codeunit and one-shot al-runner. The `--server` and resource legs were not run.

**Ruling.** No change to `line-map.ts`.
