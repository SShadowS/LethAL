Found by PR-10 ([[R1027]]). Evidence: `/coord/handoff/PR-10/guided/triage/` (triage store, edge-5a58a0f16).

The #8038 flip lets 84 Guided Experience tests run. 14 of them now fail on an assertion, all in `Checklist Facade Test`
(codeunit 132604):
- `TestInsert{ApplicationFeature,AssistedSetup,DuplicateAssistedSetup,DuplicateLearn,DuplicateManualSetup,Learn,ManualSetup,Tour}ChecklistItemWithProfiles`
  and `TestUpdate{AssistedSetup,LearnSetup,ManualSetup}ChecklistItemWithProfiles`: "The checklist item (role) table should
  contain exactly one record", expected 1, actual 0.
- `TestUpdateProfilesFor{AssistedSetup,Learn,ManualSetup}ChecklistItem`: "should contain two records", expected 2, actual 0.

Every test that uses profiles fails. Its twin that uses users (`...WithUsers`, `TestUpdateUsersFor...`) passes.

**Cause: the tests depend on test order.** Only the codeunit's first test calls `Initialize(true)`. That inserts four
profiles into `All Profile` and keeps their ids in codeunit globals. The 14 tests call `Initialize(false)` and look up
those profiles, so they pass only when the first test's rows and globals are still there. The users twins insert their
own user, so they do not depend on order.

**Measured** with an invented test codeunit (`/coord/handoff/PR-10/repro/g`, on al-runner edge-5a58a0f16): test 1 inserts a
row and sets a global, and the later tests read them.
- Under `--isolation test`, which LethAL sends ([[R96]]), the global survives and the row is gone, so the row test fails.
- Under `--isolation codeunit`, all three tests pass.

This is BC's `TestIsolation = Function` against `Codeunit`, and al-runner emulates both correctly. On BC, LethAL is
stricter still: it runs each method as its own `Codeunit.Run` (`RunMany`), which resets the globals too. [[R77]] already
records that order-dependent tests go red at baseline under LethAL. So these tests fail under LethAL on BC as well. That is
inferred from the code, not measured. Nothing is filed upstream and no regression entry is added.
