Found by coord task R-942 (2026-11-14), DC window 1 on edge-847b1fa5a (amendment 6, BC 29 packages). Related: [[R1001]].

**What.** Every DC baseline test is refused before it runs: Base Application's company initialize (`System Initialization
Impl.InitCompany`) reaches a subscriber that reads a Continia Core feature row that does not exist. `--verbose` names the cause: Continia
Core's and Continia Document Output's install routines stop at an event raised in a telemetry registry, because a subscriber in an app
with no dependency path to them would run, and the four apps involved exceed the 3 install orders al-runner tries.

**Bisected** (one-shot, `/coord/handoff/R-942/probe-dep*`): not BC 29 (DO's tests pass on BC 28 and 29 packages); every Continia
dependency alone and all together pass with an empty test; adding Microsoft's Tests-TestLibraries (which brings the company-initialize
path) reproduces it.

**Reduced** to six invented apps (`/coord/handoff/R-942/repro-order/`, each alc-clean): a SingleInstance registry raising an event from
two apps' installs, two unrelated subscribers adding to it; four apps refuse, any three pass. The subscribers touch only session state,
which no test can see, so no order changes a test.

**Filed:** https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8056 (asks to treat session-only install effects as
order-independent, or to let the user state the install order).

**To close.** #8056 fixed, the repro passing on `current`, and DC's baseline re-run with its tests running.
