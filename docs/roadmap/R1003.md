Found by coord task R-942 (2026-11-14), DC window 1 on edge-847b1fa5a (amendment 6, BC 29 packages). Related: [[R1001]].

**What.** Every DC baseline test is refused before it runs: Base Application's company initialize (`System Initialization
Impl.InitCompany`) reaches a subscriber that reads a Continia Core feature row that does not exist. `--verbose` names the cause: Continia
Core's and Continia Document Output's install routines stop at an event raised in a telemetry registry, because a subscriber in an app
with no dependency path to them would run, and the four apps involved exceed the 3 install orders al-runner tries.

**Bisected** (one-shot, `/coord/handoff/R-942/probe-dep*`): not BC 29 (DO's tests pass on BC 28 and 29 packages); every Continia
dependency alone and all together pass with an empty test; adding Microsoft's Tests-TestLibraries (which brings the company-initialize
path) reproduces it.

**Reduced** to six invented apps (`/coord/handoff/R-942/repro-order/`, each alc-clean): a SingleInstance registry raising an event from
two apps' installs, two unrelated subscribers adding to it; four apps refuse, any three pass. The subscribers touch only session state,
which no test can see, so no order changes a test.

**Filed:** https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8056 (asks to treat session-only install effects as
order-independent, or to let the user state the install order).

**To close.** #8056 fixed, the repro passing on `current`, and DC's baseline re-run with its tests running.

  #8056 was closed upstream 2026-11-23 as COMPLETED, by design: ADR-079, draft PR #8865.
- **DC's whole suite is STILL refused, with a narrower cause** (`triage-baseline.ts`, BC 29, stop: uniform refusal R1001

  - The text now names one pair: "CDO Install.OnInstallAppPerCompany stopped: event onregistertelemetryprefix: a subscriber
    in app Continia AI - Core would run while an app installs that it has no dependency path to; the install order of the

  - The old text gave no cause. Edge now judges installs per colliding pair, and DC still meets one pair it cannot place.
- **So R1003 stays open:** the repro passes, but DC does not run. Whether the rest of ADR-079 (the draft PR) covers this
  pair is upstream's. The pair's shape goes to alrunner as data (no DC names), not as a new issue.

**Re-measured 2026-11-24 (coord PR-413) on upstream main 88ea54c67**, a measurement build never pinned, with `--verbose`
(`/coord/handoff/PR-413/dc/`): still 1,839 of 1,839 refused, and the cause is wider than one pair:
- **Three install routines stop at the same `onregistertelemetryprefix` event** (a Continia AI - Core subscriber):
  Continia Core's own `CSC App Initialize.OnInstallAppPerDatabase`, and both of `CDO Install`'s. Core's own stop is the one
  that leaves the feature row missing.
- **Six apps are tied** by "an install that touches everything (a .NET call)", which is more than the 3 orders the runner
  tries. So per-pair judging cannot split them while a .NET call counts as touching everything.
- **One more stop is separate:** `CTS-COA Install` stops on the RelationFieldNo refusal.
- **24 of 28 install roots** ran to their end.
- **Sent to alrunner** as data (q-20261124T201707-db75b93a, app names replaced).

**Root cause, 2026-11-27 (coord PR-481)** (logs: `/coord/handoff/PR-481/`):
- **On current edge-e5176a9fd:** DC is still refused: 1,839 of 1,839 not run, with the same three install stops and the
  six-app tie. The tie text says only "(a .NET call)".
- **On main e806d7ebc** (a private build, al-runner issue 8954's diagnostics), every "touches everything" mark is named,
  and none is a .NET call:
  - read-only builtins reached from DC's installs through shared telemetry code: `CompanyProperty.DisplayName`,
    `CompanyProperty.ID`, `NavApp.GetCallerCallstackModuleInfos` and `TaskScheduler.CanCreateTask` (the last is #9082);
  - reads of provider-served system tables (2000000038, 2000000041, 2000000110, 2000000138, 2000000192), the #9159 shape.
- **So the pair stop at `onregistertelemetryprefix` is a consequence, not a cause.** That subscriber's effect is
  session-only, which ADR-079 already accepts, as #8056's repro shows when 3 apps or fewer are tied. The tie of 6
  installs, made by read-only calls, is what refuses DC.
- **Minimal invented repro** (`/coord/handoff/PR-481/repro`): 4 apps with no dependency between them, each install
  reading `CompanyProperty.DisplayName()` and inserting its own row, plus a test that reads one row.
  - al-runner, current AND main: TESTS NOT RUN (exit 7), "4 apps tied by their installs".
  - Controls: the same apps without the builtin PASS; 3 apps with it PASS.
  - BC 28.4 W1 (bc1, build 56590): published W1-W4 then T; the test PASSES.
- **Filed:** https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/9260 (CompanyProperty.DisplayName; also
  names CompanyProperty.ID and NavApp.GetCallerCallstackModuleInfos).
- **To close R1003:** #9260, #9082 and #9159 fixed, then DC's baseline re-run on a `current` carrying them. The
  separate `CTS-COA Install` RelationFieldNo stop may remain.
