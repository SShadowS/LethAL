**Found 2026-10-05 while measuring R454** (plan `docs/superpowers/plans/2026-10-05-R-454-untagged-hang-shapes.md`,
section 1 "Out of scope"; census `census-r454.ts` in that session's scratch, offline).

R196's hang check (`classifyHangCapable` in `loop-hazard.ts`) refuses a value operator's mutation
only when the written target RESOLVES (through `resolveVarRef`) to the same declaration a loop
condition reads. R454 extended that to `R.Field` with a resolved receiver. A write whose target does
not resolve is still declined on purpose (spec 3.1: a name match is a guess), so it is mutated with
no refusal and no tag, even where the loop condition reads the same name:

- **Implicit `Rec` fields** in table and page triggers and table procedures. 13 of them are table
  number-series loops in `OnInsert` / `InitInsert` (e.g. `Customer.OnInsert`): the loop repeats
  while the generated number already exists, so removing or changing the write hangs whenever the
  next number is taken.
- **`with` bodies**: the same unresolved case.
- **Report globals** and **xmlport procedure locals** (a probe confirmed an xmlport local does not
  resolve). R127 says xmlports deploy nothing, so those may be moot.

Measured: BaseApp (Source + Test) 38 sites / 50 mutants, CDO (Cloud + Test) 2 sites / 2 mutants,
no fixture. Every preprocessor arm read as active, so these are upper bounds.

**To close.** Resolve implicit-`Rec` (and `with`) field names to the record's field declaration,
so the existing identity comparison can apply, and make report globals and xmlport locals resolve.
That needs field resolution in the semantic layer, not a name match. Re-measure on BaseApp and CDO,
red test per direction (a number-series loop refused; a same-named field the condition does not
read still claimed), and bump `IDENTITY_SCHEME`.
