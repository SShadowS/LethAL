**Found 2026-10-05 while measuring R454** (plan `docs/superpowers/plans/2026-10-05-R-454-untagged-hang-shapes.md`,
section 1 "Out of scope"; census `census-r454.ts` in that session's scratch, offline).

R196's hang check (`classifyHangCapable` in `loop-hazard.ts`) refuses a value operator's mutation
only when the written target RESOLVES (through `resolveVarRef`) to the same declaration a loop
condition reads. R454 extended that to `R.Field` with a resolved receiver. A write whose target does
not resolve is still declined on purpose (spec 3.1: a name match is a guess), so it is mutated with
no refusal and no tag, even where the loop condition reads the same name:

- **Implicit `Rec` fields** in table and page triggers and table procedures. 13 of them are table
  number-series loops in `OnInsert` / `InitInsert` (e.g. `Customer.OnInsert`): the loop repeats
  while the generated number already exists, so removing or changing the write hangs whenever the
  next number is taken.
- **`with` bodies**: the same unresolved case.
- **Report globals** and **xmlport procedure locals** (a probe confirmed an xmlport local does not
  resolve). R127 says xmlports deploy nothing, so those may be moot.

Measured: BaseApp (Source + Test) 38 sites / 50 mutants, CDO (Cloud + Test) 2 sites / 2 mutants,
no fixture. Every preprocessor arm read as active, so these are upper bounds.

**To close.** Resolve implicit-`Rec` (and `with`) field names to the record's field declaration,
so the existing identity comparison can apply, and make report globals and xmlport locals resolve.
That needs field resolution in the semantic layer, not a name match. Re-measure on BaseApp and CDO,
red test per direction (a number-series loop refused; a same-named field the condition does not
read still claimed), and bump `IDENTITY_SCHEME`.

**Closed 2026-10-05 (81096714), by a by-name match under an implicit-record / `with` gate, not by
field resolution** (plan `docs/superpowers/plans/2026-10-05-R-458-implicit-receiver-hang-refusal.md`,
r3). The field resolver the "To close" above asks for is R464. In `loop-hazard.ts` only: when the
declaration path says no, `classifyHangCapable` asks R-364's `loopConditionReadsByName` once per
record the target's name can bind to, as `implicitReceiver`, and any match refuses:

- every enclosing `with` subject (inside `with R do`, R's field wins over any variable);
- `Rec` in a pageextension, a page with `SourceTable` (procedures too), a TableNo codeunit's `OnRun`,
  a request page with `SourceTable` (any reportextension request page), and in a table or
  tableextension;
- every enclosing report dataitem's name (an outer dataitem's field is visible too), and a
  reportextension `modify(X)`'s X.

Which candidates apply depends on what the name resolves to (R294's measured precedence): no
declaration, all of them; an object GLOBAL, all but table/tableextension `Rec` (there the global
wins); a local, a parameter or a resolved member receiver, `with` subjects only. A `SourceTable` or
`TableNo` inside a member-level `#if` counts unless its arm is inactive (undecided, or no arm map,
counts as present). `targets()`, `generate()` and `refusesHangCapable` share the one decision, so
each refused site is counted in `hang-refused` (R447). `IDENTITY_SCHEME` 18 (17 is R-254's).
Tests: `packages/builtin-tier1/tests/implicit-hang.test.ts`, 20 positives (remove-assignment and
flip-boolean-literal) and 15 controls; every positive was red before the change, and each rule was
red-checked by reverting it.

Measured, exact site diff against master (every node, every tier-1 and tier-2 operator, no arm map,
so an upper bound): **+43 hang-refused** (BaseApp 37, CDO 2, other BC.History 4: SubscriptionBilling
3, Sustainability 1; 34 remove-assignment, 9 shift-integer), the same 43 targets and specs removed,
and nothing else; fixtures and examples empty, so no itest baseline moves. Summary in
`/coord/handoff/R-458/site-diff-summary.md`. Not covered: xmlport locals (R127: xmlports deploy
nothing); the census's 7 whole-object-`#if` report rows were already refused by R-364;
`SuggestVendorPayments` (R468).

**Known limits.** In a reportextension `modify(Line)`, the BASE report's outer dataitems (`Header`
around `Line`) are not candidates, because the base report's structure is not read. A QUALIFIED
outer write (`Header.Done := true; until Header.Done;` inside `modify(Line)`) IS refused: the Line
candidate opens the gate and the matcher matches the Header pair. The missed direction is a BARE
write (`Done := true`) with a qualified OUTER read (`until Header.Done`), where the outer dataitem
is not a candidate. The engine's own `hasProperty` in `types.ts` still has the
`#if` blind spot this fix closed for the hang path (R450). The candidate list is conservative: a
candidate without the field costs an over-refusal, never a hang. Related: R464 (one implicit-`Rec`
resolver), R465 (query return values), R466 (TestPage scan's TableNo `Rec`), R468 (second `var`
section not indexed).
