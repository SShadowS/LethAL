**Found by R-309's plan (2026-09-28)**, `docs/superpowers/plans/2026-09-28-R-309-split-preamble.md`
on branch `lethal/r309`, section "What else touches this node". Filed by the orchestrator ahead of
R-309 so no other session re-finds it. Sibling of [[R309]] (the whole-run throw for this shape),
[[R301]] (the shared-`var` split procedure) and [[R302]] (the same site blindness for
`preproc_split_procedure`).

**What breaks.** A `preproc_split_procedure_preamble` member (each `#if` arm holds a header and its
own `var` section, before one shared body) is not a member anywhere in the pipeline: its
`procedureName` is `""`, it has no scope, and the line map finds no member span for it (the gap
block climbs to the file root). Two measured consequences, on hand-written repros under al-runner
v2.11.0:

- **False `no-coverage`.** With al-runner coverage ON, every mutant in such a member reads
  `no-coverage`, although its tests execute it: with coverage OFF the same mutants are scored
  (3 of 4 killed on the plan's repro). This drops live sites from the score. It never makes a kill
  or a survivor.
- **Lost sites.** The same body gets 7 mutants in a plain procedure and 4 in a preamble
  (`empty-block`, `return-value` and one `swap-additive` are missing), measured on the twin-body
  repro `q1-twin-body`.

**Size.** 0 corpus files hold this shape (R-297 Task 0's census and R-309's re-check). The trigger
form does not parse as a preamble at all (tree-sitter-al issue #32) and is refused as [[R313]].

**What would close it.** Make the preamble a member in the walks [[R301]] extended
(`isProcedureLike` or a sibling predicate for the manifest, scope, line map and gap block), so its
mutants get a name, a span and coverage attribution, and the missing operators see its body. Then
consider a per-arm reach latch (the latch declared after each arm's header), whose `alc` evidence
(`pa-p1`, `pa-p2`, `pa-p4`, `pa-p8`, every subset PASS; latch in the first arm only fails with
AL0118) is in the R-309 plan. Until then R309's named refusal keeps such a member's mutants at
`reachGrain: "unplaced"`.

**Closed 2026-09-28 (R-316).** Plan: `docs/superpowers/plans/2026-09-28-R-316-preamble-member.md`.

- **The predicate.** `isProcedureLike` (`packages/engine/src/ast/tree-walks.ts`) now admits a
  `preproc_split_procedure_preamble`, so every walk [[R301]] extended sees it as a member: the
  manifest's name, scope and member lines, the gap block (`gapBlockOf`), both line maps (fenced
  bcdev's and al-runner's Cobertura index, each built from the emitted source) and `latchNameFor`.
  `findEnclosingProcedure` and the semantic walks still do not; that is [[R302]].
- **Scope.** `procedureScopeOf` reads scope per arm for either split shape: `local` only when every
  arm is `local`, so a public arm never widens coverage to object grain.
- **Name.** [[R301]]'s rule, unchanged: one name when every arm agrees, none (`""`) when an arm
  renames the procedure. A renamed member therefore still reads `no-coverage` under coverage
  attribution when it is public; that gap is filed as [[R318]].
- **Identity keys.** An agreeing preamble's keys gain its name in the procedure part. The one other
  effect, measured on hand-written collision repros: an identical site after an agreeing preamble,
  in the same object, under the same operator, is renumbered, because the preamble left the `""`
  twin group and joined its name's group (`c1-preamble-then-renamed-split`: a renamed split
  procedure's ordinal drops; `c3-preamble-then-overload`: a same-named overload's rises;
  `c2-renamed-split-then-preamble`: no change). Pinned by the `ordinals` test in
  `packages/runner/tests/preproc-instrumentation.test.ts`.
- **One reach latch per arm** (`preambleArmHeaderEnds`, `packages/schemata/src/dispatch.ts`; the
  preamble branch in `injectReachLatches`, `packages/schemata/src/compile.ts`). Each arm's header
  takes ` var <latch>: Boolean;` and every arm's var-section `var` keyword is blanked, so each build
  declares the latch exactly once and no line moves. It replaces [[R309]]'s refusal.
- **Parse errors.** [[R313]]'s `varSectionUnparsed` scans a preamble from its own start to its body,
  every arm's header included, and runs before the preamble rule: a parse error in any arm's header
  or var section refuses the latch with R313's sentence (hand-written repros `p14-arm-unparsed`,
  `p15-param-error-nested`, `p16-param-error-before-close`, `p17-param-error-after-open`, and a
  later-arm header error pinned by test). Known wording gap, left as is: for a header error R313's
  sentence still says the member's "var section did not parse cleanly"; the member and outcome are
  right, the runner tests split on that sentence's prefix, and the fix is a sentence change for
  [[R313]] to make.
