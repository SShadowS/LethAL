Found by lethal-code, 2026-11-12 (coord R-942, window 1). Related: [[R955]], [[R896]], [[R866]].

**What happened.** During DO's baseline (1,979 tests, isolation `auto`, default transport), the processes running were one-shot
`al-runner test --isolation codeunit --test-exact <one test> --run-selected-only`, four at a time, each about 30 s and 3 GB (peak RSS of
the run about 20 GB). `--isolation codeunit` is the request mode of a codeunit `chooseIsolation` set to `method` (R896), and a
method-isolated codeunit's tests are baselined one process each (`fillIsolatedBaseline`, R866). R-925's eight BC.History apps all ran
on serve with at most 18 codeunits re-baselined; here the rate implies most of DO's 112 test codeunits went per-test. The run was
stopped before any report, so the fallback/auto caveats that would name the reason were never written (R955).

**To find out (offline, before any DO resume).** Which codeunits auto moved to `method` and why (the trigger in the re-baseline
rule), and whether serve was used at all (no "fallback" line in stderr). Reproduce on a few of DO's test codeunits (`--tests` scope
narrowed) with the report written. Then: a LethAL cost gap (per-test one-shot where a served per-test request would do, R866's
ponytail note), a real interference in DO's tests (then the cost is the price of a correct verdict), or an al-runner difference
(invented repro + upstream issue, no Continia source text).
