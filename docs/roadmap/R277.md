**What.** `ExplainGap.unobservedBlock` is deliberately absent on an operator- or line-narrowed run,
because a narrowed run cannot tell whether every RECORDED row of a block truly survived versus rows
outside the narrowing simply never running. It is also absent on a quarantined run (the report
carries `quarantined`), which stops scheduling mutants mid-run, so a killable neighbour in the block
may never have run either. A `--changed-since` PR run narrows by line, so it falls
into the same withholding: it never gets the mark, even on a block where it would otherwise be true.

**Who hits it.** Anyone running `explain` against a `--changed-since` PR run and expecting
`unobservedBlock` to flag a fully-surviving block: it is silently absent there, same as any other
narrowed run, which can read as "not fully surviving" when the real reason is "not measurable this
way".

**Evidence.** The Task 5 withholding test ("unobservedBlock is withheld on an operator- or
line-narrowed or quarantined run").

**What would close it.** Either accept the withholding as a documented limit of narrowed runs (of
which `--changed-since` is one instance, not a special case), or teach the check to widen its view
for a line-narrowed run when the narrowing happens to cover the whole block.

**Filed under `product-gaps`** per controller ruling (2026-09-27): the roadmap has no
`known-limits` section.

**Found by.** C02-09's own review of GitHub issue #11, filed as a follow-up rather than folded into
this task's scope.

**Done (R-277b).** Admitted only where the mark stays provably true. A line filter (`--lines`,
`--changed-since`) drops a site only when its span touches no range (`spanTouches`), so where the
run's recorded `lines.ranges` cover EVERY line of a gap's block (`spanCovered`, the same
case-insensitive file match), no site of that block was dropped and `unobservedBlock` is kept.
Still withheld: any block a range misses even one line of; an operator-narrowed run (it drops
mutants inside a block whatever the lines); a quarantined run; a line-narrowed run that recorded no
ranges; and R447's hang-refused files. `lines.ranges` is now validated by `assertExplainableReport`
(a bad range is refused, never read as covering a block). No explain schema bump (same meaning,
present in more cases); v13's description and the schema history say so. Pinned in `explain.test.ts`
("R277: ..."): whole, partial, adjacent ranges, a one-line hole, case-insensitive file, operator and
quarantine overrides, no ranges, a malformed range. Red-checked: coverage always true, line-narrowed
always withholding, and the validation removed each turn it red.
