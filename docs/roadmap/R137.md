`lethal.swap-rec-xrec` declares four `conformanceTests` cases whose `expectedSpecs` is EMPTY, and it
has no unit-test file. The conformance runner (`packages/operator-sdk/src/conformance.ts`) checks
only that every EXPECTED spec was produced; it never checks that nothing EXTRA was produced. An
empty expectation therefore passes unconditionally on any input — the operator's four documented
refusals (OnModify sites, assignment targets, a bare `Rec`, a site outside any trigger) have no
offline guard at all. If one of those refusals broke, the first detector would be the live tables
baseline, and it would present as an unexplained new mutant rather than a named regression.

This is the repo's signature empty-vs-empty failure shape, sitting inside `builtin-tier2`.

## What landed

Fix direction 2 (a refusal contract in the harness) plus fix direction 1 (a unit-test file), because
the harness fix immediately turned a real bug red and that bug deserved its own named test.

1. **`runConformance` now treats an empty `expectedSpecs` as a refusal case** and fails it when the
   operator produces anything, reporting the count and every produced spec. A stub-operator test in
   `packages/operator-sdk/tests/conformance.test.ts` pins both directions: a refusal case that emits
   fails, a refusal case that emits nothing passes.

2. **The sweep found that `swap-rec-xrec`'s assignment-target refusal had NEVER held.**
   `isAssignmentTarget` walked up to the enclosing `assignment_statement` and asked
   `current.namedChildren[0] === child`. `namedChildren` builds a FRESH wrapper object on each
   access, so that identity comparison was false even when the two were the same syntax node, and
   the guard returned `false` for every site. The operator was emitting `xRec.Amount := 5` mutants
   the whole time — exactly the non-compiling-mutant class the refusal exists to prevent, which
   would have poisoned a batch and sent bisection after a phantom. Fixed by comparing SPANS
   (`startIndex`/`endIndex`), which identify a node uniquely inside one tree.
   `packages/builtin-tier2/tests/swap-rec-xrec.test.ts` now covers all four refusals, the two
   positive swaps, an indexed assignment target (`xRec.Name[1] := 'A'`), and the read on the RIGHT
   of an assignment that must still be claimed.

## Evidence

- RED, harness: with the refusal contract removed, `fails a refusal case when the operator produces
  a spec it must not` fails and everything else passes — the harness accepted the emitted spec.
- RED, operator: with the span comparison reverted to `===`, three tests fail — the two
  assignment-target tests and `lethal.swap-rec-xrec passes its conformance suite`. That second one
  is the whole point of the row: the conformance case existed before, and only now can it fail.
- GREEN: `bun test` 2286 pass / 0 fail; `bun run typecheck` clean.
- **No live gate figures move.** The offline census is unchanged at 243 raw / 224 deployed for
  `fixtures/sandbox-data/src` and 16 deployed for `fixtures/sandbox-app/src`. The table fixture has
  exactly one `swap-rec-xrec` site (`DataScopeProbe.Table.al:60`, `xRec.Tracked` — a READ), so no
  fixture ever exercised the broken refusal.

The residual hole the fix deliberately does not close — a case with a NON-empty expectation still
does not check for extra specs — is filed as [R142](R142.md).
