[[R196]]'s refusal reads a loop's CONDITION only: a value operator refuses a site that writes a
variable an enclosing `while`/`repeat` condition reads (`hangCapableForMutatedNode`). A loop whose
condition is constant and whose exit sits in the body is not covered:

```al
while true do begin
    I += 1;
    if I > 3 then
        exit(I);
end;
```

**Measured 2026-10-04** on the R-196 code (worktree `lethal/r196`, uncommitted): all six Tier-1
mutants of this procedure are still emitted, among them `remove-assignment` on `I += 1`, which can
never end the loop. `shift-integer` (`1` -> `2`) and `conditional-boundary` (`>` -> `>=`) are also
emitted there and both still terminate. With `I := I + 1` instead, `swap-additive` gives the same
hang. This is the R196 design's section 3.2.1 widening (a target read in the body, not the
condition; `docs/superpowers/specs/2026-09-06-r196-hang-capable-design.md`) and part of [[R159]]'s
general hazard.

**Corpus count, approximate.** A `remove-assignment` site (after R196) inside a `while`/`repeat`
whose target an in-loop `if` condition reads, where that `if` holds an `exit` or `break`: 4 on
`do-lethal/Cloud`, 0 on `do-lethal/Test`, 433 on BaseApp `Source`, 15 on BaseApp `Test`. This
OVER-counts the hazard: it includes loops whose own condition still ends them (a guard that is only
an early exit, as in `repeat ... until Rec.Next() = 0`), where deleting the write cannot hang. A
precise count needs the loop's condition to be constant or unaffected, which is the rule this item
would build.

Closing it: extend `classifyHangCapable` to read an in-body exit guard's condition when the loop's
own condition cannot end it (constant `true`/`false`, or no variable the body writes), refuse
through the same path, measure the added refusals on the reference corpora first, and pin it
positionally with a same-loop control as `packages/builtin-tier1/tests/loop-exit-refusal.test.ts`
does. Scheme bump if any refused site has a later twin.

**Closed 2026-10-05 (d70cad43), identity scheme 23.** When a loop's condition reads no name and
calls nothing (`while true`, `until false`), the guards of its body exits count as its exit test
(`loopExitParts` in `packages/builtin-tier1/src/loop-hazard.ts`): `exit`, `Error(...)` outside
`asserterror`, `CurrReport.Quit`/`Break` (and the `CurrXMLport` twins), and a `break` whose nearest
loop is this one. A write ANY such guard reads is refused and counted as `hang-refused`. Loops whose
condition reads a name are untouched, so the 433-site over-count above is not refused. This is a
scoped heuristic, not a proof: the shapes it still misses are filed as [[R480]], each pinned by a
witness test. Tests: describe blocks "R446: a write a body-exit guard reads ..." and "R446
exclusions ..." in `loop-exit-refusal.test.ts`, and "R446: a body-exit guard's write is refused AND
counted ..." in `refuses-hang-capable.test.ts`.
