Found by coord PR-161 (lethal-bugs, 2026-11-18), the invented-pair hunt. Evidence: `/coord/handoff/PR-161/result.md`, the probe
`probe/` (cell `P161 Session.WorkDateAgainstToday`), and `cells3.tsv` (al-runner, BC's dev-endpoint runner, and LethAL's bcdev
path, per cell).

**Measured on bc3 (BC 28.4.53241.56646, CRONUS International Ltd., a demo company), one cell
`Error('MEASURED workdateIsToday=%1 workdateIsBlank=%2', WorkDate() = Today(), WorkDate() = 0D)` at the start of a test:**
| runner | session | WorkDate = Today? |
|---|---|---|
| al-runner edge-4ebfe7913 (LethAL's v3 backend, client mode) | client | No |
| BC's dev-endpoint test runner | client (`Web`, GuiAllowed Yes) | No |
| **LethAL's bcdev path** (the control app, OData) | `ODataV4`, GuiAllowed No | **Yes** |

**Why.**
- A client session runs Base Application's `LogInManagement.GetDefaultWorkDate` at company open. In a demo company that returns the
  last G/L entry's posting date ([[R771]]: al-runner does this since upstream #5743, as BC does).
- The OData session LethAL's bcdev path runs tests in does not run it, so its WorkDate is Today.
- Both readings are BC's. They come from two session kinds, the same split as GuiAllowed and ClientType ([[R895]]).

**The verdict risk.**
- A test whose outcome depends on the default WorkDate in a demo company can pass on one backend and fail on the other. Examples:
  posting dates that must fall in an open period, CalcDate from WorkDate, aging.
- So the same mutant can get different verdicts on v3 and bcdev. This is not a wrong answer by either runner: each answers as BC
  does for its own session kind.
- On a customer's own (non-demo) company `GetDefaultWorkDate` returns Today in a client session too, so the split is limited to
  demo companies such as CRONUS, which is what our BC servers and al-runner's restored company use.

**Not measured.**
- How many tests depend on it. A parse for `WorkDate()` reads in tests and in the code they cover would size it.
- Whether `--isolate-tests` ([[R857]]) changes it. It should not: it changes grouping, not the session kind.

**To close.** Decide which session the verdict should follow, then measure it. One option is v3's `noClient`, whose WorkDate
should then match bcdev; measure that first. The other is to name the split in the report when a run uses a demo company.
