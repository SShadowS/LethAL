**Evidence.** `/coord/handoff/R-778/breakdown.md` (the measurement and the design), `/coord/handoff/R-778/design-review.md`
(the opus spec review, amendments 1, 2, 4, 5, 6 binding), `/coord/handoff/R-778/red/` (the red/green output of every
guard). Upstream: https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5856 (per-request cost).

**Measured (D1, 63 mutants, 51 kills, serve-entries, dcdf9e821).** The 51 R577 kill pairs (`sendKillPair`: NONE echo,
NONE codeunit, M echo, M codeunit) took 29.6 to 34.5 s of a 36.9 to 42.0 s mutant loop (82% to 85%). A pair request
costs 480 to 930 ms (mean 677 ms); the tests take 3 ms of it. All of it is inside al-runner: a request costs about
0.5 s fixed plus about 10 ms per entry (gift card: about 10 ms fixed, 1.8 ms per entry). So fewer requests is the
lever, not fewer tests.

**Built.** After the prefetch, `batchKillPairs` finds the kills in the prefetched rows (per mutant, the first covering
test whose row is `fail`) and sends their pairs in chunks of at most 64 kills (4 entries each, the 256-entry cap),
each kill's NONE group directly before its M group, kind `live`. `sendKillPair` uses a stored pair instead of sending
one. The orchestrator is unchanged: its confirm and reproduction read the same `lane.pair` as before.

**The review's amendments, as built.**
1. (A1) A group KEY separate from the override text: ids `<key>|<cu>` (`NONE#<mutant>` and `<mutant>#m`), the override
   stays exactly `NONE` or the mutant id. `assertEntriesWellFormed` checks one override per key, the override equal to
   the key or the key `<override>#...`, contiguity by key, and refuses a duplicate key. `request()`'s results and
   resend are keyed by the group key, never by mutant id (the old keying let the last NONE row of a codeunit answer
   every kill's confirm).
2. (A2) Prefetched rows carry `prefetchSeq`, the number of the prefetch request from a backend-wide counter. A stored
   pair is used only if the killing run came from rows with that tag and the pair's request number is higher.
3. (A3) Not built here: the live probe. The follow-up is R784.
4. (A4) Store key includes the artifact id; single-use (deleted at the first lookup, match or not); cleared by a
   deploy (`resetLayoutState`), `prefetchMutants`, `baselinePhase` and `status`.
5. (A5) A chunk that throws stores nothing, ends the batch, and gives the notice `al-runner-v3-pair-batch-skipped`;
   each kill then takes today's pair. Kind `live`, so a refusal costs a kill's saving and never the session. An R612 cut
   keeps the pairs whose NONE and M entries both stood, leaves the cut kill to today's pair, and re-sends the kills
   after it once, on a fresh daemon. A pair is never half-stored, so an M row never stands without its NONE row.
6. (A6) At lookup `pair.ref` is the actual killing ref (the rows cover the whole codeunit).

**Counters.** New: `pairBatchRequests` (batch requests sent, also counted in `liveRequests` and `boundChecks`),
`pairBatchStored`, `pairBatchServed`, `pairBatchRefused` (a stored pair found but not usable). Unchanged:
`pairRequests` still counts a pair whose confirm passed (served or sent), `pairFallbacks1/2` count only pairs sent by
`sendKillPair`. Relation: `liveRequests = pairBatchRequests +` the old per-kill formula over the kills that took
today's path; `boundChecks - warmups = prefetchRequests + liveRequests + coverageRequests` as before. The close line
prints the four new counters.

**Not measured here (no BC server, no itest in this build).** D1 per-mutant equality against the current serve report,
`itest:alrunner-v3` all legs including hang, and the time saving (estimated 22 to 30 s of the 31 to 42 s loop). The
fake serve in the unit tests decides each answer from state (the request's position and its entry count), never from
ids.

**Build review fixes (S1, S2).** S1: `batchKillPairs` now absorbs only `AlRunnerServerRequestError`, as `prefetchMutants` does; an unproven-batch or entries-refused error stops the session instead of leaving stored pairs to serve. S2: a lanes-rig test with the batch ON covers a kill on lane 1 served from lane 0's batch and a live kill on lane 1 refused.
