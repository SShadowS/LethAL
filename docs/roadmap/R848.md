**Filed 2026-11-06 by lethal-bugs.** Related: [[R446]], [[R480]], [[R846]], [[R830]].

**What.** `exitsLoop` counts `exit`, a report quit, a `break` of the loop, and a raised error (`isRaisedError`), but not an error raised by
`TestField` or `FieldError`. So in `repeat Cur := Node.Parent; Node.Get(Cur); Node.TestField(Parent); until false`, the guards and writes
that lead to that error are not exit parts, and a mutant of them can hang. Not measured: synthetic shape from the review.

**Counted 2026-11-06, with a scratch probe, master cd2c02ee.** A `TestField` or `FieldError` counted as an exit, with its own receiver and
arguments as parts, in `exitGuards` (about 10 lines). Counting only the `if` around it is too narrow: it misses the shape above.
Specs newly refused: fixtures 0, CDO 0, DO 0, DC 48 (44 in test projects), BC.History 163. Added 0, tuples 0, tags 0. Ordinals moved: 12 on
BC.History, 0 elsewhere, so it needs an `IDENTITY_SCHEME` bump and a re-record. No fixture key moves. Diffs:
`/coord/handoff/R-842/r848b-diff-*.out`.

**Sampled 2026-11-06 by parse: 15 of the 211, seed 848** (4 DC, 11 BC.History): 0 hang, 0 maybe, 15 no hang. Every loop traced ends by a cursor
step, a counter or a flag. 6 of the 15 are `remove-testfield`, all real mutants that would be lost: that is the cost to check on any build. The
probe also matched a project procedure named `FieldError`, 24 of the 155 BC.History Source specs. A small sample; the table is in
`/coord/handoff/R-842/r848-sample.md`.

**So the rule narrows.** Count `TestField` or `FieldError` as a loop exit only when the loop's own condition is constant (`until false`,
`while true`), and only for the built-in methods, not a project procedure of that name.

**Closed by ruling, 2026-11-06 (orchestrator).** Counts on master f4e17705, fixtures / CDO / DO / DC / BC.History:
- Constant-condition loops: 0 / 0 / 0 / 4 / 40. Those holding a call named `TestField` or `FieldError`: 0 / 0 / 0 / 0 / 1, by name, so an upper bound.
- The narrowed rule moved no spec on any set: added 0, removed 0, ordinals 0.

**A weakness in that probe, on the record.** It can fire, but only in part. On the shape above it refuses `Node.Get(Cur)` and `Node.TestField(Parent)` and leaves
`Cur := Node.Parent` claimed, because `Cur` is neither the receiver nor an argument of `TestField`, and the feed walk follows assignments, not a call that moves
`Node`. An extension, where a body call on a receiver the exit reads makes its arguments exit parts, refuses it too. That is proved on an invented project only and
was not diffed on the corpora. With one loop in five corpora, neither is worth building. Evidence: `/coord/handoff/R-852/counts.md`.

**The limit.** A loop that ends only by a `TestField` or `FieldError` error is not seen, so a mutant of it can hang. That costs a timeout, and on BC 29 on Linux it can
end the run until SShadowS/LethAL#49 lands. It is the same class as the README's "Some loops can still hang".
