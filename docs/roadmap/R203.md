**The sequence.** A slow but finite test exceeds its budget. With `--stop-hung-sessions` the
watchdog fires `StopHungRun`; `TryStopHungRun` matches the marker, calls `StopSession`, tombstones
the op, answers `stopped: true`. `StopSession` takes effect ~4 s later (measured, E8 of the R198
probe). Inside that window the test finishes and `RunMutant` reaches phase 3. `TryFinishRun`
requires `Op Kind = run` for our `(AttemptId, OpSeq)`; the marker is `none` and tombstoned, so it
refuses. `ControlApi.RunMutant` answers `lease-invalid` with no `reason`, discarding the result.
`run-mutant-transport.ts` maps it to `operation: "lease-lost"`; the orchestrator's covering loop
classifies it `lost`, R194's `retryAfter` is not `not-started`, so the refusal is `genuine`,
`noteLeaseLostOrThrow` latches, and the batch's verdicts are invalidated at session end with a
note saying the lease was lost. Nobody took the lease; our own stop tombstoned the op.

**Why it is rare today and would not be under R198.** Today's op is one test, so the window is
the ~4 s after a stop that fires at the budget; a test that finishes exactly then is unusual. A
group op runs for minutes and its stop hits a running method whose remaining time is unknown,
so the window is hit whenever the stopped method was slow rather than hung.

**Fix, in the R198 build.** `TryFinishRun` distinguishes "tombstoned by a stop for this very
`(AttemptId, OpSeq)`" from every other refusal and answers `reason: op-stopped`. That needs a NEW
pair of fields on `LC Lease` (`Stopped Op Attempt Id`, `Stopped Op Seq`), written by both stop
paths and cleared by `ForceResetLease`: no such record exists today, and the residual `Op Attempt
Id`/`Op Seq` that look like one are left identically by a successful `TryFinishRun` and by
`TryRecoverOp`. The answer is given only with the lease tuple still matching (a force-reset after
the stop is a genuine loss and must still latch); the covering loop treats that reason the way it treats
`result-lost`, under its own cause `op-stopped`: this mutant is `error` (its result is lost, the container is clean, the budget was
exceeded but no 408 proved the stop), no latch, no quarantine, continue. Pinned by a fake-backend
test at both grains and by `itest:hang`'s existing ON leg (which must NOT change: a hang never
finishes, so it never reaches phase 3).
