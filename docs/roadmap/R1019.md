Related: [[R978]] (the verdict of these cascades), [[R1004]] and R-998 (other refusals that close the daemon), [[R945]] (the keep

**What happened.** Baseline 5/5 green in 0.4 s. Mutant phase 2,226 s for 343 covered mutants (214 killed, 108 survived, 8
timeout-killed, 13 error). Serve: 466 daemons, 465 warm-ups, 576 live requests. Daemon closes: 424 by the refusal `a test
before this one in the codeunit did not pass`, 28 by timeout, 13 by three Evaluate/date-formula refusals. The other four
modules of the same run (3-4 tests each) needed 2-3 daemons.

**Why.** When a mutant makes an earlier test of a codeunit fail, al-runner refuses the later tests of that codeunit with this
cascade text. The text is not on the serve keep list, so LethAL closes the daemon and the next request warms a new one. In a
codeunit whose first tests kill most mutants, that is one warm-up per kill.

**Question for the keep list.** The refused test did not run, and the failing test ran under per-test rollback; whether the daemon
state is then safe to keep is the same question R-998 answered for its three texts by measurement (a refuser/reader probe on one
kept daemon against fresh ones). Measure it the same way before keeping it.

**To close.** Either the text joins the keep list after such a measurement (and a DO-sized or Filter Tokens re-run shows the
closes gone with every verdict equal per mutant), or the measurement shows it unsafe and this item records why.
