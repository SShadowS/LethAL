`negate-conditional` claims the `until` condition of a `repeat` loop. On the canonical BC shape the
mutant does not terminate:

```al
repeat Process(Rec) until Rec.Next() = 0;    // before
repeat Process(Rec) until Rec.Next() <> 0;   // after: on a ONE-ROW set, Next() returns 0 forever
```

**Measured on `do-rel2/Cloud`:** 334 `repeat` loops, of which **290 are exactly `<rec>.Next() = 0`**
and every one of them is claimed by `negate-conditional` (326 of the 334 conditions are claimed in
total: 303 comparisons plus 23 logical expressions). A test fixture with a single row is the common
case, so a large share of those 290 hang rather than finish.

**This is not new and it is not a wrong verdict.** R53 is exactly this mutant, found as M0013 on
Document Output, and it is CLOSED: with `--stop-hung-sessions` the run scores it `timeout-killed`,
proven live on `fixtures/sandbox-hang` and gated by `itest:hang`. Design §6.7 is explicit that a
timeout counts as killed, since the mutation caused observable misbehaviour. So the mutant is
neither a false kill nor unhandled.

**What IS unfiled is the cost on the default path.** `--stop-hung-sessions` is off by default,
deliberately, because it ends a BC session on the user's server, and
`docs/using-lethal-from-an-agent.md` tells a caller not to turn it on unasked. Without it each of
those mutants strands its tier and blocks every mutant behind it. R53's own limits note adds a
second case: on a hosted topology the proxy ceiling (R44 measured 362 s) can kill the held request
before BC answers, so the feature may be structurally unable to score them there.

**The candidate.** A terminating mutant at the same site, `until <cond>` rewritten to `until true`,
so the body runs exactly once. A SURVIVOR is then a precise statement: no test drives this loop over
more than one row, which is the most common weakness in a BC suite. It scores on the default path,
needs no session kill, and cannot hang.

**It is a precedence question, not just a new operator.** `negate-conditional` claims the site first,
so taking it needs a §3.2-style cession at `until` position, and that has to be designed rather than
bolted on. First measurement before any of it: how many `negate-conditional` mutants sit at `until`
position in the tables fixture, and how each one actually died.

Proposed by the Fable subagent 2026-08-19. Its framing, "a false kill with no screen", is wrong on
both halves; the argument survives restated as a default-path cost.
