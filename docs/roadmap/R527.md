**Filed 2026-10-08 by the [[R500]] build** (plan r3 `/coord/reviews/R-500-plan/plan.r3.md`, adversary r2 finding 4e).
A plausible hang that is NOT refused.

**What.** `Codeunit.Run(Codeunit::X, Rec)` and `Report.Run(...)` start code in another object by id or name, not
through a typed receiver, so R500's one-hop rule does not find the target. Its `OnRun` (or the report's own items)
can write what the calling item's exit reads, and is still mutated.

## Closed by ruling

R-522 measurement, 2026-10-23 (`/coord/handoff/R-522/measure.md`, section R527). 35 rows (BaseApp 29, Withholding
Tax 6); 29 targets are in the project, 6 in another app. OnRun is not refused today in any of the 29 (a trigger is
never a procedure). All 29 were read: 25 `*-Printed` codeunits Modify `No. Printed`, which is in no key, filter,
sort or link of the 25 reports, and `Rec.Find()` re-reads the same key (the Find re-read is the real reason; no
operator rewrites `Find()`); the two VAT Settlement posters insert only rows outside both filters; Post Inventory
Cost to G/L never touches the walked buffer; Resource-Find Price and Create Put-away touch nothing walked. 0 of 29
consume or reorder a walked set. Stated limit: the same-rec class counts any Modify and overstates; a new target
that changes a key field would not be seen.

**To close (original plan, closed by the ruling above).** Resolve the literal target of such calls from open report-item code, measure, then refuse the
target's `OnRun` closure or close it with a ruling.
