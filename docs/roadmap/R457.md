title: "`flip-boolean-literal`'s `false` -> `true` RunTrigger flip on `ModifyAll`/`DeleteAll` FORCES the trigger, R165's `run-trigger-forced` class, and is untagged"
section: "correctness-risks"
status: "open"
order: 1172
---

**What.** `lethal.flip-boolean-literal` flips every boolean literal it does not cede, and it cedes
only `Modify`/`Insert`/`Delete`'s `true`. So `Rec.ModifyAll(F, V, false)` -> `..., true)` and
`Rec.DeleteAll(false)` -> `DeleteAll(true)` are its mutants. Each makes `OnModify`/`OnDelete` RUN for
every affected row where it did not. That is the forcing direction [[R165]] tags for
`Modify()` -> `Modify(true)` (`run-trigger-forced`, emitted where `forcedTriggerCanRaise` finds a
raise-capable statement in the trigger). A kill here can be the trigger's own `Error`, `TestField`
or a write that hits a duplicate key, not an assertion, and today it is scored with no tag.

**Why not in R452.** [[R452]] tagged the SKIP direction (`true` -> `false`) of the same two
arguments. The forcing direction needs R165's scoping, not R281's refusal detector: R165 claims only
tables this project declares that declare the trigger, so a tag means something. Mixing the two in
one change was out of scope.

**Size (probe, R-452 survey, no `#if` arms).** `ModifyAll(..., false)` sites: BC.History 82 (20 on
a table with no `OnModify`); `DeleteAll(false)`: BC.History 217, CDO 32 (all unresolved),
sandbox-data-tests 2 (a test app, never mutated).

**What to build.** In `flip-boolean-literal`, for a `false` that is span-equal to
`exactArguments(call, 3)[2]` of a `ModifyAll` or `exactArguments(call, 1)[0]` of a `DeleteAll`
claimed by `claimsRecordMethod`, resolve the trigger the way `resolveForcedTrigger` does and tag
`run-trigger-forced` where `forcedTriggerCanRaise` holds. Unlike R165 this operator already emits the
mutant whether or not the trigger exists, so only the TAG is scoped; no site is added or removed.
