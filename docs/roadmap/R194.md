**Measured.** *"RunMutant connection failed after dispatch: Error: The socket connection was closed
unexpectedly"* on a mutant, after the run had been healthy for minutes; also two `RenewLease` HTTP
503s in a row (`lease-renew-unanswered`, correctly not treated as loss). The operator put a
one-connection-per-request forwarding proxy between LethAL and the sandbox and the drops stopped
for the rest of the session (its docstring: *"the sandbox's proxy occasionally closes one between
requests. The next write on that socket fails"*). Bun's `fetch` reuses pooled connections; a
survivor takes about 24 s of covering tests, which is long enough for the gateway to close the
idle socket.

**Two halves.**

1. **Transport.** For an `https` target, send each fenced request on a fresh connection
   (`Connection: close`, or Bun's per-request keep-alive switch). One extra TLS handshake per
   mutant is nothing against a 24 s survivor. Measure on the tables gate that a container is
   unaffected.
2. **Reconciliation.** `reconcileLostAck` returns `unresolved` for "the marker names an op that is
   not ours", and the quarantine stands. When the write itself failed, the request never reached
   BC: the marker reads idle with `lastCompletedOpSeq` exactly one below ours. That is not
   "establishing nothing"; it is the server stating the op never began, and the fence's monotonic
   `opSeq` already refuses a late duplicate. Classifying that exact shape as `not-started`,
   retry-safe as a fresh attempt, removes the quarantine and the [[R192]] resume that follows it.
   It is a design §5 change and wants a spec and an adversarial review before code: the failure
   mode to rule out is a gateway that queued the request and delivers it after the retry.

**What it cost here.** One quarantine, one `force-reset-lease`, one `clear-quarantine`, one
[[R192]] resume, one mutant recorded stranded plus its [[R193]] twins.

## OUTCOME, half 1, 2026-09-02

`bc-fetch.ts` wraps `fetch`: an `https` request gets `Connection: close`, an `http` one is passed
through untouched (every live gate is a container over http and keeps the old transport). Measured
on this machine's Bun 1.3.14: three requests reuse ONE socket by default and open THREE with the
header, whether given as a plain object or a `Headers` instance. Every BC-facing client defaults to
it (activation, lease, harness, deployment verifier, permission canary, RunMutant transport, the
published-test-app read, and the three `cli.ts` fallbacks); injected fakes are unaffected. Probed
read-only against `demoportaldev.continiaonline.com` while the operator's run was in progress:
`HarnessInfo` and the lease read both answered through the gateway with the header set. bcdev gate
3/12/4 unchanged.

Not yet measured: a full hosted run with no proxy in front. The operator's run was still going on
the proxy at the time, and switching its transport mid-run would have changed the thing being
measured. The next hosted run should go direct and its drop count is the number to quote here.

## OUTCOME, half 2, 2026-09-02

Design in `docs/superpowers/specs/2026-09-02-r194-never-started-reconciliation.md`, reviewed by
the spec-adversary agent BEFORE code. The review found eight things; the two that mattered most
would have shipped a wrong rule:

- the draft's rule 2c keyed on a `lease-invalid` answer carrying NO `leaseInvalidReason`, which is
  the shape of the phase-3 refusal (a run that DID execute) and never of a phase-1 refusal, i.e.
  exactly backwards. It now keys on a marker read for the original attempt's coordinates after ANY
  `lease-invalid` to a 2b retry, and it has a `completed` arm for the ordering the draft missed
  (the late original finishing before the retry arrives);
- the draft's "there is no fourth history" was false: `force-reset-lease` clears the marker without
  advancing the tombstone. What closes that history is the new generation the reset mints, which
  refuses the retry by the tuple check, and the spec now says so instead.

Also from the review: a second consecutive `not-started` is `unresolved` rather than a continue on
a counter one ahead of the server's; the resync before the retry is guarded; the rule-2 poll now
requires the tombstone, not merely an idle marker; 2c polls with the mutant's own budget; and the
baseline loop is stated out of scope.

**Proof.** `orchestrator.test.ts`, "R194: a lost ack the marker shows was NEVER CLAIMED": eight
tests over the fake lease client, one per marker shape the spec names, including the hole-below-
ours negative, the between-reads claim, the second `not-started`, the three 2c arms and the
throwing resync. Disabling rule 2b fails four; disabling 2c's completed arm fails one. Full suite
2704. bcdev 3/12/4 and tables 299/63/15 unchanged, which on a container path is the control that
the change is inert where no ack is ever lost.

**Not measured, and owed.** How late an abandoned request can still land on the hosted gateway.
The design is never worse than today's quarantine in any of the three orderings and better in two,
which is why it ships without a flag; the probe (abandon one real RunMutant with a tiny budget,
then watch `lastCompletedOpSeq` for minutes) is what would say whether the settling delay is long
enough, and it belongs to the next hosted run.
