**Measured.** *"RunMutant connection failed after dispatch: Error: The socket connection was closed
unexpectedly"* on a mutant, after the run had been healthy for minutes; also two `RenewLease` HTTP
503s in a row (`lease-renew-unanswered`, correctly not treated as loss). The operator put a
one-connection-per-request forwarding proxy between LethAL and the sandbox and the drops stopped
for the rest of the session (its docstring: *"the sandbox's proxy occasionally closes one between
requests. The next write on that socket fails"*). Bun's `fetch` reuses pooled connections; a
survivor takes about 24 s of covering tests, which is long enough for the gateway to close the
idle socket.

**Two halves.**

1. **Transport.** For an `https` target, send each fenced request on a fresh connection
   (`Connection: close`, or Bun's per-request keep-alive switch). One extra TLS handshake per
   mutant is nothing against a 24 s survivor. Measure on the tables gate that a container is
   unaffected.
2. **Reconciliation.** `reconcileLostAck` returns `unresolved` for "the marker names an op that is
   not ours", and the quarantine stands. When the write itself failed, the request never reached
   BC: the marker reads idle with `lastCompletedOpSeq` exactly one below ours. That is not
   "establishing nothing"; it is the server stating the op never began, and the fence's monotonic
   `opSeq` already refuses a late duplicate. Classifying that exact shape as `not-started`,
   retry-safe as a fresh attempt, removes the quarantine and the [[R192]] resume that follows it.
   It is a design §5 change and wants a spec and an adversarial review before code: the failure
   mode to rule out is a gateway that queued the request and delivers it after the retry.

**What it cost here.** One quarantine, one `force-reset-lease`, one `clear-quarantine`, one
[[R192]] resume, one mutant recorded stranded plus its [[R193]] twins.
