Found by lethal-preproc in the combined DO run c2 (2026-11-21), class C of
`docs/measurements/2026-11-21-combined-do-c2-main.md`. Evidence: `/coord/handoff/combined-do/` (`r1167-lines.py/.txt`,
`c2.sqlite`'s baseline snapshot, `c2.run.report.json`). Mutant codes and numbers only.

**What looked wrong.** In c2, 8 mutants of one dispatcher procedure (M6778, M6781, M6782, M6785, M6786, M6789, M6790,
M6793) have 26 covering tests, while every other mutant of the procedure, on the same lines, has 7.
- The first reading (this item's first version) was that the 7-test sets under-report, which would mean false
  survivors. That reading came from a name-format error: `killingTest` names the method alone, so a killer looked as if
  it were outside the 7. Matched properly, every killer is inside the 7.

**What it is.** Measured offline from c2's stored baseline (per-test LINE coverage, as the run used it):
- The 7-test set is exactly the set of green tests whose coverage reaches the procedure's lines. No coverage entry, line
  or procedure anywhere has the 26-test set.
- The 26 are every test of two test codeunits (15 + 11), including 6 that are not green in the baseline.
- All 8 carry `isolatedRecheck`: they were killed through PR-144's withheld-kill recheck, which runs whole test
  codeunits in method isolation.
- Across c2, a covering list holds a non-green test ONLY on rechecked rows: 189 of the 349 rechecked mutants, and 0 of
  the 16,486 others.

So `coveringTests` on a rechecked row is the recheck's run set. That matches its field doc ("the tests this mutant was
actually RUN against"), but the same row keeps `coverageAttribution: exact`. That value promises "these tests executed
THIS procedure", and a consumer (`lethal explain`, the gap list, a run-to-run diff) reads it that way. The verdicts are
not affected: each kill is reproduced by a test that does reach the code.

**Not part of this item:** M19606-M19610 (a loop body of another codeunit). perf10c's baseline has no test reaching that
procedure at all; on main-ccd0f823d, 2 tests that are green in both runs reach all of it. That is a runner behaviour
difference between the two builds, and its BC check is in coord PR-300.
