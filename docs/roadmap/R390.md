**What.** R-371's digest treats a call to external code as unfollowed (whole-source digest) when an
argument can hold a test-app codeunit, record or object reference (orchestrator ruling,
2026-10-01). To decide that, the walk types each argument. A call used as an argument is typed by
its return value only when the receiver is a codeunit. So `DepCU.Process(Rec.GetMock())`, where
`GetMock` is a procedure on a test-app TABLE that returns a test-app codeunit, is not seen: an edit
to that codeunit leaves the test's digest unchanged (the unsafe direction).

**Scope of this item.** By the orchestrator's stop condition for R-371 (2026-10-01), every argument
shape found after the last fix wave (commit 30f2abc5) is recorded HERE as a stated limit, rather than
as a new review round. Add each new shape below with its probe. R389 (a Variant holding a test-app
codeunit) is the separate, larger limit.

**Evidence.** The member typing in `packages/runner/src/testpage-scan.ts` (`argInfo`,
`holdsTestApp`); found by the R-371 build's own review, probe shape above.

**What would close it.** Type a call argument by its return value for every receiver kind the walk
resolves (tables, pages, reports and their extensions too), and fall back when the receiver cannot be
resolved.
