**What.** R-371's digest folds every test-app codeunit that reached code names as a value
(`Codeunit::X` or its literal id), with what it reaches, so an id carried through an Integer, a table
field or a global still covers that codeunit (review round 2, commit bb2ef6a1). An id the test gets
from the PLATFORM is not named anywhere in the test app, for example by looping over `AllObj` or
`AllObjWithCaption` and running each codeunit it finds, or by passing such an id to external code.
An edit to that codeunit leaves the test's digest unchanged (the unsafe direction).

**Scope of this item.** By the orchestrator's stop condition for R-371 (2026-10-01), every shape
found after the last fix wave is recorded HERE as a stated limit, rather than as a new review
round. Add each new shape below with its probe. R389 (a Variant holding a test-app codeunit) is the
separate, larger limit.

**Open shape: a COMPUTED codeunit id (owner ruling 2026-10-01, at R-371 acceptance).** Found by the
round-2 acceptance review (`H:/lethal-coord/reviews/R-371-002/review-r2.md`, finding 3):
`DepCU.RunById(50000 + 101)`, where unchanged external `DepCU` runs `Codeunit.Run(Id)` and test-app
codeunit 50101 is `Mock`. The additive argument is classified as a value, and `idRefsIn` sees only the
literals `50000` and `101`, neither of which names `Mock`, so an edit to `Mock` leaves the digest
unchanged. Every safe fix measured (fall back on any non-literal integer, or fold every test-app
codeunit) put 100% of DC and DO on the whole-source digest, which removes R-371's gain. The owner
accepted it as a stated limit: the shape is rare in real AL, and closing it waits on a cheaper
narrowing (for example, a fallback only for an integer expression containing an operator or a call
on an unfollowed edge, measured first).

**Closed shapes.** The item was filed for `DepCU.Process(Rec.GetMock())`, a test-app codeunit
returned by a test-app table procedure and passed to external code. Commit aafb1394 types a member
call through the return type of a procedure on any test-app object, so that shape now falls back and
`R.MakeMock().Go()` walks `Go`.

**Evidence.** The codeunit-id fold and the member typing in `packages/runner/src/testpage-scan.ts`;
both found by the R-371 reviews.

**What would close it.** Treat a read of `AllObj`, `AllObjWithCaption` or `Object` (and any other
platform source of object ids) in reached code as an unfollowed edge, after measuring how often real
suites do it.

## Done 2026-10-23 (R-175, lethal-bugs): the platform-sourced shape falls back; the computed shape stays a stated limit

**Measured by parse** (`/coord/handoff/R-175/census390.ts`, outputs `census390-*.json`). Code is read through
`maskAlNonCode`, so comments and strings do not count. Records over a platform object-id table declared in test
apps:
- CDO: 1 (`AllObj`);
- DC: 6 (`AllObj` 5, `AllObjWithCaption` 1);
- DO: 1;
- BC.History: 113 in 16 of its 176 test apps (`AllObjWithCaption` 66, `AllObj` 34, `Published Application` 10,
  `Object Metadata` 3).

Read by callee name, most uses are metadata checks (`Format`, `SetRange` on a table id, asserts, setup `Validate`).
They are not runs of a test-app object. But the walk cannot tell which ids are the test app's.

**The fix** (`testpage-scan.ts`, `Scanner.reach`):
- A reached procedure (or trigger) puts the test on the whole-source fallback when it, or its object, holds a
  record over `AllObj`, `AllObjWithCaption`, `Object`, `Object Metadata` or `Application Object Metadata`. That
  covers:
  - its variables and parameters;
  - its object's globals;
  - its object's implicit records: `Rec` of a page's `SourceTable` or a codeunit's `TableNo`, and a report data
    item;
  - `array[n] of` such a record, and a namespaced type (`System.Reflection.AllObj`).
- The fallback's reason names the procedure and the table.
- `Published Application` is left out: it lists apps, whose ids nothing runs.
- The check is cached per procedure.

**Cost, measured before and after on the final rule, over EVERY test app** (`/coord/handoff/R-175/digest-diff/`,
`summary.txt`: all 176 BC.History test apps, CDO, DC and DO, 53,936 tests):
- 20 digests change, and the fallback count goes from 45,827 to 45,847.
- The 20 are: Quality Management 18 (0 → 18 of 747), CDO 1 (6 → 7 of 1,287), DO 1 (105 → 106 of 1,986). No other
  test's digest moves.
- `cost390/`, an earlier estimate, counted 27. It included System Application's Extension Management (3) and VS Code
  Integration (4), which read only `Published Application`, and the final rule leaves that out.
- The census (`census390.ts`) counts declared variables only. Its pattern does not see an array, a namespaced type
  or an implicit `Rec`. The cost above is measured on the rule itself, so it does not depend on the census.

**Tests** (`test-digest.test.ts`, the R390 describe, 14 cases):
- each of the five tables as a local falls back;
- a global in a reached codeunit, a parameter, an `array[2] of`, and a namespaced type each fall back;
- a reached page over `AllObjWithCaption` (its implicit `Rec`), and a reached `TableNo = AllObj` codeunit, fall back;
- controls, each also checking the digest exists:
  - an ordinary record plus `Published Application` keeps the narrow digest;
  - such a record in UNREACHED code does not move the test.

**Red-checked, each restored** (`/coord/handoff/R-175/red-unit/`):
- without the fallback, the moves-direction tests go red (`C-*`);
- an over-wide check, any record at all, turns the control red (`D-*`);
- without the implicit records, the page and `TableNo` tests go red (`E-*`);
- with the old type pattern, the array and namespaced tests go red (`F-*`).

**Still a stated limit:** an id COMPUTED from data (`50000 + 101`, the owner's 2026-10-01 ruling above, kept by
R684), and an id read from any platform source not in the list above.
