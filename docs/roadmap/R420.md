**Found by the R-403 lane (lethal-preproc), 2026-10-03,** while building arm-aware discovery. The gap was already there before R-403.

**What happens.** `discovery.ts` finds tests with one regular expression, `TEST_METHOD`: `[Test]`, then any number of further `[...]` attributes, then `procedure <name>(`. Only whitespace is allowed between them. A preprocessor line between the attributes breaks the match:

```al
[Test]
#if LETHALX
[HandlerFunctions('ConfirmYes')]
#endif
procedure GuardedTest()
```

`testsInAlSource` returns `[]` for this file, measured. The test is not run and not reported. R79's "every test is attributed" check does not fire either, because the method was never seen as a test.

**Why it matters.** Wrapping a handler list in `#if` is a normal way to support two BC versions in one test app. A killed mutant whose only killer is such a test would score `survived` (or `no-coverage`), and nothing says why.

**Direction to fix.** Allow directive lines (and comments, which the mask already blanks) between the attributes and `procedure`, OR find tests from the parsed tree instead of the regex. The arm filter added by R-403 already knows which branch is active, so the result should be the same test under every build, with only the handler list differing.
