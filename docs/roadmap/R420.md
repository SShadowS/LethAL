**Found by the R-403 lane (lethal-preproc), 2026-10-03,** while building arm-aware discovery. The gap was already there before R-403.

**What happens.** `discovery.ts` finds tests with one regular expression, `TEST_METHOD`: `[Test]`, then any number of further `[...]` attributes, then `procedure <name>(`. Only whitespace is allowed between them. A preprocessor line between the attributes breaks the match:

```al
[Test]
#if LETHALX
[HandlerFunctions('ConfirmYes')]
#endif
procedure GuardedTest()
```

`testsInAlSource` returns `[]` for this file, measured. The test is not run and not reported. R79's "every test is attributed" check does not fire either, because the method was never seen as a test.

**Why it matters.** Wrapping a handler list in `#if` is a normal way to support two BC versions in one test app. A killed mutant whose only killer is such a test would score `survived` (or `no-coverage`), and nothing says why.

**After R-403 it is loud on bcdev, with a misleading message.** R-403's compiled-membership check reads every method with the `Test` attribute from the published app's `SymbolReference.json`. A test the regex misses is therefore reported as `published-only`, and the run is refused with `test-app-differs`. That is better than silent. But the message blames other preprocessor symbols or a missing republish, and neither is the cause. al-runner and the no-evidence path still drop the test silently. Other shapes the regex may miss, NOT yet checked (from the R-403 review):
- a `#pragma` line between `[Test]` and `procedure`;
- `[Test] internal procedure` (matters only if `SymbolReference.json` lists internal methods);
- a combined `[Test, HandlerFunctions(...)]` (only if AL accepts that syntax).

None of the committed fixtures has any of these: the review compared `[Test]` counts with regex matches in every `fixtures/*-tests` and `examples/*` project, and they were equal.

**Direction to fix.** Allow directive lines (and comments, which the mask already blanks) between the attributes and `procedure`, OR find tests from the parsed tree instead of the regex. The arm filter added by R-403 already knows which branch is active, so the result should be the same test under every build, with only the handler list differing.

**Closed by R-420 (2026-10-04, plan `docs/superpowers/plans/2026-10-04-R-420-split-test-attributes.md` r2).**
- **Measured with alc 18.0.41.45789.** Twelve shapes, each under every build. Today's regex missed nine accepted test shapes, and three of them have no `#if` at all: `#pragma`, `#region`, and `internal procedure`. alc rejects `[Test, HandlerFunctions(..)]` (AL0104) and `[Test] local procedure` (AL0245). An `#if` with no `#else` gives `[Test]` to the procedure after `#endif` when no arm is compiled in.
- **Discovery.** A file goes to the parser (tree-sitter) only when its masked `[Test]` token count differs from the regex's match count. Every committed fixture stays on the regex path, identical to master (tree = regex is pinned on all of them).
  - R79's guard now counts consumed tokens on both paths.
  - A test the regex found and the tree did not refuses by name (`TreeDiscoveryMismatchError`).
- **The TestPage scan and the digest** read handler attributes from every arm of an attribute-only `#if`, for test procedures only. Helpers keep their old digests byte for byte. A codeunit holding such a test has its digests change once (CHANGELOG).
- **Fingerprint and bcdev message.** `testDiscovery` gains `tree-v1`. The bcdev published-only message gains the cause "LethAL did not recognise a test declaration".
- **Out of scope:** a procedure header split by `#if` (S10) warns `test-shape-unsupported` and is R424.
- **Gates:** `itest:bcdev` 3/12/4 and `itest:alrunner` PASS on every leg, at the frozen figures.
