id: "R1087"
title: "`lethal doctor` checks dependencies against the package cache, not against what the server has installed"
section: "product-gaps"
status: "open"
order: 1726
---

Found by PR-84 (a pilot's friction log, entry 6).

**What.** `lethal doctor` checks the target app's DIRECT dependencies against `bcdev.packageCachePath` (not
`alRunnerV3.packagesDir`, and not the test app's dependencies). The only thing it asks the server is whether the test app is
installed; it checks no dependency against what the server has. A server that holds an older major of a dependency passes doctor, and the problem first
shows as a failed publish after the compile.

**Why it matters.** The failure comes late, after the compile and the artifact work, and its text names the publish, not the
missing or too-old dependency. The user cannot tell that a server upgrade is the fix.

**Possible fix.** Doctor reads each dependency's installed version on the server by app id (one read per id, never a list of
all extensions, R433) and reports a missing or too-old one before a run, naming the app, the version needed and the version
found.

**To close.** Doctor refuses or warns by name for a missing or too-old dependency on the server, it makes one read per app id,
and a test pins both the report and the one-read-per-id rule.
