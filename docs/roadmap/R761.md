**Why.** [[R760]] measured D1 at 667 s on one-shot and 193 s on serve-entries, with 0 per-mutant differences
(R-653: 462 s against 85 s). The owner ruled serve-entries the default.

**The rule.** A v3 config with NO `"transport"` key resolves to serve-entries, unless any of these holds. Then it
resolves to one-shot, and ONE warning, `al-runner-v3-serve-default-fallback`, names every reason that held:
- `resume`: `--resume` or `--resume-run`. A reused baseline has no serve baseline rows
  (`al-runner-v3-entries-no-baseline-rows`), and the transport is not in the session fingerprint.
- `multi-object-or-wrapped`: a project or test file with the MO or WR shape, measured on one-shot only.
- `unproven-test-name-shape`: a discovered test whose METHOD name fails `/^[A-Za-z_][A-Za-z0-9_]*$/`, or whose
  CODEUNIT name fails `/^[A-Za-z0-9_ .]+$/` (`V3_SERVE_PROVEN_NAME_SHAPES`). Those regexes are exactly the shapes seen
  under serve: D1, S1 and the gift card, inventoried with `discoverTests`. Widening them is [[R763]].
- `no-serve-build`: the pinned build has no serve-entries path (alpha.2, `V3_NO_SERVE_ENTRIES`).

**Explicit transports.**
- An explicit `"serve-entries"` with a "." in a test METHOD name refuses before any test call, as
  `AlRunnerV3ServeDottedTestNameError` (upstream #5798, re-measured NOT fixed on edge dcdf9e821: leg N1E still reads
  `entry "NONE|78850"` for `Dot.Step`).
- An explicit `"one-shot"` is honoured.

**Where the decision is made.** `AlRunnerV3Backend.decideTransport({ resume })`, from the session (`orchestrator.ts`)
right after the discovered tests are handed over and before the first deploy. A default-sourced backend starts
one-shot-safe, and the decision is frozen once made or once any v3 process starts
(`AlRunnerV3TransportFrozenError`). `transportSource` (default or explicit) is threaded from the config. Internal
callers that set `transport` themselves (the gate's `backendCfg`) behave as before. `lethal doctor` prints the rule.
