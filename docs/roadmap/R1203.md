**The reading (lethal-bugs, 2026-11-24), read-only from PR-359's A1 and B1 stores and events:** stop groups look MORE right
here, and BC cannot be asked (TestPage). Evidence: `/coord/handoff/R1203/` (`rows.ts`/`rows.txt`, `cov.py`/`cov.txt`).
- **Not a reach or coverage miss.** Both arms' baseline line coverage is identical: EnableService, DisableService,
  OpenPage and UniversignProvider each hit all four reach lines of the page (`cov.txt`).
  - A mutant's `reachedBy` is the covering tests LethAL actually ran as steps until the kill (`ranRefs`), not every test
    that reaches the site.
- **The walk starts at DisableService in both arms.** It is at kill position 1 in A1, and it is B1's first, passing step.
  The order "OpenPage, then EnableService, then DisableService" in the note above is al-runner's run order INSIDE the
  whole-codeunit prefetch, not LethAL's walk.
- **Why DisableService fails only in A:**
  - The test codeunit holds its TestPage in a codeunit GLOBAL (`ESealServiceSetupPage: TestPage "CDO eSeal Service Setup"`).
  - In A's whole-codeunit run, the earlier EnableService (or OpenPage) fails under the mutant before its `Close()`, and the
    global page stays open. DisableService's `OpenEdit` then fails with "The TestPage is already open." (4 of 5; M4775
    fails on the mutant's own "eSeal feature is not enabled").
  - B's stop groups run the tests apart, so DisableService passes, and the walk goes on to the first test that fails on its
    own assertion ("The row does not exist on the TestPage", "eSeal Service should not be editable when enabled",
    "Service Credential should be empty").
- **This is BC-faithful, not an al-runner defect.** On BC too, test-codeunit globals persist across a codeunit's test
  methods (TestIsolation rolls back data, not globals), so a whole-codeunit BC run would fail DisableService the same way.
  But LethAL's bcdev path runs one method per invocation (R156), where DisableService passes alone and the killer is B's P.
  So B's killers are what LethAL's own BC path would report. A's are a cascade, already flagged by its
  `[v3-codeunit-state-possible]` note.
- **BC cannot be asked:** these are TestPage tests, which LethAL's fenced bcdev session refuses (`testPageRefused`). PR-382
  found BC's dev runner could not host a page part in the same family. No upstream issue, and no new item for reach.
- **What it suggests for PR-256 amendment 1's rule:** a B killer BEFORE A's killer is the same kind when A's killer carries
  `[v3-codeunit-state-possible]` naming an earlier FAILED covering test, and P is that test. Each of the five fits.
  Whether that unblocks the flag is the orchestrator's call; M12932's two checks are still undone.

**PR-452 (lethal-preproc, 2026-11-25): the six moves are allowed under a corrected rule; the item stays open for the
flag-on gates and the DO speed series.** Spec: PR-256 amendments 4-7. Evidence: `/coord/handoff/PR-452/alone/RESULT.md`,
`spec-review-a4-6.md`.
- **"P before F" was ill-defined** (spec-adversary, accepted by the orchestrator).
  - The order in this item's table is al-runner's run order inside the codeunit, NOT LethAL's walk. By B's walk, M4774,
    M4789 and M4796 have P AFTER F.
  - M4775 and M4791 moved because R197's first sort key ("already killed in this procedure") put P first after the
    preceding mutant's kill. That is history order, not the TestPage cascade. M4775's A killer fails on the mutant's own
    OnOpenPage error, not "already open".
  - So the order-based rule could not be applied by a script, and could BLOCK a real history-order move.
- **The rule now (amendment 7):** a killingTest move is allowed only with:
  - an equal verdict;
  - (ii): B's killer P alone, on a fresh daemon, fails twice under the mutant with the same message (the only row; not
    notRun, a timeout or the stop text), and passes under NONE;
  - and one form on A's killer F: (a) F's state note names P as `fail` (the cascade), or (b) F alone under the mutant also
    fails (both real killers).
- **The six:** (ii) holds for all.
  - Form (a): M4774, M4789, M4791 and M4796 (F passes alone).
  - Form (b): M4775 and M12932 (F fails alone).
  - The checks ran on edge-e5176a9fd with PR-190's workspace, supporting the moves measured on main-bf3a3e863.
