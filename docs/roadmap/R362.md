---
id: "R362"
title: "A refused `BeginPublish` inside a lease hook warns `after-lease-acquired-uncertain`, which says there is no proof the server stopped"
section: "correctness-risks"
status: "open"
order: 1049
---

**Found while fixing R249 (2026-09-30); not measured live.** When a lease hook
(`runSession`'s `afterLeaseAcquired`, `runNamedMutants`' `inLease`) publishes through the fence and
`BeginPublish` is refused, `LeaseSession.publish` throws `LeaseUnavailableError`. `runLeaseHook`
(`packages/runner/src/orchestrator.ts`) does not count that as a confirmed terminal failure, so it
latches and emits `after-lease-acquired-uncertain`, whose text says the hook "failed with no proof
that the server stopped".

**Why that is wrong there:** a refused `BeginPublish` is a parsed server answer. Nothing was
published and no marker of ours was set by that call, so the server provably did not start
anything. The latch itself is harmless (R249's latch already won, and the first reason is kept),
but the warning tells the operator the opposite of what happened, beside R249's own accurate
outcome (a release, or `lease-kept-under-marker`).

**Fix shape:** let `runLeaseHook` recognise a refused `BeginPublish` (a typed error, or a flag on
the thrown error) and rethrow it without the uncertain warning. Test: a refused `BeginPublish`
through `inLease` emits no `after-lease-acquired-uncertain`, red-checked.
