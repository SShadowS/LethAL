**Filed by R-297 Task 8 (2026-09-28), by orchestrator ruling during Task 6's review.** Companion to
[[R303]], the member whose `var` section is split by `#if` and now gets no reach latch (minimal
refusal, `3c58bbb`).

**What is visible today.** `generateMutationSet` prints a `reach-latch-refused` warning once per
refused member (file, procedure/trigger name, site count), on the console and in the events NDJSON
(`--progress-out`), the same visibility [[R300]]'s coverage refusal has. Each refused mutant's own
manifest and report row carries `reachGrain: "unplaced"`, which `survivorReachOf`
(`packages/runner/src/report.ts`) reads as `not-decided`, correct, but generic: it looks the same as
any other unplaced-grain mutant, with nothing in the row or the report saying "this one is unplaced
because R303 refused its member's latch."

**Why this is a gap.** Inside a `SessionReport`, a reader who wants to know how many mutants R303's
refusal affects, or which ones, has no field to read: `reachGrain: "unplaced"` also covers other
causes (an `enclosing`-grain mutant that was never given a statement marker for unrelated reasons).
Distinguishing R303's cases from any other unplaced one needs re-deriving the member/file list
`reachLatchRefusals` (`packages/runner/src/orchestrator.ts`) already computes, outside the report.

**Why it is filed rather than fixed here.** The orchestrator's ruling (Task 6 review) accepted
console-plus-events visibility as enough for now and asked for this as a follow-up: a `SessionReport`
field (or a new `reachGrain` value) naming R303's refused members. Adding either ripples the way
CLAUDE.md's "Adding a `SessionReport` field ripples" note describes: `events.ts`, `report-fold.ts`'s
accumulator, `report.ts`'s type/builder/banner, `bun scripts/generate-schemas.ts`,
`tests/schemas.test.ts` (the pinned root-required list and the older-reports expectation), then
`bun test <file> --update-snapshots` for `report-equality`, then every committed sample report
regenerated LIVE, which needs a container, forbidden under this task's offline-only rule.

**What would close it.** Once a container is available: add the field (or grain value), thread the
ripple list above, regenerate every committed sample report live, and confirm `schemas.test.ts`
still validates gift-card's sample.

**Closed 2026-09-28 (R-303 Task 5), ruling.** After [[R303]]'s hoist landed (`9a308e1`) and R313's
unparsed-var refusal landed alongside it (`507442f`), a member is refused only when the token right
before its `preproc_conditional_var_block` is not its header's actual end, or its var section does
not parse cleanly. Neither condition appears anywhere in a measured corpus: dc, sysapp and bcf all
count 0 `reachLatchRefusals`, before and after (Task 0 and Task 4); BaseApp's exploratory scratch
project went from 12 refused members to 0 once the hoist covers its shape (Task 4 Step 4). So the
gap this item names, a refused mutant with nothing in the report saying why, covers zero measured
mutants today. [[R309]]'s `preproc_split_procedure_preamble` is now a third refusal, by its own
predicate (`reachLatchRefusedOwner` stops at the preamble directly), also with zero measured
members in dc, sysapp, bcf or BaseApp's exploratory scratch project, so the ruling's premise, zero
measured mutants, still holds. Adding the `SessionReport` field this item asks for is still real
future work; it is just not urgent, because there is currently nothing for it to name.
