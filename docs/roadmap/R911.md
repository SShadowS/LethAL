Found by coord task R-910, from R-908's reading of R-882's 3 ServiceDeclaration `NotSupportedException` rows. Related: [[R908]], [[R69]].

**What.** The TestPage reader (`testpage-scan.ts`) refuses a test that may open a TestPage (`OpenView`, `OpenEdit`, `OpenNew`, `Trap`). It has no rule for `Page.RunModal` or `Page.Run` anywhere. So a test reaching one is sent, whether the call is in the test app's own code or in a dependency. The earlier description, "the reader misses page opens in dependency code", is too narrow. A `RunModal` in the test app itself is not refused either.

**Measured.**
- On Linux BC, a `RunModal` reached in the fenced session fails at once with `NotSupportedException`. R-882's rows reach it in Base Application and Business Foundation.
- The reader sends all three tests of the probe below. It refuses none.
- Microsoft's published packages carry source (Base Application: 8,096 `.al` files), so a walk across dependencies is possible.

**Not measured.**
- Whether such a test hangs on a Windows server. The wedge evidence (`docs/measurements/2026-09-27-nst-wedge-incidents.md`) is about TestPage. R908's "could hang" is untested.
- What a walk across dependencies would cost. It would parse about 8,000 more files on every bcdev run. The reader does not evaluate conditions, so it would refuse every test that merely reaches such a path. For example, R-882's BankDeposits rows reach `GenJnlManagement.LookupName` from `Bank Deposit Header`'s `OnInsert`, so every test that creates a header would be refused.

**Next.** The owner runs the probe on a throwaway Windows server: `/coord/handoff/R-903/owner-note-windows-runmodal.md`, apps in `/coord/handoff/R-910/probe/`.
- It fails fast and the server stays healthy: there is no hang hazard, and this item closes with no reader change.
- It reaches the time cap or the server stops answering: the reader needs a rule. Measure first how many tests that rule would refuse on BC.History's test apps, DC and DO, with R-906's census as the before.
