**`SessionReport.excludedSites` shipped optional on purpose, and the reason expires.** It merges
`notInstrumented` and `declarativeSites` into one record keyed by reason
(`docs/superpowers/specs/2026-08-26-excluded-sites-and-report-schema-design.md` §1.3). It was added
OPTIONAL because of R157's rule: an added optional field is free, an added REQUIRED field is a new
shape and bumps `REPORT_SCHEMA_VERSION`, and `declarativeSites` and `preprocessorSymbols` were both
added as required while the number stayed 2, which is why an archived v2 report is rejected by the
published v2 schema. Shipping `excludedSites` required would have cost a bump then and a second
bump when the views are removed.

So the plan was one bump, later: **the release that DELETES `notInstrumented` and
`declarativeSites` promotes `excludedSites` to required, and bumps to 3, in one move.** That
obligation lives in a plan file under `docs/superpowers/plans/`, which is a dated record nobody
re-reads, and in no roadmap row. This row is the roadmap's copy of it.

**Why the two halves are coupled and must land together.**

- Deleting the views WITHOUT promoting the field leaves a report whose only refusal record is
  optional, so a consumer validating against the schema cannot rely on it being there.
- Promoting the field WITHOUT deleting the views costs the bump and keeps three copies of one fact
  in the report, which is the duplication A existed to remove.
- Either half alone is a bump; both together are one. A second bump would make `explain` refuse a
  second generation of archived reports for no gain.

**Blast radius, measured 2026-09-01 rather than guessed.** Eight source files still read the two
legacy names (`campaign-anchors-run.ts`, `campaign-anchors.ts`, `cli.ts`, `events.ts`,
`orchestrator.ts`, `report-fold.ts`, `report.ts`, `scripts/bench-record.ts`) and 51 files under
`itest/`, `tests/`, `schemas/` and `docs/campaign/` mention them. The campaign-anchor readers are the
ones to look at first: `campaign-anchors-run.ts` reconciles `notInstrumented.files` against source,
and that reconciliation has to move to `excludedSites` rows with `reason: "not-instrumentable"`
before the view can go. Every committed campaign report under `docs/campaign/` is a v2 document and
stays one; the bump does not relabel them (R157's own ruling).

**What is NOT owed here.** No date, no trigger. This is the same shape as R145: a decision recorded so
it is made deliberately, not a task queued. It becomes active the first time anyone proposes touching
either view or the schema version for any other reason — at which point the two halves ride the same
release.

**Done looks like:** `REPORT_SCHEMA_VERSION` 3, `excludedSites` in the pinned root `required` set in
`schemas.test.ts`, `notInstrumented` and `declarativeSites` absent from `SessionReport`, all four live
gates green with no baseline re-recording (A's landing proof, which still holds: a view is
verdict-neutral), and `itest:tables`'s `notInstrumented` pin (from A's Task 4) rewritten to assert the
same file through `excludedSites`.
