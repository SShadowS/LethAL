**Filed by the R-319 plan's review (2026-09-28)**, orchestrator ruling on the plan's open question 1,
`docs/superpowers/plans/2026-09-28-R-319-server-symbols.md`. Sibling of [[R319]].

**What is missing.** `itest:alrunner` runs four legs (one-shot twice, `--server`, and `--server` with
the resource selector) and requires every leg's verdicts to equal the one-shot leg's, per mutant.
But `fixtures/sandbox-app` defines no preprocessor symbol, so every leg compiles the same no-symbol
build whatever the transport does with symbols. [[R319]] (the `--server` daemon was started without
the session's symbols) was invisible to this gate before its fix and stays invisible after it: the
gate passed at HEAD with the defect present. The proof that closed [[R319]] is a scratch probe on
hand-written repros, not a committed gate.

**What would close it.** A symbol-defining fixture pair whose builds give different verdicts (for
example a `CLEAN`-style arm that only one symbol set compiles, with tests that assert each build's
own values), run as an extra `itest:alrunner` leg under at least two symbol sets, with every
transport required to equal the one-shot leg per mutant and to hold that build's own pre-committed
verdicts. It needs:

- a new fixture pair under `fixtures/`, wired into `bun run compile:fixtures` under every symbol set
  it is run with;
- a new frozen per-mutant baseline per symbol set, recorded and committed by the usual rule;
- the gate's notes in `CLAUDE.md` updated with the new figures.

**Closed 2026-09-29 (R-321).** Built per `docs/superpowers/plans/2026-09-29-R-321-symbol-fixture.md`
(r3, the revision the orchestrator approved). `fixtures/sandbox-symbols` + `-tests` (ids 79600-79699): an `#if LETHALA` / `#elif LETHALB` /
`#else` split of `Rate`'s `exit`, three assignments outside the arms each read by one arm, and one
test asserting each build's own value. `compile:fixtures` compiles all three builds of both apps;
`--require-symbol-sets` refuses a skip; every arm of both apps was red-checked broken (fails in its
own build only), and dropping `/define` hid a broken A arm and, separately, a broken B arm.

`itest:alrunner` runs `[LETHALA]` and `[LETHALB]` through one-shot, `--server` and server+resource.
All 39 build-mutant verdicts and killing tests (both sets plus the `#else` build) were
pre-committed in `docs/superpowers/specs/2026-09-29-r321-symbol-fixture-precommitment.md`,
committed alone before any run, and every measured one matched, al-runner v2.11.0: the 26 set rows
by the gate on every transport, and the 13 `#else` rows by the red-checks, which printed that build
on six legs and compared every row with `EXPECTED_NO_DEFINE`. Frozen: each set
5 / 8 / 0 over 13, each pair of builds different on 8 of 13. A missing symbol baseline is refused;
recording is an explicit, one-time mode that is never a pass.

Red-checked live, both ways defines can be lost: removing the one-shot `--define` forwarding in
`buildAlRunnerArgv` failed `R321 one-shot [LETHALA]` / `[LETHALB]: per-mutant verdicts differ from the
pre-committed table` before any baseline existed, writing none; removing R319's daemon `--define`
failed the `--server` and resource equality checks in both sets. Six of the 13 mutants sit in `#if`
arms, and any one build compiles out four of them ([[R214]]); R214's fix will need a new pre-commitment and a re-freeze here.

**Notes carried from the Task 3 review, recorded here since the pre-commitment is never edited.**
Red-check (b)'s failure text depends on which symbol list the report records; the count it names is
the same either way. Red-check (a) needed both baselines recorded first, which the task order
already did. The pre-commitment's R214 note lists what disappears from `[LETHALA]` and `[LETHALB]`
when R214 is fixed, but it does not say what disappears from the no-define (`#else`) table: that
table would lose M0008 and M0009 (the `[LETHALA]` arm) and M0010 and M0011 (the `[LETHALB]` arm),
keeping only its own arm (M0012, M0013) plus the six assignment mutants and M0001. The re-freeze
R214 needs should cover this table too.

**What the new legs do not prove.** They do not exercise the R147 platform-app pin; that pin still
runs only on the two `sandbox-app` one-shot legs (R235). `sandbox-app` itself is untouched and stays
3 / 12 / 4 on all four of its legs. The receipt keeps its original four sublegs (`one-shot`,
`server`, `resource`, `platform-pin`) unchanged; the symbol legs are not a fifth. And nothing here
red-checks resource mode on its own: resource mode has no `--define` forwarding of its own, it runs
the daemon (`serverMode: true`) with a resource-file selector on top of it, so the one live
red-check that touches the daemon's argv (Task 8) fails `--server` and `resource` together, for both
sets. A define-loss unique to resource mode was never tested, because there is no such code path to
lose it in.
