Found by coord task R-984 (2026-11-14), DO end to end on serve ([[R942]] amendment 8). Related: [[R761]], [[R948]], [[R912]], [[R886]],
[[R1004]].

**What happened.** Window t1 (`/coord/handoff/R-984/t1.*`, store `dos3.sqlite`) ran DO on the serve default and stopped on its
`--time-budget` (R912: "Run with --resume to continue"), 1,148 covered mutants scored, 15,563 left. Window t2 (`run.sh 2`, the same
command with `--resume`) stopped at once (rc 1):
- `al-runner-v3-serve-default-fallback: this session runs one-shot, not the serve-entries default, because resume: a --resume /
  --resume-run session (a reused baseline has no rows for the serve warm-up ...)` (R761), then
- `--resume found no unfinished run to resume in this database for this project ..., backend al-runner-v3, and configuration.`

Run 1 is unfinished (`finished_at` NULL) and its `config_fingerprint` and `resume_inputs` are the session's. What differs is
`runner_build`: run 1's ends `... baseline-daemon environment-saas license-...` (R948: "a snapshot or history from a daemon baseline is
not lent to a one-shot session, nor the other way"), and a session forced to one-shot has no ` baseline-daemon` tag. So:
- a serve run cannot resume on serve (R761 forces one-shot), and
- a one-shot session cannot resume a serve run (R948's tag).
Every `--time-budget` window on the serve default is therefore a dead end, and R912's "continue with --resume" is false there.

**Why it matters.** The serve default is the only way DO's covered mutants run at a usable rate (t1: about 340 an hour on serve, about
60 an hour one-shot), and DO's rest (15,563 covered mutants, roughly 45 hours on serve) does not fit one window. The same holds for any
project too large for one window.

**Fix shapes (not decided here; R761/R948 are code's).**
- A resumed session on the serve default re-runs its baseline on a daemon (about 43 minutes for DO), so the warm-up has rows and the
  tag matches; carried verdicts stay keyed as today. Or
- R948's tag stops deciding a resume (only history and snapshot lending), with a reason why a verdict measured with a daemon baseline
  stays valid when the rest runs one-shot (it does not change what a mutant run measures, only where the baseline rows came from).
- Either way, R912's message must not tell a serve run to `--resume` while it cannot.

R-984 waits for this: DO's remaining windows cannot run on serve.

**Fixed (coord R-999, the first shape; split agreed with lethal-code, R761/R786's owner).** A resume is no transport fallback reason
any more (`pickTransport`). A session on serve-entries says so through the new optional `ExecutionBackend.resumeRunsBaseline`
(al-runner-v3: `entries`), and the orchestrator then reuses no baseline snapshot on a resume (`allowReuse`), as R857's `--isolate-tests`
and R896's isolation "auto" already did: the baseline runs again, the warm-up has its rows, and the session's ` baseline-daemon` tag
matches the run's. Carried verdicts stay keyed as before. It also covers an explicit `"transport": "serve-entries"`, whose resume used
to reuse a snapshot with no warm-up rows. R912's "continue with --resume" is true again, so its text is unchanged. Cost: the baseline
once per resumed window (about 43 min for DO).

Proof (pre-committed, `docs/campaign/2026-11-14-r1008-serve-resume/`): on Service Declaration, a serve run stopped by its budget at 98 of
222 mutants and then resumed scored all 222, per mutant IDENTICAL to one uninterrupted run (`report-diff`). Tests: `r761-serve-default`
(a resume keeps serve, `resumeRunsBaseline` true on serve and false on one-shot) and `r619-one-lend` (a serve resume looks at no
snapshot; without the flag the same resume reuses it); each part red when reverted alone.

**Still open (named, not wrong data).** If a resumed serve session's warm-up is refused, R786's one-shot re-run is itself a resume
without the ` baseline-daemon` tag and stops with "found no unfinished run". `--workers > 1` with `--resume` stays refused (R766).
R948's daemon cross-check runs on a resumed session exactly as on a fresh one (the backend's baseline path does not read the resume).
