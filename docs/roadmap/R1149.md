Found by coord PR-233 (lethal-bugs, 2026-11-19). Pre-commitment: `docs/superpowers/specs/2026-11-19-pr233-o1-partner-login-precommitment.md`.

Since al-runner f9116dc96 (#8149), a partner app's `OnAfterLogin` that fills "Server Setting Impl." makes every row insert in the
session refused ("... what BC leaves there is not pinned"). On O1's corpus set that is exactly `InsertRow`, `InsertDepRow`,
`CommitLocalRow` and `CommitDepRow` in all 8 W and C entries. BC measured (bc4, #8239 issuecomment-7014017475): the login runs
once before the first test and leaves what the test computes; inserts work. So the refusal is a coverage loss, not a BC
behaviour. PR-233 names it on pins that carry `o1.partnerLoginRefusal`.

**When P2 lands:** drop `partnerLoginRefusal` from the pin of the first build carrying it (pre-committed), and check that O1's
corpus set passes in full again. Remove the held path for the exact text if no gated build still needs it.
