Found by PR-84 (a pilot's friction log, entries 2 and 7).

**What.** The server username and password live only in the config JSON. There is no env-file, `--from-env`, `passwordEnv`
or include. A team with a secrets file, or a CI job with secret variables, has to write the password into the JSON.

**Why it matters.** A password typed into a file ends up in the working tree, in backups and, sooner or later, in a commit.
CI systems hand secrets over as environment variables, so today they need a script that edits the config first.

**Possible fix.** Config fields that name environment variables, for example `usernameEnv` and `passwordEnv`. LethAL reads
them at run time and never writes the value back (not to the config, the store or a report). A missing variable is refused
by name. `lethal doctor` reports which source each credential came from, without printing it.

**To close.** The fields exist for every backend that logs in to a server, a missing variable is refused by name, a test pins
that the value never reaches the config, store or report, and the README documents it.

**Fixed (PR-85).** The `bcdev` section takes `credentialsEnv: {username, password}`, the NAMES of two environment variables
(one pair, rather than `usernameEnv`/`passwordEnv`). `validateBcDevConfig(raw, environment = process.env)` reads them and sets
`username`, `password`, `env.BC_DEV_USER` and `env.BC_DEV_PASSWORD`, so every reader is unchanged. Refused by name, with no
value: `credentialsEnv` beside any of those four fields; a missing, empty or invalid variable name (a bad name is not echoed,
because it may be the password); a variable that is unset or empty; and an `envTool` section beside `credentialsEnv`.
`lethal init --credentials-env <USER_VAR>,<PASS_VAR>` writes it. `lethal doctor` shows a `credentials-env` check with the
names and whether each is set. Tests, including a canary-secret scan of doctor's text and JSON and the refusal envelopes, are in
`packages/runner/tests/pr85-doctor-deps-and-env-credentials.test.ts`. Not covered: the al-runner-v3 backend has no server
login, so it has no field. The README, the agent guide and the CI templates document it.
