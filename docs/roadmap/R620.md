**Filed 2026-10-22 by lethal-preproc during R618** (orchestrator ruling 1b, from the R618 plan
review, open question 2).

**What.** [[R389]] records a closed-world session's test-app identity, and every baseline snapshot
it takes, as `<hash>|pending` (`PENDING_SUFFIX`). Only `ResultsStore.confirmClosedWorld`, run after
execution when the guard gives the same closed answer again, strips the suffix. A session that
dies before that point (a crash, a killed process, a lost container, an exception out of the batch
loop) never reaches it, so its run row keeps `|pending`. Then:

- `--resume` finds the run (`findResumableRun` does not filter on the test app) and refuses it in
  `assertSameTestApp`: "`--resume: run <id> was measured against test app <hash>|pending` ...
  none of its verdicts is carried (R247, R495)";
- `--resume-run <id>` refuses it the same way;
- none of its snapshots is reusable (`findBaselineSnapshot` excludes `%|pending`).

A QUARANTINED run is not affected: the batch loop breaks, the confirm block still runs, and only
finishing is skipped, so the run stays resumable (pinned offline in `tests/orchestrator.test.ts`,
"R618 Q1"). [[R618]]'s `itest:lend` pins the crashed shape as its RN1 refusal.

**Who trips on it.** Anyone running LethAL on a closed-world test app (every project whose test app
has no dependents, which includes `fixtures/sandbox-app`) whose run is interrupted by anything
other than a quarantine. That is the R47 case `--resume` was built for: a long run cut short. On
such a project it now always restarts from zero, and the refusal text blames the test app, not the
interruption.

**Why it is this way.** Deliberate, as far as it goes: a closed answer measured only BEFORE
execution is not proof that the test app stayed closed during it (a dependent published mid-run
changes what ran), so a run that never re-asked cannot be trusted (R389). The gap is that nothing
offers a way back.

**To close (options, not decided).** (a) On `--resume`, re-ask the guard; if the answer is still
closed AND the run's open-world digests still match, confirm the run then (`confirmClosedWorld`)
and resume it, saying so. (b) Keep refusing, but say why in the refusal (the run was interrupted
before its identity was confirmed) and that a fresh run is the only path. (c) Confirm per batch
rather than per run, so an interruption loses only the open batch. Any change needs its own
pre-commitment and a live leg.

**Closed 2026-10-22 as a duplicate of [[R601]]** (orchestrator ruling Q2 on the R-601 plan). R601
is option (a) with one difference: it confirms the RESUMED run, by that run's own re-ask after
execution, and never rewrites the crashed run, which stays `|pending` (and is revoked with the
resumed run if that re-ask answers differently). R601 accepts a pending run only when its recorded
identity string equals this session's closed identity plus `|pending`, on the same server. Equal
identity strings mean the same served package bytes, and so the same source, so the open-world
digests also match; no separate digest check is needed. Option (b)'s wording is in R601's refusals.
[[R618]]'s RN1 leg is now RN1d plus RP (`docs/gates/lend.md`).
