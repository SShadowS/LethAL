**Found 2026-10-05 while measuring R458** (exact site diff of the R-458 r1 prototype, its `wide`
variant: the by-name match applied to EVERY unresolved write; offline, coord handoff `R-458`).

In a `query` object, a procedure's named return value does not resolve through `resolveVarRef`,
so R196's hang check (`classifyHangCapable` in `loop-hazard.ts`) declines the write as a guess
(spec 3.1). System Application's `OutboxEmails.Query.al` and `SentEmails.Query.al` read rows with

```al
KeepReading := Read();
while KeepReading do begin
    ...
    KeepReading := Read();
end;
```

where `KeepReading` is the procedure's named return value. Removing the write in the body (or
flipping a `KeepReading := true` before a loop that reads it) never ends the loop: a hang on the
user's server. 14 such mutants in System Application; none in BaseApp, CDO or any fixture.

Not an implicit record, so R458's gate does not open there.

**To close.** Index query-object procedures (their parameters, locals and named return value) in
the symbol table, so the existing declaration comparison applies; red test per direction (the
`KeepReading` loop refused; a return value the loop does not read still claimed); re-measure on
System Application; bump `IDENTITY_SCHEME`.

**Closed 2026-10-05 as a ruling (R-465, orchestrator).** Measured and diagnosed, but not built:
- **Cause.** A `query` object gets no symbol scope, so no name inside its procedures resolves (their parameters, locals and
  named return value alike), and `classifyHangCapable` declines.
- **Latent.** `query` is not in `CARRIER_KINDS`, so a query file is skipped whole (it cannot carry the selector variable):
  0 query mutants are ever deployed, and none of the 14 sites can hang a server. "A hang on the user's server" above is
  wrong today. The only visible effect of a fix would be 14 report rows moving from skipped to `hang-refused`.
- **Measured** with exact spec dumps (R-465 survey): fixtures, examples and CDO (59,500 specs) show 0 change. On
  BC.History (519 projects, 2,294,008 specs), the NARROW fix moves exactly the 14 System Application query sites from
  skipped to hang-refused and changes 0 carrier specs. The broad fix (giving queries an object scope) moves 1 more
  non-carrier site.
- **The fix, recorded for whoever makes `query` a carrier.** The narrow version: `resolveVarRef` falls back to the
  enclosing query's member scope (ancestors only, gated on `query_declaration`), and `buildSymbolTable` indexes query
  members while `enclosingObjectScopeKey` stays null for queries. A carrier will need the broad version, plus types and
  the coverage join, as R254 did for reportextension.
- **Prerequisite for that day** (sol's review of the R-465 plan): a file refused whole as `object-mix` reserves identity
  entries keyed by object NAME, not kind. So changing what resolves in a query can shift a same-named codeunit's twin
  ordinals with no carrier spec changing. Bump `IDENTITY_SCHEME` then, or prove reservation numbering stable.
- Plans and reviews: coord `R-465-plan` (plan r2, sol r1 and r2).
