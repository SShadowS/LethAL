**What happened.** During the R231 re-freeze, `bun scripts/redact-campaign-report.ts --check` was
run on the two re-frozen sample reports. It exited 1 on both of them: 62 fields in
`examples/credit-limit/demo.report.json` and 87 in `docs/campaign/2026-08-16-gift-card/rehearsal.report.json`.
It also exits 1 on the gift-card rehearsal as committed BEFORE the re-freeze. Both reports are
listed in `scripts/redact-first-party-reports.json`, and both are meant to be unredacted. The
allowlist is read only by `scripts/redact-campaign-report.test.ts`, which passes. The CLI never
reads it.

**Why it matters.** CLAUDE.md tells a committer to run `--check` before committing a campaign
report. On a first-party report, the answer is always "fail", so the right move is to ignore it.
A check people learn to ignore protects nothing. It also misled a reviewer: the R231 brief and its
pre-commitment both said "`--check` passes" on the credit-limit demo. That was only true while the
committed demo happened to be redacted (see the correction in bef6693d's message).

**Fix shape.** `--check` should consult `redact-first-party-reports.json` and report an allowlisted
path as `ok (first-party: <projectDir>)`, applying the same mechanical first-party proof the test
uses. Without `--check`, the WRITE mode should refuse an allowlisted path rather than redact our
own source. Pin it with one test per direction.

Evidence: `.superpowers/r231-live.md` in the r231 worktree (scratch).
