**Filed 2026-10-22 by coord task R-572** (lethal-code), from re-price r2. A defect in [[R593]]'s guard.

**What happened.** During R-572's re-price r2, `corpus-snapshot.ts diff` for dc, do and cdo printed
`1 other slot(s) held, 4 other heavy job(s) ... -> REFUSED`
(`/coord/handoff/R-572/reprice-r2/dc-diff-official.log`). The 4 "jobs" were ONE parallel itest:alrunner:
- its root, `bun run itest:alrunner -- --parallel=3`;
- three `al-runner` processes that its workers had spawned, each in its own process group.

The guard skips `--worker` processes, but it counts the al-runner children they spawn, because it de-duplicates by
process group. The runbook counts a parallel itest as ONE heavy job.

**The outcome happened to be right.** One slot was held by R-572's own bch dump, and the itest was a second heavy
job, so a diff that dumps would have been a third. So the miscount did not let a third job through. It overstates
the load, and it can refuse a run that should start.

**To close.**
1. Count an `al-runner` process under the itest:alrunner root that started it (walk up to that root, and count the
   root once), not by process group.
2. Unit tests in each direction, red-checked: a parallel itest with three al-runner children counts as 1; two
   separate itest roots count as 2; a lone al-runner with no itest ancestor counts as 1.
