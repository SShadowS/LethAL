Found by lethal-code, 2026-11-11 (coord R-923); the same failure hit lethal-preproc's R-919 diff at 16:16 the same day. Tool friction,
not a verdict. Related: [[R593]], [[R724]], [[R905]].

**What happened.** A script ran `corpus-snapshot.ts snapshot bch --master`, then `diff bch --branch <worktree>`, both waiting for a
BaseApp-class slot. While it waited, other lanes fetched, and `origin/master` moved from 97d11119 to f81b525a. The snapshot dumped
f81b525a (origin/master at that moment); the diff then looked for the entry of merge-base(<worktree>, origin/master) = 97d11119 and
exited 2: `no master entry for 97d11119... Run snapshot bch --master first`. About an hour of dumping was unusable for that diff.
Recovered by merging exactly f81b525a into the branch, so the merge base matched the dump.

**Invented repro.** Start `snapshot <set> --master`; before `diff` runs, move origin/master by one commit (a fetch in another
worktree); `diff <set> --branch <wt>` refuses with "no master entry".

**Wanted.** `snapshot` prints (and records in its DONE marker) the sha it dumped, and `diff` takes `--master <sha>` to use exactly that
entry, refusing only if `<sha>` is not an ancestor of the branch (then the diff would compare across unrelated changes). Or `diff`
falls back to the newest cached master entry that is an ancestor of the branch and says which one it used.

**Fixed (coord R-929).** Both ends pin, since pinning the diff alone would not have saved R-923's run (its snapshot had dumped the
newer master, which was not an ancestor of the branch):
- `snapshot <set> --master --sha <sha>` dumps exactly that commit, refused by name unless it is on origin/master;
- `diff <set> --branch <wt> --master-sha <sha>` uses exactly that entry, refused by name unless it is an ancestor of the branch. An
  ancestor older than the merge base is used, and the line it prints says master's changes since then count as branch changes.
- A job pins once at its start: `S=$(git -C <wt> merge-base HEAD origin/master)`, then both commands with `$S` (the tool's header
  says so). Unpinned, both behave as before. The flags travel through the heavy-slot re-exec unchanged.
Tests (`corpus-snapshot.test.ts`, R935, real git repos with a moved `origin/master`), each red both ways: pinned, snapshot and diff
agree after master moves while unpinned they part; the refusals; the older-ancestor note; the CLI refusing the other command's flag.
