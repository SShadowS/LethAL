**Found 2026-10-05 by R-478**, while probing R478's second shape. The sibling of [[R336]], which is
the same failure for `extends <number>`.

**What.** `tableextension 50480 "X" extends R478.Ns."R478 NT"` compiles with `alc`, but the native
parser reports `hasError` for it, for every qualified spelling tried (`A.B."T"`, `A.B.T`,
`"A"."B"."T"`). An unqualified base (`"R478 NT"`, `NTPlain`) parses cleanly. Measured with
`/coord/handoff/R-478/tools/ext-parse.ts`.

**What protects the build today.** The symbol table still indexes the extension, with its base
reduced to the last name segment (`R478 NT`), and the object is also listed in `unparsedObjects`.
`mayHaveMember` and R331's rule-3 fallback read both, so a member the extension declares still
refuses a claim that would be captured by it. The probe (`/coord/handoff/R-478/tools/probe.ts`,
shape 2) emits no `validate-to-assign` mutant there; without the extension the same site emits
`Rec.Amount := 1`, and `alc` compiles it.

**The cost.** Sites inside such an extension are not mutated, as in R336.

**How often.** 0 namespace-qualified tableextension bases in BC.History (432 files with a
tableextension), CDO (31), DC (13) and DO (32), by a text census.

**Closing.** When the grammar parses it, pin the extension as a structural `tableextension` whose
base is the last segment, and keep the text fallback. Not reported upstream yet.

Related: R336, R478.
