**Filed 2026-10-21 by coord task R-587.** Plan: `docs/superpowers/plans/2026-10-21-r587-alrunner-leg-split.md`
(its r2 header wins over the r1 body). Measurement: `/coord/handoff/R-587/measure.md` (one sequential run,
3068 s; the wrapped group alone is 1175 s of it).

**What.** `itest:alrunner` ran 23 legs in one process, about 51 minutes, and its receipt named 17 sublegs that
did not match the legs (no symbol legs; A and B as one name; `platform-pin` listed as a leg). So a slow gate
could not be split, and a partial run could not be told from a full one by the receipt.

**The build (branch `lethal/r587`, follow-up `lethal/r587-fix`):**
- `packages/runner/itest/alrunner-legs.ts` holds the one list of 23 leg ids in 7 fixture groups. A leg counts
  (`LegRunner`) only after its function returns a report with a mutant and none of its group's collected
  checks failed during it.
- `-- --legs <group,...>` runs a subset and ends `al-runner itest: PARTIAL, <k> of 23 legs ran green (...)`
  with exit 4. Only all 23 print `al-runner itest: PASS` and exit 0. Exit codes: 0 full PASS, 1 failure,
  2 refused, 3 record, 4 partial.
- `-- --parallel[=N]` (N 1 to 3) runs a serial warm-up, then one `--worker` process per group, longest
  first. It counts as one heavy job (its root process).
- `-- --reports <empty dir>` writes each leg's report, each group's done-file and, after a full PASS only,
  `result.json`, all with the run's nonce. `scripts/alrunner-legs-diff.ts` compares two such runs leg by leg.
- The receipt names exactly the 23 ids; `scripts/agentflow` checks the set, not a count.

**To close:** the pre-committed equality gate (`docs/superpowers/specs/` R-587 pre-commitment): the sequential
run S and the parallel run P both PASS, and `alrunner-legs-diff S P` is IDENTICAL on all 23 legs; then the
merge. Not proven live by S or P: a worker's signal handling and its parent-death poll (review
`/coord/handoff/R-587/review-opus-build.md`).
