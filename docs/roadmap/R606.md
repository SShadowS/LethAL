**Filed 2026-10-21 by coord task R-606** (lethal-preproc; owner request: "pull latest master, do the change locally
and test on that. Before we make any PR at all").

**What.** On upstream al-runner main (at the time `5ac6853`), `warm_key` in the serve path
(`crates/alrunner-cli`, `run.rs`) includes `m.resources` since upstream #5604. A changed resource file therefore
forces a full compile, although resources reach the VM only as run-time data (`app.resources`, read in the VM
context). LethAL's resource selector (`selectorMode: "resource"`) writes the active mutant to such a resource file,
so every mutant pays a compile it should not need.

**The plan (R-606, local only).**
- Clone upstream main fresh; confirm the change is small and local to serve's reuse path before editing (stop
  otherwise).
- Change it test-first, in upstream's conventions: resources out of the warm key; the current resource content
  handed to the VM per request. Upstream's regression test `a_changed_resource_file_is_seen_by_the_next_request`
  must still prove the new content is seen, now from the cache. Add a test that a SOURCE change still recompiles.
- Run upstream's full suite on the patched tree and on unpatched main.
- Time the invented probe (1,500 filler codeunits, one resource-reading test): unchanged, source change and
  resource change, on both builds.
- Install the result at `/work/tools/al-runner-v3/local-<sha>-resfix/`, never touching `current`.
- Evidence goes in `/coord/handoff/R-606/`.

**Not done here:** no push, PR or comment upstream. Whether to open a PR, and whether bugs runs the CDO slice with
the resource selector on this build, is the owner's and the orchestrator's call afterwards.
