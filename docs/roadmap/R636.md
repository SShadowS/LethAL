(`/coord/reviews/R-631-build/review-r3.md`, findings N4 and N5). Both fail safe.

**N4 (LOW, measured).** [[R631]]'s "reaches a .al" scan follows excused and cache links, with a shared visited set
and a depth cap of 32 that refuses at the cut-off. The cap counts depth THROUGH links, not real folder depth. So a
pnpm-style chain of about 20 linked packages that holds no `.al` at all refuses the run falsely. It is the safe
direction: a refusal, never a wrong verdict.

**N5 (LOW).** The cache-file refusal message names the project folder as "the package cache", which reads wrongly.

**To close.**
1. Cap the number of folders scanned rather than the link depth, still refusing at the cap, so a long link chain
   with no `.al` passes.
2. Add a test with a 20-link chain of no-`.al` packages that runs, and a red-checked cap test.
3. Fix N5's wording.
