**Filed 2026-10-22 by lethal-code** from R-657's build review. Related: [[R657]], [[R553]], [[R641]].

**What.** R657 measured that al-runner v3's failure `message` has no `<Type>: ` prefix (alpha.2 and edge
57f1e4f98), so v3 keeps bcdev's assertion-screen rule. The unit tests that pin this use fixed message strings.
If a future v3 build starts writing `{Type}: {Message}` as v2 did, those tests stay green. The screen would then
flag almost every v3 kill as `vacuous`, the skew R553 measured for v2 (51 of 51), and only the report figures would
show it.

**To close.** Make the live v3 gate notice it. One way: `itest:alrunner-v3` asserts that 0 kills in its legs'
reports match `AL_RUNNER_EXCEPTION_PREFIX`, so an edge or update run fails by name the day a prefix appears.
Report figures only: verdicts are not touched.

**Closed 2026-10-23 (0ea0a076):** leg C's contract fact `message-has-no-type-prefix` (pre-commitment r12) reads a
plain `Error()` and an `Assert.AreEqual` failure and is `gate-fail` when either matches `AL_RUNNER_EXCEPTION_PREFIX`;
in a session a prefix refuses by name, because it would also hide a not-trusted refusal from the K1(a) guard (a false
kill). Leg C has 27 facts (9 defect, 17 contract, 1 warn). Not yet run live.
