**Found 2026-10-05 while building [[R446]]** (plan
`docs/superpowers/plans/2026-10-05-R-446-body-guard-loop-hang.md`, sol reviews r1 and r2).

**What.** R446 refuses a value-operator write that a body-exit guard reads, but ONLY in a loop whose
condition reads no name and calls nothing (`while true`, `until false`). It is a scoped heuristic.
These shapes can still get a mutant that never ends, and each is pinned as NOT refused today by a
witness test in `packages/builtin-tier1/tests/loop-exit-refusal.test.ts`, describe block
"R446 exclusions: hang-capable writes still claimed (R480)":

1. **A body-exit flag under a condition that reads a name.** `while Go do begin Done := true; if
   Done then exit; end;` with `Go` never changed. Deleting `Done := true` hangs. Witness: "a
   body-exit flag under a condition that reads a name".
2. **An indirect guard.** `while true do begin I += 1; Done := I >= 3; if Done then exit; end;`.
   The guard reads `Done`, so `Done := ...` is refused, but removing `I += 1` hangs. Witness: "an
   indirect guard: the write feeds the guard's variable".
3. **A condition that calls something.** `while not Cust.IsEmpty() do ...` keeps R196's
   condition rule only; body guards are not added. Witness: "a condition that calls something".
4. **An outer `for`/`foreach`.** Not a hang-refusal loop at all (`LOOP_KINDS`); whether moving a
   `for` bound or replacing a `foreach` list inside the loop can stop it ending is unmeasured on BC.
   Witness: "an outer `for` whose bound the body moves, and an outer `foreach`".
5. **`asserterror` as the only exit.** `while true do begin Done := true; asserterror if not Done
   then Error('x'); end;`. The original ends when the assertion fails (no error); with the write
   deleted the error is caught every time and the loop never ends. An `Error` inside `asserterror`
   is deliberately not an exit. Witness: "`asserterror` as the only exit".
6. **`CurrReport.Skip()`.** Its docs say only that report processing "continues with the next
   record", not that it interrupts an AL loop, so it is not an exit. Witness:
   "`CurrReport.Skip()`, whose docs do not say it ends an AL loop".

Also not counted as exits, by ruling rather than omission: an `exit` inside a called procedure
(it ends that procedure), `Commit()`, and `Codeunit.Run` returning false.

**Measure first.** For each shape, count its sites on the fixtures, CDO and BC.History with the
identity-keyed dumps R446 used, read a sample by hand for real hangs, and then either extend the
refusal (with a scheme bump if keys move) or close the shape with a ruling. Shape 6 needs an
`al-probe` measurement of whether `Skip` unwinds an AL `while` loop before it can be counted.
