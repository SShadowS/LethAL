**What.** R193's identity ordinal separates "twin" mutants: two mutants whose identity tuple
(object, member, operator, subtree hash) is the same. The ordinal is assigned over one batch's
manifest (`identityOrdinalsOf`, called from `writeInstrumentedProject` in
`packages/schemata/src/project.ts`), and each batch has its own manifest. So when
`--max-guards-per-batch` splits a project, twins that land in different batches BOTH get ordinal 0
and share one identity key.

**Why it matters.**
- `filterHistory` (`packages/runner/src/selection.ts`, `--skip-known-survivors`) matches by that key.
  If only one twin survived, both are skipped as known survivors: a mutant is never run and is
  reported on its twin's verdict.
- `buildResumeIndex` refuses a duplicate key within ONE prior run, but a change of batching between
  runs can turn a formerly unique ordinal into another mutant's key, and that key is unique in the
  prior run, so it carries.

**Evidence.** Found by the gpt-6-sol review of the R-307 plan, round 2
(`H:/lethal-coord/reviews/R-307-plan/review-r2.md`, final paragraph), and checked by the orchestrator
against `project.ts` (the per-manifest `identityOrdinalsOf` call).

**What would close it.** Number identity ordinals over the whole RUN, not per batch, so batching
never changes a key. That changes keys wherever batching splits twins, so it needs an
IDENTITY_SCHEME bump. Pin it with a test in which twins split across two batches get distinct keys
and `--skip-known-survivors` runs the twin that did not survive. R-307 (per-file refusal) takes this
as its first task, because its reserved-ordinal rule is only sound once ordinals are run-wide.

**Closed (eab7e089, R-307 T1; status recorded 2026-10-05 under R-374).** The fix had landed, but
this item was never marked. `identityOrdinalsOf` (`runIdentityOrdinals`) numbers ordinals ONCE over
the whole run, and every batch's writer receives that one map (`prepareArtifactDir` passes
`args.identityOrdinals`); IDENTITY_SCHEME 5 retired the per-batch keys, and later schemes kept the
rule. The pin is `packages/runner/tests/run-wide-ordinals.test.ts`:
- (a) the twins split across two batches take ordinals 0, 1, 2;
- (b) `--skip-known-survivors` runs the killed twin instead of skipping it on the survivor's verdict;
- the scheme-retirement tests refuse a previous-scheme `--resume`, history row and mark by name.

RE-CHECKED 2026-10-05 on master fd3f1c1d: numbering per batch again (`runIdentityOrdinals` over the
batch's own files at that call) turns test (b) red, and the history-control test with it, so the pin
is load-bearing. Test (a) asserts `identityOrdinalsOf` itself and stays green under that revert.
