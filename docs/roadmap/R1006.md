Coord task R-994, from the 2026-11-14 review of how we find bugs (`/coord/handoff/R-994/bug-finding-review.md`, proposal 1).
Related: [[R956]] (the license), [[R960]] (the serve fallback), [[R996]] (R-975's re-sweep, whose method this reuses).

**What happened.** About 12 h of corpus windows were void, each detectable in the first minutes: DO window 1 ran 4 h 40 min with
every test refused for no license; two R-984 serve windows fell back to one-shot; R-969 ran mutants on five projects with no green
baseline test. Avalara's fresh R-986 run spent 4 h before its serve warm-up fallback was visible in the report.

**Fix.** `scripts/triage-baseline.ts` runs `lethal run --only <files>` (the whole baseline, a few files' mutants) through
`scripts/heavy-slot.sh` under `timeout -k 120`, retrying only on exit 75, then reads the store's baseline rows, its mutants' test rows
and the report. It stops by name with its own exit code: 10 no-baseline, 11 fallback (`al-runner-v3-serve-default-fallback*`), 12
no-license (al-runner's "with no license file loaded"), 13 uniform-refusal, 14 zero-green, 16 run-failed (quarantined, nothing
scored, no report, timed out or crashed), 15 fallback-unchecked (no mutant's test row in the store); 0 is `TRIAGE GO`. A run that
wrote no report (killed) still names a fallback its stderr printed. Without `--only`, a dry run picks the smallest codeunit files,
read from the file's text (`codeunit <id>`, skipping `Subtype = Upgrade` and `Install`), until they hold 100 mutants (the file that
crosses 100 is taken unless the total would pass 300) or 8 files. `--budget-s` defaults to 900 s: LethAL's `--time-budget` counts from
the session start, baseline included, so a baseline longer than that leaves no mutant to run, and stop 15 then says to raise it.
The `measurement-campaign` skill now says every al-runner-v3 corpus window starts with it.

**Review fixes (Opus, before submit).** "Reached a test" first meant "not every mutant is no-coverage", which an `error` verdict
broke, and the run's own exit code was never read; a refusal was matched only as a "NotRun" prefix, missing `<no message> [... (notRun)
...]` and `Runtime error: NotRun:` rows; codeunits were found by file name (`Cod50100.al` was missed); `timeout` had no hard kill; the
default budget could end before any mutant; a path with a glob character would match nothing.

**Found while building it.** The first version picked the single smallest file. On Avalara that was a page extension whose 2
mutants no test covered, so serve never ran and the triage said GO while the window's real fallback stayed hidden. Hence stop 15 (no
mutant reached a test: the fallback check proved nothing) and the codeunit pick. On Service Declaration the two smallest codeunits
were uncovered too (0 of 23, 0 of 30); only the third (134 mutants) reached serve, hence several files and the crossing file. With
no budget, Avalara's mutants ran one-shot after the fallback (LethAL estimated 50 min for 55 of them); that run was stopped by
hand, wrote no report, and was named `no-baseline` although its stderr had printed the fallback, hence the budget and the stderr read.

**Measured** (2026-11-14, al-runner edge-a184cfc79, final script, `/coord/handoff/R-994/final2-*`): Service Declaration `TRIAGE GO`
(56 of 61 green, two codeunits) in 5.5 min; Avalara `STOP fallback` (exit 11, four codeunits) in 19 min, most of it the 900 s budget
spent on one-shot mutants after the fallback. Earlier versions: `smoke-*`, `final-*`. Each rule is red-checked by reverting it alone
(`scripts/triage-baseline.test.ts`).

**Not done.** The review's proposals 2 to 5 (a refusal ledger, repros as a regression set, differential runs, generators); a
bcdev variant (the stops read al-runner-v3 caveats and texts).
