**The env-tool read-only resolution is DUPLICATED across two commands, and the safety property is carried by a comment rather than by the code.** `resolveForceResetLeaseConfig` (`cli.ts`) and `buildDoctorDeps`'s `resolveEnvToolOnce` + `resolvedBcdev` are ~50 near-identical lines: same `bcdevDeclaredKeys` filter, same `validateEnvToolConfig` opts, same `requireBcDevRawFields`, same default `makeEnvToolClient`, same `supplied` record (only `runId` differs — `"doctor"` vs `"force-reset-lease"`), same resolve loop, and the same `baseUrl` -> `splitBaseUrl` -> `deriveMcpPort` -> credentials -> `packageCachePathDefault` -> `validateBcDevConfig` tail. The property that matters is that BOTH spawn only `envTool.resolve` blocks and never `createEnv`/`startEnv`/`publish`/`downloadSymbols` — because `resolveEnvToolSession` "can provision a real, billed Layer-6C environment" (`cli.ts`) and these are RECOVERY and DIAGNOSTIC commands, run after a session has already died. Today each copy is correct and independently tested, but a third caller inherits nothing and must re-derive the restriction. **This is not hypothetical: the two copies had already drifted once** — `packageCachePath` was supplied by the force-reset path and not by doctor, so `lethal doctor` threw `missing required field(s): packageCachePath` on any env-tool config legally omitting it, which is why `packageCachePathDefault` was extracted. Fix: extract `resolveBcdevReadOnly(configFile, { projectDir, runId, makeEnvToolClient })` — the callers differ only in `runId` — so the no-provisioning boundary lives in one function with one test rather than in two comments. Filed 2026-08-05 from subsystem C's whole-branch review; deliberately deferred past the live gates rather than refactored under them.

**Closed 2026-08-07. Extracted, and the safety property is stronger than the row asked for.**

The row asked for `resolveBcdevReadOnly(configFile, { projectDir, runId, makeEnvToolClient })` so
the boundary lives in one function with one test. What shipped is `prepareBcdevReadOnly`, which
returns the three things the two callers actually needed rather than only the last one: the
validated `envCfg` (doctor inspects it for create-mode and `requireStatus`), the MEMOIZED raw
`resolve` output (doctor's `envStatus` reads it, and `runDoctor` may call several checks
concurrently), and the assembled `BcDevConfigSection`. `resolveForceResetLeaseConfig` is now one
line; `buildDoctorDeps`'s `resolvedBcdev` is one line.

**The improvement on the row's design:** the row would have left "spawns only `resolve`" as a
property of the extracted function's body — still a convention, just a single one. Instead the
client is constructed from `readOnlyEnvConfig(envCfg)`, a copy with `createEnv`, `startEnv`,
`readyWhen`, `downloadSymbols`, `publish` and `deleteEnv` REMOVED. A future edit inside the helper
cannot provision or publish, because the config it holds has no such block to run. Tested on the
config the client is HANDED, not only on what got spawned — a spawn assertion says what today's
code does, this says what tomorrow's could.

**Red-checked:** replacing `makeClient(readOnlyEnvConfig(resolvedEnvCfg))` with
`makeClient(resolvedEnvCfg)` reddens two tests, one of them at the `force-reset-lease` CALL SITE
rather than at the helper — which is what would catch a rewrite that quietly went back to building
its own client.

**One real bug was found and fixed while rewiring**, and it is worth recording because typecheck
did not see it: collapsing doctor's original three-way `if/else if/else` into two branches left
`validateBcDevConfig(configFile.bcdev)` running for env-tool projects — precisely the configs whose
`server`/`serverInstance`/credentials are legitimately absent, so `lethal doctor` would have thrown
on every Layer-6C project. `tsc` was happy; it was caught by re-reading the branch. The structure is
now an explicit `if (configFile.envTool === undefined)` guard.

R112 landed on top of this in the same session — the ceiling's inspect and clear surfaces are the
third caller the row anticipated, and they inherited the boundary instead of re-deriving it.
