**Measured 2026-10-25** (`/coord/handoff/R-781/default/`, al-runner 3.0.0-alpha.5+edge.20261024 (dcdf9e821), LethAL
566643ad, N = 1). The same CDO slice run twice, differing ONLY in the config's `alRunnerV3.transport`:
- `--project Cloud --tests Test`, `--only` CDOMailMessageBuilder, CDO Log Management and CDO JSON Management;
  `--tests-only` their three test codeunits.
- **Default (no `transport` key, so serve-entries per [[R761]]): the run FAILS, exit 1, after 59 s**, with
  `AlRunnerV3EntriesRefusedError: al-runner-v3-entries-warmup-dirty: the warm-up row
  Codeunit68903.CreateLogEntry_WithValidEMailLog_ShouldInsertLogEntry (codeunit 68903) is one R612 does not keep
  (NotRun: out-of-scope: FindSet on the Company table: the database may hold companies this runtime does not know
  (ADR-046 decision 4a)); every daemon repeats it, so no entry is trusted on any (R635 plan §3, §6)`. No mutant scored.
- **`transport: "one-shot"`: the run COMPLETES, exit 0, 571 s**: 387 mutants, 39 killed, 7 survived, 277
  no-coverage, 64 error (the refused test and the tests after it in its codeunit, each named `NotRun: out-of-scope:
  an earlier test of this codeunit was refused while it ran (...)`).
- R781's measurement hit the same refusal on two more slices (`/coord/handoff/R-781/try1/`, `try2/`), there because
  a test needs an unbuilt DotNet sidecar (`System.TimeZoneInfo` in the MergeFieldValueFinder tests,
  `System.Web.HttpUtility` in the String Functions tests): `NotRun: out-of-scope: dotnet-unavailable: ...`. Those
  runs set `transport: "serve-entries"` explicitly; the default is expected to behave the same (the warm-up check is
  shared).

**Why it matters.** R761 made serve-entries the default "where proven", and its proof is decided before the
warm-up. A test that v3 refuses by name (a Company read, a missing sidecar) is not known until the warm-up runs it,
and the warm-up then refuses the WHOLE session. One-shot treats the same refusal per test and scores everything
else. So a real project with one such test gets a failed run by default, where the explicit one-shot works.

**To close.** On the DEFAULT transport only (`transportSource: "default"`), a `warmup-dirty` refusal caused by a row
R612 refuses by name falls back to one-shot for the session, with one named warning (the row and its reason), and
the run completes as one-shot would. An explicit `serve-entries` keeps today's refusal. Test both directions, and
prove it on this slice (default equal to one-shot per mutant).

**Built (not yet proven live; status stays open until the slice is run).** `startDaemon` throws the typed
`AlRunnerV3ServeFallbackWarmupError` instead of `warmup-dirty` when `transportSource` is `"default"` and the bad row is
a `notRun` error that is not a timeout (`isNamedRefusalRow`, the rule `noteBaselineRows` already uses). It runs only
after the disagreement and echo checks, so those still refuse. The daemon is closed first. `runFromCli` catches it
(and nothing else), lets the first attempt's `finally` close backend and store, then runs a SECOND attempt: a new
backend built with `serveFallbackWarmup`, which `decideTransport` turns into one-shot plus ONE
`al-runner-v3-serve-default-fallback-warmup` warning, and `status()` details say `transport one-shot (...)`. Nothing
else crosses over. With `--workers > 1`, `runFromCli` refuses by name (`al-runner-v3-workers-refused`) as soon as the
first attempt falls back, before any second backend is built. The report carries the caveat
`al-runner-v3-serve-default-fallback-warmup` (raised from the warning event, like `project-symlink-skipped`; explain
schema v21, report-v3 schema regenerated). The caveat is a fixed code: the row and its reason are in the warning.
A re-run is a new run row; the aborted first run stays in the store.
