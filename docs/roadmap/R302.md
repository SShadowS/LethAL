**Filed by R-297 Task 5 (2026-09-28), by ruling I1.** Plan:
`docs/superpowers/plans/2026-09-28-R-297-instrumentation-real-corpora.md`, "Root causes", class C.
Companion to R301, which makes a split-header procedure (`preproc_split_procedure`) instrument and
gives it correct manifest fields.

**What is lost.** R301's fix changes only the manifest and line-map walks. Every SEMANTIC walk still
stops at `procedure`, so inside a split procedure the tool cannot resolve local variables,
parameters, the return type or the enclosing member. Operators that need a type or a receiver
refuse those sites; the procedure keeps HEAD's site set. A split procedure therefore reads as having
fewer mutants than its body deserves, with no warning. Mostly that is under-generation; the two
exceptions (an operator swap at one call, and a missing hang tag) are below.

**The places** (unchanged by R-297, on purpose):

1. `buildSymbolTable`'s `indexMembers` (`packages/engine/src/semantic/symbol-table.ts`) indexes only direct
   `procedure` children, so a split procedure is not a member of its object.
2. `packages/engine/src/semantic/types.ts` has its own private `findEnclosingProcedure`, blind the
   same way.
3. `empty-block` (`packages/builtin-tier1/src/empty-block.ts`) admits a body only when its parent
   kind is in `BODY_PARENT_KINDS`, which does not include `preproc_split_procedure`.
4. The engine's `findEnclosingProcedure` (`packages/engine/src/ast/tree-walks.ts`) returns null
   inside a split procedure. It feeds `packages/engine/src/semantic/receiver.ts` and
   `packages/builtin-tier1/src/return-value.ts`.

**Other walks that stop only at `procedure`** (operator-local, same blindness): the executable-body
tests in `flip-boolean-literal.ts` (`BODY_ANCESTORS`), `toggle-blank-string.ts`,
`toggle-blank-temporal.ts`, `shift-integer.ts`, `loop-skip.ts` and `loop-truncate.ts`; the scope
walk in `loop-hazard.ts` (`SCOPE_KINDS`); `packages/builtin-tier2/src/write-txn-codeunit-run.ts`;
and `packages/engine/src/semantic/callers.ts`.

**Measured losses** (R-297 Task 5, 2026-09-28): hand-written repros, each a split procedure against
its de-preprocessed twin (the same file with one plain header), run through `generateMutationSet`.
Mutants the twin has and the split procedure does not:

| operator | lost sites | why (by mechanism) |
| --- | --- | --- |
| `empty-block` | the body, 1 per procedure | `BODY_PARENT_KINDS` |
| `flip-boolean-literal` | 4 (`true`/`false` arguments and an assigned `true`) | `BODY_ANCESTORS` |
| `toggle-blank-string` | 3 | its executable-body test |
| `toggle-blank-temporal` | 1 (`0D`) | its executable-body test |
| `shift-integer` | 1 (`I := 5`) | its executable-body test |
| `swap-additive` | 3 (`D + 1`, `X + 1`, `I + 1`) | `ctx.types` (`semantic/types.ts`) |
| `return-value` | 2 (`exit(X + 1)`, `exit(I > 3)`) | `findEnclosingProcedure` |
| `loop-skip`, `loop-truncate` | 1 each | their executable-body tests |
| `swap-modify-flag` | 3 (`Modify(true)` twice, `Delete(true)`) | receiver resolution (`receiver.ts`) |
| `swap-find-direction`, `validate-to-assign` | 1 each | receiver resolution |
| `remove-setrange` | 1, REPLACED by a `void-method-call` at the same call | receiver resolution; the Tier-2 claim is lost, so the Tier-1 deletion is emitted instead |

**Not only losses: a missing hang tag.** In a split procedure, `remove-assignment` of a variable an
enclosing `while`/`repeat` condition reads (`I := I + 1` under `while I < 10`, `Done := true` under
`until Done`) is emitted WITHOUT `hangCapable: "loop-condition-target"`, which its twin carries:
`resolveVarRef` cannot resolve a split procedure's local, and `classifyHangCapable` refuses on an
unresolved target. The mutant still runs. What is lost is the pre-run warning
(`hangCapableCount`) and the report field; a hang is still caught by the per-mutant time budget.

**Review note (2026-09-28): that budget is not the whole safety net.** The per-mutant time budget
only ends the ONE mutant's run; on the DEFAULT path, where `--stop-hung-sessions` is off because it
would end a session on the user's own server, a mutant that hangs still strands the whole tier behind
it until the session itself times out or is killed by hand (the same tradeoff `empty-block.ts`'s
`BODY_PARENT_KINDS` doc comment already states for the `while`-body cession). A missing hang tag on
this shape means the pre-run warning that would have told an operator to expect that risk does not
fire, on top of the report field being absent.

**Size** (R-297 Task 0 census): files holding a `preproc_split_procedure`: DC/Cloud 3, BaseApp 4.

**Closing.** Closes when those walks treat a split procedure as a procedure, with a test per place
that shows a site inside a split procedure is generated with the same operator and text as in its
de-preprocessed twin.

**2026-09-28: widened to the preamble shape ([[R316]]).** Every place listed here is blind inside a
`preproc_split_procedure_preamble` too, measured on hand-written repros: `q1-twin-body` (a preamble)
and `q2-split-twin` (a `preproc_split_procedure`) both lose the same three operators against their
plain twin (`empty-block`, `return-value`, one `swap-additive`). [[R316]] made the preamble a member
for the manifest, line map and latch walks only. The preamble adds one rule of its own for this
item: each arm declares its OWN locals (and may take different parameters or return types), so a
name inside the shared body may be resolved to a type only when every arm that declares it agrees.
