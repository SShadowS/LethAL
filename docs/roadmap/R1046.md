Coord task PR-33, part 1 (2026-11-15). Evidence: `/coord/handoff/PR-33/` (`rsa-texts.ts`, `rsa-texts.txt`, `run-rsa/`,
`bc-check/dotnet-exception-rsa`, `bc-check-expected/`, `bc-run/result.md`, `measured-7924-rsa.md`). Related: [[R1044]] (family 9,
which named this gap).

**The gap.** R1044's RSA cell raised the managed CryptographicException, so the two largest #7924 keys were not measured:
`RSAWrapper.Decrypt` (43 standing sightings) and `RSACryptoServiceProvider.Decrypt` (38), both raising
`Interop+Crypto+OpenSslCryptographicException`, all in Microsoft's crypto test apps (`RSA Test`, `RSACryptoServiceProviderTests`).
The stored texts (`rsa-texts.txt`) name four OpenSSL causes. Three cover 80 of the 81 sightings: "oaep decoding error", "padding
check failed", "value missing". The fourth, `RSAWrapper.Decrypt` "error:1C8000A2:Provider routines::failed to decrypt" (1
sighting, a mutant), is not reproduced by any cell.

**What was built.** `scripts/refusal-family.ts` family `dotnet-exception-rsa` (BC-check number 10), 16 cells:
- 7 sites: PKCS1 ciphertext decrypted with OAEP, OAEP ciphertext decrypted with PKCS1, and a key holding only its public part
  decrypting (and, on RSACryptoServiceProvider, signing), on RSACryptoServiceProvider and on RSA.Create() (RSAWrapper);
- each in PR-32's guarded and text shapes (`guardedAndText`, now shared with family 9), plus a same-padding control per path.
A test pins the sites, that each wrong-padding site decrypts with the other padding and each control with the same one, and that
a public-only site uses a key made from the public part. It goes red when a control decrypts with the wrong padding.

**Measured.**
- **edge-5a58a0f16:** the 14 site cells are refused, each with one of the three stored OpenSSL texts; the 2 controls pass.
- **BC** (lethal-bugs, bc2, BC 28.4 W1 on Linux, 2026-11-15): 9 pass, 7 fail. All 7 guarded cells and both controls pass. Each
  text cell gives `A call to <Type>.<Member> failed with this message: <OpenSSL message>`, naming the same member as al-runner's
  refusal (RSAWrapper for RSA.Create()) and the same OpenSSL message; no exception type name.

**Filed.** On #7924, with BC's text per site and an invented repro:
https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7924#issuecomment-6899052160. Regression entry
`u7924-dotnet-exception` gains two tests (51595 wrong padding on RSACryptoServiceProvider, 51596 public-only key on RSA.Create());
both are refused on 5a58a0f16, and BC's answer is that of the equivalent guarded cells (the entry's own app has not run on BC).
