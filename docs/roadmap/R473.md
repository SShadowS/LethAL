**Found 2026-10-05 in the [[R459]] survey and sol's review of its plan (finding 4).** It predates
R459 and is out of its scope.

**What.** When a receiver does not resolve at all (`receiverUnresolved`, for example a caller inside
a `#if`), `claimsRecordMethod` refuses the call, so `swap-modify-flag` does not claim it and
`flip-boolean-literal` does not cede it. Flip then emits `Par.Modify(true)` -> `Modify(false)`, and
the same for `Delete(true)` and `Insert(true)`. Its `RUN_TRIGGER_ARGUMENTS` rows for these three
methods at count 1 have `skip: null`, so the skip flip carries NO `run-trigger-skipped-*` tag. The
forcing `false` on the same receiver IS tagged (R460), and so is the skip direction of `ModifyAll`
and `DeleteAll` (R-364). So the screen under-tags exactly here.

**Precedent.** R-364 (unresolved receiver keeps the SKIP tag, R143's rule) and R460 (the forcing
`false` tagged there too) both rule that a screen tags what it cannot prove harmless. The likely fix
is a `skip` on those three rows, using `modifySkipCanRaise`, `deleteSkipCanRaise` and
`insertSkipCanRaise` (all keep the tag on an unresolved receiver). [[R464]] may resolve some of these
receivers, but not every one.

**Measure first.** Count the sites on BC.History, CDO and the fixtures (untagged sole-argument
`true` flips on an unresolved receiver), and pre-commit any gate move. The change is tag-only: no
site and no identity moves.

**Done (2026-10-05, 3fffd472).** Plan `docs/superpowers/plans/2026-10-05-R-473-unresolved-sole-argument-skip-tag.md`.
The three count-1 rows of `RUN_TRIGGER_ARGUMENTS` get their skip check (`modifySkipCanRaise`,
`deleteSkipCanRaise`, `insertSkipCanRaise`). It is reached only through `runTriggerTag`'s
unresolved branch, which keeps the tag (R-364's rule): a claimed sole `true` is still ceded to
`swap-modify-flag`, and a receiver that resolves to a non-record stays untagged. Letting Tier 2
claim unresolved receivers was rejected: it would move every such site to another operator (an
identity change) and treat a receiver that may be a codeunit as a record.

Measured from complete spec dumps (every operator), master against the branch, by identity key:
0 added, 0 removed, 0 changed other than the tag, 0 keys moved, on every set. Newly tagged
(modify / delete / insert): BC.History 879 / 130 / 107 (1116 in 57 projects), CDO 1 / 0 / 0,
fixtures and examples 0. No `IDENTITY_SCHEME` or operator version change. No fixture mutant
changes, so no gate pin (including `itest:tables`' `platformArtifactKills`) moves.

Tests: the flip test "tags a sole true RunTrigger by kind when the receiver does not resolve"
(red when any one row goes back to `skip: null`, when every unclaimed `true` is tagged without
`receiverUnresolved`, and when the cession is removed), and `r459-run-trigger-seam.test.ts`'s
unresolved-receiver case, which pinned the gap and now expects `run-trigger-skipped-modify`.

**Landing order with R464** (agreed with lethal-bugs). R464's implicit-Rec resolver shrinks the unresolved set, so
some of these tags move to `swap-modify-flag`'s proof-based decision once it lands. Whichever of R473 and R464 lands
second merges the other and re-runs its exact site diff on top, row by row.
