Coord PR-74 (2026-11-16). Spec: `docs/superpowers/specs/2026-11-16-pr74-t9-refusal-families.md`. Evidence:
`/coord/handoff/PR-74/` (`census/census.t9-refusals.json`, `census.log`).

**Part 1, the drift.** PR-56's guard fired once in DO window t9. A fresh daemon reproduced the row, so the kept class carried
nothing. The row it compared was a baseline fail. The guard stays as it is (ruling recorded in R1072).

**Part 2, the census.** A new generator family, `t9-refusals` in `scripts/refusal-family.ts` (15 invented cells, ids
51001-51015), produces each text t9 met in its mutant phase. The texts are exact, because al-runner's text is the class.
PR-54's strict `keep-census.ts` then measured 10 classes, all CLEAN. Each had `engineKept` on every kept reader, and every
refuser refused under serve. Every target text could be driven. The ZipArchive text needed an empty stream,
`Report.RunRequestPage` a `Commit()` after the kit's writes, and `Report.SaveAs` the Xml format.

**Kept** (`PR56_KEPT` in `al-runner-server.ts`; pinned by `al-runner-serve-pr74.test.ts` against
`tests/pr74-measured-refusals.json`):
- new entries:
  - `setfilter-value-expected` (`..` and `@`);
  - `evaluate-decimal-comparison` (`>100`, `>1000`, `<1000` only);
  - `report-parameters-no-xml-declaration`, for `Report.SaveAs` only;
  - `dotnet-zip-central-directory-corrupt`, exact;
  - `dotnet-json-writer-no-token-to-close`, exact;
  - `dotnet-json-writer-start-object-in-object`. The census measured the path `a`; t9's three paths (`message`,
    `message.ccRecipients[0]`, `message.toRecipients[0]`) are added by name. The path is the writer's own nesting, not engine
    state, so this is a widening by name, not a measurement;
  - `boolean-false-to-biginteger`, exact;
- widened: `recordref-method-not-open` (Duplicate, ClearMarks) and `fieldref-method-never-assigned` (SetFilter).

Each entry rests on one call shape per text. The SetFilter operators were measured on a Decimal field through
`Record.SetFilter`, the BigInteger conversion through `RecordRef.Field(..).Value`, and `Report.SaveAs` in Xml format on a
report without triggers. Another code path that yields the same text is kept without its own measurement.

**Not kept:**
- `Report.RunRequestPage` with the same parameters text (review H1). The census cell needed a `Commit()` after the kit's writes;
  without it, the run stopped before the refusal. A real mutant reaches this text inside an open write transaction, which was
  not measured. To keep it: a cell in that shape (a plain Insert, then RunRequestPage), and a census of it.
- `JsonTextWriter.WritePropertyName` and `WriteEndArray` (t9: 1 and 2). The first was produced, but the census drives at most 3
  refusers per class; the second was not driven.
- `SetFilter: ... is not a BigInteger` (t9: 2): not driven.
- `Page.Run with RecordRef as the record` and the other small families t9 met (3 or fewer closes each): not measured.

R945's closes stay closed: FieldRef.Value, RecordRef.Get and CopyLinks, each tested.

**Open, a census tool gap (review M1):** `keep-census.ts` names each class's log by its class text, cut to 60 characters. Two
pairs of classes got the same name, so one log of each pair was overwritten: Evaluate `>1000` against `<1000`, and the two
Report parameter classes. Their CLEAN verdicts stand in `census.t9-refusals.json` and `census.log`, but the per-request rows of
`>1000` and RunRequestPage are gone. The name needs a class index. **Fixed in PR-76 (fe099d4a):** the log is
`serve.<source>.<index>-<text cut>.log` (`classLogName`), and a test shows two classes with the same 60 leading characters get
two files. The index is per invocation, so a re-run into the same out dir can still overwrite an old log of a class that shares 60
leading characters. PR-74's two lost logs are not re-made.
