**Filed 2026-10-22 by coord task R-612** (measure step; the plan review rated it a live false-kill candidate in
shipped code).

**What.** v3's `--help` says of `--test-timeout-secs`: a stopped test is "reported as not run, with the limit as
the reason; the codeunit's later failures are then not trusted". But the row of a later failure does not say so.
It is a plain `status: "fail"` with no `notRun`. `AlRunnerV3Backend.run` scores it as `fail` and adds only a
`backendNote` (`stateNote`). So under a mutant that makes test A hang, a test B of the same codeunit that fails
only because A was stopped half-way (codeunit variables survive between tests under `--isolation test`) becomes a
kill. Reproducing the kill re-runs the same sequence, so the reproduction rule does not catch it.

**Measured shape** (invented probe, pinned alpha.2 91253f2d6, one-shot and serve alike):
codeunit "R612 Cpu" = `SpinInsert` (inserts 50 rows, then loops forever), `AfterSpin` (empty), `FailsAfterSpin`
(`Error`). With `--test-timeout-secs 3 --isolation test`: `SpinInsert` is `notRun` "Test exceeded 3s timeout.",
`AfterSpin` `pass`, `FailsAfterSpin` plain `fail`, exit 1. The probe shows the row shape only. No test here
fails BECAUSE of the stopped sibling.

**Evidence.** `/coord/handoff/R-612/probe/oneshot-cpu.json` (one-shot), `/coord/handoff/R-612/probe/main.stdout`
(serve, kind "CPU timeout"), `/coord/handoff/R-612/measure.md` finding F2; the scoring is in `AlRunnerV3Backend.run`
and `v3RowVerdict` (`packages/runner/src/al-runner-v3-backend.ts`).

**Closed by ruling, 2026-10-22 (coord task R-637; orchestrator ruling: option (b) plus a pin).**
- **The premise was false for dependent failures.** The premise was "a later failure's row does not say it is not
  trusted". That holds only for a failure that v3 has proved independent of the stopped test, like R612's
  `FailsAfterSpin`, which reads nothing its sibling wrote. R-637 measured the dependent case on alpha.2
  (`/coord/handoff/R-637/measure.md`). There, test B fails only because test A was cut off. v3 reports B as
  `notRun: true`, `status: "error"`, with "... this failure is not trusted: <B's own message>". `v3RowVerdict`
  scores that row `error` (`runner-refused`), never a kill. That held on 19 state channels, with 0 escapes, in
  one-shot. On serve, only codeunits 50792, 50793 and 50786 ran, and their rows matched one-shot. LethAL's own run (`runSession` with `AlRunnerV3Backend`) scored no kill.
- **So no fail-closed scoring rule was built.** Such a rule would also throw away real kills. The probe's `tests2`
  shows a plain `fail` after a timeout that is a real kill, reproduced.
- **The pin.** Pre-commitment r8
  (`docs/superpowers/specs/2026-10-22-r586-alrunner-v3-precommitment-r8-dependent-notrun.md`, 848371cb) adds the
  leg-C contract fact `dependent-fail-after-timeout-is-notrun`.
  - It uses probe codeunit 50652 "Probe Cut": `HangsDirty` is stopped, and `ChecksClean` then fails on its global.
  - The fact reads `matches` only on v3's not-trusted row. A plain `fail` reads `diverged`: it refuses a session
    and makes the update gate `gate-fail`.
  - So a build that drops v3's guard cannot become `current`. Leg C now has 24 facts.
- **The note change.** The `[v3-codeunit-state-possible]` note (`stateNote`) now names a not-run covering
  sibling as `timed out` or `refused`, no longer only `not run`.
- **Nothing goes upstream.** v3 behaves as its `--help` says.
- **Left over.**
  - A cost: a not-trusted row as LethAL's first covering test ends the mutant as `error`. It never reaches the
    hanging sibling's timeout kill. Filed as [[R639]].
  - The residual risk is a false negative in v3's reach analysis. The pin cannot see that, and the probe could not
    produce one.

**To close (original).** First measure whether a later failure can really come from the stopped sibling (a probe where B
fails only when A was cut off). Then pre-commit a rule: a `fail` row ordered after a timeout row of the same
codeunit in the same call is not a kill (`error`, naming the timed-out sibling), unless the killer is the
timed-out test itself. Red-check both directions. Run `itest:alrunner-v3` with every figure unchanged, or with
moves that are pre-committed.
