**What.** `Rec.Insert(RunTrigger, InsertWithSystemId)` takes two Booleans; the FIRST is
RunTrigger. Two gaps, both left out of [[R457]] on purpose because closing them moves sites or
identities, which R457 (a tag-only change) must not do.

1. **The forcing flip is untagged.** `flip-boolean-literal` reads the RunTrigger of `Insert` only
   under an exact argument count of 1 (`RUN_TRIGGER_ARGUMENTS`), so `Insert(false, X)` ->
   `Insert(true, X)` forces `OnInsert` and carries no `run-trigger-forced`. Measured in the R-457
   survey (`/coord/handoff/R-457/survey.md`, section r2): BC.History 4 sites, CDO 0, fixtures 0.
   Pinned untagged by the flip test "does NOT tag the first argument of a two-argument
   Insert(false, true)".
2. **The cession orphans sites.** `isCededRunTriggerFlag` cedes EVERY `true` argument of a call
   `claimsRecordMethod` claims as `Insert`, but `swap-modify-flag` refuses a two-argument `Insert`
   (it reads a sole argument). So `Insert(true, X)`'s first argument (BC.History 13, the R-457
   survey's `Insert2 true not-emitted`) and `Insert(X, true)`'s second are mutated by nobody. sol's
   R-457 plan review r1, finding 4, found it.

**Why separate.** Fixing (2) ADDS mutants, and moving the cession can change which operator owns a
site, so it is an identity change with its own pre-commitment, not a tag. (1) is small and could ride
with it: count 2, index 0 for `Insert`, judged by `forceCanRaise` with the insert kind.

**What to build.** Cede only a `true` that `swap-modify-flag` actually claims (a sole argument), so
the two-argument forms fall to `flip-boolean-literal`; tag the RunTrigger position of a two-argument
`Insert` both ways (skip: `insertSkipCanRaise`'s rule; force: `forceCanRaise`). Measure the new sites
on BC.History, CDO and the fixtures, and pre-commit any gate move before landing.
