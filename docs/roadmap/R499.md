**Found by R-496's final review (sol round 6).** Follows [[R496]].

A control request can still be outstanding when a score is published. Two orderings:

1. A `StopHungRun` request is still outstanding after `settleStop`'s bound. Later it gets a redirect to
   an unfiltered extensions query, and there is no next call to throw it. R-496 now surfaces this at
   session teardown (the session ends with `UnfilteredExtensionsQueryError`), but only at the end,
   and only the refusals collected by then: a refusal that arrives after teardown is still lost.
2. A confirmation call that started earlier returns a pass, because it checks only its own record.
   The ORIGINATING run's holder is closed while the confirmation call is already running, so a
   refusal that lands after that goes to the transport, not to this call.

In both cases the forbidden request is never sent. Every scored verdict comes from a real answer to
an unredirected request. The risk is a verdict recorded while a refusal is still pending.

Two ways to close it:

- Drain outstanding control requests before accepting a scored result.
- Fail closed while any control request is outstanding.

It needs `itest:hang` to land. That gate is the only one that exercises the stop path.

**Closed by draining, with a bound** (plan `/coord/handoff/R-499/plan.md` r3, reviews r1 and r2 in
the same folder). Before `run`, `runWithCoverage` or `runMany` returns a scored result, it waits up
to `CONTROL_DRAIN_MS` (5 s) for every control fetch still in flight: its own, and the orphans of
earlier unscored calls. A refusal that lands meanwhile is thrown from that call. A fetch still in
flight at the bound throws `ControlDrainTimeoutError`: nothing is published for that call and the
session ends. The backend owns one `ControlState` that every transport it binds shares, so a
re-deploy cannot strand an orphan, and `bindTransport` refuses a transport built without it. The
teardown drains once more, before `phase-left: teardown`. A second late refusal is now warned
rather than dropped. Proof: the S, C, G, B and T tests in `run-mutant-transport.test.ts`,
`run-mutant-many.test.ts`, `bcdev-backend.test.ts` and `refusal-scope.test.ts`, each red-checked
(`/coord/handoff/R-499/redchecks.md`). The live `itest:hang` run is pre-committed in
`/coord/handoff/R-499/hang-precommitment.md` (every frozen figure unchanged). Left open: the
watchdog's status poll has no timeout of its own (R503). A refusal after the bounded teardown
drain can only come from a fetch that ignored its abort for 5 s twice.
