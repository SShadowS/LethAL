Found by coord task R-908 (2026-11-10). Evidence: `/coord/handoff/R-882/S3.events.ndjson`, `/coord/handoff/R-908/`. Related: [[R69]], [[R908]], [[R909]].

**What.** The reader (`scanTestPageModel`, `testpage-scan.ts`) follows calls through the test app's own source. A test that reaches a page through dependency code is not refused and is sent to the fenced session. R-882's 3 ServiceDeclaration failures, "cause not found" there, are this:
`Sales Line.ShowItemChargeAssgnt` and `Purchase Line.ShowItemChargeAssgnt` (Base Application), and `No. Series - Impl..LookupRelatedNoSeries` (Business Foundation). Each failed with a CLR `NotSupportedException`.

**Why it matters.** On Linux BC such a test fails fast. On a Windows server, R69 measured that a page open with a realistic page can hang the fenced session, so a test the reader misses is a wedge risk there.

**To decide (coord R-910).** Whether the reader can see dependency symbols or source well enough to follow these calls, or whether the limit is named instead.
