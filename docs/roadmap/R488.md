**Found 2026-10-06 by R-300b's live gate** (the `sandbox-wrapped` record run, blocked). Diagnosis is in the
coord handoff for R-300b (`twin-leak-diagnosis.md`).

**What.** al-runner's `--test PATTERN` selects every test whose name contains PATTERN, ignoring case. It is not an
exact match, and `--help` on v2.12.0-main.c39ad5de documents no way to anchor it. LethAL's one-shot path asks for
one test (e.g. `--test Codeunit78950.GrowPre`). al-runner also runs `GrowPreTwin`, writes ONE Cobertura file for
both, and the one-shot `run()` credits all of it to `GrowPre`.

**Measured:**
- `--test ...GrowPre` reports `GrowPre` AND `GrowPreTwin` (both pass). The coverage hits the lines of both tested
  objects.
- `--test ...GrowPreTwin` hits only the twin.
- `--server` per-test coverage is clean, so only the one-shot leg is affected.
- It is pre-existing: the transport and the one-shot `run()` are unchanged by R-300b, and the merge is in
  al-runner's raw output. No committed fixture had two test names where one contains the other, so no gate saw it.

**Why it is a correctness risk.**
- Today's symptom is an EXTRA covering test, which only makes more tests run.
- The same mechanism can DROP coverage. The merged invocation shares ONE deadline: if a requested test's sibling
  is slow or hangs, the requested test reads deadline-exceeded or not-green, and the mutants only it covers lose
  coverage or verdict.
- A sibling failure is also credited to the requested test's name, so `killingTest` can name the wrong test.

**Closing it.** In the one-shot `run()`, refuse loudly by name when al-runner returns any test other than the one
requested. Alternatively, re-run that test alone. A cheaper stopgap is a session-start check that refuses a test
whose qualified name contains another test's name. Ask al-runner upstream for an exact-match `--test`. Do NOT
rename fixture tests to dodge it. Each fix needs a red test in each direction (a merged run is refused; an exact
single test is unaffected).

Related: R-300b (its gate exposed this), R220 (al-runner coverage), R383.

**Closed 2026-10-06 (client-only).** Measured on c39ad5de (raw table in the R-488 coord handoff,
`selector-probe.md`): al-runner has no exact `--test` (no anchor, quote, regex or `--test-exact`),
but `--exclude-test` matches a WHOLE qualified name, case-insensitively, and
`--test ...GrowPre --exclude-test ...GrowPreTwin` runs `GrowPre` alone with a clean Cobertura.
`AlRunnerBackend.run()` (one-shot) now never credits a result that names any other test: it learns
each sibling by name, re-runs the test with one `--exclude-test` per sibling, sends those excludes on
every later call, and refuses by name a result that still names another test. Unit tests in
`al-runner-backend.test.ts` go red in each direction. R-300b's gate with this merged: the wrapped
one-shot leg matches its pre-committed table (22/9/3, `--define` adds), equal per mutant to
`--server` and resource. Review follow-up: `runSession` now gives the session backend and every
worker backend the discovered test list (`useDiscoveredTests`, every arm read), so every name that
contains the requested one, ignoring case, is excluded from the FIRST call on, and the shared
deadline is no longer at risk; the learn-and-refuse path stays as the defence for a test discovery
did not see (for example one outside `--tests-only`). A name equal to the requested one ignoring
case is never excluded. Deliberately unchanged: `al-runner-canary.ts` and `al-runner-contract.ts`
also send `--test`, but over LethAL's own fixed probe names with no look-alikes, and they produce
no verdicts. Upstream ask drafted in the same handoff (`upstream-issue.md`).
