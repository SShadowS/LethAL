**Filed 2026-10-08 by the [[R500]] build** (plan r3 `/coord/reviews/R-500-plan/plan.r3.md`, shape 2; survey
`/coord/handoff/R-500/survey.md`, shape 2 "table trigger" first hop). A plausible hang that is NOT refused.

**What.** R500's one-hop rule follows procedure calls on a typed receiver. A call that fires a TABLE TRIGGER
(`Insert(true)`, `Modify(true)`, `Delete(true)`, `Rename`, `Validate` of a field with an `OnValidate`) runs code in
the table object that the item's progress can depend on, and none of it is refused.

**To close.** Count the trigger firings from open report-item code with production code, read a sample, then
refuse the fired triggers (and their same-object closure) or close it with a ruling.

**Closed by ruling 2026-10-23 (R-523, lethal-preproc).** Evidence: `/coord/handoff/R-523/measure.md`,
`sample.tsv` and the parse scripts beside them. It was measured by parse on master d7bdd4e3, with R500's own
predicates (`inOpenItemCode`, `callTargets`), from a fresh BaseApp generation.
- **Reach.**
  - BC.History has 51 trigger-firing calls in report open-item code (Validate 43, Insert 6, Modify 1, Delete 1).
    37 fire a mutable trigger, all in Base Application, across 9 reports.
  - CDO, DC and DO have 0.
  - There is no `Rename`, `DeleteAll(true)` or `ModifyAll(..., true)`, and none is in test code.
- **Consumption, all 37 classified by parse.**
  - 0 re-filter or consume the loop's own set through `Rec`.
  - 5 write other tables only.
  - 31 touch no record set.
  - 1 changes the walked set through another variable: `Contract Price Update - Test` fires
    `Service Contract Line.OnModify`, which modifies `Service Contract Header`. A Modify adds and removes no record.
    By parse it writes only `Annual Amount` (and, one level further, `Amount per Period`). Neither is a key or filter
    field of either walked record:
    - the header data item: sorted by `Next Price Update Date`, filtered on `Contract Type`, `Status`,
      `Change Status`, `Next Price Update Date`, `Contract No.` and `Item Filter`;
    - the temporary `Service Contract Line` loop: primary-key order, no filter.
    So the loop cannot revisit or skip records because of it.
- **Cost of the refusal.** Refusing the fired triggers and their same-table closure would remove 2,506 of Base
  Application's 748,002 deployed mutants (0.33%), and 0 elsewhere. It would still be incomplete: 22 of the 37 leave
  the object, which is [[R520]]'s question.
- **Already covered.**
  - A loop inside a trigger is caught by the product-wide loop rules ([[R196]], [[R446]], [[R480]], [[R531]],
    [[R570]]).
  - R-500's survey read 6 trigger and event sites by hand and found 0 hangs.
  - Any hang a mutant in such a trigger could still cause is stopped and quarantined, not scored as a kill
    ([[R658]], [[R665]]).
- **Not taken:** a prototype of the refusal is kept at `/coord/handoff/R-523/r523-prototype.diff`, in case uniformity
  with R500's record-callee rule is wanted later.
