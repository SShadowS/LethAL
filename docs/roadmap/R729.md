**Shape 1 (AL0111).** The original has an `if <cond> then;` (an inner `if` whose `then` is empty, the `;` ending it)
as the whole body of an outer `if` or a `case` branch. A mutant arm for the inner condition (negate-guard) is
emitted as `begin <reach latch>; if not (<cond>) then; end`, and the next statement follows with no `;` after
that `end`. The original's one `;` ended both statements; the wrapper keeps only the inner one. Not seen in
any fixture: no committed fixture has an `if ... then;` as a single-statement body.

**Shape 2 (AL0110).** One arm of a `then`/`else` pair: the `then` body is a single call, the arm that removes the
call emits `then ; else`, which alc reads as an orphaned `else`. The same site's other arms compile.

**Fix direction.** Shape 1: when the wrapped statement already ends in an empty statement, the wrapper must
supply the `;` after `end`. Shape 2: a removal arm for a sole `then` body next to an `else` must emit
`begin end`, not `;`. Each needs a fixture shape that is red before the fix (the R402 sweep,
`scripts/fixtures/r402`, is the place), then re-run `scripts/r315-dc-compile.ts` on DC/Cloud.

**What this does not show.** alc stops at syntax errors before it binds names, so the instrumented compile
reports nothing about symbols or types yet. Re-run after the fix to see the next layer.
