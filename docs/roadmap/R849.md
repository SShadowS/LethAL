**Filed 2026-11-06 by preproc.** Related: [[R810]], [[R332]], [[R827]].

**What.** A change to a fixture's text can re-key a v3 baseline row with no verdict moved. Two routes are both closed:
- R810's rule: a record on a pinned build may write only the rows already committed, every field, in order. So R332 cannot write a new key.
- `LETHAL_RERECORD_BASELINE=1`: `.claude/hooks/baseline-guard.ts` reads it from the environment of the Claude session, and the Edit tool has no command to prefix. In a running
  session it can only be set by a relaunch or a settings change.

**Next.** Decide the route. One candidate is a pre-committed re-key table in the pinned path, by the `undo` hook leg T uses: a pinned build still writes nothing of its own.
