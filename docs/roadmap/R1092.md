Coord task PR-90 (2026-11-16), measure only. A small DO scope (one source codeunit, 105 mutants, and its one test codeunit of
23 tests) on al-runner edge-847b1fa5a serve, plus one serve daemon driven by hand that reads al-runner's own per-request
`summary.timings` and per-entry `resetMs`/`wallMs` (al-runner #5856; LethAL receives these fields and drops them). Evidence and
the full table: `/coord/handoff/PR-90/result.md`. Counts are from R-984's window t10 (774 new covered mutants, mutant phase
6,992 s: warm-ups 3,712 s, prefetch 2,270 s, live 942 s); the seconds per lever are count x the unit cost measured here.

**Measured unit costs:**
- A fresh daemon's fixed start is ~4.6-8.9 s (cached compile 2-5 s, install baseline cached after the first, setup ~1 s). The
  rest of a DO warm-up (~16-20 s of ~25 s) re-runs the proven codeunits' tests.
- Every request pays a setup of 0.4-0.95 s (workspace load), even on a kept daemon with unchanged sources.
- A pass costs 0.27-0.30 s for one test and 0.7-0.85 s for 23 tests. Each pass starts a new .NET sidecar (0.07-0.15 s), because
  Newtonsoft leaves it dirty. The test code itself is a few ms.
- DB reset between passes: 0 ms. LethAL's own work around requests: ~10-60 ms per mutant.

**Levers, largest first (overlapping; seconds in t10):**
1. Daemon restarts on refusal closes (77 x ~25 s, ~1,900 s). LethAL: keep-list measured-clean families. Upstream: a clean-state
   flag on a refusal.
2. What a warm-up re-runs to prove a fresh daemon (~2,400-3,000 s). A LethAL design question with a verdict-safety side.
3. Tests per pass: t10 sends ~9.4 entries per new covered mutant, each a codeunit pass cut after its last covering test
   (~1,000-1,500 s if half the tests are not covering). LethAL design.
4. The .NET sidecar is restarted every pass (~500-1,100 s). Upstream.
5. The workspace is reloaded on every request (~270-620 s). Upstream.
6. Live requests carry one mutant each (~130-300 s, inside 5). LethAL: batch them.
7. al-runner's per-pass start besides .NET (~0.15 s per pass). Upstream; unmeasured on a non-.NET codeunit.

**Follow-ups measured (2026-11-16):**
- **Lever 2 (PR-91): the premise above was wrong.**
  - The figure "~16-20 s re-runs the proven codeunits' tests" was inferred by subtracting plain-source start costs from ~25 s.
  - Measured on the FULL instrumented DO app (43,518 mutants, edge-4ebfe7913), a fresh daemon's first request spends 25.8 s
    and 27.8 s in `compileMs`. The second daemon recompiled in full: upstream #8143, numbers added there.
  - Proving 5 DO codeunits (170 tests) on a kept daemon takes 2.5-3.5 s of `testsMs`. Two-test `runSelectedOnly` sentinels
    take ~0.7 s.
  - So a warm-up is the recompile, and the opt-in sentinel the owner approved would save ~2-3%. Not built; the owner is asked
    to confirm closing it (q-20261116T214008-a938ded5).
  - The warm-up's real levers are #8143 (upstream) and fewer restarts (lever 1: R1095).
- **Lever 3 (PR-92): dropped.** On PR-90's scope, with the instrumented app and entries as LethAL builds them, a pass costs
  ~0.1 s for al-runner's start plus ~0.15 s for .NET, and each test only 3-5 ms.
  - Narrowed entries (1-3 covering tests) took as long as today's 7-17-test entries.
  - 14 mutants compared: 0 verdicts differ, and no measurable time saved.
  - DO-wide that is ~90-300 s, not the 1,000-1,500 s above. The 0.75 s for 23 tests above was plain source, measured while
    a DO window ran; on the instrumented app such a pass is ~0.28 s.
  - Not built: small gain, real verdict risk from the state that dropped tests leave.
- **Lever 6 (PR-92): measured, not built.**
  - The cost it would remove: a request's fixed cost is ~0.7 s. That is setup (#8205), plus the install baseline, which runs
    again on every request with `resources` (#8206). 14 one-mutant requests took 16.3 s, against 5.9 s batched.
  - The likely source of the one-mutant requests is groups that a second cut left unreached (R635 §7's "re-sent once"); the
    split of t10's live requests by cause is not measured.
  - The re-batching design (spec `docs/superpowers/specs/2026-11-16-pr92-rebatch-unreached.md`) was stopped by its
    spec-adversary review:
    - the re-send rule as drafted can loop (an always-unkept echo) or adds live requests;
    - a refusal does not stop a request's stream, so each cut re-runs the whole remainder, and on DO's dense refusal
      closes the work can exceed today's;
    - under PR-89's lanes the saving shrinks.
  - The leftovers come from refusal closes, so lever 1 removes them at the source.
- **Upstream:** lever 4 is #8204, lever 5 is #8205 (not reproduced by invented apps; a breakdown is asked for), and the install
  baseline per request is #8206.
- **The echo pass per mutant group is new:** 0.10-0.125 s each, ~28% of a batched mutant. Dropping it is a guarantee trade.
- **A batched mutant costs ~0.4 s on al-runner today.**
