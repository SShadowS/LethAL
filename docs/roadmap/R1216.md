**Found by** PR-435 (lethal-code, 2026-11-25), measured on c5's events. Evidence: `/coord/handoff/PR-435/findings.md`,
`split.py`, `prefix.py`. The figures are shares, because c5 ran under load.

- **What was measured:**
  - In c5's prefetch and live requests, al-runner executed about 2.56M tests in 83,736 s of `tests` time.
  - The scored mutants' covering runs (`test-costs`) are 605k runs, taking 18,243 s.
  - Entries average 16 executed tests to reach 3.8 covering ones: a plain codeunit entry runs the codeunit's tests up
    to its last covering test (the tail after it is cut, PR-94).
  - So about 65,490 lane-s (66.3% of the mutants phase) is non-covering prefix tests plus per-test overhead (isolation
    reset). c5's events cannot separate the two, because the rows of non-covering tests are not recorded.
- **Why the prefix runs:** under isolation `test`, codeunit globals persist from test to test, and DO's tests depend on
  that (R1141). App SingleInstance state persists too (R1173).
  - A non-covering prefix test never runs mutated code, so the state it leaves is the baseline's. But a later covering
    test may need that state.
  - So skipping it is safe only where no state carries between tests: the test codeunit has no globals, and the prefix
    writes no app SingleInstance state.
- **First steps:**
  1. Split #1 into prefix tests and per-test overhead. A run that records every row's duration would do it, or a
     single-mutant probe with and without `runSelectedOnly` over covering tests only.
  2. Measure the share of the prefix time in codeunits that would qualify, by parse: test codeunits without globals,
     and the SingleInstance codeunits their tests reach.
  3. Only then design a safe rule, with a pre-commitment and a DO per-mutant equality check. An al-runner-side
     alternative, a daemon checkpoint after the prefix, would be an upstream request.
- **Re-measured by PR-436 (lethal-code, 2026-11-25; `/coord/handoff/PR-436/findings.md`). The premise above was
  wrong:** the 66% is not mostly prefix tests.
  - **Split of the 83,736 lane-s of `tests` time:**
    - covering rows: about 28,700 (34%);
    - non-covering prefix rows, at their unmutated price: about 13,000 (16%, about 13% of the mutants phase);
    - a fixed cost per entry outside every row: about 42,000 (50%, about 43% of the mutants phase), about 260-270 ms
      per entry (R1219).
  - Two estimates agree on the per-entry cost: the remainder model, and a fit over 3,655 requests (`testsMs ≈ 524 ms ×
    entries + 2.1 ms × tests`, R² 0.74). m1's single-test requests show about 200 ms each directly.
  - **What carries between tests on al-runner** (`--isolation test`, measured with an invented-AL probe on
    edge-e5176a9fd):
    - carry: codeunit globals, SingleInstance state, WorkDate;
    - do not carry: the last error, the Random sequence.
  - **The prefix by class** (13,028 lane-s):
    - provably safe, by a parse closure over test code, Microsoft's test libraries and baseline app coverage: 88
      (0.7%);
    - unknown: 3,250 (25%);
    - measured unequal by refusal cascade (each test alone vs in sequence): 8,026 (62%);
    - measured unsafe (pass/fail differences): 1,664 (13%).
  - So prefix-skip is not worth building on DO.
