**Filed 2026-10-10 by the [[R564]] build** (opus R-564 plan review r1, a minor: "`r531Call.argsOf` counts
comment nodes as arguments"). An UNDER-refusal: mutants that can hang may be deployed.

**What.** `r531Call` in `packages/builtin-tier1/src/loop-hazard.ts` takes a call's arguments as every named
child of its `argument_list`, and the parser makes a comment a named child. So `Att.SetCm(xRec /*c*/)` has
arity 2, and `r531ProcsIn` finds no 1-parameter overload. At every HOP and FILTER HOP site the callee is then
not followed: the call itself is refused (R562's "cannot be followed" rule, or the R531 consumer call), but the
callee's `SetRange`/`SetFilter` (FILTER HOP) and `Delete`/`DeleteAll` (HOP) sites are NOT refused, so a
`remove-setrange` or `void-method-call` mutant there can make the loop run for ever. Worse, when a sibling
overload of the INFLATED arity exists (here a 2-parameter `SetCm`), the HOP follows that WRONG overload instead
of none: it refuses the wrong callee's sites and still leaves the reached overload's sites deployed.

**Evidence.** `packages/builtin-tier1/tests/r564-overload-by-type.test.ts`, describe "a comment among the
arguments keeps today's behaviour": four tests pin today's outcome at the R562 recv-proc, R562 same-object,
R562 table/codeunit and R531 HOP (recv-proc and same-object) sites. Red-checked: dropping comment nodes from
`r531Call`'s arguments makes all four go red (the callees are then followed and refused). Not measured on any
corpus.

**To close.** Drop comment nodes (`comment`, `multiline_comment`) from `r531Call`'s arguments, and flip the
four pins to "the callee's sites are refused". Re-dump the corpora: the change only removes keys.

## Done (R-567, 2026-10-10, 063aebb3 + a9d04db3)

Every consumer that reads a call's or an attribute's arguments now goes through the engine's
`argumentList` (comments removed; a call, or an `argument_list` / `attribute_argument_list` node) and asks
`argumentsReadable` (no `#pragma` or preprocessor node among the arguments, and the list is as long as the
top-level comma count) before it reads by position. Plan r2 (`/coord/handoff/R-567/plan.md`, after the opus
plan review). The consumers: loop-hazard `r531Call` (HOP and FILTER HOP arity and parameter mapping, the
`.args[i]` field readers, `Copy`, `Codeunit.Run`), `directWrite`, the open-item write scan, `subscriberKey`,
the SetRange read scan and literal bounds, `attributesOf` (now skips comment and pragma siblings), engine
insert-key-assignment's `Validate` scan and trigger-skip `subscribesToTable`.

An unreadable list takes the direction that refuses MORE: candidates of any arity, R paired with every
parameter, any field (`"*"`), every argument a `Copy` alias, any TableNo codeunit for `Codeunit.Run`, the call
itself refused; `directWrite` counts a passed name as written and the open-item scan counts none as written;
an unreadable `[EventSubscriber]` is reached by every event a refused scope raises (the wildcard option, the
simpler of the review's two); an unreadable `Validate` counts as assigning the key. `subscribesToTable` needs
no rule: a pragma never reads as another table.

The four R564 pins flipped to `[true, false]` (the overload the argument type chooses). Tests:
`packages/builtin-tier1/tests/r567-comment-arguments.test.ts`, engine `tests/ast/arguments.test.ts` and
`tests/semantic/r567-argument-readers.test.ts`; 31 red checks in `/coord/handoff/R-567/redcheck.md`.

Measured (`/coord/handoff/R-567/reproduce.md`): every project with either shape (DO 1, CDO 2, DC 2,
BC.History 33, fixtures 0), master fb13b03c vs built, by key and ordinal: 0 removed, 0 added, 0 moved. No
scheme bump.
