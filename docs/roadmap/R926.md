Found by coord task R-916 (reading 140 survivors of R-913, 2026-11-11). Evidence: `/coord/handoff/R-916/` (`class-*.json`,
`cov/<app>-<test>/cov.json`). Related: [[R116]], GH-24 (`survivorReachOf`), [[R245]].

**What.** A survivor's `coverageAttribution: "exact"` is, by design (R116), a PROCEDURE-level match on the baseline: a covering test
entered the procedure. Whether it reached the mutated STATEMENT is `guardReached`, from the mutant run's own attestation
(`reachedActive`), and `survivorReachOf` turns the pair into `reached-unnoticed` / `covered-but-unreached`. Only the BC transport
reports `reachedActive`. On v3, `guardReached` is never set, so every v3 survivor with a `reachGrain` is `not-decided` (Audit File
Export 396 of 396, Data Search 483 of 483), and the report cannot tell a missed assertion from an untaken branch.

**Measured.** Two readers found survivors after an early `exit` their tests never pass. The unmutated tests, run alone with al-runner's
`--coverage-json` (`cov1.sh`), give 0 hits on those lines:
- Audit File Export `AuditFileExportMgt` lines 173, 188 and 297 (M0344, M0359, M0441): 0 hits from both covering tests. Line 286
  in the same procedure (M0430) has 3, so that one is reached.
- Data Search `DataSearchLines.page.al` lines 205, 212 and 214 (M0722, M0727, M0730): 0 hits from `TestSetupListsToSearch`.

So 6 of the 140 sampled survivors (4%) are `covered-but-unreached` on v3's own data, reported as plain survivors. The verdict
`survived` is not wrong, but the work it asks for differs: a new test case for the branch, not a stronger assertion.

**Fix direction.** v3 already runs every mutant call with `--coverage-json`. Decide `guardReached` from the mutant run's statement
hits at the mutated site (any covering test's run with a hit on the site's lines is a reach), with `reachGrain` as now, and
pre-commit the survivor-reach counts on the gates.
