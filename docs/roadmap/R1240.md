**Filed 2026-11-27 by lethal-preproc, from PR-478's library probe against bcwin** (Windows BC 28.4.53241.56646).

**What happened.**
- `ClientSession.OpenSessionAsync` stayed `Busy` for 20 s.
- It raised no `CommunicationError` or `UnhandledException` event and opened no TCP connection.
- The cause was a `FileNotFoundException` for `System.ServiceModel 4.0.0.0`, which the library swallowed. After that was
  fixed, a `TypeLoadException` (`FaultException<T>`, from a mismatched `System.ServiceModel.Primitives.dll`) was swallowed
  the same way.
- Both showed only through `AppDomain.FirstChanceException`.

**The fix that made it open.** `System.ServiceModel.Primitives` 4.10.3 (the version the library's deps.json names) supplies
the facade. The cache's own WCF files must not overwrite it. Evidence: `/coord/handoff/PR-478/libprobe/` (`result.md`,
`libprobe.csproj`). The cache gap is with kraken (q-20261127T161926-e83ceb80).

**What PR-479's driver must do.**
- Give every session open (and every page call) its own deadline, and refuse BY NAME when it passes. Never wait on the state
  alone.
- Log first-chance exceptions from the library, and name the first one in the refusal.
- Check at start that the WCF facade loads (resolve `System.ServiceModel`), so a broken install refuses before any session.
- A unit test drives the deadline with a fake session that never leaves `Busy`, and red-checks it.
