**What is open.** R1080's hint and renderer landed in PR-76 (fe099d4a): `lethal export --format mutation-elements-html` writes one
page with the report JSON inlined and `mutation-testing-elements@3.9.0`'s browser bundle loaded from jsDelivr (pinned, `integrity`
and `crossorigin`). Chromium renders it (measured 2026-11-16, `/coord/handoff/PR-76/render/`). The Azure template
(`docs/ci/azure-pipelines.yml`) publishes it with the Stryker extension's `PublishMutationReport@2`. Whether that build tab lets the
page load a script from a CDN (the tab's content policy) is not measured: the template's own comment says so, and asks users to check
it on their organisation.

**How to measure (once access exists).**
1. Keep LethAL out of the question: export the committed gift-card report locally
   (`lethal export docs/campaign/2026-08-16-gift-card/rehearsal.report.json --format mutation-elements-html --project <its project>
   --out mutation-report.html`), commit that page to a scratch repository, and run a minimal pipeline whose only step is
   `PublishMutationReport@2` with `reportPattern: mutation-report.html`.
2. Open the build's report tab in a browser with the developer tools open. Pass: the request to `cdn.jsdelivr.net` succeeds, the
   integrity check passes, no content-policy error in the console, and `<mutation-test-report-app>` shows the report's own counts
   (61 mutants: 35 killed, 15 survived, 11 no coverage; 70.00 "of covered"), as Chromium did.
3. Negative control: the same page with one character of the integrity hash changed shows nothing (so the measured render is the
   pinned bundle, not a cached or other copy).
4. Record the tab's response headers (any `Content-Security-Policy`), the console and network logs, and screenshots, under
   `/coord/handoff/<task>/azure/`.

**If the tab blocks the CDN script.** The options need a decision, since the export avoids shipping or downloading the bundle on
purpose (`2026-08-26-excluded-sites-and-report-schema-design.md`): inline the 238 KB bundle in the page (LethAL ships it), or document
the artifact as the only way to view the report on Azure (download, open locally). Either way, the template's comment and
`lethal export --help` then say what the measurement showed.

**To close.** A measured Azure DevOps run of the tab (pass or fail, with the evidence above), and `--help` and the template's comment
updated to match.
