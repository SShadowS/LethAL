**Priority.** Filed 2026-10-08 by the R517 build, from the R-517 measurements (finding 6) and the
adversarial review of its plan. A LOST kill on every al-runner one-shot hang, never a false one
(verified by the review). It also masks [[R516]]'s one-shot confirm live, and with it the one-shot
half of [[R517]]'s fix.

**What.** On al-runner `2.12.0-main.43f76177` a one-shot run whose test times out exits **3**. Its
JSON still carries the row (`status: "error"`, `Test exceeded 20s timeout.`) plus
`suiteErrors: ["tests: TEST-TIMEOUT-ABORT: ..."]` and `exitCode: 3`. `OneShotTransport.send` reads
only exit 0 and 1 as test results; every other code is `kind: "error"`. So the verdict is `error`
with `operation: "pre-dispatch-rejected"`, which `runOnce` retries once: a second full hang. The
diagnosis is the "could not compile" shape, for a hang. No gate sees it: `itest:hang` is
bcdev-only and no `itest:alrunner` leg has a timeout. When this started is not known (the source
clone is shallow).

**Evidence.** `/coord/handoff/R-517/measure.md` rows d2 (`bun probe.ts backend oneshot 40000`:
`error`, 42152 ms) and d3 (`AL_RUNNER_TEST_TIMEOUT_SEC=20 al-runner --output-json --isolation test
--test Codeunit79620.LongSpin app tests`: the row says `Test exceeded 20s timeout.`, process exit
3). The probe is `scripts/r517-probe/`. The decode is `OneShotTransport.send` in
`packages/runner/src/al-runner-transport.ts`.

**Proposed close.** Accept exit 3 as test results ONLY when every entry of `suiteErrors` is a
`TEST-TIMEOUT-ABORT`; any other suite error keeps today's `error`. Then the row decodes through
`verdictFromRunnerTest` as a `timeout` with its `reportedStopMs`, and R516's and R517's one-shot
confirm runs. Offline tests for both directions (timeout-only exit 3 read as results; exit 3 with
another suite error still refused).

**To close.** The fix above, red-checked per direction, and a live one-shot hang leg: no fixture or
gate has one today (`itest:alrunner` has no timeout). Which fixture carries it is open.
