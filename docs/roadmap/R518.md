**Priority.** Filed 2026-10-08 by the R517 build, from the R-517 measurements (finding 6) and the
adversarial review of its plan. Diagnosis corrected by the R518 plan's review (I1): the impact was
a SESSION ABORT at the first genuine hang on al-runner one-shot, not one lost kill. Never a false
kill. It also masked [[R516]]'s one-shot confirm live, and with it the one-shot half of [[R517]]'s
fix.

**What.** On al-runner `2.12.0-main.43f76177` a one-shot run whose test times out exits **3**. Its
JSON still carries the row (`status: "error"`, `Test exceeded 20s timeout.`) plus
`suiteErrors: [{ errors: ["tests: TEST-TIMEOUT-ABORT: ... watchdog timeout aborted the run ..."] }]`
and `exitCode: 3`. `OneShotTransport.send` read only exit 0 and 1 as test results, so the verdict
was `error` with `operation: "pre-dispatch-rejected"`, which `runOnce` re-sends once: a second full
hang. The retry errored too; `classifyNonVerdictStep` treats an `error` back from `runOnce` as a
transport failure, and `runMutantsOnBackend` threw `backend transport error: two consecutive run()
failures for mutant <id> (test <m>) — aborting session per spec §11`. So the FIRST genuine one-shot
hang ended the session with no verdict for it or any later mutant. No gate saw it: `itest:hang` is
bcdev-only and no `itest:alrunner` leg has a timeout.

**Evidence.** `/coord/handoff/R-518/measure.md` (runs 1 to 4, read with the al-runner source at
43f7617) and `/coord/handoff/R-517/measure.md` rows d2 and d3. The decode is `OneShotTransport.send`
and `timeoutAbortTests` in `packages/runner/src/al-runner-transport.ts`.

**Fix (cef943c2).** `timeoutAbortTests(stdout)` reads an exit 3 as results ONLY when the envelope
proves a test timeout: no `compilationErrors` / `executionErrors` (null counts as absent), an
envelope `exitCode` of 3 when present, a non-empty list of string suite errors whose every marker
(al-runner's `MarkerOf`) is exactly `TEST-TIMEOUT-ABORT`, and every one naming a row that did not
pass or fail. Anything else stays `kind: "error"`. The row then decodes through
`verdictFromRunnerTest` exactly as on exit 1, so a hang is `timeout` and goes through the unmutated
confirm. R123's contract probe gains `timeout-exit-readable`, measured on its own hang run every
session; a divergence refuses the session, and `itest:alrunner` asserts the fact matched on every
pinned one-shot leg. Offline tests, each red-checked (`/coord/handoff/R-518/redchecks.md`): the
transport's accept and refusals, the session-level genuine hang (`timeout-killed` via one confirm)
and 15-of-20 s case (`timeout-unconfirmed`) in `packages/runner/tests/r518-oneshot-timeout.test.ts`.

**Not fixed here.** An unclassified `error` row on exit 3 (an `OnRun`-trigger hang, a
`RunnerOutOfScopeException`) is still retried and still aborts the session: [[R534]].

**To close.** Pre-commitment `docs/superpowers/specs/2026-10-08-r518-alrunner-precommitment.md`:
Part A, `itest:alrunner` unchanged per mutant with `timeout-exit-readable=matches` on every leg
that runs the probe; Part B, one evidence run of `scripts/r518-probe/run.ts` with its five hang
rows as pre-committed. Then `done (<commit>)`.
