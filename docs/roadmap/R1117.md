Found by coord PR-67 (lethal-code, 2026-11-17), the DO pilot; friction log item 1 (`/coord/handoff/PR-67/friction.md`).

**What happened.** On a fresh copy of a real app (no `.alpackages` yet), `lethal init --project` warns that a clash of its picked
selector ids with "Continia Core" and 5 more dependency apps' codeunits (alc AL0264) is "NOT ruled out". [[R888]] made the
check walk the dependency closure. But when the packages are absent, the message does not say what would let it check: which
field or flag points at the packages, or that re-running init after a symbol download does it.

**Possible fix.** Name the fix in the warning: "populate `<project>/.alpackages` (or set `bcdev.packageCachePath`) and run
`lethal init --project <dir>` again; with the packages present the ids are checked against every dependency's codeunits".
Add a test for the wording.
