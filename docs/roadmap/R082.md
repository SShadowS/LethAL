**`SwapCallArguments` — swap two same-typed arguments at a call site.** What is left of `EventPublisherSignature` once R13 measured that the operator as sketched cannot be emitted: a publisher's signature is declarative and the only emittable form (a duplicate publisher) is equivalent by construction because subscribers bind to the original, while the OBSERVABLE effect — a callee receiving `(B, A)` instead of `(A, B)` — sits at the raise site, in ordinary executable position the existing guard already reaches. It is filed as its own item because it is **not event-specific**: restricting an argument swap to event raises is arbitrary, and the general operator applies to every call in the language. Measured footprint so far is the event-scoped slice only, and both figures are GENEROUS upper bounds (publisher map keyed on bare name, subscriber match ignores the publishing object): 140 event publishers on `do-rel2/Cloud`, 40 with two parameters of one type, **44** raise sites reaching such a publisher, **21** whose event name is subscribed anywhere in the checkout. The general footprint — any call with two same-typed arguments — is UNMEASURED and needs `buildTypeTable`, not a name census. Two things to settle before writing code: the kill signal (a swap is only observable if the callee distinguishes the two arguments, which for two Booleans it often does not — this is `swap-modify-flag`'s equivalence problem at a larger site count), and whether a same-typed swap can be proven type-safe from source alone. Evidence: `docs/superpowers/specs/2026-08-02-r13-tier3-decision.md` §1, §3. **COUNTING RULE PRE-COMMITTED 2026-08-03, BEFORE any general count was taken** (R13's discipline at `349901a`, which is what makes a refusal a measurement rather than a rationalisation): (1) **Unit** — one mutant per CALL SITE (`call_expression` carrying an `argument_list`), as every shipped operator emits; a call with three same-typed arguments still counts **1**. (2) **A site qualifies iff** it has >=2 arguments AND >=2 of them resolve to the SAME non-null type through the real `buildTypeTable` over the whole project (not a name census) AND those two arguments differ in whitespace-normalised source text (a swap of textually identical arguments is a no-op, equivalent by construction, and must never be counted) AND `isMutableSite` holds, since the guard chain wraps the enclosing STATEMENT and a call in a page property has none. (3) **Denominator** 19,132 — R13's shipped-mutant count on `do-rel2/Cloud` — so the result lands on the same axis as bar (a)'s **>=13** and bar (b)'s 957. (4) **Bar (a) applies, at >=13 MARGINAL mutants**, and marginal here is expected to equal gross: dedup identity is `kind:start:end:after.text` (`packages/schemata/src/dedup.ts`'s `identityOf`) and `emitDispatch` chains multiple mutants per component, so a swap's replacement text is never byte-identical to `void-method-call`'s empty deletion at the same call — unlike `IsolationLevelSwap`, whose 25-of-36 overlap was a genuine identity collision. The overlap is reported anyway rather than assumed away. (5) **Reported, not hidden:** the share of >=2-argument sites where fewer than two arguments type at all, because that bounds the count from BELOW and states how much of the corpus the type table cannot see; and the Boolean/Boolean share, which is the slice carrying `swap-modify-flag`'s equivalence problem. (6) **Type-safety split** — same declared type on both arguments makes the swap type-safe *by the arguments*, but a callee `var` parameter is decided by the CALLEE, so the census reports separately the slice where both arguments are plain variable references (safe whatever the callee's var-ness) and the slice where at least one is a literal or expression (a `var` parameter there is a compile error the operator would have to avoid). Excluded from every count: `.dependencies/` files and files whose basename starts with `Mutation`. **MEASURED 2026-08-03 — the footprint question is SETTLED, R82 is NOT refusable on cost, and killability is now the only gate left.** `scripts/census-swap-call-arguments.ts` over `do-rel2/Cloud` (417 files): 9,798 calls carry an argument, 4,573 carry two or more, **893** qualify under the pre-committed rule = **4.67%** of 19,132, and **zero** are dropped as non-executable — unlike `NegateConditional`, whose 154 page-property sites R40 had to refuse, every argument-swap site is already executable. Full numbers and bounds: `docs/measurements/README.md` §R82. **Three findings the count alone would have hidden.** (1) **893 is the LOOSE number and 135 of it would not compile.** `buildTypeTable`'s `extractType` keeps the first whitespace-delimited token, so `Record "Sales Header"` and `Record "Purchase Header"` both answer `Record`; re-checking each pair against its FULL declared type leaves **340** genuinely same-typed, 135 same-head-different-type (118 `Record`, 9 `Codeunit`, 4 `List`, 2 `Option`, 2 `Enum`), 418 with a literal or expression member. Filed as **R84** — nothing shipped reads the type table today, so it is this operator's precondition rather than a live defect. (2) **Type safety IS provable from source alone, for those 340, with no callee resolution** — the proof is about the arguments, not the callee: if the call compiles, A fits parameter *i* and B fits *j*, so equal declared types make the swap fit both ways. The single hazard the arguments cannot settle is a callee `var` parameter (AL matches those by exact type and refuses a non-lvalue), and it vanishes when both members are bare variables, which is exactly the 340. That is **26x bar (a)**, so the cost bar cannot refuse this operator. (3) **Boolean/Boolean is a minority, measured: 40 of 340 (11.76%).** The fear that an argument swap is mostly `swap-modify-flag`'s equivalence problem at a larger site count is false on this project. **What is still NOT measured, and it is the whole remaining question: whether a swapped call ever changes a verdict.** No current fixture can answer it — `fixtures/sandbox-data` has 3 loose sites and **0** provable ones, `fixtures/sandbox-app` none — so a live kill measurement needs a new fixture site, the way R30, R70 and R78 each grew the table fixture. Also unmeasured: the true footprint is LARGER by an unknown amount, since 2,689 of the 4,573 two-argument sites (58.80%) have fewer than two arguments `buildTypeTable` can type at all. **SHIPPED AND MEASURED LIVE 2026-08-03 (`f9e055c`): 30 of 30 pre-committed per-mutant predictions matched, exactly.** The operator is `lethal.swap-call-arguments`, **tier 1** (design.md §4's generic set — an argument swap knows nothing about AL), and it is `ctx.types`'s FIRST consumer in the shipped pipeline, which is why R84 was its precondition rather than a nicety. Predicate: two bare identifiers of one FULL declared type, differing text. Bare identifiers are the `var`-parameter guard — AL matches those by exact type and refuses a non-lvalue, and the callee is never resolved — and arm A proves against a real compiler that the argument holds. `itest:tables` moved 84/12/10 over 106 to **109/17/10 over 136** (148 raw), `untargetedTriggerCount` 0, twice. Six arms, all as predicted: **A** kill via redirected `var` writeback; **B** kill in EXPRESSION position (the shape 452 of 893 real sites have); **C** an EQUIVALENT survivor (`or` is commutative — no assertion can ever kill it); **D** an UNDERTESTED survivor, deliberately readable apart from C; **E** a FALSE KILL, killed by a platform length overflow under a test that asserts NOTHING; **F** the R84 refusal, no swap mutant emitted. Four sites carry BOTH a swap and a `void-method-call` mutant and both scored, so **"marginal == gross" is now measured** rather than argued. Evidence: `docs/measurements/README.md` §"R82 live". **What is NOT established, and it is the whole remaining question: the RATE at which a real suite notices a real swap — filed as R85 with its own pre-committed bar.** Arm E also found a gap it was not aimed at: **none of the 109 kills records WHY it died** (`failure_note` is NULL for every one), so a platform-artifact kill is indistinguishable from an assertion kill in the stored record — filed as **R86**, and it is R85's precondition.

**Closed 2026-08-08 with R85's measurement.** R82's own text says the rate "is the only R82 question
left". It is answered: `docs/campaign/2026-08-08-r85-swap-population/rung2.result.md`, 523 swap
mutants deployed on Continia Document Output, 177 scored, first-party rate 40.9% raw and 37.0%
false-kill-adjusted.

**What that settles for this operator.** The swap population on a real 554-file app is 523 deployed
mutants, two thirds of which no test covers, and of the third that is covered the suite kills about
four in ten. Arm E was not a fixture artefact: 6 of 63 kills are the same length-constraint shape,
9.5% of kills against R82/R85's 5.2%-of-sites prediction.

**What it deliberately does not settle: whether the operator should be on by default.** The
pre-committed bar puts that decision at the 40% line and the 95% interval covers both sides of it.
A second project would narrow it; nothing else would. Recorded here so the closure of this row is
not read as a shipping decision.
