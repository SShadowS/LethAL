**Filed 2026-10-09 by the [[R531]] build** (plan r3, ruling 3, `/coord/reviews/R-531-plan/plan.r3.md`; the
loops were read in `/coord/handoff/R-531/measure.md`, Addendum 2, section 1). Linked to [[R521]], whose area
(RecordRef, FieldRef and Variant receivers) this is.

**What.** R531 refuses mutants that can hang a loop whose cursor condition ends only because its body consumes
the record set. It compares receivers by NAME. Three loops in BC.History's `Application Test Library` refilter
through a FieldRef taken from a RecordRef: `LibraryUtility` `GenerateRandomCode`, `GenerateRandomCodeWithLength`
and `GenerateRandomCode20` (`FieldRef := RecRef.Field(N)`, then `FieldRef.SetRange(<a new random code>)`, then
`until RecRef.IsEmpty()`). The consumer is on `FieldRef`, not on the loop's receiver `RecRef`, so R531 finds no
consumer and refuses nothing there. Removing the `SetRange` (`void-method-call`) leaves the set unfiltered, and
the loop runs for ever on any table that has a row. R531's alias scan does not help: the right side of
`FieldRef := RecRef.Field(N)` is a call, not a name.

**How far the hole reaches.** `LibraryUtility` is a TEST LIBRARY. LethAL mutates a project's own source only, so
these loops are mutated only when that library is itself the run's `--project` (BC.History's `Application Test
Library`), never when a project merely depends on it. Of the 13 cursor loops with no consumer that R531 read across
BC.History, CDO, DC and DO, these three are the only ones of this shape. So the hole is real but narrow, and it
claims no more than that.

**To close.** Treat a `FieldRef` obtained from R (`X := R.Field(N)`, `R.FieldIndex(N)`) as R for the consumer
scan, so `X.SetRange`/`X.SetFilter` count as a refilter of R. That is RecordRef/FieldRef resolution, which is
R521's area, so it is filed here rather than folded into R531. Measure the cost on `Application Test Library`.
