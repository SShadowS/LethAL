**Found by** PR-432's measurement (lethal-code, 2026-11-25). Evidence: `/coord/handoff/PR-432/findings.md`, R1206.

- **What R949 assumes:** a serve daemon cannot report `flagged` (upstream #7954), so every daemon baseline row is
  marked `flaggedUnknown` (`al-runner-v3-backend.ts`, both daemon baseline paths). `flaggedUnknown` survives on every
  row that is not `flagged: true`.
- **What was measured:** `current` (edge-e5176a9fd) and main-bf3a3e863 both write `flagged: true` on serve rows (PR-422's
  c5: 1,735 flagged passes and 129 PR-410 skips; c4's walks failed on "passed but al-runner flagged"). So #7954's
  premise no longer holds on either build.
- **What it can cost:** an over-refusal, never a false kill. On these builds an unflagged daemon pass is reported
  `baselineFlaggedUnknown` and refused by B1, although the build may have reported it sound. c5 shows no case, since
  all of its passes were flagged.
- **To measure before any fix:** does the daemon write an explicit `flagged: false` on an unflagged pass, or only omit
  the field? `serveRow` keeps only `flagged: true`, so today the two cannot be told apart. If it is explicit, the decoder
  can keep it and R949's marking can apply only to rows without the field. If it only omits, a per-build fact (a pin
  field like R782's `serveRowFields`, or a leg-C fact) is needed.
- **Related:** R949, R1206, R782, PR-432, upstream #7954.
