**Found 2026-10-06 in the post-merge gpt-6.1-sol review of R-488** (`/coord/reviews/R-488/sol-postmerge.md`).

**What.**
1. **Duplicate rows are credited (important).** In `AlRunnerBackend.run`, a one-shot result with two rows that both
   carry the requested name (one pass, one fail) has no extras. `.find()` then credits the first row and that call's
   coverage. A duplicate qualified name should be refused by name. Not measured on the real binary: a static
   counterexample.
2. **The fake accepts excluding the requested test.** `substringRunner` in `al-runner-backend.test.ts` returns a
   wanted-only pass for ANY `--exclude-test`, so a bug that excluded the requested test itself would stay green. The real
   al-runner returns no tests then. The fake must return an empty list when the requested name is excluded.
3. **Merged coverage is untested.** Every R488 test runs with coverage off. A bug that reads the FIRST (merged) call's
   `coverageOut` and the re-run's row would stay green. Add a test with coverage on, where the two calls'
   coverage differs.
4. **The wiring test is weak (minor).** The orchestrator test does not show that the seed is `discovery.unfiltered`
   rather than the filtered list, nor that seeding happens before the first `run()`. Add a compiled-out twin and an
   order assertion.

**To close.** Refuse duplicates by name, fix the three tests, and red-check each one.
