**Filed 2026-10-23 by coord task R-686** (lethal-code), the orchestrator's ruling on R-686's plan review. Never a
false kill: a whole session lost to one mutant.

**What.** LethAL Control activates the mutant BEFORE suite discovery (`TryBeginRun` writes it, then
`SelectTestMethodsByRange` runs each test codeunit's `OnRun`). A mutant in code a test codeunit's `OnRun` calls can
make discovery list no methods for that codeunit, under that mutant only. Today (since [[R686]]) the session stops
with `MutantBrokeTestDiscoveryError`, which names the mutant, its file and the codeunit and says how to go on. Before
R686 it stopped as "two consecutive run() failures". Either way no report is written. `--resume` does not get past
it: it carries killed, survived, timeout-killed, no-coverage and known-survivor verdicts, but re-runs an `error`,
so it reaches the same mutant and stops again. There is no per-mutant exclusion (`--exclude` drops a whole file).

**Design (from R-686's plan review, `/coord/handoff/R-686/review-plan.md` F3-F6, F10).**
- A mandatory unmutated confirm: after a found-0 under the mutant, run the same test with no mutant active (as the
  kill confirm does). Only a `pass` scores the mutant `error`, new cause `test-discovery-failed`. Anything else keeps
  the abort. A test-app identity re-read is NOT a guard: it cannot see an uninstalled-but-published app or earlier
  committed data that breaks the OnRun, and `error` leaves the score's denominator.
- The found-0 codeunit is a non-run, not the end of the mutant's covering loop: the other covering tests still run,
  so a kill elsewhere stands. On the grouped path `ResolvePairs` refuses the whole chunk; re-send it without that
  codeunit (or fall back to single calls), so chunked and unchunked agree (`itest:chunked`'s rule).
- Read `identityMismatch` before the line-count and `suite-unresolved` branches in `run-mutant-transport.ts`.
- R686's message branch fires only for the mutated covering call (`transportErrorUnderMutant`); a found-0 on the
  grouped warm replay (`confirmWarm`, no mutant active) keeps the plain transport abort. No test reaches that replay
  case yet; this item's tests should.
- The new cause ripples: `MutantErrorCause`, `ERROR_CAUSE_INTERPRETATIONS`, `EXPLAIN_SCHEMA_VERSION` bump, schemas,
  the banner, `docs/using-lethal-from-an-agent.md`, CHANGELOG.

**Evidence.** `/coord/handoff/R-686/mid-run-trace.md` (the code trace of both transports), `review-plan.md`.
Unmeasured on BC: whether discovery under such a mutant lists 0 methods or raises (the grouped path then answers

**Done (coord task R-688, lethal-code): such a mutant is scored per mutant, and the session goes on.** Plans
`/coord/handoff/R-688/plan.r1.md` and `plan.r2.md` (after the Opus plan review, `review-plan.md`).
- **The confirm.** When a single run under the mutant answers the RunMutant found-0 form, `confirmFoundNone`
  (beside `reproduceKill`) runs the same test once with no mutant active, at the budget the mutated run was sent.
  Its row is unmutated and its time is not the mutant's. A reused session is `session-reused`. A `pass` confirms.
  Found 0 again, a failure or a timeout means the test app, the server or committed data changed: the mutant is
  recorded and flushed, then the session stops with a message that says so. Any other ending keeps its own cause
  (a lease loss latches, a strand quarantines); a transport error keeps today's abort.
- **After a confirmed found-0** the codeunit is skipped for this mutant only, the mutant is activated again, and the
  covering loop goes on. A kill by another test stands, and its note names the skipped codeunit. If nothing kills,
  the mutant is `error` with the new cause `test-discovery-failed`, unless a test outside the skipped codeunit was
  never attempted, which stays R198's `group-coverage-incomplete`.
- **Grouped calls.** `coveringRuns` drops a skipped codeunit's tests before it builds a chunk. A chunk BC refuses with
  `suite-unresolved ... found 0` is recorded, then run one method at a time, so every found-0 handled comes from a
  one-codeunit discovery and grouped, chunked and sequential runs agree. A found-0 on a group call's own answer, or
  on the warm replay, keeps today's abort.
- **Transport.** `identityMismatch` is read before the line count (`mapRanResult`) and inside the `suite-unresolved`
  branch (`scoreManyAnswer`), so a wrong binary is never taken for a blank discovery.
- **Removed:** `MutantBrokeTestDiscoveryError`, R686's end-of-loop branch and its `transportErrorUnderMutant` flag.
- **The cause's ripple:** `MutantErrorCause`, its interpretation, the banner's breakdown, `EXPLAIN_SCHEMA_VERSION` 20
  (`schemas/explain-v20.schema.json`; v19 frozen), the generated report and stream schemas, the report-equality
  snapshot, `docs/using-lethal-from-an-agent.md` and the CHANGELOG.
- **Known limit, unchanged:** a discovery that RAISES rather than lists nothing aborts on the single path and is
  `group-run-error` on the grouped path. Unmeasured on BC ([[R689]]).
