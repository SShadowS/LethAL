**Upstream PR #5715 read against LethAL (lethal-code, 2026-10-22, read-only).** It merged on upstream main c2031b99f
and closes #5702, #5703, #5704 and #5698. It is not yet in a published build; edge is still 57f1e4f98. Findings, all
MEASURED from the code on master 13464684:
1. **LethAL never sends `test` as a list.** Every entries request goes through `encodeGroups`, which sets
   `test: "Codeunit<cu>."`; `assertEntriesWellFormed` throws on anything that is not a string. The coverage window
   and its echo also send a string.
2. **No duplicate entry ids within one request.** Ids are `<mutantId>|echo` or `<mutantId>|<cu>`, and
   `assertEntriesWellFormed` throws on a duplicate. The R653 pair `[NONE, M]` carries four distinct ids. Ids repeat
   only across requests. Upstream's check that an explicit id must not equal another entry's index cannot fire,
   because our ids contain `|`.
3. **The new exit code 6 changes nothing for us.** The new per-entry `exitCode` 6 with a warning, and a
   request-level exit code 6 when any entry matches nothing, are both ignored on the entries path: `send()` and
   `plain()` never read `summary.exitCode`, and `decodeEntriesAnswer` compares counts only. An entry that matches
   nothing still decodes as today: `suiteMissing` then `rowMissing` for a scored entry, and "has 0 rows" in
   `echoMismatch` for an echo. No request is newly refused, quarantined or mis-scored. The one-shot path's exit 6
   → `AlRunnerV3SelectionError` is unaffected, because upstream's `empty_entries` check applies only to requests
   with entries.
4. **The new OnRun time limit touches no gate leg.** No test codeunit in S1, S3, N1, T or X has an `OnRun`.
   sandbox-data's `DataCommitTarget` (79313) is a target run by `Codeunit.Run`. In CDO, `CDO Orphan Cleanup Tests`
   (68871) has a trivial OnRun, and 68999 is a `TestRunner`. Leg C's `Serve OnRun` (50673) overflows at once, and
   its `onrun-failed` text is unchanged.
