[[R942]] amendment 7), after [[R1000]]'s fix. Related: [[R786]], [[R612]], [[R960]], [[R982]], [[R945]].

**What happened.** The serve session ran its whole baseline on serve (2,224 s, 1,681/1,979 green, 8 daemons, 6 closed on a refusal:
`ZipArchive.Dispose` 3, `GoToKey` on a descending view, and others), then entered the mutant phase. There LethAL raised
`AlRunnerV3ServeFallbackWarmupError`: the warm-up request held the row
`Codeunit68922.ZipFiles_WithMultipleFiles_ShouldCreateZipArchive`, refused by name ("NotRun: out-of-scope: DotNet
System.IO.Compression.ZipArchive.Dispose: a .NET write over the bytes an AL OutStream held before the call (what the Blob then holds
is not pinned)"). By R786's rule `lethal run` dropped the serve attempt and re-ran the session one-shot: a second, one-shot baseline
(6,319 s), then about one covered mutant a minute. The window was stopped by SIGTERM (R955).

**Why it matters.** The test is one of R982's three known DO refusals: al-runner refuses it on every run, on serve and on one-shot alike.
R786 falls back so that one-shot can score such a test per test, but a refused test scores nothing on one-shot either. So for a project
whose warm-up request holds any test al-runner refuses by name, the default transport can never be serve, and the cost is a second
baseline plus a one-shot mutant phase (for DO: days instead of hours). The daemon close itself is fine (R945's keep-list closes on
this unmeasured shape, the safe direction); the whole-session fallback is what costs.

**Questions for the owner of R786 (not decided here).**
- Should a warm-up row refused by name fall back only when one-shot would score it differently (a refusal one-shot does not give),
  and otherwise close the daemon and go on, as a refusal outside the warm-up already does?
- Or should the warm-up request avoid tests the baseline already marked refused?
- Either way, a test: a warm-up holding a test refused on both transports stays on serve, and the session's verdicts equal a session
  whose warm-up held no such test.

R-984 (DO on serve) waits for this: no further DO serve window until it is decided.

**Decided (lethal-code, R786's owner, 2026-11-14): option 2.** A test the baseline did not score green decides no verdict (a mutant
runs against its green covering tests), so leaving it out of the warm-up is verdict-neutral by construction; option 1 would need a
second keep-list measured per text.

**Built (coord R-992).** `startDaemon`'s warm-up leaves out every test in `baselineRefused` (the baseline's named refusals, I3): an
isolated call whose one test was refused leaves the union, and a plain codeunit entry carries `excludeTests` for its refused tests
(`encodeGroups`' new `excluded` argument, passed through `send`); the warm-up's rows are compared with the baseline's rows WITHOUT
those tests. Only the warm-up changes: mutant entries still send the whole codeunit (R612's cut and daemon close handle a refused row
there, as before). R786 keeps its teeth for a refused row the baseline did not note, and a left-out test whose row comes back anyway
reads as `warmup-disagrees`. Tests: `al-runner-v3-entries.test.ts` "R1004: ..." (default and explicit stay on serve, the warm-up
entry names the excluded test, the mutant entries do not, a clean baseline sends none, a returning row disagrees) and the R786 tests,
now on a forgotten note; red-checked both ways (the exclusion off; the comparison without the filter).
Not changed: a GREEN test refused at the warm-up was never R786's case (the disagreement check refuses it as `warmup-disagrees`,
an existing test).
