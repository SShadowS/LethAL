**Found 2026-10-21** by the Opus review of [[R586]]'s merge of master (`/coord/handoff/R-586/review-merge-8a71e87d.md`,
F2). It predates that merge on both sides: R594 added `--held-lease` on `lethal/r586`, and R598 then replaced the
fixed-lane `krakenLease`.

**What.** `heldLeaseDeps` in `scripts/bc-linux-setup.ts` (R594) gives `withLease` a lease the CALLER already
holds: it must heartbeat that token, never take a new lease and never release one. Since the R598 merge its
heartbeat calls `kraken` directly, so no test can see what it does. Untested today:
- that `take` returns the given token without asking coord for a lease;
- that `release` does nothing;
- that `parseArgs` refuses `--server all --held-lease <token>` (one token leases one server).

**Effect.** A regression that released the caller's lease, or took a second one, would pass every test. The
caller's other work would then run unleased on a shared bc server.

**To close.** Inject the kraken-call seam into `heldLeaseDeps` (a `run` parameter defaulting to `kraken`, as
R598's `krakenLeaseFor(lane, run)` does). Unit-test it with a recording fake: `take` makes no call, `heartbeat`
sends exactly `["heartbeat", server, token]`, `release` makes no call. Unit-test `parseArgs` refusing
`--server all --held-lease t`, and accepting `--server bc3 --held-lease t`. Red-check each.
