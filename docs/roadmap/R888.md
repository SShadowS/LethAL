Found by coord R-883, which instrumented and compiled BC.History offline with alc. Related: [[R169]], [[R170]].

**What.** `pickSelectorIds` (which `lethal init` uses) and `validateSelectorIds` check the three injected codeunit ids (Mutation Selector, Register and Upgrade) against the codeunits the PROJECT declares (`scanProjectCodeunitIds`). An id that a DEPENDENCY already uses passes both checks. alc then rejects the instrumented app with AL0264: "An application object of type 'Codeunit' with ID 'N' is already declared by the extension 'X'".

**Repro** (invented). Take an app whose `idRanges` overlap a dependency's object ids, where the dependency declares codeunit 50199. The app's own top free ids are 50199, 50198 and 50197, so `pickSelectorIds` picks 50199, and alc gives AL0264.

**Measured.** 25 AL0264 errors in 14 BC.History apps: 17 clash with Base Application's codeunits and 8 with System Application's. All are Microsoft apps, whose id ranges overlap the base apps'. A partner app with its own range does not hit this. A suite of apps sharing one range can, when one app depends on another.

**To close.** Check the three ids against the dependencies' declared codeunits too: their symbol packages are already read for compiles. Refuse by name with the clashing extension, and have `pickSelectorIds` skip those ids. Test with a dependency that declares one of the top ids.

**Done.** `dependencyCodeunitsOf` (`packages/runner/src/dependency-codeunits.ts`) walks the dependency closure alc compiles against: app.json's dependencies, the `Application` meta app when app.json names an `application` (it reaches Base Application, System Application and Business Foundation), and each package's own manifest dependencies. It reads the packages through `packageFolderReader` and `declaredObjectsOfPackage`, the readers the compile and the object-clash check already use. The platform package `System` is not read. `pickSelectorIds` skips those ids; `validateSelectorIds` throws `SelectorIdDependencyClashError` naming the id, which of the three it is, and the dependency's name, publisher and version. A package that is missing or unreadable does not stop the run (the symbols may be downloaded later, and alc still rejects a clash): `lethal init` and `lethal run` print a warning naming each such dependency and saying a clash is NOT ruled out. No fixture or example id changed (checked against all 33 projects' packages).
