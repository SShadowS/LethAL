808d5f69). Related: [[R956]], [[R912]].

**What happened.** Window 1 ran `lethal run --backend al-runner-v3 --time-budget 14400` (4 h) under `timeout 18000` (5 h). It entered
the baseline (1,979 tests, batch 0) at 16:53 and was still in it at 21:32, 4 h 40 min later, with 0 of 43,583 mutants decided. The
budget never fired: it is checked between mutant groups, not during the baseline. Only the outer `timeout` would have stopped the run,
and a run killed there writes no `--out` report and no `run-finished` event, so the four-plus hours leave no record of how far the
baseline got. The lane stopped it by hand (SIGTERM, rc 143): no report either. Evidence `/coord/handoff/R-942/do.w1.*`.

**Why it matters.** `--time-budget` is the one knob a user has to bound a run's wall time; a large test app silently exceeds it by
hours, and the time is lost without a report. The windowed pattern (budget, then `--resume`) cannot continue a run that never
finished its baseline.

**Wanted.** The budget bounds the baseline too: when it runs out mid-baseline, the run stops scheduling baseline calls, writes its
report with a caveat that names where it stopped (tests run / total), and exits like `time-budget-reached`; and a SIGTERM during the
baseline also ends with a report. Whether a partly-run baseline can be resumed is a separate question (today nothing of it is stored).

**Done (coord R-944).** The budget is checked before each baseline call and each auto re-baseline call; when it is spent the batch
ends `budget-in-baseline`, nothing of it is scored, and the report's `timeBudget.baselineStopped {testsRun, testsTotal}` (with
`inAutoRebaseline` when it stopped there) and banner say where; exit 7 through the existing `time-budget-reached` caveat. SIGTERM and
SIGINT spend the same `TimeBudget` (one-shot handler; a second signal kills at once), so a stopped run writes its report with
`stoppedBySignal`. A baseline call the signal killed is dropped, not kept as a red test, so no snapshot or isolation choice is stored
from it; an alc killed by a signal is `ArtifactPrepareError`, never "does not compile", and bisection stops on a spent budget. Known
cost gap, not a verdict risk: under `--isolate-tests` a signal does not stop the parallel isolated-baseline fill ([[R958]]).
