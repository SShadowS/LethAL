**Found by the R-420 lane (lethal-preproc), 2026-10-04,** while measuring the `[Test]` shapes the discovery regex misses. Plan: `docs/superpowers/plans/2026-10-04-R-420-split-test-attributes.md` (r2, §8).

**The shape** (S10 in R-420's measurements):

```al
[Test]
#if X
procedure T10a()
#else
procedure T10b()
#endif
begin
end;
```

alc 18.0.41.45789 accepts it. The compiled test app contains `T10a` under `[X]` and `T10b` under `[]`, measured from the package's `SymbolReference.json`. tree-sitter-al 4.4.1 parses it as one `preproc_split_procedure` node, which holds one name per arm and the shared body. No ERROR node.

**Why R-420 did not take it.** Discovery could read it, but two other readers cannot. The TestPage-scan model keeps only `procedure` nodes (`testpage-scan.ts` ≈:602-616), so `analyzeTestPageModel` would fail and refuse the whole run. The test digest's `walkTest` (`test-digest.ts` ≈:185) would throw `TestDigestError`, and the orchestrator would then drop every test's digest. A project that runs today would stop.

**What R-420 does instead.**
- The test is still not discovered, as before, but no longer silently: discovery emits a `test-shape-unsupported` warning naming the file and both arm names.
- Its `[Test]` token counts as accounted for in R79's guard.
- On bcdev, R-403's compiled-membership check names it `published-only`, and the message carries R-420's added cause, "LethAL did not recognise a test declaration in the source".

**To close.**
- Teach the TestPage-scan and digest models a split member: one declaration per arm, sharing the body span.
- Then let discovery emit one candidate per arm. A candidate is filtered by the arm its NAME starts in.
- Pin it with the measured shape under `[]` and `[X]`.
