Filed by coord PR-48 (2026-11-16) from its Opus build review. None of these occurred in PR-48's corpus or DO measurement. Probe
shapes (invented) are in the review's scratch copy. Related: [[R1050]], [[R1053]], [[R1061]].

**Misses (a hang shape that is still mutated).**
- R1050, on master too: inside a progress procedure, a local copy that feeds the exit name is not followed:
  `Next := Pos; Skip(T, Next); Pos := Next`. Emptying `Skip` freezes `Pos`.
- Rule B: `until Y = X` with an up-counter Y. A bound read through a second variable (`Limit := X; ... until N < Limit`). A write
  to X later in the same outer `foreach` stops the search, though the first pass still hangs.

**Over-refusals (a site refused that cannot hang).**
- Rule B: an earlier non-default write of X (`X := 5; X := 1000; repeat ... until N < X`). Removing the second assignment leaves 5,
  not the default. The same holds for a global set by an earlier call.
- Rule B: the up-counter's start is not checked. A parameter or global counter may start below 0, and then `Y < 0` ends the loop.

**PR-50 (2026-11-16, 8bbd371b) closed most of the above** (`docs/superpowers/specs/2026-11-16-pr50-remaining-hang-shapes.md`;
measured at 0 moved sites):
- the local copy, followed when it is copied back into the exit name;
- `until Y = X`, a bound read through a second variable, and the search past a later `foreach` write;
- the earlier write, given back only when the loop provably ends at that value (so `X := 5; ... until N < X` stays refused);
- the counter start, given back for a global counter only.

**Still open after PR-50:**
- A progress call to ANOTHER object with a `var` parameter in an assignment (`X := Helper.Adv(Pos)`), and built-ins that write
  their arguments (`Ok := Evaluate(Pos, T)`, `Steps := Rec.Next()`). R1052's H covers only same-object callees: the wider form
  cost 6 scored sites and caught no hang.
- The Filter Tokens give-back below.
- PR-53's rule A assignment variant (`X := ''` under an exit that needs X blank) judges the NEAREST while/repeat loop only, so
  `while Rest <> '' do while P < 3 do begin Rest := ''; ... end` (only the outer exit reads X) is a missed hang. It is also a
  shared base name over-refusal (`Rec."Name 2" := ''` under `while Rec.Name <> ''`), the same weakness as PR-44's path. Neither
  occurred in PR-53's measurement.

**Also not followed (safe direction).** Filter Tokens' `ResolveDateTimeFilter`, `ResolveDateFilter` and `ResolveTimeFilter` stay
refused by R1050. They cannot hang, because `FilterText := Tail` overwrites the value before the exit reads it again. Giving them
back needs an "overwritten before the next exit read" check.
