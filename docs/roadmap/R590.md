**Filed 2026-10-21 by coord task R-583** (lethal-code), from build review r2, follow-up 4
(`/coord/reviews/R-583-build/review-r2.md`).

**What.** al-runner can drop objects from a DEPENDENCY it cannot compile. The case measured on 069cbf32 in
[[R583]]'s `output-shapes.md` is `Microsoft_Tests-TestLibraries ...: EMIT-EXCLUDED`, which drops 2 of 203 objects.
- R583 scores such a run and raises the warning `al-runner-dependency-emit-excluded` (one-shot only).
- Now take a dependency the TARGET uses. A mutant can send target code into a dropped object of it, where the
  unmutated code never went.
- That test then fails with al-runner's `NavNCLMissingMethodException` and is scored **killed**. BC would run the
  same code, so the kill comes from al-runner, not from the test.

**Not a baseline issue.** The unmutated run never reaches the dropped object, or the baseline would fail. In the
measured case, target code cannot call Tests-TestLibraries, so the false kill needs a dependency the target itself
uses.

**Same class as R148.** R148's "NO IMPLEMENTATION" warning reports, and does not change verdicts. So far this item
only warns too.

**To close.**
- Tag a kill whose failure message names an object that a dependency drop listed in the same session. Use
  `NavNCLMissingMethodException`, together with the dropped object's name.
- The tag should mark it as a platform kill (`PlatformKillMechanism`), not change the verdict, as R138 and R143
  did.
- On `--server` the drop list cannot be seen: it prints only on the daemon's stderr (R583). So close this for
  one-shot first, or read the daemon's stderr for the request.

**Measured 2026-10-21: no occurrence (`/coord/handoff/R590/measure.md`).** No killed row has a kill from al-runner's
missing-method or missing-object error. This covers every committed baseline and report and every recorded
`/coord` run. The only dependency drop ever recorded is `Microsoft_Tests-TestLibraries` v28.5 (2 of 203 objects,
on al-runner f06ee78c, BC 28.5). It appears only in baseline and probe runs, which score no mutants, and target
code cannot call a test library.

**Parked (orchestrator ruling, 2026-10-21): open, nothing built.** The trigger is the first recorded drop of a
dependency object that the TARGET calls. R583's one-shot warning `al-runner-dependency-emit-excluded` surfaces such a
drop.

**v2 retired (R654); re-measure on v3.** `NavNCLMissingMethodException` and the dependency drop are .NET al-runner
behaviour, and that backend was deleted in R654 S3 (35f3c67f), with the `al-runner-dependency-emit-excluded`
warning. So the trigger above can no longer fire. Whether the Rust al-runner can drop a dependency object, and what a
call into one looks like there, is not measured.

**Closed 2026-10-23 by ruling (coord task R-537, lethal-code): v3 cannot score a kill through a dropped dependency
object.** Measured offline on alpha.2 (91253f2d6) and edge (57f1e4f98) with an invented target that calls a
dependency; the evidence is in `/coord/handoff/R-537/` (`measure.md`).
- **There is no per-object drop.** By the upstream source (93415c0), v3 loads a dependency whole, or skips the whole
  app when it has no package with AL source (stderr `dependency skipped: ...`). Nothing like v2's `EMIT-EXCLUDED`.
- **A test that reaches a skipped dependency is not run.** With the dependency's package removed, both the test that
  calls into it and the one that does not (they share the routine, so both reach it statically) came back `notRun`
  (`codeunit ... is outside the workspace`), scored `error (runner-refused)`. A routine v3 cannot lower is refused the
  same way, before the test starts. With the package present, both tests run as plain AL.
- **Stored v3 reports:** 0 of 8,275 kills carry `outside the workspace` or `dependency skipped`.
