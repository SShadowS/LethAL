**Found while implementing C02-06 part a (2026-09-26), confirmed by reading.** `warnAlRunnerNotAuthoritative`
in `cli.ts` prints, on every al-runner run: "al-runner is NOT authoritative: it reports `pass` for an
`asserterror` that raised no error, so any mutant killable only by an asserterror assertion is reported as
SURVIVED". That was R7, an al-runner v1 behaviour. CLAUDE.md records that it was fixed in v2 and that
`runAlRunnerCanary` has reported it `defect-not-reproduced` since 2.0.0.0; the README, the EMEA runbook
and the agent guide were swept for the same stale claim on 2026-09-03, but this runtime string was not.

`authoritative: false` still holds, for a different reason (coverage is conditional on the project's
file layout, upstream #3713, per R220). So the warning's conclusion ("treat survivors as unconfirmed")
is still right, but the reason it gives a user is false, and a user who reads it will draw the wrong
lesson about asserterror tests.

Fix: reword the warning to the current reason (conditional coverage), and pin its text by test against
the canary's own verdict, so the next al-runner change cannot leave it stale again.
