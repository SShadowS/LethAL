**Found while implementing C02-06 part a (2026-09-26), confirmed by reading.** `warnAlRunnerNotAuthoritative`
in `cli.ts` prints, on every al-runner run: "al-runner is NOT authoritative: it reports `pass` for an
`asserterror` that raised no error, so any mutant killable only by an asserterror assertion is reported as
SURVIVED". That was R7, an al-runner v1 behaviour. CLAUDE.md records that it was fixed in v2 and that
`runAlRunnerCanary` has reported it `defect-not-reproduced` since 2.0.0.0; the README, the EMEA runbook
and the agent guide were swept for the same stale claim on 2026-09-03, but this runtime string was not.

`authoritative: false` still holds, for a different reason (coverage was conditional on the project's
file layout, upstream #3713, per R220; since R383 the multi-object half has a new cause, al-runner's
frame for later objects, and the remaining reasons are in `AlRunnerBackend.capabilities`). So the warning's conclusion ("treat survivors as unconfirmed")
is still right, but the reason it gives a user is false, and a user who reads it will draw the wrong
lesson about asserterror tests.

Fix: reword the warning to the current reason (conditional coverage), and pin its text by test against
the canary's own verdict, so the next al-runner change cannot leave it stale again.

**Closed (cba033cc, R-466).** `warnAlRunnerNotAuthoritative` now gives
`AlRunnerBackend.capabilities`' reasons: coverage that depends on the project's file layout (a file
whose later objects carry code turns it off for the whole run) and transaction semantics not
verified against BC. The `announceAlRunnerCanary` fallback test refuses `asserterror` in the
warning and requires `coverage`; it failed before the change. The canary itself was re-run the same
day on the pinned `v2.12.0-main.c39ad5de`: `asserterror`, `tableGlobalVar` and
`transactionRollback` all `defect-not-reproduced`. Pinning the text to the canary's live verdict, as
proposed above, was not built: the fallback prints only when no `alRunnerPath` is configured, so
there is no binary to measure at that point. Every run with a path prints the canary's own
measured lines instead.
