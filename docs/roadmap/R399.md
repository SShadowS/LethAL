**Found by R-307 task 8b (orchestrator ruling 2026-10-02).**

**The inconsistency.** `buildReport` in `packages/runner/src/report.ts` sets `narrowed` from
`--only`, `--exclude`, `--operator`, `--lines`, `--tests-only`, and, since R-307, from any
`excludedSites` row with reason `instrumentation-refused`. It does not look at rows with reason
`preproc-undecided` (R-214: a file whose `#if` directives LethAL cannot evaluate as `alc` does) or
at the not-instrumentable rows. Those files are also in the build, ran unmutated, and are left out
of the score. The report still says `reliability: full`, which is the over-claim that field exists
to prevent (see the R221 comment on the same condition).

The `preproc-files-refused` caveat does appear for the undecided rows, so a careful reader sees it
in `validity.caveats`. The headline field does not move.

**Recommendation.** Count `preproc-undecided` and not-instrumentable rows as narrowing, like
refused rows. Keep compiled-out rows (an `#if` arm the build's symbols remove) as NOT narrowing:
that code is not in the build, so there is nothing to measure.

**Related minor.** When every file with sites is either R-307-refused or undecided, the "nothing is
left to measure" error in `packages/runner/src/orchestrator.ts` (near line 1038) names only the
R-307 files. It should name both kinds.

**Cost of the fix.** `reliability` moves for existing projects that hold undecided `#if` files, so
it is a report-meaning change: it needs the report/explain version and snapshot ripple that
CLAUDE.md lists for report fields, and it touches R-214's contract. That is why R-307 did not do
it.

**Evidence.** `packages/runner/src/report.ts` (the `narrowed` condition), `packages/runner/src/
excluded-sites.ts` (the row reasons), `docs/superpowers/plans/2026-09-30-R-307-per-file-skip.md`,
and the test in `packages/runner/tests/excluded-sites.test.ts` that feeds both kinds through one
`buildExcludedSites` call.
