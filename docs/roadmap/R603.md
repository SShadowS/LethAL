**Filed 2026-10-21 by coord task R-588** (lethal-code), as the follow-up [[R593]] left open, on the orchestrator's
ruling.

**What.** [[R593]] made a local full `bun scripts/verify.ts` run in parallel: about 21 s instead of 67.5 s. Its
equivalence was proven per test name on Linux (`/coord/handoff/R-588/equivalence.md`). Under CI, P is forced to 1,
so both CI jobs still run serially. The Windows `check` job's unit-test step takes about 110 s of a job of about
6 min. A parallel run on Windows has never been measured. Two of R593's tests (A5, A7) skip on win32 for that reason.

**To close (a measurement item).**
1. Make one measurement push that sets `LETHAL_VERIFY_PARALLEL` on the Windows job only. CI must still go through
   `verify.ts`, never a bare `bun test --parallel`.
2. Compare the run per test name per file against a serial Windows run, with `scripts/verify-equivalence.ts`'s
   method.
3. Adopt parallel on Windows only if the names are identical and the step drops by 45 s or more (R593's plan
   threshold). Otherwise record the measurement and close with that ruling.
4. If Windows goes parallel, un-skip A5 and A7 there.
