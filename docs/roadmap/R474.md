**Found 2026-10-05 by the adversarial review of R-391's plan** (coord handoff `R-391`, plan r3/r4
reviews), pre-existing and outside R391's scope.

**What.** A mutant's identity key is its statement's subtree hash, object name, member, operator
and twin ordinal (`identityTupleOf`, `serializeKey`). Nothing in it covers the code AROUND the
statement. `--resume` (`carriedVerdictFor`) and `--skip-known-survivors` (`filterHistory`) carry a
recorded verdict onto any mutant with the same key, so after an edit that leaves the statement
itself untouched but changes its context, the old verdict carries.

**The false-kill sequence.** A statement `S` is mutated and recorded `killed` in run 1, which is
interrupted. The user inserts an `exit;` just before `S` (so `S` is now unreachable and its mutant
cannot be killed) and resumes. `S`'s subtree is unchanged, so its key is unchanged, and the
mutant carries `killed` with run 1's `killingTest` without being run. A survived verdict carries the
same way under `--skip-known-survivors` (a mutant that edited context now makes killable is skipped).

`carriedVerdictFor`'s doc comment says "a stale verdict can never attach to edited code"; that
holds for the statement's own text only.

**To close.** Since R391, a run records its generation-time source hash. A cheap tightening: when
the hash changed, carry only for files whose BYTES are unchanged (a per-file hash from the same
source snapshot), and say how many carries that refuses. Measure first how often a resume or a
history carry crosses an edited file in practice.

**Closed 2026-10-05 (52dbf33d), with a narrower cut than the per-file one.** Plan:
`docs/superpowers/plans/2026-10-05-R-474-member-hash-carry.md` (adopted on sol's r2 review);
survey: coord handoff `R-474/survey.md`.

- **What changed.** Rule 2 of `carryRecord` (rule 1 is untouched) now also requires an equal
  `memberHash`: SHA-256 of the enclosing member's RAW source (procedure-like, else trigger; `""`
  at object level) from its first attribute to its end, attribute-only `#if` wrappers and S11's
  outer run included. The span is engine's `attributeRun` (moved from runner's testpage-scan,
  whose `memberRun` keeps its own policy) through `memberSpanText`, cached per member. It is stored
  as an optional `MutantManifestEntry.memberHash` and a nullable `mutants.member_hash`, read by
  `buildResumeIndex` and `priorSurvivorKeys`. A NULL row (before R474) still carries under rule 1
  and carries nothing under rule 2; a manifest entry without the field records NULL, never an
  invented hash. `lethal verify` writes the hash through its shared `record` path. Identity keys
  are unchanged, so there is no identity-scheme bump and no baseline re-record. The manifest's
  bytes, and so its SHA-256 and the installed-payload digests, do change.
- **Measured cost.** Over 22 version pairs (six BC apps across 28.3-28.6, and CDO PRs and months),
  1,973,516 rule-2 mutant-site pairs: the member hash refuses 0.03-0.74% across one PR and
  0.24-6.6% across a release or a month, against 0.4-35% (100% on an object-id renumbering) for the
  per-file cut. These are a structural proxy, not production figures: on the six apps reconciled
  the proxy holds 0.4-3.5% extra sites, and 12 production sites (8 in Subscription Billing, 4 in
  E-Document Core) are missing from it, so production is NOT a strict subset; BaseApp was not
  reconciled. The text hash refuses 128 site pairs more than `astSubtreeHash` would, and catches
  the global and receiver swaps the AST hash's positional identifiers miss.
- **Residuals (rule 2 still carries across these).** Edits outside the member: its callers (one
  changed to bypass it), callees, globals and their initialisation, table definitions and
  properties, other triggers and subscribers, and the `#if` context around the member (equal
  build symbols do not mean the surrounding source is unchanged). Rule 1 admits none of them, since
  any edit changes the generation hash. An enclosing-object "outside members" hash was measured and
  rejected: 0.4-28% refused, close to the per-file cut, and it still misses every cross-object
  effect.
- **Safe false refusal.** The hash is over raw text, so a formatting-only edit, or a checkout that
  turns CRLF into LF, reads as an edit: the mutant re-runs. That costs a run, never a verdict.
- **Tests.** `packages/runner/tests/r474-context.test.ts` (sol's `exit(1)` sequence and its
  history reverse, global and receiver swaps, an `[EventSubscriber]` retarget bare and inside an
  attribute-only `#if`, a trigger, rule 1 with NULL rows, history NULL, migration from a database
  without the column, a manifest entry without the field) and the two `R474:` verify write-through
  tests in `orchestrator.test.ts`; each red-checked, listed in coord handoff `R-474/build.md`.
