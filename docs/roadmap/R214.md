id: "R214"
title: "Site enumeration ignores preprocessor directives, so a mutant can be planted in an `#if` branch the compiler never builds and can never be killed"
section: "correctness-risks"
status: "open, filed 2026-09-08, measured"
order: 926
---

**Found by the issue #6 cross-check, on its first run against deliberately awkward AL.** That is
the audit working as intended: R159's census counts kinds tree-sitter reports, so it could never
have surfaced this.

**What happens.** `tree-sitter-al` parses BOTH arms of a `#if` / `#else` block. The AL compiler
evaluates the directive and parses only the arm that is active for the symbols it was given. So
LethAL enumerates mutation sites inside an INACTIVE branch, and the compiler does not agree those
are sites at all.

Measured with `scripts/probe-grammar-crosscheck.ts` on a fixture containing:

```al
#if CLEAN25
    procedure BehindDirective(A: Integer; B: Integer): Integer
    begin
        exit(A * B);      // <- tree-sitter reports a multiplicative_expression here
    end;
#else
    procedure BehindDirective(A: Integer; B: Integer): Integer
    begin
        exit(A - B);      // <- the compiler parses THIS arm
    end;
#endif
```

```text
multiplicative_expression   tree-sitter 3   compiler 2   <-- differs
sites only TREE-SITTER sees (possible over-claiming): 1
   multiplicative_expression at tricky.al:505      (the `A * B` above)
```

**Why it matters.** This is the over-claiming direction, which is the worse of the two the audit
looks for. A mutant planted in an inactive branch is deployed, but its code is not in the built app,
so no test can reach it. It cannot be killed. It is therefore reported as a SURVIVOR, and a survivor
is the output a user is meant to act on. The score is diluted by mutants that were never live, and
nothing in the report distinguishes them from a real survivor.

**Prevalence, measured, and it is the honest part of this row.** On the two reference corpora the
exposure is near zero:

| corpus | files using directives | `#if` blocks |
| --- | ---: | ---: |
| `do-rel2/Cloud` (554 files) | 1 | 1 |
| `do-lethal-53470/Cloud` (572 files) | 1 | 1 |

So this is not currently costing those measurements anything detectable. It is filed because the
mechanism is real and the exposure is a property of the CORPUS rather than of the tool: Microsoft's
own AL uses `CLEAN`-tagged directives heavily for deprecation, and any app carrying feature flags
would too. A user whose code looks like that gets false survivors and no warning.

**The input already exists.** `preprocessorSymbols` is read from configuration and threaded to the
compile step (`al-runner-backend.ts`, `ArtifactCompilerConfig`), so LethAL already knows which
symbols are defined. Nothing in `packages/engine` or `packages/schemata` consults them: site
enumeration has no reference to directives at all.

**What closing it would take**, roughly in order of cost: refuse to enumerate sites inside a
directive block at all (cheap, correct, loses sites in the ACTIVE arm too); or evaluate the
directives against the configured symbols during enumeration and skip only inactive arms (right, and
needs the grammar to expose the directive structure); or emit the sites and mark them, so the report
can say "not built under these symbols" rather than "survived". The third is the one that keeps
faith with the three-verdict model, since it makes the fact observable rather than silently absent.

See [[R159]] for the census this was invisible to, and the issue #6 harness
(`scripts/probe-grammar-crosscheck.ts`) for how to reproduce it.
