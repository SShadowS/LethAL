Found by coord PR-202 (lethal-bugs, 2026-11-19, bc3, BC 28.4 W1, LethAL Control 1.0.0.28), the wrong-answer hunt round 3.
Evidence: `/coord/handoff/PR-202/result.md`; LethAL's rows in `/coord/handoff/PR-158/runs/p202.bc3/tests.tsv`.

**What was measured.** One invented test calls `Report.RunRequestPage` on an invented report, with a `RequestPageHandler`,
and reports the error text it gets:
- BC's dev-endpoint test runner (a client session): `An error occurred and the transaction is stopped. Contact your
  administrator or partner for further assistance.`
- al-runner v3 (edge-4ebfe7913): the same text.
- **LethAL's bcdev path** (the control app runs each test method in an OData web-service session): **`The report request
  page cannot be used in background or server sessions.`**

**Why it matters.** It is the same family as [[R890]] and [[R895]]: what LethAL's BC path cannot run the way BC's own test
runner does, because each test method runs in a web-service session. In this probe all three runners fail the call, so only
the text differs. A test that asserts on that text, or a suite whose request page runs without error in a client session,
gets a different verdict on LethAL's bcdev backend than on BC's test runner. Not measured: a request page that succeeds in
the client session.

**Possible fix.** Name it, the way R895 names the session kind: when a covering test reaches `Report.RunRequestPage` (or
`Report.Run` with a request page) on the bcdev backend, report it as not runnable on this path instead of scoring a verdict
from the background-session error. First measure whether any request-page call succeeds on BC's runner in a test.
