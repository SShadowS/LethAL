**Filed 2026-10-08 by the [[R500]] build** (plan r3 `/coord/reviews/R-500-plan/plan.r3.md`, shape 2). A plausible
hang that is NOT refused.

**What.** R500's one-hop rule matches a typed receiver against the project's object declarations
(`projectObjects` in `loop-hazard.ts`, from `objectDeclarationsOf`). A codeunit or table whose header is split by
`#if` (`ctx.symbols.splitObjects`) or that sits in an `ERROR` node (`unparsedObjects`) is not among them, so a call
into it from open report-item code is not followed and its procedures are still mutated. Shape 7 already counts
such a reportextension as extending every report; callee objects get no such treatment.

## Closed by ruling

R-522 measurement, 2026-10-23 (`/coord/handoff/R-522/measure.md`, section R522), by parse on BC.History (519
projects), CDO, DC and DO. 7,659 seeds were read; 0 rows reach a callee object wrapped in `#if`. There are 5
split-header objects (3 production projects) and 0 unparsed objects, and no seed names any of them. A file whose
object header is split by `#if` is not mutated at all: its sites are listed as skipped, kind
`preproc_split_declaration`, so the split case can cost no mutant whatever a later census finds. Stated limit:
the unparsed-object case rests on the count (0) alone.

**To close (original plan, closed by the ruling above).** Count the split and unparsed objects that open-item code calls into on every corpus; refuse their
named procedures or close it with a ruling.
