these two, because they are outside that task's files.

1. `warnAlRunnerNotAuthoritative` in `packages/runner/src/cli.ts` tells the user al-runner "reports
   `pass` for an `asserterror` that raised no error". That is R7, a v1 defect fixed in al-runner v2
   and reported `defect-not-reproduced` by `runAlRunnerCanary` since 2.0.0.0. What keeps al-runner
   non-authoritative today is conditional coverage (a file declaring more than one object disables
   it for the whole run), per CLAUDE.md and the agent reference.
2. `fixtures/README.md` says `itest:alrunner` gives 3 / 16 / 0 against bcdev's 3 / 12 / 4. Since
   R220 wired al-runner's own coverage it is 3 / 12 / 4, matching bcdev per mutant.

Both are user-facing text. The warning prints on every al-runner run, so a user reads a false reason.

Evidence: the two sites named above; `docs/measurements/README.md` §"al-runner v2".
