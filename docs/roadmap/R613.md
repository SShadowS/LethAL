**Filed 2026-10-21 by coord task R-613** (lethal-preproc; owner request: fix #5641 locally too, on R-606's rules).

**What.** Upstream #5623 made the company-open refusal per test, through a static reach walk. A routine that lowering
refuses (a `[RunOnClient]` DotNet routine) makes the whole reach "not known", so EVERY test is refused, even when the
routine sits behind a branch that is never taken. Bugs' repro: `/coord/handoff/R-606/reach-repro/`, an invented app
where a never-taken branch to such a routine refuses all 3 tests. In the control, a plain Insert refuses only the
test that reads it.

**The candidate rule (to confirm before editing).** A routine that cannot be lowered cannot run, so statically it
writes nothing. If a test ever ENTERS it at run time, that test is refused at that point. Every other unknown (a
dynamic call, an unresolved target) stays "not known" and refuses as today, so #5623 is not weakened in general.

## Progress (2026-10-21, R-613, local only)

Evidence: `/coord/handoff/R-613/` (`size.md`, `result.md`, `reach.patch`, `resfix-reach.patch`, `baseline-res.patch`,
`logs/`, `repro-run/`).

**#5641 (reach).** Small: 3 files, +82/-3.
- **The cause:** a statement using a `[RunOnClient]` variable lowers to a refuse-when-run step (`Expr::Refused`).
  The reach walk counted that as "not known", so the company-open check refused every test.
- **The fix:** a new `ReachFacts.unknown_besides_refusals`, read only by the two company-open checks. Every other
  unknown still refuses: a compiler-refused routine, an uncompiled object, a dynamic id, an unknown table, RecordRef
  triggers.
- **At run time:** entering the step is already a NotRun that AL code cannot catch (`Signal::Unsupported`).
- **Bugs' repro:** it now gives exactly the control's result, 2 pass and the reader of the table the subscriber
  writes NotRun (#5623's own rule). Unpatched gave 3 of 3 NotRun.
- **Tests:** red-checked in each direction, including "a refused step, then an unknown dynamic call" still refusing
  every test.

**Fix 3 (baseline-res, owner ruling: tracked here).** Upstream's install-baseline cache key (`baseline_key`) left
resources out. So a workspace `Company-Initialize` subscriber that reads `NavApp.GetResource*` got a stale baseline
after a resource change. The fix adds each workspace app's resource names and bytes to the key: 2 files, +91/-1, as
its own branch and patch.
