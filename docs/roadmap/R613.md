**Filed 2026-10-21 by coord task R-613** (lethal-preproc; owner request: fix #5641 locally too, on R-606's rules).

**What.** Upstream #5623 made the company-open refusal per test, through a static reach walk. A routine that lowering
refuses (a `[RunOnClient]` DotNet routine) makes the whole reach "not known", so EVERY test is refused, even when the
routine sits behind a branch that is never taken. Bugs' repro: `/coord/handoff/R-606/reach-repro/`, an invented app
where a never-taken branch to such a routine refuses all 3 tests. In the control, a plain Insert refuses only the
test that reads it.

**The candidate rule (to confirm before editing).** A routine that cannot be lowered cannot run, so statically it
writes nothing. If a test ever ENTERS it at run time, that test is refused at that point. Every other unknown (a
dynamic call, an unresolved target) stays "not known" and refuses as today, so #5623 is not weakened in general.
