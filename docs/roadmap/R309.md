**Filed by R-297 Task 8 (2026-09-28)**, plan
`docs/superpowers/plans/2026-09-28-R-297-instrumentation-real-corpora.md`. Sibling of [[R301]] (class
C, the split-header procedure whose arms share ONE `var` section, which R-297 Task 5 fixed) and
[[R303]] (a member whose var section alone is split by `#if`, now done: it gets ONE unconditional
latch declaration hoisted ahead of the split blocks).

**The shape.** `preproc_split_procedure` covers a procedure whose HEADER differs per `#if` arm but
which shares one `var` section and one body. `preproc_split_procedure_preamble` is the sibling shape
where each arm ALSO has its own `var` section: the preamble (declarations) is split too, not shared.

**What breaks.** [[R301]]'s fix gives `preproc_split_procedure` one shared `var` section to declare
the reach latch in. A `preproc_split_procedure_preamble` has no such single place: one latch
declaration cannot serve both arms' separate `var` sections, the same problem [[R303]] names for an
ordinary member whose var section alone is split. R-297 Task 2 confirmed this stays unfixed: the
`a-preamble` test in `packages/schemata/tests/compile.test.ts` still throws
`a reach marker sits outside any procedure or trigger body` for a spec inside the preamble
procedure's body. Two tests only cover it (an isolated position test, which is green even at HEAD
since the preamble parses as a sibling of `var_section` rather than inside it, and the throwing
test); no compile is claimed.

**Size.** R-297 Task 0's census: 0 files in DC/Cloud, System Application, BusinessFoundation or
BaseApp hold this shape. It is filed because the sibling shape ([[R301]]'s `preproc_split_procedure`)
is real (DC/Cloud 3, BaseApp 4) and the preamble variant would hit the same throw if a corpus ever
has one, not because one has been seen.

**What would close it.** [[R303]] closed its own shape by hoisting one unconditional `var` holding
the latch ahead of the conditional declarations. That hoist is not proven for this shape, where each
arm has a whole `var` section of its own under a different header. Closing it needs either a
per-member refusal (no latch, `reachGrain: "unplaced"`, named in a warning, instead of the whole-run
throw) or a per-arm placement (declare the latch in EACH arm's own `var` section), proven by `alc`
and al-runner the way R303's was. Until R-309 landed, the injector still threw for this shape, as
`compile.ts` and `dispatch.ts` said.

**Closed 2026-09-28 (R-309), a named refusal.** `reachLatchRefusedOwner`
(`packages/schemata/src/dispatch.ts`) now stops its walk at a `preproc_split_procedure_preamble` and
returns it directly, alongside the two shapes [[R303]] and [[R313]] already refuse. `placeReach`
marks every mutant inside such a member `reachGrain: "unplaced"`, so `injectReachLatches` never sees
a statement-grain marker there and its throw is no longer reachable for this shape.
`generateMutationSet`'s `reach-latch-refused` warning gets its own R309 sentence, naming the member.
The label rule (`unnamedMemberLabel`, `packages/runner/src/orchestrator.ts`, the fallback for any
member `procedureLikeNameNode` gives no single name): drop each arm's blank (missing) name, then
deduplicate the rest the same way `procedureLikeNameNode` compares names, quotes stripped and
case-insensitive, keeping the first spelling. Two or more distinct names left give
`procedure <renamed per #if arm: A, B>`; one name or none left gives `procedure <unnamed>` (the
`["Pick", ""]` case: one real name survives the drop, so the label is `<unnamed>`, not a rename).

Measured on 11 hand-written repros (no corpus text; `p1-if-else` through `p10-renamed`, plus
`q1-twin-body`), covering `#if`/`#else`, `#if`/`#elif`/`#else`, one arm with no `var` section, an
arm's own var section itself inside `#if`, CRLF line endings, a mix of a plain member, an R303 hoist
member and a preamble in one file, and arms that rename the procedure. `alc` (24 symbol subsets
across the 10 non-twin repros): all PASS. A local al-runner v2.11.0 probe (no BC container) of the 9
preamble repros, every symbol subset, coverage ON and OFF: 18 `CHECK PASS` (every subset's baseline
green, verdict counts and per-mutant map identical across subsets). Every refused member's file
still compiles and runs; the rest of each file, admitted members included (`p7-mixed`'s `Plain` and
`Hoist`, `p9-all`'s `Split`), is unaffected. This is scratch evidence from hand-written repros, not
a committed gate; the unit tests below (`packages/schemata/tests/compile.test.ts` and
`packages/runner/tests/preproc-instrumentation.test.ts`) are what CI re-checks.

**Per-arm placement was not built.** Three reasons: it buys nothing measurable today, since with
coverage attribution on, such a member has no name or span for any test to be attributed to
regardless of its reach grain ([[R316]]); it is not cheap, a second per-arm header-end anchor rule
with its own controls, red-checks and al-runner probes, for a shape with 0 corpus sites; and the
named refusal is small, proven and truthful, the same pattern [[R303]] and [[R313]] already use.
Per-arm placement waits on [[R316]] giving the member a name and a span first; its own `alc` evidence
(every arm's header taking its own latch line) is recorded in
`docs/superpowers/plans/2026-09-28-R-309-split-preamble.md`, "Per-arm placement, measured on
hand-written text".

**Visibility.** The refusal's cause (`"preamble"` in `reachLatchRefusals`'s three-way `cause` field)
appears only in the `reach-latch-refused` warning and its event (console and `--progress-out`
NDJSON). The manifest and `SessionReport` still carry the generic `reachGrain: "unplaced"`, with
nothing naming which of the three causes applied, consistent with [[R310]]'s ruling.

**The trigger form does not reach this fix.** Each `#if` arm holding its own `trigger OnRun()`
header and `var` section does not parse as a preamble in tree-sitter-al 4.4.1: it leaves a
`preproc_conditional` with ERROR nodes (measured on `p5-trigger`, 4 ERROR nodes), so it is already
refused as [[R313]] instead, by its own `varSectionUnparsed` predicate. Filed upstream as
SShadowS/tree-sitter-al #32.

**Corpus size, unchanged.** 0 files hold a `preproc_split_procedure_preamble` in DC/Cloud (1135
files), System Application (1718), BusinessFoundation (104) or BaseApp (9620, parse-only, two
halves), before and after this fix. Every `fixtures/*` emission and identity key is byte-identical
(`sandbox-app`, `sandbox-data`, `sandbox-hang`, `sandbox-harden`, `sandbox-coverage-probe`), so no
live gate needed re-recording.
