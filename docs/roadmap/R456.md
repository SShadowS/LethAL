**Found 2026-10-05 while implementing [[R455]]** (alc 18.0.43, synthetic app, invented names).

R294's context predicate (`implicitRecordShadowsGlobals` in `types.ts`) treats a report's own
triggers and procedures as seeing the report's globals and procedures. That holds for a report
WITHOUT a request-page `SourceTable`. With one, alc binds the request page's record first in the
whole report:

- `OnPreReport` and a report procedure: `I := F() + F()` with a report `F(): Integer` and a table
  `F(): Text` is AL0122 (Text to Integer), with AL0604 "implicit with" on each `F`. Without the
  request-page `SourceTable` the same lines compile.
- A NAME too: `T := Amount` with a report global `Amount: Text` and a Decimal field `Amount` is
  AL0122 (Decimal to Text) in both a report procedure and `OnPreReport`.

So in such a report a bare name falling through to a global, and (since R455) an unqualified call,
are typed by the wrong declaration, and `swap-call-arguments` / `swap-additive` can emit AL that
alc rejects. Not measured on a corpus yet: no wrong mutant is known in BaseApp or CDO.

The R294 test fixture (`packages/runner/tests/r294-implicit-with.test.ts`, the "control, report
trigger" case) is this shape: its report declares a request-page `SourceTable`, and its original
`RTakeInts(Q2, Z)` is itself AL0133 under alc (Z binds to the Text field), so that control asserts a
swap on AL that does not compile.

**To close.** Measure how many reports in BaseApp and CDO declare a request-page `SourceTable` and
how many typed mutants sit in their triggers and procedures. Then widen the shared predicate (the
`report` case returns whether its request page declares `SourceTable`), fix the R294 control to a
report without one, and red-check both directions.

**Closed 2026-10-05 as a ruling: a stated limit, no change to the predicate** (R-456 measurement, `/coord/handoff/R-456/measurement.md`, master 0277ce3b; orchestrator ruling).
- **alc 18.0.43 confirms the binding.** In a report whose request page declares `SourceTable`:
  - `I := F() + F()` (report `F(): Integer`, table `F(): Text`) and `T := Amount` (a Text global, a Decimal field) are AL0122 in `OnPreReport` and in a report procedure;
  - a control report without a request-page `SourceTable` compiles;
  - dataitem triggers still bind their own dataitem's record first, with the request-page record as the next fallback above the report's globals.
- **Measured exposure: none.** Over 209 projects (the 203 BaseApp corpus projects and CDO at 5f2a71d), through the real generation path:
  - 3 BaseApp reports declare a request-page `SourceTable` (`WhseChangeUnitofMeasure`, `VATReportRequestPage`, `ConfigPackageProcess`); CDO has none.
  - **0** `swap-call-arguments` or `swap-additive` mutants sit in those reports, against 37,639 + 10,391 in BaseApp and 728 + 97 in CDO in all.
  - 0 wrong mutants.
- **Why no change.** Widening the predicate would remove mutants, which can move same-tuple identity keys and so needs another `IDENTITY_SCHEME` bump, for 0 measured sites.
- **The fix, for whoever reopens this** (re-run the R-456 census first): the `report` case of `implicitRecordShadowsGlobals` in `packages/engine/src/semantic/types.ts` returns whether the report's request page declares `SourceTable`, so its own triggers and procedures refuse a name or unqualified call that falls through to the report's globals.
- **Landed here:** R294's "control, report trigger" test in `packages/runner/tests/r294-implicit-with.test.ts` now uses a report WITHOUT a request-page `SourceTable`. Its old original was itself AL0133 under alc, so the control asserted a swap on AL that does not compile. It is red-checked against an over-broad refusal of every report trigger.
