**Found 2026-10-08 by the R-487 final review** (`/coord/reviews/R-487/opus-final.md`). In a report data item
written `dataitem(X; System.Utilities.Integer)`, the parser gives one `table_name` field per name segment, and
`childForFieldName("table_name")` returns the FIRST one (`System`). [[R487]] fixed this for the hang rule
(`isIntegerItem` in `loop-hazard.ts` now reads the last segment). The same first-segment read remains in the
`report_dataitem` case of the engine's receiver binding (`packages/engine/src/semantic/receiver.ts`), so the item's
record binds to a table named `System`.

**Effect.** A Tier-1 or Tier-2 rule that resolves the data item's record to its table (trigger-skip tagging,
receiver checks) does not find the table. BC.History has 5 such items, all in BaseApp. Unmeasured: which mutants'
tags or claims change.

**To close.** Read the last `table_name` segment there too, measure the spec and tag diff on BC.History (keys can
move, so ask for a scheme), and add a test with an unqualified twin.

## Fixed (R-502, 2026-10-08)

**Every reader, not only the data item.** tree-sitter-al 4.4.1 gives a qualified name one child per segment in:
- `report_dataitem`/`query_dataitem`/`tabledata_permission` `table_name`;
- `record_type`/`object_reference_type` `reference`;
- `simple_table_relation` `table`.

A sweep of `packages/` found two FIRST-segment reads:
- the data item scope (`recordScopesAt`);
- `classifyDeclaredType` (`R: Record System.Utilities.Integer`, 1045 sites in BC.History).

It also found three FULL-dotted-text reads of the same names, which match no table either:
- `types.ts`'s `recordTableName`;
- its call-return branch (`Codeunit X`/`Record X`);
- `propertyValueOf` (`SourceTable`, `TableNo`).

All five now read every segment (`fieldSegments`/`nameSegments`, `ast/qualified-name.ts`) and resolve through one
function, `qualifiedObjectName` (`symbol-table.ts`). `loop-hazard.ts`'s `isIntegerItem` and `testpage-scan.ts`'s
`lastSegment`, already last-segment, now use the same helpers. The only difference is that `lastSegment` now
unquotes before it trims, so `" Foo "` normalises to `foo`; no object name starts or ends with a space. No reader
of the other fields exists.

**Not the bare last segment (opus plan review, C1).** A qualified name is the spelling AL needs when a name
collides, and `resolveObject` returns the FIRST same-named object. So a qualified reference resolves only when:
- the project declares exactly one object of that kind and name; and
- that object's file declares exactly the qualifier as its `namespace` (each `ObjectSymbol` now carries
  `namespace`).

Otherwise it becomes the dotted text with every segment quoted (`"Microsoft"."Sales"."Customer"`). No object name
contains a `"`, so that text names nothing, not even a project table literally named `"Sales.Setup"` (opus build
review, minor 1). The reference stays unresolved and the tag is kept, as before. One segment reads exactly as
before. A text that is not a clean dotted name (`"X" temporary`) also keeps
the old reading ([[R509]]).

**A qualified `extends` (opus plan review, I2)** does not parse ([[R511]]). `projectObserves` keeps the
trigger-skip tag whenever an extension has an ERROR beside its `base_object`, and both error-recovery shapes are
tested.
