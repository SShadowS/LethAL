**Found 2026-10-06 while building [[R484]]** (plan
`docs/superpowers/plans/2026-10-06-R-484-report-dataitem-loops.md`, sol reviews r1 to r5).

**What.** R484 treats an open `Integer` report data item as a loop. It refuses a value-operator write
when the item's Break, Quit or Error guards read the target, or when the item's own `SetRange` or
`SetFilter` bounds read it. These shapes are not seen. Each is a known exclusion, and none is shown
safe:

1. **An exit behind a call.** In `if Done then Fail()`, `Fail` raises an error, but the call is not
   read as an exit. R446 has the same blind spot.
2. **An indirect feed.** Report guards get no R480 closure. In `I += 1; Done := I > 3; if Done then
   CurrReport.Break()`, the `Done` write is refused, but the `I` write is not.
3. **Items over ordinary tables.** They end when their records end. A trigger that inserts into the
   temporary set it walks can keep that set growing.
4. **Other places.** `Date` items (4 on BaseApp); writes in procedures a trigger calls;
   reportextension `modify(...)` triggers, because the base report is not read; an XMLport
   `tableelement` over `Integer`.
5. **A bound set through another record.** In `Src.SetRange(Number, 1, N);
   Src.CopyFilter(Number, D.Number)`, the item is open, but writes to `N` are not refused.
6. **Condition-side mutants of a data-item Break guard** (`remove-not`, `negate-guard`,
   `conditional-boundary`). R196 has the same exclusion.
7. **An unqualified `Number := X;` in the item's own trigger.** It moves the `Integer` cursor. It
   is an assignment, not a call or a name, so the mention scan does not count it, and a bound
   certificate still holds.
8. **A reportextension `modify(D)` trigger that resets or widens the filter on D.** The mention scan
   reads only the report object that holds the item, so a filter change made from an extension is
   not seen.

**Closed 2026-10-07 by the blanket rule** (`538c38c8`; IDENTITY_SCHEME 30 in `9ce9e1af`; plan
`/coord/reviews/R-487-plan/plan.r7.md`, sol r7 SOUND; evidence `/coord/handoff/R-487/survey.md`
and `build.md`). In an OPEN `Integer` report data item, `remove-assignment`, `shift-integer`,
`flip-boolean-literal` and `swap-additive` now refuse EVERY site, whatever it writes or reads
(`inOpenItemCode` in `loop-hazard.ts`). The rule covers:
- the item's triggers, and its child items' triggers and columns (a child of an open item counts as
  open, even when it is bounded);
- a reportextension dataset block (`modify`, `add`, `addfirst`, `addlast`, any
  `*_dataset_modification`) whose base item is open, or whose base report or item is not in the
  project;
- every same-object procedure that code reaches by name, transitively (`P()`, `P;`, `this.P()`,
  column sources, both split-header procedure kinds, any arm name).

"Open" is still R484's certificates, with two changes. An unqualified `Number := X` is a mention,
so it voids them (item 7). An `Integer` item of a report that any project reportextension extends
is bounded only by `MaxIteration`: its view and SetRange certificates do not hold, in the base
report's own code too (item 8). An extension names its base by the last name segment, which the
vendored grammar already isolates (pinned on the AST); one with no base name counts as extending
every report.

**Measured** (exact identity-keyed dumps, every operator, against master `155c4dd8`): BC.History
5,010 sites move from emitted to hang-refused (remove-assignment 3,417, shift-integer 919,
flip-boolean-literal 557, swap-additive 117), 0 released, 0 changed, 0 appeared, 203 keys move.
CDO, DC, DO, the fixtures and the examples are unchanged, so no gate moves. Over-refusal: 1.11% of
BC.History's sites for these four operators.

**Per item.** 1, 2, 5 and 7 are refused. In 4, writes in same-object procedures are refused, and
so are reportextension blocks unless their in-project base item is bounded. 8 is covered by the
`MaxIteration`-only rule for extended reports. NOT covered, and moved: items 3, `Date` items and
XMLport `Integer` elements (4), procedures in OTHER objects (4), reportextensions outside the
project (4, 8), and code that runs before the item, to [[R500]]; item 6, with the exit removal
itself, to its own correctness risk, [[R501]]. [[R493]] s1 to s3 are covered too; its s4 is kept
refused (ruled there).
