**Filed by R-297 Task 8 (2026-09-28), consolidating the plan's ruling 2.** Plan:
`docs/superpowers/plans/2026-09-28-R-297-instrumentation-real-corpora.md`, Task 3's decision note
("mutants in an arm the build compiles out are a known, separately filed issue"). Not a new
mechanism: [[R214]] already names the general phenomenon (tree-sitter parses both `#if` arms, the
compiler builds one, LethAL plants mutants in both). This item names the three different outcomes
that phenomenon now has, after R-297, depending on the container:

1. **An ordinary in-arm statement**, inside a plain procedure with no wrapper on the `#if` at all
   (the shape [[R214]], [[R285]] and [[R287]] measure). The mutant is planted, instruments, and is
   scored normally. Whether it is a false "survived" (the compiler never built it, so no test can
   kill it) is [[R214]]'s open question, unchanged here.
2. **A `#if`-wrapped whole OBJECT** ([[R298]], [[R300]]). Since R-297 Task 3/4, such an object
   instruments instead of throwing, but its coverage is refused by name in both coverage paths
   (bcdev line map and al-runner), so every mutant in it, active arm or not, reads `no-coverage`.
   Measured: R-297 Task 4's tests and the R300 census.
3. **An in-body `#if` inside an otherwise-ordinary, reach-latched procedure**: a statement wrapped
   in `#if`/`#endif` where the procedure around it is a plain `procedure` or `trigger_declaration`
   with its own working reach latch (not one of R301's, R303's or R304's to R305's broken shapes).
   This is PREDICTED, not measured: such a mutant's own statement-grain reach marker
   (`MutationSelector.Reached`, gated by `reachGrain: "statement"`) never fires, because the
   compiler never builds that arm, but the enclosing procedure's OTHER markers can fire when a
   covering test runs it. Per `survivorReachOf` (`packages/runner/src/report.ts`), a statement-grain
   survivor whose own marker did not fire reads `covered-but-unreached` when attribution is
   `"exact"` (a statement marker exists to compare against) and `unreached-and-uncovered` otherwise.
   No repro or corpus run has exercised this specific shape end to end; the prediction follows from
   reading `survivorReachOf` and the reach-latch injector together, not from a run.

**Why it is filed rather than fixed.** Case 1 is R214's open question, already tracked there. Case 2
is measured and its own item (R300) already owns closing it (measure how BC and al-runner number a
wrapped object's lines, then score instead of refusing). Case 3 has no fix to propose yet: it needs
a live measurement of whether `covered-but-unreached` actually reaches a real survivor row for this
shape, which needs a container.

**What would close it.** Build the case-3 repro (a plain procedure, `#if not SYM` around one
statement, `#endif`, more statements after, a test that covers the procedure), run it end to end
offline (report only, no server) to confirm the predicted `reachGrain`/`guardReached` values, then
either measure it live or fold the confirmed prediction into R214's own evidence.

**R214 update (2026-10-01).** Case 1 is closed by [[R214]] (`84f72d33`): compiled-out arms get no mutant. Case 3's prediction was wrong (it said unplaced) and is now right: a statement directly inside a statement-level `#if` has statement grain since `38a82a55`. Case 2 remains [[R300]]'s.
