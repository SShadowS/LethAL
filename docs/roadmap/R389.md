**Closed 2026-10-05 (893b2e3c).** Built to the adopted plan
`docs/superpowers/plans/2026-10-04-R-389-variant-interface-reach.md` (r2), after a live probe
(6e9b20ed) showed external code running a test-app codeunit it received in a Variant three ways.
First landing 41ff941d; a final review found three holes, closed in 5bb28e93; the orchestrator's
option (a) then narrowed two of the resulting fallbacks (612b0573, 64e95a80).

The digest walk (`Scanner` in `packages/runner/src/testpage-scan.ts`) traces, inside the procedure
that hands a Variant to code it does not follow, what the Variant is assigned from: a test-app
codeunit or `this` in a codeunit folds that codeunit whole; an Interface folds every test-app
codeunit implementing it, through `extends`; a test-app page, report, query or xmlport is entered;
a record keeps the table fold. A Variant PARAMETER is traced through every test-app call site of
its procedure, by name and arity, over-approximated (option a). Anything the walk cannot see falls
back to the whole-source digest: a global, a `foreach` variable, a `var` argument to a test-app
procedure, a call returning Variant, an element of (or a fill from) a Variant array or collection,
`this` outside a codeunit, a cycle, a caller chain deeper than 32, an unresolved name, an
unmodelled shape, and a parameter of a procedure the platform or another app can call (a
subscriber, a test, a handler, a trigger, a web service, any procedure of a codeunit that
implements an interface). Access level is not a reason to fall back: only the test app and an app
that depends on it can call a test-app procedure by name, and a dependent app is outside every
digest already. Part 2: a procedure external code can CALL (an `[EventSubscriber]` procedure, every
procedure of a codeunit folded whole, an enum's implementation codeunit) is an entry, and its `var`
parameters and return value of type Variant, Interface, RecordRef or FieldRef are read the same way
(`foldEntryUnit`, `handOuts`; `subscriberFold` in `test-digest.ts` enters subscriber procedures
through `foldEntryProc`).

Final review (5bb28e93): a Variant, Interface or test-app codeunit handed to a BUILT-IN (`Format`,
`StrSubstNo`, a system method) is a hand-out too, since `Format` of a Variant gives the held
codeunit's id (probe R4d); a parenthesis-less call (`V := MakeVariant;`) is traced as a call; and
for an interface the test app does not declare, every test-app codeunit whose `implements`
ancestry reaches an interface the test app does not declare is folded, since a dependency's
`IDerived extends IBase` is not visible. A test-app interface needs only its own implementers (a
dependency cannot extend it). An interface with neither kind of implementer folds nothing (the
probe's `bi:none`), pinned byte-equal to the pre-change build. Option (a) also reads a
namespace-qualified name (`System.RestClient."Http Response Message"`) as a dependency's object
when its last segment names no test-app object (every resolver matches by the last segment); an id
or any other shape is still refused.

No `TEST_DIGEST_SCHEME` or identity bump (the plan's ruling), because the change only adds
coverage: a test whose digest now covers more (newly on the whole-source digest, or with a new
fold) gets a new digest and reads as new once; every other test keeps its digest, pinned in
`packages/runner/tests/r389-variant-reach.test.ts`.

Measured at 893b2e3c through `scripts/r371-reach-measure/product-measure.ts` plus a per-test digest
diff against the base 48598264 (no R-389 code), one corpus at a time:

| Corpus | Tests | Whole-source fallback, base -> build | New fallback | Digests moved | Subscriber closure |
|---|---|---|---|---|---|
| DC/Test c895a7d | 1,854 | 66 -> 71 | 5 (0.3%) | 5 | unchanged, not on the fallback |
| DO/Test b3b4459 | 1,986 | 103 -> 105 | 2 (0.1%) | 1,986 | wider by a fold (400 -> 407 procedures, 42 -> 44 objects), not on the fallback |
| CDO 5f2a71d | 1,287 | 6 -> 6 | 0 | 0 | unchanged |

DO's every test moves ONCE because the closure's dependency-interface hand-out now folds the test
app's codeunits of unknown interface ancestry (with that fold switched off, 2 move). The first
landing measured 29 / 1,854 and 29 / 1,986 new fallbacks; option (a)'s parameter tracing removed
most of them. The plan's stop rule does not trigger.

Limits, stated: the walk does not read dependency symbols, so interface ancestry across a
dependency is over-approximated, not resolved; a caller list is by name and arity, so it can
include calls that resolve elsewhere (more is traced, never less). Red-checks for every rule and
its control are in the coord handoff (`R-389/red-checks.md`).

**What.** R-371's digest folds every test-app table into a test's digest when the test passes a
Variant, RecordRef or FieldRef to code in another app (orchestrator ruling, 2026-10-01), because a
record reaches test-app code only through its table's triggers. A Variant can also hold a test-app
CODEUNIT or an interface implementation, and external code can run it. The walk did not track
where a Variant's value comes from, so that case was not folded: an edit to that codeunit, or to
what it calls, left the test's digest unchanged and verify treated the test as old (the unsafe
direction).

**Why it was not closed with R-371.** Treating every Variant argument as possibly holding any
test-app object put all 1,301 DC tests on the whole-source digest (194 Variant arguments, one of
them in the subscriber closure), measured with `scripts/r371-reach-measure/product-measure.ts`.
