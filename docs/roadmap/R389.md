title: "lethal verify cannot see an edit to a test-app codeunit that external code runs through a Variant or interface the test passed it"
section: "correctness-risks"
status: "open, filed 2026-10-01"

---

**What.** R-371's digest folds every test-app table into a test's digest when the test passes a
Variant, RecordRef or FieldRef to code in another app (orchestrator ruling, 2026-10-01), because a
record reaches test-app code only through its table's triggers. A Variant can also hold a test-app
CODEUNIT or an interface implementation, and external code can run it. The walk does not track
where a Variant's value comes from, so that case is not folded: an edit to that codeunit, or to
what it calls, leaves the test's digest unchanged and verify treats the test as old (the unsafe
direction).

**Why it was not closed with R-371.** Treating every Variant argument as possibly holding any
test-app object put all 1,301 DC tests on the whole-source digest (194 Variant arguments, one of
them in the subscriber closure), measured with `scripts/r371-reach-measure/product-measure.ts`. The
stated limit is commented where the table fold happens in `packages/runner/src/testpage-scan.ts`.

**What would close it.** Track what a Variant is assigned from inside the test-app procedure that
passes it. A Variant assigned from a test-app codeunit or interface variable (or from anything the
walk cannot see) folds that codeunit's reach, or falls back.
