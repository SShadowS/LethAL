**Closed 2026-10-05 (41ff941d).** Built to the adopted plan
`docs/superpowers/plans/2026-10-04-R-389-variant-interface-reach.md` (r2), after a live probe
(6e9b20ed) showed external code running a test-app codeunit it received in a Variant three ways.
The digest walk (`Scanner` in `packages/runner/src/testpage-scan.ts`) now traces, inside the
procedure that hands a Variant to code it does not follow, what the Variant is assigned from: a
test-app codeunit or `this` in a codeunit folds that codeunit whole; an Interface folds every
test-app codeunit implementing it, through `extends`; a test-app page, report, query or xmlport is
entered; a record keeps the table fold. Anything the walk cannot see falls back to the
whole-source digest: a parameter, a global, a `foreach` variable, a `var` argument to a test-app
procedure, a call returning Variant, an element of (or a fill from) a Variant array or collection,
`this` outside a codeunit, a cycle, an unmodelled shape. Part 2: a procedure external code can CALL
(an `[EventSubscriber]` procedure, every procedure of a codeunit folded whole, an enum's
implementation codeunit) is an entry, and its `var` parameters and return value of type Variant,
Interface, RecordRef or FieldRef are read the same way (`foldEntryUnit`, `handOuts`;
`subscriberFold` in `test-digest.ts` enters subscriber procedures through `foldEntryProc`).
An interface with NO test-app implementation folds nothing and widens no digest (the probe's
`bi:none`, the shape DO's closure has); a product test pins that digest byte-equal to the
pre-change build, with a control where one implementation is folded.

No `TEST_DIGEST_SCHEME` or identity bump (the plan's ruling): unchanged shapes digest byte-identically
(pinned in `packages/runner/tests/r389-variant-reach.test.ts`, recorded before the code), and a test
that gains a fold or the fallback reads as new once, the safe direction.

Measured through the built product (`scripts/r371-reach-measure/product-measure.ts` plus a per-test
digest diff, base against build), equal to the probe on every corpus:

| Corpus | Tests | New whole-source fallback | Digests moved | Subscriber closure |
|---|---|---|---|---|
| DC/Test c895a7d | 1,854 | 29 (1.6%) | 29 | unchanged |
| DO/Test b3b4459 | 1,986 | 29 (1.5%) | 29 | unchanged |
| CDO 5f2a71d | 1,287 | 0 | 0 | unchanged |

The plan's stop rule did not trigger. Red-checks: 24 one-line reverts, each turning its test red.

**What.** R-371's digest folds every test-app table into a test's digest when the test passes a
Variant, RecordRef or FieldRef to code in another app (orchestrator ruling, 2026-10-01), because a
record reaches test-app code only through its table's triggers. A Variant can also hold a test-app
CODEUNIT or an interface implementation, and external code can run it. The walk did not track
where a Variant's value comes from, so that case was not folded: an edit to that codeunit, or to
what it calls, left the test's digest unchanged and verify treated the test as old (the unsafe
direction).

**Why it was not closed with R-371.** Treating every Variant argument as possibly holding any
test-app object put all 1,301 DC tests on the whole-source digest (194 Variant arguments, one of
them in the subscriber closure), measured with `scripts/r371-reach-measure/product-measure.ts`.
