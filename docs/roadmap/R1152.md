Found by coord PR-217 (PERF-10, lethal-bugs, 2026-11-19). Evidence: `/coord/handoff/PR-217/perf10.run.events.ndjson` (the
stopped first start), `/coord/handoff/PR-217/keep-audit.md` (the audit of every keep entry against al-runner's texts).

**What happened.** perf-combined 2bb4b686 passed the private update gate with every leg green. Its first DO run then restarted the
serve daemon 32 times in 40 minutes (y3: 31 in its whole run), every time on one refusal:
`FindSet on the Company table: the database may hold companies this runtime does not know; name them with --companies
NAME[,NAME...] (serve: the `companies` field); `all` needs test data (ADR-046 decision 4a)`.
LethAL's keep entry for that refusal is an anchored regex for the OLD text (`... does not know (ADR-046 decision 4a)`), so the
reworded text no longer matched and each refusal closed the daemon. The verdicts are the same class either way (NotRun); the cost
is speed: the baseline took 29 min against y3's 10.7.

**Why the gate missed it.** Leg C's serve-keep-reasons runs a measured case only for some keep entries
(`SERVE_CASES` in `al-runner-v3-contract.ts`); there is no Company-table case, so a reworded text in that class is invisible
until a full run meets it.

**To do:**
- a serve-keep-reasons case for every keep entry that can be produced without the .NET helper or a platform table (the
  Company-table read can: a test that runs FindSet on the Company table), each judged against the entry's own regex, so a
  reworded text fails the gate instead of a run;
- for the rest (the .NET and platform ones), the run-time warning PR-244 adds (a refusal that closes a daemon while a keep entry
  nearly matches it is named once).
