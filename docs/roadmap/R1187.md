**Found by** coord PR-364 (lethal-code, 2026-11-23), mining c3's `error` mutants on current main-bf3a3e863 against y3
(R1140). Evidence: `/coord/handoff/PR-364/` (`findings.md`, `mine.py`, `causes.tsv`, `moved.tsv`). Names and counts only.

**What happened:**
- **The refusal:** al-runner now refuses `Field.RelationFieldNo` for a TableRelation without a field whose shape its probe
  did not measure: "the value of field 'RelationFieldNo' of platform table 'Field' is not known for field ... of table ...,
  a TableRelation without a field of a shape not measured".
- **Where it comes from:** upstream `1bea5bc7a` (2026-11-20, after issue #8249). The text is in no build up to
  edge-4ebfe7913, and in every main build from main-ccd0f823d on.
- **Where it hits:** on DO it refuses 7 test runs at BASELINE, over three BaseApp fields: `Dimension Code` of `Dimension Set
  Entry`, and `Ship-to Post Code` and `Dimension Set ID` of `Sales Invoice Header`. In y3 the same tests ran and passed.
- **Why it costs so much:** the serve daemon does not keep this refusal, so PR-250 cuts each codeunit's entry before the
  refused test. Every mutant that needs a later test of that codeunit reads `error`.
  - c3: **1,504** such mutants. y3 had 182 of them killed and 1,233 survived. c2 (main-ccd0f823d): 1,469.
- **The second case:** "Report.SaveAs as Pdf of report "Standard Statement": not measured on BC. Never measured: data items
  = another tree ..." works the same way, for 58 c3 mutants (54 via the cut).

**The lever in LethAL's hands:**
- keep the daemon through these refusal texts (a `PR56_KEPT` row each), only after a kept-vs-fresh DO check that
  exercises the real text (PR-354's method, principle 9);
- the refused tests stay unrun, and the cut goes;
- the recovery is up to 1,504 plus 58 mutants, less those only the refused tests cover (to count in the check).

**The kept-vs-fresh DO check (PR-365, 2026-11-23, `/coord/handoff/PR-365/keepcheck/`, `c-classify.md`; the ruling is in
`/coord/handoff/PR-365/result.md`):**
- **Plan A** (one kept daemon vs a fresh daemon per request, main-bf3a3e863): 20 of 20 requests equal.
- **Plan B** (each refused test excluded vs present): 38 pairs, 0 differences.
- **Plan C** (keep mode on main vs a full run on edge-4ebfe7913, rows after a refused test): 10 of 20 requests differ, in
  2 tests. In all 10, keep mode reads `error` (main withholds the test after a refused test that ran part-way, upstream
  `1bea5bc7a`'s out-of-scope rule, which edge predates), and edge reads `fail`. None is a false kill or a false survived.
  - Codeunit 68984 `U_ChainThroughTwoCompositeKeys_AsksOnceAndFillsTheSameKindOfValue`, requests 11-19 (5 under no
    mutant, M12482, M12483, M12484, M12504): it fails under no mutant on edge too, so it scores nothing on either build.
  - Codeunit 68975 `CopyToTemplate_RunTwice_DoesNotDuplicateTheChildren`, request 9 (M13065): edge kills it, keep mode
    withholds it (`error`). c3 already read M13065 `error`. Whether BC kills it is not measured.
  - **alrunner (via kraken, 2026-11-23):** the withholding is upstream ADR-064 on purpose (a later FAILURE after a refused
    test of partly unknown reach is not trusted; passes stay clean). It ends with the RelationFieldNo refusal (upstream
    #8592). Edge's kill rested on `RelationFieldNo = 1`, which BC does not give.
  - BC's `RelationFieldNo` for these shapes is 0 (PR-367 on bc4), so amendment 1's "another value" case applied. Its
    "oracle value" category (the later test reads state the refused test built) is not shown from the code: both tests
    roll back and build their own records.
- **The kit had two faults in that run, fixed after it:** compare-c's self-test exited 1 (it caught 11, its rule wanted
  exactly 1), and `run.sh`'s `| tee` hid that exit. The compares were re-run on the saved answers with the fixed rule.
- **So C was not a mechanical pass.** The rows landed on a RULING: their claim is kept = fresh, which A and B show, and
  C's differences come from the named upstream change, not from the rows.

**PR-365's recovered survivors are UNCONFIRMED until PR-381 lands** (owner's ruling, q-20261123T112833-7e045797). With the
keep rows, the 7 refused tests never run while the other tests of 68975 and 68984 do. So a mutant only a refused test would
kill reads `survived` (preproc found 9 such false survivors of 47 in codeunit 68874 on bc4). Survivors in a codeunit with a
refused test stay `error` or carry a caveat; kills stay. PR-381 builds the rule; PR-382 measures the false-survivor rate.
- **The population at risk (PR-382, `/coord/handoff/PR-382/strata.tsv`):** 214 of the 1,504 survived in t1 while a
  refused test covers them in y3: 185 through 68984's refused tests, 29 through both codeunits', 0 through 68975's alone.
- **A blind spot for BC through LethAL:** all 7 refused tests open TestPages, and bcdev's fenced session refuses those on
  BC too (`tests-testpage-refused`, PR-357's bc4 run). So a bcdev run cannot observe their kills.
- **Nor can BC's own test runner, today (PR-382's probe on bc4, pre-commitment master fb7e94d91 with amendments 1 and 2,
  `/coord/handoff/PR-382/run/result.md`):** the dev endpoint's runner executes TestPage tests, but the refused
  `U_FieldPickerHopIntoAnUnpinnableKey_TakesTheValueTyped` fails UNMUTATED ("The part with ID = 1589389838 was not found on
  the page."), on bc4's instrumented DO and again on a plain DO build that matches the test app. So no kill through it can be
  read on BC (option (b)); bc4 was restored by an upgrade to the resident build's content.
  - **Told apart (amendment 3, master 1cc738cca; bc4 11:57Z):** `U1_CreateLineFromLinesPart_LinePersisted`, NOT refused and
    green in c3, fails the same way in the same call ("The part with ID = 1589389838 was not found on the page."). So the
    dev runner's session cannot host that page part for any test; the refused test's result says nothing about the test.
    Reading these kills on BC needs a client session that hosts TestPage parts (R1170's client-session work).
- **Static reach does not narrow it on DO (PR-386, closed before the build; spec master c11fe0d31, result section;
  `/coord/handoff/PR-386/probe-b.md`):** the blanket every not-run test must reach (subscribers, extensions, run-by-id
  objects, table triggers, over both apps) itself falls back on DO, so every test reaches everything, which is PR-381's
  `ALWAYS_REACHES`. Without that fallback it would still reach the members of 8,398 of c3's 8,618 survivors (97.4%), a
  2.6% ceiling. Reopen only on a narrower blanket argued sound first, with its own spec and review.
