**Found by** coord PR-364 (lethal-code, 2026-11-23), mining c3's `error` mutants on current main-bf3a3e863 against y3
(R1140). Evidence: `/coord/handoff/PR-364/` (`findings.md`, `mine.py`, `causes.tsv`, `moved.tsv`). Names and counts only.

**What happened:**
- **The refusal:** al-runner now refuses `Field.RelationFieldNo` for a TableRelation without a field whose shape its probe
  did not measure: "the value of field 'RelationFieldNo' of platform table 'Field' is not known for field ... of table ...,
  a TableRelation without a field of a shape not measured".
- **Where it comes from:** upstream `1bea5bc7a` (2026-11-20, after issue #8249). The text is in no build up to
  edge-4ebfe7913, and in every main build from main-ccd0f823d on.
- **Where it hits:** on DO it refuses 7 test runs at BASELINE, over three BaseApp fields: `Dimension Code` of `Dimension Set
  Entry`, and `Ship-to Post Code` and `Dimension Set ID` of `Sales Invoice Header`. In y3 the same tests ran and passed.
- **Why it costs so much:** the serve daemon does not keep this refusal, so PR-250 cuts each codeunit's entry before the
  refused test. Every mutant that needs a later test of that codeunit reads `error`.
  - c3: **1,504** such mutants. y3 had 182 of them killed and 1,233 survived. c2 (main-ccd0f823d): 1,469.
- **The second case:** "Report.SaveAs as Pdf of report "Standard Statement": not measured on BC. Never measured: data items
  = another tree ..." works the same way, for 58 c3 mutants (54 via the cut).

**The lever in LethAL's hands:**
- keep the daemon through these refusal texts (a `PR56_KEPT` row each), only after a kept-vs-fresh DO check that
  exercises the real text (PR-354's method, principle 9);
- the refused tests stay unrun, and the cut goes;
- the recovery is up to 1,504 plus 58 mutants, less those only the refused tests cover (to count in the check).

**The other lever (upstream):** measure these shapes. That needs the BC check first (R1188).
