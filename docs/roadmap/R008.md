**al-runner drops a table global var written by a trigger.** After `Validate("No.", 'B2')` the fixture's `TouchCount()` returns 0 there, though the trigger body demonstrably ran. Root-caused 2026-07-26 (three throwaway diagnostic probes against al-runner.exe directly): the write is real — a nested `TouchCount()` call from INSIDE the trigger's own frame reads 1 — and the field write (`"No."` itself) demonstrably survives the same call boundary; only the non-field global does not survive the return from `Validate()` back into a later, separate top-level dispatch on the same record variable. Third-party, upstream — documented rather than fixed. Detectable: al-runner is now startup-canaried for it (`packages/runner/src/al-runner-canary.ts`, `runFromCli`'s al-runner branch), so every session states whether the defect reproduces on the binary actually configured, rather than repeating a static 2026-07-25 claim. Any mutant whose only observable effect is table-global state may still be misjudged on that backend when the canary confirms it. Evidence: `fixtures/README.md` §Tier-2 Phase 0.
