**Found by lethal-preproc, 2026-10-05,** reading branch CI for R-294.

**What happened.** On GitHub CI run 37239963279 (branch `lethal/r294`, commit 435c7d55), the Windows `check` job failed one test and nothing else: `scripts/store-query.test.ts`, "latest run is the highest FINISHED id; a newer unfinished one is reported, not chosen", at 8290 ms. The Linux `unit-linux` job passed. The next push to the same branch (run 37241383676, whose code differs only in an unrelated engine file) passed both jobs. R448 does not list this test.

**Why it matters.** It is the same family as R226, R335, R428 and R439: a unit test with no headroom against bun's 5 s default, which turns a CI run red at random. Here it is on Windows only, where the kraken container cannot reproduce it.

**What would close it.** Find what the test spends its time on (a real `bun:sqlite` store, possibly a spawn of `scripts/store-query.ts`). Remove that cost, or give the test a file-local timeout with the measured reason, as R439 did. Unmeasured: the cause has not been looked at, and Windows timings are not available in the container.
