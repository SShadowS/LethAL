**Filed 2026-11-05 by lethal-code, from R-796c's merge review.** Related: [[R796]], [[R682]], [[R332]], [[R690]].

**What.** [[R796]] raised `IDENTITY_SCHEME` to 43 and left 12 committed baselines at 42; [[R829]] (coord task R-818, GitHub #50) landed first and raised it to 44, so the re-record's target is 44 (ruling 2026-11-05). They are listed in
`LAGGING_SCHEME` (`gate-pages.test.ts`) against this item: six `al-runner-v3.*` baselines, plus `bcdev`, `bcdev.names`,
`bcdev.wrapped`, `hang.single`, `harden` and `tables`.

**Why it matters.** Across a scheme change, a byte-identical twin's mutated text cannot be checked, so a gate prints
"N mutant(s) text-UNVERIFIED", and a mutant changed under an unchanged key would go unseen. On R-796c's v3 gate every
leg still reported 0 text-UNVERIFIED. No verdict moves: fixtures, CDO and DO dump identically under 4.5.0.

**To close, by R332's procedure** (pre-commit, delete, record once, confirm a pass, review the diff, update the page):
- **The BC baselines need a BC server.** None was allocated when this was filed.
- **`al-runner-v3.tables.baseline.json` needs a design first.** Leg T's record branch hard-codes the figures 290/57/59
  and 3 refused tests, while `current`'s pin reads other figures (318/70/18 and 0 refused on alpha.7). So recording on
  `current` refuses. A hand re-record would also break the pins' `from` rows, and `current` cannot move backwards.
  Either the record branch reads the pin, or this file stays on its old build and is recorded some other way.
- Clear each file from `LAGGING_SCHEME` in the commit that re-records it. `gate-pages.test.ts` fails on a listed file
  that has caught up.
