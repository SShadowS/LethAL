**Filed 2026-10-02 at the owner's request.** It was raised by an orphan-process problem in another
project (tree-sitter-al, where `find /` searches ran for hours after their agent finished). Not yet
observed in LethAL: a check on 2026-10-02 found no stray `al-runner.exe`, `alc.exe` or `bun`.

**The risk.** Since R-387 (7ecf6945), `lethal run --backend al-runner` defaults to `--server`, so
every such run starts an `al-runner.exe` daemon. On a normal exit and on an error path,
`backend.close()` sends `shutdown`, kills the daemon and reaps it
(`packages/runner/src/al-runner-server.ts`, `close()`). On a HARD kill of the bun process (an
agent's background task stopped, a lane session closed mid-run, Ctrl-C in some terminals), no
`SIGINT`/`SIGTERM` handler runs `close()`, and Windows does not end a child when its parent dies.
The daemon would then keep running and hold memory, and a later session could not tell it from
another session's run (R345: one al-runner session at a time on this machine).

**Options.**
1. A `SIGINT`/`SIGTERM` handler in the CLI that closes the backend before exit. Cheap, but no
   handler runs on `TerminateProcess` (what a task stop does on Windows).
2. Start the daemon in a Windows job object with kill-on-close, so it dies with its parent
   whatever the kill. Covers the hard kill, needs native help from bun or a helper.
3. Ask al-runner upstream to exit when its stdin closes. The daemon reads commands from stdin, so
   EOF is a clean signal that its client is gone, and it covers every kind of kill.

Option 3 is the most robust and is al-runner's to make; option 1 is worth doing alone either way.

**Measured 2026-10-02, al-runner v2.12.0: the risk does not reproduce.** A bun script spawned
`al-runner.exe --server` with piped stdio, as LethAL does, and the bun process was hard-killed
(`Stop-Process -Force`, which is `TerminateProcess`). The daemon was gone within 5 s. Control: with
no kill, the same daemon was still alive at 20 s. So the daemon already exits when its stdin closes
(option 3), and that covers every kind of kill, so no LethAL change is needed. If a later al-runner
stops doing this, re-run the probe below and reopen.

**The probe.** Measure it: start `lethal run --backend al-runner` on `fixtures/sandbox-app`,
hard-kill bun mid-run, and see whether `al-runner.exe` outlives it.
