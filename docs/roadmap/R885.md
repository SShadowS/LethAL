Found by coord task R-881 (BC.History on al-runner v3, edge-05d692e5e). Evidence: `/coord/handoff/R-881/` (`sd.*`, `bd.*`,
`direct/sd-explain*.txt`, `result.md`). Related: [[R886]].

**What.** Microsoft's test apps expect a CRONUS company with its demo data. al-runner downloads that data from Microsoft's feed, or
reads it from its cache; LethAL always passes `--no-download`. With no demo data in the cache, al-runner refuses every test that reads
a row the dependency apps' install and Company-Initialize would have created ("... could not be created (ADR-013 decision 5)",
"IsEmpty on Workflow: BC holds rows here ..."). ServiceDeclaration: all 60 of its 61 baseline tests that did not pass. BankDeposits: 30
of 75 for this cause; of its other not-green tests, 37 are [[R886]] (15 refused on `System.DateTimeOffset`, 22 by cascade), 4 are a
SaveAsXml refusal, and 2 are plain fails. al-runner prints the cause,
"test data is off: the demo data of build ... is not cached and --no-download is set", but LethAL does not show it, so the user sees
only a red baseline and a near-empty run.

**Measured.** al-runner run directly on one refused ServiceDeclaration test: refused without the data; PASS after one download (549 MB)
into a scratch cache; PASS again with `--no-download` against that cache. A LethAL config naming that cache as `alRunnerV3.cacheDir`
gets the data into every run (round 2).

**What a fix needs.** At least: surface al-runner's "test data is off" note as a LethAL warning, and say in the docs that a
Microsoft-style test app needs the demo data of the `bcVersion` in `cacheDir` (one `al-runner warm` or one run without
`--no-download`). Possibly a `doctor` check. Whether LethAL should ever let al-runner download is the owner's call.

**Landed.** Owner ruling 2026-11-09: al-runner downloads demo data by default.
- `alRunnerV3.downloadDemoData` (boolean). Its default is the one constant `V3_DOWNLOAD_DEMO_DATA_DEFAULT` in
  `al-runner-v3-config.ts` (now `true`); flipping the constant flips the product and the tests that follow it. `false`
  passes `--no-download` (one-shot and `serve`); `true` does not. No CLI flag (the v3 options have none).
- Warning `al-runner-v3-test-data-off`, once per run, from v3's `note: test data is off:` line (matched by that prefix; the
  build is read from it, never matched). Caught in the one-shot call's stdout and stderr, and in the daemon's stderr after every
  request. It names `alRunnerV3.cacheDir`, `al-runner warm` and the opt-out key. The all-failed baseline note
  ("no green baseline tests") gets the same line (`ExecutionBackend.baselineNote`).
- Warning `al-runner-v3-demo-data-download`, once per run, when v3 prints its own `test data: downloading ...` line (so only
  when it really downloads). Limit: it reaches LethAL when the call ends, not before the first byte.
- Gates opt out (`downloadDemoData: false` in `backendCfg` and leg K's section in `al-runner-v3.itest.ts`, and in
  `scripts/v3-timing.ts`), so argv pins, figures and warning sets do not move. The contract probe and the itest's own spawns
  keep their literal `--no-download`.
- Docs: `docs/using-lethal-from-an-agent.md`, `fixtures/README.md`, `README.md`, each saying the feed's copy replaces an older
  Microsoft app in `.alpackages` when the setting is on.
- Pre-run line (warning `al-runner-v3-demo-data-may-download`), once, before the first al-runner call (`status()` or
  `deploy()`): download on, `cacheDir` named, and no `*.bak` at `<cacheDir>/artifacts/<bcVersion>/demo/w1/`. Informational: other
  places al-runner reads from are not looked at. Silent when opted out or when the entry exists. Not printed with no `cacheDir`.
- The download warning ends with the file's size and sha256 (`Downloaded file: N bytes, sha256 ...`), read from the same path at
  the end of the call (one 549 MB read, about 1-2 s, once). v3 prints no CRC-32, so none is recorded. A re-published build shows
  as a changed hash between runs. It is in the warning text only, no report field.

**Evidence: immutability.** Not settled by al-runner's source or docs. ADR-020 says the backup is cached at
`<cache>/artifacts/<build>/demo/w1/BusinessCentral-W1.bak`, downloaded once, "size and CRC-32 checked, then renamed", so the cache
is keyed by build and a download is checked for integrity. Nothing says Microsoft never re-publishes a build's artifact, and the
key holds no hash of the feed's file. The feed was not fetched.

**Evidence: dependency apps.** `--no-download` is ONE switch in al-runner: "Never fetch from the artifact feed (apps, System.app,
demo data)". There is no separate demo-data switch, so with the default LethAL lets al-runner fetch dependency apps too, and a
Microsoft app in `.alpackages` older than the run's build gives way to the feed's copy. R860's refusal (exit 2) exists only
under `--no-download`, so it and its contract-probe leg (own spawn, `--no-download`) still hold for gates and opted-out runs. On the
default path a dependency absent from the feed is expected to come back as the `dependency skipped:` line that R590 already refuses;
not measured (no network use here).

**doctor: not built.** The cache layout is certain on disk (`artifacts/<build>/demo/w1/*.bak`), but a missing entry is not a
fault: al-runner also reads `~/.bcartifacts.cache/sandbox/<build>/w1`, a named `.bak`, `--country`, or another build of the same
major, and a project with no Microsoft app needs none. A check would warn falsely.

**The direct route (owner's pointer, 2026-11-09).** al-runner takes the company data as a parameter: `--test-data=PATH` names a
database backup (`.bak` or `.bacpac`) whose data the tests then run on, and `--test-data-company NAME` picks the company in it (default:
the only one, else 'CRONUS International Ltd.'). A bare `--test-data` insists on test data, so a missing backup stops the run instead of
running without it. LethAL passes none of these. So the likely fix is a config field (for example `alRunnerV3.testData`, a backup path,
plus an optional company) passed to every al-runner process, one-shot and serve, and part of the run's cache key; with it set, a
missing backup is a refusal by name, never a silent run without data. A project's own `.bak` would also cover data a non-CRONUS suite
needs. Not yet measured through LethAL: whether serve takes the flag the same way (`al-runner --help` lists the flags for `test`). Not built by R-885, which built the download switch instead.

**Not the whole story.** With the data, most of those tests then reach .NET types and are refused for want of the sidecar: [[R886]].
