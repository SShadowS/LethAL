**There is no way to run a subset of a project's mutants, so a large app has no cheap first run.** `lethal run` takes `--project` and mutates all of it; the only narrowing that exists is `--skip-known-survivors` (needs a prior run) and `--dry-run` (executes nothing). Continia Document Output generates **11,777 mutants in a single batch** — at an assumed 10 s per mutant that is ~33 hours before the first score, and the real per-mutant cost against a hosted environment is not yet measured. The instrumentation itself is not the problem (2.6 s to parse 551 files, 1.6 s to write): the barrier is that a first run on a real app is all-or-nothing. Wants a way to scope the executed set — by file glob, by object, or a bounded sample — so a project can be trialled before it is committed to. Hit 2026-07-27 attempting exactly that trial.
