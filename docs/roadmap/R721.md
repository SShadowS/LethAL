**Found by the opus review of coord task R-327b (2026-10-24), reproduced.** Same root as [[R720]]'s hang finding,
different shape.

**The shape.** An object-level `var` section declaring a global inside a `#if`:

```al
codeunit 50100 "Repro"
{
    var
        Total: Integer;
#if not CLEAN27
        Extra: Integer;
#else
        Extra: Decimal;
#endif

    procedure Q(): Integer
    begin
        Extra := 0;
        while Extra < 5 do
            Extra := Extra + 1;
        exit(Total);
    end;
}
```

The symbol table does not collect `Extra` into the globals: it is inside a `preproc_conditional_var`, which [[R468]]
and [[R364]]/[[R369]] already record as unread. So `resolveVarRef` returns null for `Extra` in the DIRECT procedure
`Q`. R196's hang check (`classifyHangCapable`) declined on that null, and `remove-assignment` was emitted on
`Extra := Extra + 1`. That mutant loops forever. R164's hazard: a hang-capable mutant deployed with no refusal and no
tag.

**Why it was missed.** R364/R369 ruled on the WRONG-TIER rows these declarations cause (they compile and are
misattributed). Nobody recorded the hang result.

**Reach:** to be measured by the fix's dump diff, split by cause.
