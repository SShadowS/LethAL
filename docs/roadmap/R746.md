**Correction (plan r2, measured).** R739's first reading ("the covered row is a field declaration line") was a
misreading.
- "Data No Trigger" means no OBJECT-level trigger (no OnInsert, OnModify and so on). The table
  `fixtures/sandbox-data/src/DataNoTrigger.Table.al` does have a FIELD-level `trigger OnValidate()` on "No.", and the
  test runs it through `Validate("No.", 'A1')`.
- Measured on bc1 (`itest:chunked`, master 218605f7, with `LETHAL_FENCED_COVERAGE_DUMP`; rows in
  `/coord/handoff/R-746/measure/chunked-rows.jsonl`): the one declared row is table 79301, line 11, in both legs.
  Line 11 is the `if StrLen("No.") > 10 then` line inside the trigger body (the trigger spans lines 9-13).
- In chunked's `--only src/DataMain.Table.al` slice nothing in DataNoTrigger is instrumented, so this is the plain
  fixture file. The test's other row (codeunit 79310, line 60) is not declared in that artifact.
- So the row is in a trigger span. The line map has no named procedure for it, and it is not a naming gap either.

**The rule.** In `warnOnThinFencedCoverage`, when there is no member entry and some declared row exists, warn only if
at least one declared, unrefused row falls in NO known span (a naming gap, R175). The consequence sentence also says
what is really lost: member attribution only. Rows with no named procedure still feed object-level (trigger)
matching.

**The exact quiet set.** Rows in trigger spans, line-0 rows, and R318 shared lines inside a procedure span. None of
them depends on the base-line frame.

**Known blind spot.** A frame shift that lands every row of a test inside trigger spans, shared lines or line 0 stays
quiet.
- Likelihood: low. A real shift (R55, R58) is 1-2 lines on a later object of a multi-object file. On trigger-only
  coverage the old rule could not tell such a shift from correct coverage either.
- The dangerous shift into a neighbouring procedure gives a member entry, so both the old rule and the new one are
  silent there.
- R175's naming-gap reporting is unchanged.
- The selector codeunit masks this check on most full runs: see [[R747]].
