**Counted by coord task R-334 (2026-10-24), checked by R-327b.** This is [[R327]]'s grammar defect in whole-member
form. R327 measured only split-header members (`preproc_split_procedure`) and found 0, so its closure did not cover
this shape. The shape itself was already on record: [[R369]] (closed 2026-10-05 with [[R364]]) noted that "the tree can
stretch that `#if` over whole members", citing DC's `CDCCaptureRTCLibrary`. It recorded 14 wrong-tier rows there and
ruled the fix ("treat a stretched var `#if` as member-level") a reopen. R-302's addendum 3 counted 2 removed rows
inside a `preproc_conditional_var`. This item does not reopen R364/R369's wrong-tier ruling. It adds what they did not
record: the count by arm state, the lost hang refusal, and the correctness check.

**The shape.** An object's global `var` section, followed by a `#if` region holding whole procedures:

```al
codeunit 50100 "Repro"
{
    var
        Total: Integer;

#if not CLEAN27
    procedure Add(Amount: Integer): Integer
    begin
        Total := Total + Amount;
        exit(Total);
    end;
#endif

    procedure Touch()
    begin
    end;
}
```

tree-sitter-al 4.4.1 parses it as `declaration_body > var_section > preproc_conditional_var > procedure`. The
region becomes part of the var section, so `declarationMembers` does not list `Add`, and `buildSymbolTable` does not
index it, even when the build compiles its arm ([[R405]] (a) indexes a member-level `#if` only when it is a direct
member).

Tier-2 claims still apply inside a swallowed TABLE procedure, through the implicit `Rec` (`remove-setrange`,
`swap-modify-flag`). They are correct, because the implicit `Rec` is the table itself, and w6 compiles.

  the c03d5356 dump): a sample of 10 was read by span. Each is a whole statement or `begin ... end` block of the

**Correctness risk: the false-kill class.**
- *Risk.* A newly typed site is a site the engine now believes it understands. A wrong type means an operator rewrites a
  call or an operand that does not compile, or compiles with another meaning. The build then fails the whole batch, or a
  mutant is mislabelled.
- *Where a wrong type can come from.* (i) The wrong arm: a member in the arm the build does not compile. Mitigation: only
  `active` arms are indexed. (ii) Overloads across `#if`/`#else` arms: only the active one is indexed, and an
  `undecided` one stays unindexed, so its names stay "unknown". (iii) A global the member uses that sits in a var-section
  `#if` ([[R721]]): it stays unindexed, so the use resolves to "unknown" and the site is declined. (iv) The implicit
  `Rec` inside a swallowed TABLE procedure: correct, because it is the table itself (R-327b, w6).
- *Proof, three layers.*
  1. **Sweep shapes.** `scripts/r402-shape-sweep.ts` over `w1`..`w7` (`scripts/fixtures/r402/`). Their pinned
     `expected.json` rows turn from "no typed site" into the typed sites, and each emitted instrumented artifact must
     compile with `alc` under all four builds. Add shapes: `w8` an active arm with a `trigger`; `w9` a swallowed
     procedure whose parameter shadows a global; `w10` a swallowed overload set split over `#if`/`#else`; `w11` a call
     into a swallowed member from OUTSIDE it (an active swallowed `Add(): Integer` with an inactive `#else` twin
     `Add(): Text`, so the outside call must type Integer under the active build and not Text); `w12` an inner
     `var_section`, a split member and an `attribute_item` inside the region.
  2. **Per mutant, by splice** (`scripts/r364-mut-compile.ts`): every NEW mutant in the swallowed members compiles under
     the build's symbols and its poisoned copy fails, so `alc` really built the site (`compiledOut` false). Run it on the
     hand-written repro, and on a sample of the corpus additions: all DC's 3 and 10 of BaseApp's 92, spread over the
     operators. A pass under a symbol set that compiles the arm out proves nothing and does not count.
  3. **Red-check each direction** of each guard (the `mutation-red-checker` agent): (a) drop the `active` test, so both

### Option B: patch the grammar under `packages/engine/native`

There is no vendored grammar source to patch. The addon takes `tree-sitter-al` from crates.io at `=4.4.1`. A patch means a
fork: change `grammar.js`, regenerate `parser.c` with the tree-sitter CLI, vendor the crate with `[patch.crates-io]`, and
carry it. What it touches: `Cargo.toml`/`Cargo.lock`; `build.rs`'s source hash (so every built `.node` is stale:
`NativeParserStaleError` on every checkout until rebuilt); `EXPECTED` hashes in `check-native-grammar.ts`, which today
prove the crate equals upstream's WASM inputs, so the check loses its meaning; `GRAMMAR_PIN`; the WASM reference
(`packages/engine/vendor/tree-sitter-al.wasm`), which would need a rebuild or the parser-equivalence comparisons
(`scripts/probe-parser-equivalence.ts`) compare unlike grammars; `statement-containers.json`; and every tree-shape pin and
golden. It also forks the owner's own grammar, whose main is already 463 commits ahead and fixes this shape (R-327c).
**Rejected:** it is the largest change, it needs a fork that must be merged away later, and it buys no more than A.
A middle variant, pinning tree-sitter-al to main `c89c2ecb` by a git or path patch (what R-327c did in a scratch tree),
is Option C with a pre-release: it also brings the new containers (`case_body`, `preproc_conditional_case`,
`preproc_split_*`), each to classify under R217, and it makes the product depend on an unreleased commit.

### Option C: wait for upstream

The draft issue in this item and in [[R327]] was never filed, and need not be: main fixes both shapes (R-327c). Only a
RELEASE carrying `c89c2ecb` or later is needed, and tree-sitter-al is the owner's repository, so the release date is the
owner's. When it lands: the pins (`=4.4.1`, `GRAMMAR_PIN`, `check-native-grammar.ts`, WASM), the new node kinds (R217),
an `IDENTITY_SCHEME` bump with a pre-commitment, and the gates. C costs nothing until then and leaves 235 members at
under-generation (the safe direction) in the meantime.
