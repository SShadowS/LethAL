**Counted by coord task R-334 (2026-10-24), checked by R-327b.** This is [[R327]]'s grammar defect in whole-member
form. R327 measured only split-header members (`preproc_split_procedure`) and found 0, so its closure did not cover
this shape. The shape itself was already on record: [[R369]] (closed 2026-10-05 with [[R364]]) noted that "the tree can
stretch that `#if` over whole members", citing DC's `CDCCaptureRTCLibrary`. It recorded 14 wrong-tier rows there and
ruled the fix ("treat a stretched var `#if` as member-level") a reopen. R-302's addendum 3 counted 2 removed rows
inside a `preproc_conditional_var`. This item does not reopen R364/R369's wrong-tier ruling. It adds what they did not
record: the count by arm state, the lost hang refusal, and the correctness check.

**The shape.** An object's global `var` section, followed by a `#if` region holding whole procedures:

```al
codeunit 50100 "Repro"
{
    var
        Total: Integer;

#if not CLEAN27
    procedure Add(Amount: Integer): Integer
    begin
        Total := Total + Amount;
        exit(Total);
    end;
#endif

    procedure Touch()
    begin
    end;
}
```

tree-sitter-al 4.4.1 parses it as `declaration_body > var_section > preproc_conditional_var > procedure`. The
region becomes part of the var section, so `declarationMembers` does not list `Add`, and `buildSymbolTable` does not
index it, even when the build compiles its arm ([[R405]] (a) indexes a member-level `#if` only when it is a direct
member).

state):

**Correctness, compile side: holds (R-327b, 2026-10-24).** R-302's run-003 guard ("unindexed means unknown") covers
this shape. Inside such a member, `resolveIdentifierType` and `lookupVar` answer nothing, and `allProcedureLikes`
counts its names, so a same-named direct procedure is never "unique" and `declaresProcedure` sees a swallowed table
`Validate`. The R-327b review red-checked each of the three: breaking any of them makes w3 or w6 fail `alc`. Two
Tier-2 claims still apply inside a swallowed TABLE procedure, through the implicit `Rec` (`remove-setrange`,
`swap-modify-flag`). They are correct, because the implicit `Rec` is the table itself, and w6 compiles.
- **DC's 86 mutants inside the 22 members** (`empty-block` 22, `remove-assignment` 20, `void-method-call` 44, from
  the c03d5356 dump): a sample of 10 was read by span. Each is a whole statement or `begin ... end` block of the
  member it names, in the arm DC's build compiles. Members in a compiled-out arm get no mutant.
- **Three pinned shapes in `scripts/fixtures/r402/`, run by `scripts/r402-shape-sweep.ts`.** Each emitted spec set's
  instrumented artifact compiles with `alc` under all four builds.
  - `w1_var_swallowed_members`: two swallowed members.
  - `w2_var_swallowed_else`: an `#if`/`#else` pair; each build mutates its own arm only.
  - `w3_var_swallowed_typing`: R327's two typing failures in this shape. A swallowed `Pick(X: Integer; Y: Text)`
    with globals `X, Y: Integer` gets no `swap-call-arguments` on `Show(X, Y)`. A swallowed overload `Foo(T: Text)`
    stops `Foo('x') + Foo('y')` in a direct member from being typed `Integer`, so it gets no `swap-additive`.
  - `w6_var_swallowed_table` (the review's shape): a swallowed table `Validate` overload (R-302's C2). The
    codeunit's `R.Validate(N, 5)` stays a call and never becomes an assignment to a non-field.
- **Per mutant, by splice (`scripts/r364-mut-compile.ts`, a hand-written repro):** under the build's symbols (`[]`),
  every mutant inside the swallowed members compiles, and its poisoned copy fails, so `alc` really built each site.
  Under `[CLEAN27]` those members are compiled out, so a pass there proves nothing, and no mutant is generated there.

**Correctness, hang side: was WRONG, fixed on lethal/r327b.** The R-327b review found that R196's hang refusal was
lost inside a swallowed member. `classifyHangCapable` resolves a loop write's target by declaration. "Unknown"
reached it as null, and it declined on null. So a write to a variable its loop condition reads (`while J < 5 do
J += 1;`, a local or a global) got `remove-assignment` and `shift-integer` with no refusal: mutants that can loop
forever (R164). The direct twin was refused.
- **The fix.** When the target, or a member target's receiver, does not resolve and the engine's three-state lookup
  (`declarationStateAt`) says "unknown" rather than provably absent, the write is matched by NAME against the
  enclosing loops' exit conditions and any enclosing `for`'s control variable (R480). This is R-364's existing
  fallback for unindexed objects, widened. It only adds refusals.
- **The same fix covers two other shapes with the same root:** [[R721]] (a global declared inside a var-section
  `#if`) and R302's every-arm-ambiguous names.
- **Pinned by:**
  - `packages/builtin-tier1/tests/r720-unknown-hang.test.ts`, red-checked in each direction;
  - the sweep shapes `w4_var_swallowed_loop` (20 -> 16 specs under `[]`), `w5_var_cond_global_loop` (7 -> 6) and
    `w7_for_control_unknown`.
- **Reach** (`corpus-snapshot.ts diff`, `/coord/handoff/R-327b/diff/`): **0 deployed mutants change in any corpus.**
  - Fixtures (23 projects, vs a913261f) and DC (14 projects, vs 65776e74) are identical.
  - BC.History (519 projects, vs f30c9190): every identity key is unchanged (added 0, removed 0, tags 0).
  - Only the hang-refused counter moved: BaseApp +5, Email - Outlook REST API +1, System Application +18. The
    `skipped` counter fell by the same amounts. So each added refusal sits in a file that cannot carry the mutation
    selector (`canCarryMutationSelectorVar` is false), whose sites were never deployed.
  - In the corpora, the swallowed members' loop writes (0 by parse, R-327b review) and the other two causes deploy
    nothing different.
- **Gates on head 266d416b**, all PASS as pre-committed (`2026-10-24-r720-hang-unknown-precommitment.md`, master
  1dc4bb48): `itest:bcdev`, `itest:tables` and `itest:chunked` on bc3, and `itest:alrunner-v3` (every leg).

**The cost that remains.** Sites that need a name's type are not generated inside these members. Measured on the
shapes: `swap-additive` on `Total + Tmp` (w1), `swap-call-arguments` on `Show(X, Y)` (w3), and `return-value` on
`exit(Name + '!')` (w1's `Tag`). This is under-generation, the safe direction.

**Ruling (R-327b): keep it open, deferred.** R327's reopen condition ("a project that hits the shape") is met:
BaseApp and DC both hit it. Recovery is still deferred, for two reasons:
- A local recovery (read members out of a `preproc_conditional_var`, then index them by R405 (a)'s arm rule)
  loosens a refusal. It would need a pre-commitment of the added sites, a deep review and a false-kill hunt.
- The grammar fix removes the defect at its root, together with R327's split-member form. tree-sitter-al is the
  owner's repository, so the draft issue below is the owner's to post.

**To close.** When tree-sitter-al ends the var section at the `#if`: pin `w1`..`w7` as direct members, re-measure the
census, and pre-commit the added sites.

**Not checked (the review's suspects).** Other readers that treat a null `resolveVarRef` as "absent" may still
decline where "unknown" should refuse: R572's `var`-out flag check, and the r531/R696 write collectors, which read
null as the implicit `Rec`. Their direction was not determined. They are listed here so the next reader of
`declarationStateAt` checks them.

## Draft upstream issue (not filed; SShadowS/tree-sitter-al)

> **A `#if` region of whole procedures after an object-level `var` section is parsed inside that `var_section`**
>
> Input (valid AL; `alc` compiles it with and without `CLEAN27`): the codeunit above.
>
> Actual: `declaration_body > var_section > preproc_conditional_var > procedure` (the procedure `Add` is a child of
> the var section).
>
> Expected: `declaration_body > [var_section, preproc_conditional > procedure, procedure]`. A plain `procedure` in
> the same place, and the same region placed before the `var` section, are already siblings of the `var_section`.
>
> Same root as the split-header case (a `#if`-split procedure in the same place lands in `var_body`). It is common in
> Microsoft's Base Application (`#if not CLEAN27` obsolete overloads after the globals): 161 members in 20 files.
