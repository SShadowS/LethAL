**The hub credited tests with coverage they could not have produced — measured on Document Output as 77 vacuous `survived` verdicts — and the mechanism was NOT the one first filed here.** R58's differential showed the five `ChangeAutomaticToManual_*` tests sharing one identical 11-procedure covering set equal to the `CreateOrSendAutStatements` call tree, proven unreachable for `...WhenNoLastDate...` by its call tree (literal `0D` LastDate -> immediate exit; the setup library only INSERTs records). The first filing blamed `buildCoverageMap` matching the payload by `testObjectId` only — **that hypothesis was then MEASURED WRONG, twice.** (1) A raw-payload probe (`packages/runner/scripts/probe-r63-hub-payload.ts`, run against the DO environment on BC28 and the sandbox fixture on Cronus281) shows a single-method run returns exactly ONE coverage entry keyed by a STABLE per-method `testMethodId` with per-method-correct content (fixture: 6 vs 4 procedures, disjoint as written; DO: `WhenNoLastDate` -> exactly `ChangeAuatomaticToManual` + one unresolved local — right). No multi-entry payload, no cross-call accumulation, nothing for a wrong `find` to grab. (2) The 11-set is not another method's coverage — it is EXACTLY `{the one public the test genuinely executes} U {ALL TEN local procedures of codeunit 6175297}`. **The real mechanism: `buildCoverageMap`'s local-procedure EXPANSION.** `AppMethodIndex.lookup` resolves public members only (locals are absent from SymbolReference.json — re-verified against DO's compiled app, whose `Codeunits[].Methods` lists exactly the 5 publics; the method ids are a hash that did not yield to java/djb2/fnv/crc32/dotnet-classic candidates — recorded so nobody re-tries blindly), so the fallback credited EVERY local `findLocalProcedureNames` could grep from source whenever ONE unresolvable member executed. The fixture runs (one local, one test) made it look exact; on DO (ten locals, five tests) it detonated into R29's exact shape: confident, non-empty, WRONG covering sets, and 77 mutants in never-executed procedures scored `survived`. The expansion's own doc comment called it safe because it "only ever turns a no-coverage skip into an actual test run, never hides a real kill" — true, and beside the point: it manufactures false SURVIVORS, the error class this project treats as the worst kind. **Fix shipped:** (a) the expansion is deleted — an unresolvable member is emitted at OBJECT level, feeding `byObject` (the R29-safe branch, one precision level coarser), and `findLocalProcedureNames` is gone with it; (b) R61's scope check landed with it — coverage for objects the compiled artifact does not declare (Base App, test framework, `Codeunit:71002`) is now SKIPPED on the hub path, same rule the fenced path has; (c) since `coverageFilter`'s object-level FALLBACK 1 is trigger-only, a mutant in a genuinely-executed LOCAL would now report `no-coverage` while running (measured live: the fixture's three `LogAudit` mutants moved survived -> no-coverage, failing the frozen gate) — so the manifest now carries `procedureScope: "local" | "public"` (schemata emits it from the parse; absent on triggers) and `coverageFilter` has an unnamed-member fallback keyed on it: local mutant + member miss + some unnameable member observed executing in the object -> covered at object grain, attribution `object`. The `=== "local"` gate is the load-bearing part: a PUBLIC procedure whose member key misses DID NOT EXECUTE, and widening it would re-manufacture the vacuous survivors this item exists to delete; a pre-existing test ("an ordinary procedure mutant is NOT credited by an object-level-only entry") pins exactly that doctrine and went red on the un-gated version. Every piece red-checked by revert (expansion deletion, scope skip, fallback, gate, scope emission). Frozen gates re-verified per-mutant on the new code: `itest:bcdev` 3/10/3 (LogAudit mutants back to `survived`, now via the honest object-grain path), `itest:tables` 64/9/2 with `untargetedTriggers` 0, `itest:alrunner` 3/13/0. Hub-mode verdicts on DO are unchanged by construction (same covering sets, coarser honest attribution) — the verdict-level answer for DO remains R58's fenced mode.
