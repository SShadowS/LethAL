**Found 2026-10-08 by R-508's adversarial plan review (I2), by reading the code. Not verified live.** A false-kill
risk, narrowed but not closed by [[R508]].

**What.** R508 corrects a lease-lost batch in the store twice: once at the moment of loss (`LeaseSession`'s
`onLost`, called by `noteLeaseLost` after the latch) and once in the session's `finally` (`invalidateLostBatch`).
There is no SIGINT/SIGTERM handler, so Ctrl-C or a kill skips every `finally`. What is left is a verdict recorded
AFTER the loss note and BEFORE such a crash. Example: the heartbeat notes the loss while a `RunMutant` is in flight,
`onLost` rewrites the rows recorded so far, then the in-flight run answers a position-1 `timeout`, which is recorded
as `timeout-killed` with no further dispatch, and the process is killed before the `finally`. The run is unfinished
and that row is not `error`, so `--resume` carries the kill. The R508 test "a verdict recorded after the loss note is
corrected by the session's finally" shows the row; only the `finally` corrects it.

**Not a fix: a positive "batch completed" marker.** The store has no batch-completion transaction, and without
`maxGuardsPerBatch` the whole project is ONE batch, so every crash would leave the batch unmarked and `--resume`
would carry nothing. That breaks [[R47]] on every crash.

**Proposed fix: a negative record, written at the loss.**

- A new `lost_batches (run_id, batch_index, note)` table, created if absent. No migration of existing rows and no
  `IDENTITY_SCHEME` change.
- `onLost` inserts the row in the same synchronous write as today's `invalidateBatch`.
- Readers exclude a lost batch's rows whatever their verdict: `mutantVerdicts` (the reader behind
  `buildResumeIndex`; the exclusion belongs in the reader, not in `strandedKeys`), `findResumableRun`'s `EXISTS`
  and its sibling queries (`unfinishedRunUnderOtherScheme`, `unfinishedRunUnderOtherSymbols`,
  `unfinishedRunUnderOtherCoverageMode`), and `findBaselineSnapshot`.

**To close.** Reproduce offline first: R508's crash stand-in (a store that breaks when teardown starts) combined
with a verdict recorded after the note, then a resume that carries it. Then add the table and the reader
exclusions. Pin both directions (a lost batch's late verdict is not carried; a completed batch before it still is),
red-checked. Plan: `/coord/handoff/R-508/plan.md` §"Crash window".
