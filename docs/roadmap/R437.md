**Found 2026-10-04, running `bun update` for the kraken no-pinning change.** `bun outdated` shows
`typescript` 5.9.3 current, 5.9.3 within range, 7.0.2 latest. 7.0 is the native (Go) compiler, so
`tsc --build`, project references and the `exactOptionalPropertyTypes`/strictness behaviour must be
re-verified rather than assumed. The kraken tooling repo already runs TypeScript 7.

Evidence: `bun outdated` output on branch `lethal/kraken-corpora` (commit "bun update: in-range
updates"). The update to 5.9 also surfaced TS2589 and TS7022 in two test files (fixed there), a
sign that checker changes reach this code base.

Gate: bump the range, then `bun run typecheck` (`tsc --build --force`) clean on every package,
`bun scripts/verify.ts`, and both CI jobs (`check` on Windows, `unit-linux`) green. Fix type errors
by annotation, not by loosening `tsconfig` strictness.

**Fixed (R-437, 2026-10-08): migrated to TypeScript 7.0.2.** Measured first, on origin/master
736dd7ff:
- `typescript` ^5.9.3 -> ^7.0.2. Under 7.0 `tsc --build --force` checks all nine projects and the
  checker raises NOTHING in the code base. All 279 errors came from one cause: 7.0's package no
  longer ships the JavaScript compiler API (its main export is only the version; the new API is
  `typescript/unstable/*`, a client to the Go process). Five files parse TypeScript with the old API:
  `scripts/generate-schemas.ts` and four tests (`refusal-sites`, `baseline-wiring`,
  `format-failure`, and the `type-leaf-paths` helper). They now import Microsoft's
  `@typescript/typescript6` instead of `typescript`: a one-line wrapper over `@typescript/old`,
  which the lockfile resolves to typescript 6.0.3, the old API as its own package. That is
  the whole change: two dependency lines and five import lines; no type annotation and no
  `tsconfig` flag moved.
- Strictness is unchanged, measured, not assumed: a probe with one violation per flag
  (`noImplicitAny`, `strictNullChecks`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `strictBindCallApply`)
  gives the same eight errors with the same codes under 5.9.3, 6.0.3 and 7.0.2. The opus build review added six more strict checks
  (`strictPropertyInitialization`, `useUnknownInCatchVariables`, `strictFunctionTypes`,
  `noImplicitThis` and two more): same codes under 5.9.3 and 7.0.2. It also measured `tsc --build
  --force` writing the identical 2273 files into `packages/*/dist` and `scripts/dist` under both,
  so the build loop's dist trap and the clean-dist hook apply unchanged, and found the 6.0.3 parser
  reads all 727 tracked `.ts` files into the same trees as 5.9.3.
- `bun run typecheck` takes 1.2 s, was 12 s. `generate-schemas.ts` writes byte-identical schemas.
  `verify` passes; `bun run mutate` (Stryker, which uses Babel, not `typescript`) runs as before.
- `scripts/generate-schemas.ts` is not in the `scripts` project's `files`, so the typecheck never
  saw its import; it would have failed only when run. Admitting it is a separate decision (R119's
  list is explicit).
- The old-API package is a dev dependency until the tests and the schema generator move to the
  7.x API, which is still `unstable` in 7.0.
