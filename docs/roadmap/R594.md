**Filed 2026-10-21** at the orchestrator's ruling during R-586.

**What.** Cronus28 (BC 28.4 DK) is parked by the owner's ruling. It was the only server holding the Continia stack
that Continia Document Output (CDO) depends on: Continia Core, System Application, Delivery Network, Connector App
and Core Internal Activation, installed Global. The R546 CDO slice (`CDO Recipient Mgt.`, 63 mutants, 21 tests) was
measured on it. The replacement gate servers bc1, bc2 and bc3 (BC 28.4 W1 on Linux, [[R589]]) do not have those
apps.

**Effect.** No live BC measurement of a CDO slice is possible. [[R586]]'s new `al-runner-v3` gate therefore uses
R546's committed reports (`docs/measurements/r546/bc-A`, `bc-B`) as a FROZEN oracle, named in its pre-commitment as
"measured on Cronus28, BC 28.4 DK, with the Continia stack; not re-measured live because Cronus28 is parked and the
bc servers lack the Continia apps". A frozen oracle cannot catch a BC-side change.

**To close (owner).**
1. Install the Continia stack on one of bc1, bc2 or bc3, Global, at the versions R546 pinned (the R396 pre-commitment,
   addendum 2). Publishing third-party apps Global is host and owner territory.
2. Check whether CDO needs the DK localization the CDO tests use. bc1 to bc3 are W1.
3. Then re-measure the R546 slice live there, and compare per mutant with the frozen reports.

containers and the orchestrator gave this lane bc3.

  each of the 11 Microsoft apps of the pinned packagesDir must be resident at 28.4.53241.53758. Only then does it
  publish the 5 sha256-pinned Continia apps, dependencies first, in Dev scope.

  frozen reports are not comparable there. The tool stopped before publishing anything. All 5 Continia apps, the CDO
