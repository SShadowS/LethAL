Coord task PR-165, 2026-11-18. Related: [[R614]], [[R1128]], [[R885]].

**What happened.** PR-162's full al-runner-v3 gate failed N1, N1E, N1S, WR and WRE on one extra warning,
`al-runner-v3-test-data-off` ("the demo data of build 28.0.46665.47126 is not in cacheDir"). It was first read as a
master-wide change, because master failed the same way. That check had run in the same worktree.

**Measured cause** (evidence in `/coord/handoff/PR-162/`):
- In a fresh worktree, leg N1 PASSES with no test-data line at master `938740d8`, at PR-159's head `dd97842a`, and
  either side of PR-151 (`gate-n1-master-fresh.log`, `gate-n1-pr159head.log`, `gate-n1-6c80a839.log`,
  `gate-n1-907ec1c5.log`).
- The same worktree FAILS N1 after the whole symbol tar is extracted into it (`gate-n1-master-fulltar.log`). It passes
  again with only `fixtures/sandbox-names-tests/.alpackages` moved away (`gate-n1-no-namestests.log`).
- The leg's `packagesDir` is the Microsoft deps it prepares, but al-runner v3 also reads the test project's own
  `.alpackages`. A full extraction puts Base Application 28.0 there, so v3 treats the app as Microsoft-style and,
  with no 28.0 demo data cached, turns test data off.
- PR-162's worktree had the whole tar for `compile:fixtures`. Kraken's lane setup also extracts the whole tar by
  design.

**The fix: the gate is immune, rather than refusing,** because a refusal would fight `compile:fixtures` (orchestrator
ruling).
- **`backendCfg`** passes each test dir through `v3GateTestDir` (`fixture-symbols.ts`). A test dir under `fixtures/`
  with its own `.alpackages` is copied, once per run, to a temp folder without it.
- **Used as they are:**
  - dirs that own one of the gate's two prepared folders (`sandbox-tests`, `sandbox-data-tests`);
  - dirs without one;
  - dirs outside `fixtures/`, such as a leg's scratch copy. Leg X (c2) edits its copy after building the backend, and
    the first version, which staged scratch copies too, failed it (the Opus review caught this; seen live in
    `/coord/handoff/PR-165/gate-full-fulltar.log`).
- **The three legs that copy a fixture test dir to scratch** (N1S, and the two order legs) use `copyTestDirForV3`,
  which leaves a stray `.alpackages` behind.
- **A fresh worktree** has none of these folders, so its legs read the same inputs as before.
- **Measured:**
  - with the whole tar extracted, the five legs pass (`/coord/handoff/PR-165/gate-5legs-fulltar.log`);
  - with the final head, so does the full gate (`gate-full-fulltar2.log`).
- **Tests** are in `fixture-symbols.test.ts`, red-checked:
  - with the copy filter disabled, the copy test goes red;
  - with the `fixtures/` scoping removed, the leg X (c2) test goes red.
