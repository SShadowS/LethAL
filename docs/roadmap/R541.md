**Priority.** Filed 2026-10-09 by the R534 build (plan r2, roadmap item 5; review F1). A FALSE
KILL is possible.

**What.** al-runner discovers an expectations manifest beside the test bundle on its own and
rewrites a row's status from it, recording an `expectation` on the row. Read from its source at
43f7617 (not measured by LethAL): `FailManifestDrift` turns a test that PASSED into `fail`, which
LethAL scores as a kill; `PassOos` turns a failure into `pass`, which hides a kill. LethAL neither
reads the row's `expectation` field nor turns the discovery off, so a test project that carries such
a manifest changes LethAL's verdicts without saying so.

**Evidence.** `/coord/handoff/R-534/review-plan-opus.md` F1; `/coord/handoff/R-534/measure.md`
(the one-shot row's fields include `expectation`); `parseAlRunnerPayload` and
`verdictFromRunnerTest` in `packages/runner/src`.

**To close.** Measure both rewrites on the current build. Then either turn discovery off in the argv
and the daemon request (if al-runner has a switch), or refuse or flag any row that carries an
`expectation`, never scoring it as a kill. A test per direction, red-checked.

**Measured by R-541 (2026-10-22); to be closed by [[R654]], the retirement of the .NET al-runner.**
Evidence: `/coord/handoff/R-541/measure.md` and `wip-report.md`.

  - Discovery is silent. It walks up from every bundle folder, then from the working directory.
  - `--server` rows carry no `expectation` field.
  - v2 has no off switch; only `--expectations <dir>` overrides the discovery.
