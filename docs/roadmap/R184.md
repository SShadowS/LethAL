**R178's export embeds the full source of every mutated file, and nothing stops that file being
committed.** `toMutationElements` reads each mutated file off disk and assigns it to the schema's
`source` field, because the schema REQUIRES it: a report without source renders nothing, which is
the whole reason the format carries it. The projection is correct. The gap is everything around it.

**What EXISTS, stated first because this row's first draft got it wrong.** A commit guard is
already in place: `scripts/redact-campaign-report.test.ts` carries a test named "R178: no exported
mutation report is COMMITTED, because it embeds full source", which lists tracked files and expects
none to match. The command also warns on every run. The first draft of this row claimed no guard
existed; that was wrong, and the error was mine for grepping the script and `.gitignore` without
grepping the test.

**What is actually missing, each verified.**

1. **The commit guard matches by FILENAME, not by shape.** Its filter is
   `/mutation-report.*\.(json|html)$/i` over `git ls-files`. A report written to `out.json`,
   `elements.json`, `report.json`, or any name not containing "mutation-report" passes straight
   through. The test's own neighbouring test argues that a hand-maintained claim is what "let six
   reports sit unswept"; a filename convention is the same class of assumption.
2. **No `.gitignore` entry.** The command takes `--out <path>`, so the output lands wherever the
   user points it, commonly inside the repo they are measuring. Nothing declines it.
3. **`scripts/redact-campaign-report.ts` does not know the format exists.** It redacts
   `originalText` / `mutatedText` and only inside a top-level `mutants` array. A mutation-elements
   report has no top-level `mutants`, so it takes the "no `mutants` array" branch and dies with
   `this is not a SessionReport` — a message that tells the user the file is unrecognised rather
   than that it is dangerous.

**Why this is a correctness risk and not a nit.** The 2026-08-09 ruling exists because two Continia
Document Output reports were committed with 2,550 source-bearing fields before anyone noticed. The
guard built afterwards covers exactly one shape, `SessionReport`, and R178 introduced a second
source-bearing shape without extending it. The repo is PUBLIC, and redaction after a push changes
only what a fresh clone sees.

**The shape of the fix, not a prescription.** Strengthen the EXISTING guard from a filename regex
to a SHAPE test (parse each tracked `.json` and refuse any with root `schemaVersion` plus `files`
plus a file entry carrying `source`); add a `.gitignore` entry for the conventional output name; and
teach the redactor to DETECT the format and refuse it by name rather than dying as "not a
SessionReport". The refusal is the right answer rather than redaction: a mutation-elements report
with `source` blanked is still schema-valid but renders nothing, so "redacted" would be false in
both directions.

**Related and separate:** the same script honours `--check` only as `argv[0]`, so
`redact-campaign-report.ts <file> --check` runs in WRITE mode and rewrites the file before dying on
the unreadable `--check` path. A check flag that fails open, in the script guarding a public repo.
