**R178's export embeds the full source of every mutated file, and nothing stops that file being
committed.** `toMutationElements` reads each mutated file off disk and assigns it to the schema's
`source` field, because the schema REQUIRES it: a report without source renders nothing, which is
the whole reason the format carries it. The projection is correct. The gap is everything around it.

**What ALREADY EXISTED, stated first because this row's first draft was wrong about most of it.**
R178 shipped with two of the three protections this row originally claimed were absent: a commit
guard (`scripts/redact-campaign-report.test.ts`, "R178: no exported mutation report is COMMITTED"),
and `.gitignore` entries for `mutation-report.json` / `mutation-report.html`. The command also warns
on every run. **The first draft missed both because it grepped for `mutation-elements`, and the
entries say `mutation-report`.** A row filed on a wrong search term is worse than no row, and this
one had to be narrowed twice while being fixed.

**The two REAL gaps, both now fixed.**

1. **The commit guard matched by FILENAME, not by shape.** Its filter was
   `/mutation-report.*\.(json|html)$/i` over `git ls-files`, so a report written to `out.json` or
   `elements.json` passed straight through, and `--out` is the user's to name. The test's own
   neighbouring test argues a hand-maintained claim is what "let six reports sit unswept"; a
   filename convention is the same class of assumption. FIXED: it now parses every tracked `.json`
   and refuses any matching `isMutationElementsExport`, with a second test proving that predicate
   fires, since every tracked file being clean would let a broken predicate pass unnoticed.
2. **`scripts/redact-campaign-report.ts` did not know the format existed.** It redacts
   `originalText` / `mutatedText` and only inside a top-level `mutants` array. A mutation-elements
   report has no top-level `mutants`, so it took the "no `mutants` array" branch and died with
   `this is not a SessionReport` — telling the user the file was unrecognised rather than that it
   was dangerous. FIXED: detected by shape BEFORE that branch and refused by name, with a message
   saying it must not be committed at all. Verified end to end: exit 1, the file untouched, and
   `--check` refuses it too.

Making the predicate importable required guarding the script's CLI body with `import.meta.main`,
because importing it previously executed the CLI against `bun test`'s argv and died on the usage
error.

**Why this is a correctness risk and not a nit.** The 2026-08-09 ruling exists because two Continia
Document Output reports were committed with 2,550 source-bearing fields before anyone noticed. The
guard built afterwards covers exactly one shape, `SessionReport`, and R178 introduced a second
source-bearing shape without extending it. The repo is PUBLIC, and redaction after a push changes
only what a fresh clone sees.

**The shape of the fix, not a prescription.** Strengthen the EXISTING guard from a filename regex
to a SHAPE test (parse each tracked `.json` and refuse any with root `schemaVersion` plus `files`
plus a file entry carrying `source`); add a `.gitignore` entry for the conventional output name; and
teach the redactor to DETECT the format and refuse it by name rather than dying as "not a
SessionReport". The refusal is the right answer rather than redaction: a mutation-elements report
with `source` blanked is still schema-valid but renders nothing, so "redacted" would be false in
both directions.

**Related and separate:** the same script honours `--check` only as `argv[0]`, so
`redact-campaign-report.ts <file> --check` runs in WRITE mode and rewrites the file before dying on
the unreadable `--check` path. A check flag that fails open, in the script guarding a public repo.
Filed as [[R185]].

**Also fixed in the same pass, and the reason this row was opened at all:** the projection declared
`Ignored` in its status vocabulary and never emitted one, reading `excludedSites` zero times. Every
site LethAL deliberately refused rendered identically to a file it simply found nothing in, and
`lossesFor` did not mention the omission, so it was a SILENT loss of exactly the kind this module's
own doc comment forbids. Refusals now become one `Ignored` entry per excluded FILE, grouped under
the reason so a renderer can select them as a set, with the site count in the description. The
lossy half is declared rather than assumed: one entry per file and not per site, because
`excludedSites` records a count and no spans. Red-checked by breaking the merge that keeps a file's
real mutants alongside its refusals, which is the path that could lose data silently.
