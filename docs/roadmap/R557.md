**Found 2026-10-09** by the Opus review of the R-551 plan (finding M6), measured on al-runner
`v2.12.0-main.c5bbaf89` with invented names. Filed at once at the orchestrator's ruling.

**What.** al-runner names each test row `{CLR type}.{CLR method}`, and a quoted AL method name is
mangled into a CLR identifier:
- `"Stone Quoted"` → `Codeunit61511.Stone_Quoted`;
- `"Dot.Name"` → `Dota46Name`;
- `"Plus+Paren(x)"` → `Plusa43Parena40xa41`.

LethAL's `qualifiedTestName` (`al-runner-backend.ts`) builds the AL name, so both `--test` and R551's
`--test-exact` select nothing (exit 6) for such a test, on both R488's path and R551's.

**Why it matters.** A mutant that only such a test would kill cannot be killed on al-runner. If
nothing notices, it reads `survived`: a FALSE SURVIVE (class 1, under-reporting). The open questions,
not yet measured:
- How many tests in the fixtures, CDO, DC, DO and the BC.History test apps have quoted names?
- What exactly does al-runner report for them: missing, skipped, or silently absent?
- Does LethAL's baseline count such a test as green, or as not green?
- Does the covering-set logic credit it?

If any of these is silent, LethAL is blind.

**To close.**
1. Measure the questions above (counts per corpus, and al-runner's and LethAL's behaviour on a
   quoted-name test at baseline and per mutant).
2. Fix it: map an AL name to al-runner's CLR name using the same rule al-runner applies, or match
   rows another way, and refuse loudly anything unmapped.
3. Red test each direction; live evidence on a fixture with a quoted-name killer.

**Measured (2026-10-09).** `/coord/handoff/R557/measure.md` and `/coord/handoff/R-557/measure.md`:
- quoted or renamed `[Test]` names: fixtures 0, CDO 0, DO 0, DC **248 of 1,902** (13.0%), BC.History
  2 of 48,136; a leading digit is 82 of DC's 248;
- not only quoted names: an UNQUOTED test named after a C# reserved keyword (`Default`, `Delegate`,
  `Finalize`) is renamed too (`_Default`);
- al-runner answers the AL name with exit 6 and no row (one-shot) or a suite with the row under the
  mangled name (`--server`); LethAL read the test as a baseline `error`, dropped it from every
  covering set, and scored each mutant only it kills `survived` (coverage `none`) or `no-coverage`
  (coverage `al-runner`): a FALSE SURVIVE, on both builds and both transports;
- bcdev selects by the AL name and is not affected.

**Fix.** Plan `docs/superpowers/plans/2026-10-09-r557-alrunner-test-name-mangling.md` (r2), predictions
in `docs/superpowers/specs/2026-10-09-r557-names-precommitment.md` (r3). Upstream: al-runner #5572
asks for the AL name on the row.
- `alRunnerMethodName` (`al-runner-transport.ts`) computes BC's C# name for the AL method: a space
  or `"` to `_`; a leading non-start unit gets a `_`; any other non-identifier unit is `a<code>`; an
  ASCII result whose upper case is a reserved keyword (with `ſ` read as `s`) gets a `_`, so unquoted
  `Default` is covered; every Unicode format (Cf) unit is deleted last. 58 measured names, both
  builds, pinned. `qualifiedTestName` uses it, so every consumer does (the argv, row lookup, R488
  siblings, coverage keys).
- A session-suite test al-runner has no row for stops the session by name
  (`AlRunnerTestNameError`): one-shot on exit 6 or no row equal to the name sent; `--server` only on
  a clean answer (exit 0 or 1, every row a pass or fail `Codeunit<id>.` row), or on an unclean
  one when the missing test's own codeunit has a run row (`Codeunit<id>.<method>`, not `<ctor>`,
  `OnRun` or `<event>`), since one emit-excluded codeunit elsewhere makes every answer unclean.
  Otherwise today's `error`, naming the rows that made it unclean. The stop lists only missing
  SESSION-SUITE tests (on an unclean answer, only those of a codeunit that ran). A test
  kept in an undecided `#if` arm (R403) keeps its `error` (`AL_RUNNER_UNDECIDED_ARM_MISSING`), named
  in one `al-runner-undecided-test-missing` warning per batch.
- C1: a prior al-runner run lends nothing unless it is an R557+ run. Store column
  `runs.al_runner_names` (INTEGER, added by `migrate()`; NULL on every older row, read as untrusted,
  like R442's `carry_hidden`) is set to 1 at run creation by every R557+ al-runner session.
  `runLendsAlRunnerNames` refuses an al-runner run without it, so EVERY al-runner run recorded before
  R557 is refused, including one that carried false verdicts without a baseline row showing it (a
  resume of a resume, a resume-only run, `known-survivor` rows). As a second check, a marked run whose
  baseline holds a renamed test as `error` is refused too. Refused means: `--skip-known-survivors`
  skips none of its survivors (`history-al-runner-test-names`); `--resume` carries none of its
  verdicts, so R53 stranded keys run again too, and the RESUMED banner says why
  (`resumedFrom.carryRefused`); no baseline snapshot of it is reused (`resume-al-runner-test-names`).
  A renamed test that FAILED does not taint, and a bcdev run is never refused by either check.
- R123 gains `test-name-mangling`: one `--test Codeunit50012.` run over eleven probe methods, whose
  row set must equal the rule's names.

  `itest:alrunner` and the new `itest:bcdev-names`, frozen at 36 / 0 / 0 (`fixtures/README.md`
  §"sandbox-names (R557)"); master reads 6 / 30 / 0 and 6 / 0 / 30 there.
