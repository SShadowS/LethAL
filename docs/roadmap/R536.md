**Filed by R-497's opus build review (2026-10-09), Minor findings M1 and M4.** Neither can produce a false kill:
coverage only chooses which tests run against a mutant, so a misplaced line moves a mutant between `survived` and
`no-coverage`.

**1. Object kinds beyond codeunits are unmeasured on BC.** [[R497]] admits the one-arm wrapped shape for every
object kind. The R-300b probe and `itest:bcdev-wrapped` are all codeunits. The R-497 census's admitted files in the
real corpora (BaseApp 241 files, 5,987 sites; DC 21 files, 320 sites; script and outputs in
`/coord/handoff/R-497/scratch/`) are mostly tables, pages and their extensions. BC's coverage line numbers are source
positions, so a difference by kind is unlikely, but a one-line shift near a trigger boundary would give a wrong
covering set. To close: add one wrapped table (with a field trigger) and one wrapped page to `sandbox-wrapped`,
pre-committed, or run one more R-300b-style probe round.

**2. `lethal verify` contradicts the run for a wrapped object.** `runNamedMutants` hands no build symbols over, so
verify refuses a wrapped file (fail-closed) with a sentence ending "Its mutants read no-coverage", while the run that
produced the survivor scored it `survived`. To close: hand the build's symbols to verify, or give verify its own
sentence.

**Part 2 fixed (R-536, 2026-10-09; plan `/coord/handoff/R-536/plan.md`, opus plan review applied).**
`runNamedMutants`, the one function every verify path goes through, reads the build symbols the SOURCE run recorded
(the set its installed artifact and line map were built under) and hands them to the backend before the first
`attach`; a source run that recorded none is refused by name, never read as `[]` (the R214 rule). The reach filter's
refused set is read under the same symbols with R497's BC shape rule, joined with what the attached line map itself
refuses (a key two compiled files declare, an unmapped object), so verify refuses exactly what the run refused and
places what it scored. Each wiring site has a test that goes red when it is reverted. A source run recorded before
R497 (scheme 35 or older) refused every wrapped object; verify now reads such a run's installed artifact by today's
rule, which only decides which new tests run, never a verdict on its own.

**Part 1 measured (R-536, 2026-10-09).** `fixtures/sandbox-wrapped` 1.0.0.1 gained a one-arm wrapped TABLE (a field
`OnValidate` and a procedure) and a wrapped PAGE (a never-run `OnOpenPage` and a procedure called on a page
variable), each with an unwrapped twin on the same lines: 22 new mutants, every per-mutant verdict, killing test and
covering set pre-committed (`docs/superpowers/specs/2026-10-09-r536-wrapped-table-page-precommitment.md`, master
d3dbdfba) before any live run. Live, all 22 matched on every leg: `itest:bcdev-wrapped` on Cronus28 (fenced and hub,
38 / 20 / 0 over 58, hub identical) and `itest:alrunner`'s wrapped legs (one-shot, `--server`, resource, 36 / 19 / 3
over 58), with strict twin parity and no refusal. So BC and al-runner number a wrapped table and page as they number
a codeunit: the codeunit measurement R497 rested on holds for these kinds. Extensions (table and page extensions)
remain unmeasured as wrapped objects; no gate holds one.
