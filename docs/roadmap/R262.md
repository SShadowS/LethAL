**What.** `verify.ts` turns an unmutated `error` or `timeout` answer for a NEW test into `"fail"`. A fresh answer of
that kind is then reported as `red` at baseline, or `flaky` on the second unmutated run, although nothing says the
test itself failed: the call did. Exit 0 stays blocked in both cases, so no gate passes wrongly. The damage is the
label: an agent told its new test is `red` goes to fix a test that may be fine.

**Found by** gpt-6-sol's review of C02-06b (`H:/lethal-coord/reviews/C02-06b-001/review-r1.md`, Minor 1), accepted
by the orchestrator as a reporting error, not a verdict error.

**Related, same review (Minor 2).** R258 is titled for an edited test that did NOT cover the mutant (verify does not
select it), while its body describes an edited COVERING test (verify selects it, but does not give it the new-test
double-run check). Both are real limitations. Split: R258 (not selected) and R278 (selected, no double run).

**What would close it.** Keep `error`/`timeout` distinct from `fail` in the new-test state: report `flaky-unknown`
(or a dedicated value) for an infrastructure answer, with a test per path and a red-check, and update the verify
schema's value set and the agent reference together (C02-07's contract test pins that set).

**Superseded by the orchestrator's rulings (2026-09-27).** The text above groups `timeout` with
`error` and proposes `flaky-unknown`. The rulings kept a runner-confirmed `timeout` as the test's own
(`red`/`flaky`, design.md 6.7) and chose a dedicated state, `infra-error`, over a reuse of
`flaky-unknown`. The fix below follows the rulings.

**Closed 2026-09-27 (`d24e766`, `a25351a`).** Each unmutated run now keeps the backend's own outcome
(`UNMUTATED_OUTCOMES`: `pass`, `fail`, `skip`, `timeout`, `deadline-exceeded`, `error`, `not-run`),
and a new state `infra-error` reports a run whose CALL failed (`error` or `deadline-exceeded`). A
runner-confirmed `timeout` and a `skip` stay the test's own (`red`/`flaky`), per the orchestrator's
rulings. Exit `0` stays blocked. `schemas/verify-v2.schema.json` was extended in place (version 2),
and the agent reference's value table and contract test moved with it. Every rule red-checked.
