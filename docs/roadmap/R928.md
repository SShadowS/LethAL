Found by coord task R-919 (2026-11-11), once [[R924]] made XMLports carry the selector and R500's XMLport rule went live.
Evidence: `/coord/handoff/R-919/dry-peppol-r919.txt` (the rule as it is) and the scratch run described below. Related: [[R500]],
[[R487]], [[R501]].

**What.** R500 treats an XMLport `tableelement` over the virtual `Integer` table as a loop BC drives, like a report data item, and
R487's blanket rule refuses every site in an OPEN item's code, nested elements included. An item counts as bounded only by
`MaxIteration`, a closed `SourceTableView`, or the single-`SetRange` certificate. XMLports have no `MaxIteration`, and the rule never
reads `MaxOccurs`.

Both PEPPOL 3.0 XMLports (`SalesInvoicePEPPOL30`, `SalesCrMemoPEPPOL30`) are `Direction = Export`. Each wraps nearly all its code
in one outer element (`invoiceheaderloop`, `crmemoheaderloop`): over `Integer`, `filter(1 ..)`, `MaxOccurs = Once`, ended by a
`currXMLport.Break()` when its iterator runs out. Because the outer element counts as open, every site inside it is refused.

**Measured on PEPPOL** (dry run, al-runner-v3 backend):
- as it is: 1,072 XMLport sites hang-refused (539 + 533); 1,440 mutants deployed in the app;
- with `MaxOccurs = Once` counted as a bound (a scratch copy only, never committed): 443 refused (223 + 220), 2,311 deployed. The
  XMLports' own deployed sites go from 40 to 669, and two more files gain mutants (one-hop callees no longer refused).
- The 443 left are real hang shapes: inner elements (`invoicelineloop`, `taxsubtotalloop` and others) walk `Integer` from 1 with no
  upper limit, and only an iterator's `Break` or a `SetRange` stops them. Removing that stop runs for up to 2^31 rows.

**A second, smaller case: import.** On `Direction = Import` an XMLport builds its records from the incoming XML, so an `Integer`
element probably does not walk the table at all. The rule does not read `Direction` either. Not measured; no PEPPOL XMLport imports.

**To close.** First a probe, on BC and on al-runner v3: does `MaxOccurs = Once` stop an export `tableelement` over `Integer` after
one record, when its `Break` is removed? (And, for the import case: does an import XMLport's `Integer` element run its triggers
once per XML node only?) Only if both answer yes on both backends, change the rule (`dataItemOpenOnce` in
`packages/builtin-tier1/src/loop-hazard.ts`), red both ways, and pre-commit the moved figures. If v3 ignores `MaxOccurs`, a mutant
there hangs the run, so the rule must stay as it is for v3 and the gap goes upstream.

**Measured and closed (coord R-923, lethal-code, 2026-11-11).** The probe (`/coord/handoff/R-923/r928/`, invented XMLports, ids
91540-91545), on bc1 (BC 28.4 W1 Linux) and on al-runner v3 edge-42af5d384, equal to the byte on both:
- export over `Integer`, `MaxOccurs = Once`, no `Break`, a 1000-record cap: 1 record, cap not hit (232 bytes written);
- the same with `Break` after the first record (control): 1 record (132 bytes: the `Break` stops before that record is written);
- import fed 3 XML nodes: its record triggers ran 3 times, once per node.

**Fix (d5eb16ff).** `dataItemOpenOnce` counts an XMLport `tableelement` with `MaxOccurs = Once` as bounded (only that element; nested
open elements stay refused), and an XMLport whose every `Direction` is `Import` makes no loop items. A `Direction` or `MaxOccurs` that
sits only in an `#if` arm the build cannot decide does not count (a build without the arm is unbounded or `Both`). Red both ways in
`r500-shapes.test.ts`.

**Moved figures.** PEPPOL dry run: 2,311 deployed (as pre-committed above; was 1,440), the two XMLports 337 + 332 sites, hang-refused
1,457 -> 574. BC.History identity diff (`scripts/corpus-snapshot.ts diff bch`, master f81b525a vs the branch,
`/coord/handoff/R-923/r928/bch/bch.diff.txt`): three projects change, every change an addition: Base Application specs 769,706 ->
771,285 (hang 67,432 -> 65,853), E-Document Core 16,014 -> 16,311 (hang 460 -> 163), PEPPOL 1,495 -> 2,378 (hang 1,457 -> 574);
2,741 sites added over 519 projects, 0 removed, no tuple, ordinal or tag moved. So of R-919's 3,990 newly refused XMLport sites, about
2,760 come back; the rest are real hang shapes (open inner `Integer` elements).
