**Filed 2026-10-24 by lethal-code during R-685**, from the triage of its dropped-dependency check
(`/coord/handoff/R-685/drop-triage.md`). A false "old" verdict: the unsafe direction. Older than R-685.

**What.** A test-app codeunit with `Subtype = Install` or `Subtype = Upgrade` runs when the platform installs or
upgrades the test app, before any test runs; tests then check the data it wrote. No digest holds it:
`subscriberFold` (`packages/runner/src/test-digest.ts`) folds subscribers, extensions and enum implementations, and no
test reaches the install/upgrade triggers (`OnInstallAppPerCompany`, `OnUpgradePerCompany`, `OnCheckPreconditions...`,
`OnValidateUpgrade...`) or what they call.

**Measured** (offline, scratch copies; procedure names only, no source):
- On master, tests outside the whole-source fallback already miss it: E-Document Core (320 tests), SalesLinesSuggestions
  (104), NoSeriesCopilot (1), Sustainability Copilot (3).
- R-685's narrowing would expose 36 more (Tests-Upgrade 15, all of its tests; BankAccRecWithAI 15; E-Document Core 6):
  on master they sat on the fallback, which hid the gap by accident.
- Experiments: an edit to `Upgrade Test Data Setup Mgt.BackupTablesPerCompany` (called from Tests-Upgrade's Upgrade
  codeunit) moved 15/15 digests on master (fallback) and 0/15 with R-685; BankAccRecWithAI's install trigger 15/15 and
  0/15; E-Document Core's 7 and 1. An invented one-file repro (an upgrade codeunit writes a status a test reads) shows
  the same.

**To close.** In `subscriberFold`, fold every test-app codeunit that has an install, upgrade, check-preconditions or
validate-upgrade trigger (by its `Subtype`) with `foldEntryUnit`, so it is in every digest. This only widens. Measured
on a scratch copy: the repro moves, Tests-Upgrade 15/15, BankAccRecWithAI 15/15, E-Document Core 327/327; an unedited
copy moves 0. Red tests for each direction.
