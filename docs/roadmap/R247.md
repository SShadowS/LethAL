**Found while planning C02-05 (2026-09-26), confirmed by reading.** `sessionFingerprint` keys a
session on `projectDir`, `testDir` and `backend`, that is on paths and scope, never on the bytes of
the test app the server actually runs. R192 half 1 (`batchCarriesEntirely`) can then carry a whole
batch's verdicts on `--resume` without a deploy or a baseline. So a resume carries verdicts that
were measured against a test app which has since been republished.

Today that needs a hand republish between two resumes. C02-05 and C02-06 (`lethal verify`) make a
test-app republish routine, so the case stops being rare.

R192 half 2's `testAppHashFor` key does see a changed test app, but only for baseline REUSE, and
only in a batch that reaches its baseline. It validates no carried verdict, so it does not close
this.

A possible fix: refuse, or re-measure, carried verdicts when the published test app's package hash
differs from the one the carrying run recorded. Not measured live. Status `open`: C02-05 files it
and does not solve it.

**Done 2026-09-30.** Each run now records `runs.test_app_hash`, the value `testAppHashFor` already
used for baseline reuse (`package:<sha256>` of the published test app on bcdev, `source:<hash>` of
the test `.al` tree otherwise), taken from the one package read `reportPublishedTestApp` already
made. NULL (every run from before this) is unknown and never matches, NULL against NULL included.
`--resume` and `--resume-run` refuse BY NAME when the carrying run's test app differs or is unknown,
before any resume index is built, so both R192's whole carried batches and single carried rows are
covered; a republish that only moved the version stamp counts as a change. `--skip-known-survivors`
skips nothing across a changed or unknown test app and warns `history-test-app-changed` once.
`lethal verify` goes through neither rule (it calls `runNamedMutants`, not `runSession`), and its
own run records `package:<compiled sha256>`. Tests in the `R247` blocks of `resume.test.ts`,
`store.test.ts` and `orchestrator.test.ts`; each check red-checked.
