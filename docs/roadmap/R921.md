Found by lethal-code, 2026-11-11 (coord R-914, MasterDataManagement on al-runner v3). Related: [[R916]], [[R890]], [[R694]], [[R639]].

**What happened.** `Master Data Mgt. Synch. Tests.SynchMediaField` is refused by v3 at baseline (`Insert on virtual table 'Tenant
Media'`), so it is not green. Auto isolation kept `test` for its codeunit (15 of 15 green tests pass either way). Under `test` a mutant
call runs the codeunit whole, so the refused test runs again in every call and al-runner then refuses each LATER test of that call:
`NotRun: out-of-scope: an earlier test of this codeunit was refused while it ran (SynchMediaField: ...)`. 39 mutants ended as `error`
this way, and 5 more by the same cascade from another refused test (FindAndSynchRecordIDFromIntegrationSystemId). Those mutants have
green covering tests that would have run under `method`, so these are lost verdicts, not refusals of the mutant.

**Invented repro.** A test codeunit with tests A (refused by v3 by name at baseline) and B (green, covers mutant M), A before B in the
file. Under `isolation: "auto"` (both modes pass B), every call for M runs A, then B is refused by cascade: M is `error`.

**Wanted.** When a codeunit has a test refused at baseline, either auto picks `method` for it (its green tests then run alone), or the
whole-codeunit call leaves out tests that are not green at baseline. Measure which keeps the verdicts equal on the fixtures.

**Fixed (coord R-922): auto picks `method`.** On a tie, a codeunit moves to `method` when v3 refused one of its tests by name at
baseline and `method` loses none (an extension of the owner's R890 ruling, still decided by the baseline). Why MDM's codeunit
139758 stayed on `test`: it tied, 15 of 16 both ways. Why the cascade showed only in mutant calls: v3 cascades a later test only
when it reads state the refused test could change, and the baseline path did not read it while a mutant's did. Invented repro
(`/coord/handoff/R-922/src`): a refused test sets a global; a green test reads it only when a clamp result is wrong. Before, 5
mutants that test should kill were `error` by cascade; after, all 5 are killed, and the run equals an all-one-shot run per mutant
(22 of 22). No verdict moved except those 5.
- A v3 cascade row ("an earlier test of this codeunit ...") does not count as a refusal by name: it names another test's refusal
  or state (build review r1).
- `--resume` of an `auto` run recorded before this change, where a codeunit tied with a refused test, now stops with
  `isolation-choice-changed`: the stored choice says `test`, the new one `method`. It refuses loudly, as R896 intends; run it fresh.
- No gate leg runs `isolation: "auto"` (the itest pins `"test"`), so the rule rests on its unit tests and the invented-app proof.
