**Found 2026-10-08 by R-506's planning (bugs lane), by reading the code. Not verified live.** A wrong-verdict risk.

**What.** A lease loss latches the session, so `finishRun` is skipped and the run stays resumable. The lost batch is
invalidated only by an event (`emitLeaseLostInvalidation`): `store.invalidateBatch` is called only from the
attestation gate. `findResumableRun` and `buildResumeIndex` never filter by batch. So a later `--resume` can carry
the invalidated batch's stored verdicts, kills included, as if they had been measured under a held lease.

**To close.** Reproduce offline first with a fake lease client (lose the lease mid-batch, then resume, and show the
batch's verdicts are carried). Then invalidate the batch in the store beside `emitLeaseLostInvalidation` (the proposed
fix), or have resume refuse rows from a batch the session never finished. Pin both directions (a lost batch is not
carried; a completed batch before the loss still is), red-checked. The fix must cover both callers of
`emitLeaseLostInvalidation`: `runSession` and `runNamedMutants`.

**Also (R-506 final build review, M1).** Since [[R507]], a session that throws a lease-path refusal at teardown
(`surfaceLateRefusal` in the `finally`) skips the `emitLeaseLostInvalidation` call after it, so a `--progress-out`
stream can hold a lost batch's kills with no `batch-invalidated` event. No report is built from such a session
(`foldEvents` refuses a stream without `session-finished`). Moving the invalidation into the store, as above, makes
the event ordering irrelevant; otherwise emit it before `surfaceLateRefusal`.

**Closed by R-508 (3203624b).** A lease-lost batch is now corrected in the store twice. At the moment of loss,
`LeaseSession.noteLeaseLost` calls `onLost` after the latch, which synchronously runs `store.invalidateBatch` and the
new lease-only `store.dropBaselineSnapshot`. In both `runSession` and `runNamedMutants`, the `finally` runs
`invalidateLostBatch` after `closeLeaseScope` and before `surfaceLateRefusal`: it emits the event first, then writes,
and a failed write throws `LostBatchNotStoredError`. So `--resume` no longer carries a lost batch's verdicts,
`--skip-known-survivors` no longer gets them through a resumed run, and the batch's R192 snapshot is not reused;
batches completed before the loss are still carried. Reproduced offline first (`/coord/handoff/R-508/repro.md`);
red-checks R-A to R-J per direction (`/coord/handoff/R-508/redchecks.md`). The `C02-04 characterization 7: lease
lost mid-batch` snapshot was updated on purpose: M0001's verdict `survived` to `error` and its lease-lost note, the
only change. Follow-ups: [[R512]] (the attestation path keeps its batch's snapshot) and [[R513]] (the crash
residue).
