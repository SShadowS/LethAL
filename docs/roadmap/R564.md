**Filed 2026-10-10 by the [[R562]] build** (orchestrator ruling (a) on plan r1, `/coord/reviews/R-562-plan/`).
An over-refusal: mutants that cannot hang are not deployed.

**What.** [[R531]]'s HOP (a consumer one hop away) and R562's FILTER HOP (a filter one hop away) both follow
EVERY procedure of the called name whose parameter count fits the call (`r531ProcsIn`). AL chooses an overload by
the arguments' TYPES, so when two overloads have the same parameter count, the one the call never reaches is
followed too and its sites are refused.

**Measured payoff.** DO Cloud, R562: each of the two callee tables (`CDOEMailTemplateAttachment`,
`CDOEMailTemplLineReport`) has two 1-parameter overloads of the filter procedure, one taking
`CDO E-Mail Template Line` and one taking `CDO Document Template Line`. `CDOEMailTemplateLine`'s OnRename passes
`xRec`, a `CDO E-Mail Template Line`, yet the `CDO Document Template Line` overloads' `remove-setrange` x3 and
`empty-block` x1 per table are refused: **8 of DO's 23 removed keys** (`/coord/handoff/R-562/measure.md`).
Choosing by type would bring DO to 15 keys (about 0.05% of its specs). R531's own HOP was not measured for this
over-refusal.

**To close.** Narrow `r531ProcsIn`'s candidates by argument type where the type is known: a Record argument's
table (`declaredType`, which the HOPs already use for receivers) against the parameter's declared Record type;
keep every arity-fitting overload whenever a type is unknown (the refusal direction). Re-dump DO and CDO and
every corpus R531's HOP touches against the master legs; the change only adds keys back, so expect no tuple or
ordinal to move.

## Done (R-564, 2026-10-10, a79cb1f3)

`r531ProcsIn` (all four call sites: `r531TableProcs`, R562's same-object and table/codeunit paths, R531's HOP)
narrows the arity-fitting overloads only when ALL of these hold, else it keeps all (plan r2, after the opus plan
review: `/coord/handoff/R-564/plan.md`, `review-opus-plan-r1.md`):
1. no candidate is `#if`-split (one `parameter_list`, no preprocessor or ERROR node in its header);
2. every argument resolves to a project table (engine `recordTableObjectOfName`: "unknown" declarations, a
   shadowing field, a `with`, a qualified `extends` that parses as ERROR, and anything not a Record are null);
3. every parameter of every candidate is a `Record` of one project table (engine `tableObjectOfRef`, by id or
   name; a name or id two project tables share resolves to neither);
4. exactly one candidate has the argument's table at every position, compared by object IDENTITY.

- **alc probe** (`/coord/handoff/R-564/alc-probe.md`): a `Record A` argument against a by-value, `var` or
  `temporary` `Record B` parameter fails with AL0133 each time; the matching control compiles.
- **Tests:** `packages/builtin-tier1/tests/r564-overload-by-type.test.ts`, each red-checked in its own direction
  (`/coord/handoff/R-564/redcheck.md`). R562's former over-refusal test now pins the narrowed outcome.
- **Measured** (`/coord/handoff/R-564/reproduce.md`): DO +8 keys, all in DO Cloud and the same 8 the prototype
  predicted; 0 keys removed or changed in all 7 DO projects. No tuple or ordinal moves: scheme stays 39.
- **Filed:** [[R567]], a comment inside an argument list counts as an argument, so the callee is not followed.
