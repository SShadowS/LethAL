**Filed 2026-10-24 by lethal-preproc during R-709b.** Related: [[R709]].

**What.** `notReinstalledApps` (app-version.ts) reads BC's list of the apps it could not reinstall after a refused
upgrade. R-709b measured that list on bc2 through a DIRECT HTTP publish, in a JSON body. A real `lethal run` publishes
through altool (`ContainerDeployer.publish`), and how altool prints the 422 is not measured:
- whether it prints the Message escaped or raw;
- whether BC's trailing blank lines survive;
- what altool adds after the list (its stderr line).

The R709 build review tried each plausible shape, and each makes the parser fail closed. So the refusal then says
the list could not be read, which is true but names no app.

**To close.** One altool publish of a probe target that breaks two installed dependents, with fresh app ids and
versions, on bc2, under a pre-commitment, capturing altool's full stdout and stderr. Then adjust the parser to the
measured shape, keeping it fail-closed.

**Closed 2026-10-24 by R-728 (lethal-preproc), measured.** Evidence: `/coord/handoff/R-728/measure.md`, probe
`scripts/r728-probe/`, pre-commitment `docs/superpowers/specs/2026-10-24-r728-altool-restore-list-precommitment.md`
(master 9f26ffac).
- **What happened:** the breaking upgrade, published through LethAL's own deployer (`deployerFor` ->
  `ContainerDeployer.publish`, altool `publishapp`, ForceSync, bc2's fixture config), was ACCEPTED on bc2. The target
  was installed at the new version. Both dependents STAYED installed, and their calls then answered HTTP 400 ("The
  object with ID ... does not have a member with that ID").
- **So there is no refusal and no not-reinstalled list on a real run's path,** and no parser change is needed.
- **Why, by reading:** the direct publish sends `DependencyPublishingOption=default`, which makes BC recompile the
  installed dependents; altool does not. Both used ForceSync.
- **The quieter risk** this leaves on the run path (an installed tests app broken against the new target) is filed as
  [[R738]]. R709's reading is corrected there.
