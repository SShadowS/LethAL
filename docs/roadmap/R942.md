Found by lethal-code, 2026-11-12 (coord R-925, Sustainability on al-runner v3 edge-42af5d384). Related: [[R929]].

**What happened.** 9 baseline tests are refused with `NotRun: out-of-scope: an action that makes a part visible, other than the
pinned shape: a Document page opened with OpenEdit, on a stored row without an unsaved ...` (full text in
`/coord/handoff/R-925/sus.events.ndjson`, `baseline-batch-finished`).

**Why not filed upstream.** About 15 invented shapes (Worksheet, Document, List and Card hosts; OpenView and OpenEdit; ListPart and
CardPart; with and without a repeater, temporary or stored, with and without SubPageLink; `OnAfterGetCurrRecord` also setting the
visibility variable) all run on v3. The refusal text does not say which condition failed (`/coord/handoff/R-925/up2/2-*`).

**Next step.** Cut a copy of the real page and its test down step by step until the refusal goes, then write the invented repro from
the last shape that still refuses, and file it at aldevtools/BusinessCentral.AL.Runner. Ask upstream to name the failing condition in
the refusal text either way.

**Reproduced and filed (coord R-941, 2026-11-12):** https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7922. The real page
is a Worksheet opened with OpenView; its action calls a codeunit and then sets the part's visibility variable from a function on the
part's page. The part is Base Application's `Workflow Status FactBox` (page 1528, a ListPart over a temporary table) — a page from a
DEPENDENCY package, which none of the 15 earlier invented shapes used. Cutting the real app: removing the three sibling parts still
refuses; removing the codeunit call lets the test run. An invented one-app repro that uses that package page refuses with the exact
message; the same shape with the part page in the app's own source passes. The refusal's wording names the pinned shape (a Document
page, OpenEdit), not the failing condition; the issue asks upstream to name it. Evidence `/coord/handoff/R-941/p2/`.
- Seen on the way, not examined: calling the part's function as a statement (not assigning the result) gives a different refusal, "an
  action left the list's view without rows (not pinned)". A follow-up if it shows up in a real app.
This item stays open until #7922 is fixed and the 9 tests run on v3.
