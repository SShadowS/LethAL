Found by R-984's DO windows t5 and t6 (lethal-bugs, 2026-11-16; `/coord/handoff/R-984/t6-block.md`), where it was t6's BLOCK.

**Measured.** Two DO mutants, each with the same covering-test set in the same order in both windows, both kills reproduced:
- `CDOEMailHandler:462` (void-method-call): t5 timeout-killed by a test that hangs (position 14 in the covering list); t6 killed in
  432 ms by an assertion in another test (position 3).
- `CDOMailMessageBuilder:137` (toggle-blank-string): timeout-killed both times, by two different hanging tests (positions 17 and 2).

Each mutant has more than one killing test, and one of them hangs. Which one LethAL meets first depends on two inputs that differ
per window by design: R987's entries cap, MEASURED per window (about 119, 41, 208, 230, 201 and 38 entries per request in t1 to
t6), which packs the same tests into different requests that a timeout cut (R895) ends early; and [[R197]]'s order, which puts first
the tests that already killed in the same procedure this session. So the verdict CLASS (killed vs timeout-killed) and the killing
test are not stable across runs for such a mutant.

**Handled for now** by a comparison rule, not by the product (orchestrator ruling 2026-11-16; `/coord/handoff/R-998/do/verdict-rule.ts`,
tests red-checked for each condition): killed and timeout-killed count as the same verdict, with the killing test exempt, only when
one side is timeout-killed, both sides reproduced, and the covering-test set is identical. Everything else stays strict.

**Possible fix** (not built): after a request is cut at a timeout, run the covering tests not yet answered that come before the hung
test in covering order, and score the earliest failure. The verdict class then follows the covering order, as a test-at-a-time run
would. Cost: runs on mutants already known to be killed.

**To close.** Either the fix, with a test that the same mutant scores the same class whatever the request packing, or a ruling that
the comparison rule is the permanent answer.

**Fixed (PR-51, 2026-11-16; spec `docs/superpowers/specs/2026-11-16-pr51-timeout-class-stable.md`, 7a4ceb4d + addendum 1
76ee780e).** The covering walk holds its first timeout and walks on: a confirmed, reproduced later fail scores `killed`;
otherwise the held timeout goes through the old timeout path, and the noted later timeouts are replayed in order if it does
not reproduce. On v3 a later fail measured alone is confirmed and reproduced alone (`RunOpts.alone`). The property test
(`pr51-held-timeout.test.ts`, P13) gives the same class over 20 orders and 15 packings. Left out: an error met before a fail
([[R1066]]); an alone-measured first kill ([[R1067]]).

**The cap re-opened (coord PR-108, lethal-code, 2026-11-17, orchestrator ruling).**
- **Why.** DO t13's held-timeout walk was 14.3% of the mutant phase, against this item's 5% trigger. One mutant (M36641,
  `remove-not` in `ReadAsText`) hung in 19 of its 22 covering tests, at about 104 s each, and was timeout-killed by its first
  hang anyway.
- **The rule (simple cap, spec `docs/superpowers/specs/2026-11-17-pr108-walk-cap-and-budget.md`, addendum 2).** The 3rd
  non-replay hang ends the walk exactly as a natural end does; today's after-walk code replays the held step.
- **What it can move** (the safe direction: a lost kill, never a false one):
  - `killed` -> `timeout-killed`;
  - `killed` -> `error`;
  - `timeout-killed` -> `error`;
  - a terminal error past the cap -> the held replay's verdict.

  Each move needs a later decisive test beyond the 3rd hang.
- **How a move stays visible.** Every capped walk carries the note `the walk stopped after 3 timeouts (PR-108, R1057's cap);
  <k> covering test(s) after them were not run` and one `held-walk-capped` warning naming its verdict. TIMING counts capped
  walks by verdict.
- **The window comparison.** lethal-bugs' comparison relaxes only `killed` <-> `timeout-killed` under the note; the error moves
  stay strict.
- **The order limit.** The class can depend on the covering order across `--resume` for mutants with 3 or more hangs.
- **Pre-committed:** 0 moves on t9-t14's 13 walks. Each was timeout-killed by its held, reproducing first hang.
