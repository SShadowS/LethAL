[[R769]], [[R734]], [[R461]], [[R777]].

**The plan:** `docs/superpowers/specs/2026-10-25-a2-alc-overlap.md`. It folds in one spec-adversary review: three
BLOCKs and three FIXes, all addressed.

**In one paragraph.**
- On v3 only (a backend capability, first attempts, one worker, no resume, no TranslationFile), `deploy()` returns
  with the proof's byte fields bound and alc still running on copies of the batch and the test dir.
- The orchestrator scores the batch with a journaled store and emitter. When alc resolves:
  - **passed, and no answer tainted by alc's CPU:** the journal is replayed and the batch continues live;
  - **alc rejected:** the journal is discarded, the orchestrator and backend checkpoints are restored, and today's
    alc path (R461, bisection, R734) runs with the same error object;
  - **any other join error:** aborts as today;
  - **a tainted, refused or copy-changing window:** re-runs the batch sequentially on the same proved deploy.
- At most the alc time is saved: about 6 s on D1 at 6aa7700c (arithmetic, not measured).

**Before building:** measure the taint rate (D1 runs whose answers time out beside alc's CPU). A high rate makes A2
save little against A1.
