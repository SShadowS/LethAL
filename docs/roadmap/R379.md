**Found by the R-214 lane (lethal-preproc), 2026-10-01.** Plan: `docs/superpowers/plans/2026-09-29-R-214-symbol-aware-site-enumeration.md`. Pre-commitment: `docs/superpowers/specs/2026-09-29-r214-precommitment.md`.

**What happens.** `scripts/campaign/compile-only.ts` compiles and enumerates a project with no config symbols and does not read `app.json` symbols. After R214 its site list can differ from a real run's for any project with a `#if`.

**What would close it.** Pass the same effective symbols (config plus `app.json`) that `runSession` uses.

**Done (R-359b).** Narrower than written: `generateMutationSet` already adds `app.json`'s
symbols itself (`effectiveBuildSymbols`). What compile-only lacked was the CONFIG's
`preprocessorSymbols`, for both enumeration and `alc`. It now takes `--config` (default
`<project>/lethal.config.json`, as `lethal run`; a missing file adds none), validates the symbols
as `lethal run` does, generates through `compileOnlyMutationSet`
(`packages/runner/src/compile-only-args.ts`) and passes them to `ArtifactCompiler`. Pinned in
`compile-only-args.test.ts`: on `fixtures/sandbox-symbols`, a config naming `LETHALA` enumerates
exactly the sites a real `[LETHALA]` generation does, and differs from no config. Red-checked: not
passing the symbols turns it red.
