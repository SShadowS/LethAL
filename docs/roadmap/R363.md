**Found by the code lane planning R360 (2026-09-30), measured.** `prepareBatchProject`
(`packages/runner/src/orchestrator.ts`) copies every file under the project that is not `.al`,
`.app` or `app.json` and not under a dot folder into each batch dir, so a control add-in or a
layout reaches `alc`. The default results database is `<project>/lethal.sqlite`, which sits in the
project, so every batch dir gets a copy of it and its `-wal`. On the `sandbox-data` fixture one
batch dir was 10.3 MB, of which 10.1 MB was that copy and 0.2 MB was the build. The same goes for
`--db results.db`, `--out report.json` and `--progress-out events.ndjson` when they point inside the
project: the run copies its own outputs into the thing it compiles.

**To close.** Skip exactly the run's own output files: the resolved `--db` path and its `-wal`,
`-shm` and `-journal` sidecars, and the `--out` and `--progress-out` paths when given. No guessing
from a file extension: an old report the run did not name is copied like any other resource
(harmless, a build never reads it), and a JSON file a control add-in needs must still be copied.
Tests: a custom `--db results.db` and its `-wal` are not copied; a needed `addin/config.json` is.
