**Found 2026-10-05 by the orchestrator's opus merge review of R-294** (merged 281efeca).

R-294 stops typing a name that falls through to globals in implicit-`with` contexts (a page or
pageextension with `SourceTable`, a codeunit's `OnRun` under `TableNo`, report dataitems and request
pages), because a record field can shadow the global there. It finds the property with `hasProperty`
in `packages/engine/src/semantic/types.ts`, which reads `declarationMembers()` (`tree-walks.ts`),
direct members only. A `SourceTable` or `TableNo` wrapped in a member-level `#if` is therefore missed,
the object reads as having none, and its globals are typed again: the unsafe direction (a swap that
`alc` rejects, the R295 wrong-mutant class).

REASONED, not parsed or compiled; expected rare. **To close:** measure first (count such objects on
BaseApp and CDO); if any exist, also look inside member-level `preproc_conditional` nodes, in any
arm, and pin it with a red-checked test (a `SourceTable` under `#if` must block the global's type). If
there are none, close as a ruling with the count.

Also noted, no action: the reportextension request-page branch (`p.parent?.parent`) has no test, and
is moot today because `enclosingObjectScopeKey` gives reportextension no scope.
