Found by lethal-code, 2026-11-12 (coord R-925, Late Payment Prediction on al-runner v3). Related: [[R612]], [[R808]], [[R635]].

**What happened.** The serve-entries summary said `daemons 18, ... warm-up 18 / ... live 600`, where the other R-925 apps used 1 to 4.
The events file and stderr give only these totals. From the report and the code, 11 restarts follow refusals outside
`V3_SERVE_SAFE_REFUSALS` (WithEvents x5, GetDotNetType of an unassigned Dictionary x3, a DateTime before 1753, an InStream never
created, a RecordRef that is not open), which the keep rule correctly closes on; the other 6 cannot be assigned. Cost here: about 78 s
of warm-ups in a 1,536 s mutants phase.

**Invented repro.** A suite where 3 mutants each hit a different refusal outside the keep list: the summary says `daemons 4` and
nothing else.

**Wanted.** Each daemon close emits one event (or a stderr line) naming the reason: the refusal text's family, a timeout, a crash, or
the entry that failed `serveDaemonReusable`; and the summary counts closes by reason. Then a restart-heavy session shows which refusal
an R612-style probe should admit to the keep list.
