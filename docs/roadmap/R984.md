Found by R-970's build review (R983, GitHub #51). Related: [[R983]], [[R172]].

`shift-integer` claims an integer literal whose parent is a comparison (`=` / `<>`, the operators it does not cede to
`conditional-boundary`) as well as an assigned one, and its survivors are all listed under the operator's `value-rewrite`, whose
text says the mutant is equivalent where nothing downstream reads the value. For a comparison operand the comparison reads it,
the same misfit #51 reported for the blank toggles. Not measured: no reader has counted how many `shift-integer` survivors sit in
a comparison, or how many of those were real gaps. Fix shape, if it is worth it: set R983's per-site `equivalenceRisk` for the
comparison arm, with its own explanation (the branch changes only where the other side equals the original or the shifted value).
