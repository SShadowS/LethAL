gate, so gates can run in parallel instead of queueing on Cronus28's lease.

**Built (branch `lethal/r589`, 2026-10-21).**
- **Setup script** `scripts/bc-linux-setup.ts --server bc1|bc2|bc3|all [--dry-run]`: reads the login
  from the owner's secret file in-process (refusing a missing file, an extra key or an empty value,
  and never printing a value), writes the gitignored `lethal.config.<server>.json` and
  `.vscode/launch.<server>.json` per gate fixture (refusing a path git does not ignore), takes the
  coord lease and records its token first, publishes LethAL Control 1.0.0.22 and `PUBLISH_PLAN`
  (probes, every fixture pair, the harden answers, wrapped with WRAPDEF, names) in-process over
  `dev/apps` with no credentials on a command line, skips what the server already holds, and runs
  `lethal doctor` on every config.
- **Port wiring (R591, folded in):** OData from `bcdev.baseUrl`, the harness's API reads from the new
  `bcdev.apiBaseUrl`, the dev port from `bcdev.port` to bc-dev-mcp and to altool's `--port`, in
  `lethal run` and in every BC itest. A config with no ports (Cronus28) builds the same URLs and argv
  as before (`packages/runner/tests/port-wiring.test.ts`, both directions per plane).
- **Strict launch pairing and a server guard:** `LETHAL_ITEST_CONFIG=lethal.config.<x>.json` requires
  `.vscode/launch.<x>.json`, which must name the same host and the same effective dev port (an unstated
  port means 7049); each
  BC itest prints its target (config, host and dev port, OData and API roots) as its first line.
