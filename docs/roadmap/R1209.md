**Found by** coord PR-415 (2026-11-24): every refusal family re-run on main-bf3a3e863 and on edge-e5176a9fd (now `current`).
Each refused cell's text was checked against `V3_SERVE_SAFE_REFUSALS` (`/coord/handoff/PR-415/keepcheck.ts`,
`keep-moves.tsv`).

- **What:**
  - Of 3,418 cells, 683 refused cells are kept on both builds.
  - One cell moves from kept to unkept: t12-refusals 51009 (`Conversion.TextToInteger (1=18)`).
  - On bf3a3e863 it read "conversion of Text '1=18' to Integer", kept by `conversion-text-to-integer`, whose `%INTTEXT%`
    slot allows `=18` and `1=18`.
  - On edge it reads "SetRange or SetFilter of Text '1=18' into a Integer field in a shape no cell measures (assumption
    setrange-other-type-convert)".
  - PR-408 kept the edge wording only for the exact `'=18'` line (`setrange-text-eq18-to-integer`), the one leg C captured.
- **Why it matters:**
  - An unkept refusal closes the serve daemon. A DO run that meets the `'1=18'` shape pays a restart where bf3a3e863 paid none.
  - No verdict moves: the cell is refused on both builds.
- **The fix to decide:** a keep row for the `'1=18'` line (or `%INTTEXT%` in the new wording), proven the way PR-408 proved
  its rows: a kept-vs-fresh check on edge's binary, plus the PR-361 and PR-363 guards.
- **Also seen, not this item's:**
  - 4 new unkept refusals (Boolean `false` into a Code or Text field) are a regression to BC, filed upstream as #9026;
  - 21 cells moved from unkept-refused to running.
- **Related:** PR-408, R1000, R1192.
