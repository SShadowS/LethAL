Coord task PR-42 (2026-11-16). Owner ruling q-20261115T202541-baaa349b: keep LethAL's product default off, but every mutant
run on our own pool has the `--stop-hung-sessions` backstop (PR-34's bc2 strand had none).

**What changed.**
- `bcdev.stopHungSessions` (cli.ts, `BcDevConfigSection`): `true` records a server owner's yes.
  - `runFromCli` turns the stop on for the whole run (backend, session, `--resume`), exactly as the flag does. Absent or
    `false`, the flag alone decides; another backend ignores it; a config with an `envTool` section ignores it (the
    environment it provisions is not the server the yes was for).
  - `lethal verify` (which also runs mutants on bcdev) passes it to its backend.
  - Any other value is refused by name (`validateBcDevConfig`).
- `scripts/bc-linux-setup.ts` `bcdevSection` writes it for bc1-bc4, so every fixture config the setup writes and
  r560c's credit-limit bc1 config carry it. bc-demo's section does not.
- Lanes build per-task configs from the setup's `bcdev` section, so they carry it once rewritten (`--write-config-only`,
  bc4 on its own since `--server all` is bc1-bc3). docs/gates/servers.md records the ruling, the step and how results can
  differ (a hang scored `timeout-killed`, `--resume` re-running such rows); README, the agent guide and the
  measurement-campaign skill name the field.

**Why no gate moves.** Every BC gate builds its backend from named config fields and sets the stop per leg (`itest:hang`'s OFF
leg stays off); none reads the new field, and none starts a run through `runFromCli` or `verifyFromCli`. Proven live: the
hang gate's legs and one bcdev gate on configs rewritten with the field (figures in the task result).

**Tests.** cli.test.ts: the validator both ways; `runFromCli` passes the stop to the backend and the session for bcdev +
true, not for absent, false, al-runner-v3 or an envTool config, and the flag still wins over false; `verify` passes it
only when the section says true. bc-linux-setup.test.ts: every server and fixture on; bc-demo's section off. Ten
mutations, each red.
