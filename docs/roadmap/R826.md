**Filed 2026-11-05 by lethal-code, from GitHub #28.**

**What was reported.** An all-operators run on one codeunit (1,342 lines, 38 procedures, 907 guards deployed) published fine in
169 s. During the baseline the BC service tier died with exception 0xc00000fd in `coreclr.dll`, which is a stack overflow. The
service stayed stopped until someone started it. LethAL's side worked: the run was quarantined, no mutant was scored, and it
exited 3. On the same codeunit, build and container, single-operator runs passed at 56 guards (`conditional-boundary`), 137
(`negate-conditional`) and 263 (`remove-assignment`). The crash run had 19 operators.

**What is checked (code read on master, 2026-11-05).** LethAL does not handle this.
- `publish-ceiling.ts` refuses a file only after a publish failure is recorded on that tier. A stack overflow in tests comes after
  a successful publish, so it cannot see one.
- `--max-guards-per-batch` splits by file, so one 907-guard file stays one batch.
- `--dry-run` prints site counts and the publish bracket, and gives no warning about run-time risk. `doctor` does not read guard
  counts. The run itself has no check.
- R349, R353, R411, R421 and R513 are about other things.

**What is not known.** The cause is an inference. The failure point is between 263 and 907 guards in that file, from one
reporter's runs. Guard count is not separated from guard shape, because every passing run had one operator and the crash had 19.
- `emitDispatch` builds a flat `if ... else if ... else` chain per statement, so guards add no call depth at the AL level.
- How the AL compiler and .NET handle a long chain, or one very large generated method, is not measured. An `else if` chain is
  still nested in a syntax tree, so a recursive pass over it could go deep.
- It could be the total count, one operator's guard shape, or the longest single chain.

**Proposal.**
1. Measure first, as a separate task: on a bc server, grow guards per codeunit, per procedure and per statement separately, and
   find what crashes, with several operators in one run. A crash stops the service tier, so use a server that can be restarted,
   under a lease, and bound it. The reporter says every other operator on that codeunit is under 80 guards, so single-operator
   runs cannot narrow the range much further.
2. Only then pick the limit. Until a figure is measured, any threshold is a guess, so do not ship one as a refusal.
3. Then add a warning to `--dry-run` and the run's first lines, in the place `--dry-run` already shows per-file counts, with an
   override flag if it refuses.
4. When a run's service tier dies, name guard count as a suspect in the quarantine message.

**To close.** A measured limit with its evidence, the warning or refusal built on it, and a reply on #28.
