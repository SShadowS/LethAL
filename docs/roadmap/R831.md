**Filed 2026-11-05 by lethal-bugs.** Related: [[R196]], [[R829]].

**What.** `assignmentTargetOf`, `memberTargetOf` and `indirectFeeds` read a bare name or a member, not a subscript. So the loop's
own step above is mutated, and `remove-assignment` of it hangs. The feed form misses too: `Buf[1] := Step; Pos := Buf[1]`. This
predates R829, which does not change it.

**Next.** Match on the array's name, by name, the safe direction for a refusal. Count the sites on the corpora first; ordinals
move, so it needs an `IDENTITY_SCHEME` bump and a pre-commitment.

## Plan (R-833, draft 1, not reviewed)

Teach `assignmentTargetOf`, `memberTargetOf` and `indirectFeeds` to read a subscript as its array's name, so `Buf[1]` and `Buf[2]` are
one name: the safe direction for a refusal. This is the smallest piece of R-833 and has no ruling to wait for, apart from the same
`IDENTITY_SCHEME` bump as [[R830]]. The two go in one bump. [[R829]], which walks the same feeds, has landed, so build on it.
