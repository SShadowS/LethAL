**Filed 2026-10-10 by coord task R-521** (found on the way, `/coord/handoff/R-521/measure.md`, "Outside both
items"). A plausible hang that is NOT refused. Not [[R520]] or [[R521]]: those are about report items; this is a
codeunit's own `repeat`/`while` loop.

**What.** R196/R239 refuse a value mutant at a site in the loop's own exit condition, and [[R531]] refuses a
consuming loop's record consumers. Neither follows the exit condition into a procedure in ANOTHER object that
advances the cursor. Examples in BaseApp on master `4b71102a`:

- `Create Pick`.CreateTempItemTrkgLines repeats until FindNextEntrySummaryFEFO returns false or the quantity left
  to pick is zero. The callee is in `Whse. Item Tracking FEFO`. 14 mutants are deployed in
  FindNextEntrySummaryFEFO, among them a `flip-boolean-literal` of the false it returns at the end, which can make
  the loop never end.
- `Gen. Jnl.-Post Line` and `Budget Depreciation` repeat until GetNextGLAcc returns 0. The callee is in
  `FA Insert G/L Account`. 4 mutants are deployed in GetNextGLAcc, among them `return-value`. (Corrected at close:
  this one does NOT hang, see below. And `Gen. Jnl.-Post Line` calls `FA Jnl.-Post Line`.GetNextGLAcc, which
  hands off through `FA Insert Ledger Entry`.GetNextGLAcc to `FA Insert G/L Account`.GetNextGLAcc: a delegation
  chain.)

**Not measured.** The price and the hang rate: only these procedures were read. Whether [[R531]]'s HOP could carry
this shape was not checked.

**To close.** Count the loops whose exit reads a call into another project object, price the callee's deployed
sites, read a sample, then refuse the exit-feeding callee or close it with a ruling.

**The sample.** 15 sites read by hand: 10 can hang (Create Pick's FEFO, Business Chart Buffer, Sales Tax Calculate,
Document Attachment Mgmt, TempStack, Power BI Report Aggregator, Price Source/Asset List, Workflow Step, Job Queue
Entry, DC's Message Bus Socket), 1 plausibly can (Reservation Engine Mgt. NEXTRecord), 4 cannot. **GetNextGLAcc does
NOT hang**: it returns an Integer, and every deployed mutant there (`return-value`, a removed Next assignment) ends
the loop EARLY by making it 0. Its chain is refused anyway, because the rule is positional and does not read values.

**The rule** (`inR570Callee` in `loop-hazard.ts`, one more OR term in R501's dispatch check `openItemHangRefuses`,
over a per-context map built once, the `oneHopReach` pattern):
- every `while`/`repeat` loop of every object kind, report item triggers included (R500's shape 8 ruling updated);
- its EXIT CALLS: the calls in its condition, and the calls in a body exit guard (`exit`, a `break` of THIS loop,
  `Error` outside `asserterror`) when the condition steps no cursor, or when the guard call shares the condition's
  cursor (that record is the call's receiver, or is passed to a `var` parameter);
- resolved with the existing resolvers (`callTargets`, `objectsOfType` with tableextensions and interface
  implementers, `r531TableProcs`, R564's `r531ProcsIn`; an uncertain call follows every candidate), into ANOTHER
  project object;
- the callee is CURSOR-SHAPED: it calls `Find*`, `Next`, `IsEmpty` or `Count` (by name, so a List `Count` counts) or
  holds a loop;
- the DELEGATION CHAIN: every call inside the callee's `exit(...)` that resolves to a project procedure is followed,
  up to 4 hops (the cap also ends a cycle); only built-in methods end a chain, so a wrapper over a `Next`-named
  project procedure reaches the real one. Every procedure on a chain that reaches a cursor-shaped one is refused;
- a SAME-OBJECT FIRST HOP (I3b): an exit call to a procedure of the loop's own object whose `exit(<call>)` reaches
  such a chain in another object refuses that procedure and the chain;
- EVERY deployed site in those procedures is refused, for every operator (the sample's hangs include index
  increments, row deletes and flag assignments, not only returns). Matching is by name, so every overload of a
  refused name is refused.
