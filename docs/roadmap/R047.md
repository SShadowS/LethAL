**The per-mutant time budget is a hardcoded floor, and one slow (mutant, test) pair costs the WHOLE run.** The budget is `2 x that test's baseline duration`, floored at `MIN_MUTANT_BUDGET_MS = 30_000` (`packages/runner/src/orchestrator.ts`) — a constant with no config or flag reaching it. When a mutated run exceeds it the client aborts, which is correctly indistinguishable from "the server may still be executing it", so the session latches unsafe, stops scheduling, and writes a durable quarantine. **Measured 2026-07-27** attempting R37's all-tests sweep on Continia Document Output with `coverageMode: "none"`: quarantined at mutant **M0013 of 138** on `SendPeriodStatements_WhenCustomerSetToAutomatic_ShouldProcessCustomer`, losing the run after 330 s. The exposure scales with (mutants x tests): an all-tests sweep multiplies the number of pairs that can hit the ceiling, so the very configuration R37 asks for is the one most likely to abort. A slow test is ordinary in a real suite — DO's per-mutant mean under all-tests was 19.5 s with a p95 of 43 s across 44 tests. Wants `--mutant-timeout-ms` (or a multiplier) so a real project can raise it, and is worth pairing with a resume capability so an abort at mutant 13 does not discard the first 12. Evidence: `docs/benchmarks/` timings, the quarantine reason recorded in that run's report.
