`doctor`'s `al-runner-cache` check reads `~/.local/share/al-runner/artifacts` — the BC artifact
cache R131 measured, 1.5 GB here across 10 builds. That is the whole of what LethAL reports.

al-runner also keeps `~/.cache/al-runner/`, and on 2.3.1 it holds SIX directories:

| directory | size here |
| --- | ---: |
| `ncl-cecil` | 86 MB |
| `al-out` | 37 MB |
| `workspace-deps` | 14 MB |
| `compiled-deps` | 6.5 MB |
| `bc-symbols` | 5.3 MB |
| `app-manifests` | 577 KB |
| **total** | **149 MB** |

`al-out` is named in 2.3.1's `--help` as the AL-output cache (`--cache DIR`, `--no-cache`,
`--print-cache-key`), keyed on "hash of .al sources, resolved deps, runner mtime". The other five are
undocumented in `--help`.

**Why it matters, and why it is small.** R131's ruling is that LethAL REPORTS cache size and never
deletes: removing directories out of a cache al-runner owns is a destructive operation on state
another tool manages. That ruling is right and this row does not reopen it. But the reporting is
now partial — a user asking `doctor` why their disk is filling gets 1.5 GB when the answer is
1.65 GB, and the missing tree is the one that grows per PROJECT rather than per BC build, so on a
machine running many projects it is the one that surprises.

**What a fix looks like:** extend `al-runner-cache` to report both roots separately, keeping the
existing superseded-build analysis for the artifact tree (which is what makes that number
actionable) and reporting the second as a plain total. Do NOT invent a superseded rule for the
second tree: `al-out` is content-keyed and al-runner manages its own eviction, so "superseded" has
no meaning there that this project has measured.

**Not urgent.** 149 MB against 1.5 GB, and nothing is wrong with the number LethAL prints today — it
is accurate about what it names. It is incomplete about what a reader wants to know.

Found while re-measuring the gate after the 2.1.2 -> 2.3.1 bump.

---

**CLOSED 2026-08-20.** `AlRunnerCacheReport` gained `secondaryBytes`/`secondaryDir`, and the one-line
`doctor` summary appends a clause naming the second root, its size, and that LethAL reports rather
than manages it.

Measured on this machine after the change: **1.4 GB** of artifacts across 10 BC builds, plus
**133.1 MB** in `~/.cache/al-runner`. The row measured 149 MB on 2026-08-20; the tree moves as
projects come and go, which is the point of reporting it rather than pinning it.

Two things the row asked for and this deliberately does NOT do. It invents no superseded analysis for
the second tree — `al-out` is content-keyed and al-runner evicts it, so "superseded" has no meaning
there this project has measured. And it deletes nothing, which is [[R131]]'s ruling carried over
unchanged rather than re-decided.

The clause is appended to EVERY branch, including the two that report no artifact cache at all: a
machine can fill `~/.cache/al-runner` while the artifact root is missing, and reporting 0 there would
be the incomplete answer this row exists to fix. A test pins that branch and pins the absence of a
superseded verdict.
