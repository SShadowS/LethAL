Coord task PR-162, 2026-11-18. Evidence: `/coord/handoff/PR-162/compile-fixtures.txt` (with the script's tar) and
`compile-fixtures2.txt` (with the tar PR-162 pinned). Related: [[R670]], [[R673]], [[R56]], [[R807]].

**Gap 1: the rebuild script drops sandbox-wrapped's WRAPDEF objects.**
- `scripts/build-fixture-symbols-tar.sh` rebuilds every LethAL app copy with `alc /project:<target>`, and passes no
  preprocessor symbol.
- `sandbox-wrapped`'s tests app is compiled against a build WITH `/define:WRAPDEF` (R673 built it by hand that way). So a
  tar rebuilt by the script fails `sandbox-wrapped-tests` with 8 AL0185 errors ("Codeunit 'Wrapped Top' is missing", and
  others).
- Measured in PR-162. The script's output tar compiled every project but that one. PR-162 therefore pinned a tar made of
  the R673 tar, byte for byte, plus only its two new projects, not the script's output.
- **Fix:** the script builds `sandbox-wrapped` with `/define:WRAPDEF`, or reads the symbols each test project needs from
  its config. A test of the script against R673's tar would catch it.
- **Fixed (coord PR-167, 2026-11-18):** the script builds each LethAL dependency that has a `symbol-sets.json` under the
  file's FIRST set, with `/define:` (`sandbox-wrapped`: `WRAPDEF`). An empty first set gets no `/define`, so
  `sandbox-symbols` (`[]` first) builds as before.
  - **Measured:** the fixed script, run on the pinned tar `165b17dd…`, made a tar against which `compile:fixtures`
    compiled all 35 projects, `sandbox-wrapped-tests` included, with no SKIP and no FAIL
    (`/coord/handoff/PR-167/compile.log`).
  - **Test:** `scripts/build-fixture-symbols-tar.test.ts` runs the whole script with a fake `alc` that records its
    arguments. Red-checked: with the `/define` dropped, the WRAPDEF test goes red.
  - **The pinned tar is unchanged**, so there is no swap: its contents were already right (orchestrator ruling). The fix
    guards the next rebuild.

**Gap 2: six projects are in no tar.**
- `fixtures/sandbox-dates`, `sandbox-dates-tests`, `sandbox-optin`, `sandbox-optin-tests`, `sandbox-order` and
  `sandbox-order-tests` have no `.alpackages` in the pinned tar (R673's, or PR-162's). So `compile:fixtures` prints
  `SKIP ... no .alpackages` for all six on every machine that takes its symbols from the tar.
- R807 compiled `sandbox-order` by hand for that reason.
- This is R56's trap: a broken fixture there is measured from a stale build, and nothing compiles it.
- **Fix:** add their `.alpackages` (Microsoft symbols plus the LethAL app copy for the tests projects) to the tar, re-pin,
  and confirm `compile:fixtures --require-symbol-sets` prints no SKIP.
