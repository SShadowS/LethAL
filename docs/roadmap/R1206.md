**Found by** the spec review of PR-410 (lethal-code, 2026-11-24), SERIOUS 3. It is pre-existing, from PR-340; PR-410
does not change it. Evidence: `docs/superpowers/specs/2026-11-24-pr410-carry-walk-skip.md`.

- **What could break:**
  - Baseline rows from a serve daemon get `flaggedUnknown` when the daemon does not report a flag state (R949).
  - The carry walk builds its rows with `serveRow` in `carryWalkSend` and never adds `flaggedUnknown`.
  - `judgeCarryWalk`'s B1 leftover refuses a pass that is `flagged` or `flaggedUnknown`. So on a build whose serve rows
    omit `flagged` (the R949 shape, upstream #7954), a pass resting on an unprobed assumption would read as a sound pass
    inside the walk.
  - That pass could then take part in a `fail, pass, fail` kill.
- **Today:** c4's walks (main-bf3a3e863) failed on "passed but al-runner flagged", so that build writes `flagged` on serve
  rows and the gap is closed in practice.
- **The fix to decide:**
  - Either the carry walk marks its rows `flaggedUnknown` exactly as the baseline daemon path does,
  - or "carry-proven" also requires a gate fact that the build writes `flagged` on serve rows.

  Not built here.
- **Measured by PR-432 (lethal-code, 2026-11-25; `/coord/handoff/PR-432/findings.md`).**
  - `current` (edge-e5176a9fd) writes `flagged` on serve rows. PR-422's c5 ran on it with a serve-daemon baseline
    (the R949 notice fired): 1,735 of its passes carry `flagged: true`, and PR-410's skip fired 129 times, which it does
    only on a daemon row with `flagged: true`. main-bf3a3e863 writes it too (c4, above).
  - So the gap is closed in practice on both builds in use, and a fix would move 0 results.
- **Closed by ruling, nothing built.** Both proposed fixes were rejected:
  - Marking every walk row `flaggedUnknown` makes every walk pass unsound, which turns the carry walk off everywhere.
  - The orchestrator's in-run signal ("any baseline daemon row is `flaggedUnknown`, so the walk fails safe") does not
    work either. R949 marks EVERY daemon row `flaggedUnknown` (`al-runner-v3-backend.ts`, the daemon baseline paths),
    and `flaggedUnknown` survives on every row that is not `flagged: true`. Any unflagged daemon pass therefore fires
    the signal, on a build that writes the flag as on one that does not, and the carry gate's walk kills would move.
  - A sound per-build fact (a pin field, or a leg-C fact) was not chosen. R1215 files the underlying problem.
