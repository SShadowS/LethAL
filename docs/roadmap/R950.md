Found by lethal-bugs, 2026-11-12 (coord R-939, from the day's update run). Evidence: `/coord/handoff/R-815/daily-2026-11-12.out`.
Related: [[R723]], [[R814]], [[R777]].

**What happened.** edge-2bd87774f (251 commits past `current`) passed every gate leg at 13:30 UTC, and the update logged `passed;
deferred: in use (current not moved)`: three lanes had v3 runs going, and the guard (`inUse`) defers a move while ANY process whose
executable resolves under /work/tools/al-runner-v3 runs. A deferred pass is retried by the next daily run, which meets the same
lanes. So the move can wait for days.

**Why the guard is wider than it needs to be.** A move swaps only the `current` symlink. The v3 backend resolves its binary once,
when it is built (`resolveV3Binary`, a `realpath`, in `AlRunnerV3Backend`'s constructor), so every LethAL session spawns
`.../edge-<build>/al-runner` by its real path and never sees a later move: measured 2026-11-12, every running al-runner process,
those of a session whose config named `current/al-runner` included, had the explicit build path as `argv[0]`. Only a process
started through `current/` itself (by hand, or by a tool that does not resolve) would get the new build at its next spawn. The
old `.gated` stays too, so a pinned build stays admitted.

**Wanted.** The guard counts a process only when its `argv[0]` runs through `current/`, or cannot be read or is relative; a process
whose `argv[0]` names an explicit build folder is ignored. Red both ways.
