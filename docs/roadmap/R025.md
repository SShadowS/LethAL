**A stale locally-built `lethal-control.app` fails with a confusing error.** `*.app` is gitignored, so the control artifact is a local build — and a build older than its AL source publishes fine, then fails harness verification with `HTTP 400: the parameter 'clientProtocol' … is not a valid parameter`. Confusing precisely because the endpoint EXISTS and answers; it just rejects an argument added later. Hit live on 2026-07-26 during the first env-tool gate run. Wants either a build step that rebuilds it before a gate, or a version/shape check in `HarnessVerifier` that says "your control app is older than this client" instead of surfacing BC's parameter error.
