Filed by coord PR-221 (lethal-code, 2026-11-19) on the owner's ruling q-20261119T120709-aec0ef17: do not build it now
(principle 13); file it with its trigger (principle 35). Evidence: [[R1113]]'s PR-221 section, `/coord/handoff/PR-221/`.

**What was measured.** PR-200's T3 test (create a company, Commit, delete it, Commit) ran through LethAL on bc4 (BC 29):
- **With LethAL's lease renew:** 2 of 2 runs broke the tier. BC answered HTTP 400 "begin transaction world not called",
  then 401 for every web-service call, until a restart.
- **Without it** (a scratch client that skips the renew): 2 valid runs. One was clean. The other left the tier rolling
  back every company create.
- **BC's own test runner, with no LethAL in the path,** once took a freshly restarted bc4 down with the same test.
- So the shape is unsafe on BC 29 whatever runs it, and the renew is a second trigger on LethAL's path.
- **Today's protection:** PR-212 leaves company-writing tests out of a default run.

**Why the renew is a trigger.** The client renews about every 5 s from a second web-service session.
`LC Control State.TryRenew` does `LockTable` on the one cross-company `LC Lease` row, then Get, Modify, `Commit`. The run
session claims the same row in `TryBeginRun` (before the test) and `TryFinishRun` (after it). In PR-200's T3 run the
renews first got no answer for 30 s and then HTTP 400, while the test created and deleted its company. The break
followed.

**The options:**
- **(a) Client side:** pause the renew while a run call is in flight, and let the run claim cover the gap. `ExtendRunClaim`
  already pushes Expires At out by grace plus one renew period, and the run's own finish is honoured past expiry. The
  runway must then cover the longest call (the 120 s baseline budget, and RunMutantMany's length).
  - Risk: a competing acquire could classify a long run as orphaned, which is [[R658]]'s rule and design §5. The server
    would need to treat Op Kind = run as alive.
- **(b) Server side, the lean:** `TryRenew` neither locks nor writes while Op Kind = run and the runway is long enough; it
  answers renewed:true from a read.
  - It removes the write contention at its source and keeps the client's contract and R658's liveness.
  - It needs a control-app bump and the hang gate, which is the only gate that exercises the control app's stop.
- **Either way:** this removes one trigger, not the platform's. A company-commit test can still break BC 29 through any
  runner.

**The trigger to revisit:**
- `--keep-company-tests` is used for real, so company-writing tests run on BC on purpose; or
- Microsoft fixes the platform behaviour (the BC 29 note: `/coord/handoff/PR-212/bc29-tier-break-note.md`, with PR-221's
  repro through BC's own runner).

**The trigger fired: `--keep-company-tests` used for real (PR-287, lethal-bugs, 2026-11-21; `/coord/handoff/PR-287/`).**
- **What ran:** 14 company-writing DO tests on bc4 (BC 29), under the owner's yes (q-20261121T161208-2fb06e17), in one batch
  through LethAL with the lease renew in place:
  - 2 in `CDO ABS Auth Settings Tests`, one of them create, delete and Commit;
  - 12 in `CDO Azure Blob Folder Tests`, most creating a second company through a helper in another codeunit.
- **The tier did NOT break this time.** Doctor was healthy before and after; no 401s, no restart. Together with codeunit 69001
  alone, that is 2 runs with company tests and 0 tier breaks.
- **The rollback symptom showed up instead, on every test that creates a SECOND company through a library helper:**
  - all 12 `CDO Azure Blob Folder Tests` error in the baseline with "RunMutant returned 0 test lines, expected exactly 1; server:
    Transaction was rolled back by the server";
  - the 2 `CDO ABS Auth Settings Tests` (direct company writes) pass.
  This matches the "rolling back every company create" outcome measured above.
- **So:** company-creating tests can run through the harness on BC 29 without breaking the tier, but those that create another
  company mostly cannot be measured: they error at baseline, so they kill nothing.
  - PR-287's verdicts were not affected beyond that: 1 of 174 mutants, M37120, had such a test as its only al-runner killer.
  - The gap to close is the same as this item's: one run session that does not contend, or a platform fix.
