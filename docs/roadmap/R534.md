**Priority.** Filed 2026-10-08 by the R518 build, from the adversarial review of its plan (I1, M5).
A policy question, not a measured defect: never a false kill, but a whole session lost to one
mutant.

**What.** `verdictFromRunnerTest` scores an al-runner row whose status is not `pass` or `fail`, and
whose message is not a timeout wording (`RUNNER_TIMEOUT_MESSAGE`), as `error` with
`AL_RUNNER_UNCLASSIFIED_ERROR` and `operation: "pre-dispatch-rejected"`. `runOnce` re-sends it once
(`isRetrySafe`). If the retry is the same `error`, `classifyNonVerdictStep` marks it a transport
error and `runMutantsOnBackend` throws `backend transport error: two consecutive run() failures for
mutant <id> (test <m>) — aborting session per spec §11`. No verdict for that mutant or any later one.

[[R518]] fixed the common case, a test that hits al-runner's in-run stop (exit 3, now read as a
`timeout`). It did NOT change this path. A hang in the test codeunit's `OnRun` trigger, or a
`RunnerOutOfScopeException`, can still give a TEST-TIMEOUT abort whose row message is not a timeout
wording: R518's transport accepts the envelope, the row scores `error`, the retry runs the hang a
second time, and the session aborts.

**The question.** Spec §11's rule exists for a TRANSPORT that failed twice (the backend cannot be
trusted to answer). An al-runner `error` row is an ANSWER: al-runner ran, reported, and exited.
Should such a row (a) keep aborting the session, (b) score the mutant `error` with its cause and let
the session continue, or (c) at least not be re-sent (it is not "pre-dispatch": the test ran)?
Option (c) alone halves the cost of a hang that is not classified; (b) also keeps the session.

**Evidence.** Plan `/coord/handoff/R-518/plan.md` §D2 last point; review
`/coord/handoff/R-518/review-r1-opus-adversary.md` I1 and M5. The offline test that pins today's
shape is `AlRunnerBackend one-shot: a test timeout exits 3 (R518)` > "an OnRun-trigger exit 3 is
accepted as rows but scored a fail-closed error, never timeout" in
`packages/runner/tests/al-runner-backend.test.ts`. The code is `verdictFromRunnerTest` in
`packages/runner/src/al-runner-backend.ts` and `classifyNonVerdictStep` in
`packages/runner/src/orchestrator.ts`. Not measured live: no fixture has an `OnRun` hang.

**To close.** A ruling on (a), (b) or (c). If (b) or (c): the change, red-checked both ways, and a
session-level offline test where the unclassified row no longer aborts the session.
