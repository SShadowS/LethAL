**What.**
- **#7818** (https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7818): an API page that declares several versions gets
  only the first in `Page Metadata.APIVersion`; BC holds all of them comma-separated, as Microsoft's MCP module reads it. Two MCP
  tests fail in the baseline. A wrong answer, reduced to an invented page.
- **#7819** (https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7819): six refusal causes reduced to invented tests
  (`Clear` of an `XmlWriteOptions`, `RemoveCookie` of the last cookie, `Error` with a blank `ErrorInfo`, `FilterGroup` on an unopened
  `RecordRef`, platform table `Performance Profile Scheduler` with no provider, `Query Metadata`'s `AL Namespace` column), and more by
  Microsoft test name. The largest losses: External File Storage 15 of 28 tests (a system-table `ReadPermission` refusal),
  Performance Profiler 16 of 30 (DotNet Newtonsoft, then a profiler contract type), MCP 8 (platform `Query Metadata`), Retention
  Policy 8 (relation targets on system tables). The issue also lists 16 baseline fails not yet reduced.

Both runtime differences rest on Microsoft shipping these tests as passing; neither invented app was run on a BC server.

**Also measured, no change made.** al-runner's `--dotnet-assembly-dir` is not wired from `assemblyProbingPaths` ([[R900]]: a separate
knob). Pointing it at the Windows BC 28.4 service folder loads Newtonsoft for Performance Profiler's chart tests, but they then stop on
the next refusal, so wiring it would not win tests here yet.

**To close.** Both fixed upstream, and the seven modules re-run: the refused and failing tests in the baseline, their mutants scored.
