**Measured offline 2026-09-26 for GH-09 (hypothesis H4 in the GH-09 plan), in a scratch copy of
`sandbox-data`.** A `report 79391` plus `reportextension 79390` in `namespace LethAL.Probe`, holding
one procedure with an `if` and two `exit`s:

1. **No mutant is emitted there, and it is said out loud.** `lethal run --dry-run` skips the file:
   `skipped ... src\DataProbeReportExt.ReportExt.al (namespace_declaration,
   reportextension_declaration, 4 site(s))`, because `reportextension` is not in `CARRIER_KINDS`.
   So this is NOT a silent `no-coverage` path like issue #9; it is a scope gap that is reported.
2. **The stated reason does not hold for this kind.** The skip message says a guard in any other
   kind "cannot compile (AL0118)". The same report extension with a global
   `var Probe: Codeunit "Data Ops";` compiles clean (`alc` 18.0.41, exit 0). R40 found the same for
   `page` and `report`: the constraint was never the kind.
3. **Adding it to `CARRIER_KINDS` alone would CREATE the silent path.** The compiled
   `SymbolReference.json` carries the object under `Namespaces[LethAL > Probe].ReportExtensions`, and
   `AppMethodIndex`'s `SYMBOL_ARRAYS`, `OBJECT_TYPE_NAME` and the line map's
   `OBJECT_KIND_TO_TYPE_NAME` have no report-extension entry. Its rows would be dropped as
   undeclared and every mutant would read `no-coverage`, which is issue #9's shape exactly.

**To build it:** measure the `Code Coverage` "Object Type" integer BC records for a report
extension's rows first (R40's rule: these integers are measured, never guessed), then add all three
entries and the carrier kind together, with a fixture arm whose verdicts are pre-committed. Until
then the loud skip is the honest behaviour.

**Done 2026-10-05 (`2573f39b`, merged `c5e39fed`, IDENTITY_SCHEME 17).** A reportextension is a carrier
kind; BC records its coverage as Object Type 22 under its own id (measured on Cronus28) and al-runner
gives it its own Cobertura class. The sandbox-data arm (15 mutants) was pre-committed in
`docs/superpowers/specs/2026-10-05-r254-reportextension-arm-precommitment.md` and `itest:tables`
matched it (310 / 70 / 22). The status line was left `open` at merge and corrected by the
orchestrator's roadmap audit. Follow-ups: [[R463]] (Tier-2 claiming in a reportextension) and
[[R470]] (selector name collision, fixed).
