**Filed 2026-10-09 by the [[R531]] build** (plan r1, "The miss, filed as its own item",
`/coord/reviews/R-531-plan/plan.r1.md`; measured in `/coord/handoff/R-531/measure.md`, Addendum). A plausible
hang that is NOT refused.

**What.** R531's FILTER part refuses every site inside a `SetRange`/`SetFilter` on R that comes before a
consuming loop in the same scope, when the loop's ending depends on that filter (for a `Rename` consumer, every
filter on R). In CDO and DO the OnRename loops of the same shape take their filter from a TABLE PROCEDURE on the
line record instead: `SetTemplateFilter(xRec)` and `SetEMailTemplateLineFilter(xRec)` (DO's
`CDOEMailTemplateLine` OnRename is one, sampled in measure.md as a certain hang if the `Rename` is removed;
the build's re-measurement names every site). The filter call sits inside the callee, so FILTER does not see it, and
CDO and DO get 0 FILTER sites (measure.md Addendum, "Results, per corpus"). A mutant that weakens the callee's
filter (`remove-setrange`, or `swap-rec-xrec` turning `xRec` into `Rec` in the call's argument) can make the
OnRename loop find the renamed lines for ever, as it does in BaseApp's directly filtered OnRename loops.

**To close.** Follow a call on R before the loop (a table procedure on R, or a same-object procedure taking R as
`var`) into its body, and treat the `SetRange`/`SetFilter` calls on R found there as pre-loop filters, with the
sites in the CALL's arguments (the `xRec` passed in) refused too. That is a call-following resolution rule (the
R500 / [[R521]] kind of callee resolution), which is why R531 did not include it. Re-measure on CDO and DO and
name the sites.

## Built 2026-10-10 (branch `lethal/r562`, coord task R-562; identity scheme 39, no bump)

Plan: `/coord/reviews/R-562-plan/plan.r1.md` and `plan.r2.md` (r2 overrides), with the review `adversary-r1.md`.
Census, sites and cost: `/coord/handoff/R-562/measure.md` (with Addendum 1). Build log and red checks:
`/coord/handoff/R-562/build.md`.

**What was built: FILTER HOP**, in `r562FilterHop` (`packages/builtin-tier1/src/loop-hazard.ts`), called from
`r531AnalyzeOnce` for every call that ends before a loop whose ending depends on a filter (R531's dependency map,
or a `Mark` consumer). Every part is always on.
- **Followed one hop:** a table procedure on R (`declaredType` + `objectsOfType`, every overload that fits by
  arity); a same-object procedure that sees R (the implicit Rec, or a global neither side shadows); R passed to a
  `var` parameter of a same-object procedure, or of a project codeunit or table procedure (F4). A by-value Record
  is NOT followed: its filters belong to the copy, never to the caller's R. (This is the reverse of R531's HOP,
  where a by-value copy's `Delete` still hits the table.)
- **Refused in the callee:** each `SetRange`/`SetFilter` on R that passes FILTER's dependency test (any filter
  for a `Rename` consumer, otherwise a field the consumer changes), and `MarkedOnly` for a `Mark` consumer; the
  statements and blocks containing them; the conditions around them; and (F2) every `exit` and raised `Error`
  (outside `asserterror`) that starts before the last such filter, with its guards, since taking one skips the
  filter while the caller's loop still runs.
- **The call itself** joins the pre-loop filters, so its `void-method-call`, its arguments, the guards around it
  and FEEDS on its arguments are refused by R531's existing rules.
- **F1:** a `modify-unseen` loop (no filter on R in the procedure) now records every written field (and a
  `ModifyAll` field) as a dependency, so a loop filtered only through a helper is followed.
- **F3:** a call that cannot be followed is refused itself (the call, its arguments, its guards; nothing in a
  callee): a call on R whose procedure has no body in the project, R passed to a same-object name with no
  arity-fitting overload, or R passed into an object outside the project.
- **Not calls:** built-in record methods, `RecordRef.GetTable`/`SetTable`, `Codeunit.Run` (and a codeunit
  variable's `Run`), `Page`/`Report`/`XmlPort`/`Query` runs, and the pure functions R531 already excludes.

**The 4 sites** (census on every corpus: BC.History with BaseApp, CDO, DC, DO, fixtures; all OnRename):
- CDO `CDO E-Mail Template Line` (Table 6175284) OnRename -> `SetTemplateFilter` and
  `SetEMailTemplateLineFilter`;
- DO `CDOEMailTemplateLine.Table.al` OnRename -> the same two.

BC.History (BaseApp included), DC and the fixtures have 0.

**The known cost: 8 DO over-refusals.** Each DO callee table has TWO 1-parameter overloads, one taking
`CDO E-Mail Template Line` and one taking `CDO Document Template Line`. Overloads are chosen by arity (R531's
rule), so both are followed, and the `CDO Document Template Line` overload's `remove-setrange` x3 and
`empty-block` x1 per table are refused although OnRename never calls it. Choosing the overload by argument type
removes them; it is filed as its own item, [[R564]].

certain-hang shape R-531 sampled, and 8 of the 35 specs are the arity over-refusal".

**F1-F4 measured at 0 sites today** on every corpus (the adversary's findings 1-4, prototyped behind switches and

`GetTable`/`Codeunit.Run`/object run passing R; no project-codeunit callee. They are built because each is a
certain hang the base rule would miss, at no measured cost.

**Limits (shared with direct FILTER, stated):**
- two hops (a callee that calls another procedure to set the filter);
- event publishers and their subscribers: a subscriber can filter a `var` Rec, while the empty publisher body
  reads as setting no filter;
- a filter set on a local copy and moved over with `CopyFilters`/`SetView`;
- a call between nested loops (after the inner loop but inside the outer, it runs before the inner's next pass);
- the callee's own FEEDS (an assignment in the callee feeding its filter).
