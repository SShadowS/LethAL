**Found by** the spec-adversary review of PR-411's pre-commitment (lethal-preproc, 2026-11-24, review L3). Evidence:
`/coord/handoff/PR-411/spec-review.md`.

- **The gap:** `AlRunnerV3Backend.carryWalkSend` sends `[mutant, NONE, mutant]` on one daemon.
  - It closes the daemon only when a row is not kept (`serveDaemonReusable`), and it never sets `daemon.keptRefusal`.
  - So a daemon kept past a kept refusal in the walk serves the next `requestOne` with the drift guard (`keptRefusalDrift`)
    unarmed.
  - `requestOne` arms it from every answer, and the warm-up does not (PR-99 counts that one as `warmupsAfterKept`).
- **Why it matters:** every new keep row (PR-411's for R1205, for one) widens what a walk can keep a daemon past.
- **The fix:** the walk sets `keptRefusal` from its answers (the first kept refusal row) when it keeps the daemon. It never
  clears an earlier arm. Add a red-going test on the shell backend of `pr340-carry-walk.test.ts`.
- **Order:** after PR-410, which rewrites `carryWalkSend` (lethal-code). It was split out of PR-411 on the orchestrator's
  word, to avoid two edits to the same function.
- **Related:** PR-56 (the drift guard), PR-340 (the walk), R1205, PR-410.
