**Found by R-796b (2026-10-25)** building the tree-sitter-al 4.5.0 upgrade ([[R796]]). The unit half of the R402 shape
sweep (`scripts/r402-shapes.test.ts`) moved for ten shapes that 4.4.1 refused.

**What moved.** Under 4.5.0 the grammar attaches a loop condition's `#if` tail or prefix to the loop
(`preproc_conditional_expression_tail`, `preproc_operand_prefix`), so the shapes `c7b`, `c7e`, `c7f`, `c8`, `s4`, `s4b`, `s4c`,
`s4d` (4.4.1: `directive-continues-statement`) and `s8`, `s12` (4.4.1: `marker-mismatch`) are no longer refused. They are
admitted with these spec counts for the builds `[]`, `[LETHALX]`, `[LETHALY]`, `[LETHALX,LETHALY]`: c7b/c7e/c7f/s4/s4b 8,7,8,7; c8 10,9,9,9;
s4c 10,9,10,9; s4d and s12 10,9,10,8 and 10,9,10,8; s8 10,9,10,9. `w1`, `w2`, `w6` are direct members (16, 8, 32 specs in the
builds that compile the member). `s13` is still refused.

**A hang hole found and closed in R796b.** `s8` with `or` in place of `and` (`while #if X (B < 5) or #endif (A < 10)`) made
`B := B + 1` a `remove-assignment` site in the build with X: removing it hangs the loop. `loopConditionParts` read only the tail
kind, not the prefix. R796b reads `preproc_operand_prefix` too (and `flip-boolean-literal` walks through it). Tests:
`r402-hang-active-arm.test.ts` (S8, S8or, S12, t3), red-checked.

**Still open.**
1. Run `scripts/r402-shape-sweep.ts` (its alc half) on the ten admitted shapes: the unit half pins spec counts only, so nothing
   has compiled the instrumented artifact of a repeat-tail or prefix shape under 4.5.0. Until then those mutants are unproven.
2. An empty `var` followed by a `#if` procedure (`schemata` test `a-only-swallow`) now parses with ERROR nodes, so the file is
   refused whole (safe, but 4.4.1 instrumented it). Measure how many corpus files this costs; the dumps for R796 already include it.
3. `r424-split-members.test.ts` lost its live trigger for `TreeDiscoveryMismatchError` (the `#if` between `while` and `do` is read
   now); no 4.5.0 parse is known that trips that guard.
