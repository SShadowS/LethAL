**Eight of 19 `scripts/` files do not compile under the repo's own strict flags.** Measured
2026-08-07 by the survey R119 asked for, before `scripts/tsconfig.json` landed: 11 files compile
clean and are admitted to `tsc --build`; these 8 are not, and were deliberately left out rather
than admitted by weakening a flag for everyone else.

What each fails on:

- `census-swap-call-arguments.ts`, `census-tier3-candidates.ts`, `probe-grammar-corpus.ts`,
  `probe-grammar-table.ts`, `measure-gui-guarded.ts` — **TS2367 / TS2345 against `ALNodeKind`**:
  they compare or pass node kinds (`"quoted_identifier"`, `"basic_type"`, `"argument_list"`,
  `"attribute_content"`, `"property_name"`, `"ERROR"`, `"MISSING"`, `"if_keyword"`,
  `"then_keyword"`) that are not members of the union. Either the grammar moved under them and the
  comparison is now dead code that silently never fires, or `ALNodeKind` is incomplete. **Both
  readings matter and neither is cosmetic**: a comparison that can never be true makes a census
  under-count without erroring, and `census-swap-call-arguments.ts` and `census-tier3-candidates.ts`
  are the scripts whose counting rules R82 and R13 were decided on. Deciding which reading is
  right needs a run against a corpus, not a type fix.
- `probe-alrunner-tables.ts` — treats a `MutationSetResult` as an array (`.reduce`, spread), which
  it is not; the two implicit-`any` errors are downstream of that.
- `probe-continia-env.ts` — imports `@modelcontextprotocol/sdk/*`, which is not a dependency of
  this repo.
- `roadmap-index.test.ts` — TS5097 only, and **already fixed**: it is admitted, because
  `allowImportingTsExtensions` in the new `scripts/tsconfig.json` is what its `./roadmap-index.ts`
  import needs.

Fix: admit them one at a time by adding each to `files` in `scripts/tsconfig.json` once it
compiles, starting with the two census scripts, since those are the ones whose output was
load-bearing for a decision. **Do not** widen `files` to a glob and relax a flag to make the set
pass — the point of the explicit list is that admitting a script is a decision somebody made.
Filed 2026-08-07 alongside R119's fix.

**Closed 2026-08-07. The row posed the `ALNodeKind` failures as a fork — dead code that
under-counted, or an incomplete union — and the answer is NEITHER, which the row could not have
guessed without reading one getter.**

**`ALSyntaxNode.kind` is a type-level LIE, by design and with a comment saying so.** Its getter
returns the raw tree-sitter node type CAST into `ALNodeKind` whenever the raw type is not a member
of that union, and directs consumers to branch on `rawKind` for arbitrary kinds. `ALNodeKind` is a
CURATED subset of the grammar, not an enumeration of it — `symbol-table.ts` warns against widening
it precisely because widening also widens `isALNodeKind`, which every `kind` consumer reads. So
`node.kind === "quoted_identifier"` is a `TS2367` at compile time and TRUE at run time. The
comparison was never dead.

**Measured on the corpus the censuses were run on** (`U:/Git/do-rel2/Cloud`, 554 `.al` files), by
walking every parsed tree and counting raw node types:

| raw kind | nodes |
| --- | --- |
| `quoted_identifier` | 24,911 |
| `argument_list` | 18,146 |
| `property_name` | 16,230 |
| `basic_type` | 5,883 |
| `if_keyword` / `then_keyword` | 4,389 each |
| `attribute_content` | 369 |
| `ERROR` / `MISSING` | 0 |

`ERROR`/`MISSING` at 0 is the corpus parsing cleanly — the guard is unexercised, not unreachable.

**So no shipped census under-counted, and R82's and R13's counting rules rest on sound numbers.**
That is the part of this row that mattered, and it is now settled rather than assumed.

**The fix, therefore, was not to widen `ALNodeKind`** (which would change behaviour for every
consumer of `isALNodeKind`) **but to compare `rawKind`** — the honest `string` the codebase already
tells arbitrary-kind consumers to use. Behaviour-neutrality was PROVED rather than asserted: each
affected script was run against the corpus before and after, and every output is byte-identical.
The swap census was run three times — before the R117 sweep, after it, and after the `rawKind`
change — so the one differing line (a prose citation R117 rewrote) is separated from the counting,
which never moved.

**7 of the 8 admitted**, with no flag weakened and no `files` glob:
`census-swap-call-arguments.ts`, `census-tier3-candidates.ts`, `probe-grammar-corpus.ts`,
`probe-grammar-table.ts`, `measure-gui-guarded.ts` (all `rawKind`), and
`probe-alrunner-tables.ts` (`generateMutationSet` returns a `MutationSetResult`, not an array —
destructured, and it now also PRINTS `skipped`, since a site count with no hint that files were
left out is the empty-vs-empty reading this project keeps designing against).

**The 8th is a deliberate refusal.** `probe-continia-env.ts` imports
`@modelcontextprotocol/sdk/client/*`, which is not a dependency of this repo and is load-bearing
for what the probe does. Admitting it means adding a real dependency to typecheck a spent
2026-07-26 probe whose question is already answered in its own header. It stays out, and
`scripts/tsconfig.json` now says why.

**Row corrections:** the row lists nine kinds; the real set also includes
`tabledata_permission_list`, `attribute_item` and `attribute_arguments` (all in
`census-tier3-candidates.ts`). And the row's "deciding which reading is right needs a run against a
corpus" was right about the method and wrong about the stakes — the run confirmed the numbers
rather than overturning them.
