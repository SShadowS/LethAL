**Seen 2026-10-25** (`/coord/handoff/R-786/v3b/alrunner-v3.log`, LethAL 6475a706, al-runner 3.0.0-alpha.5+edge.20261024
(dcdf9e821), load average 15-16 on 32 cores, three heavy v3 jobs at once). Leg C's `timeout-is-cpu` pins one huge burn
to core 0 at the 2 s limit: run A alone must stop near 2 s, and run B beside seven busy loops must stop with a
durationMs over 3000 ms AND over twice A's. Here A itself took 16009 ms (wall 16298 ms) and B 16069 ms, so B was not
twice A and the fact read `diverged` against its pre-committed `matches`: `C=gate-fail`. The same build and fixture
measured A = 2008 ms on the previous gate run of that day (`/coord/handoff/R-786/v3/`), and R786's change does not
touch the contract probe. So the fact measures the load on core 0, not the build: when another job shares core 0,
A's CPU time accrues slowly in wall time and the "twice A" rule cannot hold.

**Effect.** The update gate and every gate run can fail on a correct build whenever the container is busy (now up to
three v3 jobs at once, by the owner's ruling). A failed update gate is `gate-fail`, which blacklists the build.

**To close.** Make the fact robust to load: e.g. measure A and B back to back on a core that A's own reading shows is
not contended (re-run A when its durationMs is far above the limit, and call the reading `infra` rather than
`diverged` when A itself is slow), or judge B against the limit only. Pre-commit the new rule; prove it on a loaded and a
quiet machine.

## Fixed (494082ea)

Rule: `docs/superpowers/specs/2026-10-25-r789-timeout-is-cpu-load-precommitment.md`. The fact pins A, B and the 7 busy
loops to the least busy core (`leastBusyCore`: two `/proc/stat` samples 200 ms apart just before A; busy = total - idle
- iowait; core 0 if unreadable). `measured` starts `core N; A ...`. A stopped with durationMs over 3000 ms
(`BURN_WALL_FACTOR` x limit; 3000 itself is not late) reads `unmeasurable` ("A late: core N contended") and B is not
run; leg C reads that as `infra-fail`, which the update gate retries and never blacklists. A wall-time build stops A at
about 2000 ms whatever the load, so it still reads `diverged`. Test hooks: `readProcStat`; `startBurner` now gets the
core. With only `startBurner` set, the real `/proc/stat` is not read (core 0).

Tests (`al-runner-v3-contract.test.ts`): contended correct build -> unmeasurable and B not run; wall-time build ->
diverged, loaded or not; quiet correct build -> matches; two probe runs (loaded then quiet: unmeasurable then matches;
wall-time build diverged both times); A at exactly 3000 ms runs B, 3001 does not; picker on fake snapshots (least busy,
ties to lowest, iowait not busy, unreadable -> 0); busy loops and both calls use the chosen core. Two older tests used
A = 4000 ms; they now use A = 2900 / 2500 ms because an A over 3000 ms is `unmeasurable` by design. Red checks (logs in
`/coord/handoff/R-789/red/`): no contention check -> 3 red; late check on wall time -> 3 red; late check inverted (fast A
skips B) -> 34 red; `>=` instead of `>` -> the 3000 ms test red; core 0 forced -> 3 red; picker returns 0 -> 4 red.

### Review fixes (addendum 1, 788d1961)

Rule: `docs/superpowers/specs/2026-10-25-r789-timeout-is-cpu-load-precommitment-addendum-1.md`. The first build read every
A over 3000 ms as contention, which would also read a wall-time limit WITH slack (a 3.5 s stop for a 2 s limit) as
`unmeasurable` on an idle core: lost detection. Now a stopped A over 3000 ms is contention only when its own process CPU
time is under 0.75 x its wall time (`BURN_CPU_SHARE`); otherwise B runs and the old rules judge it (the slack build reads
`diverged`). CPU time comes from Bun's `resourceUsage()` on the child (`SpawnFn` result `cpuMs`; `taskset` execs into
al-runner, so it is the same process); unknown CPU time reads `unmeasurable`. The picker also reads only the cores in
`Cpus_allowed_list` of `/proc/self/status` (`parseAllowedCores`); unreadable means core 0. Test hooks: `readSelfStatus`,
and `cpuMs` / `wallMs` on a fake spawn result. Red checks per direction: `/coord/handoff/R-789/red-review/`.
