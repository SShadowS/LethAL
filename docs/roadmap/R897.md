Found by coord task R-892. Evidence: `/coord/handoff/R-892/` (`result.md`, `hang/`, `repro-timeout/`, `pp/b-*`). Related: [[R896]],
[[R893]], [[R164]].

**What.** LethAL calls al-runner once per test codeunit, with every covering test of that codeunit, and sets `--test-timeout-secs`
from the per-mutant budget, at least 180 s (`MIN_MUTANT_BUDGET_MS`). When a mutant makes a test loop forever, al-runner stops that
test at the limit (CPU time). It then runs **every later test of the codeunit to the limit as well**, and reports each as "not run"
("an earlier test of this codeunit was refused while it ran"). So the call costs about (tests in the codeunit) x the limit, and yields
one stopped test plus a column of not-run rows.

**Measured.**
- PaymentPractices with one hand-made hang (`FindLast` to `FindFirst`, R893's site), `--test-timeout-secs 20`: the first test stopped
  at 20.7 s, then 27 more tests at 20-25 s each, all reported not run.
- Invented repro (`repro-timeout/`), 5 s limit: the looping test is stopped at 5.1 s, and a second test that reaches the same loop
  runs 6.8 s and is reported not run.
- Through LethAL: one such mutant, alone, ran its 20-minute cap with no verdict. A 57-mutant file with it took more than 1 hour against
  257 s without demo data. R-887's PaymentPractices run hit its 3-hour cap.

At 180 s and 23 covering tests this is about 69 minutes per hanging mutant.

**Directions (not chosen).**
1. When a call comes back with a stopped test, score the mutant from that row (a timeout is a non-pass, so it ends the mutant as on
   bcdev) and do not wait on the rest. That needs al-runner to stop the codeunit early, so see the upstream issue.
2. Run a mutant's covering tests one per call (`--test-exact`) after a timeout row is first seen in the batch.
3. A lower `--test-timeout-secs` for v3, set from the baseline's per-test times, not the 180 s floor (R47 set that floor for bcdev's
   slow cold starts).

**Upstream.** Filed with al-runner as an invented repro: a test stopped by `--test-timeout-secs` still costs every later test of its
codeunit the full limit: https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7517 (2026-11-09).

## Built for serve (coord task R-895)

Evidence: `/coord/handoff/R-895/` (`plan.md`, `measurements.md`, `fixture/`, `pp/`). Pre-commitment:
`docs/campaign/2026-11-09-r881-bc-history/r895-precommit.md`.

**What.**
- On the serve-entries transport, `AlRunnerServer.runEntries` stops reading at the first streamed timeout row and kills the daemon;
  serve streams a test line as each test ends (measured). The cut entry stands with its rows; later entries are re-sent as R612's cut
  does.
- A test of the cut codeunit that has no row, and that the covering loop asks for, runs ALONE (exact selection, `runSelectedOnly`,
  the same mutant and limit). A timeout there ends the mutant `timeout-killed`.
- Only on a build that retires the §6 Sleep rule (the current pin does): where §6 applies, nothing is cut, as before.

**Measured.**
- Invented fixture on serve: 1,181 s before, 383 s after. All 17 mutants identical; the hung one is `timeout-killed` by the same test.
- PaymentPractices' `PaymentPracticeBuilders` with demo data: R-892 could not finish it in an hour; now 57 of 57 scored in 1,974 s.
  M0019 and M0048 are `timeout-killed`.

**Not changed.**
- **One-shot:** al-runner prints every test line only at the end, so a call cannot be stopped early. The cheap lever is direction 3
  above (a lower `--test-timeout-secs`); upstream #7517 would allow the same cut there.
- **Kill-pair order:** for a hung mutant, a batched kill pair can be stored for a later fail row while the real first failure is
  fetched alone, so its NONE run comes before that kill. This touches hung mutants only, inside the pre-committed move (build review,
  R-895).
