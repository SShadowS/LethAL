---
id: "R373"
title: "An env-tool run, or a bcdev run that cannot ask the dev endpoint for the test app, records no test digests, so lethal verify refuses it"
section: "product-gaps"
status: "open"
order: 1060
---

**What.** R372 takes the per-test digest from the PUBLISHED test app. Two run shapes cannot give
one, so they record NULL, warn `test-digests-unavailable`, and `lethal verify` refuses them as
`source-predates-verify`:

- **env-tool sessions.** `envTool.publishApps` are PREBUILT `.app` files, published as they are by
  `EnvToolSession.publishTestApps` through `afterLeaseAcquiredFor` (cli.ts), under the lease. That
  is AFTER `reportPublishedTestApp` reads the published package, and nothing compiles them from the
  test source during the run, so neither the read nor the disk is known to be the body that runs.
  `testAppIdentity` (orchestrator.ts) records NULL whenever `afterLeaseAcquired` is set.
- **bcdev with no dev server or no dev credentials**, where `fetchPublishedAppPackage` answers
  `undefined`. The comment on `BcDevMcpBackend.fetchPublishedAppPackage` names the env-tool path as
  this case, but `startEnvToolSession` does set `server`, `serverInstance` and `BC_DEV_USER`, so
  that comment looks stale (not measured live).

**What would close it.** For env-tool: digest the `.al` entries of the `publishApps` file that is
the test app (it is a local file, read once before publishing), or read the published package
again after the lease-held publish. For the `undefined` case: nothing short of a readable dev
endpoint; the refusal is the correct answer there.

**Evidence.** `testAppIdentity` and `reportPublishedTestApp` in `packages/runner/src/orchestrator.ts`;
`publishTestApps` in `packages/runner/src/env-tool-session.ts`; the R-372 tests in
`packages/runner/tests/orchestrator.test.ts`.
