**What.** R372 takes the per-test digest from the PUBLISHED test app. Two run shapes cannot give
one, so they record NULL, warn `test-digests-unavailable`, and `lethal verify` refuses them as
`source-predates-verify`:

- **env-tool sessions.** `envTool.publishApps` are PREBUILT `.app` files, published as they are by
  `EnvToolSession.publishTestApps` through `afterLeaseAcquiredFor` (cli.ts), under the lease. That
  is AFTER `reportPublishedTestApp` reads the published package, and nothing compiles them from the
  test source during the run, so neither the read nor the disk is known to be the body that runs.
  `testAppIdentity` (orchestrator.ts) records NULL whenever `afterLeaseAcquired` is set.
- **bcdev with no dev server or no dev credentials**, where `fetchPublishedAppPackage` answers
  `undefined`. The comment on `BcDevMcpBackend.fetchPublishedAppPackage` names the env-tool path as
  this case, but `startEnvToolSession` does set `server`, `serverInstance` and `BC_DEV_USER`, so
  that comment looks stale (not measured live).

**What would close it.** For env-tool: digest the `.al` entries of the `publishApps` file that is
the test app (it is a local file, read once before publishing), or read the published package
again after the lease-held publish. For the `undefined` case: nothing short of a readable dev
endpoint; the refusal is the correct answer there.

**Evidence.** `testAppIdentity` and `reportPublishedTestApp` in `packages/runner/src/orchestrator.ts`;
`publishTestApps` in `packages/runner/src/env-tool-session.ts`; the R-372 tests in
`packages/runner/tests/orchestrator.test.ts`.

**Done (R-373b; plan `docs/superpowers/plans/2026-10-06-R-373b-envtool-post-hook-digests.md`,
reviews in `/coord/handoff/R-373b/`).** An env-tool session now records its digests from the
published test app read AGAIN after the lease-held hook has published (`deferredTestDigests`), with
R372's own code, so the format is unchanged (no `TEST_DIGEST_SCHEME` change). They are recorded
(`setRunTestDigests`, which never overwrites) only when proven to be what runs:
- exactly one INSTALLED row for the read-back's app id, at the read-back's version (R-385's
  `checkInstalled`: `dev/packages` alone means published, not installed);
- every app the hook republished is installed at the version the server serves;
- when a `publishApps` file is the test app, the read-back's id, name, publisher, version and `.al`
  source set equal that file's.
Anything unproven (an unreadable read-back, a staged upgrade, a mismatch, an unreadable dependency
or installed list, a hook that did not run) records NULL with exactly one `test-digests-unavailable`
warning, and verify keeps refusing. `published-test-app-mismatch` and `-unreadable` are judged on
the post-hook read. The bcdev case with no dev endpoint stays refused, which is correct. The
false-kill path found on the way is [[R486]], closed in the same change.
- **Not measured live:** the env-tool environment is gone. Whoever restores one: run
  `itest:envtool`, with a `--resume` leg, before trusting this or R486 live (the installed check, and
  two `dev/packages` reads in one session returning the same bytes, are unmeasured; a wrong
  assumption gives NULL digests or a refusal, never a wrong digest).
