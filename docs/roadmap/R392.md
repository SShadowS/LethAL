**Found by the R-214 lane (lethal-preproc), 2026-10-01, closing R377.**

**What.** An al-runner run's effective symbol set includes `AL_RUNNER_PREDEFINED_SYMBOLS` (`packages/runner/src/preprocessor-symbols.ts`): `CLEANSCHEMA1` to `CLEANSCHEMA25`, measured on al-runner v2.12.0 (R377). al-runner ships several times a day. If a newer release predefines `CLEANSCHEMA26`, or drops one, LethAL enumerates `#if` arms al-runner does not build, and records a build identity that is not the build. Nothing would say so: the mutants would be compiled out (no verdict) or missing (no site), with no error.

**Fix direction.** Extend `runAlRunnerCanary` with a one-arm probe per session, like its existing probes: a project with one `#if <symbol>` block per candidate (`CLEANSCHEMA1` to about `CLEANSCHEMA40`, plus `CLEANSCHEMA`), run with no `--define`, reading back which arms compiled. Refuse the run, or warn by name, when the set differs from `AL_RUNNER_PREDEFINED_SYMBOLS`. The probe method and evidence are in R377.

**Landed offline (2026-10-01), plan `docs/superpowers/plans/2026-10-01-R-392-al-runner-predefined-probe.md` (r2).** Stays open until the live run.
- **No assumed list.** `effectiveBuildSymbols` and `generateMutationSet` take `BuildBackend = { kind: "bcdev" } | { kind: "al-runner"; predefined: AlRunnerPredefinedProbe }`, so an al-runner build cannot be described without a probe result. The constant is renamed `AL_RUNNER_PREDEFINED_SYMBOLS_V2_12_0` and is only compared against (the warning below, and the R377 message hint).
- **The probe** (`packages/runner/src/al-runner-predefined-probe.ts`, `probeAlRunnerPredefinedSymbols`): a two-app project generated in a temp dir, run as ONE one-shot al-runner process with no `--define`, through the canary's `OneShotTransport`. `Mask()` has one `#if c` / `#else` block per candidate (`CLEANSCHEMA1`..`40` and `CLEANSCHEMA`, 41 in all), appending `+c` or `-c`; a `+ALWAYS` arm sits under a symbol the file `#define`s itself and a `+NEVER` arm under one nothing defines. The test `Codeunit50101.ProbeMask` (codeunit "LethAL R392 Probe") raises `Error('R392MASK:' + Mask() + ':END')`. An answer is accepted only with exactly one result, for that test, status `fail`, exactly one mask, only known tokens, no repeat, every candidate present, `+ALWAYS` present and no `NEVER`. Anything else throws `AlRunnerPredefinedProbeError`, with the reason and al-runner's output tail. The generated AL compiles under alc 18.0.41 with no define and with `/define:CLEANSCHEMA1`.
- **Deviation from the plan:** the ALWAYS arm is `#define LETHALR392ALWAYS` + `#if LETHALR392ALWAYS`, not `#if true`, because nothing measured says the AL preprocessor reads `true` as a literal rather than as an undefined symbol (which would refuse every run).
- **runSession** calls `measurePredefinedSymbols` (a structural method, like `provisionOnce`; `AlRunnerBackend` implements it) once per non-authoritative session, awaited, after `provisionOnce` and before `effectiveBuildSymbols`, with the directory provisioning reported (so it does not pay `--auto-provision` again). A non-authoritative backend without the method is refused by name. bcdev never probes.
- **A difference** from the v2.12.0 list uses the MEASURED set and emits `al-runner-predefined-symbols-changed` naming what was added and removed. It flows into the run row, fingerprint, history, resume and marks.
- **Dry run.** `lethal run --dry-run --backend al-runner` now spawns al-runner for the same probe, and refuses by name when the config names no `alRunner.alRunnerPath`.
- **Tests:** `packages/runner/tests/al-runner-predefined-probe.test.ts` (match, mismatch, every partial case) and `packages/runner/tests/r214-al-runner-predefined.test.ts` (call order probe -> effectiveBuildSymbols -> fingerprint -> generation with the probe finished first, mismatch, refusal before any run row, the pin, bcdev never probes, dry-run probe and refusal, through `main()`). Each product hunk was red-checked.
- **Not done here:** R-387's `cliDefaultMechanismFailures` must still allow exactly this one probe spawn (that check is not on master yet).

**Still to measure, on the first live `itest:alrunner` run:** that the probe takes the match path with no frozen figure moving, and its wall time. Over 15 s makes a per-binary cache a follow-up item.

**Known limit.** The probe sees only its candidates. A predefined symbol outside `CLEANSCHEMA1`..`40` and `CLEANSCHEMA` goes unseen. R345's cross-session risk (two sessions running al-runner at once) remains; this only keeps the probe sequential within one session.
