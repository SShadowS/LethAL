**Measured on a Document Output PR** (2026-09-25, bcdev on a hosted BC 29 sandbox, 3 touched files,
527 deployed mutants, 136 tests; reported in GitHub issue #19): 137 mutants sat on lines the PR did
not change and cost ~833 s of the first 935 s of mutant time. One unchanged procedure reached from
an `OnInsert` trigger cost 523 s alone. The workaround, filtering `report.json` by `file:line`
afterwards, fixed the reading but not the cost.

**Landed:** a line-scoped mutant filter, `packages/runner/src/line-filter.ts`, applied inside
`generateMutationSet` after per-file dedup and after `--operator`, so what it deploys is a strict
subset of an unfiltered run and it cannot change a verdict. A mutant is kept when its span shares a
line with a range, so an `empty-block` over a whole body with one changed line stays in: the PR
changed its behaviour. `--changed-since` diffs `git merge-base <ref> HEAD` against the working
tree in the project, adds every line of each untracked, not-ignored `.al` file, and keeps `.al`
files only; a pure deletion adds no line. On a clean tree its ranges equal the old
`<ref>...HEAD` form's (GH-25). The 1,000-site pre-flight counts
after the filter. A range naming no project `.al` file, and a filter keeping nothing, both refuse.
The report carries `lines` (ranges plus the excluded site count), the `line-narrowed` caveat,
`reliability: narrowed`, and a `NARROWED (lines)` banner line; the ranges are in the resume
fingerprint. Pinned by `packages/runner/tests/line-filter.test.ts`, including a `runSession`
end-to-end case.

**Not measured live yet.** No gate exercises the flag against a real server; the claim that it
cannot change a verdict rests on the post-dedup placement, the same argument R127 makes for
`--operator`.

**Measured on al-runner v3 (coord PR-112, lethal-code, 2026-11-17).**
- **Setup.** Pre-commitment `docs/superpowers/specs/2026-11-17-pr112-changed-since-on-v3.md`; evidence
  `/coord/handoff/PR-112/`. Three real DO pull requests (squashed "Merged PR" commits from DO's own history, in a private local
  clone), each run as `--changed-since <commit>^` against `--only <the changed files>`, on edge-4ebfe7913, `--workers 1`.

  | commit | `.al` files | mutants changed / full | wall changed / full |
  |---|---|---|---|
  | 5f2a71d | 5 | 85 / 910 | 3m53 / 6m26 |
  | 735fb42 | 5 | 98 / 867 | 3m27 / 7m08 |
  | 14cc704 | 6 | 84 / 1,476 | 5m21 / 24m24 |

- **The selection is exact in all three.** An independent check against `git diff -U0` found:
  - 0 changed-run mutants missing from the full run;
  - 0 full-run mutants that share a changed line but were dropped;
  - 0 kept mutants that share no changed line.
- **Verdicts are identical.** Per (file, line, operator), the shared mutants show 0 differences in verdict, `killingTest`,
  `gapId`, `killReproduced`, `coverageAttribution`, `guardReached` and `runner`.
- **Wall time falls less than the mutant count.** The changed run took 0.22-0.60 of the full run's wall time, for 0.06-0.11 of
  its mutants. The rest is the fixed deploy and the baseline of about 1,250 tests.
- **A 4th candidate (9d4491a) was refused** by the line filter, as designed: it only adds permissions, so no deployable site.
- **A comparison caveat.** `scripts/report-diff.ts` keys mutants by hash, procedure and operator. On a subset run it groups twin
  mutants on different lines together, and prints spurious differences. Compare a narrowed run per (file, line, operator).
