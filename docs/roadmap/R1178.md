Found by coord PR-302 (lethal-preproc, 2026-11-22), the DO measurement of PR-297's flag. Evidence: `/coord/handoff/PR-302/`
(`score.py/.txt`, `outside-moves.tsv`, t1's and t1b's events). Related: [[R1160]], [[R197]], [[R1174]].

**What moved.** Three mutants outside PR-302's named 1,590 cut-error set moved `killed -> error`: M2519, M2548, M2549.
- **In c2** (the flag absent) each was killed at position 1 by a test of codeunit 68874.
- **In t1** (the flag on), the first leg scored them `error`: "NotRun: out-of-scope: an earlier test of this codeunit was
  refused while it ran". The refused test is another 68874 test, which reaches `Report.SaveAs` as Pdf under the mutant. The
  resume re-ran them and scored `error` again, with the SaveAs refusal itself.

**Why (reading of the events).** The flag adds tail kills, which R197's ledger promotes. That reorders the walk of later
mutants, so a 68874 test that is refused under the mutant is walked before c2's position-1 killer. Today's rule then scores the
walk `error`: a refusal before any kill.
- It is a LOST kill, never a false one, but the flag causes it outside the set it was meant to touch.

**What to fix.** A refusal under a mutant must not outrank a kill that an earlier-positioned killer of the same walk finds. One
way: when a refusal ends a walk, still run the ledger's or the baseline order's remaining covering tests before the refusal
decides the verdict. Another: walk the baseline order for mutants of a cut codeunit. Red then green on these three shapes,
then a DO re-check that they score `killed` again with the flag on.
