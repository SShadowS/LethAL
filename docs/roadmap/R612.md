**Filed 2026-10-21 by lethal-bugs from R-606's table measurement** (orchestrator ruling).

**What.** LethAL's v2 `AlRunnerBackend` closes the `--server` daemon after any suite run whose rows include a status
other than `pass` or `fail` (R517 I2, in `AlRunnerBackend`'s suite run). The rule was written for v2, where a timed-out
test left an abandoned thread inside the daemon, so a reused daemon could not be trusted.

On al-runner v3 a refusal is a `notRun` row (exit 7) and leaves no thread behind. But the rule still fires on it. On the
table fixture, v3 always reports the three Commit tests as `notRun` under `--isolation test` (#5607). So the daemon is
closed after EVERY suite run, and every request starts a new daemon.

**Measured** (R-606, pre-commitment d0d75f23, `/coord/handoff/R-606/tables/results.md`): on all three serve legs
(unpatched 93415c0bb + resource selector, patched + resource, patched + static), **928 `runTests` requests started 928
daemons, with `cached: true` = 0**. Verdicts were unaffected: 406 of 406 mutants equal across the legs. Only the warm
path was never used, so serve gave no speed benefit, and the patch's warm-key change could not be measured there.

**Why it matters.** Not today: [[R586]]'s v1 `al-runner-v3` backend is one-shot only. It matters once v3 gets a serve
transport. Any real suite with one refused test then runs every suite cold, which removes serve's whole point.

**To close.** For a v3 serve transport, close the daemon only when a row shows a condition that can leave the daemon
unsafe (for example a timeout), not on every `notRun`. Measure first, under a pre-commitment, that a v3 refusal leaves
the daemon reusable: the same per-mutant verdicts with the daemon kept against closed. Keep v2's rule for v2.

**Done (592ec593, coord task R-612; plan `docs/superpowers/plans/2026-10-22-r612-v3-serve-keep-rule.md`).**
- `serveDaemonReusable(rows, "v2" | "v3")` in `al-runner-backend.ts`. v2 is unchanged.
- **v3 keeps the daemon only when every row is pass, fail, or one of FIVE measured refusals,** matched as whole
  messages (`V3_SERVE_SAFE_REFUSALS`): HttpClient, Commit #5607, the cascade #5610, OnRun failed, and no-callee.
  - The two entries with free text at the end refuse, case-insensitively, any "panic", "timeout", "timed out",
    "exceeded", "wall", "deadline" or "time limit".
  - A duplicate test name in one answer throws and closes.
  - Anything else closes, including an unknown row shape.
- `serveDaemonRule` is internal: a user config is refused.
- **Measured** (`/coord/handoff/R-612/measure.md`): on alpha.2 each kept refusal leaves the next request correct and
  warm, with tables empty and no SingleInstance state leaking.
- **Live proof** (pre-commitments 8d9ae54b and addendum df79e246; `/coord/handoff/R-612/live/results.md`): on the
  table fixture with coverage on, the keep leg (never-merged tap ed485caa on 592ec593) equals the close leg per
  mutant on all 406 mutants, with 0 differences and 406 texts verified. It started EXACTLY 1 daemon against 928, in
  66 s against 149 s. The proof exercises the Commit refusal and its cascade only.
- **The update gate:** leg C of al-runner-v3's update gate gained a warn-kind fact, `serve-keep-reasons`. It read
  `matches` (all 5 entries) on alpha.2, and leg C passed with 24 facts on 592ec593. The run log's own tally reported
  the 24 as 16 matches, 8 defect-present and 0 warn. It counts by reading, not by kind; `serve-keep-reasons` is
  registered in `V3_WARN_FACTS`.
