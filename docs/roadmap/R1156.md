`docs/superpowers/specs/2026-11-20-pr259-lane-idle.md` and `/coord/handoff/PR-259/`.

**What.** perf10c's lanes were idle 2,664 lane-s (888 s of wall). Almost none of it is start, window or tail: 2,482
lane-s sit in 10,047 gaps of about 240 ms between one lane's consecutive requests. perf10c's own counter reads
`bound 2,380,997 ms over 10,050 checks`: R652's per-send `assertBound` re-reads and SHA-256s every `.al` file of the lane's
tree (591 files, 69 MB on DO) before every send, synchronously (R767), so three lanes' checks also queue on the JS thread.
Offline the hash takes 84 ms; in the run 237 ms.

**Proposed (spec-light, for the orchestrator's ruling).** A per-file `Bun.hash` fingerprint for the bound check only,
recorded at proof time: every byte still read before every send, about 36 ms offline against 68 ms; about 420 s saved
per DO run. A stat fast path (about 750 s) changes what the guard trusts (R652, R767) and is the owner's call.
