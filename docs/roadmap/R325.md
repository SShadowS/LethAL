**Found by the R-302 plan's review r2 (2026-09-29), Critical.** Plan:
`docs/superpowers/plans/2026-09-28-R-302-split-semantics.md`, "Revision r3".

**What breaks.** A mutant's identity key is `astHash|object|procedure|operator|major`, plus an
ordinal when several mutants share that tuple (R193, `assignIdentityOrdinals`,
`packages/schemata/src/project.ts`). Ordinals are assigned in SOURCE order. An engine change that
generates a NEW mutant with the same tuple BEFORE an existing one renumbers the existing one, and the
new mutant takes the OLD key. Nothing records which scheme produced a key: `sessionFingerprint`
(`packages/runner/src/resume.ts`) holds no engine or identity-scheme version, the runs table has no
such column, and a marks file has no such field. So with the AL source unchanged:

- `priorSurvivorKeys` / `filterHistory` (`store.ts`, `selection.ts`) can skip the NEW mutant as a
  known survivor on the OLD one's verdict (`--skip-known-survivors`);
- `buildResumeIndex` (`resume.ts`) can carry the OLD verdict onto the NEW mutant on `--resume`;
- an equivalence mark (`equivalence-marks.ts`, `verify.ts`) can attach to the NEW mutant.

**Measured** on R-302's r2 prototype (scratch, not merged): in System Application,
`SFTPClient.Codeunit.al`, a new `swap-call-arguments` at L42 in one `Initialize` overload takes
exactly the key the existing L56 site in the other overload held
(`373c5b11...|SFTP Client|Initialize|lethal.swap-call-arguments|1`), and L56 moves to ordinal 1. The
same on the hand-written repro `o1-overload-split-first` (L13's `empty-block` key moves to the new
L8 site). Any future operator or engine change that adds a same-tuple site earlier in an object does
the same.

**Not affected, and why:** committed per-mutant baselines (`packages/runner/itest/baseline-guard.ts`,
the itest and campaign baselines) never carry a verdict into a run; they compare verdicts per key,
and a renumbering shows up as a loud per-key difference, never a silent pass that changes a score.

**Closing.** R-302 adds an identity-scheme version, bumps it, records it on every run, report and
marks file, and refuses (with a named reason) to carry history, resume state or marks across a
different scheme. Closes with that commit and its red-checks.
