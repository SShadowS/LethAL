**Found 2026-10-06 by R-485's plan review** (`/coord/handoff/R-485/review-r1.md`, pre-existing, not
caused by R485).

**What.** An object whose HEADER is split by `#if` (`preproc_split_declaration`, one header per arm,
one shared body) is not in `SymbolTable.objects` (`OBJECT_KIND_BY_NODE` has no entry for it), not in
`tableExtensions` (`parseExtensionHeader` matches only `tableextension_declaration`), and not in
`unindexedObjects` (which collects only the declarations inside a `preproc_conditional_object`). R-485
measured the `#if`-wrapped case: a split-header tableextension of the table inside a wrapper drops
`run-trigger-forced` on master too. So `projectObserves` cannot see a split-header tableextension or
codeunit at all, and a tag such an observer should keep is dropped: the UNSAFE direction.

**How common.** 3 split-header codeunit or tableextension headers in BC.History (none in BaseApp),
0 in DC, DO and CDO (R-485 review count).

**To close.** Read a split declaration in `projectObserves` (every arm's `base_object`, every arm's
subscribers), or fall back to the any-table text rule for it. A red-going test: a split-header
tableextension of the table (top-level, and inside a wrapper) keeps `run-trigger-forced`.

## Fixed (R-494, 2026-10-08)

**Measured first, on master `1f3a4540`** (`/coord/handoff/R-494/scratch/measure494.ts`): it was NOT moot. R-485's
`opaque` fallback only widens the reading of OTHER unindexed objects, and never scans the split objects
themselves. The case: table `Par` with no `OnModify`, a project observer, and a call site. With a plain
tableextension (`OnAfterModify`) or a plain `OnAfterModifyEvent` subscriber, both tags are kept, the forced one
(`Modify()`) and the skip one (`Modify(true)`). With the same observer behind a split header, both tags were
dropped, at the top level and inside a `#if` wrapper. That is the unsafe direction.

**Fix:** `projectObserves` now reads every `symbols.splitObjects` entry. Each is collected at any depth, so both
shapes are covered. It is read by:
- the any-table text rule (`textObserves`, as for an unparsed object);
- R-485's any-event subscriber rule (`subscribesToTable`), which the text rule alone misses for a subscriber to
  a custom event of this table.

Both can only over-tag.

**Corpus diff,** master `1f3a4540` against the build, every spec field and tag: **0 differences** on fixtures,
examples, CDO, DC, DO and BC.History (519 projects). BC.History's 3 split headers observe no table whose tags
decide anything there. No identity key moved, so the scheme is unchanged.

**Tests:** `engine/tests/semantic/r494-split-header-observers.test.ts`, 7 tests:
- twins of the plain observers, for the tableextension and the subscriber codeunit, top level and wrapped;
- a custom-event subscriber;
- a split-header codeunit that observes nothing keeps no tag (the other direction).

Red-checked:
- the loop disabled: 5 red;
- the subscriber read disabled: 1 red (the custom event);
- the text rule disabled: 2 red (the tableextensions).
