**Filed 2026-10-22 by lethal-code**, from R651's measured split (CDO E3a run2 at e1cd0cd8,
`/coord/handoff/R-651/live/run2/results.md`; the trace: `/coord/handoff/R-651/live/gap.md`).
Class: FULL, because it changes a safety guard.

**What.** `AlRunnerV3Backend.run()` calls `assertBound()` at its top on every call. Each call hashes
every .al file of the instrumented target (554 on CDO) and of the test dir (104), hashes both
app.json files, and reads the selector, the resource file and the deps list. On the CDO slice that
was **86.3 s over 527 checks (about 164 ms each), 62% of the 139.2 s mutant loop**: larger than
every request put together. 425 of those 527 calls only read rows already held in memory from the
one prefetch request, so no al-runner process reads the tree during them.

**Proposed step.** Run `assertBound` once just before each request is SENT: the warm-up, each
prefetch chunk, each live request, and each §5 window's plain requests. Do not run it on a `run()`
that is served from memory. On CDO that is about 141 checks instead of 527.

**Gain (for ranking).** About 386 fewer checks x 164 ms = **about 63 s**: the CDO leg goes from
about 169 s to **about 108 s**, and the mutant loop from about 139 s to **about 78 s**.

**The safety argument to be reviewed.** The guard proves that the bytes v3 reads are the bytes alc
proved (R586 §3 step 3): the active tree, its app.json, the selector, the resource file (NONE
outside a window), the test dir and its app.json, and the deps. The claim to prove: a row served
from memory was produced by a request that was itself bound-checked just before it was sent, so a
later check before reading that row from memory catches nothing the earlier one did not. The review
must answer, case by case:
1. **A change between the check and the send.** It is the same window as today's check-then-call
   at a live `run()`. Is it widened anywhere? For example, a prefetch chunk of N groups is checked
   once, then sent.
2. **A change after the send and before a later memory read.** Today it is caught, and the batch
   fails with `AlRunnerV3UnprovenBatchError`. Under the proposal it is not caught until the next
   send. The rows already produced came from the checked bytes, so is any verdict wrong? What does
   the batch lose? (Today a late change stops the batch loudly; the proposal could finish a batch
   whose tree changed after its last request.)
3. **Today the prefetch request has NO check just before it.** Today, the `run()` checks AFTER the
   prefetch are what catch a change made before it, because they still see a change that persists.
   Under the proposal the check moves to just before the prefetch send. Show that every change
   caught today is caught there too, including one made between the baseline's last `run()` and
   the prefetch.
4. **What the daemon reads, and when.** If the daemon compiles only at warm-up (`cachedFalse` 1 on
   CDO), a later change may never reach it. If it recompiles when a request's sources differ
   (`cached:false`), a check before each send is exactly what the guard needs. Measure which one
   applies before relying on either.
5. **The `lastActivated in manifest` and resource-file checks** are per-activation and per-window
   facts. Keep them where they are cheap (no hashing) if moving them would weaken them.
6. **A transient change** (made and reverted between two checks) is invisible to both schemes.
   State it, do not claim it.

Not proposed here: a size/mtime fast path in `hashAlTree`. gap.md measured the walk alone at about
half the cost, and it weakens content-equality.

**To close.**
- Measure first: re-read `boundMs`/`boundChecks` on the leg (the split line prints them since
  R651), and measure point 4 (does a mid-run .al edit reach the daemon, as `cached:false` or as
  changed rows?).
- ONE deep plan review. It must state what the guard protects against, and SHOW that checking once
  per request sent still catches every case today's per-`run()` check catches (points 1-6): that
  nothing can change the bound tree between the check and the send that the check does not see.
- Build with red-going tests for each direction: a change before a send is refused, and a memory
  read with no send does not re-hash (a call counter on a stateful fake, never wall time).
  Re-measure the CDO legs with per-mutant equality held as in R635, and record `boundChecks`
  of about 141.
