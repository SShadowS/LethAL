**Priority.** Filed 2026-10-09 by the R534 build (plan r2, roadmap item 8; review M6). Never a
false kill; mutants read `no-coverage` or are never scheduled against tests that never ran, and
nothing says why.

**What.** On `--server` one `runTests` runs the whole suite, and a timeout ends al-runner's run, so
every test after the hung one has no row. At the BASELINE (no mutant active) a test codeunit whose
`OnRun` hangs therefore takes the rest of the suite with it: those tests are non-green (no row),
drop out of the green set, and their coverage is never collected. The report shows fewer green
tests and more `no-coverage`, with no line naming the hang that caused it.

**Evidence.** `/coord/handoff/R-534/review-plan-opus.md` M6; `/coord/handoff/R-534/measure.md`
section C (`--server`: four tests with no row after the hang); `ensureServerSuite`'s `hungTest` in
`packages/runner/src/al-runner-backend.ts`.

**To close.** At the baseline, when the suite has a `hungTest`, emit one warning naming it and how
many tests had no row because of it. Optionally re-run the remaining tests without the hung one.
