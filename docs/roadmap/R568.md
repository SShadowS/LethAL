**Filed 2026-10-10 by the [[R532]] build** (opus build review r2, finding 2). A possible UNDER-refusal: a mutant
that can hang may be deployed. Master never refused these either, so nothing regressed.

**What.** R532 refuses a FEED of a report's preset exit name (a variable whose value flows into the write of a
name an open item's exit or bound reads). To keep to R532's ruling that a value passing through another
object's function is not followed, the feed search in `r531Feeds` (in `fed` mode, in `loop-hazard.ts`) does
not take a name read in the right side ONLY as an argument of a non-bare call (`X.Proc(...)`). That rule is
wider than the ruling: it also stops at PLATFORM methods, which are not another object's code. Examples, all in
the same procedure:
- `Key := Txt + 'k'; Continue := Cust.Get(Key);` leaves `Key := ...` emitted;
- `Tmp := Txt + 'q'; Continue := Txt.Contains(Tmp);` leaves `Tmp := ...` emitted;
- `CurrReport.X(Tmp)` in the right side is treated the same way.
A receiver (`Continue := not Buf.IsEmpty()`) and the arguments of a bare call still feed.

**To close.** Narrow the rule to calls whose target resolves to a project object (`callTargets`), so platform
methods feed their arguments again. Then re-measure BaseApp against master, per mutant (keys, tuples, ordinals).
The R532 BaseApp census found no hang among the preset writes it sampled, so the expected cost is small. Measure
it, do not assume it.

**Built (2026-10-10).** `r568StopsAt` (in `loop-hazard.ts`) now decides where `r531Feeds`' `fed` mode stops.
The rule: the arguments of a non-bare call feed, as a bare call's do, unless the receiver is typed as any object
other than a record (a codeunit, report, page, query, xmlport, testpage or interface, for example; in the project
or not) or is a record whose table
or a project tableextension declares the member as a procedure. Those two are another object's function, which
R532's ruling does not follow. So record built-ins (`Cust.Get(KeyVal)`), text and other primitive methods
(`Txt.Contains(Tmp)`), `CurrReport.X(Tmp)` and a receiver nothing resolves now feed their arguments; an
unresolved receiver feeds because that is the safe direction for a refusal. The receiver itself still feeds, as
before. R-531's own use of `r531Feeds` (no `fed`) is unchanged.

**Residual (kept).** A platform method on an object-typed variable still stops, because the rule reads the
receiver's type, not the method: `Rpt.SaveAsPdf(F)`, `Cu.Run(Rec)`. This is not a practical hang door: `Run`,
`RunModal` and `SaveAs` run the other object's code, which the ruling covers, and pure setters are statements, not
right sides. Also unchanged from master: inside a table, `Rec.OwnProc(Tmp)` stops, because `Rec` resolves to the
table that declares the procedure. It cannot reach a preset write: preset exit names live in reports, and in a
report a same-object call is bare or goes through `CurrReport`/`this`, which feed.

**Measured** (the built branch against fresh master legs, per mutant, one corpus job at a time). BaseApp: -1 deployed, 0 added, 0 identity
tuples and 0 ordinals moved, `skipped` equal. The one mutant is in `Account Schedule` `ValidateDateFilter`: the
`void-method-call` of the `SetFilter` on the `"Acc. Schedule Line"` data item. Why: the preset write
`DateFilter := CopyStr("Acc. Schedule Line".GetFilter("Date Filter"), ...)` now feeds `GetFilter`'s argument, so
the new fed name is the FIELD identifier `"Date Filter"`. The `SetFilter("Date Filter", NewDateFilter)` call then
counts as a write of that name only because its data-item receiver does not resolve (R532 counts an unknown
callee as writing its arguments). A resolved record receiver would not be refused there (R532's record-method
residual). A field-name argument can also match `X.<Field> := ...` by member name; that is an over-refusal in the
safe direction, and it is inside the -1. Withholding Tax, Tests-TestLibraries and all 19 fixtures: 0. No scheme
change (`IDENTITY_SCHEME` stays 39). CDO, DC and DO cannot move: `r568StopsAt` runs only inside `presetFeeds`, and
only for a scope that has preset names or project preset writers. The R532 census found none in those three, and
their reportextensions extend dependency reports, so they have no project preset writers.

**Tests** (`r532-preset-feeds.test.ts`, each red-checked alone, recorded in `/coord/handoff/R-568/build.md`): a
record built-in's argument feeds; a text method's argument feeds; an undeclared receiver's argument feeds (these
