**Filed 2026-10-24 by lethal-bugs during R-737.** Related: [[R737]].

**What.** `r737Partial` (in `packages/builtin-tier1/src/loop-hazard.ts`) calls a receiver partial only when one of its
types names no project object (for example a dependency codeunit). A receiver typed two ways where BOTH arms are
project objects, but one arm has no procedure of the called name, still yields a shorter target list that looks
complete. A strict reader (`r570Targets(..., true)`) then trusts the list and may miss the callee on the other arm.

**Reach.** 0 today: R_amb = 0 on every corpus (R737 census), so no test exists and none can be built from real code.

**To close.** Make the test "some type yields no procedures for this member" instead of "some type names no project
object". Add a red test per direction, then re-run the R737 census to confirm the reach.

## Done (75ededaa)

`r737Partial(n, c, arity, ctx)` now calls a receiver partial when ANY of its types yields no procedure for the called
member (and arity; a paren-less `CU.P` has arity 0), not only when it names no project object. Tests in
`packages/builtin-tier1/tests/r725-unknown-readers.test.ts`: B1 (two project codeunits, one lacks the member: refused;
the old rule admitted it), B2 (both have it: admitted), B3 (the existing dependency-type case, unchanged). Red checks:
old predicate, B1 red; always-partial, B2 red; "has objects but lacks the member" only, B3 red. The R737 census re-run
on all five sets is identical to R-737's (R_amb = 0), so the change has no reach.

**Build-review fix (R752 branch).** A PAREN-LESS member call (`Qv.X`) on a partial two-type receiver, where one type
has a procedure `X` and the other only a field `X`, was read as a field read after R751 (the strict list is `[]`), where
master followed the procedure. Two readers fixed: `r572StatefulOnce` (the paren-less branch now flags a hit when the
non-strict list has a target) and the R570 writer search in `r570Scan` (the viaRec condition also accepts a non-strict
target). Test: `(b)` in `r725-unknown-readers.test.ts` (stateful `T1.X`, field-only `T2.X`: refused; both types
field-only: not refused, as master); red check: dropping the branch's hit turns it red. The R570 writer-search site has
no unit test: its key is a callee parameter (never typed two ways) or a global cursor, and a `#if`-typed global is no
resolvable cursor, so it is marked with a `ponytail:` comment.
