Found by PR-64 ([[R1082]], 2026-11-16) acting on the scan's ([[R1073]], PR-59) first rows.

**What.** `scripts/upstream-fixed-scan.ts` uses the newest maintainer comment that names a commit the clone knows. On #8038,
#8032, #7924 and #7586 the newest maintainer comment names no build: it describes planned work (a corpus probe). An older
comment named a build for another item, so each row read `build-named-in-current`, and its "entry still differs" action looked
like a fix that failed.

**Fix (orchestrator, 2026-11-16).** When a maintainer comment newer than the build-naming one names no build, the row says
"latest comment is a plan, not a fix" (its own class or a flag), with that comment's excerpt, rather than classifying by the
older comment. The rule that the regression entry's repro result decides "fixed" is unchanged. A unit test with a recorded
fixture of that shape pins it.

**To close.** The scan reports such rows by the newer comment, tested; the daily report shows them that way.

**Done (PR-82, 2026-11-16).** New class `latest-comment-names-no-build`: an older maintainer comment named a build, but the
newest names none. The row shows the newest comment's link and excerpt, and the older builds stay listed (not hidden).
- It is named for what it measures, not "a plan": a later "thanks" lands there too, and the excerpt tells the two apart
  (no keyword rules, PR-59's review).
- Such rows leave the action list.
- Tests, red both ways: the #8038 shape; a later "thanks"; a newest comment that names the build keeps its class.
- First real scan (`/coord/handoff/PR-82/scan-after.txt`): 9 rows in the new class (#8038, #8036, #8032, #8028, #7924, #7832,
  #7827, #7780, #7586).

  narrowed the measured shape to a Temp Blob's stream, and our repro reads a table's Blob field. Correction commented on
  #7996 (it stays open); [[R1073]] notes it.
