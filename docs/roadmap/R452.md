**What.** `swap-modify-flag`'s `Modify` kill carries no `PlatformKillMechanism` today. [[R138]]'s
reasoning was that a skipped `OnModify` only writes less, so it cannot add an error. [[R281]] shows
that reasoning fails for `OnDelete`, and it fails for `OnModify` the same way: a trigger that writes
OTHER rows (deletes or inserts children, renames, calls project code) can make a later statement hit
a duplicate key, or `Get` a row the trigger would have written. That kill is a platform error, not a
test assertion, and is scored as an ordinary kill.

**What to build, after R281 lands.** A sibling `PlatformKillMechanism` value, for example
`run-trigger-skipped-modify`, plus an `OnModify` reader that reuses R281's separate harmless-call
helper. An `OnModify` that only changes `Rec`'s own fields (the common "last date modified" shape) is
an ordinary changed-value kill and needs no tag. One item covers BOTH `Modify(true)` and
`ModifyAll(..., true)`: `ModifyAll` with RunTrigger runs `OnModify` per row, so tagging one and not
the other would be incoherent. Both edit `swap-modify-flag`'s tag-by-method choice in `generate()` and
its test file, so this rebases on R281.

**Evidence.** The plan in `/coord/handoff/R-213/plan.md`, question 1. In BaseApp `Source`, 17 of 37
three-argument `ModifyAll(F, V, true)` sites have a table with an `OnModify`. Raised by [[R213]].

**Done.**
- R281's detector moved to `@lethal/engine` (`skipCanRaise`, with `deleteSkipCanRaise` and
  `modifySkipCanRaise`), first as a pure move, proven by identical spec dumps on BC.History, CDO and
  every fixture. The argument readers (`exactArguments` and its siblings) moved with it.
- New mechanism `run-trigger-skipped-modify`, with its own report explanation. `swap-modify-flag`
  tags `Modify(true)` through `modifySkipCanRaise`. `flip-boolean-literal` tags a `true` -> `false`
  flip of a Record `ModifyAll`'s third argument (modify) and of a `DeleteAll`'s argument (delete),
  read comment-aware and span-equal. Its `false` -> `true` direction forces the trigger and is filed
  as [[R457]].
- Post-merge finding 1 (rule D): no `Modify`/`Delete` inside the trigger is ever harmless. Own
  record is not own row, and a RunTrigger=true write runs a trigger nobody read.
- Post-merge finding 2: split-header procedure names count, and a bare `X.Y` is a field read only
  when `X` is the trigger's own implicit `Rec`/`xRec` and `Y` is a field of its own table. The
  binding is checked, not the spelling: alc 18.0.43 (Linux) compiles a trigger-local
  `Rec: Record "Kid"` in a table trigger, and `Rec.Y` then binds to that local (an
  Integer-returning `Kid.CleanUp` against Par's Boolean field `CleanUp` gives AL0122).
- The three weak tests, each red-checked on its named revert.
- Final review (sol final r1): any live `with` in the trigger keeps the tag (a parenthesis-less
  call inside it binds to the `with` record); an unindexed or unparsed object that looks like a
  tableextension of the table keeps it (its procedures are not indexed); the report explanations
  say the table events still fire with `RunTrigger` false; the global-`Rec` half of the binding
  check has its own test (alc refuses a table global named `Rec`, AL0155, so it pins the engine
  only). These moved 2 BC.History `Modify` sites to tagged, the `No. Series` one below among them.
- Measured (probe, no `#if` arms): BC.History gains 22,523 tagged `Modify` mutants, 188 `ModifyAll`
  and 846 `DeleteAll` flips; CDO 35 and 9; the fixtures only `grammar-probe`'s unpinned
  `Other.Modify(true)`. Rule D and the field-read fixes moved no mutant on any corpus. Every pinned
  fixture manifest is byte-identical, and `itest:tables`' `killedCount` stays 3.

**Limit kept (post-merge finding 3): subscribers in the test app.** The detector reads only the
project being mutated, so a modify or delete subscriber, or a `tableextension` trigger, in the TEST
app (or any other app) is not seen, and the report's explanation says so. Reading the test app was
rejected for its cost: `generateMutationSet` has no test directory, so it would need a new option,
and the mutant manifest would then depend on test sources (its digest inputs, `--dry-run`, the
census and the itest callers all change, and a run and a dry run would disagree). Measured over
each whole corpus, the dropped tags meet ONE cross-project observer: BC.History's `No. Series`
`Modify` site in `NoSeriesCopilotImpl.Codeunit.al`, observed by a test library's
`OnAfterModifyEvent` subscriber (`DocumentNoVisibilityClearCache`) that only clears a cache and never
reads RunTrigger. That is one observer match, not a demonstrated under-tag. CDO 0, fixtures 0.
After the final-review fixes that site keeps its tag anyway, so today the count is 0.
