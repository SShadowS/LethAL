**Measured.** Run 2 (pre-R198, one HTTP call per test) and run 3 (R198, one `RunMutantMany` call
per mutant) on the same 741 mutants. 17 verdicts differ: 9 are run 2's stranded hangs scored
`timeout-killed` by the stop (expected); **8 are `survived` → `killed`**, every one in cache code
(`CDOVariantMatchCache` 82–84, `CDOTemplateVariantMgt` 531–533 and 913), every killer at position
3, 3, 4, 7, 7, 9, 9 or 110 of its group call, every failure a stale-cache assertion. 20 more kills
kept their verdict and named a different killer with R197's order unchanged. 0 moved the other way.

**Mechanism.** Each method is its own `CODEUNIT.Run` under Microsoft's `Test Runner - Isol.
Codeunit`, and the database rolls back per method (probe E1/E7/E12, committed writes included). A
`SingleInstance` codeunit's variables live for the SESSION, and a group call is one session. Before
R198 every request got a fresh session, so the target's match cache was cold for every test and a
mutant that removes its invalidation was unobservable. Warm, it is caught.

**Decided and built: option (A), the warm confirmation.** Design:
`docs/superpowers/specs/2026-09-03-r206-warm-confirmation.md`, revision 5, refused three times and
approved on the fourth. What landed:

- **The ruling**, shipped as the `session-warm` caveat on every report with a grouped call: a kill
  is the test failing (or exceeding its budget) with the mutant active, in a session that was fresh
  at the call's start, where the same ordered prefix passes without it in another fresh session. A
  cold-only kill is a survivor here, the accepted direction.
- **The session guard.** The control app counts test-method runs per SESSION in a dedicated
  `SingleInstance` field with one writer and no reset, and every answer that ran reports the count
  at the call's start (`testRunsBefore`). Anything but 0 is a reused session: a fail or timeout
  there is `session-reused`, never a kill. The predicate lives in the same kind of state as the
  target's cache, so it rests on no belief about BC's session handling and covers the first call of
  a resumed run.
- **The confirmation.** A kill at position k > 1 replays its CALL's methods 1..k unmutated through
  one ordinary `RunMutantMany`; confirmed iff `complete`, `ranCount = k`, every entry passed, and
  for a timeout method k inside its cold budget. Every other ending is an error with its own cause.
- **`killPosition`** on every kill and **`warmKills`** on the report.
- **The per-method cost cut**: one suite per call keyed on the (codeunit, method) pair, a filtered
  `RunTests`, results read back off the function line.

**Gates, on numbers pre-committed before they ran**
(`docs/superpowers/specs/2026-09-03-r206-build-precommitment.md`): hang 40 mutants with the new
`SpinUntil` arm, `timeoutKilled` 5, `warmKills` 4; bcdev 3/12/4, `warmKills` 0; tables 299/63/15,
`warmKills` 13, `groupedCalls` 375, three named positions; al-runner 3/16/0.

**Run 4 on the hosted sandbox, 2026-09-04 — the measurement this row was open for.**

- The **verdict table is identical to run 3 across all 741 mutants**, same verdict and same
  `killingTest`, with **0 errors**. All 8 moved verdicts stand, each now carrying a confirmed warm
  position. All 201 warm kills confirmed; `session-reused`, `warm-prefix-unstable`,
  `warm-timeout-unconfirmed`, `warm-confirmation-incomplete` and `unstable` are all **0**.
- The **named near-cap risk did not fire**: both 158-method replays confirmed, as predicted.
- The **cost cut beat its target**: per-method median **281 → 105 ms** (target 140–200), survivors'
  total **3,165 → 1,082 s** (target < 2,400), wall clock **111.0 → 86.2 min** while doing strictly
  more work.
- Two numbers deviated, both explained and both consequences of the cut: `warmKills` 201 vs 198
  predicted (the prediction was computed from row order, and a 408 discards a timeout's prefix
  answers, so it forced all 8 timeouts to position 1 and could not see the 3 warm ones), and
  `groupedCalls` 895 vs 896 (five fewer cap continuations at 105 ms/method, plus one lost-ack retry
  R194 absorbed).

**What this row does NOT close:** the chunked group path still has no live gate ([[R208]]), which
is the one place where `chunkPrefix` versus `ordered` is verdict-bearing.
