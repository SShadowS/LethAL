Found by coord task PR-33 (2026-11-15) while measuring family 10 ([[R1047]]). Evidence: `/coord/handoff/PR-33/ws-run/result.md`
(both runs), `issue-restrictive-default.md`. Related: [[R026]] (LethAL's permission canary: a codeunit without TestPermissions
defaults to Restrictive).

**The difference, measured.** Regression entry `u8160-restrictive-default`, run by lethal-bugs on bc2 (BC 28.4 W1, Microsoft's
Permissions Mock 28.4 installed, through LethAL's web-service path):
- `InsertUnderRestrictiveDefault`, a codeunit with no TestPermissions that inserts into its own app's table before any
  `PermissionsMock.Set`, fails on BC: `Sorry, the current permissions prevented the action. (TableData 51600 URD Row Insert:
  Upstream Repro Restrictive Default)`. al-runner edge-5a58a0f16 passes it.
- `InsertWithTestPermissionsDisabled`, the same write with `TestPermissions = Disabled`, passes on both.

Ten cells of family 10's first BC-check app had the same shape and were refused the same way on BC; al-runner passed the three it
ran.

**Why it matters for LethAL.** A wrong verdict, not a refusal: a test that writes before lowering its permissions passes on
al-runner and fails on BC. Under a mutant, al-runner then scores the test against a baseline BC would not give. Not measured: a
server without Permissions Mock.

**How far the refusal reaches (PR-35, measured in three probes).** Each probe is pre-committed in
`docs/superpowers/specs/2026-11-15-pr35-8160-at-risk-precommitment.md` (addenda 1-3). lethal-bugs ran them on bc3 (BC 28.4 W1,
Permissions Mock installed, LethAL's web-service path, which goes through Microsoft's runner), with a target app as the app under
test and test codeunits without TestPermissions that lower nothing. Results: `/coord/handoff/PR-35/bc3-run{,2,3}/result.md`.
- **Every write is refused, in any app's code** (probe 1). That covers the test app's own table, the app under test's table
  written from the test, and the app under test's own codeunit writing its table (BC then names the target app as the writer). An
  Insert is refused, and so is a Modify with no read before it (probe 3).
- **A read of a table that holds rows is refused too** (probes 2 and 3): a Get, a FindFirst, and the filtered scan inside
  DeleteAll and ModifyAll, even when no row matches. A FindFirst on an empty table passed (probe 1).
- **TestType does not change it** (probe 3): Uncategorized, IntegrationTest and UnitTest are refused like no TestType.
- With `TestPermissions = Disabled` the same write passes. al-runner edge-5a58a0f16 passes every cell of the three probes.

**The at-risk set in stored results (PR-35).** By parse (`/coord/handoff/PR-35/at-risk.ts`), over PR-15's 84 BC.History projects
and DO:
- 58 of the 84 BC.History projects install Permissions Mock, directly or through Tests-TestLibraries. Of their 335 test
  codeunits, 83 are exposed: no TestPermissions, or Restrictive (75.2% declare another value).
- 306 test methods in 20 projects write a non-temporary record before their first permission lowering. By table owner: the test
  app 33, the app under test 47, another app 226. By first write: DeleteAll 140, Insert 114, Modify 48, Delete 3, ModifyAll 1.
  As addendum 2 set out, they split by what the probes measured. **Corrected by PR-36** (`/coord/handoff/PR-36/recount.txt`):
  the tier reads every access before the first lowering, not only the first write. An Insert or Modify anywhere there is refused
  whatever came before it: a read or DeleteAll before it is either refused (the table holds rows) or passes on an empty table,
  and then the write is refused. PR-35 first tiered by the first write alone, which put 100 such tests in "uncertain" (162 firm,
  36 passing, 169 kills).
  - **Firm: 262 tests with an Insert or a Modify before their first lowering** (probes 1 and 3), in 20 projects. **111 pass in
    the stored al-runner baseline** (BC, as LethAL runs it, would fail them), and **384 kills rest on them**.
  - **Uncertain write: 44 tests whose only writes before lowering are DeleteAll, ModifyAll, Delete or Rename.** They are refused
    at their read when the table holds rows (probe 2); on an empty table not measured. 12 pass, and 71 kills rest on them.
- **Uncertain, read only: 42 more tests read a record before lowering**, at risk only if the table holds rows. 4 pass, and 21
  kills rest on them.
- **Upper bound, all three: 348 tests in 21 projects, 127 passing, 476 of the projects' 1,883 kills.** Over 5% of the kills in 12
  projects; all of them in recref, privacy, transl and usrperm. Kills are joined on the method name, and no name is ambiguous.
- Files: per project `at-risk.write.txt` (write-first) and `at-risk.access.txt` (all three); per test `outcomes.*.tsv` and
  `tests.tsv` (its `firstWriteMethod` and `accessBeforeLowering` columns give the tier); per kill `kills.*.tsv`.
- DO installs the mock, but all 76 of its test codeunits declare TestPermissions: no at-risk test. Its FR app has no AL in
  `do-lethal` (only app.json), and DO's kill figures move, because another lane's run is writing that store.

**Limits of the set.**
- Tables with `InherentPermissions` are not excluded, and neither is a codeunit's own `Permissions` property, so some writes to
  other apps' tables may pass on BC.
- `NonRestrictive` (5 codeunits in the mock projects) is treated as not exposed; it is not measured.
- 268 exposed tests reach another codeunit before any lowering ("indirect"). Those with no direct record access first are left
  out: a stored BC baseline (R-882 S3,
  Service Declaration, mock installed) has 7 of them passing. Their codeunit's TestType does not explain it (probe 3). A
  library that lowers permissions or restores state before the first table access would, and a parse of the test codeunit cannot
  see that.
- Not explained: Microsoft ships suites with the firm shape as passing (recref declares Restrictive and inserts in Initialize
  before `PermissionsMock.Set`). How Microsoft's own pipeline runs them is not known here.
- No fixed build exists, so nothing is re-scored. The refusal ledger has no entry for this class, since it raises no refusal; the
  record is this item.

**Re-checked by PR-153 (lethal-bugs, 2026-11-18; `/coord/handoff/PR-153/result.md`), offline.**
- **Current build:** on edge-4ebfe7913, `u8160-restrictive-default` still passes `InsertUnderRestrictiveDefault` (BC fails it), so
  the difference stands.
- **Upstream's reading:** the maintainer traced it to Microsoft's Tests-TestLibraries, not Permissions Mock. BC's test runner lowers
  permissions before a test only through codeunit 130302 "Set State Test Run", which that app ships, and only if AllObj holds it.
  al-runner loads the app's dependencies plus the test runner, so with no dependency on Tests-TestLibraries it models a BC without
  it. The runner's owner chose a flag that declares apps installed on the server but not listed as dependencies. **PR 8166 merged
  on 2026-11-17, after edge-4ebfe7913.**
- **Our servers had 130302:** `bc-linux-setup.ts`'s pinned Microsoft apps include Tests-TestLibraries on bc1-bc3, and that
  package's symbols declare codeunit 130302 as "Set State Test Run". So the maintainer's reading fits every measurement above. The
  answer is drafted for upstream (`draft-8160.md`, with the orchestrator).
- **Sizing, by parse** (PR-35's script with one change): PR-35's walk skipped every dot-folder, but `alc` compiles `.al` under
  `.dependencies`. None of PR-35's 83 BC.History test folders holds `.al` under a dot-folder, so its figures above stand. DO has
  0 exposed codeunits (unchanged). **DC**, which PR-35 did not parse: 122 test codeunits, of which 4 are exposed (3 without
  TestPermissions, 1 Restrictive, all under `Test/.dependencies/DC/Test`). 30 tests write a non-temporary record before their first
  lowering, and 11 more reach another codeunit first. There is no stored DC run, so no passing or kill count.
- **Next:** re-run the entry on the first edge that has both #8166 and the flag. The entry will then need to declare
  Tests-TestLibraries as installed through the flag; without it, the runner still models a BC without 130302.
