Found by coord task PR-33 (2026-11-15) while measuring family 10 ([[R1047]]). Evidence: `/coord/handoff/PR-33/ws-run/result.md`
(both runs), `issue-restrictive-default.md`. Related: [[R026]] (LethAL's permission canary: a codeunit without TestPermissions
defaults to Restrictive).

**The difference, measured.** Regression entry `u8160-restrictive-default`, run by lethal-bugs on bc2 (BC 28.4 W1, Microsoft's
Permissions Mock 28.4 installed, through LethAL's web-service path):
- `InsertUnderRestrictiveDefault`, a codeunit with no TestPermissions that inserts into its own app's table before any
  `PermissionsMock.Set`, fails on BC: `Sorry, the current permissions prevented the action. (TableData 51600 URD Row Insert:
  Upstream Repro Restrictive Default)`. al-runner edge-5a58a0f16 passes it.
- `InsertWithTestPermissionsDisabled`, the same write with `TestPermissions = Disabled`, passes on both.

Ten cells of family 10's first BC-check app had the same shape and were refused the same way on BC; al-runner passed the three it
ran.

**Why it matters for LethAL.** A wrong verdict, not a refusal: a test that writes before lowering its permissions passes on
al-runner and fails on BC. Under a mutant, al-runner then scores the test against a baseline BC would not give. Not measured: a
server without Permissions Mock.

**How far the refusal reaches (PR-35, measured in three probes).** Each probe is pre-committed in
`docs/superpowers/specs/2026-11-15-pr35-8160-at-risk-precommitment.md` (addenda 1-3). lethal-bugs ran them on bc3 (BC 28.4 W1,
Permissions Mock installed, LethAL's web-service path, which goes through Microsoft's runner), with a target app as the app under
test and test codeunits without TestPermissions that lower nothing. Results: `/coord/handoff/PR-35/bc3-run{,2,3}/result.md`.
- **Every write is refused, in any app's code** (probe 1). That covers the test app's own table, the app under test's table
  written from the test, and the app under test's own codeunit writing its table (BC then names the target app as the writer). An
  Insert is refused, and so is a Modify with no read before it (probe 3).
- **A read of a table that holds rows is refused too** (probes 2 and 3): a Get, a FindFirst, and the filtered scan inside
  DeleteAll and ModifyAll, even when no row matches. A FindFirst on an empty table passed (probe 1).
- **TestType does not change it** (probe 3): Uncategorized, IntegrationTest and UnitTest are refused like no TestType.
- With `TestPermissions = Disabled` the same write passes. al-runner edge-5a58a0f16 passes every cell of the three probes.

**The at-risk set in stored results (PR-35).** By parse (`/coord/handoff/PR-35/at-risk.ts`), over PR-15's 84 BC.History projects
and DO:
- 58 of the 84 projects install Permissions Mock, directly or through Tests-TestLibraries. Of their 399 test codeunits, 83 are
  exposed: no TestPermissions, or Restrictive (79.2% declare another value).
- **Firm: 306 test methods in 20 projects write a non-temporary record before their first permission lowering.**
  - By table owner: the test app 33, the app under test 47, another app 226.
  - By first write: DeleteAll 140, Insert 114, Modify 48, Delete 3, ModifyAll 1.
  - **123 pass in the project's stored al-runner baseline;** BC, as LethAL runs it, would fail them. 183 already do not pass there.
  - **455 of those projects' 1,848 kills rest on one of them**, joined on the method name with no ambiguous name. Over 5% of the
    kills in 12 projects; all of them in recref, privacy, transl and usrperm.
  - Files: `at-risk.write.txt` per project, `outcomes.write.tsv` per test, `kills.write.tsv` per kill.
- **Upper bound: 348 tests in 21 projects touch a record (read or write) before lowering.** 127 pass in the stored baseline, and
  476 kills rest on them (`at-risk.access.txt`, `outcomes.access.tsv`, `kills.access.tsv`). The 42 read-first tests are at risk
  only when the table they read holds rows, which a parse cannot see.
- DO installs the mock, but all 76 of its test codeunits declare TestPermissions: no at-risk test. Its FR app has no AL in
  `do-lethal` (only app.json), and DO's kill figures move, because another lane's run is writing that store.

**The pre-committed predictions, scored.**

- P2 (fewer than 100 passing at-risk tests, in fewer than 10 projects): missed, 123 in 20.
- P3 (DO installs no mock): missed. DO installs it, but has no exposed codeunit, so no at-risk test.
- P4 (under 5% of each project's kills): missed in 12 projects.
- Addendum 1: writes outside the test app pass. Missed; they are refused.
- Addendum 2: DeleteAll with no matching row passes. Missed; it is refused at its read.
- Addendum 3: TestType Uncategorized passes. Missed; TestType does not matter.
- Validation: the only stored BC baseline of an at-risk test is the control's (refused, as predicted).

**Limits of the set.**
- Tables with `InherentPermissions` are not excluded, and neither is a codeunit's own `Permissions` property, so some writes to
  other apps' tables may pass on BC.
- `NonRestrictive` (15 codeunits) is treated as not exposed; it is not measured.
- 258 more tests reach another codeunit before any lowering ("indirect"). These are left out: a stored BC baseline (R-882 S3,
  Service Declaration, mock installed) has 7 of them passing. Their codeunit's TestType does not explain it (probe 3). A
  library that lowers permissions or restores state before the first table access would, and a parse of the test codeunit cannot
  see that.
- Not explained: Microsoft ships suites with the firm shape as passing (recref declares Restrictive and inserts in Initialize
  before `PermissionsMock.Set`). How Microsoft's own pipeline runs them is not known here.
- No fixed build exists, so nothing is re-scored. The refusal ledger has no entry for this class, since it raises no refusal; the
  record is this item.

**Filed.** https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8160 (upstream's #7640 says the per-method Restrictive
default is pinned; this shows it does not stop the write).
