**Found by the R-302 plan's review r1 (2026-09-29), finding C1**, and measured on PLAIN
procedures at `00e514c4`. Plan: `docs/superpowers/plans/2026-09-28-R-302-split-semantics.md`,
"Revision r2".

**What breaks.** `callType` (`packages/engine/src/semantic/types.ts`) types a call by
`resolveProcedure(owner, name)?.returnType`, and `resolveProcedure`
(`packages/engine/src/semantic/symbol-table.ts`) returns the FIRST procedure with that name, never
looking at the arguments. AL allows overloads. So with `Foo(X: Integer): Integer` declared before
`Foo(T: Text): Text`, the call `Foo('x')` is typed `Integer`.

**Measured** (hand-written repro `o2-overload-plain`, both overloads plain, a caller
`exit(Foo('x') + Foo('y'))`): HEAD emits `swap-additive` there, and the instrumented project FAILS
`alc`, `AL0175: Operator '-' cannot be applied to operands of type 'Text' and 'Text'`. R-302 would
widen the same hole to split members (repro `o1-overload-split-first`), which the review caught.

**Size** (a read-only census of HEAD at the positions `swap-additive` reads): 0 calls to an
overloaded name in every fixture and every measured corpus (DC/Cloud, System Application,
BusinessFoundation, the BaseApp scratch project).

**Closing.** Fixed in R-302: a call is typed only when its owner declares EXACTLY ONE procedure of
that name (compared as AL compares names, case-insensitively; a split member counts under every
arm's name). Closes with that commit and a test that goes red on the first-match lookup.

**Done (2026-09-29, R-302, `db641338`):** a call is typed only through `uniqueProcedure` (one procedure of that name). The unit test goes red when the fix alone is
reverted, and the pipeline pins in `packages/runner/tests/preproc-instrumentation.test.ts` do too.
Pre-committed corpus effects matched (see [[R302]]'s closing record).
