Found by coord task R-892 (PaymentPractices, BC.History, on al-runner v3). Evidence: `/coord/handoff/R-892/result.md`. Related:
[[R893]] (the one case found, being fixed by coord task R-894), [[R196]], [[R830]], [[R164]], [[R897]].

**What.** The check that refuses a mutation which could make an enclosing loop never end (R196: a write the loop condition reads;
R830: a call the loop's progress rests on) runs inside the Tier-1 operators, through `loop-hazard.ts`. The Tier-2 operators in
`packages/builtin-tier2/` do not call it. So a Tier-2 mutation inside a loop is mutated whatever the loop's shape.

**Correction (lethal-code, R-899, 2026-11-10).** That holds for the per-operator check (`hangCapableForMutatedNode`, R196/R830),
which Tier-1 operators call in their own `candidate`. The dispatch-level refusal `openItemHangRefuses` (R501, in `loop-hazard.ts`)
already runs for EVERY operator, Tier-2 included: R-531's consuming loops, R-696's moved walks, the open-item rules, and R893's walk
jump, which reached `swap-find-direction` that way. So the gap is the R196/R830 shapes, plus any Tier-2-specific shape that no
dispatch rule covers.

**Built (R-899).** Five rules inside `openItemHangRefuses`, so R447 counts each refusal by operator name; each has a test seam and
tests in `packages/builtin-tier1/tests/r896-tier2-hang.test.ts`. Evidence: `/coord/handoff/R-899/findings.md`.
- P1 (`r896FilterBeforeJump`): `flip-filter-literal` on a `SetFilter` on the walked record R inside R's `Next` walk, when a jump on
  R (`FindFirst`, `FindLast`, `Find`) follows in that body.
- P1b (`r896JumpViaCopy`): `swap-find-direction` on a jump on X inside R's `Next` walk, when the body later does `R := X`,
  `R.Copy(X)` or `R.TransferFields(X)`.
- P2 (`r896ValueSwap`): `swap-enum-member` and `swap-rec-xrec` in a loop's exit parts, or feeding a write the exit reads (the first
  two clauses of `clockSwapHangs`, now one shared helper).
- P5 (`r896InvisibleProgress`): any operator on a record call on X inside a loop whose condition asks another variable of X's table
  (`Find*`, `IsEmpty`, `Count`) with no `Next`, when R-531 finds no consumer in the loop.
- P6 (`r896TestFieldOnlyExit`): `remove-testfield` in a loop whose condition reads no name and calls nothing, with no other exit in
  its body.

**Named limit: `remove-commit` (P4, not built).** Removing a `Commit` can stop a loop only when the loop polls for work another
session does after the commit (`Commit(); repeat Sleep(10); until IsProcessed(..)`): without the commit the other session never sees
the row. An uncapped poll would then wait forever. This is argued, not measured: al-runner v3 runs one session, so it cannot show the
hang, and repro RCM1 has a cap. A `remove-commit` mutant in such a poll stays admitted. Measure it on BC before building a rule.

**Named limit: P5 does not look one call deep.** In `while not X.IsEmpty() do Step();`, with the progress inside `Step`, a site in
`Step` is not inside the loop and is not seen.

**Named limit: P2 over-refuses in a `Next` walk's exit.** An enum swap in `until (R.Next() = 0) or (R.Phase = ...)` is refused,
although the `Next` still ends the walk. This comes from `clockSwapHangs`' exit-parts clause and is kept.

**Seen.** `swap-find-direction` turned a `FindLast()` that skips ahead inside a `repeat ... until Next() = 0` walk of the same record
into `FindFirst()`, which rewinds the walk. With demo data the loop never ended: R-887's PaymentPractices run hit its 3-hour cap. On BC
the run stranded and quarantined (R893). R893 fixes that operator only.

**Candidates to check, by what they change.** Each needs a loop shape where its change stops progress:
- `swap-find-direction`: R893.
- `remove-setrange`, `flip-filter-literal`, `filter-expression`: a filter change on the record a `while Rec.FindFirst() do ...` or
  `repeat ... until Rec.Next() = 0` loop walks, for example a filter that keeps matching rows the body no longer removes.
- `swap-modify-flag`, `validate-to-assign`, `swap-rec-xrec`: only if the changed trigger or field drives the loop's key or filter.
- `remove-commit`, `remove-testfield`, `swap-enum-member`, `swap-workdate-today`, `forced-trigger-raise`, `write-txn-codeunit-run`,
  `remove-calcfields`: no progress-bearing effect seen; to be confirmed.
