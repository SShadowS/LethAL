**Found by the R-547 plan review (opus spec-adversary, adversary-r2 finding 3, 2026-10-09).** Pre-existing
(R500 shape 1); not caused or changed by R-547.

R500 shape 1 (`writesPresetExitName` in `packages/builtin-tier1/src/loop-hazard.ts`) refuses a site that
writes a preset exit name: an assignment to it, or a call that passes it as a `var` argument (`argWritten`).
A call to a procedure that writes the name ITSELF, with no argument (`InitContinue();` in `OnPreReport`,
where `InitContinue` does `Continue := true`), is neither. So a mutant that deletes that call
(`void-method-call`, `empty-block` of the caller) leaves the name in its walking state, and the open item
that reads it may loop forever. The write inside `InitContinue` is refused (it is an assignment of the
name); the call that decides whether it runs is not. R548 (`extensionPresetExitNames`) inherits the gap
inside a reportextension, for a call to a base-report procedure or an extension procedure.

**To build it.** Treat a call as a write of every preset name its callee writes (same object, and the base
report candidates inside a reportextension; transitively, as `openReachable` does), outside open-item code.
Red-test both directions: deleting `InitContinue();` is refused; deleting a call to a procedure that writes
no preset name is not. Count the sites on BaseApp first.

**Built (coord task R-555, branch `lethal/r555`, identity scheme 38).** Plans
`/coord/reviews/R-555-plan/plan.r1.md` to `plan.r3.md`, measurement `/coord/handoff/R-555/measure.md`,
build log with every red check `/coord/handoff/R-555/build.md`, tests
`packages/builtin-tier1/tests/r555-preset-writer-calls.test.ts`. All in `writesPresetExitName`
(`packages/builtin-tier1/src/loop-hazard.ts`):

- **A preset writer.** `presetWriters` names every procedure that writes a preset exit name (R500 shape
  1's assignment or `var`-argument write, now `directWrite`), or calls such a procedure, to a fixpoint over
  the call shapes `openReachable` follows (`bareCallee`, `hiddenCallee`: `P()`, `this.P()`,
  `CurrReport.P()`, a paren-less `if Ready then`). Inside a reportextension the base candidates'
  procedures count too (`baseCandidatesOf`, R-547), each over the extension's names AND that base's own
  preset names, since a base procedure can write a base-private name the extension cannot spell.
- **A call to a writer is a write.** Shape 1's existing walk then refuses the call and its arguments,
  every enclosing block up to the body, the condition of an `if`/`while`/`repeat`/`case` holding it, and
  an early exit before it. The early return on "no preset names" is skipped when writers exist (an
  extension with no names of its own can still call a base writer).
- **Cross-object.** In EVERY object (reports and reportextensions included), a call whose receiver is
  declared `Report X` (a variable or a parameter) to a writer of project report X, or of any project
  reportextension of X, is a write. An alc probe (alc 18.0.43, runtime 16) showed that a reportextension
  procedure binds through a `Report X` variable from a codeunit (AL0432 from an `[Obsolete]` marker at
  the call; AL0132 for an unknown member), so extension writers are included. The report lookup is local
  to this rule: `objectsOfType` still returns `[]` for kind `report`, pinned by a test, because widening
  it would also widen R500 shape 2's callee follow.
- **Unknown callees.** A bare name no parsed procedure declares is a built-in in a report (not a writer).
  In a reportextension it is a writer when an UNPARSED base candidate declares it as `procedure <name>`;
  in a parse-damaged report with preset names, when an ERROR descendant declares it so. Both match the two
  tokens `procedure <name>`, not the bare name, so `Error`, `Message` and `Format` do not match. The same
  narrowing now applies to `argWritten`'s unread-base rule (R548), so the two unread rules agree.

**The extension-writer site (plan r3 item 1).** `ProductionOrder.Table.al` `RunCreatePickFromWhseSource`
calls `SetProdOrder` on a `Report "Whse.-Source - Create Document"` variable. `SetProdOrder` is declared in
`MfgWhseSourceCreateDocument.ReportExt.al` and writes the base's protected preset name `WhseDoc` (R548). Its
sibling `AssemblyHeader.Table.al` `RunWhseSourceCreateDocument` calls `SetAssemblyOrder`, a writer of the
base report itself. The alc probe answered YES, so BOTH are refused sites on the built branch. The sibling
was in the measured set; `SetProdOrder` was not, so it is expected beyond it.

**Residuals (not seen).**

  case): its preset names cannot be read, so neither its writes nor its writer calls are refused.
  Measured: 0 parse-damaged reports on any corpus, and 0 files with a parse error of BaseApp's 8,098.
- A procedure the parser RECOVERS as a node but whose body was swallowed into a sibling ERROR node counts as a

  callees). Measured cost 0: no parse-damaged report on any corpus. (R-555 build review, finding 4.)
