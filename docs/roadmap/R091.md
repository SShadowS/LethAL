**The 30 s mutant budget floor is wrong by default for real AL, and the failure it produces is a tier quarantine rather than a verdict.** R47 records that `MIN_MUTANT_BUDGET_MS` is a hardcoded floor; `--mutant-timeout-ms` now reaches it, so what remains is that the DEFAULT is wrong and the consequence of it being wrong is disproportionate. **Measured 2026-08-04/05** on DO codeunit 6175297: at the default floor, three consecutive runs each stranded and quarantined the tier, costing ~10 min of recycle + `force-reset-lease` + `clear-quarantine` + resume each time. The stranding mutants were **`void-method-call` deleting a `SetCurrentKey`** — which does not hang, it makes the following filtered query pick a worse plan and scan. They are SLOW, not hung. `--mutant-timeout-ms 180000` eliminated them entirely (errors 2 → 0, single-pass completion, twice) while `M0013` — `negate-conditional` on `until ... Next() = 0`, genuinely non-terminating — still scored `timeout-killed` at 30172 ms. **That contrast within one run is the control**: the machinery distinguishes the two correctly once the budget is honest. Options, none yet chosen: raise the default; derive it from the observed per-mutant distribution (median here was 433 ms, p95 6.4 s, so 180 s is ~28× p95 and cost nothing); or make a budget overrun score `timeout-killed` rather than strand, which is the real asymmetry — an overrun is currently indistinguishable from a genuine strand on the fenced path.
