Coord task R-967, from R977's closure (R-964 batch 11). Related: [[R977]], [[R945]] (the method), [[R612]] (the keep list).

**What.** Microsoft's APIV1 tests on edge-c8fe56e05: 271 of 467 refused at baseline with `store error platform table 'Api Web
Service' (2000000193) has no provider` (upstream #7775 row 4). The family was not in `V3_SERVE_SAFE_REFUSALS`, so every refused codeunit
closed its serve daemon: 100 daemon starts in a 417 s baseline.

**Measured clean (`/coord/handoff/R-967/probe/`, R-937's kit and method, invented AL, edge-c8fe56e05).** Two refusers, one per table
(`Api Web Service` 2000000193, `Tenant Media Set` 2000000183), each after R-937's standard writes (a row, SingleInstance Text and
StringBuilder, IsolatedStorage, NumberSequence, WorkDate); 47 refusals each with exactly that text. On one kept daemon 27 readers after
refusals, all equal to the control; 20 rounds on fresh daemons, one answer, equal to the kept control; the pid unchanged; no panic
text. The refusal is the store's, before any row is read, so the entry takes the table as a parameter.

**Built.** `platform-no-provider` in `V3_SERVE_SAFE_REFUSALS`, anchored at both ends (`... platform table '<name>' (<number>) has no
provider`), red both ways in `al-runner-serve-rule.test.ts` (a tail, a missing number and a Tenant Media write still close). Like
R945's entries it is not in the update gate's `serve-keep-reasons` fact: a reworded text only stops matching and the daemon closes again.

**Effect, measured (APIV1 re-run on the branch, same pool and config as R-964):** daemon starts 100 -> 16, baseline 417 s -> 323 s,
session 468 s -> 373 s; all 467 baseline rows identical (outcome and message, `baseline-eq.ts`), all 5,442 verdicts identical.
