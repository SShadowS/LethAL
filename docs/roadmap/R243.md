**Found 2026-09-26, while closing R235.** `fixtures/README.md`'s "Expected verdict table
(hand-computed)" section, covering `sandbox-app` + `sandbox-tests`, lists 16 mutant sites and
gives bcdev 3 killed / 10 survived / 3 no-coverage (3/13) and al-runner 3 killed / 13 survived / 0
no-coverage (3/16). Both `al-runner.itest.ts` and `bcdev.itest.ts` now assert `EXPECTED.
totalMutantSites` of 19, with both backends at 3 killed / 12 survived / 4 no-coverage, per R220's
comment there: the two gates now agree PER MUTANT, which the stale prose does not reflect.

**Why the table is short three.** R159 landed three operators against this fixture after the
table was last hand-computed: `swap-additive` on `DiscountedPrice`'s subtraction, and
`remove-assignment` plus `shift-integer` on `Sandbox Logic.LogAudit`'s `Amount <> 0` guard. Each
is recorded in the itest files' own comments as moving the count by one, but `fixtures/README.md`'s
per-procedure table and its "Totals (16 mutant sites)" block were never updated alongside them.

**Who it hits.** Anyone reading `fixtures/README.md` to understand what this fixture measures, or
using its verify command (`... --dry-run` printing `16 mutant site(s)`) as a check, gets a number
three short of what the live gates actually assert and would trust it.

**What would fix it.** Recompute the per-procedure table and totals against the current fixture
(the three new sites plus their verdicts on each backend), and update the `--dry-run` count in the
same commit, per the note already at the top of that section: "If the fixture AL or tests ever
change, recompute this table and update both itest scripts in the same commit" — the itest scripts
were kept current; the README was not.

Evidence: `fixtures/README.md`'s "Expected verdict table (hand-computed)" section, versus
`EXPECTED` in `al-runner.itest.ts` and `bcdev.itest.ts`.
