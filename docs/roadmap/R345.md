**Seen 2026-09-29 by the orchestrator**, re-running `itest:alrunner` on master after merging R-242
(al-runner v2.12.0). The `--server` leg of the `[LETHALA]` symbol set refused to start: the R149
re-probe under the session's platform-app pin reported `qualified-test-name` UNMEASURABLE,
"no readable --output-json envelope (exit 82)", and `runSession` refused. Log:
`H:/lethal-coord/tasks/R-242/orch-itest-alrunner.log`.

At the same time another session was running its own al-runner probes (two `--server` daemons,
one with `--define R318A`), sharing the same al-runner cache (`~/.cache/al-runner`, the
`ncl-shadow` engine variant) and package directories. An immediate re-run on the same tree PASSED
every leg (`orch-itest-alrunner-2.log`), and the lane's own two runs of the same branch passed.

**Not known:** what exit 82 means in al-runner 2.12.0, and whether concurrent al-runner processes
(a shared cache lock, a variant rebuild, or a port) caused it. Until measured, this is a suspected
flake, not a LethAL defect: the refusal itself was correct (the probe could not read the contract,
so the run did not guess).

**To close.** Reproduce with two concurrent al-runner sessions on this machine, read al-runner's
exit code 82, and decide: document "one al-runner session at a time" for the lanes, retry the
probe once on this exit code, or report it upstream. Until then, lanes should not run
`itest:alrunner` while another session runs al-runner.
