Coord PR-03 (lethal-bugs, 2026-11-15), process review item 4, under the owner's standing approval for small BC.History
app+test pairs on bc2/bc3. Pre-commitment: `docs/superpowers/specs/2026-11-15-pr03-bc-differential-precommitment.md` (master
a5eb0a75). Evidence: `/coord/handoff/PR-03/` (v3 stores, reports and events per module; `bc/<m>-test/` the BC test apps and
`compile.md`; `docshare.bc.json`; `bc2-doctor.txt`; `result.md`). Related: [[R1019]] (Filter Tokens' daemon closes).

**Method.** v3: `current` edge-5a58a0f16, each module's source and test project as in BC.History (28.6). BC: bc2 (BC 28.4 W1),
one lease throughout. On BC 28 the modules live inside the one System Application app, so only a renumbered copy of each test
app was published (ids 91500-91589, publisher "LethAL Scratch", depending on System Application and Library Assert alone; each
compiled offline against the server's symbols first, so none uses module internals), run by codeunit through the dev endpoint,
then uninstalled with its data and unpublished. `lethal doctor` ok after; lease released. Baseline only: a mutant sample on BC
would need a renumbered copy of the MODULE in its own namespace (publishing the module's source would clash with System
Application's objects).

- **Json, two v3 differences (prediction 2 held).** `TestGetBoolPropertyValueFromJObjectByName`: refused, `Evaluate with format
  number 2 (not pinned by the corpus)` (#7995 item 3). `TestGetEnumPropertyValueFromJObjectByName`: fails, `'Option1' is not an
  option. The existing options are:` with an empty list: Evaluate into a `var` Option parameter declared without members loses
  the caller's members (#7994). BC passes both. Both issues were open and waiting for BC evidence; BC's answer posted on each
  (#7994 comment 6892541680, #7995 comment 6892541858). Regression-set entry `u7994-u7995-evaluate` (invented repros, both
  reproduce on edge-5a58a0f16). The 28.4/28.6 source comparison could not be made (the BC.History checkout is shallow); both
  failures are v3's own texts (a refusal, an empty option list), so a version difference is not their cause.
- **Document Sharing: not a v3 defect.** 14 tests fail on BC with `ALAzureAdCodeGrantFlow.ALAcquireOnBehalfOfToken ...
  parameter 'resource'` from Base Application's `Azure AD Auth Flow`/`Azure AD Mgt.`: the server has Base Application installed,
  and its document-service subscriber runs. Microsoft runs these tests on System Application alone, as v3 did (its packages hold
  no Base Application). A pair measured on a server without Base Application would decide it; not filed.
- Json's mutant run also met four refusal causes the ledger lacked: added to `docs/measurements/refusal-ledger.json` (#8036 §1
  JObject.DeepClone and JProperty.Value, #7924 JObject.Add's ArgumentException, #7995 CopyStr of an unassigned Variant).

**Dropped candidates.** Client Type Management, Confirm Management and Field Selection (the survey's first picks) need their own
test libraries, which use the module's internals: on BC only Microsoft's own test apps may see System Application's internals.
Encoding, Azure Storage Services, VS Code Integration and Headlines need Any, Library Variable Storage, Permissions Mock or a test
library the server lacks.
