**Install code (measured, al-runner edge-c8fe56e05).** An invented dependency, compiled to an `.app` and given to al-runner as a
package, whose install codeunit sets a flag in OnInstallAppPerCompany (a per-company table) and in OnInstallAppPerDatabase (a
`DataPerCompany = false` table), and a test app that reads both: both pass. So al-runner runs a dependency's install codeunit before
the tests, and DO's ~32 "Document Output has not been activated" baseline failures are not that. The message comes from Continia
Core's online module activation, a state its activation service sets: DO's environment on a fresh database, not an al-runner
difference.

**Refusals.**
- `the caption of a page with DataCaptionExpression and no source table` (1 DO test): reproduced, filed as #8004 (follow-up to #6320).
- `FindSet on the Company table` (39 DO tests): already #7775's item; count added there.
- Outbound HTTP with no test handler (5 DO tests): al-runner's stated design (the message asks for an `[HttpClientHandler]`); not filed.
- `ZipArchive.Dispose` over an AL OutStream (3) and `GoToKey` at the last row of a descending view (2): NOT reduced. A zip written
  over a Blob's OutStream, with or without bytes written first, passes; a 120-row descending list, opened plainly or with OnOpenPage
  FindLast, passes GoToKey. Both need DO's own shape; left unfiled until a repro exists.
- DO's 23 Newtonsoft.Json failures: a config gap (no `assemblyProbingPaths`), noted in R-942's result for its resume.
