**Filed 2026-10-22 by lethal-preproc during R-622** (found while hunting [[R622]]'s verify hang;
measured, Bun 1.4.2 on Linux).

**What.** In Bun, `readdir(dir, { recursive: true })` and `readdirSync(dir, { recursive: true })`
FOLLOW directory symlinks. Node's do not. Measured:
- **Sync, two links forming a cycle** (`a/to-b -> b`, `b/to-a -> a`, inside a small tree): ran
  past a 30 s timeout at 100% CPU. The tree it walks grows with every turn of the cycle
  (`/coord/handoff/R-622/probe/p7`, `walk.ts cycle`).
- **Sync, one link back to an ancestor:** fails fast with `ELOOP`.
- **Async, the same two-link cycle in an empty tree:** throws `ELOOP` after about 40 levels
  (`a/to-b/to-a/...`). With real files in the cycle, the work before that point grows the same
  way as the sync case.
- **A link to a tree outside the root:** the whole outside tree is walked as if it were inside.

**Where it matters.**
- **Product code walks the user's project this way.** Examples: the project scan in
  `orchestrator.ts` and `cli.ts`, `line-map.ts`, `source-drift.ts`, `baseline-snapshot.ts`,
  `al-runner-coverage.ts`, `discovery.ts` and `testpage-scan.ts` (test folders), and the cache walks
  in `artifact.ts`, `al-runner-cache.ts` and `bcdev-backend.ts`. A symlinked folder in an AL project
  (a shared `src` linked from two apps, or a link to a sibling checkout) would be walked:
  - a cycle ends in a cryptic `ELOOP` crash, or runs a very long time;
  - a link out pulls foreign `.al` files into the run, or into a source hash.

  None of this is measured on a real project. No corpus project is known to contain a symlink.
- **Tests:** `real-home-guard.test.ts` walks `scripts/` and `packages/*/src|tests` with the sync
  form. A lane's gitignored scratch folder with a link cycle under `scripts/` would hang every
  verify at 100% CPU. That was ruled OUT as R622's cause: no symlink appeared during a watched
  verify, and the cause would not print R622's `killed 1 dangling process` line.

**To close.**
- One shared walk helper that does not follow directory symlinks. Use `withFileTypes` and skip
  entries where `isSymbolicLink()` is true, or walk with `lstat`. Then:
  - refuse BY NAME on a symlinked folder inside a project, with the path, until a ruling says
    whether such a folder belongs to the project;
  - or document that it is skipped.
- Move every product walk and the test walk onto the helper.
- Red test: a fixture tree with a two-link cycle and a link out. Each walk must finish fast and
  must not list the foreign files.
