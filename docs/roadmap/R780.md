**Built 2026-10-25 for coord task R-772.** Related: [[R586]], [[R762]].

**What.** `deploy()` of the al-runner-v3 backend compiled the user's test dir with alc after every batch (about 11 s on
the D1 slice), only to learn the same "it compiles" answer. It now skips that compile when alc already passed for the
same key. Everything else is unchanged: staging, the target compile, the symbols-unreadable refusal, the proof's hashes
and `assertBound`. A hit changes no verdict; it only avoids repeating a compile whose inputs are the same.

**Evidence (measured).** `/coord/handoff/R-772/out/*.analysis.txt` and `/coord/handoff/R-772/scripts/q-measure.ts`: alc
writes nothing into `active/` or the test dir. The target's `SymbolReference.json` differs between batches only by its
top-level `Version` (minted per batch) and by the global `MutationSelector` / `MutationSelector<id>` variables that
schemata adds to each object holding a mutant of the batch. `testAppSha256` and `targetAppSha256` in the proof had no
reader.

**The key.** sha256 over these parts, in this order, each length-prefixed (`al-runner-v3-testapp-cache.ts`,
`testAppCacheKey`):

1. The test dir: the hash of its `.al` files, the sha256 of every non-`.al` file (`.alpackages` included), and the sha256
   of its `app.json`. These are the very values stored in the proof (one read in `deploy()`, passed to both).
2. The staged `active/app.json` with `version` removed (canonical JSON).
3. The target .app's `SymbolReference.json` with top-level `Version` removed (canonical JSON).
4. The `MutationSelector*` globals are removed from (3) ONLY when no test `.al` declares an extension object (any
   `<kind>extension <id>`, matched conservatively anywhere in the text; what it extends is not resolved). A test
   `reportextension` shares its target report's global namespace and a duplicate global is AL0155, so dropping them there
   could hide a compile failure. The flag is part of the key too.
5. The staged dependency packages used for the test compile: name and sha256, sorted, the target's own app id excluded.
6. The alc binary path and its sha256.
7. The preprocessor symbols passed to alc, in order.
8. The transport (one-shot or serve-entries; it changes the selector's symbols).

**Outside the key, checked on every hit.** The batch's minted version must satisfy the version the test `app.json` declares
for the target dependency (matched by id, or name and publisher). If not, or if either version is unreadable: a miss, so
alc runs live and fails as it does today.

**The store.** `<cacheDir>/testapp-proof/<64 hex key>`, one small marker per key (`alRunnerV3.cacheDir`). Written only
after a PASSING test-app compile, by temp file plus rename. Capped at 2000 markers; the oldest by mtime go first (a hit
refreshes the mtime). A marker with any other content, a directory or a link where the file should be, or a read error is
a miss. Failures are never cached, so `TestAppError` and its text are unchanged. Without a `cacheDir` nothing is cached
(the conservative choice: the backend has no other default cache location). Any part that cannot be read (target
symbols, alc binary, `active/app.json`) also means no key, so no hit and no marker.

**Proof fields.** `testAppSha256` is informational (no reader); on a hit it is `cached:<key>`, never a built .app's hash.
`targetAppSha256` is unchanged. Stats: `testAppCacheStats()` gives `{ hits, misses }`, and the serve-entries close line
ends with them.

**Tests** (`packages/runner/tests/al-runner-v3-backend.test.ts`, describe "R780"): cold writes a marker and a second
instance skips the test-app alc; same objects with a new minted version hits; a new object with no test extension hits;
the same with a test `reportextension` misses; misses for a changed test `.al`, test `app.json`, dependency sha, alc sha,
symbol interface, preprocessor set and transport (the key alone, plus a deploy); minted version below the declared
minimum misses; an alc failure is never cached; four corrupt-marker shapes miss; after a hit `assertBound` still refuses
a changed `active/` or test dir byte; the size cap evicts the oldest. Each was red-checked by breaking its code path.

**Open.** The v3 gate (`itest:alrunner-v3`) has not been run for this change; merge waits for it.
