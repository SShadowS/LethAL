**Filed 2026-10-23 by lethal-bugs during R-674**, from its build review's finding F3 (orchestrator ruling: file it,
don't fix it in R-674).

**What.** `dryRunCeiling` in `packages/runner/src/cli.ts` is not passed the backend kind. Take a
`lethal run --backend al-runner-v3 --dry-run` whose config has an `envTool` section and no `bcdev.server`:
- it calls `prepareBcdevReadOnly(...).bcdev()`, which runs the external env tool's `resolve`;
- it then prints the publish ceiling of a bcdev tier.

But an al-runner-v3 run publishes nothing to any BC server. The printed ceiling describes a server the run never
uses (class 3, a misleading note). The `resolve` call is a needless external step: it may need the tool's login, or
fail on its own.

R674's warning (`runFromCli`) does not reach this path, because `--dry-run` goes through `dryRunFromCli`.

**Who hits it.** A user whose shared config carries an `envTool` section for bcdev runs, and who dry-runs with
`--backend al-runner-v3`.

**To close.**
- Pass the backend kind to `dryRunCeiling`, and return `undefined` (no ceiling, no env-tool `resolve`) unless it is
  bcdev. Use the `isLocalRunner` predicate, as R674 does.
- Consider printing R674's `envTool ... IGNORED` warning on the dry-run path too.
- Add a test for each direction: v3 runs no `resolve` and prints no ceiling; bcdev still does.

Evidence: R-674's build review (F3); `dryRunCeiling` and `dryRunFromCli` in `cli.ts`; R674; R18.

**Closed by R-676 (ddd8bab5).** `dryRunCeiling` now receives `printDryRun`'s backend kind. When it is absent the
backend is bcdev, as before. For a local runner (`isLocalRunner`) it returns before reading the config: there is no
env-tool `resolve`, no ceiling and no note.
