**Filed 2026-10-23 by lethal-code**, from R-656's build review (`/coord/reviews/R-656-build/review-r1.md`), on the
orchestrator's ruling. Related: [[R667]], [[R657]], [[R553]].

**What.** `v3RowVerdict`'s K1(a) guard turns a row whose message starts with `NotRun: out-of-scope:` but carries
no `notRun` flag into `error` (`runner-test-error`), never a kill. It checks with `startsWith(V3_REFUSAL_PREFIX)`.
Suppose a future v3 build wrote failure messages as `{Type}: {Message}`, as v2 did. Then a refusal written as a
plain `fail` would read `SomeException: NotRun: out-of-scope: ...`, slip past the guard, and score as a KILL.

**Today it is closed in two places, both downstream of the cause.**
- R667's leg-C fact `message-has-no-type-prefix` fails the update gate on a prefixed build, so such a build never
  becomes `current`.
- R-656's session check refuses a run whose probe row is prefixed.
- alpha.2 and edge 57f1e4f98 write no prefix (R657).

**To close (FULL: it touches a verdict rule).**
- Make K1(a) recognize the refusal text after an optional `<Type>: ` prefix, so that a prefixed refusal stays
  `error`.
- Write one deep plan review on exactly which prefixes are stripped, so that a real assertion message that
  happens to contain the text is not turned into an `error`.
- A red test in each direction.
- Then decide whether R-656's session refusal can relax to a warning.

**Closed by R-672** (plan `docs/superpowers/plans/2026-10-23-r672-v3-refusal-prefix.md`, commit e11a42c6).
- One prefix, `V3_TYPE_PREFIX` = `[A-Za-z_][\w.]*: ` (one word, dots allowed), in `al-runner-rows.ts`.
  `isV3RefusalText` reads v3's refusal after at most one such word, as one anchored regex with an optional group.
- K1(a) (`v3RowVerdict`), `refusalRowShape` and `commit-under-test-isolation` read `isV3RefusalText`. An
  unprefixed refusal's verdict is unchanged, compared as a whole object.
- Leg C's `message-has-no-type-prefix` reads `^V3_TYPE_PREFIX`; `AL_RUNNER_EXCEPTION_PREFIX` is deleted. A
  property test ties the fact to K1(a) over the plan's 12 prefixes. (History: [[R675]] later deleted
  `V3_TYPE_PREFIX` and this property test; see R675's own text. Cross-reference added by the R-755 audit.)
- The v3 serve-keep rule (`serveDaemonReusable`) no longer keeps a daemon after a refusal written as a plain
  `pass`/`fail`. A stateful fake daemon shows the tainted next request runs on a fresh daemon and never scores.
- The session refusal stays; `MESSAGE_PREFIX_REASON` now scopes K1(a) to a one-word prefix.
- Residuals, pinned as `fail` by name: `A: B: ` is closed by the leg-C fact, which refuses such a build;
  `Runtime error: ` and `a::b: ` are [[R675]].
- Every guard was red-checked in both directions. The live gates cannot reach the new branches, since no build
  writes a prefix; `itest:alrunner-v3` on the final head is pre-committed in the plan (§4, §5).
