Found by coord PR-401 (lethal-bugs, 2026-11-24), the shell-write advisory hook's fix.

**What happens:** `selectLegs` (`scripts/agentflow/gate-table.ts`) matches every changed path against its rules. A path no rule
matches is default-deny: it selects the full leg set. `.claude/hooks/shell-write-advisory.ts` matches no rule, so PR-401's
diff (that hook and its test in `scripts/`) selected all 11 legs: bcdev, lease, stale-publish, tables, chunked, alrunner-v3,
harden, verify, testapp, agreement and hang.

**Why that is wrong for this path:** a `.claude/hooks/` script runs only inside Claude Code sessions, around tool calls.
No gate, no itest and no LethAL code path loads it. Its tests are under `scripts/` and run in VERIFY and CI. So 11 gates prove
nothing about such a change.

**The ruling for PR-401** (the orchestrator, 2026-11-24): submit on VERIFY plus CI, with the fallback named in the result.

**The fix:** a rule in `RULES` matching `^\.claude/hooks/`, selecting no gate legs (the change is proven by VERIFY's
`scripts/*` hook tests and CI). A `gate-table` unit test pins it: a hook path selects no legs and is not "unmatched". Its twin
pins that a path outside every rule still selects the full set (default-deny unchanged). Keep `.claude/settings.json` OUT of
the new rule: it is configuration that changes which hooks run, so it stays default-deny until it is weighed on its own.
