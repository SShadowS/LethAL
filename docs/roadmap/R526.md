**Filed 2026-10-08 by the [[R500]] build** (plan r3 `/coord/reviews/R-500-plan/plan.r3.md`, adversary r2 finding 4d).
A plausible hang that is NOT refused.

**What.** For an `Interface X` receiver, R500 refuses every project codeunit whose `implements` clause names X
(`objectsOfType` in `loop-hazard.ts`). A codeunit that implements an interface B which `extends` X can be the object
behind that receiver too, and it is not refused.

## Closed by ruling

R-522 measurement, 2026-10-23 (`/coord/handoff/R-522/measure.md`, section R526). 11 interfaces carry an `extends`
clause (BC.History, production); of 97 interface seeds, none sits on an `extends` parent that gets a new
implementer. CDO, DC and DO: 0. Stated limit: a future `interface B extends A` with an open-item receiver typed A
would not reach B's implementers.

**To close (original plan, closed by the ruling above).** Follow `extends` transitively when collecting implementers, measure the change, and land it or
close it with a ruling.
