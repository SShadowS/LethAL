**Coord task R-791.** Related: [[R771]], [[R788]]. Evidence: `/coord/handoff/R-791/` (`report.md`, `ab.out`,
`ab/*.report.json`, `a157/timing.md`, `login-cost.out`).

**The question.** R-771's timing on the new `current` (edge-a157b2d34) read slower than dcdf9e821's, but under other
load. The talk demo runs on `current`.

**A/B under the same load** (`ab.sh`, 20:32-20:39Z):
- Method: the same `cli.ts run` that `scripts/v3-timing.ts` makes, with only `alRunnerV3.path` changed to each build's
  kept, gated folder. `current` was never moved. One warm-up, then 5 rounds with the builds alternating inside each
  round.
- Gift card: best 1.6 vs 1.7 s, median 1.9 vs 1.9 s. Equal.
- D1: best 26.7 vs 25.0 s (+6.8%), median 27.6 vs 26.4 s (+4.5%). Under the 10% bar.
- The one phase that clearly grows is D1's one-shot baseline call: 4.35 vs 3.43 s.

**Not #5743.** The login WorkDate lookup costs about 6 ms per test session: 0.07 vs 0.01 s of run time over ten
sessions with demo data.

**The upstream regression**
([#5872](https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5872)). A plain `al-runner test` on
a157b2d34 spends about 4 s in "compile" on every warm run:
- 4.0-5.2 s, against 0.15-0.31 s on dcdf9e821;
- reproduced with Microsoft-only packages and an invented ten-codeunit app;
- not network (`--no-download` makes no difference, and there are no connects);
- 18,216 `pread64` calls against 1,748;
- `--require-compile-cache` takes about 1 s on a157b2d34, so a usable entry exists.

Suspect, not bisected: a157b2d3 (#5841, the translations step).

**LethAL impact.** The cost is paid once per serve daemon start and once per one-shot call, so D1 is about 3% slower and
the gift card is unchanged. There is no LethAL-side fix worth making, and no pin-back (R125).
