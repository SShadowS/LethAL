**What.** `ExplainGap` (C02-09) groups a block's survivors, but carries no per-test detail: no
covering test's file and line, and no ranking of those tests by reach (did the test actually run the
mutated statement) then by duration. A user staring at a gap still has to go find which test to run
first and where it lives.

**Who hits it.** Anyone using `lethal explain` to decide what to run next on a gap with several
covering tests: the tool names the gap and its survivors, not which test to try first or where that
test's source sits.

**Evidence.** `ExplainGap` has no test fields.

**What would close it.** Add a per-test list to `ExplainGap` (name, source location, and a reach
signal) ordered by reach then duration, sourced from the same coverage data `explain` already reads
for `reach`.

**Found by.** C02-09's own review of GitHub issue #11 (point 3), filed as a follow-up rather than
folded into this task's scope.

**Sized 2026-10-06 (R-276b): not small, left open.** What the report already holds: each mutant's
`coveringTests` and `reachedBy`, and `testFiles` (test codeunit to its file). What it does NOT hold:
a test method's LINE and a per-TEST duration (`durationMs` is per mutant). So "file:line" and "rank
by duration" need two new `SessionReport` fields, recorded at discovery and per test call, with the
full report ripple CLAUDE.md lists (events, report-fold, report builder, generated schemas, the
schemas and report-equality tests, and every committed sample report regenerated live). A reduced
version from today's data alone (each gap's covering tests with their FILE, ordered by how many of the
gap's members each reached) is possible, but it would not meet this item.

**Done 2026-10-06 (R-272b), with duration displayed, not a key.** The report gains `testMethods`
(each discovered test's file, the line of its name, and its smallest per-test baseline duration
measured in this run: al-runner's own figure, bcdev's per-call wall clock, never a resume-reused
or shared value). `lethal explain` gives each gap `coveringTests` and `reachMeasuredMembers`,
ordered by survivors reached, then `compareCodeUnits` name. Ranking by duration was ruled out for
now (orchestrator, option (a)): R197 measured baseline durations unstable between runs, so
measuring that is filed as R489. Pinned in `packages/runner/tests/r272-covering-tests.test.ts` and
the R272 test in `resume.test.ts`; red-checked. Known limits, left as stated: a test codeunit
renamed on disk and not republished, then `--resume`, makes explain refuse (named in the message);
the regex path's line count is linear per test. No sample report needed a live regeneration (both
fields are optional). Plan and reviews:
`docs/superpowers/plans/2026-10-06-R-272b-explain-covering-tests.md`.
