**Found 2026-10-06 by R-492's plan review** (`/coord/handoff/R-492/review-r1.md`, I1). R492 closed the
gap for env-tool (hook) sessions only.

**What.** A bcdev session WITHOUT an `afterLeaseAcquired` hook records `test_app_hash` from the
pre-lease `dev/packages` read (`testAppIdentity` / `reportPublishedTestApp`) and nothing proves that
version is the installed one. `checkInstalled`'s own comment (R-385 D2) says `dev/packages` can serve a
published-but-not-installed version (a staged upgrade, a publish without `-install`). The resume,
history and R192 snapshot sequences are then R492's: a run that measured P1 while P2 was served records
P2, and a later proven-P2 run can carry its verdicts or reuse its baseline (a false kill through a
test that is green under P1 and red under P2).

**Why separate.** The hook sessions' proof (`proveReadBack`) runs on the read-back after the hook. A
session without a hook has no read-back; it needs the same installed check on the pre-lease read,
and a decision on what an unproven read means for its digests and history. Not designed yet.

**To close.** Apply `checkInstalled` to the pre-lease read on a session without a hook; record NULL
(and so carry, skip and reuse nothing) when unproven; extend R492's `requireDigests` marker or add an
explicit proven flag. Red-check the same directions R492 does.
