**Found 2026-10-06 by R-492's plan review** (`/coord/handoff/R-492/review-r1.md`, I1). R492 closed the
gap for env-tool (hook) sessions only.

**What.** A bcdev session WITHOUT an `afterLeaseAcquired` hook records `test_app_hash` from the
pre-lease `dev/packages` read (`testAppIdentity` / `reportPublishedTestApp`) and nothing proves that
version is the installed one. `checkInstalled`'s own comment (R-385 D2) says `dev/packages` can serve a
published-but-not-installed version (a staged upgrade, a publish without `-install`). The resume,
history and R192 snapshot sequences are then R492's: a run that measured P1 while P2 was served records
P2, and a later proven-P2 run can carry its verdicts or reuse its baseline (a false kill through a
test that is green under P1 and red under P2).

**Cross-session paths, both directions (R492 final review, findings 1 and 2).** Hook and non-hook runs
share the backend name (`bcdev`) and the config fingerprint, and the snapshot lookup has no project or
backend filter, so each consumes the other's rows:
- a NON-hook session trusts an OLD hook row (recorded before R492: the served or pre-lease hash, NULL
  digests) through `--resume`/`--resume-run` (`assertSameTestApp`), `--skip-known-survivors` and R192
  snapshot reuse, because R492's digests marker is applied to hook sessions only;
- a HOOK session trusts a NON-hook row through all three, because a non-hook bcdev row usually HAS
  digests (taken pre-lease from the served package), which are no proof of the installed app there.

**Why separate.** The hook sessions' proof (`proveReadBack`) runs on the read-back after the hook. A
session without a hook has no read-back; it needs the same installed check on the pre-lease read,
and a decision on what an unproven read means for its digests and history. Not designed yet.

**To close.** Apply `checkInstalled` to the pre-lease read on a session without a hook; record NULL
(and so carry, skip and reuse nothing) when unproven. Replace R492's digests marker with an EXPLICIT
proven flag on the run row (written only behind `checkInstalled` / `proveReadBack`): digests prove the
installed app only on hook rows, so extending the digests marker to every consumer would let every
non-hook row through and close nothing. Every consumer (resume, history, snapshot) then requires the
flag. Pin both cross-session directions above with tests, and red-check the same directions R492 does.
