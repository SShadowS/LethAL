`R-458`; split off by orchestrator ruling: R458 takes only the hang refusal). Queued after R458.

Three parts of the engine each decide which record a bare or `Rec.`-qualified name binds to:

1. `receiver.ts`: the BARE forms (`claimsRecordMethod`, `resolveReceiverTable`, rule 3 of
   `claimsSystemCall`) know table, tableextension and page with `SourceTable`.
2. `receiver.ts` `resolveReceiver`, the QUALIFIED `Rec.` / `xRec.` form, knows table and
   tableextension only. So `Rec.Modify(true)` on a page is unresolved while `Modify(true)` on the
   same page is claimed: the two spellings of one call get different mutants.
3. `types.ts` `implicitRecordShadowsGlobals` (R294, measured with `alc`): page with `SourceTable`,
   pageextension, a TableNo codeunit's `OnRun`, report dataitems and request pages.

An `alc` 18.0.43 probe (R-458) measured the TableNo codeunit: `Rec` binds in `OnRun` only (AL0118
elsewhere) and `xRec` does not exist there (AL0161).

**Measured effect of one resolver** (R-458 r1 prototype, exact site diff against R-364, every node,
every operator, 0 exceptions; BaseApp, CDO, every other BC.History app, 21 fixture and example
projects): +2,914 Tier-2 specs (BaseApp 2,223), -236 `flip-boolean-literal` mutants ceded under
precedence, 3 of R-364's 8 `run-trigger` tags on unresolved receivers dropped by the shared
trigger-skip predicate (none in BaseApp). Fixtures and examples: no change.

**Requirements before it lands** (sol's review of r1):
- **Resolve an explicit `with` subject first.** A bare `Validate(Amount, 1)` inside `with R do` in
  a TableNo codeunit's `OnRun` validates `R.Amount`; claiming it through the implicit record makes
  `validate-to-assign` emit `Rec.Amount := 1`, a mutant of a different record. Refuse or resolve.
- **A replacement for every removed flip, per mutant.** Ceding a flip is right only where a Tier-2
  operator then emits a mutant at that site. `Rec.Insert(true, true)` loses both flips, but
  `swap-modify-flag` needs a sole argument, so nothing replaces them. Pair all 236 mechanically.
- **Emitted-text tests** for the new claims (the receiver in the generated text), not only
  claim/no-claim, plus red tests per direction; pageextension stays refused (R30/R67).
- **Its own `IDENTITY_SCHEME` bump**, separate from R458's.

**Related.** R460 (forcing `false` -> `true` flip on an unresolved receiver gets no
`run-trigger-forced` tag) belongs here: resolving the receiver changes which flips are tagged.
R458's hang refusal does not touch it.

**A fourth consumer: `lookupVar` lets a global outrank a field (measured 2026-10-05 under R-468).**
`receiver.ts`'s `lookupVar` (behind `claimsRecordMethod`, `receiverUnresolved`, the receiver-table
helpers, and `resolveVarRef`, which R196's hang check uses) has no implicit-record or `with` guard
at all. Where AL binds a bare name to a FIELD of the implicit record before a global, it binds the
global. Measured on master over BaseApp history (203 projects) and CDO, the scope list being
`implicitRecordShadowsGlobals`'s plus `with` bodies, each implicit table resolved by name over the
whole corpus: **39 BaseApp uses, 11 name+file pairs in 6 files**, where a global shares its name with
a field of the implicit record (`CDSNewManIntTableWizard.Page.al` `direction`;
`CopilotMarketingText.Page.al` `emphasis`, `textformat`; `JobQueueNotificationWizard.Page.al` seven
names, `threshold1` and `threshold2` being Integer globals against Decimal fields;
`QltyInspectionCopyTemplate.Report.al` `description`; `ShpfySuggestPayments.Report.al` `gateway`).
CDO: 0. 5,254 BaseApp and 154 CDO uses sit against an implicit table the corpus does not hold, so
they are unchecked, not clean. Evidence and scripts: the coord handoff `R-468`
(`measurement-r2.md`, `tools/b1.ts`, self-checked on a planted-clash project). Only `lookupVar`
users are exposed: `swap-call-arguments` and `swap-additive` type their arguments through
`types.ts`, which has the guards. R468's fix (every direct var section indexed) adds no such use.

**Do NOT copy `types.ts`'s guard into `lookupVar`.** That guard nulls EVERY global in a page with a
`SourceTable`, a TableNo `OnRun`, a dataitem or a `with` body, which is right for typing (a missed
type costs a site). In `lookupVar` it would make every global there unresolvable to the hang
check, so R196 would stop refusing loop-counter writes on pages and reports: the UNSAFE
direction, at scale. The guard `lookupVar` needs is precise: answer `null` (or the field) only
when the implicit record's table HAS a field of that name, which needs this item's one resolver
plus the fields index. **Before building, measure how many mutants the 39 uses move** (receiver
claims, tags, hang refusals), per mutant.
