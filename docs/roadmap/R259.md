id: "R259"
title: "lethal verify does not say whether a new test also kills other survivors in the same procedure (the overfitting signal, #16 requirement 4)"
section: "product-gaps"
status: "done (6bfc005b)"
order: 963
---

**What.** `runVerify` sends only the survivors named on the command line to `runNamedMutants`. A new
test that happens to kill some OTHER survivor in the same procedure, one nobody asked verify about,
gives no signal: verify only ever reports on the mutants it was told to check. There is no way from
`lethal verify`'s output to tell a test that kills precisely the targeted mutant apart from one broad
enough to kill everything nearby, which is the overfitting question #16 requirement 4 asks for.

**Ruling.** Orchestrator ruling 2 (2026-09-26): filed, not built, for C02-06. Flakiness (running each
new test twice on the unmutated build) was ruled IN; overfitting was ruled reportable only if cheap
from data already collected, and it is not, so it stays a filed gap.

**Evidence.** `runVerify` (`packages/runner/src/verify.ts`), which calls `runNamedMutants` with only
the named mutants; the ruling in
`docs/superpowers/plans/2026-09-26-C02-06-lethal-verify.md`.

**What would close it.** Running the new test against every other survivor in the same procedure (or
at least those already scored in the source run) and reporting which of them it also kills, as a
separate, non-gating field.

**Closed.** Verify schema v8 adds `results[].sameProcedure` on every row killed by a new test
(plan `docs/superpowers/plans/2026-10-05-R-259-also-kills-probe.md`). Siblings are the source
batch's other survived and no-coverage mutants in the same declaration, by the manifest's line
span (`declarationKeyOf`, `siblingsOf` in `packages/runner/src/verify.ts`). A pair the named
survivors' own runs prove is reused (`pairAnswerOf`); every other pair gets one run of the new
test alone, through `runNamedMutants`' `probe` hook, inside the same lease and R-384's budget
(`pairsToProbe`). Anything without a sound answer is `unknown`. Unit-tested only (verify.test.ts
"R259: sameProcedure", orchestrator.test.ts "R259: runNamedMutants' probes" and "R259:
sameProcedure probes through the covering loop"); no live gate has run a probe yet.
