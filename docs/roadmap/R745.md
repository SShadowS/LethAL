**Filed 2026-10-24 by lethal-preproc during R-740** (orchestrator ruling). Related: [[R740]], [[R738]].

**What.** [[R740]] refuses a run when a baseline test fails on a stale DEPENDENCY member ("The object with ID <id> does
not have a member with that ID" naming an object the project does not declare). Its remedy is to recompile the calling
app against the dependencies installed now. When the stale caller is an app the user cannot rebuild (a third-party test
library left stale by a platform update, say), the only way to run today is `--tests-only <glob>`, which limits the
baseline to whole test FILES (the report flags `tests-narrowed`). A test file that mixes such a test with good ones
cannot be split: either all of its tests run, so the run refuses again, or none do, and good coverage is lost.

**The gap.** There is no way to leave out one named test method (for example `--exclude-test "Codeunit.Method"`), with
the report naming what was left out and why.

**First user.** R740's refusal would name this flag as the way out for an unrebuildable caller, beside
`--tests-only`.

**Not before the release.** It is a new scope flag that can change verdicts (an excluded killing test), so it needs the
same `tests-narrowed`-style report flag and its own red tests.
