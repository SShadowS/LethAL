**Filed 2026-10-24 by lethal-preproc during R-740** (orchestrator ruling). Related: [[R740]], [[R738]].

**What.** [[R740]] refuses a run when a baseline test fails on a stale DEPENDENCY member ("The object with ID <id> does
not have a member with that ID" naming an object the project does not declare). Its remedy is to recompile the calling
app against the dependencies installed now. When the stale caller is an app the user cannot rebuild (a third-party test
library left stale by a platform update, say), the only way to run today is `--tests-only <glob>`, which limits the
baseline to whole test FILES (the report flags `tests-narrowed`). A test file that mixes such a test with good ones
cannot be split: either all of its tests run, so the run refuses again, or none do, and good coverage is lost.

**The gap.** There is no way to leave out one named test method (for example `--exclude-test "Codeunit.Method"`), with
the report naming what was left out and why.

**First user.** R740's refusal would name this flag as the way out for an unrebuildable caller, beside
`--tests-only`.

**Not before the release.** It is a new scope flag that can change verdicts (an excluded killing test), so it needs the
same `tests-narrowed`-style report flag and its own red tests.

**Done (f43a9308).** `--exclude-test <Codeunit.Method>` (repeatable, `lethal run` only, listed in `RUN_ONLY_FLAGS`, so
`campaign` and `verify` refuse it by name; an empty value and `--dry-run` are refused).
- One filter point: `runSession` applies `excludeNamedTests` (in `discovery.ts`) right after `chooseTestSuite`, so
  R403's membership check still reads the whole discovery, and everything after (the `useSessionTests` call,
  `tests-discovered`, the TestPage scan, `sessionTestScope`, the test-app identity) sees the filtered suite. A name
  is compared whole against `Codeunit.Method`, ignoring case and double quotes.
- A name that matches no test in THIS run's suite (after `--tests-only` and the arm filter) is refused after
  discovery and before the lease or any deploy, listing every unmatched name. An exclusion that empties the suite has
  its own refusal.
- al-runner-v3 refuses the flag by name before `status()`: it runs whole codeunits, so an excluded method would still
  run and could change what the kept tests see. bcdev runs one method per call, so an excluded test never executes.
- The resume fingerprint (`sessionFingerprint`) gets a conditional `excludeTests` key (sorted, only when non-empty,
  so every existing digest is unchanged). The history lend (`sessionTestScope`) comes from the filtered suite, so an
  exclusion run's survivors are not lent to a wider run, and a full run's survivors are lent to an exclusion run.
- Report: `ExcludedTestRecord.reason` gains `exclude-test`. Any such record raises `tests-narrowed` and narrows
  `reliability`; the banner prints a `TESTS EXCLUDED` line; the `tests-narrowed` interpretation names the flag and
  `excludedTests`; the warning `exclude-test-narrowed-baseline` names the tests. No new root field, no new caveat; the
  report-equality snapshot is unchanged. R740's `StaleDependencyMemberError` names `--exclude-test "<name>"` per test.
- Tests: `r745-exclude-test.test.ts` (each direction red-checked, outputs in `/coord/handoff/R-745/red/`).
- Not done here: `lethal verify` still re-discovers every test (filed as [[R759]]). The group-run path has no stub in
  the unit suite; it is covered by the live proof only.
- The live proof (R-740's probe on bc1, `scripts/r740-probe/drive.ts --step 3 --exclude-test "R740 Tests.TestLib"`) is
  pre-committed and is recorded after it runs.
