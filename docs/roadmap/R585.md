**Filed 2026-10-20 by R-557** (the final build review's minor 5; pre-existing, not R557's).

**What.** `ResultsStore.priorSurvivorKeys` takes the latest finished run of the project and refuses it
on the identity scheme, the coverage mode, the test app, the build symbols, the hidden files and (since
R557) al-runner test names. It never reads the run's `--tests-only` scope. A run scoped by `--tests-only`
ran only some of the suite, so a mutant it scored `survived` may be killed by a test it never ran (the
session's own warning says so: "A mutant whose killing test was excluded is reported SURVIVED"). A later
`--skip-known-survivors` session over the whole suite then skips that mutant as a known survivor, and its
report carries a survivor the full suite was never asked about. A false survive, carried forward on every
later history read.

**Not affected.** `--resume`: `resolveResume` compares `config_fingerprint`, which carries the
`--tests-only` patterns, so a resume across a scope change is refused by name.

**Fix direction.** Record the run's test scope (or reuse `config_fingerprint`'s test half) and refuse
history from a run whose test scope is narrower than, or unknown against, this session's, with a named
`history-*` warning like the others. A run with a WIDER test set than this session lends safely.
Red test per direction: a `--tests-only` run's survivor is not skipped by a full-suite session; a
full-suite run's survivor still is.

**Evidence.** `priorSurvivorKeys` and its `on` hooks in `packages/runner/src/store.ts`; the
`--tests-only` warning in `runSession` (`packages/runner/src/orchestrator.ts`).
