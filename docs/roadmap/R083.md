**Is `InherentPermissions` a better `PermissionReduce` target than `Permissions`? Unknown, and worth one measurement before anyone assumes either way.** R13 measured that `Permissions` is purely ADDITIVE — it grants indirect rights to code executing in the object (arm A5: BC’s demand moves from `Insert` to `IndirectInsert`), so reducing it is observable only in a session that already lacks the right, which is why `PermissionReduce`’s kill needs the rare permission-lowering test. `InherentPermissions` is a DIFFERENT property and the R13 decision explicitly does not cover it. **What is measured:** Continia Document Output carries **2** occurrences across 554 files, both on CODEUNITS and both `InherentPermissions = X` (zero on tables — consistent with R1’s note), and this repo’s own `fixtures/sandbox-probes` table 79200 carries `InherentPermissions = RIMD`. **What is NOT measured, and must not be assumed:** whether it can REFUSE an operation a SUPER session would otherwise be allowed — the claim that it constrains rather than grants comes from reading the AL compiler’s option list, not from any run, and an unmeasured platform claim written into this file is the exact failure R33 §2 records. Order of work: probe table 79200 through the fenced path with the property reduced and intact, THEN decide. Even a positive result leaves 2 sites on the one project censused, far below the >=13 bar — so this is a question to close cheaply, not a build.

---

**MEASURED 2026-08-08 against Cronus281 (BC 28.0.46665.49944), through the fenced `RunMutant` path.
Full arm table, design notes and reproduction in `scripts/r83-probe/README.md`. The answer is NO,
and the row's suspicion is measured FALSE.**

**Two facts the COMPILER settled before anything ran, and neither was in this row.**

```
error AL0776: The identifier 'tabledata' is not a valid permission value
    (on `InherentPermissions = tabledata Item = rm;`)
error AL0195: Invalid permission kind. Expected: 'X'
    (on `InherentPermissions = R;` — on a CODEUNIT)
```

`InherentPermissions` cannot name a table at all, and on a codeunit it accepts exactly one letter.
So **at a codeunit site there is nothing to weaken** — no smaller letter set, no table clause. The
only edit a `PermissionReduce` operator could make there is DELETION. That alone reshapes the
question this row asks, and it cost one compile to learn.

**It does NOT constrain — the claim this row flagged as unmeasured is now measured false.** Three
probe tables identical except for the declaration, each taking the same `Insert` from the same test
body in the same SUPER session: no property, `R`, and `RIMD`. **All three inserted.** Declaring
read-only did not stop an insert the session was otherwise allowed to perform. The no-property arm
succeeding is what makes that meaningful rather than vacuous: the calling-user gap that makes
`LethAL Control`'s own tables carry `InherentPermissions = RIMD` did not bite in this session, so
"permitted anyway" and "refused anyway" are distinguishable here and the result is the first.

**And at the real site shape it is INERT IN BOTH DIRECTIONS.** Under R13's lowered-session mode
(`TestPermissions = Disabled` plus `SetO365Basic()`), with the direct-write control correctly
refusing so the lowering is known to have taken:

| callee | result |
| --- | --- |
| `Permissions = tabledata Item = rm` | modified |
| `InherentPermissions = X` only | **refused** |
| no permission property at all | **refused**, same message |
| `Permissions = tabledata Item = rm` + `InherentPermissions = X` | modified |

`X`-only equals no-property, and grant-plus-`X` equals grant. It grants nothing about a table
operation and takes nothing away from a `Permissions` grant. **Deleting it at either of Document
Output's two real sites changes nothing observable**, so an operator targeting them would emit
guaranteed-equivalent mutants — worse than the >=13-site bar this row already said it would fail.

**No operator. R83 closes negative**, and it closes for a stronger reason than the footprint bar:
not "too few sites to pay" but "the mutation cannot change an outcome at the sites that exist".
