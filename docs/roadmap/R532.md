**Filed 2026-10-08 by the [[R500]] build** (plan r3 `/coord/reviews/R-500-plan/plan.r3.md`, shape 1). A plausible
hang that is NOT refused.

**What.** R500 shape 1 (a stated LIMIT, `writesPresetExitName` in `loop-hazard.ts`) refuses, outside open-item
code, the writes of a report global that an open item's exit or bound reads and open-item code never writes, the
guards around those writes, and an early exit before them. Two feeds are not seen. A value computed in another
object (`Continue := Mgt.ShouldContinue()`): the assignment and the call are refused, but the mutants INSIDE
`ShouldContinue` are not. And a value that reaches the global through another variable (`Tmp := ...; Continue :=
Tmp`, with the mutant on the first line).

**To close.** Census the indirect feeds of preset exit names on BC.History (R500 found 302 preset names, 2 of them
data hangs), read them, and refuse or close it with a ruling.

## Built 2026-10-10 (branch `lethal/r532`, coord task R-532; no scheme change, identity scheme stays 39)

Plan: `/coord/reviews/R-532-plan/plan.r1.md`, then `plan.r2.md` (overrides) and the review `adversary-r1.md`.
Measurement: `/coord/handoff/R-532/measure.md`. Build record and red checks: `/coord/handoff/R-532/build.md`.

**The same-scope part (B) is built.** In `loop-hazard.ts`, shape 1's `writes` predicate in `writesPresetExitName`
is now `directWrite || callsPresetWriter || isFeed`, so shape 1's existing walk refuses a FEED, the blocks
containing it, its guards and an early exit before it. There is no second walk. A feed (`presetFeeds`) is found in
the scope (a procedure, trigger or column) of a preset write outside open-item code. It is either:
- an assignment whose value flows by name, to a fixpoint, into the right side of an assignment to a preset exit
  name (R-531's `r531Feeds`, which for this caller also matches a target by its ROOT name, so `Arr[1] := X` feeds
  `Arr`, and collects the `#if` expression tails R480's `indirectFeeds` follows; R-531's own use is unchanged); or
- (plan r2 F1) a `directWrite` of a name read on the way, through the existing `argWritten`: a `var` argument
  (`Compute(Tmp)`), `Evaluate`/`Clear`, or an unknown callee (refused, as master's "unknown counts as a write").

The search also starts from every argument of a call in the scope that is itself a preset write
(`S := 'yes'; Evaluate(Continue, S)` refuses `S := 'yes'`) or that calls a same-object preset writer
(`Tmp := Limit > 55; SetContinue(Tmp)`, where `SetContinue` writes `Continue`, refuses the `Tmp` assignment and its
mutants). So a parameter fed from a call site in the SAME object is built (build review r1, finding 2).

Over-refusal, the safe direction: matching is by name, so a same-named variable written AFTER the preset write is
refused too (as in R-531's FEEDS). A feed in open-item code was already refused by R-501 and is not searched.

**Cost on BaseApp:** the prototype (assignment feeds only) measured -18 deployed, 0 added, 0 identity tuples, 0
ordinals (`measure.md`). The built rule is wider (F1 call feeds, root-name targets, `#if` tails); its cost is
re-measured on the built branch by lethal-code.

**Residual (not refused, stated).** A record method that changes what the preset write reads (`Buf.SetRange` or
`Buf.Insert` before `Continue := not Buf.IsEmpty()`); the other arguments of a call that writes a FEED rather than
a preset name (`S` in `Evaluate(Tmp, S)`); and every value that comes from another object, or from another
procedure other than through a same-object call's arguments (the ruling below).

## Ruling: the cross-object part

**"The cross-object part closed 2026-10-10 by ruling."** The census (`scripts/r532-preset-feed-census.ts`, parse
only, counts and names) found preset writes outside open-item code only in BaseApp (280 writes), Withholding Tax (2)
and Tests-TestLibraries (1). CDO, DC, DO, the fixtures and the examples have none. Withholding Tax and
Tests-TestLibraries reach only code outside their own project, which cannot be followed. Every BaseApp class, with
its count and why it is closed:

| class | writes | ruling |
|---|---:|---|
| A: a call into another project object | 34 | closed by ruling: the sample and the price (below) |
| A': a same-object `var` call | 14 | closed: mostly empty OnAfter event publishers, which write nothing; a real same-object writer is already a preset WRITER under R-555 |
| B-obj: a global written in another procedure of the same object | 24, split as `<B-obj-preset n> / <B-obj-other n>` (to be filled from the re-run census) | the census now splits this class in two. `B-obj-preset`: the global is itself a preset exit name, so shape 1 already refuses its write in the other procedure, and the widened B covers that write's own feeds. `B-obj-other`: the global is not a preset name. It is a cross-procedure feed and is NOT refused; closed by ruling with A's reason (the value crosses a procedure boundary, like a callee's) |
| P: a parameter fed from ANOTHER object's call sites | 78 (all parameters; the census does not tell the callers apart) | closed with A's reason: the value comes from a caller in another object, which is the cross-object call case. A parameter fed from a call site in the same object is built (above). The sample includes P-fed names (the setter pattern) |
| B: fed by assignments in the same scope | 3, plus the F1 widening | built (above) |

The remaining rows (calls that do not resolve to project code, 32 + 17; constants and `Clear`, 46; fields and
unwritten names, 32) have no project code to follow.

**Sample.** 15 sites were read by hand, drawn from ALL classes (about 11 cross-object or parameter-fed names and
3 B), not from the 34 A writes alone: 0 certain hangs, 0 plausible. Where a preset name gates a dataset item, each
gates only an OnPreDataItem Break, which can only skip an item that is bounded on its own (Number = const(1), a
finite Count, a table item). The rest filter an ordinary table item, end at end of file, or gate a loop that ends
through `Next`. Checked against BC.History beyond the sample: the FormatAddress-fed `ShowCustAddr` (Sales Shipment,
Service Shipment), `ShowShippingAddr` (Service Contract, Return Order Confirmation, Arch Sales Return Order) and the
purchase `ShipToAddr[1]`, each an OnPreDataItem Break on a `Number = const(1)` item; and `LineIsEmpty` in
PostedPhysInvtOrderDiff and PhysInvtOrderTest, the same shape as the sampled PhysInvtOrderDiffList.

**Price of A.** Refusing every followed callee would remove **321** BaseApp mutants (`measure.md`), mostly in
shared library code: FormatAddress 90 and ServiceFormatAddress 57 (reached through 22 document reports'
FormatAddressFields), PostedPhysInvtOrderDiff 76 and PhysInvtOrderDiffList 49 (EmptyLine), AccountSchedule 23, and
the PhysInvt order line tables 13 each. Refusing only the callee sites that affect the return value ("return-affecting
only") is NOT sound: it misses record state (a `SetRange` before a `Count`) and globals.

**Re-open when** a corpus loop with an EXIT OR BOUND that is a preset exit name fed indirectly (another object's
function, a parameter, or another variable) is found. Re-run `scripts/r532-preset-feed-census.ts` on each
BC.History or customer-corpus bump, and read any new A or P site whose item is not bounded on its own.
