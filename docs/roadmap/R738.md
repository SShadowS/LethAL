**Filed 2026-10-24 by lethal-preproc during R-728.** Evidence: `/coord/handoff/R-728/measure.md` (bc2 probe
`scripts/r728-probe/`). Related: [[R728]], [[R709]], R31 and R139 (`StaleTestAppError`).

**What was measured.** A target build that removes a procedure two installed dependents call was published through
LethAL's own deployer (`ContainerDeployer.publish`, altool, ForceSync). BC ACCEPTED it, installed the new target, and
left both dependents installed. Their calls then answered HTTP 400: "The object with ID ... does not have a member with
that ID".

**The risk (not yet measured through a run).** Every `lethal run` publishes the instrumented target over the installed
tests app, and publishing the tests app is the user's job. A user who removes or renames a target procedure and runs
before republishing the tests app gets an accepted publish and a tests app that is broken at run time. At the baseline,
each test that calls the removed member would FAIL or error, rather than answer the control app's "expected exactly
one method X, found 0" (the only text `describeStaleTestApp` reads). So `StaleTestAppError` would not fire. Those tests
would drop out of the green set, and every mutant they covered would read `no-coverage`: the silent under-report R31
and R139 exist to prevent.

**To close.**
1. Measure first, through a real test run under a pre-commitment: publish a target through the deployer that removes
   a member a test in the installed tests app calls, run that test's baseline through the control app (RunOneMethod,
   as a run does), and record the exact answer and how `runSession` classifies it.
2. If the baseline would drop the test from the green set without a named refusal, refuse it by name, for example by
   recognising "does not have a member with that ID" in a baseline failure as a stale tests app, with the recovery
   (republish the tests app built from the current source). Build it test-first, with a red test per direction (a
   genuinely failing test must still read as failing, not stale).

**Done 2026-10-24 by R-738 (lethal-preproc).** Evidence: `/coord/handoff/R-738/measure.md` (runs 1 and 2), probe
`scripts/r738-probe/`, pre-commitment `docs/superpowers/specs/2026-10-24-r738-stale-member-probe-precommitment.md`
(master 72650194, addendum 1 e4f9bc17).
- **Measured (run 1, a real `lethal run` on bc2):** the run's altool publish was accepted.
  - The test calling the REMOVED member and the test calling a member with a CHANGED SIGNATURE both failed at the
    baseline as ordinary test lines, with BC's "Function ID <n> was called. The object with ID 93790 does not have a
    member with that ID." (93790 is the target's codeunit).
  - The run did not refuse: exit 0, "score 100.0%". The stale tests were listed with the genuine failure under
    `unsupportedTests`, and the 3 mutants they covered read `no-coverage`.
- **Built:**
  - `staleTargetMember` (stale-test-app.ts) reads that sentence from the failure's first line, anchored at its measured
    start, and returns the object id only when it is one of the target's declared objects (`targetObjectIdsOf`:
    `objectHeadersOf` over the source snapshot, or over `alSources` on the named-mutants path; a file with no readable
    header is skipped).
  - `scoreBatch` then refuses with `StaleTargetMemberError`, after the found-0 refusal and before `select`. The error
    names the tests, the object, and the remedy (republish the tests app built against the current target).
- **Proved live (run 2, the built head):** the same run refused by name, exit 1, naming TestAnswer, TestScale and object
  93790 (not the genuine failure). No report was written and no mutant was scored.
- **Tests:** r738-stale-member.test.ts (6) and the orchestrator R738 describe (4).
  - Each is red-checked: a non-target object does not refuse, a genuine failure stays a failure, a quoted or near-miss
    wording does not match, and the call stack is never read.
  - A target with an interface and a permissionset still runs. This was a BLOCK the build review found: reading object
    ids aborted every such run.
  - The refusal precedes `select`: no `coverage-split` is emitted.
- **Limits:**
  - English text only.
  - The fenced (RunMutant) path's layout only; the line-count wrapper and the legacy hub path are not read.
  - A stale member of a DEPENDENCY app is [[R740]].
  - A target member added through a tableextension or pageextension, which BC may report by the base object's id, is
    [[R741]].
