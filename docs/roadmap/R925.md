Found by coord task R-916 (reading R-913's kills, 2026-11-11). Related: [[R121]] (the false-kill screen reads this text), [[R577]].

**What.** On the BC path, `run-mutant-transport.ts`'s `failureTextOf` joins al-runner's `message` and `stackTrace`, so a kill's
`killingTestFailure` names the frames. On al-runner v3, `v3RowVerdict` (al-runner-v3-backend.ts) builds `failureMessage` from
`row.message` only. One-shot's `--output-json` has a `stackTrace` per test (measured in R-902: Simplified Bank Statement Import's
failure came with `"Bank Statement File Wizard"(Page 8850).ReadBankFile line 32 - ...`). So every v3 kill in R-913's seven reports is a
message without a stack, and a reader cannot tell whether the killing test failed at or beyond the mutated statement, or in setup.

**Not known yet.** Whether serve-entries' `test` lines carry a stack too (its `--help` does not list the fields); measure first.

**Fix.** Keep `stackTrace` on v3 rows where al-runner gives it, and append it to the failure text as the BC path does. The gates read
`killingTest`, not the text, but R121's screen and the R-882-style kill comparisons read the text: pre-commit and check them.
