**Filed 2026-11-08 by lethal-bugs (coord task R-870).** Related: [[R151]], [[R868]].

**What.** An agent reading `lethal ... --json` got a different shape from each command, and a failure arrived as prose on stderr only. #27 asks for the bc-toolbox envelope, `@sshadows/bc-toolbox-envelope` 0.1.0: `{ schemaVersion: "1", status: "ok", data, warnings }`, or `status: "error"` with `{ code, category, message, retryable, details, nextSteps }`.

**Owner's ruling (2026-11-08, option A).** Wrap the existing documents as `data`; pre-release, so no fallback; the CHANGELOG states the break.

**What landed.**
- `lethal doctor --json` and `lethal campaign compare --json` print the envelope; their old documents are `data`. A failed check or a stage that differs is a result, so the status is "ok"; exit codes do not change.
- Under `--json`, any failure is also an error envelope on stdout, and stderr stays as it was: argv refused is `INVALID_ARGUMENT`; a config that cannot be read or used is `CONFIGURATION_ERROR`; an uncommitted stage pre-commitment is LethAL's own `UNCOMMITTED_PRECOMMITMENT`; anything else is `INTERNAL_ERROR`.
- The class rides on the error as a hidden property, so the error's name, text and the default stderr line do not move.
- The schema is vendored: `schemas/cli-envelope-v1.schema.json`, byte for byte, pinned by sha256. The package needs zod 4 and LethAL is on zod 3, so it is not a dependency.
- Without `--json`, stdout, stderr and the exit code were byte-identical to master on the three fixtures.

**Tests.** `r870-cli-envelope.test.ts` runs the real CLI as a child process on bad input, missing configuration and a failing check. Each one: the stdout envelope validates against the vendored schema, stderr matches the default run's, and the exit code is unchanged. The same three without `--json` are pinned. The validator covers exactly the schema's keywords, and a test refuses any keyword it does not know. `agent-contract.test.ts` pins the reference's error sample and its code table to the code.

**Not done.** `--json` on other subcommands (`explain` and `verify` already print JSON; `run` has `--out`): not asked, option C. The MCP `isError` body (`error-body.schema.json`) is for MCP servers; LethAL is a CLI.
