`generateMutationSet` drops every mutation spec whose `before` node is not inside executable AL —
`isMutableSite` returns false for an AL page/report/table property, which parses as a comparison
expression while being declarative and having no statement to wrap. The drop is correct. What
happens next is not: the count lands in a local `nonExecutableSites`, reaches exactly one
`warn(...)` line on stderr, and never reaches `SessionReport`.

So a reader of a report cannot tell a project with no declarative surface from one where LethAL
silently declined 154 sites. That is the same unassertable-warning shape R132 and R140 were about,
and it has the same two consequences: no gate can pin it, and a regression that changes what
`isMutableSite` drops moves no number anyone can see.

It matters more now than it did, because **[R135](R135.md) closed by RULING that LethAL does not
mutate declarative surfaces**, and that ruling was Option C: "refuse the class permanently **and say
so in the report**". The first half is done. This row is the second half, and without it the ruling
is a decision the product never communicates — the exact failure R69 avoided by making its three
unrecovered mutants visible in a gate rather than arguing about them.

What this asks for:

1. `SessionReport` carries the declarative-site count, and a caveat naming it, the way
   `notInstrumented` (R5) already carries files that cannot hold the guard. The two are siblings: one
   is "this FILE cannot carry the mechanism", the other is "this SITE cannot".
2. The count should be broken down enough to be actionable — at minimum by object kind or by file, so
   a reader can see whether the refusal touched anything they care about. A bare total invites the
   same "checked, and there was nothing" misreading an empty block would.
3. A `CAVEAT_INTERPRETATIONS` entry stating what the number MEANS: these are not mutants that
   survived, not mutants that went uncovered, and not a gap in the operator set. They are a surface
   LethAL's mechanism cannot reach, and R135's spec records the measurement behind that.
4. A gate assertion, so the number is pinned rather than admired. The table fixture is the natural
   home if it has such sites; if it has none, that zero is itself worth asserting, and adding a
   declarative site to the fixture is cheap.

Evidence: `nonExecutableSites` in `packages/runner/src/orchestrator.ts` (incremented at the
`isMutableSite` guard, consumed only by the `warn` below it),
`docs/superpowers/specs/2026-08-14-r135-declarative-mechanism-ruling.md` §5, and the 154 dropped
specs across 47 Document Output files that R40 measured when it first admitted pages.
