**Found by PR-327** while reproducing GitHub #53 (`/coord/handoff/PR-327/findings.md`). On bcdev (bc2, BC 28.4), with the
invented probe, a SingleInstance flag set by test codeunit A carries into test codeunit B. Three mutants of the reset
procedure `EndIt`, all leaking the same way:
- **M0009 (empty-block):** A then B; B failed. **Killed** by `ComputeIsPlain`.
- **M0010 (remove-assignment) and M0011 (flip-boolean-literal):** R197's ledger (`orderCoveringTests`) put B first,
  because B had killed in this scope. B passed, then A. **Survived.**
- The store's `test_results`, in id order, show it.

**Why it matters:**
- R197 was meant to change only the ORDER, a cost knob, and maybe `killingTest`. Here it changes the VERDICT.
- bcdev is the authoritative backend, so this is a false survivor where LethAL claims to be right.

**The fix to measure** (PR-327 (c)): the ledger may move a killer ahead only within its own test codeunit, never across
test codeunits. The codeunit order stays the manifest's, which is the order in which state could have been set. It is
measured red then green on the probe, and the DO verdicts the reordering could have touched are sized.
