Found by coord PR-67 (lethal-code, 2026-11-17), the DO pilot on `bc4` (BC 29). Evidence: `/coord/handoff/PR-67/before/`
(stderr, report), `/coord/handoff/PR-67/friction.md` item 11.

**What happened.**
- A `lethal run --backend bcdev` scoped with `--only` to one codeunit still runs the WHOLE test app at baseline: here 1,979 tests.
- One test unrelated to the scope, `CDO Azure Blob Folder Tests.Uniqueness_ThreeWayCollision_Errors`, never answered. The run
  printed "RunMutant timed out before headers" and "the server-side stop was attempted but BC never answered this request with its
  stop confirmation", and ended QUARANTINED: 0 mutants scored, after 1,077 s of baseline.
- The message ends "the control-app lease will read clean and must not be trusted until an NST restart (R658)".
- **The likely cause:** a real outbound HTTP call on a server with network access. The same test passed in al-runner v3's
  baseline.

**Why it matters to a user.** On a real suite, any one test that can wait on the network (or loop) costs the whole run. The user
learns it only after the baseline, and is then left with:
- a service-tier restart they must do outside LethAL;
- no printed next step (whether `lethal clear-quarantine` is needed after the restart, and with what arguments);
- no hint that `--tests-only` on the covering tests, or `--exclude-test`, would have avoided it.

**Possible fix.**
1. **On a quarantine, print the recovery steps:** restart the service tier, then the exact `lethal clear-quarantine ...` command
   for this tier, then rerun. Name the test that caused it, and suggest `--exclude-test <Codeunit.Method>` for it.
2. **Before the run** (`--dry-run` and `doctor --tests`): list test codeunits that can make real outbound HTTP calls (no
   `TestHttpRequestPolicy = BlockOutboundRequests`; any `HttpClient` use reachable from them). One such test can hang a whole
   baseline.
3. **When `--only` narrows the target far below the suite,** suggest `--tests-only` over the covering tests, if a coverage source
   exists (for example an earlier al-runner v3 run). The scope stays the user's call, since `--tests-only` can change a verdict.

**More hangs (coord PR-68, lethal-code, 2026-11-18, bc4).** Two more bcdev baselines over DO's suite were quarantined. Evidence:
`/coord/handoff/PR-68/friction.md`.
- **The full arm** (105 test files, 1,839 tests) hung on `CDO ABS Auth Settings Tests.ApplyAuthSettings_EarlyValidationFails_SecretsUntouched`,
  an Azure test (18 HTTP or Azure references in its file). The same 105 files had passed a baseline 20 minutes earlier, so it is
  intermittent.
- **The changed arm** (101 files, 1,786 tests, every Azure file left out) hung on
  `StaleExpiryUpgrade_ClearsOnlyTheCurrentCompany` in `CDODataUpgradeTests`. That file makes **no** HTTP, Azure or storage call.
- **So fix 2 alone cannot cover baseline hangs:** a check for tests that can make outbound HTTP calls would not have caught the
  third. A hang with no network in it needs fix 3 (run only the covering tests), or a per-test baseline budget that ends the hung
  test and leaves it out instead of quarantining the run. Its cause is unknown.
- Each quarantine cost an owner restart (sql then bc, an in-memory database) and a full republish.

**BC's default TestHttpRequestPolicy, measured (coord PR-176, lethal-bugs, 2026-11-19, bc3, BC 28.4).** Evidence:
`/coord/handoff/PR-176/result.md`, `http/bc3.json`. An invented pair made one `HttpClient.Get` to a loopback address under each
setting, on the dev-endpoint test runner:
- **No policy set:** the request goes out; `Send` returns false with "the connecting endpoint violates security requirements"
  (BC's own endpoint check refused the loopback address; a real external host would be contacted). Word for word the same as
  `AllowAllOutboundRequests`.
- **`BlockOutboundRequests`**, and **`AllowOutboundFromHandler` with no handler:** an error before sending ("Unhandled outbound
  HTTP requests are not permitted when the TestHttpRequestPolicy property is set to '...'").
- al-runner v3 (edge-4ebfe7913) gives the same four texts.
- **So fix 2 is needed:** a test codeunit with no policy that reaches `HttpClient` makes a real call on BC.
