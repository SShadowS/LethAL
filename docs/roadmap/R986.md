**Found by** R-965 (2026-11-14), running the `coverage-differential` leg on `bc3` with `--config fixtures/sandbox-app/lethal.config.bc3.json`.

**What.** `scripts/probe-r58-differential.ts` builds its `HarnessVerifier` and activation config from `odataBaseUrl(bcdev.server, bcdev.serverInstance)`, which forces port 7048. Since R589 the servers' OData roots differ (`bc1` 7048, `bc2` 7148, `bc3` 7248), and every bcdev itest uses `configuredOdataBaseUrl` (the config's `baseUrl` when it names one). So on `bc2` or `bc3` the probe deploys through the configured dev endpoint but asks `bc1`'s control app for its session lease, its harness checks and its activations: a run that mixes two servers.

**Seen.** On `bc3` the probe's `AcquireLease` was refused six times with `operation-busy`, holder `...:lease-itest:p9b`: the `itest:lease` gate running on `bc1` at the same time, under R-965's own `bc1` lease. Nothing was published (the refusal came first). With `bc1` idle the probe would have taken `bc1`'s control lease and activated mutants there while its app sat on `bc3`, with no lease of `bc1` behind it.

**Also.** It reads `.vscode/launch.local.json` only, not the `launch.<server>.json` the setup script writes; that file supplies only optional fields today.

**Workaround.** Run the leg on `bc1` only, whose OData is on 7048.

**To close.** Use `configuredOdataBaseUrl(bcdev)` in the probe (the one derivation the itests use), with a test that a config naming `baseUrl` on another port reaches that port; read the launch file the config's server names.
