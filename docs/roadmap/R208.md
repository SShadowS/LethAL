**What was missing.** `docs/superpowers/specs/2026-09-03-r198-run-mutant-loop.md` §7 and §8 pinned
two forced-chunk campaigns as if a gate ran them; none did. Every live gate ran each mutant's
covering tests in ONE call, so `--max-methods-per-call` was exercised by a differential UNIT test
only.

**Why it mattered under R206.** The warm confirmation replays the prefix of the CALL that produced
the failure (`chunkPrefix`), never the prefix of `ordered`. Unchunked the two lists are identical,
so no gate could tell them apart; chunked they differ, and a replay built from `ordered` would run
a different session's worth of tests than the mutated call did.

**Closed by `packages/runner/itest/chunked.itest.ts`** (`bun run itest:chunked`,
`LETHAL_ITEST_CHUNKED=1`). Two legs over the same narrowed slice, one unbounded and one at
`--max-methods-per-call 2`. The slice is `--only src/DataMain.Table.al`, the only file in the
fixture whose kills reach ordered position 5; everything else has one or two covering tests, where
chunking at 2 changes nothing. 46 s per leg.

Every number was pre-committed in
`docs/superpowers/specs/2026-09-04-r208-chunked-gate-precommitment.md` BEFORE the chunked leg had
ever run: the unbounded leg was measured, and the chunked leg derived from it mechanically. All of
them held on the first live run.

- **Unbounded (control):** 17 killed / 7 survived / 2 no-coverage, 0 errors, `warmKills` **9**,
  `groupedCalls` **33**, positions 8·1 3·2 3·3 2·4 1·5.
- **Chunked at 2:** every verdict and every `killingTest` IDENTICAL, `warmKills` **5**,
  `groupedCalls` **57**. Four of the control's warm kills go COLD (their killer heads its chunk:
  M0011, M0012, M0017, M0020) and five stay warm at chunk position 2, each replaying exactly its
  chunk's two methods.
- M0015 and M0016 are the rows the gate is built around: killer at ordered position 4, so the
  control replays four methods and the chunked leg must replay chunk 2's two — lists that start at
  a different test.

**Red-checked, not assumed** (mutate `coveringRuns`, run the gate, restore):

- Taking BOTH `groupPosition` and `chunkPrefix` from `ordered` — the coherent form of the bug this
  row names — is caught here and nowhere else: `warmKills` 9 not 5, `groupedCalls` 61 not 57, while
  **the verdict differential still passed**. The bug moves no verdict, which is exactly why an
  unchunked gate cannot see it.
- Taking only `chunkPrefix` from `ordered` never reaches the gate's assertions: `confirmWarm`'s own
  caller-contract check rejects it first, by name. The gate's doc comment said the replay-list
  assertion stopped that variant; it does not, and the comment now says so. What that assertion
  does pin is the residue the contract check cannot see (right length, right last element, wrong
  start) and the CONTENT of a replay, which nothing else in the repo pins.

**Not closed by this:** the gate runs at `--max-methods-per-call 2` on one file. A cap that
interacts with the server's headroom cap (a chunk that answers `cap` mid-walk and continues) is
still only unit-covered; run 4 on the sandbox exercised 108 such continuations live but pins none.
