**Filed and fixed 2026-10-24 by lethal-preproc during R-741.** Evidence: `/coord/handoff/R-741/measure.md` (run 1,
bc2), probe `scripts/r741-probe/`. Related: [[R738]], [[R740]], [[R741]].

**What was measured.** BC's stale-member sentence carries a SIGNED function id. In R-741's run, the stale page member
failed with "Function ID -935096164 was called. The object with ID 93861 does not have a member with that ID." The
shared anchor in `stale-test-app.ts` (`STALE_MEMBER`, used by both `staleTargetMember` and `staleDependencyMember`)
read only `Function ID \d+`, so the minus sign defeated it. That test was left as an ordinary failure. The run still
refused, but only because the OTHER stale member (the table's) carried a positive id. A run whose only stale members
have negative ids would have exited 0, with those tests out of the green set and their mutants `no-coverage`: R738's
silent under-report, for target and dependency members alike.

**Who was exposed.** Every R738 and R740 user, since those refusals landed. Their live proofs saw positive ids only:
R738's runs saw 1933812373 and 1105190687, and R740's saw 1425126407. The id is very likely a hash of the member: the
same `Answer()` gave 1933812373 in both R738's and R741's probes. So whether a given member's id is negative is fixed
by its name or signature, not by chance per run. How large a share of real members is negative is not measured.

**Receipts searched (never source).** Committed reports and docs, and `/coord/handoff`, were searched for "Function ID
-<n> was called". The only hits are R-741's own run, and one in `docs/superpowers/specs/2026-08-28-alrunner-bc-parity-probe.md`:
an al-runner (not BC) failure, `NavNCLMissingMethodException: Function ID -1626256597 was called.`, whose first line
starts with the exception name. That is outside the layout the anchor reads, and it is not a LethAL run.

**Fixed.** The anchor reads `Function ID -?\d+ was called`: an optional minus sign directly before the digits, nothing
looser. Tests: `r749-negative-function-id.test.ts` (3), plus two orchestrator tests: a negative id on a target object
refuses as R738's, and on a non-target object as R740's. Red-checked: each goes red with the old `\d+`, and the
near-miss test goes red with a looser sign (`[-+ ]*`).
