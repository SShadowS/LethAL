Found by coord task R-927 (2026-11-11), sampling on al-runner v3 three BC.History apps that build since the probing path became
the Windows BC service folder ([[R900]]). Pre-commitment `docs/superpowers/specs/2026-11-11-r927-dotnet-unblocked-v3-precommitment.md`.
Evidence: `/coord/handoff/R-927/findings.md`. Related: [[R918]], [[R895]].

**What.** Two al-runner differences make Microsoft's own tests, which Microsoft ships as passing, fail or refuse on v3. Each test
lost is coverage lost, so mutants it would reach read `no-coverage`:
- **#7811** (https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7811): `SetValue` on a `TestPage` opened with `OpenNew()` fails with "already exists" when the page's `OnOpenPage` inserted
  the blank record into its temporary source table. 22 of the 47 tests in Email - SMTP Connector's `SMTP Account Auth Tests` (every
  `SMTP Account Wizard` test after the first) fail in the baseline this way.
- **#7812** (https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7812): `JsonToken.ReadFrom` and `JsonObject.ReadFrom` return false for a raw TAB inside a JSON string. Sales Lines
  Suggestions' test install routine imports a JSONL dataset with such lines, so all 18 tests that depend on it are refused.

Both repros are invented and run on edge-42af5d384; neither was run on a BC server (the BC side rests on Microsoft shipping these
tests as passing).

**To close.** Both fixed upstream and the two samples re-run with the same seed: the 22 and the 18 tests in the baseline, and the
mutants they reach scored.

**Re-checked (coord R-981, 2026-11-14, edge-736fc7677).** Both issues are closed upstream; both invented repros pass on
edge-736fc7677 and fail on edge-42af5d384.
- **#7811: fixed.** Email - SMTP Connector's tests run directly on al-runner (one-shot, `--isolation test`): no "SMTP Account already
  exists" failure is left (4 on edge-42af5d384), 18 failed instead of 40. 14 of the 18 are `The TestPage is already open` in
  `SMTP Account Auth Tests`, a cascade: that codeunit's two TestPages are globals, and a test that fails (4 OAuth / Azure AD tests,
  present on both builds) leaves one open; one such test run alone passes. The LethAL sample run was not repeated: R-927's package
  folder is gone.
- **#7812: fixed for TAB only.** Sales Lines Suggestions' 18 tests are still refused at install, now for another raw control
  character. A per-file bisect of the install found the line: the import reads each dataset line with `NavApp.GetResource` (no
  encoding) and `InStream.ReadText`, which on al-runner gives one character per byte, so a line with CJK text holds U+0015, and
  `JsonObject.ReadFrom` refuses a raw U+0015 (or U+001F) in a string as it did TAB. Commented with an invented repro on the closed
  issue: https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/7812#issuecomment-6873926933. Not measured on BC whether BC
  decodes the resource differently or accepts the character.
This item stays open until the SLS install runs on v3.
