**Filed 2026-11-05 by lethal-preproc, from coord task R-803.** Related: [[R803]], [[R612]], [[R705]].

Both are speed or noise, not verdicts. Neither has been changed.

**1. The `http` entry of `V3_SERVE_SAFE_REFUSALS` is too narrow.** Its regex expects "an outbound HTTP request with no
[HttpClientHandler] bound to the test". Alpha.7 and alpha.12 write "an outbound HTTP request that a test handler does
not answer: the runtime never opens a connection (ADR-027). To run the test, bind an [HttpClientHandler] ..." (leg C,
`refusal-row-shape-public`, in the alpha.12 `gate.log`). So a project whose tests hit that refusal closes the serve
daemon where it could stay warm, and a warm-up that hits it falls back to one-shot.
- The safe direction today: the daemon closes.
- **Do not just widen the regex.** The list widens only by probe (R612): a new entry needs a measurement that the
  daemon is correct and warm after that row.

**2. `serve-keep-reasons` reads `diverged` on every alpha.7 gate.** `.gated` stores `"warnFacts":
{"serve-keep-reasons": "diverged"}`. The reading is `commit: MOVED pass` and `onrun-failed: MOVED no row`, because
`SERVE_CASES` still expects both as refusals. It is a WARN fact and never refuses. But a standing `diverged` hides a
real move in the same fact, and two entries are no longer exercised on these builds.
- To fix: key the expectation by the pin, or re-probe so that each entry has a row on the build in use.
- It changes a gate reading, so it needs a regate. Wait for R-807, which is moving the pins.
