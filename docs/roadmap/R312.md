**Found by the R-303 plan's own measurement (2026-09-28), Task 0** of
`docs/superpowers/plans/2026-09-28-R-303-latch-placement-split-var.md`. A second defect in the same
area as [[R303]], distinct from it: R303 is a member whose var section is WHOLLY inside `#if`
(`preproc_conditional_var_block` between the header and the body, no plain `var_section` on the
member at all). This item is the shape R303 calls INBODY: a plain `var_section` IS present, but its
LAST declared child is a `preproc_conditional_var` (an `#if` arm of declarations sitting inside the
already-open `var` block, right before `end` of that section).

**The mechanism.** `injectReachLatches` (`packages/schemata/src/compile.ts`) finds the member's last
declaration, `lastDecl`, and appends ` <latch>: Boolean;` at `lastDecl.endIndex`. When `lastDecl` is
a `preproc_conditional_var`, that node's own end IS the `#endif` line (the conditional declaration
node spans from its `#if`/`#elif`/`#else` line through the matching `#endif`). The emission lands
literally on the directive line: `#endif LethALReachLatch: Boolean;`. `alc` reads `#endif` as a
complete preprocessor line and rejects anything trailing it.

**Measured through the real pipeline** (`generateMutationSet` + `writeInstrumentedProject` +
`injectControlDependency`, Control 1.0.0.20 staged), on a hand-written repro (`procedure
Pick(X: Integer): Integer`, `var`, `#if not CLEAN27`, `K: Integer;`, `#endif`, body with an `if`):

| repro | alc, CLEAN27 absent | alc, CLEAN27 defined |
| --- | --- | --- |
| INBODY-only, HEAD `a513df8` | FAIL `AL0631: Single-line comment or end-of-line expected.` | FAIL, same |
| plain var section (harness control) | PASS (exit 0, `.app`) | PASS |

The un-instrumented source compiles under both symbol sets; the failure is LethAL's, under every
symbol subset, not just one build.

**Census** (parse-only, `preproc_conditional_var` as the last child of a member's `var_body`,
"INBODY with `#if` as the LAST var child"): DC/Cloud 40, System Application 1, BusinessFoundation 0,
BaseApp 11 (parse-only, two-half census; exploratory, not a claim about instrumenting or compiling
whole BaseApp, which stays blocked on [[R311]]). Zero in every `fixtures/*` project (all `preproc_*`
node counts are zero there per R-297 Task 0's census), which is why no gate has ever seen this.

**Why R-297's corpus proof did not catch it.** That proof measured that instrumentation COMPLETES
over whole real corpora (parses, selects sites, writes files, builds a manifest); it never ran `alc`
on the corpus emission afterward. This defect only shows up at compile time, one directive line
past where instrumentation itself succeeds silently.

**Not the same code path as R303's refusal.** `reachLatchRefusedOwner` refuses a member with NO
plain `var_section` at all; a member here HAS one, so that refusal never triggers and the latch is
still emitted, on the wrong line.

**Reproduce.** `procedure Pick(X: Integer): Integer`, then `var` / `K: Integer;` /
`#if not SYM` / `L: Integer;` / `#endif`, then a body with a statement-grain site (an `if`).
Instrument, compile under both `SYM` absent and `SYM` defined: both fail `AL0631`.

**What would close it.** The R-303 plan's placement rule (hoist the latch onto the member's header
line, blank the arm's own `var` keyword) covers this INBODY shape as well as R303's BLOCK shape,
since both are cases where the injector's normal "append after the last declaration" anchor lands
inside or at the end of a directive rather than after a plain declaration line.
