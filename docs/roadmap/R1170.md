**The owner's goal** (R1168, confirmed in q-20261121T211549-6b0d2540) is to run tests in the session kind the project's CI
uses. For DO that is a client session (`GuiAllowed` true).

**Measured so far, all on R910Win** (Windows BC 28.4 with a web server, now removed):
- **PR-308:**
  - `Run-TestsInBcContainer` runs tests in a client session through `/cs` (`GuiAllowed=Yes`, `ClientType=Web`), and a
    bound ConfirmHandler fires.
  - LethAL's instrumented build runs normally there.
  - Each call costs about 7.25 s, nearly all fixed.
  - `-testCodeunit` alone silently ran 0 tests; it needs `-extensionId`, and 0 tests must count as a failure.
- **PR-313:** LethAL Control's `LC Control State` is SingleInstance and loads the active mutant once per session
  (`EnsureLoaded`).
  - A second mutant activated over OData is NOT seen by a client session that already read the first, not even in a
    later test codeunit.
  - A fresh session sees it.
- **PR-314:** a probe-only patched control app (branch `lethal/pr-314`, 1.0.0.29, never on bc1-bc4) adds a `Generation`
  counter that the guard checks.
  - With it, the guard sees M2 in the same session, and ONE kept client session (`New-ClientContext` + `Run-Tests
    -clientContext`) served 5 of 5 mutants.
  - Per mutant: `Run-Tests` about 3.5 s (the Test Tool page's own work), activation about 0.05 s; the session open is
    0.33 s, paid once.
  - The generation check costs about 4 µs per guard call.

**What a build needs:**
- **(1) A per-mutant activation reload in the control app.** PR-314's generation counter works and is cheap enough to
  check on every guard call.
  - It must not weaken the OData path's fail-closed rule (`ResetAttestationState` leaves a blank cache on purpose), and a
    review must check that.
- **(2) The attestation in a table** (`ObservedActive`, `NoteReached`, `TestMethodRuns`), because the client session is not
  the OData session that reads the answer.
- **(3) A client-session driver** (a `ClientContext` sidecar kept open per lane), fenced by the lease, with a stop for a
  hung client session.
  - The cost to beat is the Test Tool page's own work, about 3.5 s per `Run-Tests`. Driving page 130455 directly, and
    keeping it open, may cut it.
- **(4) A BC with a web server.** bc1-bc4 (BC on Linux) have none, which makes it an infrastructure decision for the owner
  and kraken.
- **(5) Gate baselines** recorded in the new mode, since every BC gate today is headless.
