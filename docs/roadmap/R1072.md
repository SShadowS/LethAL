**Keep entries.** 66 new `V3_SERVE_SAFE_REFUSALS` entries (48 exact, 18 bounded patterns), plus two measured exception types in
`dotnet-exception`.
- A pattern's `*` stands for the measured variants only: FieldRef Active/Caption/Class, RecordRef FilterGroup, the Company and
  Power BI reads. A free slot is used only for an object id, a name or a filter: one line, no `\r`, length-bounded.
- The texts R945 keeps closing as never measured close still (`FieldRef.Value`, `RecordRef.Get`, `CopyLinks`, `ReadPermission`).
- Pinned against the 127 measured texts, and against the ledger: a key matched by an entry belongs to that entry's class.
- No leg C case: most of these refusals need the .NET helper or a platform table.

**Drift guard** (`al-runner-v3-backend.ts`). After a request that held a kept refusal, the next request on that daemon compares
two kinds of row with the batch baseline: NONE rows, and mutant-entry rows of tests that run before the first covering test.
Skipped: alone confirms, timeout rows, and an answer cut at a timeout. On a difference it:
- closes the daemon;
- re-runs the request on a fresh daemon, without counting it twice;
- emits `serve-drift-after-kept-refusal`, with the `keptDrifts` counter.

**Open (before any inversion):**
- the guard checks the next request only, not later entries of the same request;
- a kept refusal in the warm-up or a coverage window does not arm it.

**Expected:** DO saves about 15.6k s over t1-t8's pattern, and the guard fires 0 times in the next window.

**Measured in t9 (PR-74):** the guard fired once, and falsely. After the kept number-sequence cascade, the next request gave a
red test (`fail` in the baseline) a refusal row instead. The fresh daemon reproduced the same row, so no state was carried.
**The false-fire class:** the comparison row is a BASELINE FAIL. A red test's coverage stops where it fails, so a mutant past
that point can change its row without counting as covering. Ruling (orchestrator, 2026-11-16): keep the guard as it is. A false
fire costs one re-run; skipping baseline-fail rows would also hide a fail-to-pass flip caused by carried state. Evidence:
`/coord/handoff/R-984/t9.run.events.ndjson`, seq 33330-33333; R1078.
