**Found by** PR-429's build review and spec review (lethal-code, 2026-11-25). Evidence:
`docs/superpowers/specs/2026-11-25-pr429-loop-cursor-hang-refusals.md`, `/coord/handoff/PR-429/result.md`. Each gap
costs a timeout on a live run, never a wrong verdict: a hang is caught as `timeout-killed`, or by the hung-session stop
on bcdev.

- **(1) An end test below an outer `or`/`and`.**
  - In `until (R.Next() = 0) or A or B` the grammar groups `((N or A) or B)`. Flipping the OUTER `or` to `and` gives
    `(N or A) and B`, which repeats the last record while `B` is false.
  - The same happens in `until A or (B or (R.Next() = 0))`.
  - Rule 1(b) refuses a logical expression only when the `Next` comparison is a DIRECT operand, so these flips stay
    scored.
- **(2) A paren-less `R.Next = 0`.** AL allows calling a method without parentheses. `r429Next` needs a call node, so
  rule 1 and the "loop over R" test both miss this form (`r696Next` has the same limit).
- **(3) A removed filter call before a self-inserting loop** (PR-427's M2284, scored `error` on al-runner).
  - The mutant removes a filter-setting call on the loop's record before a loop that walks that record and inserts into
    the same table. Without the filter, the walk can meet the rows it inserts and grow forever.
  - A narrow rule needs the table the loop inserts into, as `altersSelfInsertFilter` does for some shapes. That check
    does not reach this one.
- **The fix to decide:** extend rule 1(b) to an end test at any depth below a same-direction chain; accept a paren-less
  `Next`; and widen the self-insert filter check to M2284's shape. Each needs a red check on invented AL, and a DO reach
  diff like PR-429's.
