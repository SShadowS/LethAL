`negate-conditional` claims `comparison_expression` (flipping `=` <-> `<>`) and `logical_expression`
(`and` <-> `or`). `conditional-boundary` shifts `<` to `<=`. `remove-not` strips a `not` that is
already written. A condition that is none of those falls through all three, and nothing else mutates
a condition at all:

```al
if Rec.Get(No) then Rec.Delete();      // no mutant on the guard
if GiftCard.Blocked then Error(...);   // no mutant on the guard
if SkipValidation then ...             // no mutant on the guard
```

**Measured on `do-rel2/Cloud`** (Continia Document Output, 554 `.al` files), counting `if` / `while`
/ `repeat until` conditions inside `procedure` or `trigger_declaration` bodies:

| branch / condition shape | total | has polarity mutant | gap | MARGINAL |
| --- | ---: | ---: | ---: | ---: |
| `if` / `comparison_expression` | 1,110 | 1,110 | 0 | 0 |
| `if` / `call_expression` | 1,068 | 0 | 1,068 | **949** |
| `if` / `unary_expression` | 862 | 847 | 15 | 13 |
| `if` / `identifier` | 620 | 0 | 620 | **620** |
| `if` / `logical_expression` | 370 | 370 | 0 | 0 |
| `if` / `member_expression` | 252 | 0 | 252 | **252** |
| `if` / `quoted_identifier` | 27 | 0 | 27 | 27 |
| `if` / `parenthesized_expression` | 67 | 49 | 18 | 17 |
| `if` / `in_expression` | 13 | 0 | 13 | 13 |
| loops (`while` / `repeat`) | 367 | 361 | 6 | 4 |
| **TOTAL** | **4,756** | 2,737 | **2,019** | **1,895** |

`if` guards alone: **4,389 total, 2,013 with no polarity mutant, 1,891 MARGINAL** — marginal meaning
no operator claims ANY site inside the condition, so the mutant would be additive rather than a
second mutant on a span that already has one. That is the number [[R13]]'s bar of 13 applies to,
and it clears it by 145x. The 4,389 independently matches the `if_statement` count
`census-node-kind-coverage.ts` recorded for the same corpus in [[R159]], which is the cross-check
that this census counts the population that row counted.

**The loop case is deliberately separated and is NOT the proposition.** Negating a loop-exit
condition is [[R164]]'s hang risk. It barely intersects: only 6 of the 2,019 uncovered conditions are
loop conditions, because the canonical `until Next() = 0` is comparison-shaped and already claimed.

**Why this one does not collapse under scoping.** [[R162]] records the pattern that a raw ceiling
falls one to two orders of magnitude once scoped to what a source-derived layer can reason about
(2,472 -> 65 there, 394 -> 49 for [[R165]], 1,121 -> 100 for [[R159]]). This candidate has no such
scoping step: AL requires the condition of `if` to be Boolean-typed, so `not (<condition>)` is
well-typed for every one of these sites by construction, with no symbol resolution, no receiver
typing and no enum lookup. The raw number and the reachable number are the same number. If that
turns out to be wrong the spike is where it should surface, and this paragraph is the claim to
attack.

**Why it is worth more than the count suggests.** `empty-block` already deletes the guarded body, so
[[R159]]'s "the gap is in DISCRIMINATION, not reach" objection has to be answered rather than
assumed. It is answered here: deleting the body tests whether the body matters. Flipping the guard
runs the body when it must not run and skips it when it must, which is the failure a wrong guard
actually causes. On `if Rec.Get(No) then Rec.Delete();` the two mutants ask different questions, and
only the flip asks whether any test covers the not-found path.

**A second, smaller finding from the same census.** 15 `if` guards are `not (<parenthesized>)` where
`remove-not` refuses the operand and nothing inside is a comparison or a logical expression, so no
operator claims the polarity. Twelve are `not (<expr> in [<set>])` and three are
`not (<member expression>)`; 13 of the 15 are marginal. `remove-not` refuses a parenthesized operand
deliberately and its own doc comment says why: `not (A = B)` is "ceded to `negate-conditional`". The
cession is correct for comparisons and silently wrong for everything else, because
`negate-conditional` does not claim `in_expression`. So the two operators each assume the other
covers it. At 13 marginal sites this sits exactly on [[R13]]'s bar, and the fix is a predicate
change rather than a new operator.

A methodology note, because it nearly went into this row as a wrong number. A scratch probe that
RE-IMPLEMENTED `remove-not`'s operand predicate reported 153 such sites rather than 15, because it
matched the raw string `"field_access"` while `ALNodeKind.field_access` is actually
`"member_expression"` — so it counted 120 sites the operator does claim. `census-branch-conditions.ts`
calls `op.targets()` and `op.generate()` directly and was right. This is [[R120]]'s hazard in
miniature: the curated enum is a mapping, not an identity, and any census that restates an
operator's predicate instead of asking it can be wrong with no type error anywhere.

**What a fix looks like:** one Tier-1 operator that wraps a non-comparison, non-logical `if`
condition in `not (...)`, refusing loop conditions so it cannot manufacture [[R164]]'s hang. Then
close the cession seam by letting `remove-not` strip a parenthesized operand when the inner
expression is not a comparison, or by teaching `negate-conditional` `in_expression`. Both need the
usual live pre-commitment: predict every verdict on a fixture arm before running it.

**The instrument.** `scripts/census-branch-conditions.ts` is per-DECISION-POINT operator coverage,
and it is the falsifiable form of the question that prompted this row. The tempting form, comparing
mutant COUNT against cyclomatic complexity, is not falsifiable in a useful way: measured across this
repo's own fixtures, complexity and mutant count correlate at only r=0.48 and just 6.1% of mutants
(20 of 330) are decision-flavoured at all, because most operators fire on statements and call sites.
75 of 94 fixture procedures have complexity 1 and still carry up to 7 mutants each. Count tracks how
much code there is. Only per-site coverage says whether a decision can be tested.

**SPIKED 2026-08-20. Recommendation: build it.**
Full evidence in [`docs/superpowers/specs/2026-08-20-r171-negate-guard-spike.md`](../superpowers/specs/2026-08-20-r171-negate-guard-spike.md).

`lethal.negate-guard` claims **1,998 sites, 1,878 marginal** after ceding `unary_expression` to
`remove-not` and refusing loop conditions outright. Hazards are small: 12 empty-`then` guards
(equivalent by inspection), 20 guards inside loops whose branch exits (R164's cost by another route),
0 symmetric `if/else`, 0 degenerate replacements.

**Compile-proven twice**, because once is a different question: 11 of 11 shapes compile as a naive
splice, and the INSTRUMENTED artifact compiles with 0 errors through `writeInstrumentedProject`
alongside every shipped operator, with the probe refusing to report a pass unless it can find and
print the emitted dispatch. That second check is the one `swap-multiplicative` failed.

**All six live verdicts matched pre-commitment**, on two fixtures, with both killing-test names
predicted by name on `sandbox-data`. The load-bearing one is D4, which answers [[R159]]'s standing
"discrimination, not reach" objection by measurement: at `src/DataOps.Codeunit.al` lines 91-92, under
the SAME covering test, R161's branch-slot mutant that deletes the body SURVIVES (the branch never
executes) while this operator's guard flip is KILLED (the branch now executes when it must not).
Same statement, same test, opposite verdicts.

**Not registered in this commit.** Doing so moves `itest:tables` from 246 to 250 deployed (266 -> 270
raw, verdicts 201/34/11 -> 204/34/12) and the gift-card demo from 43 to 45 (26/11/8, 70.3%), each
needing a re-freeze. Both new figures are already measured and pre-committed, so the build is
mechanical.

**The seam fix was measured and then REVERTED, deliberately.** Ceding only the inner kinds
`negate-conditional` actually claims takes `remove-not` from 1,106 to 1,121 corpus sites, exactly the
15 predicted, with the `not (A = B)` and `not (A and B)` controls still refused and pinned by two new
conformance cases. But it adds ZERO sites on every fixture, so nothing would notice if it broke,
which is [[R56]]'s shape. It should land together with a `sandbox-data` arm carrying
`not (<expr> in [<set>])`, not on its own.

**BUILT 2026-08-20.** Both halves landed, with the fixture arm the spike said the seam needed.

`itest:tables` re-frozen at **213 / 34 / 12 over 259 deployed** (279 raw), the demo at **45**
(26/11/8, 70.3%). Thirteen new mutants, all thirteen pre-committed in
[`2026-08-20-r171-build-precommitment.md`](../superpowers/specs/2026-08-20-r171-build-precommitment.md)
and all thirteen matching, including `totalMutantSites` which that document deliberately declined to
predict and read from the run.

`itest:bcdev`, `itest:alrunner` and `itest:hang` were not re-run: `negate-guard` claims zero sites in
`sandbox-app` and `sandbox-hang`, measured before the build rather than assumed after it.

What remains open is [[R170]]'s convention question, which is unrelated, and the equivalent-mutant
class the spike named: 12 empty-`then` guards on the measured corpus are equivalent by inspection and
no Tier-1 operator detects that.
