Found by the spec-adversary review of coord PR-180's design (lethal-code, 2026-11-18). Spec:
`docs/superpowers/specs/2026-11-18-pr180-bcdev-client-workdate.md` §2.5. Related: [[R1127]].

**What.** After PR-180, the control app sets each test's start WorkDate to BaseApp's `GetDefaultWorkDate()`. In a demo
company that is the last G/L entry's posting date, read again on every call. Before, the start date was Today, which moves only
at midnight.

**A failing sequence.**
1. The baseline runs with last G/L date D1.
2. Something posts in the same company during the run: a user in a shared sandbox, another client of an envtool environment,
   or a job queue entry or background session that commits outside test isolation.
3. Later mutant calls start on D2.

**What it costs.**
- Kill confirmations re-run unmutated under D2, so a kill that rests on the date becomes `unstable` (an error), not a false
  kill.
- But kills are lost without a stated cause, and survivors are measured on a date the baseline never used.
- No answer and no report shows which date any call started from.

**To close.**
1. Each control-app answer returns the start `workDate` it set, next to `sessionId`.
2. The client refuses a mutant or confirm answer whose date differs from the baseline's, as an error with a named cause, never a
   verdict.
3. The report records the baseline's date. This also catches the midnight change of a non-demo company.
