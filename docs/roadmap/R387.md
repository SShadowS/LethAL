**Reported 2026-10-01 by an outside user (al-runner's author), confirmed by reading.** On a small app,
one pass of `lethal run` with the al-runner backend took 30 to 40 minutes, while al-runner alone ran
the same suite in about 5 seconds.

With no flags or config, every slow choice is the default:
- **One-shot, not `--server`.** `serverMode` is off unless the config sets `alRunner.serverMode`
  (`packages/runner/src/al-runner-backend.ts`, the `serverMode` doc; `cli.ts`, the `AlRunnerBackend`
  construction). There is no CLI flag.
- **Static selector.** `selectorMode()` falls back to `"static"`, which bakes the mutant id into AL
  and recompiles per mutant. `"resource"` (R222) is reachable only by code that builds the backend
  directly; only `packages/runner/itest/al-runner.itest.ts` does. A CLI user cannot turn it on.
- **No coverage.** `coverage` falls back to `"none"`, so every mutant runs every green test. The CLI
  never sets `coverage: "al-runner"` (R220), so this is also unreachable from the CLI.

Measured costs, from R222 on a 553-file app: the static selector through `--server` costs 69.3 s per
mutant; the resource selector costs 24.9 s, about 11.7 s at the margin after one cold compile. On the
2-file fixture: 137 s one-shot, 31 s server, 20 s server plus resource.

**What to do:**
1. Give `selectorMode` and `coverage` a config surface (and CLI flags if the CLI has a pattern for
   backend options).
2. Decide the defaults. Making them fast changes verdicts in two places, and both need a
   pre-commitment and the al-runner gate per mutant: coverage turns an unreached mutant from
   `survived` into `no-coverage`, and coverage is refused for a run holding a multi-object file (R383).
   `--server` and `resource` are already gated to equal the one-shot verdicts per mutant, so those two
   are the safer defaults to flip first.
3. Until then, `lethal run` should say once, on an al-runner run with the slow defaults, which
   settings would make it faster.

The owner said on 2026-10-01 that making these the default is work in progress. Check before starting
that this is not already being built.
