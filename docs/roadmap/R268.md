---
id: "R268"
title: "`lethal verify` refuses a test app whose symbol cache holds a Ready-to-Run Microsoft package (no root NavxManifest.xml)"
section: "correctness-risks"
status: "done (63d381e)"
order: 968
---

**What.** `compileTestApp` reads every package in the test project's `.alpackages` to learn its app
id, so it can drop stale copies of the target and of LethAL Control from the scratch symbol cache
(`identityOf`, `readAppIdentity` in `packages/runner/src/published-test-app.ts`). A package without a
root `NavxManifest.xml` is refused as `symbols-unreadable`, on purpose. But Microsoft now ships some
packages as Ready-to-Run wrappers: the outer zip holds `readytorunappmanifest.json` (with an
`EmbeddedAppId`) and an embedded inner `.app`, and the INNER package carries the manifest. `alc`
accepts these packages. On this machine every Microsoft `*_28.0.46665.50383` build found is a wrapper
(for example `Microsoft_Test Runner_28.0.46665.50383.app`); the `*_47126` builds are plain.

**Who hits it.** Any test project whose `.alpackages` holds such a package: `lethal verify` exits 6
before it measures anything, and its test-app publish path cannot run. `sandbox-harden-tests`,
`sandbox-data-tests` and `sandbox-hang-tests` all hold one; only `sandbox-tests` (no Test Runner) had
been through `compileTestApp` before.

**Found by.** C02-08's first live `itest:agreement` run on Cronus28 (2026-09-26): verify refused
`symbols-unreadable` on the scratch copy of `fixtures/sandbox-harden-tests`, and the gate's restore
compile of the committed suite was refused the same way. Nothing was published; `itest:harden`
passed right after.

**What would close it.** When a package has no root `NavxManifest.xml` but has
`readytorunappmanifest.json`, read the embedded `.app` it names and take the identity from the inner
manifest, cross-checked against `EmbeddedAppId`; anything else still refuses. Pin it with wrapper
packages built in the test-app-publish tests (inner id is the target: excluded; unrelated id: staged;
inner file missing: still refused), red-checked by reverting the fallback.
