Found by PR-94's spec-adversary (2026-11-16), building on R1094 (excludeTests hides rows but still runs the tests).

**Mechanism (by reading code; not yet measured end to end).**
- v3 runs every `[Test]` of a codeunit entry unless the request carries `runSelectedOnly`. It filters the left-out rows before
  streaming them (R1094).
- LethAL's daemon-close rule (R612, `serveDaemonReusable`; the close loop in `requestOne`) reads only the rows it receives.
- So a left-out test that is refused, or that hangs, on a state the mutant or an earlier test left, runs on the daemon unseen.
  The daemon is then reused, although R612 would have closed it had the row been visible.

**Where it applies today:**
- the warm-up: R1004 leaves unkept-refusal tests out, possibly in the middle of a codeunit, and `judgeWarmup` passes on the
  visible rows;
- gapped entries (#8059's kept names);
- the serve coverage windows' `leaveOut` (`plain()`, from `leftOutNames`);
- every L4 tail before PR-94.

R998's and R1004's reasoning ("would only leave a daemon R612 cannot reuse") assumed the left-out tests do not run.

**Why it is not a false-kill door:** a kill still needs R653's unmutated (NONE) confirm and R577's reproduction under the
mutant. Persistent dirt fails the confirm, and passing dirt fails the reproduction. **What it may cause:** wrong SURVIVORS, where
a reused daemon's state hides a fail. Not measured.

**To measure first:** a probe with a hidden unkept refusal (a left-out test that is refused and leaves state), followed by a
reader request on the same daemon. Compare it with the reader on a fresh daemon.

**Possible fix:** run left-out tests not at all where a prefix allows it (`runSelectedOnly`, as PR-94 does for L4 cuts). Where a
gap remains, close the daemon after any request that left out a test known to refuse. Or ask upstream for the hidden rows'
status to be streamed.

**To close.** The probe's result, then either the fix with a per-mutant proof, or a measured reason the reuse is harmless.
