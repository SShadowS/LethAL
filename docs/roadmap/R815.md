**Filed 2026-11-05 from coord task R-808.** Related: [[R808]], [[R586]].

**What breaks.** On one-shot, `callCodeunit` throws `AlRunnerV3SelectionError` when v3 exits 6
(`if (res.exitCode === 6) throw ...` in `al-runner-v3-backend.ts`). That throw dates from R-586, when exit 6 meant "the
selection matched no test". Since #5859, alpha.12 (R807) gives no row at all for a test codeunit whose OnRun raises, and
exits 6 with "NOTHING SELECTED". So a mutant that makes a test codeunit's OnRun fail now stops the whole one-shot session,
and the stop names the wrong cause ("selected no test").

- **No verdict is at risk.** Nothing is scored. But the session is lost, and a user reads a wrong cause.
- **Under serve-entries** the same mutant reads `error` through `rowMissing` (R808 addendum 2).
- **Measured** by the review of R-808, on the scratch fixture `r808-review/or/` (a mutant that makes OnRun fail, one-shot).

**Proposed fix (not built).** Under a mutant (`lane.lastActivated !== null`) route exit 6 through `rowMissing`, so the mutant
reads `error` as under serve-entries. Keep the throw for unmutated calls, where "selected no test" is a real baseline stop.
Needs a red-checked test for each direction.

**Fixed (coord task R-817).** The proposal above was not quite enough: a baseline with a failing OnRun is not "selected no
test" either. v3's own words tell the two exit 6 cases apart (measured on alpha.12 and alpha.13+edge, `/coord/handoff/R-817/`):

| Case | v3's stderr | What LethAL does |
|---|---|---|
| A selection miss (no such codeunit, or no tests in it) | `error: the selection matches no test` | Stops, `AlRunnerV3SelectionError`, as before |
| It ran and gave no row (a raising OnRun, since #5859), mutant active | `Result: NOTHING SELECTED (exit 6)` | That mutant reads `error`, and the session goes on |
| The same, unmutated (the baseline) | the same | Stops, `AlRunnerV3NoTestRanError` (`al-runner-v3-codeunit-ran-no-test`), naming OnRun; no verdict is scored |
| Any other text | | Stops as a selection miss, so nothing is guessed |

`exit6Kind` holds the rule. If upstream rewords these lines, the fallback is the old stop, with the old wrong cause: never a
wrong verdict.

**Live on alpha.13+edge, one-shot** (`/coord/handoff/R-817/`, the gift card with one added test codeunit):
- OnRun raises on the unmutated build: `baseline.run.log`, exit 1, the new name.
- OnRun raises only under a mutant: `mutant.report.json`, exit 0, 3 mutants read `error`, and the other 60 read 34 killed,
  15 survived, 11 no-coverage, as on the plain gift card.

**Not changed:** under serve-entries a baseline with a failing OnRun still stops through `rowMissing`, by that error's name.
No figure moved, and the R-808 pin that such a mutant is never `survived` holds on both transports.
