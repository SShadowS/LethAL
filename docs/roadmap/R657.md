**Filed 2026-10-22 by lethal-preproc** during the R-654 inventory (`/coord/handoff/R-654/inventory.md`), and
confirmed by reading the code. Related: [[R553]], [[R654]], [[R586]].

**What.** `report.ts` picks the screen's message rule from the backend kind:
`screenBackend = caps.kind === "al-runner" ? "al-runner" : "bcdev"`. An `al-runner-v3` run therefore takes
bcdev's rule. `screenMessageOf` strips no leading `<Type>: ` prefix, and the `vacuous` note's al-runner check is
skipped.

**Why it matters.** R553 measured that v2 writes every failure as `{Type.Name}: {Message}`. Read unstripped, that
form made the screen flag 51 of 51 kills as `vacuous`, where bcdev flagged 3. Nobody has measured v3's (Rust)
failure-message shape. If v3 also prefixes its messages, its assertion-screen figures are skewed the same way.
These are report figures only: verdicts are not touched.

**To close.**
- Measure v3's `killingTestFailure` text on the sandbox fixture (a plain `Error()`, an `Assert` failure, a
  runtime error).
- Then either give v3 its own `screenMessageOf` branch or record that bcdev's rule fits it.
- A test per backend kind.
- Fold this into [[R654]] if that change touches the screen.
