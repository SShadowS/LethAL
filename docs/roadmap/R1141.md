Found by coord PR-204 (lethal-bugs, 2026-11-19), y3: the first full DO run with the recheck on by default (PR-182).
Evidence: `/coord/handoff/PR-204/scoring-draft.md` and `y3.run.events.ndjson` (`mutant-rechecked`, `recheck-baseline-finished`).

**What happened.** The recheck re-ran all 516 of y3's withheld kills under method isolation (one test per session), within its
budget, and recovered 409. Of the 107 it kept as error:
- **96 by rule (e)** (`withheld-recheck.ts`: every test of the killing test's codeunit that passed in the main baseline must pass
  alone in the recheck baseline): the recheck baseline "lost" ONE test, `CDO Variant Setup UI Tests.
  U_CopyCriteriaFromLine_TakesTheCriteriaOfThePickedLine` (codeunit 68984). It is `pass` in y3's main baseline and `fail` in the
  recheck's.
- 10 by rule (b) (no row for the mutant); 1 whose own recheck verdict was error.
None is counted as a kill: the rule fails closed, as designed. But one test blocks 96 recoveries, so the score loses up to 96
kills to it.

**Why it matters.** Rule (e) protects against a kill that depends on another test's state. If this test is order-dependent (it
needs an earlier test of its codeunit to run first), rule (e) is right to stop, and the 96 are honestly error. If it is an
al-runner difference between batched and alone runs, or a fixture effect (a TestPage test alone), the 96 are lost kills.
PR-170 (bc4) also met this codeunit: 9 of its not-measured rows had a `CDO Variant Setup UI Tests` killer that bcdev skips as a
TestPage test.

**Measure first (offline, on `current`):**
1. Run the test alone, then its whole codeunit, then the codeunit's earlier tests followed by it, on al-runner v3 (DO's build, no
   mutant). Fails alone and passes after a named earlier test = order dependence (DO's, rule (e) is right). Passes alone = the
   recheck's session differs from a plain run (LethAL's or al-runner's; an invented repro if al-runner's).
2. Compare with PR-170's 9 rows: same codeunit and the same cause, or not.
Then decide: leave rule (e) as it is, or let rule (e) ignore a test whose own baseline status is order-dependent in a way the
killing test does not share. Build nothing before the measurement.

## Measured (2026-11-19, lethal-bugs, PR-204)

Evidence: `/coord/handoff/PR-204/r1141.ts`, `r1141.out.ndjson`. Al-runner `current` (edge-4ebfe7913), the instrumented DO build
PR-195 and PR-214 checked against, no mutant (`NONE`), y2/y3's daemon flags. Each scenario ran on its own fresh daemon.

| scenario | request | the test |
|---|---|---|
| alone (the recheck baseline's call) | one test, codeunit isolation, `runSelectedOnly` | **fail**: `Assert.IsTrue failed. The overlap warning should name the Line No. whose criteria were checked` |
| whole codeunit, test isolation (the main baseline's mode) | 42 tests | pass |
| whole codeunit, codeunit isolation | 42 tests | pass |
| its 17 earlier tests, then it | prefix cut | pass |
| the same, without the refused `U_TestMatchDocument_NamesTheLineThatWouldBeUsed` | 16 earlier tests, then it | pass |
| the refused test, then it | 2 tests | error (`NotRun`: an earlier test of this codeunit was refused) |

**Cause: an order dependence in DO's own test.** The test's copy raises an overlap message. Its `OverlapMessageHandler` checks the
message against two codeunit globals, `ExpectedCheckedLineNoTxt` and `ExpectedOverlapLineNoTxt`. This test never sets them;
earlier tests of the codeunit do (`U_CopyLineFromThePart_CopiesContentAndCriteriaThroughTheDialog` and
`U_CopyLineDialogAddsACriterion_UsesTheSameWizard`), and `Initialize()` does not reset them. Run alone, both are empty, `StrPos`
returns 0, and the handler's assertion fails. BC keeps a test codeunit's globals between its tests the same way, so this is DO's
behaviour, not al-runner's. No upstream report is due. The refused `GoToKey` test is not the cause: the prefix without it passes.

**Rule (e) works as written.** It saw a real order dependence in the codeunit and failed closed.

**What it costs.** The 96 mutants' withheld failures are spread over 22 tests of the codeunit. This test is one of them in only
10 of the 96. Every one of the 96 had its failure withheld because it ran after a refused test: 92 after
`U_TestMatchDocument_NamesTheLineThatWouldBeUsed`, 4 after `U_TryItOut_ComparisonOnAFlowField_JudgesTheDocumentValue`. Rule (e)
judges the killer's whole codeunit, so one order-dependent test blocks the kills of all 22.

**PR-170's 9 rows are a different cause.** They are in the same codeunit, but their killers are other tests, which bcdev skips as
TestPage tests (`no-coverage` on BC). That is not an order dependence.

**For a ruling (build nothing yet).** Should rule (e) stay codeunit-wide? A narrower rule could ignore a codeunit test that
fails alone when the killing test itself passes alone, with no mutant, in the recheck baseline (rule (c) already reads that). The
risk to weigh: the killing test may depend on state from the same earlier tests the order-dependent one needs, and pass alone
only because it does not assert on that state. Up to 96 kills on DO ride on the answer.
