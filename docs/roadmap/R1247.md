**Found by** lethal-preproc on PR-479 (2026-11-28), reading bcwin's event log (kraken's capture,
`/coord/handoff/PR-479/wedge-1413/eventlog-1215Z-1231Z.txt`).

- **What:** each LethAL publish of an instrumented target logs a pair of warnings: "COMMIT called and skipped in
  extension upgrade context", from `"LC Control State".RegisterArtifact` (it ends with `Commit()`), called from the
  emitted `"Mutation Upgrade".OnUpgradePerCompany` (schemata `selector.ts`; 79397 in Sandbox Data, 79197 in Sandbox
  App). Six publishes between 12:19Z and 12:27Z gave 12 warnings, one pair each.
- **Why it is harmless today:** BC skips the Commit in upgrade context, and the registration still lands when the
  upgrade's own transaction commits. Every gate passes with it, and table 2's publish logged the same before bcwin's
  OData stall (R1244), so it is not that stall's cause.
- **Why it is filed:** it is a platform-deprecated pattern on every LethAL publish, on every server. A BC that turns
  the skip into an error would fail every publish.
- **The fix shape:** a Commit-free registration for the upgrade and install triggers (the triggers' transaction
  commits it). It changes every emitted selector, so every emitted golden moves and every gate needs a re-check.
  Not in PR-479 (orchestrator ruling, 2026-11-28).
- **Related:** R1244, PR-479.
