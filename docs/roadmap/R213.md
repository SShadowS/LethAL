**Where this came from.** GitHub issue #4, from the author of al-runner, proposing that
`swap-modify-flag` (which claims `Modify`, `Insert` and `Delete` through `RUN_TRIGGER_METHODS`) be
extended to AL's two other run-trigger methods. He was explicit that it was a candidate rather than
a request, because R13 prices an operator against marginal sites and he had no site count. This row
is that count.

**Measured 2026-09-08** on both reference corpora, using `claimsRecordMethod` (the same predicate
`swap-modify-flag` itself claims with, so the number is what the operator would actually see, not a
text match) and reading each call's trailing argument:

| corpus | `DeleteAll` on a resolved Record | of those, trailing `true` | `ModifyAll` on a resolved Record | of those, trailing `true` |
| --- | ---: | ---: | ---: | ---: |
| `do-rel2/Cloud` (554 files) | 84 | **6** | 78 | **23** |
| `do-lethal-53470/Cloud` (572 files) | 110 | **9** | 69 | **23** |

**Against R13's bar of 13 marginal sites: `ModifyAll` clears it on both corpora, `DeleteAll` does
not.** The reporter's own guess was the other way round ("my guess is that `DeleteAll(true)` is rare
in application code and `ModifyAll` rarer"), which is worth recording as one more case where the
measurement and the plausible expectation disagreed.

**So the ruling is to build one of the two, not both, and it is the harder one.** `DeleteAll` is the
one whose shape matches the existing three exactly, which makes it the tempting one to add; it is
also the one that does not earn its place. `ModifyAll` is the one worth building and it carries the
difference the reporter named: its run-trigger argument is the THIRD, not the first, so the
argument-position logic is not shared with `Modify`/`Insert`/`Delete` and cannot be reused by adding
one entry to `RUN_TRIGGER_METHODS`.

**What is NOT measured here, and would decide it properly.** The counts above are claimable SITES,
not marginal ones. R13's bar is about sites no other operator already reaches, and these have not
been differenced against the rest of the operator set: `flip-boolean-literal` claims a boolean
literal in an argument list and would already reach the `true` in `ModifyAll(F, V, true)` unless it
cedes, exactly as it cedes `Modify`/`Insert`/`Delete` through `CEDED_TO_MODIFY_FLAG`. So the real
marginal count could be near zero, with the operator's value being the cession it forces rather than
new sites. That question has to be answered before building, and answering it is most of the work.

**Probe.** `bun scripts/probe-r13-deleteall.ts`, committed alongside this row so the number is
reproducible rather than quoted.

Also relevant: `swap-modify-flag`'s existing `Insert` arm carries a `PlatformKillMechanism` tag
([[R138]], narrowed by [[R143]]) because skipping an insert trigger can kill through a duplicate
primary key with nothing asserted. A `ModifyAll` arm needs the same question asked of it rather than
inherited.

**Closed 2026-10-05 by ruling: the measurement above was wrong.** The probe counted a `ModifyAll`
as a RunTrigger site when its LAST argument was `true`. In `Rec.ModifyAll("Field", true)` that `true`
is the VALUE; RunTrigger is the THIRD argument (`DeleteAll`'s is its first, which the probe had
right). So the "23" on both CDO corpora were all two-argument calls. Recounted with
`claimsRecordMethod` and an argument count, 2026-10-05:

| corpus | `ModifyAll(F,V,true)` | of those, table has `OnModify` | `ModifyAll(F,V,false)` | `ModifyAll(F,V)` | forward candidates (table declared here, has `OnModify`) | `DeleteAll(true)` | `DeleteAll(false)` | `DeleteAll()` |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| CDO Cloud (554 files) | **0** | 0 | 0 | 78 | 0 | 6 | 0 | 78 |
| CDO Cloud + Test (658) | **0** | 0 | 0 | 80 | 0 | 13 | 32 | 195 |
| BaseApp Source (8098) | 37 | 17 | 10 | 544 | 186 | 314 | 4 | 2131 |
| BaseApp Source + Test (9707) | 175 | 91 | 13 | 843 | 287 | 695 | 22 | 5257 |
| every `fixtures/*`, `examples/*` | **0** | - | 0 | 0 | 0 | 0 | 2 | 4 |

The ruling is not to build. CDO, R13's calibration corpus, has no three-argument `true` site. Where
they exist (BaseApp), `flip-boolean-literal` already flips the third-argument `true` (it cedes only
`Modify`, `Insert` and `Delete`), and under R13's grain after [[R181]] the edit
`ModifyAll(F, V, true)` to `(F, V, false)` is the same bytes-to-same-bytes edit. Extending
`swap-modify-flag` would add zero mutants, only relabel them, and cost an identity scheme bump.
`DeleteAll` stays excluded. The forward direction (a new edit) is filed as [[R451]]; the question of
tagging a skipped `OnModify` as [[R452]]. The probe script `scripts/probe-r13-deleteall.ts` is fixed
(it reads the RunTrigger position through `scripts/lib/run-trigger-flag.ts`) and pinned by
`scripts/lib/run-trigger-flag.test.ts`.
