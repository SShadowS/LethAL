**Filed by R-731** (2026-10-24). [[R734]] isolates breaking mutants by halving, one culprit at a time, under a compile
budget (`MAX_ISOLATION_COMPILES = 64`). With k culprits among n mutants that costs about k * (log2 n + 2) compiles,
so 30 culprits on DC is about 540, far over the budget. Past the budget the rest stays `error`, which is correct but
loses the verdicts.

**Cause.** The halving search ignored what alc said. alc prints the line of each error, and the emitted file shows
which mutant's branch holds that line.

**Design (4c4cfb0e).**
- `parseAlcErrors` moved from `scripts/r315-dc-compile.ts` into `packages/runner/src/bisect.ts` (the script re-exports
  it). `guardGoverning(text, line)` returns the mutant id of the dispatch branch that holds a line: the nearest
  `.Active('M...')` guard at or above it. An error ON a guard line is the previous branch's (alc reports a missing
  token on the next line), so the scan starts one line up. The `else` branch (the original text) reads as the last
  member: a wrong pointer that costs one compile and blames nobody.
- `isolateBreakingMutants`: `compile` may now answer `true`, `false`, or an array of the mutants alc pointed at (a
  failure with suspects). Each suspect is compiled ALONE before anything else; one that fails alone is a culprit, one
  that compiles is cleared and never tried alone again (it may still be half of a pair). After each culprit the
  rest is recompiled and alc's new diagnostics give the next suspects. With no suspects the search is R734's
  halving, unchanged. Suspects run before the early stop, which guards only halving. The budget, the empty-set
  check and the pair logic are untouched. A suspect is never blamed without its own failing singleton compile.
- `isolateAndNote` reads each diagnostic's file from the scratch directory INSIDE the compile callback (it holds
  the subset only until the next candidate is written), by basename (batch files are written flat, R219), and maps
  the line with `guardGoverning`. A diagnostic that maps to nothing (no guard, unreadable file, id outside the
  subset) is dropped. Notes are byte-identical to R734's.
- The start warning no longer says every culprit costs log2(n)+2. A new `compile-isolation-result` warning per
  isolated batch reads `batch B: isolation used N of 64 compile-only runs: K culprit(s), G in pairs, U unresolved`
  (event only, no SessionReport field).
- `scripts/r315-dc-compile.ts --isolate <bad> [--keep <n>]` runs the real `isolateAndNote` on a corpus thinned to
  `--keep` specs (default 2000) with `<bad>` of them corrupted at a fixed stride, alternating a syntax fault and a
  binding fault (AL0118), through a compile check shaped like bcdev's.

**Cost.** About 2 compiles per breaking mutant when alc points right, plus 3 (empty set, full set, final
recompile). A diagnostic that cascades onto innocent mutants costs one singleton compile each. A syntax error can
hide a binding error until the first is removed, which costs one more round.

**DC figures** (corpus: DC Cloud, 117947 specs; symbols from `r315-dc-symbols`; 2000 specs kept; each run isolated
exactly the injected sites, no pairs, nothing unresolved). Evidence: `/coord/handoff/R-735/dc/`.

| Run | Compiles | culpritSitesEqualInjected | groupErrors | unresolved | wallMs |
|---|---|---|---|---|---|
| `--isolate 2` | 6 | true | 0 | 0 | 106674 |
| `--isolate 30` | 34 | true | 0 | 0 | 612214 |

R734's halving would have needed about 540 compiles for 30. The 2-culprit run used 6, not 5: the syntax fault hid the
binding fault in the first full compile, so the second culprit came from the recompile's diagnostics.
