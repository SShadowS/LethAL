**Found while designing the autonomous issue orchestrator**
(`docs/superpowers/specs/2026-09-13-issue-orchestrator-design.md`), by an adversarial review from
gpt-5.6-sol comparing each existing subagent against the job it was about to be given.

`.claude/agents/al-compiler.md`'s `Locate alc` step locates the compiler with:

```bash
ALC=$(ls ~/.vscode/extensions/ms-dynamics-smb.al-*/bin/win32/alc.exe 2>/dev/null | sort | tail -1)
```

One layout. `.claude/skills/al-compile/SKILL.md`'s `Procedure` block does it correctly:

```bash
ALC=$(ls ~/.vscode/extensions/ms-dynamics-smb.al-*/bin/win32/alc.exe \
         ~/.vscode/extensions/ms-dynamics-smb.al-*/bin/alc.exe 2>/dev/null | sort | tail -1)
```

`CLAUDE.md` records why, as R167: `alc.exe` and `altool.exe` live under `bin/` on the per-platform
VSIX and under `bin/win32/` on the multi-platform one, and both must be probed, newest first.

## What it costs

On the currently installed extension (18.0.2668733, per-platform) the subagent's glob can miss, and
its failure mode is `BLOCKED (AL VS Code extension not found)`. That is the good direction for a
wrong answer: it refuses rather than compiling with the wrong compiler. But it is a refusal that
looks like a broken environment, and the obvious next move for whoever hits it is to go looking at
their VS Code install rather than at this line.

The subagent and the skill do the same job and one of them learned R167. This is the ordinary cost
of the same procedure living in two files: the second copy rots, which is the reason
`scripts/roadmap-index.ts` gives, in its own header note, for generating `ROADMAP.md` rather
than maintaining it by hand.

## What closing it would take

Copy the skill's two-path glob into the subagent, which is the one-line version. Better, and what
[[R223]]'s orchestrator work wants anyway: move compiler discovery into one place that both the
skill and the subagent call, so the next tooling change has one site to update rather than two to
keep in step.

## Closed (77b8517f, checked 2026-10-05 under R-244)

The one-line version had already landed. `77b8517f` ("compile-fixtures, al-compile skill,
al-compiler agent: find Linux alc") gave `.claude/agents/al-compiler.md` the same `Locate alc`
block as the skill: on Linux `$LETHAL_ALC_DIR/alc` first, then the extension's `bin/linux/alc`;
elsewhere both `bin/win32/alc.exe` and `bin/alc.exe`, newest first, which is R167's order. The
shared-discovery version was not built: the two copies agree today, and a third consumer is what
would justify one place.
