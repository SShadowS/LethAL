Found by lethal-code, 2026-11-11 (coord R-914, MasterDataManagement on al-runner v3). Related: [[R786]], [[R612]], [[R761]].

**What happened.** MasterDataManagement's test app has 24 tests. One, `Master Data Mgt. Synch. Tests.SynchMediaField`, is refused by
v3 (`NotRun: out-of-scope: Insert on virtual table 'Tenant Media'`). The serve-entries default met it at the warm-up, R786's rule
re-ran the whole session one-shot, and the estimate for 2690 covered mutants became 71.1 h (itself overstated, R915). The other 23
tests would run on serve.

**Invented repro.** A test codeunit with two tests: one inserts into a table v3 refuses by name, one passes. `lethal run --backend
al-runner-v3` (serve default) warns `al-runner-v3-serve-default-fallback-warmup` and runs every mutant one-shot.

**Wanted.** A test refused by name at the warm-up is dropped from the green set (it would be red at baseline anyway, and is named
so), and the session stays on serve. R786 chose the whole-session fallback because the failure came at the warm-up, before any row
was trusted; this asks whether a by-name refusal of one test is a reason to give up serve for all.
