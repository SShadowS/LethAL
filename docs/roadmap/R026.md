**The permission canary measures itself, not the target.** Built to report whether the fenced path strips permissions; measured 2026-07-26 to be answering a question about its own codeunit. It does not declare `TestPermissions`, so it defaults to Restrictive and is refused — reporting `mocked` on the very server where a real suite writes happily on both paths. The mechanism and the fail-safes are sound (every degraded path is `inconclusive`, never a false clean); the predictor is wrong. Fix: declare `TestPermissions = Disabled` on the canary so it measures the platform rather than itself, and have it report the TARGET test codeunit's `TestPermissions`, which is what actually decides whether that suite can write. Evidence: `extensions/lethal-control/src/PermissionCanary*.al`, `packages/runner/src/permission-canary.ts`.
