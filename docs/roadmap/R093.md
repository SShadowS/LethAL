**al-runner v2 landed upstream and every flag we send is gone — the gate is measured RED.** Upstream PR #1654 "AL Runner v2: full architecture cutover" merged 2026-08-05 (2,340 files); v2 links unmodified MS/ISV DLLs via Cecil + JMP hooks instead of v1's Roslyn type-renaming rewriter, and rewrote the CLI. `OneShotTransport` (`packages/runner/src/al-runner-transport.ts`) sends `--run <method>`, `--packages`, `--stubs`, `--test-timeout`; **none exist in v2** — `--test`/`--filter` replaces `--run`, `--package-cache` replaces `--packages`, `--stubs` is dropped, `--test-timeout` became an env var. Any unknown `--` flag prints `Unknown option '--run'.` and exits 2 (upstream `AlRunner/Program.cs:305-308`). Independently, per-test names are now qualified — `Codeunit79100.OverBudgetDetected` (`AlRunner/Reporter.cs:190`, `AlRunner/ServerProtocol.cs:119`) — while `run()` matches the bare `ref.method` (`al-runner-backend.ts`), so even a corrected argv would report every mutant as "al-runner output missing the requested test". **Measured 2026-08-05**, both runs on the same fixture, same session: v1.0.31 (`~/.dotnet/tools/al-runner.exe`) → `itest:alrunner` PASS at the frozen 3 killed / 13 survived / 0 no-coverage, `baselineGreen=true`; a local Release build of upstream `main` + PR #1657 → all 16 mutants `error note=no green baseline tests`, `baselineGreen=false`, gate aborts on `baseline must be green`. The failure is loud, which is the one good thing here. Server mode is closer but also broken — see R97. Note the version probe cuts both ways and is measured: v2 answers `--version` with `al-runner v2.0.0.0`, while v1.0.31 rejects it (`Error: file or directory not found: --version`) — so a non-zero exit with that message IS the v1 signal, and the comment at `al-runner-backend.ts`'s `--version` probe in `status()` is right about v1 and wrong about v2. Upstream's migration matrix claims v1 supported `--version`; reported as [#1660](https://github.com/StefanMaron/BusinessCentral.AL.Runner/issues/1660). **Adapt-first is the policy** (decided 2026-08-05): al-runner is in heavy development and LethAL is unreleased, so a changed CLI/wire shape is OUR adaptation cost. Something goes upstream only if a capability is genuinely gone with no equivalent, it is a regression against a compat promise upstream made (cheap for them, expensive for us), or it is a crash/silent failure against their own loud-failure rule. Under that filter the qualified names, the exit-code remap (R95), the timeout signature (R94) and `--test`'s substring semantics are all ADAPTATION, not defects to report — the information still exists in every case. Work needed: decode adaptation plus **a wire-contract probe**, replacing `al-runner-canary.ts`'s two-defect design with one that MEASURES the contract each session (test-name shape, timeout text, exit codes for compile-fail/exec-fail/out-of-scope, whether the server honours a second `sourcePaths`, R7/R8) and refuses loudly on anything unrecognised. Version-branching a decode matrix loses to a moving target; a measured contract does not, and it is the same argument that justified the canary originally. **Pre-committed prediction for the v2 gate, recorded BEFORE the run:** 3 killed / 13 survived / 0 no-coverage, per-mutant identical to frozen — the fixture contains no `asserterror` and no table-object globals (checked), so R99's two semantic fixes cannot move it, and any deviation is an adapter bug rather than a change in what al-runner believes. Delete the v1 path once the v2 gate is green: the gate can only freeze one binary's behaviour, and a v1 branch nothing runs is a lie waiting to happen. **Environment note, 2026-08-05: this machine's global tool is now al-runner 2.0.0**, not the v1.0.31 the frozen gate was recorded against — so `bun run itest:alrunner` with the default `LETHAL_ALRUNNER_PATH` is EXPECTED to abort on `baseline must be green` until the adapter lands. That is this row, not a regression. Roll back with `dotnet tool update --global MSDyn365BC.AL.Runner --version 1.0.31` if a v1 verdict is needed before then.

**CLOSED 2026-08-07, and the measured contract is in `docs/measurements/README.md`** §"al-runner v2
— the CLI and wire contract", taken against the RELEASED binary on this Windows box rather than
against a local build of `main`. Read that section, not the paragraph above, for what v2 actually
does: several claims here and in R94/R98/R101 were measured against a pre-release build and have
since drifted.

Three corrections worth carrying forward:

- **R98's Windows blocker is gone.** The released 2.0.0.0 runs here: `--version` exits 0, and the
  fixture runs 2 pass / 0 fail / 0 error.
- **`--test-timeout` has a working replacement.** R94 called it "no longer a flag" and stopped
  there; the env var `AL_RUNNER_TEST_TIMEOUT_SEC` IS honoured by the release (measured: set to 15,
  produced a 15.027 s test), so the "halve the client deadline so the runner's own timer fires
  first" reasoning is portable and was ported.
- **R101(a) is wrong about `--bc-version`.** The runner does not silently pick the latest artifact
  in the cache; it prints its selection and defaults to the build it was compiled against. Pinning
  is a preference here, not the correctness hole that row describes.

**What this row asked for and did NOT get: the wire-contract probe.** The decode is adapted, but
`al-runner-canary.ts` still measures only R7 and R8 — both of which v2 fixes, so on a current
install it reports "not reproduced" twice and tells a reader nothing about the contract that
actually moves. Filed as **R123**, and the case for it got stronger, not weaker, during this work:
al-runner published **2.0.1 while the port was being written**, and 2.0.1 changed the timeout
wording back to v1's. A decode keyed on a literal string cannot survive that cadence. What kept it
safe was making the UNCLASSIFIED case fail closed (R94), which is a property rather than a guess —
and that is the shape the probe should generalise.

**The v1 path is deleted** as this row required: `--run`, `--packages`, `--stubs`,
`--test-timeout` and `--test-isolation method` are gone from the argv, the `skip` result member is
gone from the union, and `status()` refuses a binary that does not identify as v2. There is no v1
branch left to rot.
