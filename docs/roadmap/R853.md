Moved from [[R828]] when it closed. All of this is also on master before O1.

**Shapes that do not compile.** O1 fixed a chain's `end` touching the next source character, and the closer order on a glued statement. These stay. Each was run through the emitter by a review:

- A mutation text glued to the source after it: `Foo(C + 1)else`, with `begin end` for the call, emits `endelse`.
- A reach-marker wrap around `...Foo(C + 1)end` emits `endend`; around `...Foo(C + 1)until`, `enduntil`.
- The opener side: `begin"My Q"(C + 1)end;` emits `beginif`.

They fail at compile, loudly, so none gives a wrong verdict. The corpora hold 0 glued statements after a root ending in `;` (parse count, `/coord/handoff/R-828/o1/glued-count.txt`), but that count does not cover these shapes: how often they occur is not measured. A count by parse is the first step.

**One file the residual check cannot fold.** The tree-sitter parser finds an error in the emitted text of `CDCContiniaOnlineMgt.Codeunit.al` (DC, a `begin` inside a `#if` arm, its `end` outside it), at the same emitted text on master and on O1. `checkFile` stops at that error, so this file's mutants are not folded. The instrumented DC/Cloud app compiled with `alc` at 0 errors, so the error looks like the parser's and not the emitter's; that is not proven.
