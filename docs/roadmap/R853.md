Moved from [[R828]] when it closed. All of this is also on master before O1.

**Shapes that do not compile.** O1 fixed a chain's `end` touching the next source character, and the closer order on a glued statement. These stay. Each was run through the emitter by a review:

- A mutation text glued to the source after it: `Foo(C + 1)else`, with `begin end` for the call, emits `endelse`.
- A reach-marker wrap around `...Foo(C + 1)end` emits `endend`; around `...Foo(C + 1)until`, `enduntil`.
- The opener side: `begin"My Q"(C + 1)end;` emits `beginif`.

They failed at compile, loudly, so none gave a wrong verdict. **Fixed:** EMIT adds one space where a replacement, a list marker, a slot wrap or a chain would touch a word in the source (`wouldGlue`, `dispatch-emit.ts`). A space, never a newline, so no line moves, and only glued source changes. A slot wrap is reached when a loop's own mutant makes the loop the root: `while A do"D" := C + 1;` emitted `dobegin`, and `repeat if A then D := C + 1until"A";` emitted `enduntil`. The `block` branch is unchanged, because a block cannot start right after a word.

**One file the residual check could not fold: the cause, measured.** The emitted text of `CDCContiniaOnlineMgt.Codeunit.al` is valid AL (`alc`: 0 errors). tree-sitter drops the right parse at its limit of 6 parse versions; with that limit at 64 in a scratch build, the file parses clean. See [[R855]] for the shape and the root fix, upstream at https://github.com/SShadowS/tree-sitter-al/issues/40.

**How often, measured** on 2026-11-06, every file with mutants in DC/Cloud, DO/Cloud, DO/Test and all of BC.History: 13,484 files, 2,318,022 mutants. 0 sources have a parse error. 3 emitted files do, and the rule flags all 3 (`/coord/handoff/R-853/count3-first-rule.log`):

- DC `CDCContiniaOnlineMgt.Codeunit.al`, 246 mutants.
- BC.History `EDocIntegrationManagement.Codeunit.al` (E-Document Core), 314 mutants.
- BC.History `ProdOrderComponent.Table.al` (Base Application), 1,098 mutants.

All 19,461 `.al` files of those trees, mutants or not, parse clean as source (`parse-all.log`).

**Before the fix, by coverage mode.** A root ERROR stopped a fenced run with a message that only said LethAL had a bug. An ERROR that left the object but lost its procedures read every line as a naming gap, so a mutant there was `no-coverage` though it ran, with only a warning. Worst: valid AL with `end;` in both arms of a `#if/#else` left a MISSING `end`, so the next procedure's lines were named as the one before it, with no error and no warning. The emitter gave no such file in 90 invented sources or in the corpora, but the path was open.

**Fixed: `isUnreadFile`** (`line-map.ts`). A file is unread when the root is an ERROR, an ERROR swallowed a `procedure` or `trigger` keyword, or a `code_block` has a MISSING `end`. It gets no entries. A mutant in it stops the run before publish, by name, on bcdev fenced, on hub, and on v3 with coverage. The message names the file, the limit and `--exclude <glob>`. On hub any unread file stops the run, since the hub cannot tell which object is in it. An ERROR that lost no member (in a body, or `extends Ns.Name`) stops nothing.

Not fixed: such a file cannot be measured until it is left out. Leaving a file with 1,098 mutants out of BaseApp is a real cost, which is why [[R855]] matters. `lethal verify` stops on such a file too, but with no refusal JSON (`verifyRefusalOf` has no case for this error), and that needs an artifact from a build older than this one.
