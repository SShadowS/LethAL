**Filed 2026-10-25 (coord task R-762, item A).** The orchestrator sends a kill confirm with coverage `none`, but
the one-shot path treated every unmutated call as the baseline: it sent `--coverage-json` and ran `coverageOf`
on the answer. R760 measured coverage writes at about 0.8 s of each one-shot call.

**Fix.** `callCodeunit` takes whether coverage was asked for. An unmutated call (`lastActivated === null`) that
asked for `none` sends no `--coverage-json`, joins nothing, and marks its cached call `noCoverage` (so a later
caller that wants coverage re-calls). The real baseline (coverage `al-runner`) is unchanged, including the
unavailable-coverage throw. Mutant calls keep the flag whatever they asked, because the Sleep rule (§6) reads it
(that is item B, not this one).

**Serve-entries.** Already honours it: a confirm is outside the baseline bracket, so it never joins coverage, and
the coverage window runs only for a PASSING MUTANT call (`lastActivated !== null`), never for a confirm. Untouched.

**No verdict change.** A confirm's coverage fed nothing scored (`run` returns before the Sleep rule when no mutant
is active). Tests: `R762 A` in `packages/runner/tests/al-runner-v3-backend.test.ts`.
