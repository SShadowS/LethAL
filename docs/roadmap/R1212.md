title: "LethAL's static hang refusal misses two loop-hang shapes met on a real project: a negated `Next() = 0` in an `until` condition, and the removal of a call that re-positions the loop's record cursor (`RecRef.Get(<saved RecordId>)`)"

**Found by** coord PR-427 (2026-11-25): the al-runner v3 hang check run before a bcdev baseline of a private ISV app's Email
area. Six files (5,047 sites, 4,875 deployed) at LethAL ac413797d, run on al-runner edge e5176a9fd with BC 29 packages.

**What.** LethAL refuses a mutation site statically when the mutant could make a loop endless ("hang-refused"; 225 sites in
this scope). That rule removes hang-capable WRITES under a loop condition. Two other shapes escape it, and each mutant
was `timeout-killed` (an endless loop) on al-runner. The site keys are (file, line, operator, start/end index):

1. **M2850**, `src/Features/Email/Templates/CDOEMailTemplateHeader.Table.al` line 873, `lethal.negate-conditional`, 37888-37921
   (procedure `GetRecipients`).
   - The shape: a `repeat … until (<cond>) or (Rec.Next() = 0)` loop, with `= 0` negated to `<> 0`.
   - On the last record, `Next()` returns 0, so while `<cond>` stays false the loop repeats that record forever.
2. **M0657**, `src/Features/Email/Sending/CDOEMailHandler.Codeunit.al` line 490, `lethal.void-method-call`, 29864-29886
   (procedure `RunReportID`).
   - The shape: a `repeat … until RecRef.Next() = 0` loop whose body re-assigns the cursor (`RecRef := <other>.Duplicate()`)
     and then puts it back with `RecRef.Get(<saved RecordId>)`.
   - Removing the `Get` leaves the cursor at the start every iteration, so `Next()` never reaches the end.

**Why it matters:**
- A bcdev run relies on the hung-session stop to recover from such a mutant (bc1-bc4 are stop-capable).
- A server without the stop, or a tier the stop cannot reach, would wedge on it.
- The static refusal is the only protection that needs no live stop, and these shapes are common in AL loops over records.

**The fix to decide (not built):**
- refuse `negate-conditional` (and its relatives) on a `Next()` comparison that ends a `repeat … until` loop;
- refuse removing a call that re-positions the loop's own record variable (`Get`, `Find*`, `SetPosition`, `GotoRecord`)
  inside that loop's body.
- Each needs its own red check on an invented loop. The bcdev baseline (PR-427) keeps BC's verdict for both mutants, so no
  line is excluded there.

**The full list:** PR-427's resumed v3 check lists every hang of this scope. Any third shape is added here.
