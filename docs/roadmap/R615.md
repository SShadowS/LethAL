**Filed 2026-10-21 by R-598** (lethal-preproc; from its build review, `/coord/handoff/R-598/review-opus-build.md`,
minor point).

**What.** `bc-linux-setup.ts` writes the lease token, right after taking the lease, to `TOKEN_DIR/lease-<server>.txt`.
`TOKEN_DIR` is fixed to `/coord/handoff/R-589`, and the file name has no lane in it. Since R598 the lease is taken in
the caller's own lane, but the token record still is not separate. Two lanes setting up the same server one after the
other overwrite the record. A crash then leaves a token file that may name another lane's lease, which matters when
someone releases a stale lease by hand.

**To close.**
- Put the lane in the record (`lease-<server>-<lane>.txt`) or make the folder a required argument, as
  `scripts/bc-republish.ts`'s `--token-dir` already is.
- Update the docs that point at the R-589 folder.
- Add a test through the kraken-call seam.

**Fixed.** `krakenLeaseFor(lane, run, tokenDir = TOKEN_DIR)` writes `lease-<server>-<lane>.txt`. The R617 guard
still refuses the default folder under the unit-test preload; a test passing its own folder writes there. The
test in `scripts/bc-linux-setup.test.ts` ("R615") checks two lanes keep two files and a lane overwrites its own.
The old `lease-bcN.txt` files in `/coord/handoff/R-589/` are dead records (not deleted).
`resolveLane` now refuses a lane that is not `[a-z0-9][a-z0-9-]*`, because it becomes a file name.
No living doc named the old file, and nothing reads `lease-*.txt` (`bc-republish.ts` takes `--token-dir`).
