**Upstream `tree-sitter-al` released 4.0.0 (2026-08-10), a deliberate breaking release; the wasm
vendored in `packages/engine/vendor/` is still 3.2.1.** The gap is three releases: 3.3.0 (additive:
`#define`/`#undef` nodes, scanner directive lookahead), 3.3.1 (scanner fixes, tree-neutral), and
4.0.0. Evidence: `U:/Git/tree-sitter-al` CHANGELOG.md §4.0.0, tag `v4.0.0` = commit `27f518e`.
All corpus figures below are upstream's, measured on 15,358 BC.History files.

Unlike the clean 3.0.1 -> 3.2.1 bump (vendor README §"what it cost: nothing"), 4.0.0 **changes named
parse trees**, which is the layer `astSubtreeHash` serializes. Known LethAL-facing impacts, each
traced to a consumer:

1. **`assignment_operator` becomes a named node** (+243,044 instances upstream, was in no node at
   all). Every `assignment_statement`/`assignment_expression` subtree gains a named child, so
   **every `empty-block` mutant whose block contains an assignment gets a new identity hash**
   (`packages/engine/src/ast/hash.ts` serializes named children recursively). Per-mutant baselines
   will flag these wholesale. Re-recording demands the per-site old-key -> source line -> new-key
   proof of vendor README step 5, not a signature-multiset compare.
2. **`case … else` bare bodies gain a `statement_block` wrapper.** `isStatementPosition`
   (`packages/engine/src/ast/tree-walks.ts`) keys on the parent being `statement_block`/`block`,
   so statements in bare case-else bodies were NOT statement positions under 3.2.1 and become ones
   under 4.0.0 — `void-method-call` gains sites there. A genuine coverage gain, but it must show up
   as enumerated adds in the `census-operator-sites.ts` diff, not be waved through.
3. **Single-entry `DataItemLink`/`RunPageLink`/`SubPageLink`/`ColumnFilter` stop parsing as
   `comparison_expression`** (-1,677 upstream). Any Tier-1 operator that claimed
   `comparison_expression` inside property values loses those sites; they were misparses, so losing
   them is correct, but the census diff must enumerate them.
4. **The statement terminator leaves `code_block`** — a `begin … end;` block's span shrinks by one
   byte. Hash-neutral (the `;` was anonymous) but `empty-block`'s replacement range and
   `originalText` shift; schemata's rewriter output must be re-verified by compile.
5. **Dangling `else` in a case branch rebinds to the inner `if`** — the one semantic re-read. Fixes
   `cfg.ts`'s picture of those shapes; can shift which node `else_branch` returns on affected files.
6. **`node-types.json` moves** (new named kinds: `assignment_operator`, `where_keyword`,
   `field_keyword`, `const_keyword`, `upperlimit_keyword`, `preproc_define`/`preproc_undef` from
   3.3.0; `begin`/`end` inside `#if` become nodes). `ALNodeKind` is a curated subset and
   `ALSyntaxNode.kind` casts into it (R120), so regenerate per vendor README step 6.
7. **`exit` with whitespace before `(...)` now parses correctly** — 3.2.1 silently dropped the
   entire return value from such trees with zero ERROR nodes. `return-value` gains real sites.
   Conversely `exit (x + y) * 2;` becomes an ERROR, matching alc.
8. Anonymous-layer churn (48 uppercase keyword types removed, keyword nodes gain one anonymous
   child) — LethAL walks named nodes and uses no `.scm` queries, so this half is expected to be
   inert here. The wasm also grows: upstream `parser.c` went 23.3 MB -> 32.3 MB.

**What closing this takes:** the full vendor README procedure — build wasm from source at the tag,
record hash/provenance, typecheck + dist-clean + unit suite, BOTH censuses (aggregate + per-site)
with every add/remove in the diff explained by one of the items above, `ALNodeKind` regeneration,
then the live gates with per-site baseline proof before any re-record. Upstream's own changelog is
unusually well-measured (every tree-moving change enumerated by node-instance set difference), which
is the map for predicting the census diff — but the census is still the authority, not the map.

Also worth taking even before 4.0.0: upstream 4.0.0 fixed `parse-al-parallel.sh` counting files it
never opened as successes — a reminder that this repo's own "parsed N/N clean" claims should come
from per-file records, not subtraction.
