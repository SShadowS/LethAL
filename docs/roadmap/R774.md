**Filed 2026-10-25 by lethal-preproc, from coord task R-773.** Related: [[R760]], [[R761]], [[R766]], [[R768]].

**What.** The owner keeps asking for the same table for the al-runner-v3 backend:
- the total wall time;
- where the seconds go: the contract probe (or its cache hit), the alc compiles, the daemon warm-up, the baseline,
  and the mutant loop's parts (live requests, echoes, coverage windows, bound checks, kill pairs);
- the per-mutant median and p90;
- the al-runner build and the transport.

R760 assembled that table by hand.

**Why a script.** A hand-built table is hard to repeat, and a figure means little without the machine load
it was measured under. Other heavy jobs share the container.

**To close.** `scripts/v3-timing.ts`:
- runs `lethal run --backend al-runner-v3` on `examples/gift-card` and on the v3 gate's D1 slice of the CDO checkout;
- takes a heavy slot with `flock`;
- reads the report's timings, the events stream, the CLI's serve-entries counters and the processes it spawns;
- writes a markdown table and JSON;
- records the load (free memory, the load average, and the number of other heavy jobs) at the start and end of every
  run.

The table builder has a unit test on fixture data.

**A probe-cache caveat for anyone reading the table.** The contract-probe cache key includes each package file's
mtime (`packagesFingerprint`, see [[R776]]). So a fresh checkout, a new worktree or a copied `.alpackages` always
misses once, and that run carries a whole probe: about 10 s on the gift card. The script copies the gift card's
Microsoft apps into one fixed folder and keeps their mtimes, so repeated runs can hit the cache. Its first run on a
new code revision still misses, because the key also hashes the probe code. Read the `probe` column before
comparing two walls.
