**Priority.** Filed 2026-10-09 by the R534 build (plan r2, roadmap item 6; review F2). A FALSE
KILL is possible.

**What.** al-runner reports any exception that escapes a test body as `fail`, whatever its type
(`TargetInvocationException` is unwrapped to `Fail`, read from `TestExecutor.RunOne` at 43f7617).
`verdictFromRunnerTest` scores `fail` as a kill. AL code cannot raise a .NET
`NullReferenceException` or `NotImplementedException`: such a row means al-runner itself broke on
the mutated code (a missing shim, a runtime defect), and BC might well have run it. That is not
evidence the suite caught the mutant.

**Evidence.** `/coord/handoff/R-534/review-plan-opus.md` F2; `/coord/handoff/R-534/measure.md`
"What the source says"; `verdictFromRunnerTest` in `packages/runner/src/al-runner-backend.ts`.

**To close.** Measure which runtime exception types al-runner surfaces on a `fail` row. Score a
`fail` row whose message starts with such a type as an `error` with its own cause (never a kill),
matched at the type position as [[R534]]'s refusal rule is, with a near-miss test.
