**Filed 2026-10-08 by the [[R500]] build** (survey `/coord/handoff/R-500/survey.md`, shape 8; plan r3 ruling on shape
8). Product-wide, not only in reports. A plausible hang that is NOT refused.

**What.** A `while`/`repeat` whose condition is a `Find`/`FindFirst`/`IsEmpty` on a record and which ends only
because its body consumes that set (`Delete`, `DeleteAll`, or a `Modify` of a filtered field) loops forever when a
mutant removes or weakens the consuming call. R196/R446/R480 read the condition and its guards, not progress made
through a call ([[R196]]'s "progress through a call" exclusion), so these are emitted everywhere. In R500's sample
of loops inside bounded report items, **1 of 12 was a certain hang** of this shape (`FA Posting Group - Net
Change`: a loop that runs while a buffer's first row can be found and ends only because its body deletes the rows;
removing the `DeleteAll` hangs on any non-empty buffer).

R500 ruled the bounded report item adds nothing here: the inner loop is an ordinary AL loop, the same as in any
codeunit, so the fix belongs in the loop rules, not in the report rules.

**To close.** Census the shape product-wide (the cursor-method condition plus a consuming call on the same
receiver in the body), read a sample, then refuse the consuming call's removal in such loops or close it with a
ruling.

**The shape.** A `while`/`repeat` whose condition calls `Find`, `FindFirst`, `FindLast`, `FindSet`, `IsEmpty` or
`Count` on a record R and does NOT call `Next`, and whose body holds at least one consumer of R. A
`repeat ... until R.Next() = 0` loop is never this shape (BC.History has 4,760 such loops with a consumer): `Next`
advances whatever the body does.

**The consumer kinds** (each pinned by its label in the tests): `delete`, `deleteall`, `rename`; `refilter`
(`SetRange`/`SetFilter` on R in the loop); `mark` (Reset, Copy, CopyFilter(s), SetView, SetRecFilter,
FilterGroup, Mark, MarkedOnly, ClearMarks on R); `modify-filtered` (a `Modify` after writing a field R's filters
name, R a plain local); `modify-all` (the same with R a global, a parameter or the implicit Rec: every written
field counts); `modify-unseen` (no filter on R in the procedure: every written field counts); `delete-reinsert` (a
re-`Insert` with a filtered field written, a rename by hand); and, unknown so counted as consuming, `pass-rec` (a
call passing R), `recv-proc` (a non-built-in call on R) and `global-call` (a same-object call while R is a global
or the implicit Rec). An `alias` of R in the same procedure (`X := R`; `X.Copy(R, S)`, `R.Copy(X, S)` or a
bare `Copy(X, S)` on the implicit Rec, where `S` is anything but the literal `false`; both directions, by name)
counts as R.

**Refused, for every operator.**
- BASE: in the loop body, a site inside a consumer, a site holding one, and a site in a guard between a consumer
  (or a `continue` of the loop) and the loop. Not an `exit`, `break` or `Error`: each ends the loop.
- NEG: inside the loop's own condition, every operator except `swap-find-direction`.
- FILTER: before the loop in the same scope, every site inside a `SetRange`/`SetFilter` on R whose field the
  consumer changes, or any filter on R when the consumer is a `Rename` (so `swap-rec-xrec` in an OnRename
  `SetRange(.., xRec.Name)` is refused). Also a `MarkedOnly` on R before a loop whose consumer is `Mark(...)`.
- FEEDS: a same-scope assignment whose target name a consumer's arguments, a consumer write's right side, a
  consumer guard, a pre-loop filter's arguments or a guard around a pre-loop filter read (R480's by-name rule), and
  those guards around a pre-loop filter.
- HOP: one hop into a same-object callee (the parameter at R's argument position, the same global R unless the
  callee declares that name itself, the implicit Rec) or a table procedure on R, following EVERY overload whose
  parameter count fits the call: the callee's consumers, the sites holding them and their guards. Through a
  `var` parameter every consumer kind is followed. Through a BY-VALUE parameter only `Delete`, `DeleteAll`,
  `Rename` and `Modify` (with its field writes) are followed; refilter, mark and unknown consumers are not. This
  closes DC's certain hang `CDCContiniaConfigSubpage` `ModifyChildRecords` -> `DequeueTempConfigLine`.

  Why the by-value rule is the way it is, so it is not later mistaken for a regression: the plan's original
  by-value control (orchestrator instruction, plan r3 item 5) assumed a by-value Record is a copy of the table.
  It is a copy of the VARIABLE: a callee's Delete/DeleteAll/Rename/Modify on it hits the real rows, so those
  consumers are followed through by-value parameters; refilter and mark consumers only affect the copy and are
  not (R-531 build review finding 1, `/coord/reviews/R-531/opus-build.md`). The test that pinned the old
  belief is inverted: a by-value callee's `Delete` is refused, and a by-value callee that only refilters or
  marks its copy is not.

**Residuals (not refused; stated limits).**
- A consumer in a cross-object callee (other than a table procedure on R), a DotNet callee, or more than one hop
  away.
- A refilter through a FieldRef (`LibraryUtility` `GenerateRandomCode*`): filed as [[R563]].
- A pre-loop filter set through a table procedure (CDO and DO OnRename loops with `SetTemplateFilter(xRec)`,
  `SetEMailTemplateLineFilter(xRec)`): filed as [[R562]].
- Another variable consuming the same row: receivers compare by name, so `Other.Get(R."No."); Other.Delete();`
  in the loop body is not seen as a consumer at all (R-531 build review finding 3).
- A filter in the CALLER when R is a parameter or a global: `R.SetRange(Status, Open); Process(R)`, where
  `Process` loops and writes `Status` before a `Modify`, keeps the caller's `remove-setrange`; FILTER reads only
  the loop's own scope (R-531 build review finding 3).
- A temporary record passed by value: whether the callee's copy shares the caller's temporary table is
  unmeasured. It is refused by default, the same way as a database record (the by-value consumer kinds above).
- FEEDS matches assignment targets by name over the whole scope, so it can also refuse a same-named write to
  another record, or one after the loop (over-refusal, the safe direction).
