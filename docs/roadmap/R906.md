Found by coord task R-902 (EU 3-Party Trade Purchase on v3, 2026-11-10). Evidence: `/coord/handoff/R-902/eu3.report.json`,
`eu3.stderr.txt`. Related: [[R535]], [[R579]], [[R580]], [[R602]].

**What.** `UpgradeEU3PartyPurchase.Codeunit.al` has one `#if` around its whole object, and inside that wrapper a second `#if` that
holds only `using` lines. `alRunnerAdmitsWrappedFile` calls ANY `preproc_conditional_object` child of the wrapper "nested", though its
own doc comment says "no nested object wrapper" and allows `using` lines inside. The file is not admitted, `v3CoverageMode` turns
coverage off for the whole project, and every mutant runs against every test.

**Effect, measured.** 155 mutants, 6 killed, 149 survived, 0 no-coverage. All 149 survivors list all 14 tests as covering them,
including 57 in the upgrade codeunit, which no test runs. A mutant no test reaches should read `no-coverage`. Each mutant also cost
about 15 s against all the tests.

**R535 misread this shape.** Its census counted this same file (in BaseApp's tree) as a "nested object wrapper", with the same
predicate. A rough grep over BC.History finds the first-line-`#if` plus inner-`#if`-before-the-object shape in three files: this
one, BaseApp's `IntrastatJnlLine.Table.al`, and an E-Document enum that R580 already admits.

**Fix.** Count an inner `#if` as nested only when `wrapperHoldsObject` says it holds an object, on the al-runner path.

**Measured with the fix** (`/coord/handoff/R-902/r3-eu3.report.json`, per mutant against `eu3.report.json`, on the same al-runner
build). As predicted before the run: the same 6 mutants killed, by code. No other direction moved: 95 mutants went from `survived` to
`no-coverage` (57 of them in the upgrade codeunit), and 54 stayed `survived`. Wall time went from 2,530 s to 230 s. The v3 gate passed
on 75102d44, all 19 legs. al-runner v3 is not authoritative, so this is v3's own before and after, not BC's verdict.

**Not changed:** `bcWrappedShapeRefusal` has the same condition. Nothing in this task can measure BC's line numbers for this shape,
so the BC paths keep refusing it by name.
