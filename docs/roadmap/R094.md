**al-runner v2 turns a hung mutant into a KILL.** v1 reported a runner-enforced timeout as `status: "fail"` with the text `Test exceeded <n>s timeout`, which `RUNNER_TIMEOUT_MESSAGE` (`packages/runner/src/al-runner-backend.ts:24`) matches to produce `outcome: "timeout"`. v2 reports it as `status: "error"` with `TIMEOUT after <n>s` (upstream `AlRunner/TestExecutor.cs:292-299`). The regex misses, the status is not `pass`, so `run()` returns `fail` — and a mutant that merely hung is recorded **killed**. A false kill, the direction this project treats as unacceptable, and it is invisible in aggregate counts. Also note the budget is no longer a flag: `--test-timeout` is gone and the timeout is `AL_RUNNER_TEST_TIMEOUT_SEC` (env), default 60 s (`TestExecutor.cs:30,336`), so the deliberate "halve the client deadline so the runner's timer fires first" reasoning at `al-runner-backend.ts:257-267` has nothing to set. Measured 2026-08-05 against a local build of upstream `main` + PR #1657.
