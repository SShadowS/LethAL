Found while writing PR-70's CI templates (review of 2026-11-16).

**What.**
- `lethal export --help` says "Render the JSON to HTML with 'npx mutation-testing-elements'", and the export's console text
  says the same.
- `npm view mutation-testing-elements bin` (version 3.9.0) shows no `bin`: it is a web-component library, not a command. So
  the advice does not work as written.
- `--help` also says Azure DevOps' PublishMutationReport task reads the interchange schema. The Stryker extension's task
  publishes an HTML report.

**Effect.** In CI, the exported JSON can be kept as an artifact, but not shown as an Azure DevOps build tab or opened as a page,
without an extra step LethAL does not document.

**Possible fix.** A documented way to get the HTML: either a tiny static page that loads the `mutation-testing-elements`
bundle and the JSON (the Stryker html reporter's shape), or an `--format html` that embeds the JSON in such a page. The latter
means shipping or downloading the bundle, which the export's doc comment avoids on purpose, so it needs a decision. In any case,
correct the `--help` and console text.

**To close.** The help text matches what works, and the templates show the report in Azure DevOps.

**Partly fixed (PR-76, fe099d4a); stays open for two measurements.**
- `lethal export --format mutation-elements-html` writes one page. The JSON is inlined as the `report` of
  `<mutation-test-report-app>`, with `<`, U+2028 and U+2029 escaped. The page loads `mutation-testing-elements@3.9.0`'s
  browser bundle from jsDelivr, with `integrity` and `crossorigin`. The tarball's sha512 matched the
  registry's integrity, and the bundle inside it is byte-identical to jsDelivr's; its sha384 is the pin. LethAL ships and downloads nothing.
- `--help`, the console text and the `--format` error no longer name `npx mutation-testing-elements`. They say the page needs
  network access to jsDelivr.
- Both CI templates export the page. Azure publishes it with `PublishMutationReport@2` (only when the page was
  written), GitHub as an artifact.
- **Rendering measured (2026-11-16, after PR-76).** Chromium (Chrome Headless Shell 159, Playwright 1.65.1, installed by the
  owner) opened the page exported from the committed gift-card report (`docs/campaign/2026-08-16-gift-card/rehearsal.report.json`).
  - The bundle loaded from jsDelivr and passed its integrity check, with no console error and no failed request.
  - `<mutation-test-report-app>` rendered both files and the table: 61 mutants, 35 killed, 15 survived, 11 no coverage,
    70.00 "of covered". Those are the report's own counts.
  - Negative control: the same page with one character of the hash changed. Chromium refused the bundle ("Failed to find a
    valid digest in the 'integrity' attribute"), the element was never defined, and nothing rendered. So the hash is enforced.
  - Evidence: `/coord/handoff/PR-76/render/` (`render.mjs`, `gift.png`, `badhash.png`).
  - This was a one-off measurement, not a CI test: CI has no browser.
- **Still not measured:** whether Azure DevOps' report tab loads a CDN script. That needs a real Azure run.
- Close when an Azure run shows the tab.
