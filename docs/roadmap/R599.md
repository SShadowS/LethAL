**Filed 2026-10-21 by lethal-bugs during R-389** (orchestrator ruling).

**What.** `scripts/bc-linux-setup.ts` skips an app when the server already holds it at the same or a higher
version. Its own log line says so: "same or higher version, contents not compared". It never compares what is
published with the local build. So a fixture rebuilt without a version bump stays at its OLD build on the server,
and the setup run reports success.

**Seen on bc3, 2026-10-21.** R-583 moved every fixture to runtime 17. After `bc-linux-setup.ts --server bc3` on
R-583's code, the setup skipped all 15 fixture apps. Eleven had been published at their app.json versions by an
earlier setup run from the same code that day. Four are NOT proven to be the runtime-17 build:
- `Sandbox Names` and its test app are resident at 1.0.0.0, the same as their app.json, so a pre-R-583 build looks
  identical to the setup;
- `Sandbox App` and `Sandbox Hang` are resident at version numbers a gate run minted
  (`<major>.<minor>.<days>.<halfSeconds>`), which outrank every app.json version.

Evidence: `/coord/handoff/R-389/bc-live/setup-r583.log` and `setup-before.log`.

**Why it matters.** The per-server proof rule (`docs/gates/servers.md`, "Proof that the gates reproduce here")
admits a gate on a server only under the CURRENT fixture builds. A proof run on a stale resident build would
measure the wrong code and still look like a proof. `itest:hang` is not affected, because it publishes its own
instrumented Sandbox Hang build.

**To close.** Pick one:
- compare a content hash of the published app with the local build, and republish on a mismatch; or
- unpublish and republish through the automation API: uninstall, then the bound `Microsoft.NAV.unpublish` action
  on the extension (measured by R-389 on bc3, 2026-10-21; see [[R389]] and [[R597]]), then publish.

Either way, add a test that a same-version, different-content app is republished, not skipped.

**Until it is fixed:** any bc3 proof for `itest:bcdev` or the names gates must first republish those four apps by
the automation API path. `docs/gates/servers.md`'s bc3 row says so.
