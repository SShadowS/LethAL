**Found by R-318 (2026-09-30).** Plan: `docs/superpowers/plans/2026-09-29-R-318-renamed-split-members.md`,
Decision 6. Follow-up to [[R318]].

**What is wrong.** After R318, the mutants of a split-header procedure whose `#if` arms give it
different names are attributed `exact`. But `procedureName` stays `""` on purpose, so that no
identity key tuple moves. Three things still read the empty name:

- `report.ts` groups distinct renamed members of one file under `<object>` when they survive, so
  two such members cannot be told apart in the report.
- `lethal explain` cannot name the member.
- `test-order.ts` builds its killer-first order per procedure, and pools the kills of distinct
  renamed members in one `""` bucket. This affects the order only, never a verdict.

**Fix.** Two parts, and the first alone is not enough.

- Add a report field that carries the arm names. They are already in the manifest
  (`coverageArmNames`) and in the event stream.
- Give the killer-first order its own key. `procedureScopeOf` in `test-order.ts` keys the kill
  ledger on `procedureName || triggerName || ""`, and that runs BEFORE any report is built, so a
  report field cannot separate the ledger's buckets. The ordering key must come from the member's
  names (its `coverageArmNames`, first name or the whole list) and must NOT change the identity
  tuple: `procedureName` stays `""`, so no identity key moves.

**Cost.** A `SessionReport` field ripples: `events.ts`, `report-fold.ts`, `report.ts`,
`scripts/generate-schemas.ts`, `tests/schemas.test.ts`, the `report-equality` snapshot, and every
committed sample report regenerated live (CLAUDE.md, "Adding a `SessionReport` field ripples").

**Size.** 0 known sites: R318's census found no renamed split member in the fixtures or in the four
corpora (DC/Cloud, System Application, BusinessFoundation, BaseApp).
