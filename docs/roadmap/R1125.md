`/coord/handoff/PR-144/` (`rc-record.log`, `rc-record2.log`, `rcprobe/`, `rcprobe2/`). Related: [[R1108]], [[R1102]].

**What is missing.** PR-144 shipped `alRunnerV3.recheckWithheldKills`, default off. It is covered by unit and real-path tests and
by an approximation on a real project (arm M: 294 of 295 withheld kills recovered, all reproduced; 198 after rule (e)). It has
never run live end to end through a gate. The planned leg RC was taken out, because no fixture yet produces a withheld kill.

**Why a fixture is hard** (probes on edge-4ebfe7913, serve and one-shot):
1. A test refused at baseline is in no mutant's plan, so it cannot withhold anything. Measured on RC's second live run: "the main
   pass held 0 withheld kills", with 8 trusted kill pairs.
2. A test refused only under the mutant, with a refusal whose reach is KNOWN, such as an `Evaluate` of a NUL run into Decimal,
   leaves the next test's failure a plain trusted `fail`, with or without a write first.
3. DO's real withheld rows (x3: 295) all follow a refusal whose reach is unknown: "part of its reach is not known ... so the
   state it would have left is not BC's". The commonest are `GoToKey` on a list that opened on its last row (92), an earlier
   cascade from `InitFromTemplateLine` (62), `FindSet` on the Company table (48), and `Codeunit.Run` with an object id known
   only at run time. Some are decided before the test runs ("did not run"), which would also hit the baseline.

**To do:**
1. **Find an unknown-reach refusal that a mutant can switch on.** The earlier test must pass at baseline, and under the mutant
   reach the refusal. Probe it by hand on serve first (`rcprobe2/drive.ts` is a serve driver for an app and test pair).
2. **Pre-commit the fixture and its per-mutant figures,** then build `fixtures/sandbox-recheck` (and its tests) and leg RC
   (`"isolation": "test"`, serve, `"recheckWithheldKills": true`). The leg fails by name on 0 withheld kills, on no recovered
   kill, and on a recovered kill that rule (e) should keep.
3. **Rebuild the fixture symbol tar** with the two new projects (`scripts/build-fixture-symbols-tar.sh` keeps only projects
   already in the old tar, so the new projects' Microsoft symbols must be added to the input first). Update
   `FIXTURE_SYMBOLS_TAR`, `FIXTURE_SYMBOLS_TAR_SHA256` and the manifest, and confirm that `compile:fixtures` compiles both with no
   SKIP. Delivery to other machines is the owner's secret swap.
4. **P5, the BC differential,** needs a fixture of the same kind: an earlier test that sets state a later test's killing path
   depends on. The expected result is `survived` on bcdev and `error` from the recheck. It gates any default-on of the option.

  - `B2_SeesTheMark` also fails ("B1_OneSevenAndMarks must have run first in this codeunit"), because bcdev runs each

- **Ruling (orchestrator, 2026-11-18): rule (e) stays as it is.**
  - bcdev's one method per session is the odd one out. BC's standard test runner keeps codeunit state across methods
    (lethal-bugs measured one session for the whole run in PR-161), and that is what a user's own BC does.
  - Rule (e) protects that case, never creates a kill, and the option is off by default. Losing 4 kills on a fixture
    built to lose them is accepted.
  - PR-144's pre-commitment and leg RC's figures are unchanged.
