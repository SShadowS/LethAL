**Filed by R-297 Task 8 (2026-09-28), consolidating the plan's ruling 5.** Plan:
`docs/superpowers/plans/2026-09-28-R-297-instrumentation-real-corpora.md`: "Fail loudly.
`assertNoOverlap`, the injector's unsupported-kind throw, the latch's no-owner throw and `LineMap`'s
declared-but-unmapped throw all STAY, and the whole run still aborts on one bad file (ruling 5). No
failing file is skipped."

**What this means in practice.** R-297 fixed several throws by finding the right owner or container
for a shape ([[R297]]'s var-section anchor, [[R298]]'s object-container rule, [[R301]]'s split-header
procedure owner). It did not change the FAILURE MODE: a shape neither this landing nor an earlier
fix has covered, the next `preproc_*` container someone's AL hits, still throws an `Error` that
aborts `generateMutationSet`/`writeInstrumentedProject` for the WHOLE project, not just the one file.
[[R299]] already documents one instance of this deliberately (a file mixing an injectable and a
non-injectable object), and [[R305]] shows the alternative already exists for one shape: a
`preproc_split_declaration` object is recorded in `skipped` by name, with its site count, and the
rest of the project still instruments.

**Why it is filed rather than fixed here.** Turning every one of these throws into a per-file
skip is not a small patch: `SessionReport` already tracks a `skipped` list (`describeObjectKinds`
plus site count, see [[R308]] for that field's own gap), but a skip discovered only after specs are
generated (`assertNoOverlap`, the latch throw, the line-map throw) needs a place to land in the
SAME report shape without a new failure category. Any such change ripples the way CLAUDE.md's
"Adding a `SessionReport` field ripples" note describes: `packages/runner/src/events.ts`, then
`report-fold.ts`'s accumulator, then `report.ts`'s type/builder/banner, then
`bun scripts/generate-schemas.ts`, then `tests/schemas.test.ts` (the pinned root-required list and
the older-reports expectation), then `bun test <file> --update-snapshots` for `report-equality`, then
every committed sample report regenerated LIVE, which the container rule for this task forbids.

**What would close it.** Decide, for each of the four throw sites, whether the failure is per-file
(skip the file, keep going, name it in the report the way `skipped` already does) or genuinely
whole-project (a shape that cannot be localized to one file). Then thread the report field the
CLAUDE.md ripple list names, with a live sample-report regeneration once a container is available.
