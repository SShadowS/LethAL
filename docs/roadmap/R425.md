**Filed 2026-10-04 at the adoption of the R-384 plan.** R-384 makes `lethal verify` run each new test
only against the survivors its baseline coverage reaches, when coverage is usable. The filter is off
with `--no-reach-filter`, in coverage mode `none`, and in the hub modes. No existing field of the
verify report fits that state, so R-384 prints it on stderr only. A survivor no new test reaches stays
`survived` with an empty `testsRun` and a `failureNote`.

So the JSON alone cannot answer "was this survivor run against every new test, or only against the
tests that reach it?", and two verify reports of the same survivors under the two modes look alike.
A reader who keeps only the report, such as a campaign comparison or an agent, loses that fact.

**To close.** Record the filter state per run (on, or off with its reason) and, per survivor, whether
the filter narrowed its request. That is a new verify-report field and a verify schema bump (v5), so
it follows the ripple rules in CLAUDE.md for report fields. Readers of older reports must treat a
missing field as "unknown", never as "off".
