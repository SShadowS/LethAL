**Found 2026-10-05 while building R475** (coord handoff `R-475`, plan
`docs/superpowers/plans/2026-10-05-R-475-code-unit-identity-order.md`, open question 1, raised by the
gpt-6.1-sol r1 review). Pre-existing; R475 fixed only the identity comparators.

**What.** The function in `packages/runner/src/test-order.ts` that ranks a mutant's covering tests
(kills in this procedure, then fewest members covered, then the qualified test NAME) breaks the last
tie with `localeCompare`, which uses the host's DEFAULT collation. Two hosts with different
collations (Danish puts `Aa…` after `Z…`) can run the same covering tests in a different order.

**Why it matters (correctness, not display).** The order decides `killingTest`, `killPosition` and
warm-kill positions, and it can decide the VERDICT: `report.ts`'s `session-warm` contract admits that
an ordered warm prefix can hide a cold kill. So one project measured on two hosts can score a mutant
differently with nothing else changed.

**Measured.** 2 test-name pairs in `fixtures/sandbox-data-tests` order differently under code unit
than under the kraken default (`en`). The Windows host's default collation is not measured.

**To close.** Compare names by code unit (R475's `compareCodeUnits` in `packages/schemata/src/ids.ts`)
or a fixed collation. That can move `itest:tables` and `itest:chunked` `killingTest` /
`killPosition` / `warmKills` pins, so pre-commit the expected per-mutant moves first, then re-record
those baselines deliberately (R332).

**Closed (466bba2a, R-481).** `orderCoveringTests` (`test-order.ts`) breaks its last tie with
`compareCodeUnits` (R475's helper, now exported from `@lethal/schemata`). No identity or scheme
change: this is execution order, not identity.

**No gate figure can move; measured offline, no live gate run.**
- `name-pairs.ts` (coord handoff `R-481/tools`) lists every pair of test methods, by the qualified
  name the ranking compares, in every gate fixture test app, whose order differs between the
  kraken host's default collation (`en`) and code unit. There is ONE:
  `Data Tests.NoTriggerValidateRunsWeak` against `Data Tests.NotBlankFilterCountsOnlyTaggedRows`
  (sandbox-data-tests). Every other test app (sandbox, hang, harden, layout, multiobject, symbols)
  has none.
- That pair can reorder a mutant's covering tests only if BOTH tests cover that mutant. They cannot:
  - `NoTriggerValidateRunsWeak` only validates a field of table `Data No Trigger`, which references
    no other object;
  - `NotBlankFilterCountsOnlyTaggedRows` drives `Data Filter Ops` and writes `Data Related` rows,
    and never touches `Data No Trigger`, which only its own file and the test codeunit name.
- So no covering-test order on `itest:tables`, `itest:chunked`, `itest:bcdev` or `itest:alrunner`
  changes, and no `killingTest`, `killPosition`, `warmKills` or `groupedCalls` pin can move.
- The Windows host's default collation is still unmeasured. After this change it no longer matters
  for this order.

**Tests** (`test-order.test.ts`, "R481"):
- the code-unit order of that pair and of a Danish-style pair (`Aa…`, `Z…`);
- a `localeCompare` stubbed to reverse every comparison, which must leave the order unchanged.

RED-CHECKED: with `localeCompare` restored, both fail.

**Not changed, and not verdict-bearing:** the runner still uses `localeCompare` for report and
console ORDERING (`report-fold`'s outcome order, `report.ts`'s per-file and sorted maps, `cli.ts`'s
dry-run list, `publish-ceiling`'s count order, `stale-test-app`'s list, the al-runner cache's version
fallback). A host with another collation lists those rows in another order. No verdict,
`killingTest` or position depends on them.
