**Found by** lethal-code, PR-508 (2026-11-28), running PR-226's private gate
(`al-runner-v3-update.ts --root /coord/handoff/PR-508/root --local-candidate <build>`) on a local build of upstream main
3b055a520 from a fresh origin/master checkout. Evidence: `/coord/handoff/PR-508/private-gate.log` and the receipt folder
`/coord/handoff/PR-508/root/private/local-cab3e0cb5b45@73fdb1fc5...`.

- **What happens:** the gate worktree is created at `current`'s `.gated` `lethalCommit`, 73fdb1fc5. The update
  script, running master's code, then fills the worktree's fixture `.alpackages` by `prepareFixtureSymbols` from
  master's pinned tar, `fixture-symbols-431354324c23.tar` (re-pinned by PR-483, c42ae0f52, 2026-11-27). The worktree's
  own itest pins the older tar, `165b17dd3aae`, so it refuses at startup:
  `FixtureSymbolsRefusedError: al-runner-v3-gate-symbols-unverified: ... the marker names another tar; its
  .fixture-symbols.sha256 reads 431354324c23..., expected 165b17dd3aae...`. The gate ends `infra-fail: no receipt`
  in about one second, before any leg.
- **Who it reaches:** every gate judged at a `lethalCommit` older than c42ae0f52 while the script runs at master: the
  private gate (PR-226), and by the same code path the daily edge and release gates, `--main` and `--edge-rejudge`.
  Not seen in a daily receipt yet: no new edge has appeared since e5176a9fd (`edge.last-seen`), so the daily run has
  not gated a candidate since the re-pin.
- **Why it matters:** no build can be gated, privately or for `current`, until `.gated`'s commit moves past the
  re-pin. A `--regate` at master would move it, but its own gate takes the same path, so whether it gets through
  depends on which tar its worktree pins (at master: the same tar, so it should).
- **Fix shape (not built):** prepare the gate worktree from the tar ITS commit pins (read that commit's
  `FIXTURE_SYMBOLS_TAR` and `_SHA256`, both still on disk: tars are named by sha and kept), or leave the extraction to
  the worktree's own itest startup, which already does it. A test: a worktree whose pin differs from the script's gets
  its own tar's folders and marker.
- **Related:** R1128 (the re-pin), R614, R670 (sha-named tars kept side by side for older worktrees), PR-226, PR-508.
