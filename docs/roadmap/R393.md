**Found by the R-214 lane (lethal-preproc), 2026-10-01**, while revising R-214 after review round 1.
Evidence: the bogus entry was committed by mistake in `fd0b7795` and reverted in `0448bc0c` on
`lethal/lane-preproc`.

**What happened.** On a busy machine, two tests in `packages/runner/tests/resume.test.ts` ran just
over bun's 5000 ms default limit and were reported as timed out. One of them was the C02-04
characterization test "R192: the resumed run reuses batch 1's baseline snapshot", which ends with
`toMatchSnapshot()`. Bun moved on to the next test, but the timed-out test body was still running.
When it reached `toMatchSnapshot()`, bun filed the result under the name of the test that was
running at that moment, "R325: no verdict crosses an identity-scheme change the report carries the
identity scheme it was keyed under". That test has no snapshot. The run wrote 821 new lines into
the tracked `resume.test.ts.snap` under that wrong name. A re-run passed, and the bad file was then
swept into a commit by `git add -A`.

**Why it matters.** A tracked snapshot file can gain a wrong entry with no failing test in the
end, and a later run will compare against it. It probably also explains the
`orchestrator.test.ts.snap` rewrite that the orchestrator saw on a trial merge of R-214. It links
to R375: both appear when the machine is loaded.

**Fix direction.** Any of these would stop it:
- give the long characterization tests an explicit, larger timeout, so they never time out
  under load;
- run the suite with snapshot writing disabled (`bun test --ci` or the equivalent), so a missing
  entry fails instead of being written;
- add a check that `bun test` leaves no tracked `.snap` file modified.
