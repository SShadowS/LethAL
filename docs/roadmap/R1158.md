**Filed 2026-11-20 by lethal-preproc (coord task PR-267).** Evidence: `/coord/handoff/PR-267/ab-P/` (`events.ndjson`,
`stderr.txt`, `run.log`). The run: PR-241's DO e-document slice on master c62ac71ef, al-runner `current` 4ebfe7913,
3 lanes, `LETHAL_V3_PACK_ENTRIES=64`, no time budget.

**What happened.**
- **The stop worked for the mutants phase.** SIGTERM at 16:44:00Z, 30 min into the run (asked by the orchestrator, to
  free the box for an update gate). The run stopped at its next check: `time-budget-reached`, phases `mutants` and
  `teardown` left, and stderr says `STOPPED BY SIGNAL (SIGTERM or SIGINT): 485 mutant(s) left out of this report`.
- **The process then kept going:** it started a NEW al-runner serve daemon and ran the withheld-kill recheck (PR-144).
  - `recheck-baseline-finished` came 547 s later with `tests: 0, elapsedMs: 547044, verdicts: []`.
  - A second SIGTERM at 16:55Z was not acted on within 30 s; SIGKILL ended it (rc 137).
- **Cost:** about 11 minutes of box time and memory after the stop, during another lane's update gate, and a report
  that never got written.

**Two things to look at.**
1. **After a stop (signal or budget), skip the recheck or end it at once.** Its result cannot change the stopped
   report's missing mutants.
   - Decide whether a stopped report should carry the recheck at all. Today's code ran it, but the process was killed
     before writing, so what it would have done is not observed.
   - A second signal should end the process.
2. **A recheck baseline of 0 tests should cost about nothing.** 547 s for zero tests is a daemon start (DO's full
   instrumented build) plus something else not yet measured.
   - Find what took the time.
   - With no candidate kill, PR-225 already skips the recheck with a warning. Check why this one did not skip: were
     there targets but no tests?

**Not measured:** whether an unstopped run's recheck with 0 tests also takes this long. Look in y3's and perf10c's
`recheck-baseline-finished` events before building.
