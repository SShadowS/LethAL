Reported on GitHub #28 (2026-11-12, coord R-946). Related: [[R680]].

**What happened.** A bcdev run of 1,022 mutants reached 589 decided, then the host rebooted for Windows Update. `--resume-run` refused
with `server-generation-changed` (`ServerGenerationChangedError`, R680): the server reported a new generation, so none of the run's
verdicts was carried. The user started over. The new run's verdicts matched the first attempt's on 588 of 589; the one that differed
was the mutant in flight when the host went down (`error` there, `survived` here).

**Why R680 refuses.** A restart or a force-reset lease can mean the apps and data the verdicts were measured against are gone, so
carrying them would rest on a state no longer there. That is right in general, and the message says what to do ("Drop the flag to
run from scratch").

**The open question.** A host reboot of a BcContainerHelper container with a persistent database usually keeps the published apps, the
test app and the company data. If a resume re-verified what the verdicts rest on (the installed target and test app versions and
hashes, LethAL's own published artifact, the control app version, the company), it could carry the verdicts measured before the
reboot, and redo only the in-flight mutant, which R680's rule would still drop. If the re-verification fails, it refuses as today.
Nothing is decided here; the cost was about 10 h of redone bcdev time in the reported case.
