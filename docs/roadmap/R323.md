**Filed by the orchestrator's ruling on the R-302 plan (2026-09-29, review r1 round).** Plan:
`docs/superpowers/plans/2026-09-28-R-302-split-semantics.md`, open question 3 of revision r1.

**What breaks.** `parseProcedure` (`packages/engine/src/semantic/symbol-table.ts`) records a
procedure's parameters and `var` locals but not its named return value (`procedure P() Result: Text`).
Inside `P`, a reference to `Result` is therefore resolved against the object's globals. When the
object declares a global of the same name with another type, `swap-additive` and
`swap-call-arguments` decide on that global's type.

**Measured** at `1aec1f41`, hand-written repro `n1-named-return-global` (a plain procedure
`Pick(X: Integer) Result: Text`, global `Result: Integer`, body `Result := 'a'; Show(X, Result);`
with overloads `Show(Integer; Integer)` and `Show(Integer; Text)`): HEAD emits `swap-call-arguments`
at the call, and the instrumented project FAILS `alc`, `AL0133: Argument 1: cannot convert from
'Text' to 'Integer'`. The un-instrumented repro compiles.

**R-302 keeps this behaviour for split members on purpose** (parity with a plain procedure), so the
fix covers both shapes at once: index the named return value as a local of its member, and for a
split member apply R-302's every-arm rule (a named return declared by some arms only is ambiguous).

**Size.** Not measured on corpora yet; a named return that shares a global's name should be rare,
but every occurrence breaks the whole run's compile.

**Done (2026-09-29, R-323 run 001; Task 1 `a1f0e093` with review fix `8a2f4734`, Task 2 `48cf8b0e`,

ran (plan Decision 6); the offline proof below stands in for it.

**The rule.** A member's named return value is a local of that member. It hides a same-named global
and is typed by its own declaration. A split member follows the every-arm rule: a named return
declared by only some arms, or with different types, is unknown. In a trigger the named return is
unknown, like every other trigger header name since [[R330]]. An unindexed member's name stays
unknown. Trigger header names are not resolved; that is [[R340]]. A `#if` inside one header is a
grammar gap that yields no mutant at all, and is [[R339]].
