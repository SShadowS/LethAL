Found by coord PR-294 (lethal-code, 2026-11-21), from the combined DO run c1 (`/coord/handoff/combined-do/`). c1 was meant for
`current` main-ccd0f823d, but a reused config pinned `alRunnerV3.path` to edge-4ebfe7913.
- R814's gate accepted the build, rightly: it is gated, and older gated builds are legitimate for A/Bs.
- The one place that named the build was the R834 stderr line `[lethal] al-runner: <path> (<version>)`. It does not say the
  build differs from `current`.
- The report carries the build in its execution contexts, with no comparison either.

**The fix:** when the session's resolved binary is not the resolved `current` link, the v3 backend notifies a named warning
(`al-runner-v3-pinned-not-current`, through `setNotify`, so it is a report warning and a stderr line) naming both builds.
- It is never a refusal.
- It is silent in candidate mode: the update gate runs a non-current candidate on purpose.
- It is silent when no `current` link exists (a user's box).
