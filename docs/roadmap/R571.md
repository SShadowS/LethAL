**Filed 2026-10-10 by coord task R-570** (found on the way, `/coord/handoff/R-570/measure.md`, "Found on the way").
The R531-side twin of [[R570]]. A plausible hang that is NOT refused.

**What.** [[R531]] refuses the consumers of a loop that ends only by consuming its record set. Its HOP follows
only same-object procedures and table procedures on the loop's record R. A consumer in ANOTHER object (a codeunit
that deletes the row it hands back) is not followed, so its sites are deployed. Example in DC Cloud on master
`b163c255`: `CDC Document Card`'s two message-bus loops (`OnAfterGetCurrRecord`, `OnAfterGetRecord`) test
`CDC Message Bus Socket`.IsEmpty in their condition and call `CDC Message Bus Socket`.Pop in their body; Pop
deletes the row. Removing that delete keeps the buffer non-empty for ever.

**Not the same as R570.** [[R570]] refuses a cursor-shaped procedure in another object that the loop's EXIT calls
(its condition, or a body exit guard). Here the condition's callee (IsEmpty) is refused by R570, but the consumer
(Pop) is called in the body, not in an exit, so R570 does not reach it. A consumer that sits in the condition (for
example `TempStack`.Pop in `Item Category Management`) is covered by R570.

**Not measured.** The price and the hang rate; how many loops have a cross-object consumer.

**To close.** Extend R531's HOP to a project procedure in another object that receives R by `var` or reaches the
same table through a global (the Message Bus case: the socket holds its own buffer), price it per corpus, read a
sample, then refuse or close with a ruling.

**The rule.** When R531's same-object HOP finds no target for a body consumer that passes R or calls a procedure
on R, the call is resolved through the shared resolver (`callTargets`, R564's `r531ProcsIn`). Only procedures in
ANOTHER project object are kept.
- A parameter that receives R counts as R. A `var` parameter counts every R531 consumer kind; a by-value one
  only Delete, DeleteAll, Rename and Modify. A parameter named `Rec` is keyed like `Rec.M()` (R570's
  `r531ParamKey`).
- A call on a codeunit or interface variable that the loop condition tests by name (`while not
  Socket.IsEmpty() do Socket.Pop()`) makes every global of the callee's object R, unless the callee shadows it.
  A bare call in the callee to a procedure of its own object that can see one of those globals is a consumer
  too. The helper's own body is not followed.
- Refused in the callee: the consumers and the sites containing them; their guards; every `exit` or `Error`
  that comes before the last consumer or sits inside a callee loop that holds a consumer; every `break` that
  leaves such a loop; the guards of all of these; and the assignments in the callee that feed those guards
  (R531's FEEDS).
- **Caller-side temp-flag skip.** An argument is not followed when it is an alias of R made by assignment
  (`:=`), it is named in no `Copy` call of the scope, and its `temporary` flag and every loop-condition
  receiver's flag are both KNOWN and differ. Known means an explicit `temporary`, or a `Record X` local or
  global (never a parameter) of a project table not declared `TableType = Temporary`. Never skipped: a `Copy`
  alias, a parameter without `temporary`, a record of a `TableType = Temporary` table or of a table outside the
  project, and the callee's globals in the codeunit case (they ARE the set).
- Not followed (each errs toward deploying): a second cross-object hop, the body of the callee's own helper,
  `Codeunit.Run` targets, event subscribers, and objects outside the project.

**Seams.** `r571Seam` (the whole hop) and `r571TempSkip` (the skip alone). Both are on.

**The BC assignment probe** (`scripts/r571-assign-probe`), measured on Cronus28, System symbols 28.0.53667.0,
runtime 17.0:
- (a) Real holds {A,B}; `TempR := Real` on A; `TempR.Delete()`: TempR stays temporary, TempR.Count 0, Delete
  returned No, Real.Count 2.
- (b) TempR holds {X,Y}, Real only {A}; `Real := TempR` on X; `Real.Delete()`: Real stays real, Delete
  returned No, TempR.Count 2, Real 1 before and 1 after.
- (b2) as (b), with X also in the real table: Delete returned Yes and removed the DATABASE row X; TempR.Count
  2, X still in TempR.
- (c) control: `TempB.Copy(TempA, true)`, delete X through TempB: TempA.Count 1, X gone from TempA (shared).
- (c2) `TempC := TempA`, both temporary: TempC.Count 0, Delete returned No, TempA.Count 1 (not shared).

Microsoft Learn is silent on `:=` record assignment; the Record.Copy page is consistent (ShareTable true
shares; false makes them fully independent). Re-open: re-run scripts/r571-assign-probe if BC's
record-assignment semantics are ever documented differently, or when a BC major version moves.
