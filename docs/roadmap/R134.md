**The filter string is a mini-language and no operator can mutate inside it.** `negate-conditional`
targets `comparison_expression` nodes, but `'<>%1'` in `Rec.SetFilter(F, '<>%1', V)` is a string
literal; today the only mutation a `SetFilter` site gets is whole-statement deletion via
`void-method-call`. Measured on the 658-file Document Output snapshot (2026-08-12): **288
`SetFilter` calls — 95 carry `<>`, ~134 a comparator, 43 a `|` alternative list, 14 a `..` range**
(vs 1,279 `SetRange` calls, `remove-setrange`'s population).

Candidate mutations, one mutant per site per the counting rule:

- flip negation: `'<>%1'` -> `'=%1'` (95 sites)
- boundary shift: `'<%1'` -> `'<=%1'`
- drop an alternative: `'%1|%2'` -> `'%1'`
- flip or drop a range bound: `'..%1'` -> `'%1..'`

**Why this clears the admission bar that refused `RemoveSetLoadFields`:** an ordinary suite CAN
kill these — a flipped `<>` inverts which rows a report processes, and any test asserting output
count notices. Kill path is the same data-dependent class as `remove-setrange`, already accepted
for Tier 2 (fixture must seed out-of-filter decoy rows; with only in-filter data the mutant is
equivalent with respect to that data, and that limit gets documented, not hidden).

**What a spec must settle before code:**

1. A small filter-expression parser with a refuse-by-default posture — an unrecognized shape
   produces no mutant, never a guessed one.
2. `%N` substitution integrity: dropping a `|%2` alternative while its argument stays in the call
   changes substitution arity; the operator must either keep arity intact (mutate only shapes
   where it can) or refuse. Renumbering placeholders is forbidden.
3. Identity: the mutated node is the string literal, so `astSubtreeHash` includes literal text —
   confirm dedup semantics against Tier-1 claims on the enclosing statement (expected: coexists,
   same as `swap-call-arguments`).
4. Fixture arms with pre-committed per-mutant verdicts (R82 pattern) and tables-gate growth.

Also decided here, so it is not re-litigated: **`remove-setfilter` is refused** —
`void-method-call` already emits the identical deletion at every such site; a Tier-2 twin adds a
name, not information (same reasoning that closed R11/R13).
