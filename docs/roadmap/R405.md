**Found by the R-378 lane (lethal-preproc), 2026-10-02.** Plan: `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md` §1 B5.

**What happens.** Several project-wide readers treat code under a `#if` as unknown or as present, whatever the build. They do not use R378's `SemanticContext.armOf`. In these cases they REFUSE a site rather than mis-tag one, so mutants are lost and no verdict is wrong:
- **`buildSymbolTable`** (`packages/engine/src/semantic/symbol-table.ts`) does not index a procedure or trigger inside a `preproc_conditional`. Measured on master b1bc7e2e: a table whose `OnModify` sits inside an object-level `#if` gets no forward `swap-modify-flag` mutant on `R.Modify()` in EITHER build (pinned by `packages/runner/tests/r378-member-wide-arms.test.ts`, "A3-gone pin"). The same goes for `OnInsert` in `insert-key-assignment.ts` and `findTableTrigger` in `forced-trigger-raise.ts`, which read direct members only.
- **`receiver.ts`**: `declaresProcedure` and `projectDeclaresProcedureOnTable` count a procedure declared only in an inactive arm, so a built-in call of the same name (for example `Commit`) is refused as shadowed.
- **Structural readers**: `reachLatchRefusals` and `canCarryMutationSelectorVar` read the whole member or file, inactive arms included.

**What would close it.** Make each reader use the arm map where its answer depends on what the build compiles. The R378 test file's "A3-gone pin" then turns into a mutant that exists only under `LETHALX`. That change can renumber identity ordinals (plan r3 §2), so it needs the key diff and possibly an `IDENTITY_SCHEME` bump.

**Part (a) closed by R-405a** (code `bd5ce769`, scheme bump `e91b94b6`; plan `docs/superpowers/plans/2026-10-04-R-405a-arm-aware-symbol-table.md`). What changed: `liveMembers` (with a place, so a member inside a member-level `#if` is read by arm); the symbol table's procedures and globals read through it; `findTableTrigger` and `onInsertTrigger` read through it; the receiver filter skips only members of an inactive arm. Measured key diff: the 21 gate projects capture identically; two new mutants appear in unit fixtures (the R378 `D Tab` forward mutant, and one `swap-additive` in `p-r214.0`); the synthetic twin (a newly admitted `B.Modify()` taking ordinal 0 and moving `A.Modify()`'s key) is a (ii) move, so `IDENTITY_SCHEME` went 7 to 8, pinned by `packages/runner/tests/r405a-identity.test.ts`.

**Part (b) stays OPEN:** `reachLatchRefusals` and `canCarryMutationSelectorVar` still read inactive arms. It is held behind R-307. Related, not covered here: a whole-object `#if` is R343, and `TypeTable` is the new item R429 (unmeasured).

**Part (b) closed 2026-10-05 as a ruling: no change** (R-405b measurement, `/coord/handoff/R-405b/measurement.md`, master 77ff2531, after R-307's PLAN/EMIT split).
- **What a refusal costs.** `reachLatchRefusedOwner` (in `dispatch-plan.ts`) refuses reach latches, not mutants: a refused member's sites are still instrumented and scored, and only lose reach precision ("unplaced"). The refusal exists because a misplaced latch breaks the alc compile of the whole instrumented file. `canCarryMutationSelectorVar` refuses by object kind only (xmlport, query); a member-level `#if` cannot change its answer.
- **Measured:** 82 runs, covering every `fixtures/`/`examples/` project under its gate sets, every r214/r364 unit fixture under its symbol sets, and the CDO copy at 5f2a71d (6 projects, 5,642 members, 55,950 deployed sites):
  - the latch reader refuses **0** members anywhere, so an arm-aware reader would admit **0**;
  - `canCarryMutationSelectorVar` differs by arm in 1 file, r214 `p13-exclusions` `Wrapped`. That is a whole object in `#if`, which is R343's shape, and its sites are already dropped as compiled out. There are 0 member-level cases.
- **Synthetic shapes** (R313, R316, R303, each with the cause only in the `#if X` arm): an arm-aware reader would admit the member under `[]`. But the latch it plans for `[]` fails alc under `[X]` in two of the three (AL0118 for R316, the source's own AL0104/AL0107 for R313). A latch in every arm fails under `[X]` too (AL0519). So an arm-aware version only works if the per-file trial and the real write get exactly the same arm map, which adds a way for them to disagree, for zero measured gain.
- **Limit:** CDO uses `#if` once, inside a code block, so a project that uses `#if` heavily in procedure headers and var sections has not been measured. Re-run the R-405b measurement before reopening on such a project.
- **Side observation** (one shape, not measured further): in the R303 control, a latch placed before an always-active `#pragma` block compiled under both builds. R303's pragma-first refusal may therefore be broader than alc needs, independent of arms. It costs reach precision only, and no real input hits it (0 refusals above).
