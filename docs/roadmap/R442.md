**Found 2026-10-05 by the post-merge gpt-6.1-sol review of R-307** (`/coord/reviews/R-307-002/sol-postmerge.md`).

**1. Recorded keys poisoned by a header refusal (wrong verdict).** When R-307 refuses a file because
its object header cannot be read (`no-header`), the orchestrator reserves no identity ordinals for that
file's mutants (in `generateMutationSet`, the per-file refusal path). Its `carryDisabled` protection
covers only the current run. The keys it records are still written to the store, which later returns
those survivors (the known-survivors reader in `store.ts`) with no memory that the run was ambiguous.

Sequence: an alphabetically earlier `Bad.al` holds a table `"Twin"` whose header follows `namespace X;`
on the same line, so it is refused as `no-header`. `Good.al` holds a codeunit `"Twin"` with the same
procedure and mutation subtree. Good's mutant takes ordinal 0 and survives. Now add a newline before
Bad's header, changing neither subtree. Bad's mutant takes ordinal 0 and Good's takes 1. With scheme 9,
the same symbols and tests unchanged, `--skip-known-survivors` skips Bad's mutant using Good's verdict.

**2. EMIT's import allow-list ignores external imports.** The R-307 boundary test
(`packages/schemata/tests/refusal-sites.test.ts`) drops non-relative, non-workspace imports before
checking them, so `import { readFileSync } from "node:fs"` plus a missing-file read in an EMIT module
passes both the import allow-list and the zero-`throw` check, although it adds an exception only a real
write can hit.

**To close.** (1) Make keys recorded in a run with a header refusal unusable for later carry (taint
them in the store, or skip recording the affected tuples), or reserve ordinals so the refusal cannot
shift them; pin the Bad/Good sequence end to end, red-checked. Say whether IDENTITY_SCHEME must move.
(2) Reject unlisted external value imports in EMIT modules; red-check with a planted `node:fs` import.
