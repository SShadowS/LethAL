Found by coord task R-881 (BC.History on al-runner v3, edge-05d692e5e). Evidence: `/coord/handoff/R-881/` (`r2-*.events.ndjson`,
`result.md`). Related: [[R885]].

**What.** al-runner runs .NET types through a separate process, the sidecar, named with `--dotnet-sidecar <dll>`. Without it, a test
that reaches a .NET type is refused: "dotnet-unavailable: DotNet 'System.TimeZoneInfo' sidecar not built; run 'dotnet publish
tools/dotnet-sidecar ...' and pass --dotnet-sidecar ...". LethAL has no config field for it and never passes the flag.

**How much.** With demo data in the cache ([[R885]]), the CRONUS setup sends ordinary posting and setup paths through .NET time zone
and URI types. Round 2's baselines: PaymentPractices 29 of 36 tests refused (`System.TimeZoneInfo`), BankDeposits all 75 (TimeZoneInfo
56, `System.UriKind` 9, `System.DateTimeOffset` 3, the rest cascades and R-881's SaveAsXml refusal), ServiceDeclaration 54 of 61
directly or by cascade. Without demo data, BankDeposits still had 37: 15 refused on `System.DateTimeOffset` and 22 by cascade.

**What a fix needs.** A config field (for example `alRunnerV3.dotnetSidecar`) passed through to every al-runner process, one-shot and
serve; checked by `doctor`; in the run's cache key if it changes results. Building the sidecar needs a .NET SDK, and its build must
match the al-runner build, so where it comes from (shipped with the gated build, or built by the update script) is a decision to make
first.

**Decision (owner, 2026-11-09).** The update script builds it. Measured: `tools/dotnet-sidecar` is in al-runner's source only (not in
the release or edge files); `dotnet publish` of it works with the SDK at `/opt/dotnet` (10.0.403) in about 6 s with no NuGet download,
as long as it is run from a folder that does not hold the source's `global.json` (it pins SDK 8).

**Built (branch `lethal/r886`).** The update script builds the sidecar after a build passes and records it in `.gated` and the
manifest row (a failed build gates anyway and is noted); `alRunnerV3.dotnetSidecar` (path, or `false`) is passed as `--dotnet-sidecar`
on the one-shot and serve paths and defaults to the pinned build's own; `doctor` warns when it is missing. The gates set it `false`,
so no figure moves. Not done: the BankDeposits re-run on v3 with demo data and the sidecar (part 3) is a live measurement still to be
made. The item stays open until then.

**Resume (branch `lethal/r886-fp`).** `--resume` and `--resume-run` refuse a run whose recorded sidecar (dll sha256, or `none`) or
`downloadDemoData` differs from this session's, naming which changed and from what to what. The values live in a new `runs.resume_inputs`
column, not in `config_fingerprint`, so every older fingerprint is unchanged and a bcdev run (which records nothing and checks nothing)
resumes as before. A v3 run recorded before this change has NULL there; it is refused by name ("did not record its al-runner-v3
settings"), because the settings cannot be proven and `downloadDemoData` has changed meaning twice (R885). Baseline-snapshot reuse is not
checked for these two settings.
