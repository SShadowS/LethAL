**Filed 2026-10-18 by coord task R-583** (lethal-code), on the owner's ruling of that day: "all to 17. For now we
don't care about the old versions; that might come after the release of LethAL, when we want backwards
compatibility."

**What.** Until LethAL is released, every app it builds or tests is assumed to declare `runtime` 17.0 or
newer (BC 28). The repo's own fixtures, examples, probe apps and the LethAL Control extension all move to 17.0
under [[R583]]. A user app below that is REFUSED by name where LethAL knows it cannot work. LethAL does not fall
back to anything for such an app.

**What is known to break below runtime 17, so it is not lost:**
- **Below runtime 14.0: the al-runner resource selector.** `emitResourceSelector` (in `schemata`'s `selector.ts`)
  calls `NavApp.GetResourceAsText`, which needs runtime 14.0. alc gives `AL0666` below that. From upstream
  al-runner f23b9b5f on, al-runner compiles at the app's own `runtime` and drops the selector, so every test
  fails ([[R583]]).
  - Since R387, the CLI default on al-runner is `--server` plus the resource selector.
  - R583 replaces the silent failure with a refusal that names both ways out: raise `runtime`, or set
    `alRunner.selectorMode` to `static`.
  - **Since R654 (2026-10-23)** the .NET al-runner, its `--server` default and the `alRunner` section are gone
    (R654 S3, 35f3c67f). The resource selector is now used only by the Rust al-runner's opt-in `serve-entries`
    transport (R635), which keeps the same check (`assertResourceSelectorRuntime`). The default `one-shot`
    transport uses the static selector, so it is not affected. The refusal's text still names
    `alRunner.selectorMode static` as a way out, which no longer exists; on v3 the way out is the default
    transport.
- **Runtime 14.0 to 16.x:** nothing known yet. LethAL's own tests no longer run at these runtimes, so a break
  here would not be seen.

**To close (after release).** Decide which runtimes to support. Then, for each one:
- pick per backend: a fallback (for example the static selector below 14.0) or a stated refusal;
- add a fixture at that runtime to the gates, so it is exercised live.

**A static-selector fallback was planned once, then dropped.** R-583's first plan had it, before the owner ruled
out backwards compatibility for now. Its review (`/coord/reviews/R-583-plan/adversary-r1.md`) is the starting
point if it comes back: decide the selector mode ONCE at deploy, read the runtime from the `app.json` al-runner
compiles, compare versions as numbers, and refuse when `selectorMode` was set explicitly.
