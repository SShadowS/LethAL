**Filed 2026-10-22 by lethal-orchestrator** on the owner's decision ("Think we can retire the .net runner").
Related: [[R586]] (the v3 backend), [[R541]] (a .NET-only false kill, to be closed by this item).

**What.** LethAL has two al-runner backends: the frozen .NET build (v2, `al-runner-backend.ts` and
`itest:alrunner`) and the Rust runtime (v3, `al-runner-v3-backend.ts` and `itest:alrunner-v3`). Upstream has
moved to v3, and the .NET build gets no updates. Keeping v2 costs a gate on every change that touches shared
runner code, and it carries known defects that only v2 has (R541).

**The catch.** v3 is not a separate module: `al-runner-v3-backend.ts` and other files import from the v2 code
(`al-runner-backend.ts`, `al-runner-server.ts`, `al-runner-contract.ts`, `al-runner-coverage.ts` and others). Some
gate legs exist only for v2 (the layout and wrapped legs, the symbol-set pair in `fixtures/sandbox-symbols`).
CLAUDE.md, the gate pages and several skills describe v2.

**To close.**
1. Measure first: the inventory of every v2-only file, export, CLI path, config value, gate leg, fixture,
   doc and skill; which of them v3 uses; and which v2 gate legs check behaviour v3 also needs (port them to
   the v3 gate, or rule them out).
2. A plan, with one deep review, that removes v2, keeps what v3 uses, and makes a config or a stored run
   that names the old backend refuse by name (no back-compat before release, per the owner).
3. The CLAUDE.md edits need the owner's confirmation before they land.
4. Close R541 by this item.

**F2 landed 2026-10-24 (coord task R-654f, lethal-code); this item is closed.**
- **The prerequisite.** The owner removed the `alRunner` section from the four host-side templates on 2026-10-24
  (sandbox-app and sandbox-data, `.local` and `.agent`). The orchestrator removed it from the 12 lane container copies
  the same day.
- **The refusal.** `loadLethalConfigFile` (cli.ts) refuses a config with a top-level `alRunner` key by name
  (`refuseRetiredV2ConfigSection` in `v2-retired.ts`, `AlRunnerV2RetiredError`). The message names the file and
  R654, and points to `--backend al-runner-v3` and the `alRunnerV3` section.
  - It runs right after parsing, before any server call, publish or lease, on every user command that loads a
    config: `run`, `--dry-run`, `doctor`, `verify`, `clear-ceiling`, `force-reset-lease`.
  - An empty `alRunner: {}` is refused too.
- **Removed:** the `LethalConfigFile.alRunner` field, kraken-secrets' `alRunner.alRunnerPath` mapping, and the
  resource selector's advice to set `alRunner.selectorMode` (that last one in the F2 review fixes, 4e39ce47).
- **Tests:** "R654 F2" in `packages/runner/tests/r654-v2-retired.test.ts`, red-checked both ways (the call removed
  turns the refused cases red; refusing every config turns the control red).
- **Stated limits (developer tools, not user commands):**
  - The live itests read their fixture configs with their own reader, so a fixture config with the section would not
    be refused there. `bc-linux-setup.ts` writes those configs without it.
  - kraken-secrets copies an `alRunner` section through unchanged. A host path inside it stops as a leftover host
    path, and the loader refuses the section either way.
  - A re-provision from a host template that still had the section would bring it back: the templates must stay
    clean.
