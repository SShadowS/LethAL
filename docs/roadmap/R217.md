**This row is about the maintenance of one predicate, not about either of the sites it has missed.**
Those have their own rows ([[R216]] and [[R214]]). It is filed because two independent omissions in
the same list, found by the same instrument within a day of each other, say something the individual
rows do not.

## What happened

`isStatementPosition` accepts a node as a statement when its parent is `statement_block` or `block`.
`isStatementSlot` widens that with `SINGLE_STATEMENT_SLOTS`, a hand-written set of
`<parent>.<field>` pairs naming the places AL allows one unbraced statement. Both live in
`packages/engine/src/ast/tree-walks.ts`.

The issue #6 context probe compares that predicate's ANSWER against the AL compiler's own
(`InvocationExpression` whose parent is `ExpressionStatement`). In two runs it found two containers
the list does not know about:

| container | found on | direction | cost today |
| --- | --- | --- | --- |
| `asserterror_statement.body` | `BusinessFoundation`, 35 sites | under-claim | none: `asserterror` is test-only across all 16,898 files ([[R216]]) |
| `preproc_conditional_statement` | BaseApp, ~394 direct children | under-claim | none on any fixture; real on an app using feature flags ([[R214]]) |

Both are under-claims, both are one-way, and in both cases `tree-sitter-al` shapes the construct
correctly. The grammar is not the problem in either case: LethAL simply draws "statement position"
more narrowly than AL does, in places nobody thought to enumerate.

## Why the pattern matters more than the two instances

The set is grown REACTIVELY. Its doc comment is careful and names what it deliberately excludes
(a `case_else_branch`, a `repeat` body) with reasons, which is good practice and is exactly why the
two omissions above read as oversights rather than decisions: neither is mentioned anywhere, in the
set, in the engine, or in any operator.

The failure mode is quiet in a specific way that matters here. A missing container costs SITES, and
a site that is never enumerated produces no mutant, no warning, and no line in any report. It cannot
show up as a wrong verdict, because there is no verdict. Every gate stays green. [[R159]]'s census
counts the kinds tree-sitter reports and so cannot see it either, because the nodes are all present
and correctly shaped, sitting under a parent nobody asked about. That is why both omissions survived
until an instrument was built that asks the compiler what it thinks instead.

Two found in two runs is also weak evidence that two is all there is.

## What would close it

Not "add the two containers", which is what [[R214]] and [[R216]] each propose for their own case
and which leaves the list exactly as hand-maintained as it was. The options, cheapest first:

1. **Pin the gap at zero on a corpus.** Run the context probe over the reference corpora in a test
   and assert the two counts are equal, so a NEW container omission fails a gate instead of waiting
   for someone to run the audit. Cheap, and it turns a one-off instrument into a standing one. It
   needs a corpus the test can reach, which is the part to think about, since `U:/Git/BC.History` is
   a local checkout rather than something the repository carries.
2. **Derive the list from the grammar** rather than writing it out: enumerate the node types that
   have a single-statement field and generate the set. Right in principle, and it depends on the
   grammar exposing enough structure to distinguish a statement slot from any other field.
3. **Widen the probe past calls.** It currently asks the question only for `call_expression` /
   `InvocationExpression`. `remove-assignment` gates on the same predicate, so the same omissions
   cost assignment sites too, and nothing measures that. This is the cheapest way to learn whether
   two is really all there is.

Option 3 is the one that answers the open question, and it is worth doing before either of the
others, because it decides how much the others are worth.

## Evidence

`scripts/probe-grammar-crosscheck.ts`, the `CONTEXT_PROBES` table in `scripts/lib/al-kind-mapping.ts`
(which explains why the context dimension exists at all: a grammar upgrade once inserted
`statement_block` containers and took statement-position call sites from 703,239 to zero with every
node still present at the same offset), and the two rows above for the per-site measurements.
