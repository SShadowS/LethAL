**There is no way to tell LethAL "do not mutate calls to this method".** Stryker.NET has
`ignore-methods` and it is the feature a BC developer asks for first, because telemetry and UI calls
are unobservable by construction and every one of them is a guaranteed survivor. **CLOSED
2026-08-26 — designed in full, measured against real AL, and refused on VALUE.** Probe:
`scripts/r174-ignore-methods-probe.ts`; measured on `do-lethal/Cloud` (554 files, 38,209 raw specs)
at the pinned campaign commit `5f2a71d` (`docs/campaign/2026-08-03-do/manifest.md`). Design that was
refused: `docs/superpowers/specs/2026-08-26-excluded-sites-and-report-schema-design.md` §"What R174
would have added".

**The proposed rule.** A `lethal.config.json` `"ignoreMethods"` glob list, matched
case-insensitively against the callee AS WRITTEN (`Name`, or `Receiver.Name` where the receiver is
the variable name, since the engine resolves receivers to tables only and never to codeunits). A
spec is dropped when its `before` span lies within a matching call's span.

**Measured saving, both ends of the plausible range.** Telemetry only (`*.LogMessage`, `Message`,
`CustomDimensions.*`): 130 matched calls, **147 of 38,209 raw specs, 0.38%**. Adding UI predicates
(`Confirm`, `CurrPage.*`, all three telemetry receivers): 526 calls, **648 specs, 1.70%**. R13's
already-calibrated bar for a candidate needing a NEW activation mechanism is **5%**, and this needs
a new config surface plus a report-schema change. Both figures are an order of magnitude below it.
The bar was not pre-committed for this candidate, which is a weakness of this measurement and is
recorded rather than hidden; R13's bar is cited because it was calibrated before either number here
existed.

**The saving and the harm are the same lever, which is the reason it is refused rather than
deferred.** Every call-claiming operator sets `before` to the `procedure_call` node itself, so
STRICT containment drops only 15 of the 147 and the feature does nearly nothing; inclusive
containment is forced. Inclusive is then what reaches guards: the aggressive set drops **88 specs
inside non-statement-slot calls, 27 of them `negate-guard` mutants at exact span** — `if Confirm(…)
then` and `if CurrPage.Editable then`, real branches whose mutant vanishes with no record. So the
extra 1.3% over the safe set is bought by deleting mutants on live logic. A filter whose unsafe
direction is the permissive one, in a tool whose signature bug is empty-vs-empty.

**Two findings worth keeping even though the feature is refused.**

1. **`Session.LogMessage` matched NOTHING** on a project that unquestionably does telemetry — DO
   wraps it in `Telemetry`, `TelemetryMgt` and `TelemetryLogger`. The first pattern a user would
   write is a silent no-op, which is why any future version of this must report the distinct callee
   STRINGS each pattern matched, never a bare count.
2. **43% of calls (7,609 of 17,596) are not in a statement slot**, so `void-method-call` never
   claims them and they leave NO trace in any `SessionReport`. Any future measurement of a
   call-site feature has to parse source; a report-based one is structurally blind to nearly half
   the population. This is what made the first estimate here wrong by a wide margin, and it is the
   transferable lesson.

**The excluded-sites spine this was going to justify is being built anyway**, for the report-schema
work that needs the same record. See the design above.

**Reopen if** a project measures >=5% of raw specs behind a pattern set that matches only
statement-slot calls (which is the safe subset: on DO the safe set swallowed zero guards), or if
per-site suppression arrives some other way and this becomes a config spelling of it rather than a
new mechanism.
