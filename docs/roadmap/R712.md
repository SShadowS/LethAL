**Filed and closed 2026-10-24 by R-705 (lethal-bugs)**, evidence `docs/measurements/r706/` and [[R706]].

**The question.** R706 measured two different texts for the same unhandled `HttpClient.Get('http://localhost:1/x')` on
bc1: the web-service path (runner 130450, how LethAL's bcdev backend runs tests) reads "The request was blocked by the
runtime to prevent accidental use of production services."; the test runner hub path (VS Code, `bcdev_test_run`, a
user's CI) reads "There was an error while executing the HTTP request, the connecting endpoint violates security
requirements. Make sure you are connecting to a valid endpoint." (`HttpRequest:Security`). al-runner v3 alpha.4 and
later write the second. Which one is "BC's" reading for `refusal-row-shape`?

**Ruling (owner, 2026-10-24).** The test runner hub path. It is what a developer and their CI see.

**Effect.** `BC_HTTP_HUB_TEXT` is the oracle: `refusal-row-shape` reads `gone` on exactly that text. A build that writes
the web-service text (`BC_HTTP_INTERNAL_TEXT`, kept) reads `unlike-bc`, like any other text. alpha.2's refusal row still
reads `defect-present`. See `docs/gates/alrunner-v3.md`. The bcdev side of the difference is [[R713]].
