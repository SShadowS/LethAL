**Found by TSAL-441 Task 3**, while censusing the tree-sitter-al 4.3.0 -> 4.4.1 grammar bump end to
end (`docs/superpowers/specs/2026-09-27-tsal441-grammar-bump-precommitment.md`'s AMENDMENT 1;
`packages/engine/vendor/README.md`'s "4.3.0 -> 4.4.1" section, "Census-stability deviation").

**What happens.** `census-operator-sites.ts` parses every file into a tree-sitter tree and keeps
every tree alive for one semantic context shared across the whole run. Pointed at
`U:/Git/BC.History/BaseApp` (9,620 files), it aborts after about 20 seconds with
`RuntimeError: Aborted()` inside web-tree-sitter and writes no output file. A scratch parse probe
narrowed the cause: keeping every tree, the process aborts between file 9,000 and 9,500 (roughly
164 M characters parsed); deleting each tree right after it is used, all 9,620 files parse cleanly.
So it is wasm heap exhaustion from retained trees, not a bad file or a grammar defect.

**How this has been worked around, twice.** The earlier tree-sitter-al 4.3.0 bump's census only ever
covered `BaseApp/Source` (8,020 files); `BaseApp/Test` (1,600 files) was never censused at all.
TSAL-441 ran the two halves separately, `BaseApp/Source` and `BaseApp/Test`, each stable at 0/0
only-in-A / only-in-B across two runs under the same grammar. Both are workarounds, not a fix: they
avoid the crash by never holding all 9,620 trees in one context.

**The blind spot this leaves.** A Tier-2 operator's claim in a `BaseApp/Test` file that resolves a
symbol declared in `BaseApp/Source` is judged without `Source`'s declarations in scope, because the
two halves never share a semantic context. A grammar or engine change that alters how a `Source`
tree shapes a `Test`-side Tier-2 resolution would not show up as a moved row in either half. Every
row TSAL-441 measured moving end to end came from a Tier-1 operator, so this run did not exercise
the gap, but the split instrument cannot rule it out, and the same split will be needed for every
future grammar bump this census runs against all of BaseApp.

**What would close it.** Either make the census release each file's tree once it has extracted what
it needs (so retained memory stops growing with file count), or split the semantic context itself
into two passes: a first pass that only builds and keeps a cross-file declaration index, and a
second pass that parses one file at a time against that index and discards the tree immediately.
Either fix removes the need to run BaseApp in arbitrary halves and closes the Tier-2 cross-half
blind spot along with it.

**Reproduce.** `bun scripts/census-operator-sites.ts "U:/Git/BC.History/BaseApp"` aborts after about
20 s and writes nothing. Running it separately on `BaseApp/Source` and `BaseApp/Test` succeeds.
