**Filed 2026-11-05 by lethal-preproc, from coord task R-806.** Related: [[R783]], [[R589]].

**What.** The owner's restart of 2026-11-05 moved the worktree configs to `bc1` on server1 (`192.168.2.157`). Master's
`DEFAULT_BC_HOST` still named docker1, so every gate would have refused those configs with `BcHostMismatchError`.

**The default (done on lethal/r806).** `DEFAULT_BC_HOST` is `BC_HOSTS.server1`, by the same route as R783's runbook.
Its tests and the bc-demo pin moved with it. The tests that name a host through `LETHAL_BC_HOST` did not need to.
`docs/gates/servers.md`, `fixtures/README.md` and the autonomy runbook name server1.

**After it merges**, each worktree that holds configs reruns `bun scripts/bc-linux-setup.ts --server bc1
--write-config-only` (no server call), or the setup itself under a lease. `--write-config-only` does not check the
server's build: it names the newest cached symbol dir for that server, and every bc1-bc3 dir dates from 22 October. If
server1's `bc1` now runs another build, gates would compile against old `System` symbols. So the first run on server1
is the FULL setup, which reads the server's build and fills a new dir if it differs; the configs that writes are the
ones to use.

**What is measured.** Only a port check, by the orchestrator at 16:50 UTC on 2026-11-05: TCP ports 7049, 7149 and 7249
on `192.168.2.157` accepted a connection. That shows open ports, not a working BC, and not which build. Nothing else
is measured: this lane has called no server, because no lease was possible. The task text's "server1's BC ports are
closed" predates the restart.

**Open.**
- **No server is allocated.** `kraken coord lease bc1 preproc` refuses: "bc1 is not allocated to any project; ask the
  owner", and `/coord/machine/allocation.json` reads `"lethal": []`. Allocation is the owner's.
- **Nothing is proven on server1 under today's fixtures.** The proof tables are per host. Once `bc1` is allocated: full
  setup, doctor, `itest:bcdev`, then each gate that runs on `bc1`, adding its row to `servers.md`. Not every gate can:
  `itest:hang` refuses `bc1` (`r658-hang-gate.sh`), and the Continia stack is `bc3`'s. Those wait for `bc2` or `bc3`.
- **The owner named only `bc1`.** Leave `bc2` and `bc3` until the owner says.
- **"Every BC gate is proven on all three servers" (R604) is out of date for server1**, in CLAUDE.md and in the
  autonomy runbook. The runbook now marks its copy as history; CLAUDE.md is the owner's file to change.
- **bc-demo:** `bc-demo-setup.ts` probes server1 again, and whether bc-demo answers there is not measured. If it
  answers, the script goes on to set it up, with no lease (R663). On docker1 it stopped at the probe. **Nobody runs
  it until the owner rules on bc-demo** (orchestrator, 2026-11-05).
