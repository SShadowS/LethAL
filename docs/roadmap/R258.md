**What.** `planVerify` runs a survivor's covering tests from the source run plus the tests that are
NEW by identity (codeunit and method) against the source run's baseline. An EXISTING test that did
not cover the mutant in the source run, edited so it now would, is neither: verify never selects it,
so an agent's edit there is invisible to verify. The agent reference's "Writing the killing test
(guidance)" section already names this blind spot.

The other half of the original item, an edited COVERING test that is selected but never given the
new-test double run, was split out as R278 on 2026-09-27.

**Evidence.** `planVerify` (`packages/runner/src/verify.ts`), and the "Writing the killing test
(guidance)" section of `docs/using-lethal-from-an-agent.md`.

**What would close it.** Verify learns which existing tests changed (a per-test body identity) and
runs those too.
