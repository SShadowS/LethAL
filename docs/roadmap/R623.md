**Filed 2026-10-22 by lethal-bugs during R-599** (plan r3, row 6).

**What.** R599 makes both scripts decide by content. When the server holds a fixture at the SAME version as the
local build but with other content, they publish it in place over the dev endpoint (`dev/apps`, ForceSync, no
unpublish). That case is measured for a TEST app: R-599's live check run 1 on bc3 (2026-10-22, build 42c7dc7b,
steps 4 and 5, `/coord/handoff/R-599/live/4-in-place.log` and `5-back.log`) published Sandbox Names Tests in place
and back over `dev/apps`, each time read back byte for byte with exactly one installed row whose `packageId` was the
new build's header id, and `itest:bcdev-names` then passed on it. Run 2 on the final head (d89d6eb4,
`/coord/handoff/R-599/live/run2/4-in-place.log` and `5-back.log`) repeated it: packageId 6d81872d-… then a7c407c8-…,
installed each time, read back byte for byte, and the gate passed again. `itest:testapp` steps 6 and 7 do the same
through altool. It is NOT measured for a TARGET that another
installed app depends on: BC might refuse the publish, or replace the target under the installed test app in a way
nobody has looked at. So `decideApp` refuses it as `refuse same-version-target`, naming the installed dependent.
The lookup runs over every fixture manifest in both modes, so `republish sandbox-app` with `sandbox-tests`
installed is refused too.

**Who hits it.** Anyone who edits a target fixture's AL without bumping its app.json version and then runs setup or
`republish <target>` on a server where its test app is installed. Today's remedy, printed with the refusal: bump the
target's app.json version (an ordinary upgrade), or ask the owner.

**To close.** Measure it once on a lane's own server: a same-version target with other content, published in place
over `dev/apps` with its test app installed, then read back (rows, `isInstalled`, the dependent still installed,
the gate that uses it still passing). Then either allow row 6's case through to row 7 or keep the refusal with the
measurement as its reason.

Evidence: `scripts/bc-app-content.ts` (`decideApp`, row 6), its tests "row 6" and "F4" in
`scripts/bc-app-content.test.ts`, and the plan `docs/superpowers/plans/2026-10-22-r599-app-content-decision.md`.
