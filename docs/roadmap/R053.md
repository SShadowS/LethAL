**A mutant that makes a test hang is indistinguishable from a stranded operation, so it quarantines instead of scoring `timeout-killed`** — and it blocks every mutant after it. Measured on Document Output: **M0013 is `negate-conditional` on `until DOCustSetup.Next() = 0;`**, which becomes `<> 0` and never terminates. This is a mutant the suite arguably DOES catch (design §6.7: a timeout counts as killed, since the mutation caused observable misbehaviour), but LethAL only sees its own client-side abort, which it must treat as `in-flight-unknown` because BC may still be executing. Raising `--mutant-timeout-ms` cannot help: 180 s and 330 s both aborted, and 360 s is the hosting proxy's own ceiling. **This is what blocks R37 on this codeunit** — the sweep dies at mutant 13, so 125 of 138 mutants have never run. The fix is server-side: `RunMutant` must enforce its own time limit inside AL and RETURN a terminal `timed-out` result, which is a completed operation the client can score, rather than leaving the client to guess from a severed connection. Needs an AL change plus a protocol version bump.
