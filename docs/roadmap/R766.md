**Filed 2026-10-25 (coord task R-766).** Plan: `/coord/handoff/R-766/plan.md` (r2). Built on the serve-entries
default of [[R761]]. [[R760]] measured where the time goes; one serve daemon runs one mutant at a time.

**Design.** One `AlRunnerV3Backend` owns N lanes. A `Lane` holds the per-daemon state: the daemon and its close,
`lastActivated`, `rowsByCodeunit`, the kill `pair` and `pairVerdict`, the covering `plan`, `deployedDir`, the lane's
own real `active` dir, `activeDir`/`resourcePath`/`scratchCwd`/`requestBase`, and its own stats timers (summed in
`entriesStats`). Shared: the prefetch map, the warm-up `union`, both latches (`batchBlind`, `entriesRefused`), the
baseline rows, `testsPerCodeunit`, the echo id, the alc proof, the coverage index, the contract probe and the
transport config. Lane 0 uses `active/`; lanes 1..N-1 use proved copies `active.<k>/`, checked by hash and by
`assertBound`. Every `deploy` closes all lanes and re-copies. Each lane also gets a view of the shared Sleep index
re-keyed to its own root (step b). The serve coverage window, `inWindow` and the second echo stay on the backend in
step (a), by ruling: [[R762]]'s item B removes them first. Before the proof: a probe for state a serve daemon carries
across entries and requests, and a `mutantCode` tie-break in the report's (file, startIndex) order.

**Rulings (orchestrator, 2026-10-25; all CONFIRMED, plan r2 accepted).**
- Lanes pull whole procedure scopes (all mutants of one scope, in manifest order, on one lane), so the R197 kill
  ledger gives every mutant its N = 1 test order: `killingTest` and verdicts cannot move with timing.
- Under N > 1 the first `batchBlind` or `entriesRefused` latch (or any session-stopping throw) closes the queue.
  Mutants finished before the stop with a manifest index below the latching one are kept, and the latching mutant
  itself; everything else is discarded, never recorded, and the stop names the cause. N = 1 is unchanged.
- The warm-up `union` is order-dependent, but it only picks which codeunits a restarted daemon warms (fail-closed),
  never a verdict: accepted.
- `--workers > 1` with any transport but serve-entries is refused by name. No `--workers` means N = 1 everywhere.
- The default N and the heavy-job weight come from the RSS and thread measurements, not a guess.

**Steps (each its own submit).**
- (a) Pure refactor at N = 1: a trace test over the old code first (request bodies, closes, stats, verdicts), then
  the `Lane` move with no test change.
- (b) `lanes(N)`, `active.<k>/`, the queue, behind `--workers N` for v3 only.
- (c) Proof, pre-committed on master. Owner fast-track ruling (2026-10-25): D1 and the gift card at N = 1 and N = 4,
  once each (no N = 8, no repeats, v3 only); D1 at N = 4 per-mutant equal to N = 1 is required. The N > 1 hazards
  (a shared `plan` or real dir, prefetched rows on the wrong lane) need (b)'s own unit tests: the (a) trace runs one
  lane and cannot see them.

**Step (b) built (plan r3).** `AlRunnerV3Backend.lanes(N)` builds N lanes and returns N lane views; the root backend
is the owner. Lane 0 uses `active/`; lanes 1..N-1 use `active.<k>/` copies made in `deploy()` after the proof
(`cp` with preserved timestamps, then `assertBound(lane)`; a copy that differs refuses by name). Every `deploy()`
closes all lane daemons and re-copies; `close()` closes all. Each lane has its own cwd `daemon-<k>/`, daemon,
`plan`, `pair`, `rowsByCodeunit` and real dir. A lane view runs `activate`, `run`, `sendKillPair`,
`useCoveringBudgets` and `survivorNote`; every owner method throws by name on a lane, and the root's per-mutant
methods throw once lanes exist. The batch's baseline runs on lane 0 (`splitBackend`). The owner prefetches the whole
batch once on lane 0 (the N = 1 grouping) into the shared map; any lane consumes a mutant's rows once.
`parallel-queue.ts` holds the pull queue (one index closure over procedure scopes) and `OrderedCommit`: a finished
mutant is recorded only when every mutant before it is, so records and `mutant-scored` events come in manifest
order. The stop rule (first `batchBlind`/`entriesRefused` latch, or any session-stopping throw) keeps the mutants that
FINISHED before the stop and come before the stopping one in manifest order, plus the stopping mutant only if N = 1
would have recorded it (a latcher, or a throw AFTER its record; a throw BEFORE its record discards it). Everything
else is discarded, including earlier-index mutants still in flight at the stop. It then ends the session with a
`ParallelStopError` naming the cause and the discarded codes. `report-fold` breaks (file, startIndex) ties by
`mutantCode`.

**Gates on `--workers > 1`.** Refused by name: above 8; any transport but serve-entries; and a build whose pin does
not retire the §6 Sleep rule ("parallel v3 needs a build whose pin retires the §6 Sleep rule"). On master the last is
`AlRunnerV3Backend.sleepRuleRetiredForParallel()`, which returns false until [[R768]] wires it to `sleepRuleRetired`,
so `--workers > 1` is refused on every build today. `sleepRuleRetired` keys on the build's pin: **a new al-runner
build needs its own pin before `--workers > 1` is allowed on it.** A lane beyond lane 0 starts only with 10 GB
available (one notice when held); before the lanes start, the largest n of N with n x 2.3 GB + 10 GB available
runs (a serve daemon peaks about 2.2 GB RSS on D1; `LANE_RSS_BYTES`, `LANE_MIN_AVAILABLE_BYTES`; one notice names N
and n). Not built here: the daemon carry-over probe (a user SingleInstance counter across
entries and requests), which step (c)'s pre-commitment still owes before any N > 1 figure is trusted; and the N
default and RSS/thread measurements. This item stays open until (c) is proven.
