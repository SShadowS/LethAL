**Why this family.** After #7415 (family 3), the ledger's largest open issue is #7854: 843 open sightings over 16 causes (next:
#7819 541, #8028 429; counts from `/coord/handoff/PR-13-ledger.txt`). Its own six "a permission denial (...) whose error is not
pinned yet" causes hold 493 of them, the largest the "on a system table" one (234). Corpus tests deny through Microsoft's Permissions Mock (as Library - Lower Permissions does).

**What was built.** `scripts/refusal-family.ts` family `permission-denial`: for each of the 83 platform tables whose plain read
runs on al-runner (R1022's run), `IsEmpty` and `FindFirst` after `PermissionsMock.Set` of a set that does not grant the table
and of one that grants it Read. The app depends on Permissions Mock (`Family.dependencies`, new). `classOf` folds the object a
denial names, and a set's rows read through a system table (`<table>: permission set '<set>': ...`) to their reason.

**Result on edge-5a58a0f16** (332 cells): 178 pass, 154 refused, 0 fail.
- Not granted: 150 cells (75 tables) are #7854's known class, `IsEmpty` as much as `FindFirst`. Tenant Media (2 cells) gets
  another wording ("probe P13 pins Tenant Media writes only"). Seven tables run when not granted (Date, AllObj, Field, Windows
  Language, Time Zone, Tenant Profile, Page Control Field); BC not measured for them.
- Granted: 164 of 166 run; `Permission` (2 cells) is refused because Permissions Mock's own `All Objects` set grants
  `table * = X` (#8032's class, met through Permission).
- A separate suspect for a later BC differential: `Integer` (a virtual table, like Date, which runs) is among the 75 refused when
  not granted; on BC a virtual table is usually readable without a grant, so its refusal may be a different al-runner gap.
- BC's answer is inferred, not measured: upstream measured that a `FindFirst` without Read permission errors even with no row
  (on an ordinary table), so under `asserterror` the denied read passes; a granted read returns.
