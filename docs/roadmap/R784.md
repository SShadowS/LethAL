**Why.** R778 batches many kill pairs into one entries request, so M_k runs after M_{k-1} in the same request. That
needs "each entry starts from a fresh database" to hold. It was measured per TEST for four kinds (the R-653 order
probe, edge 57f1e4f98, a tiny app) and per entry on probe apps (R-635), not on `dcdf9e821`, not on a 17-app install,
and not for non-transactional state (NumberSequence, static caches, temp files, isolated storage). The cost model
(0.5 s per request against 10 ms per entry) hints that the step between requests is heavier than the one between
entries. Evidence: `/coord/handoff/R-778/design-review.md` finding 3.

**What was built (4730432c).** Leg `O1` in `V3_GATE_LEGS` and the default legs: one serve daemon, five requests
(`[R]`, `[W,R]`, `[R,W]`, `[W,R,W,R,R]`, then `[R]`) over `fixtures/sandbox-order` and `fixtures/sandbox-order-tests`
(seven kinds, no test that commits), on the fixture's own package set and, with `LETHAL_ITEST_V3_CDO`, on the CDO
`Test/.alpackages`. `judgeOrderProbe` is a pure function: a writer value in a Reader entry or a failing Writer test is
`gate-fail`, a daemon that cannot run is `infra-fail`, a build with no serve path reads "not applicable". Figures are
pre-committed in `docs/superpowers/specs/2026-10-25-r784-order-probe-leg-precommitment.md`; first live run on dcdf9e821
matched them (`/coord/handoff/R-784/o1-first.log`). The non-transactional kinds (NumberSequence, IsolatedStorage) and
the dependency-app SingleInstance are in. Not done by design: the CDO set loads only what the tests app declares
(the fixture cannot depend on the CDO apps), and commit-based state stays unmeasured. Per R777 run `--regate` of
`current` after the merge. Upstream ask to document the per-entry reset: posted by the coordinator,
https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5862.

**Work.**
- Add the order probe as a gated leg of the al-runner-v3 update gate, run for every pin, so a build that stops
  isolating entries cannot become `current`.
- Extend it with a non-transactional kind (NumberSequence, a static cache, a temp file, isolated storage) and a
  SingleInstance codeunit in a dependency app.
- Ask upstream to document the per-entry reset (aldevtools/BusinessCentral.AL.Runner).
- Build review fixes: `judgeOrderProbe` now fails on answer order differing from sent order (S1), checks the request count and shapes against `O1_PLAN` (N3), `SERVE_TEST_ISOLATION` is shared with `requestBase` (N1), and the gate page notes the `resources` override is not probed (N2).
- The live check stays D1 per-mutant equality (`report-diff` IDENTICAL against the current serve report).
