**Filed by R-297 Task 5 (2026-09-28), class C.** Plan:
`docs/superpowers/plans/2026-09-28-R-297-instrumentation-real-corpora.md`, "Root causes", class C.
Found by R-297's per-file locator on DC/Cloud: `CDCApprovalForwardSubscr` and
`CDCApprovalManagement` fail to instrument.

**What breaks.** A procedure whose HEADER is split by `#if ... #else ... #endif` (one header per
arm, then one shared `var` section and one shared body) parses as `preproc_split_procedure`, which
is neither `procedure` nor `trigger_declaration`. `injectReachLatches` walks up from a mutant to its
procedure or trigger, finds neither, and throws `a reach marker sits outside any procedure or
trigger body`. The whole run aborts on that one file. Before R297 and R298 landed, their throws hid
this one.

**The same blindness, silent.** Every manifest walk used the engine's `findEnclosingProcedure`,
which also stops only at `procedure`. So in a split procedure `procedureName` was `""`, no member
was recorded, `procedureScopeOf` could not see `local` (the node text starts with `#if`),
`gapBlockOf` missed the body block and could return the file root, and the line map's `spansOf`
gave the procedure no coverage span.

**Size** (R-297 Task 0 census): files holding a `preproc_split_procedure`: DC/Cloud 3, BaseApp 4.
`preproc_split_procedure_preamble` (each arm also has its own `var` section): 0 in every corpus.

**Fix in R-297 Task 5.** `isProcedureLike` (`procedure` or `preproc_split_procedure`), exported from
the engine (`packages/engine/src/ast/tree-walks.ts`, `@lethal/engine`), is the owner test for the
latch and `latchNameFor`. `gapBlockOf` (engine) and the line map's `spansOf` use `isProcedureLike`
directly. A project-local helper, `enclosingProcedureLike`, built on it, is what `procedureNameOf`,
`procedureScopeOf` and `enclosingMemberOf` use for the manifest's name, scope and member walks. Scope
is `local` only when EVERY arm is `local`: `local` widens coverage to object grain (R63), so a public
arm read as local could manufacture a vacuous `survived`.

**Still open after that fix.**

- An arm that RENAMES the procedure (a different name after `#else`) gets NO name: which arm is
  compiled depends on preprocessor symbols the writer never sees, so the first arm's name may be
  the inactive one. Its entries carry `procedureName` `""` and the line map gives it no span, so
  no coverage is attributed to it by a borrowed name (a public one reads `no-coverage`; an all-local
  one takes the ordinary unnamed-local object-grain path in `selection.ts`, as any local does). No
  corpus case was seen.
- `preproc_split_procedure_preamble` keeps throwing: each arm has its own `var` section, so one
  latch declaration cannot serve both arms (pinned by the `a-preamble` test in
  `packages/schemata/tests/compile.test.ts`).
- Semantic resolution inside a split procedure is blind, so its type-dependent sites are lost. That
  is filed separately as R302.

**Closed 2026-09-28, `4575882` (R-297 Task 5).** The defect this item names, the throw, is fixed: a
split-header procedure now gets a reach latch, a name (unless its arms disagree), a member span and
a scope, the same as an ordinary procedure, and alc proves the emitted target compiles under both
symbol sets for every admitted shape. The two gaps left open above move to their own items rather
than reopening this one: semantic resolution staying blind inside a split procedure (type-dependent
sites lost, one operator swap, a missing hang tag) is [[R302]]; the sibling shape where each arm ALSO
has its own `var` section (`preproc_split_procedure_preamble`), which still throws because R301's
fix has nowhere to anchor a per-arm latch, is filed as [[R309]].
