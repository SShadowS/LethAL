Found by coord PR-371 (lethal-preproc, 2026-11-23), the full v3 gate with `stopGroups` forced on, measured per mutant
against a same-commit control. Evidence: `/coord/handoff/PR-371/forced/` (the gate log and `reports/`). Related: [[R1146]],
[[R1067]].

**What happens (read in `packages/runner/itest/al-runner-v3.itest.ts`, the per-leg session helper):**
- The header comment says `LETHAL_ITEST_V3_REPORT_DIR=<dir>` "writes each session's report as `<dir>/<leg>.report.json`
  before any assertion".
- In the code, the warning-set check (`assertGateWarnings` or `checkGateWarnings`) runs first, and the report is written
  after it. A leg whose warning set differs throws before the write.

**The consequence.**
- In PR-371's forced run, D1, D1c and T failed their warning sets on one extra code (`alone-confirm`): the legs where the stop
  actually fired. They are the only legs with no saved report, so the per-mutant comparison could not judge them.
- Any measurement that relies on the reports (a control comparison, `LETHAL_ITEST_V3_CONTROL_DIR`) is blind to the legs whose
  warnings moved. That is a test that can hide the very legs that matter.

**To do.**
- Write the report before the warning-set check, as the comment says (and before `CONTROL_DIR`'s comparison, which already
  follows the write).
- Add a test that a leg failing its warning set still leaves its report in `REPORT_DIR`, red against today's order.
