**Filed 2026-10-24 by R-705 (lethal-bugs)**, evidence `docs/measurements/r706/readings.json` and [[R706]], [[R712]].

**What.** LethAL's bcdev backend runs tests through LethAL Control `RunMutant` (the web-service path, runner 130450).
There an unhandled outbound HTTP call fails with "The request was blocked by the runtime to prevent accidental use of
production services." In VS Code, the test runner hub and al-runner v3 it fails with "...the connecting endpoint
violates security requirements...". An AL test that asserts on that text can pass in a user's CI and fail under bcdev,
or the reverse. This is a known difference of the paths, not a LethAL defect (the owner's ruling in R712 makes the hub
the oracle).

**To close.** Decide whether bcdev should document the difference, warn when a test's failure text is the
web-service one, or run such tests through the hub.
