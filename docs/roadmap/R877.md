Found by the opus plan review of R-861's `var` fix, by reading the code. Not measured on a corpus. Related: [[R855]], [[R316]], [[R313]].

**What.** A trigger whose header and var section are both split by `#if` used to give ERROR nodes, and R313 refused it. For example:

```al
#if C
    trigger OnRun()
    var K: Integer;
#else
    trigger OnRun()
    var M: Integer;
#endif
    begin
        ...
    end;
```

Since 4.6.0 (#32) it parses as `preproc_split_trigger_preamble`. R316's comment still says this form "does not parse". `isProcedureLike` and the trigger check in `injectReachLatches` (`compile-plan.ts`) do not know the new node. So a statement-grain marker in its body walks to no owner, and the whole file is refused (`compile.latch-owner`).

**Cost.** A whole-file refusal where one member should get a latch, or at worst a member-level refusal. That is never a wrong verdict. 0 corpus files were seen: the five-set diff of 4.6.0 was identical.

**To close.** Teach the owner walk the trigger preamble, the R316 way: one latch per arm, every arm's `var` blanked. Prove each arm with alc. Or refuse the member by name before the latch walk. Not checked: whether member walks give this form any mutants at all.
