**Filed 2026-10-23 by lethal-code**, from R-666's measurement (`/coord/handoff/R-666/measure.md`, field table).
Related: [[R666]], [[R349]].

**What.** `AlRunnerV3Backend.baselineRefused` is filled by `noteBaselineRows`. It holds the tests v3 refused at the
unmutated baseline, and it grows over the whole session: neither `deploy()` nor `resetLayoutState` clears it. So a
test that v3 refused at batch 0's baseline still produces `[v3-refused-test-nearby]` notes (`survivorNote`) on batch
1's survivors, even when batch 1's own baseline ran that test.

**Why it is small.** It is a NOTE only. No verdict, killing test or refusal reads it. The cost is a survivor note
that names a refusal from another batch's layout.

**To close.** Either:
- scope it per batch (clear it in `resetLayoutState`, and build it from the current batch's baseline), with a test
  that goes red when the clear is removed; or
- rule that a session-wide set is intended, and say so in the note text.

**Closed 2026-10-23 by ruling (orchestrator, on lethal-code's proposal): session-wide is correct.**
- Every batch's baseline runs the whole suite. A v3 refusal (Commit, HTTP, duplicate-key, OnRun) depends on the
  test's code and the v3 build, and both are fixed for the session. The unmutated code is the same in every batch.
  So the batches refuse the same tests, and a per-batch clear would rebuild the identical set.
- **A per-batch clear would be WRONG for `--resume`.** A batch whose baseline snapshot is reused runs no baseline
  call, so it records no refusal of its own. Clearing would silently drop a true `[v3-refused-test-nearby]` note on
  its survivors.
- The case in "What" (refused in batch 0, ran in batch 1) needs a refusal that varies between batches, which is
  flakiness. Timeouts are already excluded from the set.

**Pinned:**
- The field's doc comment in `AlRunnerV3Backend` says it is session-scoped on purpose, and why.
- "R677: a batch-0 baseline refusal still notes a survivor in a later batch whose baseline ran nothing"
  (`tests/al-runner-v3-backend.test.ts`) goes red when `this.baselineRefused = new Map()` is added to
  `resetLayoutState`.
- The existing "I3: a survivor whose covering codeunit had a baseline refusal is noted" goes red, with the new test,
  when `noteBaselineRows` stops recording.
