**Filed 2026-11-06 by lethal-code, from R-845.** Related: [[R845]], [[R843]], [[R709]].

**What.** The clash check of [[R843]] and [[R845]] compares the target with the installed apps that depend on it, directly or through
another app. It reads each one from the package the server holds. It cannot see an installed app that is NOT a dependent, because
the control app's `InstalledDependents` lists apps by the app they depend on, and no action lists installed objects or fields.

BC refuses that clash too (R845 batch, cases U3, L2, L3h), and does not try to restore: the target and its dependents are gone, the other
app is untouched. Two unrelated apps adding one field to `Customer` is the likely real case. Today the run stops after the fact with
`UpgradeClashRefusedError`, which names the recovery section.

**To close.** A control-app action that reads `AllObj` (object type and id, with the owning app) and `Field` (table, field id and name,
with the owning app), and a check that compares the target against every installed app, not only the dependents. It needs a control-app
version bump (`MIN_CONTROL_VERSION` in `packages/runner/src/harness.ts`), AL changes verified by an offline `alc` compile and the hang
gate, and the proof table in `docs/gates/servers.md` redone for each server.

**Also not covered by the check** (from the [[R845]] limits): a test app an env-tool hook publishes before the target's deploy, an env
tool's own publish command (its schema mode is unknown),report columns, and trailing spaces in names.

The plan is `docs/superpowers/specs/2026-11-06-r847-non-dependent-clash-plan.md`. Part 1 is the AL, the client and the tests, all

**What is built.**

- `extensions/lethal-control/src/ControlApi.Codeunit.al`: two read actions, `ObjectOwners(ItemsJson, MaxMs)` and `FieldOwners(ItemsJson,
  MaxMs)`, by primary key (`AllObj`: type, id; `Field`: TableNo, No., or TableNo and FieldName). At most 200 items; one row per item
  read, in order, the target's own rows included; `read` says how many were read before `MaxMs` ran out. `outcome` is `owner`,
  `none` or `unresolved`; an owner row carries `appId`, `appName`, `appPublisher`, `appVersion` (the client needs all four to read
  that app's package; the plan named only the id). A field row carries `fieldName` and `tableName` as BC holds them. An explicit `case`
  maps the 13 kinds (`Table` is never `TableData`, `XmlPort` is `XMLport`); an unknown kind raises. `Permissions` declares both tables.
  Compiled offline with alc 18.1.43 (clean, no diagnostics): the symbols were `Microsoft_System_28.0`, System Application,
  Application, Base Application and Business Foundation 28.1 from `/work/tools/r315-dc-symbols/Cloud/.alpackages`, and a Test Runner
  built with alc from the cached 28.4 source zip, in a scratch folder (nothing written under the repo).
- `packages/runner/src/harness.ts`: `HarnessVerifier.fetchObjectOwners` and `fetchFieldOwners`, as strict as `fetchInstalledDependents`:
  a bad `read`, a row count other than `read`, a row that is not the item at its place, an unknown outcome, or an owner with no
  full app all throw `HarnessVerificationError`. Fewer rows than items is a partial read, returned as such. The client timeout is the
  time left.
- `ExecutionBackend` gets optional `installedVersions`, `objectOwners`, `fieldOwners`, implemented on bcdev only.
- `packages/runner/src/non-dependent-clash.ts` (new, pure): what is new in the target (`newObjects`, `newTableFields`), one control per
  kind (`controlObjects`), and the batched read with the 10 s deadline (`readInBatches`).
- `packages/runner/src/object-clash.ts`: `findNonDependentLeads` (skip on a first publish; base set from the INSTALLED version's
  package; new-only items; offline third-app table ids by `resolveTableIds`; blind-kind controls; leads), run in `checkObjectClashes`
  BEFORE its early returns. A lead is read from its own package and compared as a dependent is; that comparison alone refuses. A
  dependent that was not actually compared is read as a lead. `ObjectClashError` says the app is "not known to be a dependent" and to
  remove the clash in the target or in that app. `orchestrator.ts` passes the reads in for bcdev.
- Tests: `r847-owners-verifier.test.ts`, `r847-non-dependent.test.ts`, the R847 block of `object-clash-session.test.ts` (zero deploys by
  call counter) and the source pins in `control-app-source.test.ts`. Each was reddened by a real mutation (see the coord report).

**What Part 2 must measure** (the plan's list, plus what Part 1 found):

- The probe in a scratch app (ids 915xx), under a lease, bc2 then bc3, on the ladder 1, 10, 100, 1000: whether a keyed read of
  `AllObj` and `Field` is cheap (the plan stops at 100 ms above a HarnessInfo round trip).
- Which of the 13 kinds `AllObj` has rows for; whether `Field` names a tableextension field and its owner app; the join on a
  dev-published app; whether `SetRange(FieldName)` ignores case; what a published-not-installed app shows. Also `AllObjWithCaption`
  (it has `App ID` directly).
- **The field read has no control.** Blind kinds are controlled for objects only. If `Field` rows do not include tableextension
  fields, every field answer is `none` and reads as clean. Part 2 must settle that, or add a known-installed field as a control.
- The `Field` filter by name returns more than one row when two fields of one table differ only in case; the AL answers `unresolved`
  (a warning), which hides an exact-name match. Decide in Part 2 whether to return all matches.
- Enum values are not read (the `Field` table does not hold them); `Enum Metadata` is not in System's symbols.
- A tableextension on a table the target does not own is asked by table id found in the package cache (the target's dependencies plus
  the five Microsoft apps): measure its cost on Base and the 8 shared names.
- Then the bump, `MIN_CONTROL_VERSION`, the literals in `harness.test.ts`, `agent-contract.test.ts`'s guide, `CONTROL_APP` and
  `CONTROL_SHA256` in `bc-linux-setup.ts`, `scripts/testdata/bc-demo-kraken-pin.json`, `docs/gates/README.md`, publish to `bc1`-`bc3`
  and `bc-demo`, the hang gate, and the proof table per server.
