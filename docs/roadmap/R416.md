**Found reading the Windows CI job of `lethal/kraken-move` (kraken-move Task 6, 2026-10-03).**
`scripts/kraken-setup.test.ts` runs `scripts/kraken-setup.sh` through `bash` with fake `git`,
`flock`, `alc`, `npm` and `bun` first on PATH. That only works from Git Bash. Measured on the
Windows host with `bun test` started from PowerShell:
- with `C:\Windows\System32\bash.exe` first (the WSL launcher), all four tests fail;
- with Git's `bin\bash.exe` first, `process.env` under `bun test` spells the variable `Path`, the
  test adds `PATH` beside it, and the child bash keeps the original one, so the fakes are missing
  (`flock: command not found`); with the duplicate removed, Git's wrapper puts its own `/usr/bin`
  ahead of the fakes, so the REAL git runs instead of the fake.
On the runner one test of four failed (`the control app is built in the main checkout only, and
only when missing or stale`, run 37129055253), with `kraken-setup.sh: line 13: flock: command not
found`.

`kraken-setup.sh` is the per-worktree setup of the Linux kraken container and never runs on
Windows, so the Windows outcome depends only on which bash a Windows host happens to find.

**To close.** Run the four tests on Linux only (the `unit-linux` CI job and the kraken image),
skipped on win32 with this reason in a comment.
