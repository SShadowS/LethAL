**Priority.** Filed 2026-10-09 by the R534 build (plan r2, roadmap item 1). Never a false kill: a
lost kill, and a difference between the two backends' verdicts on the same mutant.

**What.** Since [[R534]], an al-runner `error` row that is not a timeout or a refusal is a
per-mutant `error`, cause `runner-test-error`. Two of those shapes are, on BC, a FAILED test: an
unexecuted UI handler (`The following UI handlers were not executed: <h>`) and a test codeunit
whose `OnRun` trigger throws. bcdev then scores the mutant `killed` after the cold confirm, while
al-runner scores it `error`. That BC reports them as a failed test is READ (measure.md finding 8),
not measured.

**Evidence.** `/coord/handoff/R-534/measure.md` (rows HandlerUnused and AfterOosOnRun, finding 8);
`verdictFromRunnerTest` in `packages/runner/src/al-runner-backend.ts`; the pre-commitment's Part B
AskLogic rows.

**To close.** One BC measurement per shape (an `[HandlerFunctions]` test whose dialog a mutant
skips; an `OnRun` that throws), through bcdev. If BC reports `fail`, score the al-runner row `fail`
too (it is the test's own failure), with a test per shape, red-checked.

**v2 retired (R654); re-measure on v3.** Everything above was measured on the .NET al-runner, deleted in R654 S3
(35f3c67f). `verdictFromRunnerTest` moved to `al-runner-rows.ts`, and the Rust al-runner reaches it. Its rows for
these two shapes have not been measured: measure them on v3 first, then apply the close above to v3.

**Closed 2026-10-23 by ruling (coord task R-537, lethal-code): neither shape is a lost kill on v3.** Measured with an
invented probe offline on alpha.2 (91253f2d6) and edge (57f1e4f98), and on bc2 (BC 28.4) through LethAL's bcdev path
under pre-commitment `docs/superpowers/specs/2026-10-23-r537-bc-probe-precommitment.md`; the evidence is in
`/coord/handoff/R-537/` (`measure.md`).
- **An unexecuted UI handler fails on both.** v3 writes `fail`, `The following UI handlers were not executed:
  MsgHandler`, which LethAL scores as a kill. BC failed the same test with the same text.
- **A throwing `OnRun` runs no test on either.** v3 writes every test of the codeunit `notRun` (`OnRun failed (runner
  behaviour not pinned): ...`), scored `error`. On BC, Microsoft's test runner gave the codeunit no method lines, so
  neither test ran and none was reported failed. The pre-committed prediction (both reported failed) was refuted.
  There is no BC kill for v3 to lose.
  - On bcdev, LethAL then reads the 0 lines as a stale test app and stops the run: filed as [[R684]].
  - The v3 refusal is filed upstream with the BC measurement, so it can be pinned:
    [aldevtools/BusinessCentral.AL.Runner#5748](https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5748).
- **Stored v3 reports:** 0 of 8,275 kills carry either wording.
