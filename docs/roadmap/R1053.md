Filed by coord PR-37 (2026-11-15) on the orchestrator's ruling, as the follow-up of [[R1050]]. Evidence: `/coord/handoff/PR-37/`
(`corpus-diff2.txt`, `classify2.txt`, `new-sites.txt`).

**What.** R1050's rule 1 refuses `empty-block` of a same-object callee's body when the callee is a "progress procedure": a fixpoint
that starts from calls in a loop whose exit reads a name the call moves, and then adds every callee Q calls with a `var` argument
that Q itself can move (Q's `var` parameters, its writes, its return). That second step follows ANY such write, not only one that
reaches the outer loop's exit.

**Cost, measured.** On 72 BC.History modules R1050 refuses 53 sites (28 scored mutants lost for 4 hangs). The transitive step
alone adds 11 sites in Filter Tokens: `MakeFilterExpression`'s loop calls `ResolveFilter(TypeOfFilter, FilterText)` (`var Filter`),
which calls its date and time helpers with `var` arguments, so every helper body is refused, although the loop overwrites
`FilterText := Tail` right after the call and none of them can hang (all 11 were killed on v3, R-969's run).

**Possible fix.** In the fixpoint, add P from a call inside Q only when the name P moves is one Q moves TOWARD the outer exit:
Q's `var` parameter that the outer call passes a name the outer loop's exit reads (or reads through R818's body closure), not
any of Q's `var` parameters. Re-measure with R1050's method (fixture dry runs unchanged; corpus before/after, earlier v3 verdicts)
and keep R1050's tests B (a real two-hop hang) green.
