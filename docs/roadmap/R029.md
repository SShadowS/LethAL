**False survivors from coverage attribution** — the worst output this tool can produce, and it was live. BC *does* report table-trigger coverage, but `SymbolReference.json` records no trigger, so `AppMethodIndex.lookup` returned `undefined`; the fallback scanned **local** procedures, which is empty for a table whose procedures are public; the observation was then dropped entirely, so the object lost credit along with the member. `byObject` kept only whichever sibling test happened to resolve, `coverageFilter`'s object-level fallback returned that non-empty-but-WRONG set, and the all-green fallback never fired. Measured on the Phase-1 fixture: **10 of 20 survivors were false**, each individually driven through the fenced path against its intended killer and killed (53/20/2 → the honest 63/10/2). Perversely, a table with **public** procedures scored worse than one with none, because the empty case fell through to the correct fallback — every real app is in the losing category. Fixed by emitting an object-level-only `CoverageEntry` (absent `procedure`, never `""`, which would collide with a trigger mutant's own `byMember` key). Evidence: `0a463fd`, `packages/runner/src/{bcdev-backend,selection}.ts`.
