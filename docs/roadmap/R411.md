**Found by the first Linux run of the unit suite (kraken-move Task 6, 2026-10-03).** The product
records project-relative paths with the host separator (`path.relative`), so a Linux run writes
`src/X.al` where Windows writes `src\X.al`. Measured on `sandbox-app`: the Linux and Windows
`mutant-manifest.json` differ ONLY in the `"file"` values; every other byte is equal. Mutant
identity keys do not contain the path, so frozen baselines are unaffected. The tests below pinned
the Windows form.

Failing tests:
- `sandbox-app's`, `sandbox-data's`, `sandbox-hang's`, `sandbox-harden's` and `sandbox-coverage-probe's emitted files are byte-identical to the WASM capture, and its ids lie inside its idRanges` (`packages/runner/tests/fixture-emission.test.ts`): only the `mutant-manifest.json` hash differs.
- `R383: sandbox-multiobject > gives the pre-committed twelve mutants in one batch`
- `R353: sandbox-layout splits at maxGuardsPerBatch 7 across a member boundary > gives the pre-committed ten mutants in two batches`
- `R332: a frozen baseline never records itself > recordRequested: exact registered basenames only; slash direction does not matter`: a backslash is a separator on Windows only; on Linux it is a file-name character.

Evidence line from the capture:

```
-     "src\LayoutAlpha.Codeunit.al",
+     "src/LayoutAlpha.Codeunit.al",
```

**To close.** Expect the host form of a path. The manifest pin stays the Windows capture, and on
Linux the test maps the `"file"` values to that form before hashing, so it still proves every other
byte is identical.
