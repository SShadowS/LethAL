**Found 2026-10-06 while measuring R451** (coord handoff `R-451`, survey). Low priority.

**What.** [[R457]]'s conservative rule keeps `run-trigger-forced` unless the receiver's table provably has no
trigger of that kind and no observer. For objects the symbol table does not index (unindexed or `#if`-wrapped
objects), `forceCanRaise` falls back to a TEXT check. On BaseApp, 301 of the forced tags come ONLY from that
text fallback.

**Why it matters, and why it is not urgent.** A tag only asks for inspection: it never moves a verdict. Keeping a
tag where the trigger cannot really run is the SAFE direction (over-tagging), so this is a precision question, not a
correctness bug. But 301 tags from one fallback is enough to blur what the tag separates.

**To close.** Measure first:
- how many of the 301 sit on objects whose real (parsed) declarations show no trigger of the kind and no observer
  (true over-tags);
- how many the fallback keeps correctly.
Then decide whether parsing the unindexed objects, or narrowing the text check, is worth its cost. Never drop a tag
where a trigger or observer may exist (the unsafe direction).
