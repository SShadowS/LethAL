**Found 2026-10-06 while measuring R451** (coord handoff `R-451`, survey). Low priority.

**What.** [[R457]]'s conservative rule keeps `run-trigger-forced` unless the receiver's table provably has no
trigger of that kind and no observer. For objects the symbol table does not index (unindexed or `#if`-wrapped
objects), `forceCanRaise` falls back to a TEXT check. On BaseApp, 301 of the forced tags come ONLY from that
text fallback.

**Why it matters, and why it is not urgent.** A tag only asks for inspection: it never moves a verdict. Keeping a
tag where the trigger cannot really run is the SAFE direction (over-tagging), so this is a precision question, not a
correctness bug. But 301 tags from one fallback is enough to blur what the tag separates.

**To close.** Measure first:
- how many of the 301 sit on objects whose real (parsed) declarations show no trigger of the kind and no observer
  (true over-tags);
- how many the fallback keeps correctly.
Then decide whether parsing the unindexed objects, or narrowing the text check, is worth its cost. Never drop a tag
where a trigger or observer may exist (the unsafe direction).

**Measured 2026-10-06 (R-485).** The 301 sites (BaseApp `Base Application`, 7,810 files) are all caused by ONE
object: of 1,129 unindexed objects (all `#if`-wrapped; 0 unparsed), only codeunit 6721 "Booking Manager" (`#if not
CLEAN28`) contains `OnBefore/AfterModify`, and its modify subscriptions name only Sales Header and Sales Line, which
declare `OnModify`. True over-tags 297 (104 tables, e.g. Reservation Entry 19, Segment Line 19, VAT Amount Line 14);
kept correctly 4 (Price Worksheet Line, by tableextension 6474 "Serv. Price List Line", `#if not CLEAN27`). Those
301 are sites a forward `, true` mutant WOULD take; that mutant is not emitted, so they carry no tag today.

**Done 2026-10-06 (R-485), ruling: narrow the text check to the table.** `projectObserves` reads a CLEAN unindexed
tableextension (its `base_object`) or codeunit for THIS table: a codeunit keeps the tag for an `[EventSubscriber]`
whose target may be this table, WHATEVER the event (a custom IntegrationEvent an invisible extension raises from its
trigger included; sol, run 001), in every member arm; only one proven to target another table or object type drops
it (numeric targets compare as integers). Any other kind and every unparsed ERROR object keep the any-table
whole-text rule. And the narrowed reading applies only when nothing of the project is hidden from it (sol, run 002):
when the project holds any split-header object (R494), unparsed ERROR object or half-parsed unindexed object, a
trigger the reader cannot see could call a codeunit's event or modify another table whose subscriber then runs, so
EVERY unindexed object keeps the old any-table text rule (`SymbolTable.splitObjects` names the split headers). Before/after tag diff over every operator (`/coord/handoff/R-485/tagdiff.md`):
fixtures 1,612, CDO 49,370, DC 73,094, DO 81,480 specs: no change; BaseApp 785,977 specs: 331 drops (12
`run-trigger-forced`, 319 `run-trigger-skipped-modify`, 132 tables), 0 adds, 0 tag changes, same spec set (no
identity moves; `IDENTITY_SCHEME` unchanged). Every drop is caused by Booking Manager; delete and insert move nothing
(their other text matches, table 5886 and report 99001015, are other kinds and keep the text rule). An independent
whole-text check found 96 (table, object) pairs naming a dropped table: all mentions only, none subscribes to or
extends it. Pinned in `packages/builtin-tier1/tests/flip-boolean-literal.test.ts` ("unindexed objects, scoped to the
table (R485)"), each direction red-checked. Split-header declarations remain invisible (pre-existing): [[R494]].
