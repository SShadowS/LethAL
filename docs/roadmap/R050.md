**Neither wasm asset survived `bun build --compile`, so the standalone binary could not parse a single line of AL.** `parser.ts` resolved the vendored grammar relative to `import.meta.url`, which under `--compile` is Bun's virtual root — and web-tree-sitter's own emscripten runtime resolved the same way, failing FIRST: `failed to asynchronously prepare wasm: Error: ENOENT ... open 'B:\~BUN\root\tree-sitter.wasm'`. The unit suite is structurally blind to this (it runs interpreted, where the relative resolve is correct), so nothing would have caught it before a user did. Note it is TWO assets, not one — `tree-sitter.wasm` (web-tree-sitter's runtime, 205 KB) and `tree-sitter-al.wasm` (our grammar, 7.9 MB, R14).
