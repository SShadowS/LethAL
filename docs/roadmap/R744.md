**Filed by R-735** (2026-10-24). [[R736]] pinned the warning-code set of every gate leg, but its v3 proof ran without
`LETHAL_ITEST_V3_TABLES` and the CDO checkout, so legs D1, D1c and T never ran and got no entry. The daily
update gate sets both, so it hit an unpinned set and infra-failed, fail-closed.

**Fix.** Three `GATE_WARNINGS` entries in `packages/runner/itest/gate-expected.ts`: `al-runner-v3/D1` and
`al-runner-v3/D1c` get the new `CDO_D`, `al-runner-v3/T` gets the existing `TABLES`. The leg list in
`gate-warnings.test.ts` now names the three legs.

**The sets, and why each code is decided by pinned input** (the CDO checkout is verified before the legs: commit
`5f2a71d`, clean tree, corpus fingerprint, slice file and all 17 `Test/.alpackages` apps by sha256).
- `only-narrowed-run`: the leg passes `only` with one file, so the rest are excluded.
- `tests-only-narrowed-baseline`: the leg passes one `testsOnly` pattern.
- `dependency-report-source-unavailable`: five pinned Continia packages have a build number above 65535, so they
  are unreadable. The cause is the bytes of the pinned `.app` files, not the OS. If they ever become readable the
  code drops and the leg fails, which is the intended signal.
- `app-json-backslash-path`: the pinned `Cloud/app.json` has a `logo` path with a backslash, and the rewrite is a
  plain string replace with no OS branch.
- Leg T (`sandbox-data` fixture, same as `itest:tables`): `not-instrumentable-files-skipped` and
  `non-executable-sites-dropped`, both fixed by the fixture source.
