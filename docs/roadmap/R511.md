id: "R511"
title: "A namespace-qualified `extends` or `implements` does not parse, so the extension is indexed under one segment of the name"
section: "correctness-risks"
status: "open, filed 2026-10-08"
order: 1221
---

**Found while building [[R502]].** It is a grammar gap in tree-sitter-al 4.4.1, not a reader of LethAL's.

`tableextension 50300 X extends Contoso.Sales.Customer` does not parse. Measured: error recovery keeps ONE
segment as `base_object` and turns the rest into an ERROR node, and which segment it keeps varies.
- `extends Contoso.Sales.Customer`: ERROR `Contoso.Sales.`, then `base_object` `Customer`.
- `extends Microsoft.Sales.Customer`: `base_object` `Microsoft`, then ERROR `.Sales.Customer`.

`implements Microsoft.Sales.IFoo` is the same: the `interface` field holds `Microsoft`, and the rest is an ERROR.

**Effect.** The symbol table indexes such an extension under whichever segment survived (`tableExtensions`,
`indexFields`). Its fields, procedures and triggers are then attached to the wrong table name, or to none:
- `procedureNamesOn` and `extensionDeclaresProcedure` miss them;
- the tableextension's implicit `Rec` (`extendedTableOf`) binds to that segment.

R502 closes the part that decides a tag. `projectObserves` treats an extension with an ERROR beside its
`base_object` as observing EVERY table, so the trigger-skip tag is kept, the safe direction. It is tested both
ways (`r502-qualified-names.test.ts`). The ERROR also counts as parse damage (`parseDamaged`), so other readers
already widen.

The census found ZERO qualified `extends`/`implements` in fixtures, CDO, DC, DO and BC.History, so nothing
measurable rides on the rest today.

**To close.** When the grammar parses a qualified `base_object`, read it through R502's `fieldSegments` and
`qualifiedObjectName`, as every other qualified reference is.

**Reported upstream 2026-10-08** as
[SShadowS/tree-sitter-al#36](https://github.com/SShadowS/tree-sitter-al/issues/36), after a duplicate search; #34
(`extends <number>`) is the same `base_object` rule, but a different shape.
- Measured for the report: a two-file app (runtime 16.0) with `extends Contoso.Sales.Customer`,
  `extends Microsoft.Sales.Customer.Customer` and `implements Contoso.Sales.IFoo` compiles cleanly with `alc`
  18.0.43.1464 against Base Application 28.0. tree-sitter-al 4.4.1 gives an ERROR beside each.
- **Ruled 2026-10-08 (orchestrator):** no local re-read of the header text until a real project shows the shape.
  A re-read would fix the index, but the ERROR would still mark the file parse-damaged and make other readers
  conservative, which only the grammar fix removes. Today's answer, which keeps the tag, is safe.
