Shipped and measured live against Cronus283 at commit `1d259ca`. The tables gate moved from
killed 113 / survived 18 / no-coverage 10 over 141 deployed mutants to killed 157 / survived 25 /
no-coverage 10 over 192 deployed mutants (207 raw specs), score 157/182, untargetedTriggerCount 0.
All 51 new mutants matched the verdicts pre-committed before the run in
`docs/superpowers/specs/2026-08-12-r136-trio-precommitment.md` (as amended before the second run),
and every pre-existing mutant kept its exact verdict.

Three operators shipped:

1. `lethal.swap-modify-flag` moved from 1.0.0 to 1.1.0 to also claim `Insert(true)` and
   `Delete(true)`, on top of the `Modify(true)` it already covered. Measured live at arm A (a
   strong assertion that kills the Insert rewrite), arm B (a weak read-back assertion that the
   same rewrite survives, since `Insert(false)` still writes the row), and arm C (the Delete
   rewrite, killed on its own arm rather than inferred from Insert).

2. `lethal.validate-to-assign` is new. It rewrites `Rec.Validate(F, V)` into `Rec.F := V`, which
   skips the field's OnValidate trigger. Measured live at arm G (the qualified-receiver form,
   killed), arm H (a value-only assertion that the same rewrite survives, since the plain field
   stays correct and only a derived field goes wrong), arm I (the implicit-receiver form inside a
   table procedure, emitted as `Rec.`-qualified, which attributed and killed at member level), and
   arm J (the refusal negative: the single-argument `Validate(F)` has no assignment equivalent,
   and the operator correctly emits nothing there).

3. `lethal.swap-find-direction` is new. It swaps `FindFirst()` and `FindLast()` in both
   directions. Measured live at arm D (`FindFirst` to `FindLast`, killed), arm E (`FindLast` to
   `FindFirst`, killed, the other direction), and arm F (an existence-only assertion that the
   swap survives, since a filter-free existence check cannot see which end of the set the row
   came from).

Arm K measured a harder case: a table whose `OnInsert` assigns the primary key, exercised by a
two-iteration loop under a test that asserts nothing. The `swap-modify-flag` mutant on its
`Insert(true)` call is killed, but the kill is a duplicate-key platform error, not anything the
test caught: with the run trigger skipped, the key is never assigned, the first blank-key insert
succeeds, and the second raises. The same untagged mechanism kills two further mutants inside the
table's own `OnInsert` trigger. All three are confirmed as kills; the mechanism itself stays
unmeasured, because the gate's healthy path never surfaces `killingTestFailure` (see R86, R138). A
fourth mutant in the same arm, the Tier-1 deletion of the `Init()` call, was re-derived before the
second run as an equivalent mutant instead: once the fixture's own baseline bug was fixed, `Init()`
does nothing observable on either loop iteration, so removing it is undetectable by any test, not
merely by this one.

The refusals this row already recorded stand unchanged. `Next()` mutation is refused, because its
natural mutants are non-terminating loops, the hang class LethAL already runs `itest:hang` for.
`IsEmpty`/`Find` negation inside a condition is refused, because `negate-conditional` already
covers it on the enclosing comparison. `remove-setfilter` is refused, because `void-method-call`
already emits the identical deletion at the same site (see R134). `FindSet` direction is deferred,
and the reason on record is corrected: `Ascending` is a record method, not a property, so the real
obstacles are that a reversed set needs a second statement inserted before the find, an emit shape
no operator in this product produces, and that the ascending state outlives the call rather than
being local to it.

Four rows were filed during this wave and stay open: R137 (`swap-rec-xrec`'s conformance refusals
assert nothing), R138 (the platform-artifact screen cannot see run-trigger-flag kills, the gap arm
K measures), R139 (a stale published test app looks like failing tests, which cost this wave a
full gate run to diagnose), and R140 (the coverage fallback that manufactures a false `survived`
when the only covering test is red).
