Replace a `unary_expression` whose operator is `not` with its operand.

```al
if not Rec.IsEmpty() then CreateEntry();   // before
if Rec.IsEmpty() then CreateEntry();       // after
```

`negate-conditional` reaches a negation only when it wraps a COMPARISON. A `not` applied to a bare
call, identifier or member access is reached by nothing, which R159's census showed as
`unary_expression` 1,124 unclaimed and this row breaks down.

**Measured on `do-rel2/Cloud`**, by operand kind:

| operand | count |
| --- | ---: |
| `call_expression` (`not Rec.IsEmpty()`, `not Codeunit.Run(...)`) | 627 |
| `identifier` | 251 |
| `member_expression` | 172 |
| `parenthesized_expression` | 43 |
| `quoted_identifier` | 1 |
| unary minus, not this operator's business | 30 |

**1,093 `not` sites**, none claimed. The 43 parenthesized ones are where a comparison usually hides,
so refusing that operand kind cedes them to `negate-conditional` and still leaves 1,050.

**Why it compiles:** the operand is already Boolean or the `not` would not have compiled.

**The false kill is real and specific.** `if not Rec.Get(X) then Rec.Insert();` inverted inserts a
row that already exists and dies on a duplicate primary key with no test asserting anything. That is
the R138 class exactly, and the machinery exists: declare a `PlatformKillMechanism` and tag, or
refuse, when the guarded branch contains an `Insert`. Under-tagging is the unsafe direction, the
same asymmetry R143 records for `insertSkipCanRaise`.

Proposed by the Fable subagent 2026-08-19, which guessed 300 to 500 sites; measured it is roughly
double that.

---

**BUILT 2026-08-19. Offline complete, live NOT done, and the row stays open until it is.**

`lethal.remove-not` (Tier 1, 1.0.0) rewrites `not <expr>` to `<expr>` where the operand is a bare
call, identifier or member access. A parenthesised operand is refused and ceded to
`negate-conditional`, which owns comparisons: 43 of the 1,094 `not` sites, a 4% cession for a clean
split.

**The false-kill screen this row asked for is NOT built, and that is a ruling rather than a
shortcut.** `if not Rec.Get(X) then Rec.Insert();` inverted can die on a duplicate key with nothing
asserted. True, and it is exactly what `negate-conditional` already does when it turns `if A = B`
into `if A <> B` — the same branch flip through a different token — and that operator declares no
mechanism. R138's mechanisms exist for a mutation that changes what is WRITTEN while leaving control
flow alone; a branch flip is ordinary changed behaviour, which design §6.7 already treats as a
legitimate kill. Tagging one and not the other would assert a difference that does not exist.
R121's assertion screen is what tells a reader the kill carried no assertion.

**Measured footprint:** 1,106 sites on `do-rel2/Cloud`, against the 1,051 this row predicted from an
operand-kind census. Both are right and they count different populations: the census walked
procedure and trigger bodies, `census-operator-sites.ts` walks whole files, and the extra 55 sit in
declarative positions where `isMutableSite` refuses them.

Fixture impact, measured: `sandbox-data` **+1**, `sandbox-probes` +7 (not gated), and **0** on
`sandbox-app`, `gift-card` and `sandbox-hang` — so `itest:bcdev`, `itest:envtool`, `itest:hang` and
the demo campaign are structurally unaffected.

**What remains.** The single new `itest:tables` mutant is
`codeunit 79313 "Data Commit Target"`'s `OnRun`, `not DataMain.Get(CommitRunNoLbl)` → `DataMain.Get(...)`,
predicted **killed** because both covering tests assert the callee set `Flagged` and the flipped
guard exits before it does. That prediction is written down in
`docs/superpowers/specs/2026-08-19-r163-remove-not-precommitment.md` and the gate now carries it,
marked in the source as predicted-not-measured. Run `itest:tables` and either delete the marker or
record the disagreement.

**LIVE-VERIFIED 2026-08-19, and the prediction held exactly.**

The fixture containers came back as clean BC, so the whole live environment was rebuilt first:
LethAL Control 1.0.0.16 to Cronus281 and Cronus283, then each fixture's target and test app. The
targets and test apps had to go through the **dev endpoint** rather than global scope — published
globally, the target becomes an AppSource app that its own test app depends on, and BC then refuses
the replace LethAL performs on every run with *"tries to replace the existing AppSource app … which
is a dependency to the following AppSource apps"*. That is the same trap the gift card demo hit when
it was first published.

`itest:tables`, twice in one invocation and then again against the committed baseline:

| | before | after |
| --- | ---: | ---: |
| killed | 194 | **195** |
| survived | 32 | **32** |
| no-coverage | 10 | **10** |
| deployed | 236 | **237** |

`untargetedTriggerCount` 0, `declarativeSites` 1, all unmoved as predicted.

The one new mutant is `M0024`, `lethal.remove-not` in `codeunit 79313 "Data Commit Target"`'s
`OnRun`, **killed by `CommitBeforeCodeunitRunSucceeds`** — the exact test named in the
pre-commitment, for the exact reason: with the `not` gone the `Get` succeeds, the trigger exits
before setting `Flagged`, and the test asserts `Flagged`.

Baseline re-recorded, diffed (**1 added, 0 removed**), and then re-run so the recorded file is proven
to COMPARE rather than merely to exist — `assertMatchesBaseline` records and returns when no baseline
is present, so a single green run after deleting one proves nothing (R29).
