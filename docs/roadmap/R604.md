**Why each deploys.**
- H2: rule P counts a READ of a real table through a local record as stateless, so no writer search runs; the
  database is state that outlives the call. A `void-method-call` on `Q.Delete()` hangs the loop.
- M1: the wrapper has no `exit(<call>)` into another object, so its chain is empty and the row is dropped
  although `r570Touches` found the touch.
- M2: writers are searched `R572_STATE_HOPS` (4) calls deep; past the cap a writer is NOT FOUND (unlike
  statefulness, where past the cap means UNKNOWN, which counts as stateful).
- M3a: the `Copy` sits in a procedure the loop never reaches, so `TempW` never joins the value path.
- M3b: a by-value parameter counts as touching only for row changes (`R570_CONSUME`). Whether a by-value
  RecordRef shares the caller's cursor is NOT MEASURED.
- S3 and S4 (added 2026-10-22 from the R-572 build review r3, `/coord/reviews/R-572-build/review-r3.md`;
  admitted on master and on lethal/r572 b2bcbdc8): in S3 a writing call's arguments join the value path but the
  callee's globals do not; in S4 a `with` subject is not a slice name. S4 is rare at runtime 17 and later.
