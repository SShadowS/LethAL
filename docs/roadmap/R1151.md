Found by coord PR-242 (lethal-code, 2026-11-19). Spec: `docs/superpowers/specs/2026-11-19-pr242-live-request-fixed-cost.md`,
amendment 1. Evidence: `/coord/handoff/PR-242/` (`spec-light.md`, `pack-sim.py`/`.txt`). Related: [[R1092]].

**What happens today.**
- y3 had 1,634 R778 kill-pair batch requests, each paying al-runner's fixed cost (about 1.5 s: setup plus its own
  per-request baseline).
- `batchKillPairs` runs once per PR-99 unit, so a batch holds only that unit's kills: 1,188 of y3's live requests carry
  ONE pair.
- PR-241 (preproc) packs consecutive units of one lane into one `prefetchMutants` call (`unitSizes` marking the
  boundaries), but still runs `batchKillPairs` per unit, after the whole packed prefetch.

**The lever.** One pair batch for the whole packed call, chunked by memory cost (`groupsThatFit`) as today.
- Scoring order does not change: every unit of the pack is scored after the packed prefetch already, and the merged
  batch runs before the first of them.
- `takeStoredPair`'s checks are unchanged, so a pair still serves only its own kill.

**Predicted** (`pack-sim.py`, a lower bound): on top of PR-241's arm B (64 entries), pair-batch requests about 950 →
about 635, about 157 s of wall per DO run at 3 lanes; at 128 entries about 245 s.

**To land it:** a spec with red tests (the merged batch stores exactly what the per-unit batches stored, pair for pair,
and every kill's verdict, killing test and reproduction are unchanged), then an A/B against PR-241's arm B on a DO scope.
Not built.
