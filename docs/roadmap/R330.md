**Found by the R-302 final review (2026-09-29), findings I1 and I2.** Review:
`.superpowers/sdd/2026-09-28-R-302-split-semantics/final-review.md` (scratch, on `lethal/r302`).

**What is not indexed.** `buildSymbolTable` indexes an object's direct members (`procedure`, the two
split-header kinds) and, since [[R327]], a split member swallowed by the global `var` section. It
does NOT index:

- a plain procedure wrapped whole in `#if ... #endif` (a `preproc_conditional` member);
- a plain procedure's locals declared in a `#if` var block (`preproc_conditional_var_block`,
  R303's shape, common in BaseApp).

So uniqueness (`uniqueProcedure`) and hiding (`resolveIdentifierType`, `lookupVar`) are judged
against an incomplete set of declarations.

**I1: a call typed as unique.** Hand-written repro: a split member `Foo(A: Integer): Integer`, then,
inside `#if X`, a plain `Foo(A: Text): Text` and a caller `exit(Foo('x') + Foo('y'))`. The wrapped
overload is not counted, so the split member looks like the only `Foo`, the call types as
`Integer`, and `swap-additive` emits `Foo('x') - Foo('y')`. `alc`: the original passes under `[]`,
`[X]`, `[Y]` and `[X,Y]`; the mutant FAILS with AL0175 under `[X]` and `[X,Y]`.

**I2: a local that no longer hides a global.** Hand-written repro: a global `AMT: Integer`, and a
plain procedure whose `#if not CLEAN27` var block declares `Amt: Text`, with `Amt + Amt` in its
body. The local is not indexed, and since [[R322]] the global lookup ignores case, so `Amt` types
as the global's `Integer` and `swap-additive` emits `Amt - Amt`. `alc`: the original passes under
`[]` and `[CLEAN27]`; the mutant FAILS with AL0175 under `[]`.

**Regressions on `lethal/r302`, in rare shapes.** `master` emits nothing at either site: in I1 it
did not index the split member at all, and in I2 its case-sensitive compare did not match `AMT`.
The same class of bug already exists on `master`: with a plain direct `Foo(Integer): Integer` in
place of the split member (I1), and with the global spelled in the same case as the local (I2),
`master` emits the same `alc`-failing swap. [[R302]], [[R322]] and [[R324]] extend the old gap to
split members and to differently-cased names; they did not create it.

**How often.** The review's censuses:
- I1 in its split-member form: 0 in DC/Cloud and BaseApp. The older plain form, a direct procedure
  and a `#if`-wrapped one of the same name: 32 pairs in those two corpora.
- I2: 0 hits in all four corpora (DC/Cloud, BaseApp, System Application, BusinessFoundation), in
  either casing.

**Fix direction.** Either index `#if`-wrapped declarations (count a wrapped member under its names,
and read a conditional var block's locals), or treat any name declared in an un-indexed `#if`
region as unknown, so it gets no type. The second mirrors [[R327]]'s guard: count wrapped members by
name as `null` in `uniqueProcedure`, and treat a name declared in a conditional var block as
ambiguous. Closes with that change, both repros pinned through the pipeline, and `alc` passing on
them under every symbol subset.

**Done (2026-09-29, R-302 run 002, `7b8409c7`; pre-committed in the plan's run 002 addendum,
`d6f194d7`).** The second fix direction, as one fail-safe: every procedure-like declaration of an
object counts by name wherever the grammar put it (unindexed ones as `null`, so `uniqueProcedure`
gives no type), and a member's header names declared in its own `#if` region are ambiguous (no
type, and they hide a global). It covers the older plain form on `master` too. Measured: 0 mutants
removed in DC/Cloud, System Application, BusinessFoundation, the BaseApp scratch project and every
fixture, and 0 spec changes over all of BaseApp. The review's 32 plain same-name pairs therefore
produce identical output before and after; that is a measurement of the whole spec set, not a check
of each pair.
The three hand-written repros each lose exactly their `alc`-failing `swap-additive` and now compile
under every symbol subset; each fix goes red when reverted alone. The Tier-2 rule-3 guard
(`declaresProcedure`) still reads only direct and swallowed members, so a `#if`-wrapped procedure
does not stop a Tier-2 claim; that mislabels a site but compiles, and is filed as [[R331]].

**Triggers, covered in the run 002 fix round (`d0a0a9e4`; pre-committed in addendum 2,
`f5075ab4`).** The first commit covered procedures and split members only; the re-review found the
same defect in triggers (I3): type resolution never read a trigger's locals, so a name used in a
trigger fell through to the globals, since [[R322]] also to a differently-cased one. Now any name a
trigger declares in its own header (plain `var` section or `#if` region) is unknown in type
resolution, and one declared only in a `#if` region no longer falls through to a global in
`lookupVar` (a plain trigger local still resolves to its declaration). Four repros (the
differently-cased form plain and in `#if`, a field trigger, and master's same-case form) each lose
exactly their `alc`-failing `swap-additive`. Measured: 0 change in the four committed corpora and
every fixture; over all of BaseApp, 4 valid `swap-additive` mutants in one `OnValidate` trigger of
the Service Header table are lost (the trigger local and the global have the same record type, so
they compiled). That is under-generation, the safe direction; keeping them needs trigger locals
typed by their own declaration, which this item leaves out.
