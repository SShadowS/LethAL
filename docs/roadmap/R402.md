**Found by the R-378 lane (lethal-preproc), 2026-10-02.** Plan: `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md` §1 A4.

**What happens.** A loop condition with a directive inside it:

```al
while (A < 10)
#if LETHALX
    and (B < 5)
#endif
do begin
    A := A + 1;
    B := B + 1;
end;
```

Built with `LETHALX`, `B` is in the compiled condition, so `B := B + 1` can make the loop run past its budget. `classifyHangCapable` (`packages/builtin-tier1/src/loop-hazard.ts`) does not tag it: the `B` operand is not in the condition subtree the walk reads. This was measured through `generateMutationSet` on master b1bc7e2e: `B := B + 1` is untagged under both `[]` and `[LETHALX]`, while `A := A + 1` is tagged under both. That is the unsafe direction for a hang tag: a hang-capable mutant goes unflagged.

**The other half, a measured limit.** `identifiersIn` (in `loop-hazard.ts`) reads every named descendant of the condition and does not check arms. No shape was found in which an INACTIVE operand lands inside that subtree. A split loop header makes R214 refuse the whole file (`marker-mismatch`). That is a limit of what was measured, not an invariant.

**What would close it.** Find how the grammar places a directive inside an expression, then read the operands of the compiled arms as part of the condition. Inactive ones are skipped through `SemanticContext.armOf` (R378). Add a test of both builds, with `B` tagged only under `LETHALX`.
