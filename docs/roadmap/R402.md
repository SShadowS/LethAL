**Found by the R-378 lane (lethal-preproc), 2026-10-02.** Plan: `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md` §1 A4.

**What happens.** A loop condition with a directive inside it:

```al
while (A < 10)
#if LETHALX
    and (B < 5)
#endif
do begin
    A := A + 1;
    B := B + 1;
end;
```

Built with `LETHALX`, `B` is in the compiled condition, so `B := B + 1` can make the loop run past its budget. `classifyHangCapable` (`packages/builtin-tier1/src/loop-hazard.ts`) does not tag it: the `B` operand is not in the condition subtree the walk reads. This was measured through `generateMutationSet` on master b1bc7e2e: `B := B + 1` is untagged under both `[]` and `[LETHALX]`, while `A := A + 1` is tagged under both. That is the unsafe direction for a hang tag: a hang-capable mutant goes unflagged.

**The other half, a measured limit.** `identifiersIn` (in `loop-hazard.ts`) reads every named descendant of the condition and does not check arms. No shape was found in which an INACTIVE operand lands inside that subtree. A split loop header makes R214 refuse the whole file (`marker-mismatch`). That is a limit of what was measured, not an invariant.

**What would close it.** Find how the grammar places a directive inside an expression, then read the operands of the compiled arms as part of the condition. Inactive ones are skipped through `SemanticContext.armOf` (R378). Add a test of both builds, with `B` tagged only under `LETHALX`.

**Closed 2026-10-02 (65e5cad2). Plan r3: `docs/superpowers/plans/2026-10-02-R-402-hang-tag-active-arm-operands.md`.**
- **Shapes.** 31 shapes and controls were parsed and alc-compiled, both the unmutated source and the instrumented artifact, under `[]`, `[X]`, `[Y]` and `[X,Y]`. They are in `scripts/fixtures/r402/`, and the tool is `scripts/r402-shape-sweep.ts`.
  - A `while` tail (`#if X and (B < 5) #endif`, `#elif`, `#if not`) sits as a `preproc_conditional_expression_tail` BESIDE `condition`, so the walk missed it.
  - Tails inside call arguments, subscripts and list elements sit inside `condition`, and were read even when inactive (an over-tag).
  - A `repeat ... until` tail is misparsed as a separate statement, which breaks the artifact (R408).
  - An operand prefix, a nested tail and an `#if`/`#else` whole header are already undecided under R214.
- **The fix.**
  - `classifyHangCapable` now reads condition identifiers through one walk (`conditionIdentifiers` in `loop-hazard.ts`). It covers the condition subtree plus the tails beside it, skips nodes in inactive arms, reads undecided ones (the safe direction for a hang tag), and never reads directive markers or their symbol conditions.
  - `evaluateArms` refuses a file where a statement-level `#if` continues an unterminated statement (`continuationRefusal`, reason `directive-continues-statement at line N`). It is separator-aware: comments, pragmas and regions are skipped as trivia. It admits a `;` sibling, an owned `;`, empty, trivia-only and `;`-first arms, keywords, and a preceding preproc container.

  - `packages/engine/tests/r402-continuation.test.ts` covers the owned terminator, on a hand-built tree.
