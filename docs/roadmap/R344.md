**Found 2026-09-29, while closing [[R242]].** After provisioning, `runSession` re-runs the R149
contract probe with `--package-cache <pin>`, because that is the argv every one-shot mutant uses.
Since R242 a `--server` backend declines the pin, yet the re-probe still runs whenever provisioning
reported a directory.

**What is wrong.** On a server session the probe measures one-shot command lines that no mutant
runs. `runAlRunnerContractProbe` makes FIVE al-runner invocations, THREE of them with the pin, and
a refusal there stops the run before it produces any verdict. So a server session can be refused
over a contract it never uses. When the run does proceed, its verdict values are unaffected.

**Fix.** Run the pinned re-probe only when the session backend consumed the pin (the same answer
`usePlatformAppsDir` gives). Whether the server transport needs a contract probe of its own is a
separate question.

Evidence: `runSession` in `packages/runner/src/orchestrator.ts`, the R149 block right after
`pinPlatformAppsDir(cfg.backend, ...)`.

**Closed 2026-10-23 by ruling (R654 S4).** R654 S3 (35f3c67f) deleted the .NET al-runner, its contract probe
(`runAlRunnerContractProbe`) and `pinPlatformAppsDir`. The `--server` session this item describes no longer exists.
v3 has its own contract probe (`runV3ContractProbe`), which runs the argv v3 sessions use.
