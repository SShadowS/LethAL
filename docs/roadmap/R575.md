**Filed 2026-10-10 by the R-571 plan review** (`/coord/reviews/R-571-plan/adversary-r1.md`, finding 5; coord
task R-571). Both are UNDER-refusals that already exist on master: a mutant that can hang is deployed. Neither
blocks [[R571]].

**1. `this.P(R)` in the same object.** R531's same-object hop follows only a BARE call (`P(R)`). A call written
`this.P(R)` is not bare, and R571's cross-object hop skips procedures of the loop's own object. So the callee's
consumers of R are not refused.

**2. Two variables of one SingleInstance codeunit.** A loop can test one variable and consume through another:
`while not A.IsEmpty() do B.Pop()`, where `A` and `B` are both declared as the same `SingleInstance` codeunit.
Both variables reach the same instance, so `B.Pop()` empties the set `A.IsEmpty()` tests. R531 matches receivers
by name, so `B` is not the loop's receiver and `Pop` is not followed.

**To close.** (1) Treat `this.P(...)` like a bare `P(...)` in the same-object hop. (2) Treat every variable of a
`SingleInstance` project codeunit as the same receiver as any other variable of that codeunit in the scope.
Measure the corpus price, per mutant, and say whether any ordinal moves.

**Closed by ruling (R-573, 2026-10-23).** Evidence: `/coord/handoff/R-573/measure.md`. Counted by parse over
fixtures, CDO, DO, DC and BC.History.

- Mutants a fail-closed fix would refuse: 0 in every corpus. Cost: 0.

R572), and (b) widens the loop's receiver set. Each needs a red test.
