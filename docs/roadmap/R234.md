---
id: "R234"
title: "`--changed-since` misses edits in files marked `assume-unchanged` or `skip-worktree`, so their changed lines get no mutants"
section: "correctness-risks"
status: "open"
order: 946
---

**Measured in the GH-25 final review** (2026-09-25). `git update-index --assume-unchanged` and
`--skip-worktree` tell git to stop checking a tracked file for edits. `git diff` then compares the
index copy, not the file on disk, so a working-tree edit to such a file yields no hunk. LethAL
still parses and deploys the file as it is on disk. The result is that the edited lines get no
mutants, and if the edit changed the file's line count, the ranges of any committed change in that
same file no longer line up with the text LethAL parses.

This is the one input where `changedLinesSince` (`packages/runner/src/line-filter.ts`) still
reads something other than the working tree. Every other case in GH-25's edge-case table is
either handled or refused.

**Possible fix:** run `git ls-files -v` inside the project and refuse, naming the file, when a
`.al` entry carries the lower-case tag (assume-unchanged) or the `S` tag (skip-worktree). This is
the same refusal shape as the submodule and nested-repository checks. A real-git test would set
the bit on a fixture file, edit it, and expect the refusal.
