**Found 2026-10-06 by R-480's sample reading** (`/coord/handoff/R-480/classify.md`, side finding).

**What.** The hang refusal (R196, R446, R480) reads only AL `while`/`repeat` loops (and, since R480,
a `for` control variable). A report data item is a loop too: BC calls its `OnAfterGetRecord` once
per record. An `Integer` data item filtered `Number = filter(1 ..)` has no end of its own; it stops
only when a trigger calls `CurrReport.Break()`. BaseApp uses this shape for header and line
dimension text in many reports.

**Example** (BaseApp `Sales/Reminder/Reminder.Report.al`, data item `DimensionLoop`):
`OnAfterGetRecord` breaks when `Number > 1` and `not Continue`; it then sets `Continue := false`,
and sets it back to `true` only when the text overflows. Flipping `Continue := false` to `true`
(`flip-boolean-literal`), or deleting it (`remove-assignment`), means the break never fires after
the dimensions are used up: the data item runs on through every `Integer` record, which for a test
is a hang.

**Not measured yet.** How many data items have this shape (an open-ended `Integer` view, a
`CurrReport.Break` guarded by a variable the trigger writes), and how many mutants the refusal would
take. Siblings: `CurrReport.Skip` is no exit (R480 shape 6), and a request-page or `Query` loop is
not a loop here.

**To close.** Measure the shape on BaseApp, CDO, DC and DO; then extend the refusal so a data item
counts as a loop whose exit is its trigger's `CurrReport.Break` guards (or rule, with a reason).

**Closed 2026-10-06 (8cfa6094; plan `docs/superpowers/plans/2026-10-06-R-484-report-dataitem-loops.md`,
r5 after five sol reviews).** `loop-hazard.ts` now treats a report data item over `Integer` as a
loop. Other tables are out of scope.

The item is BOUNDED (not a loop) ONLY in one of three cases:
- `MaxIteration` is a literal from 1 to 1,000,000. This is an engine limit that no filter replaces.
- A `const` or closed `DataItemTableView` filter on `Number`, totalling at most 1,000,000 records, and
  ZERO mentions of the item's record anywhere in the report.
- The single-mention certificate: the record is mentioned EXACTLY ONCE, and that mention is a
  literal `SetRange(Number, lo, hi)` with lo <= hi and at most 1,000,000 records. It must sit in the
  item's own `OnPreDataItem`, be unconditional and be in an active arm.

A mention is the item's name anywhere in the report (as a receiver, an argument or anything else),
or any unqualified call in the item's own triggers.

For an open item, a value-operator write in any trigger of the item, or of an item nested in it, is
hang-refused when one of these reads its target:
- the guards of `Break`, `Quit` and `Error` in the item's own `OnPreDataItem` and `OnAfterGetRecord`;
- the guards of `Quit` and `Error` in a nested item;
- the item's own `SetRange`/`SetFilter` arguments.

These are not exits: `exit`, `CurrReport.Skip`, and the item's own `OnPostDataItem` guards. The
refusal is counted as hang-refused. `IDENTITY_SCHEME` is now 28.

**Frozen counts.** These are the exact identity-keyed dumps of the branch against master
`8ab62d43`, over every operator.
- BC.History: **609** mutants move from emitted to hang-refused: remove-assignment 362,
  flip-boolean-literal 172, shift-integer 75, swap-additive 0. By project: BaseApp 589, Withholding
  Tax 18, BankDeposits 2. No spec changes, and none appears.
- CDO, DC, DO, fixtures and examples are identical, so no gate moves.
- **216** identity keys move, all in BaseApp.
- swap-additive is 0 because it claims only operands the type table resolves. In a data-item trigger
  a bare global is not resolved, so that operator never reaches the classifier there.

**Over-refusal, stated plainly.** Most of the 609 are not proven hangs.
- r1's rule covered 451 of the 609. A hand sample of 32 of them gave:
  - 13 real hangs, for example BaseApp `Reminder` `Continue := false` and `RoutingSheet`
    `CopyNo := CopyNo + 1`;
  - 2 hangs that depend on the data;
  - 17 over-refusals, mostly preheader resets and trigger-locals.
- The 158 added since then are over-refusals almost by construction:
  - 133 are writes to a variable bound (`ErrorCounter` 74, `NoOfLoops` 42, `MoreLines` 17). No
    shipped operator can set such a bound near 2^31.
  - 8 are an `OnPreDataItem` start guard (`PrintLine`).
  - 8 are view-bounded items that the zero-mention rule voids. Their bound is still finite, for
    example `filter(1 .. 99999)`.
  - 9 were not read.

So roughly one refused site in three is a real hang. That is the conservative direction R196 and
R446 chose: an extra refusal costs a site, and a missed one can hang a session.

The exclusions are filed as [[R487]]: exits behind calls, indirect feeds, ordinary tables and growing
temporary sets, `Date` items, bounds set through another record, and condition-side mutants.
