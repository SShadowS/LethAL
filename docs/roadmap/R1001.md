Found by coord task R-942 (2026-11-14), DC window 1 on edge-847b1fa5a (amendment 6). Related: [[R1003]] (the refusal itself),
[[R927]], [[R786]].

**What happened.** Every one of DC's 1,839 baseline tests was refused before it ran with ONE text ("Company Triggers OnCompanyOpen
(Completed) subscriber ... InitCompany before the first test: CSC App Feature row not found ..."). The serve baseline still ran every
codeunit: 4,656 s, and each refused request closed its daemon (the text is not on the keep-list), so 117 daemons started. The session
then ended with exit 4 (no green test), having learnt nothing after the first codeunit.

**Why the batch-refusal stop did not catch it.** R927's probe (`probeBatchRefusal`) runs only on an EXPLICIT serve-entries transport
(the default never probes), and it judges only `entries-batch-refused`: al-runner refusing a whole REQUEST with one reason. Here
al-runner answered each request with rows, each refused with the same text; nothing in the baseline judges identical row refusals.

**To build.** During a v3 baseline (serve or one-shot): once the first N codeunits (or M minutes) have returned only refused rows,
all with one normalised text, stop the session by name with that text (an exit and report that say "every test so far is refused
with: ..."), rather than run the rest. N and M chosen so that one odd codeunit never stops a run; a pinned test per direction (stops on
a uniform refusal; never on a mix, never on one codeunit).
