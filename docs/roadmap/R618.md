**Filed 2026-10-22 by lethal-bugs at R-586's accept** (orchestrator ruling).

**What.** [[R586]] put `runMayLend` in `store.ts` in front of every place where a session reuses an earlier run:
- history (`priorSurvivorKeys`);
- `--resume`;
- `--resume-run`;
- baseline-snapshot reuse.

It runs `backendBuildRefusal` first (backend and `runner_build`), then R557's al-runner checks. With R-389's
pending/revoked identity handling in `findBaselineSnapshot`, this order now decides what a BC session may carry over.

The BC gates do not exercise it with a run actually lent. R-586's final-head BC gates (`itest:bcdev`, `itest:tables`,
`itest:chunked`, `itest:bcdev-names`, `itest:verify`; `/coord/handoff/R-586/bc-gates/`) all start from an EMPTY
results store. None of them sets `--resume`, `--resume-run` or `--skip-known-survivors`, and `itest:verify-scale` and
`itest:agreement` say "No resume" in their code. So history returns before the first check, and snapshot reuse
(which needs `resumeState`) is never reached.

**What covers it today.** The unit tests of `runMayLend` and `backendBuildRefusal` (R586's T14), and R-586's
`al-runner-v3` legs. bcdev-to-bcdev lending is unchanged by construction, since `backendBuildRefusal` refuses only when
one side is `al-runner-v3`. But a live BC run has never shown it.

**Why it matters.** A wrong lend is a carried verdict, the riskiest kind of wrong result. It is invisible to every
per-mutant gate that starts fresh. A regression in the order, a filter or R-389's pending exclusion would pass every
BC gate today.

**To close.** A BC gate (or a leg of `itest:bcdev`) that:
1. runs the fixture once, to fill a store;
2. runs it again on the SAME store with `--skip-known-survivors`, and asserts per mutant which survivors were carried
   (and that their verdicts equal a fresh run's);
3. interrupts a run and resumes it with `--resume` (and `--resume-run`), asserting the carried and re-run mutants by
   name;
4. as its negative half, seeds the store with a run from another backend or another `runner_build` (or a pending or
   revoked identity), and asserts that NOTHING is lent, with the named warning.

The figures are pre-committed first; a red-check per direction.
