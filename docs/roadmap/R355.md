**Found by the review of R-354 run 001 (2026-09-30).** Review:
`H:/lethal-coord/reviews/R-354-001/review.md`, Important finding.

`freezeStageTo` (`packages/runner/src/campaign-freeze.ts`) stores normalized per-mutant verdicts, which
do not record the coverage mode, and `campaign compare` (`campaign-subcommands.ts`) compares them
without it. So a stage frozen under `procedure` coverage and a later run under `none` can compare
"identical" even though an unreached mutant means `no-coverage` in one and `survived` in the other.
It injects no old verdict into a new run (R354 covers that); it treats an old-mode baseline as valid
comparison evidence.

**To close.** Since R252 every new report records `coverageMode`. Make `campaign compare` read it
from the frozen stage report and the new report, and refuse by name when they differ, or when the
frozen one predates the field and the new one's mode is not the one the stage was frozen under
(decide how an old frozen stage without the field is handled; the safe direction is to say so,
never to assume). Test both directions, red-checked.
