**Filed 2026-10-25 (coord task R-762, an owner request).** The owner asked how al-runner-v3 can run faster, and whether
LethAL passes wrong options to al-runner. Eight levers were listed; each was measured or moved.

**Ranked summary** (full table in `docs/measurements/2026-10-25-r762-v3-levers.md`):
1. Contract probe every session (about 10 s): cached, R765. Gift card serve 12.8 s -> about 4 s.
2. Coverage on calls that never read it: kill confirms R764; the Sleep coverage rule retired on builds whose pin
   records `sleep-is-noop` gone, R768.
3. `assertBound` per send (0.35 s): R767 (lethal-spare). Whether the alc proof can be skipped on #5602-gone builds: R769.
4. Parallel lanes: R766 (lethal-code).
5. `--run-selected-only`: no saving, nothing to skip (LethAL selects whole codeunits). Do nothing.
6. Covering-only test selection: ceiling under 3% of wall. Not worth building.

**Not measured:** `--isolation` (test vs codeunit vs required), `AL_TEST_THREADS` / `AL_CHECK_THREADS` /
`AL_LOWER_THREADS` and several serve daemons, and the other `al-runner test` / `serve` options (`--affected`,
`--no-compile-cache`, `--require-compile-cache`). Echo once per daemon (rather than once per send) is built only as far
as R768 removes the second echo.

**Evidence:** `/coord/handoff/R-762/` (lever1.md, covering-only.md, lever4.md, b-figures.md, cache-proof/proof.md and
proof2.md). **Findings:** `docs/measurements/2026-10-25-r762-v3-levers.md`.
