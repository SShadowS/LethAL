Found by coord PR-299 (lethal-bugs) and confirmed by the owner (q-20261121T203539-a7741f50).
- **DO's CI:** it runs its tests in a client session (GuiAllowed true; build 828949, run 1344043, 2,154 of 2,154 passed,
  including a test that fails headless).
- **LethAL's bcdev harness:** it runs the tests inside the control app's ODataV4 call, so `GuiAllowed` is false (R895,
  `docs/using-lethal-from-an-agent.md`).

**The size, on DO** (`/coord/handoff/PR-299/result.md`): 60 of the 422 BC-checked tests differ by session kind, all of them
predicted by a static `GuiAllowed` scan:
- **39 pass with a client and fail headless,** mostly "UI handlers were not executed": a test's `ConfirmHandler` or
  `MessageHandler` never fires without a client.
- **16 pass with a client and are skipped headless.**
- **5 fail with a client and pass headless** (an unhandled Confirm that BC answers by default).

**Why it matters:**
- A test that fails at the bcdev baseline leaves the green set. A mutant covered only by such tests then becomes
  no-coverage, or survives, on bcdev, while the project's own CI would run, and maybe kill, it.
- A test that takes the non-GUI branch measures code the CI does not.
- So on such projects the authoritative backend's score is for a different execution path than the CI's.
