## Review round 2 (2026-10-02): a later object with code refuses; skipped files stop a row

**The rule (orchestrator ruling).** "More than one object" used to count only kinds with a coverage
identity (codeunit, table, page, report, query, xmlport, table and page extensions), so an enum then
a codeunit passed, though the codeunit is the file's SECOND object, the one al-runner reports in the
wrong frame. Now a file is refused UNLESS every object after its first top-level object is
CODE-FREE. The first object may be any kind. One predicate, `refusedAsMultiObject` (`line-map.ts`),
serves `alRunnerCoverageSupport`, the CLI guard (which reads its `multiObjectFiles`) and the index
skip. Code-free is an explicit allow-list: `permissionset`, `permissionsetextension`, `enum`,
`interface`, `entitlement`, and only when the node holds no `procedure`, `trigger_declaration`,
`code_block` or split procedure. Anything else after the first object refuses: a code-bearing kind,
an `enumextension`, a top-level `ERROR` or an unknown kind (fail-closed).

**Why the list is not wider, from the grammar.** tree-sitter-al 4.4.1 (the crate the native parser
pins) gives every declaration kind the same permissive body: `grammar.js` line 475
`permissionset_declaration: _object_with_id('permissionset')`, 487 `enum_declaration`, 529
`entitlement_declaration: _object_without_id('entitlement')`, all with field `body:
declaration_body`, and 559 `interface_body: repeat1(choice($._body_element, $.interface_procedure))`.
`node-types.json` lists `procedure` and `trigger_declaration` among the children of both
`declaration_body` and `interface_body`. So the grammar shows NO kind code-free (`enumextension`
included, so it is not added); the allow-list rests on AL itself, and the code-node check refuses an
allow-listed object that parsed with code anyway.

**`#pragma` is not an object.** A `#pragma` line is a compiler directive, it never moved a base before
R383, and it is the ONLY non-declaration kind at top level in any corpus below (166 in BaseApp, 11
in System Application). Counted as an object, it would have refused 146 BaseApp files and 10 System
Application files, every one because of a pragma. Round 1's partition DID move the base past a
`#pragma`: in the 63 BaseApp files with a pragma before an indexed object, that object's base line
was one too high, so on bcdev every covered line of it was looked up one line off. Fixed, back to the
pre-R383 behaviour, and pinned by test.

**Census under the final rule** (`alRunnerCoverageSupport` on each root; "before" is the old
indexed-only count):

| --- | --- | --- | --- |
| fixtures (repo) | 76 | 2 | 2 |
| DC (`U:/Git/DC`, app dirs, `Test` excluded) | 546 | 0 | 0 |

File counts leave out dot-directories (`.dependencies`, `.alpackages`); the guard's own scan includes
them and gives the same refusals. `CDOPermissions.al` (three permission sets) is admitted, so the
prevalence correction above holds again. No corpus has a top-level `ERROR`, so fail-closed refuses no
real file. The fixture census also counted top-level `ERROR` and unrecognised nodes, which the
partition steps past: zero of each, and the two refused files are the same two as before
(`sandbox-multiobject`'s pair and `sandbox-coverage-probe`'s `TwoObjects`). No fixture changes
multi-object status or bcdev base line, so no frozen gate figure can move.

**Suffix leak.** A coverage row is matched on the longest path ending first. Only `#if`-wrapped files
stopped a row at their own path, so a hit on a skipped multi-object `src/Foo.Codeunit.al` could fall
through to an indexed `Foo.Codeunit.al` elsewhere. Every skipped path now stops it
(`AlRunnerCoverageIndex.skippedFiles`), on both transports; a file admitted by
`admitMultiObjectFiles` is indexed, so it is never in that list.

## Round 3 (2026-10-02, reject r2): split headers, merging, a measured first-object control

**Split headers.** tree-sitter-al 4.4.1 lets an object be `preproc_split_declaration` (`grammar.js`
420, 426): `#if`-alternated headers over ONE shared body. The object count dropped every
`preproc_*` node, so a plain codeunit followed by one was ONE object and was admitted. Now every
preprocessor node that is not a directive line (`DIRECTIVE_ONLY_KINDS` in `line-map.ts`) counts as
an object, and a split declaration is never code-free, so after a file's first object it refuses
the file. As the FIRST object it is just the first object (base 1); it has no coverage identity, so
its own lines resolve nowhere. A `#if` wrapper holding only a split declaration now holds an object
(R298 refuses the file). **No earlier stage refuses the codeunit-then-split file**, measured with
`generateMutationSet` on it (scratch `r383r3/split-gen.ts`, symbols `[]` and `[FEATURE]`): 7
mutants, 4 of them in the split body. R214 refuses only an `undecided` file (`generateMutationSet`,
the `preproc-arms-undecided` warning), and `evaluateArms` (`preproc-arms.ts`) decides a plain
`#if FEATURE`. R305's skip (`generateMutationSet`, the `skipped` push) fires only when
`canCarryMutationSelectorVar` (`compile.ts`) finds no carrier kind anywhere, and the plain codeunit
is one.

**Merging.** Objects were merged by kind plus id, or the first header line for an interface, across
the whole file, and only the first node was kept. Two separate multiline `interface` headers both
key `interface`, so a second one with a procedure body was dropped before the code check; it could
also fold into a FIRST interface and escape the "after the first" rule. Now nodes merge only as
alternative arms of one top-level `#if` wrapper, and the code check runs on every arm.

**A measured positive control for the first object.** Round 2's control edited a captured row from
0 hits to 1 and invented a server statement; it stays as a synthetic MAPPER test. The measured one:
the SAME instrumented bundle (byte-identical `MultiPair.Codeunit.al`), on the pinned
v2.12.0-main.c39ad5de, with a copy of `sandbox-multiobject-tests` plus one test, `CallsNever`
(`MultiA.Never(1)` must be 8), placed beside `fixtures/sandbox-multiobject` so al-runner discovers
the source as it does for the real tests (scratch `r383r3/capture.ts`). One-shot (`--coverage
--coverage-out`) and `--server` (`perTestCoverage`) both report A at 8, 10, 14 and 20 (the three
Active checks and `exit(X + 7)`), in the instrumented frame, scope `Never` on the daemon; both
resolve to exactly `Multi A.Never` 8, 10, 14, 20. The same run's `ReachedBothWays` payloads equal
the round-1 capture. Committed as `cobertura-calls-never.xml` and `server-calls-never.json` under
