(`H:/al-runner-builds/c39ad5de`) the orchestrator is evaluating; re-run the probe there before
relying on these facts on that build.

**Probe.** Scratch app and test projects (copied from `fixtures/sandbox-app`'s `app.json` shape),

`--output-json --isolation test --test <filter> --auto-provision --coverage --coverage-out <xml> <app> <tests> --package-cache <.alpackages>`.

**Frames.** Both transports report **file-relative** line numbers: B's first statement at file line
19 is reported as 19, not as the object-relative 7. Cobertura has one `<class>` per FILE with no
per-object split; the daemon keys by file path and names each statement's procedure in `scope`,
and it omits statements that were not hit (Cobertura reports them with `hits="0"`). A daemon
statement `id` restarts at 0 per procedure.

## Built 2026-10-02 (offline), live check pending

Plan r3 built on `lethal/r383`, offline only; no al-runner or BC run was made for it.

- **Partition** (`fileLineMapEntries`): every top-level object moves the base line, indexed or not.
  An enum, interface or permission set before a codeunit used to give the codeunit base 1; fixed for
  bcdev too.
- **Resolver** (`resolveFileLine`, `line-map.ts`): a file-relative line to `(type, id, object line)`
  by the declaration's file span, with the same base `spansOf` uses. A gap, an unindexed object or a
  refused object gives no entry.
- **Both transports resolve by position.** Cobertura: object and object line from the resolver, then
  `lookup`. `--server`: object from the resolver, never from `scope`; procedure by r3's order
  (R318's renamed-member rule first, and inside a renamed member it decides alone; a line `lookup`
  leaves unnamed keeps `scope`; otherwise position wins with one warning, never dropped).
- **Guard:** the multi-object half is gone (`supported`, the CLI fallback, the index skip);
  `multiObjectFiles` is still reported, and every `#if`-wrapped refusal stays.
- **Live check, pre-committed** before any run:
  `docs/superpowers/specs/2026-10-02-r383-multiobject-precommitment.md`, on the new pair
  `fixtures/sandbox-multiobject` + `-tests` (killed 6, survived 1, no-coverage 5 over 12). The
  `itest:alrunner` legs (one-shot and `--server`) are written and NOT run; their baseline
  `al-runner.multiobject.baseline.json` is registered under R332 as pending its first record, so the
  gate refuses to start until it is recorded. Still to do: bcdev once on Cronus28 under a lease,
  then the al-runner legs, then the record run.
- **Known limit, stated in the pre-commitment:** a base exactly one line off cannot move a verdict on
  this fixture live, because the emitter's closing lines separate the procedures in the instrumented
  text. That case is pinned offline instead.
