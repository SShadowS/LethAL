**Filed 2026-10-24 by R-696 (lethal-bugs)**, evidence `/coord/handoff/R-696/numbers.md` and `probe/results.md`. A
plausible hang that is NOT refused. Limits of the [[R696]] rule that were accepted, not measured.

**What.** [[R696]] refuses a Next-driven loop whose BODY moves the record it walks (a Rename, a Modify after a key
write, a ModifyAll of a key field, an Insert) through a second variable. It reads only the loop's own procedure:

- **No callee is followed from a Next loop.** A mover, or an insert ahead of the cursor, made inside a procedure the
  loop calls (same object or another) is not seen. 3,134 of the 7,895 production Next loops (40%) pass the walked
  record to a call (`numbers.md`).
- **Temporary walks are skipped.** A walk over a temporary record cannot be moved by a permanent variable, but a
  second variable bound to the SAME temporary table (passed by `var`), and R's own insert into a walked temporary
  table, were not probed.
- **A RecordRef walk (`RR.Next()`) is not read.**
- **A guard in a helper**, and a bound set by a caller, stay outside (the caller-set sort key fails closed, so only
  the guard is lost).

**To close.** Run a callee census: for each Next loop that passes R to a call, read whether the callee moves or inserts
into R's table. Add a temporary-table probe leg (a second variable of the same temporary table; R's own insert into
it) on bc2. Then extend the rule, or close with a ruling.
