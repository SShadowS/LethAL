[R135](R135.md) closed by ruling that LethAL does not mutate declarative surfaces. This row keeps its
Option A alive as a measured, costed thing nobody has asked for, so the measurement is not lost and
the next person to want FlowField coverage does not have to re-derive it.

**What Option A is.** Compile one artifact per declarative mutant with the mutation applied in
SOURCE, publish each, run the covering tests, unpublish. No runtime guard, because a property cannot
dispatch at run time.

**What it costs, measured 2026-08-14** (`scripts/r135-publish-probe/`, Cronus281, BC
28.0.46665.47126):

- publish + sync + install is a flat **~4.4 s** for a two-table app, and what changed does not move
  it — a one-property change (4404 ms), an unchanged republish (4433 ms) and a real schema change
  (4351 ms) are within noise of each other.
- That 4.4 s is a FLOOR. BC publishes whole extensions, so a per-mutant artifact for a real app is a
  whole-project publish: **40.8 s** on Continia Document Output (R45), and R90 measured single-file
  hosted DO publishes at 36–97 s with 331 guards timing out entirely.
- Today's amortised deployment cost is **0.25 s per mutant** (one 40.8 s deploy over 163 mutant
  sites). Option A makes that 40.8 s each, about **163x**, and 91 CalcFormula mutants on DO would be
  **~62 minutes of publishing alone**.

**Why it is blocked on demand, not on effort.** The deployment works; the probe proves it. What
stops it is that it is a second deployment mechanism rather than a slower one — batching,
`AlcCompileError` bisection, resume, the artifact-id echo, the 5C-B1 lease and quarantine all assume
one artifact per batch with a selector inside it — and that publishing is the failure-prone step
(R44's proxy timeout, R90's publishes that fail while exiting 0), so multiplying publishes multiplies
the risk that stranded a real run.

**The question that must be answered before any of it.** Coverage attribution for a declarative
mutant is unsolved and is NOT the attribution problem this repo has already solved. A mutated
`CalcFormula` runs inside BC's own `CalcFields` implementation, not in AL that the coverage map can
name, so nothing measured says which tests reach it. Shipping declarative mutants without an answer
would produce `survived` verdicts against tests that could never have killed them — the exact defect
[R140](R140.md) was filed to remove from the trigger path.

Reopen this only with: a user who wants the surface enough to pay the cost above, and an answer to
the coverage question. Full reasoning in
`docs/superpowers/specs/2026-08-14-r135-declarative-mechanism-ruling.md`.
