Coord PR-79 (2026-11-16). Owner ruling q-20261116T134341-645f4a0f, part 2 of option 3 (PR-77 built part 1, R1084). Spec:
`docs/superpowers/specs/2026-11-16-pr79-accept-list.md`.

**Built** (`packages/runner/src/accept-list.ts`, `changed-line-survivors.ts`, `cli.ts`).
- `lethal.accepted.json` in the `--project` folder. Each entry carries the file, the identity tuple, the site's place inside its
  member (`lineInProcedure`, `column`), a hash of the site's lines, a hash of the whole member (attributes in, and for a trigger
  every enclosing declaration header up to `{`), the build's preprocessor symbols and a reason. Parsing is strict; the file is
  read and checked before the session starts, only on a run with `--lines` or `--changed-since`.
- The anchor is computed from the run's own source snapshot, never from disk and not from R443's marks. `lethal run` prints a
  ready entry under each counted survivor. A survivor with another row on the same anchor, or no usable procedure span, prints
  "cannot be accepted" and why.
- An entry accepts a survivor only when exactly one row of the run, of any verdict, matches it. Accepted survivors are listed
  with their reasons and never count toward `--fail-on-survivors`. Equivalence marks do not exempt a survivor.
- One label per entry: accepted, killed, not measured, re-opened, identity changed, ambiguous, or one summary line for the entries
  that match no site of the run.
- Docs: `docs/ci/README.md` ("Accepting a survivor") and `docs/ci/threshold-options.md` (part 2).

**Deliberate choices** (the spec's wording left room): a row whose offsets or original text do not match the snapshot (a carried
row from another source) gets no entry and is named, instead of aborting the run; a member whose re-parsed lines disagree with the
row's does abort, as the spec says. For a trigger inside a nested declaration the printed `tuple` has the enclosing headers
before the trigger name, so two triggers of one name in different fields do not share a tuple.

**Known limits, accepted** (stated in the docs): an edit outside the member (a callee, a global, a table trigger, an event
subscriber) does not re-open an entry; after a merge the entry is re-checked only when the site's own line changes again;
`app.json` is not part of the anchor.
