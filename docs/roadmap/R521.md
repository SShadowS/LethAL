**Filed 2026-10-08 by the [[R500]] build** (plan r3 `/coord/reviews/R-500-plan/plan.r3.md`, shape 2). A plausible
hang that is NOT refused.

**What.** R500's one-hop rule finds a callee through the receiver's declared type (`declaredType`: `Record`,
`Codeunit`, `Interface`) or a record the engine binds (`resolveReceiverTable`). A call through a `RecordRef`, a
`Variant`, a `FieldRef`, or a parameter or return value whose type this lookup cannot read is not followed, so
the procedure it reaches in another object is still mutated. Three more receiver shapes are not followed either
(the R-500 build review, `/coord/reviews/R-500/opus-build.md`, F2): an array element (`Post[1].Step()`, whose
receiver is a subscript, not an identifier); a `Report` or `Page` typed receiver (`objectsOfType` maps only
codeunits, records and interfaces); and an implementer whose `implements` names a namespace-qualified interface,
which the grammar parses into an `ERROR` node, so the implementer is not found.

**To close.** Count the untyped receivers called from open report-item code on BC.History, CDO, DC and DO; read
a sample; then refuse their possible targets (all implementers or tables) or close it with a ruling.

## Done 2026-10-10 (coord task R-521, branch `lethal/r521`)

Measured in `/coord/handoff/R-521/measure.md` (census of every unfollowed seed call, by class, with a price in
deployed mutants and a hand-read sample); identity effect in `/coord/handoff/R-521/reproduce.md`; red checks in
`/coord/handoff/R-521/redcheck.md`. DC, DO, CDO and the fixtures have no open report-item code, so every class
below is 0 there; the numbers are BC.History's (519 projects, 2,224,635 deployed on master `4b71102a`).

**Built: a multi-name declaration declares every name.** PEPPOL's `Sales Invoice PEPPOL30` and `Sales Cr.Memo
PEPPOL30` XMLports declare `PostedHeaderIterator, PostedLineIterator: Interface "PEPPOL Posted Document Iterator"`.
XMLports are not in the symbol table, and `declaredType`'s fallback read only the FIRST name, so
`PostedLineIterator.GetNextPostedLineAsSalesLine` was not followed. The line loop's only exit is `currXMLport.Break`
when that call returns false, and master deployed 12 mutants in each iterator implementation (`remove-assignment`
of the position step, `return-value` of `exit(Found)`, ...): **2 real hangs**. The engine's `declaredNames` is now
exported, and four loop-hazard sites read every name: `r531Declares` (the shadow check), the open-item globals in
`presetExitNames`, `declaredType`'s fallback, and `protectedVarNames` ([[R548]]). Price: **26 keys removed**, all
PEPPOL (`PEPPOL30 Sales Iterator` 12, `PEPPOL30 Services Iterator` 12, `PEPPOL30 Unknown Format` 2), 0 added, 0
moved, on all 138 corpus projects that hold a multi-name declaration. No identity scheme bump.
`packages/builtin-tier1/tests/r521-multi-name.test.ts` has one red-checked test per site.

  codeunits or interfaces, or a record-array call that fires a project trigger, appears in open-item code.
- **Page-typed: 0.** Re-open if a Page-typed receiver appears in open-item code.

- **The remaining unread receivers: 520 calls, 23 deployed (about 0.001%).** Unbound data-item and tableelement
