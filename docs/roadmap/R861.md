**Filed 2026-11-07 by lethal-bugs.** Related: [[R814]].

**What.** `--edge-rejudge` writes a ledger row and can move `current`, but it never called `publishPending`, so the row stayed off master until the next plain run. Seen on edge 6bb821b98. A machine with `.gated` beside the binary was not harmed; the manifest was just a day behind.

**Other routes.** `current` moves in `gateOne`, for a candidate that is not a release: only `edgeLocked` and `edgeRejudge` reach that. `edgeOnce` and `dailyOnce` already publish. `--regate` adds no row, a release does not move `current`, and `--refresh-rows` writes the branch's manifest itself, by design. So this was the only gap.

**Fix.** `edgeRejudge` calls `publishPending` after its gate.
