Filed and closed by coord PR-66 (2026-11-16). Spec: `docs/superpowers/specs/2026-11-16-pr66-resume-warning-lineage.md` (addendum
1). Related: [[R1060]] (PR-47's named warning, its case (a)).

**What.** DO window t8 resumed run 8 (t7) on a tree PR-44 and PR-48 had changed, ran its whole baseline, and named no reason.
PR-47's case (a) read the resumed run's own stored snapshot. t7 had reused run 7's snapshot and stored none, so the lookup found
nothing and stayed silent.

**Fix.**
- A new store table `baseline_snapshot_reuses(run_id, batch_index, from_run_id, from_batch_index)`, written when a batch's
  baseline is reused.
- The warning compares with the resumed run's own snapshot, else with the snapshot it recorded reusing (suspect and lost
  excluded), else nothing (silent).
- A guess by run order was built first and dropped: an aborted baseline would have warned falsely.

**Limit.** A store written before this change holds no reuse rows, so DO's current store stays silent for t8's case. The warning
names it from the next window on.
