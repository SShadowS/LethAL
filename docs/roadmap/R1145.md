Filed by coord PR-226 (lethal-code, 2026-11-19) on the orchestrator's ruling (option (c)). The spec is
`docs/superpowers/specs/2026-11-19-pr226-update-gate-private.md` §6, "which file PERF-10 points LethAL at".

**The gap.** `checkGated` (`al-runner-v3-pin.ts`) hashes the exact file `alRunnerV3.path` names, and reads `.gated`
beside that file. A performance run that wants to wrap each al-runner daemon therefore cannot point LethAL at a wrapper.
That wrapping covers `perf stat` on some daemons, the daemon's full stderr (LethAL keeps the last 64 KB), and `--timings`.
- A wrapper is not the gated build. A `.gated` that hashed the wrapper would trust it for a binary it does not hash, and
  the owner refused that (PR-226's option (b)).
- PERF-10 therefore runs on the gated copy itself. It pins with `taskset` around the whole `lethal run` and collects perf
  from outside, without the full stderr.

**The change, not built:** an optional `alRunnerV3.launcher`, a command prefix such as `["/path/wrapper.sh"]`.
- LethAL keeps hashing and gating `alRunnerV3.path` exactly as today. It only spawns `launcher + [path, ...args]` in
  place of `[path, ...args]`.
- The launcher is never hashed and never trusted for the binary's identity. The binary it is handed is the gated one.
- Its first argument must be an executable, refused by name otherwise. With no launcher, spawning is unchanged.
- The report records the launcher, so a measured run names it.
- Tests: a spawn with and without the launcher; `checkGated` still hashes `path`; a launcher that swaps the binary is out
  of scope, because the launcher is the user's own tool, and the report says a launcher was used.

**Trigger to build:** a performance measurement that needs per-daemon wrapping that outside tools cannot do. Full stderr
(PR-227, `daemonStderrDir`) and `--timings` (PR-237, `serveTimings`) are inside LethAL now; pinning and `perf` per daemon
work from outside (PERF-10: `taskset` around the run, `perf stat -p` on sampled daemons).

**Designed, not built (coord PR-239, 2026-11-19).** Spec `docs/superpowers/specs/2026-11-19-r1145-al-runner-launcher.md`,
r1 + amendment 1 (spec-adversary). Orchestrator's rulings: the probe runs without the launcher; identity by process group
plus one exe-matched descendant (argv, environment and starttime checked), refused by name otherwise; sampling only through
`LETHAL_V3_DAEMON_ORDINAL`; the launcher enters the resume digest when set. The launcher wraps the serve daemon only, and a
timeout under a launcher is never scored (the adversary's two false-kill paths). Not built now: the process-group and
`/proc` identity surface is large for what outside tools cannot already do.
