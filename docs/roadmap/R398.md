**Found by R-307 (per-file skip), tasks 3 and 4.**

**What happens.** `objectHeadersOf` in `packages/schemata/src/project.ts` finds a file's object
headers with the `OBJECT_HEADER` regex. It has two limits:

- The name part is `\w+`, which is ASCII-only in JavaScript. An unquoted object name with a
  non-ASCII letter, such as `codeunit 79305 Ærø`, does not match.
- The regex anchors at line start. `namespace Demo; codeunit 50100 "A"` on ONE line does not match,
  because the header does not start the line.

In both cases the file has "no AL object header". Since R-307 that is a named refusal
(`FileRefusedError`, shape `no-header`): the file is skipped whole, listed in `excludedSites` with
reason `instrumentation-refused`, and the rest of the run goes on. Before R-307 it aborted the run.

**Evidence that AL accepts both shapes.** Measured 2026-10-02 with `alc` 18.0.41.45789
(`ms-dynamics-smb.al-18.0.2732683`), offline, on a throwaway app with two files: `codeunit 79305
Ærø { procedure Foo() begin end; }` and `namespace Demo; codeunit 79306 Plain { }`. Compile exit 0,
no diagnostics. A control file, `codeunit 79307 Bad Name`, was rejected with AL0104 and AL0198, so
the compile was really parsing the files. So these are real projects' valid code, not malformed
input.

**Why it is the safe direction.** The file is refused and reported, never mutated wrongly. The cost
is that its mutants are missing from the score, which `reliability: narrowed` and the
`files-refused` caveat now say.

**What would close it.** Match the name with a Unicode-aware class (`\p{L}\p{N}_`, with the `u`
flag) and let a header follow a `namespace ...;` or `using ...;` statement on the same line. Better
still, take headers from the parsed tree instead of a regex, since the tree already knows. Tests:
the two shapes above must instrument and must not hit `no-header`. The existing refusal fixtures
in `packages/runner/tests/per-file-refusal.test.ts` that rely on the `Ærø` name for `no-header`
will need another way to make a header-less file.
