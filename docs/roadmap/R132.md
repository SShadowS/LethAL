**R121's screen ships with its useful mode untested by any live gate.** The rule is "the failure text
does not begin with `Assert.`", and `SessionReport.assertionScreen.discrimination` reports which of
four things happened: `partial` (the rule separated something), `vacuous` (everything was flagged, so
it separated nothing), `none`, or `no-text`.

What the gates actually produce:

| gate | discrimination | why |
| --- | --- | --- |
| `itest:tables` | **vacuous** | all 22 tests in `fixtures/sandbox-data-tests` raise via bare `Error(...)` |
| `itest:bcdev`, `itest:envtool` | vacuous / no-text | same fixture style, on a smaller suite |
| `itest:alrunner` | not meaningful | different message shapes entirely (R101(f)) |

The tables gate now ASSERTS `vacuous` by name, which is the right assertion for that fixture — it
pins the measured limitation rather than a count that reads the same either way. But it means the
`partial` branch, the only one where a reader is told anything actionable, is proven by unit tests
and by re-scoring the committed 73-kill Document Output corpus, and by no live run.

**Two ways to close it, and they are not equivalent.**

1. **Give a fixture a Microsoft Library Assert dependency and a few `Assert.*` tests.** Cheap, and it
   would make some gate produce `partial`. But it would tune the screen on a fixture, which is
   exactly what R121 spent its history NOT doing: a rule tuned on the wrong stack shape is how the
   first two candidate rules got written and refuted.
2. **A second real project.** R121's own next step, and the one that would actually say whether
   26.1% precision generalises past one suite. Expensive, and it needs a project with a hand-
   classified kill corpus.

(1) is worth doing anyway, but only as a PIPELINE proof — "the `partial` branch runs live and reports
what the unit tests say it reports" — and it must not be described as evidence about the rule's
precision. Confusing the two is the specific mistake this row exists to prevent.

Filed 2026-08-09 alongside R121's close.
