**Filed 2026-10-25 by lethal-preproc, from coord task R-783.** Related: [[R589]], [[R658]], [[R669]].

**What.** The owner set up docker1 (192.168.2.77), a copy of server1's three BC on Linux servers:
- the same compose, image digests, ports per name and logins;
- the same builds: bc1 28.4.53241.56590, bc2 and bc3 .56646;
- a fresh CRONUS on every restart, with no LethAL Control and no Continia stack;
- 4 vCPU, against server1's 22 cores.

Server1 goes off at 04:00 CET on 2026-10-26. This spike measures whether the BC gates run on docker1. It is not a
switch: master and the normal configs keep naming server1.

**Steps.**
- On the spike branch only, make `HOST` (`scripts/bc-app-content.ts`) overridable by `LETHAL_BC_HOST`, with
  server1 as the default.
- Set up docker1's bc3 with Continia, under the bc3 lease.
- Run `itest:bcdev`, then `itest:hang`, on it, and compare the timings with server1's.
- Report what passes, what fails, and the config a switch would need.
