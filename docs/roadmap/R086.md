**No kill records WHY it died, so a false kill and a real one are indistinguishable in the record.** MEASURED 2026-08-03 on the R82 gate run: `failure_note` is `NULL` for **all 109** killed mutants in the run database. The fixture's arm E — a swap killed by BC's *"The length of the string is 18, but it must be less than or equal to 10 characters"* under a test that asserts NOTHING — is stored identically to arm A, killed by a genuine assertion. The distinction survives there only because the fixture was built to make it inferable; on a real project nobody can infer it, and the reader is told their tests caught something when the platform did. Direction of the error is the bad one: it flatters the suite. Not hypothetical and not operator-specific — any mutant that makes the platform raise (overflow, division by zero, a JIT field-load failure) reads as a kill the assertions earned. **THE GAP IS A READ, NOT A CAPTURE — this row said the opposite for one commit and the correction is the useful part.** The text is already persisted: `test_results.failure_message` is NOT NULL for **110 of 110** failing rows in the same run 148, message plus `;`-separated AL callstack, written by `RunMutantTransport.failureTextOf` (`packages/runner/src/run-mutant-transport.ts`) on the fenced path mutants actually take and stored with a `mutantRowId` FK. What is missing is one JOIN: `MutantOutcome` (`packages/runner/src/report.ts`) carries `killingTest` and `failureNote` but never the killing test's failure text. Anyone sent to the backend to re-derive this is re-deriving something already in the database. **AND THE DISCRIMINATOR THIS ROW FIRST PROPOSED IS MEASURABLY WRONG.** It said the top callstack frame being in the TARGET app identifies a platform artifact. Classified over all 109 mutant-attributed failing rows in run 148: **4 have a target-app top frame, and only ONE is arm E.** The other three (M0059, M0062, M0066) are ordinary kills where the target's own `TestField`/`Get` raised — *"Category must have a value in Data Main"*, *"The Data Main does not exist"* — which is exactly the class the R82 spec §4 insists must be read APART from a false kill, since production validation detecting a bad state is a real kill. **75% false-positive rate on the only run the rule has been checked against.** A candidate the data does support, and which needs its own measurement before it is written down as fact: the failing frame's statement is not the mutated statement AND the message is a platform-class error. Note also the fixture is structurally blind to how real assertion kills look — all 22 of its tests raise via bare `Error(...)`, while Continia Document Output's suite uses Microsoft's Library Assert ~1,886 times, which puts a THIRD app on top of the stack. Per R72's discipline a diagnosis must NOT move a verdict: a killed mutant stays killed, this is a `cause` field, never a re-scoring. The message is also PROSE and will localise (R66 measured that class), so an English-sentence detector would be another English-only detector. Evidence: `docs/measurements/README.md` §"R82 live"; both corrections found by an adversarial review of the landed work and re-measured independently.
