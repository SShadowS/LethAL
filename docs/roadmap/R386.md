**What.** R-371's reachable-set digest cannot follow code in another app. When a test passes a
test-app codeunit (an interface implementation, say), a test-app record, `this`, or an object
reference such as `Report::"Test Rep"` or `Database::"Table With Default Dim"` to an EXTERNAL call,
or to a platform or built-in call, that call is treated as an UNFOLLOWED edge (orchestrator ruling,
2026-10-01). The test then digests the whole test-app source, so any edit anywhere in the test app
turns it new. The same applies inside the subscriber and extension closures, where it puts EVERY
test on the whole-source digest.

**Why it matters.** It is safe (an edit can only make tests new) but costly. Measured offline with
`scripts/r371-reach-measure/product-measure.ts`, before and after the ruling:
- DC: 0.1% to 0.5% of 1,301 tests on the whole-source digest; P(N>50) for an object edit 22.8% to
  26.9%.
- DO: 0% to 0.5% of 1,287; object edit 21.2% to 25.0%.
- BaseApp Test: 100% before and after. Its subscriber closure passes object references to external
  code (for example `DimensionManagement.RenameDefaultDim` with `Database::"Table With Default Dim"`),
  so R-371 gains nothing on BaseApp until this is narrowed.

**Partly closed by [[R685]].** A reference or literal id of a test-app codeunit, page, report, xmlport, query or
table, a plain `Codeunit X` variable and an `Interface I` variable no longer fall back; they are folded. Still open:
a record variable, `this`, a page/report/xmlport/query variable, an array or collection element, a `#if`
declaration with any non-plain type, and an unreached caller's reference into a traced Variant parameter.

**What would close it.** Narrow the fallback to what the external call can actually run. A
reference to a test-app object only matters if that object has code that can run from there:
triggers, an interface implementation's methods, an `OnRun`. Fold just that object's parts and
reach instead of the whole source. A per-callee allow-list of external procedures measured not to
run their argument is a second, narrower option; it must be fail-closed.

**Closed by ruling (R-386, 2026-10-24), after two measurements.** `scripts/r386-fallback-census.ts` sorts each test's
fallback reason by the code path that built it (the templates are listed in its header), and
`scripts/r386-census-aggregate.ts` totals them. Run over the 179 test apps of R-685's set (BC.History,
do-lethal/Test, DC/Test, DO/Test) at master 714c767b: **53,936 tests, 29,030 on the fallback, 0 unclassified.**
Evidence: `/coord/handoff/R-386/measure.md`, `c1/` (baseline) and `c2/` (the allow-list variant).
- **This item's listed shapes keep 71 tests on the fallback (0.13%):** a record handed to external code 57 (3 apps), a
  `#if` declaration 11 (1 app), a collection element 3. `this` and page, report, xmlport and query variables: 0.
- **25,088 of the 29,030 come from subscriber closures:** one fallback in an app's subscriber fold puts every test of
  that app on it (17 apps). By cause in the fold:
  - a Variant parameter callable from outside: 8,918 (Tests-SCM 8,160);
  - a Variant array element: 8,752 (Tests-ERM);
  - an AllObj record (R390): 6,151;
  - dynamic object runs: 772;
  - interface dispatch: 396.
- **The allow-list ("second option"), measured as an upper bound** (a scratch variant, never built, that stops
  `LibraryVariableStorage.Dequeue`/`Enqueue` and `Assert.RecordCount` from counting as running their argument):
  29,030 -> 28,994, 36 tests, all in Tests-Cost Accounting. In every other app the next subscriber site falls back
  in its place, and those sites are deliberate safety rules: Tests-ERM `PAGE.Run` by id or variable, Tests-SCM an
  AllObj record (R390).
- **So neither narrowing is worth its risk.** A further gain needs a change to R389's or R390's rules, or to dynamic
  runs, which is a separate decision. The census is the baseline for it.
