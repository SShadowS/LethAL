**Found by** lethal-preproc on PR-479 (2026-11-28), while paging `ReadClientAttestation` (amendment 8 of
`docs/superpowers/specs/2026-11-28-pr479a-bcdev-client-driver.md`).

- **Why it matters:** R1244 measured bcwin (Windows BC 28.4) never delivering an OData answer over about 29.7 KB, LethAL's
  or not, and a few such calls wedging the server. bcwin's own fault is with kraken. But any server or proxy that caps
  response size would do the same to an answer that grows without a bound, and a lost answer stops a run, or on bcwin
  takes the server down.
- **The actions, each a single answer:**
  - `RunMutantWithCoverage`: one coverage row per covered line (the headless coverage path). A large codeunit's
    coverage is the likeliest to be big.
  - `RunMutantMany`: one result per method in the call, bounded only by the batch the client sends.
  - `ObjectOwners` and `FieldOwners`: up to 200 rows each (`OWNERS_MAX_ITEMS`); the size of a full answer is unmeasured.
  - `InstalledDependents`: one row per installed dependent app.
- **Not listed:** `HarnessInfo`'s arrays are fixed and small. `ReadClientAttestation` is paged by 1.0.0.32 (PR-479).
- **Next:** measure the largest answer each action gives on the fixtures and on the DO corpus, to see whether any comes
  near 30 KB. Page or cap only the ones that can.
