**Found 2026-10-05 while revising R-458 (r3)**, tracing the one row of R458's census that neither
R-458 nor R-364 refuses: BaseApp `SuggestVendorPayments.Report.al` line 1078, in report procedure
`ClearNegative`:

```al
while TempPayableVendorLedgerEntry.Next() <> 0 do begin
    ...
    if TempCurrency.Insert() then begin
        TempPayableVendorLedgerEntry2 := TempPayableVendorLedgerEntry;
        ...
        TempPayableVendorLedgerEntry := TempPayableVendorLedgerEntry2;
    end;
end;
```

**Cause.** `TempPayableVendorLedgerEntry` is a report global, declared in the report's SECOND
object-level var section (a `protected var` section comes first, then a plain `var` section).
`buildSymbolTable`'s `indexMembers` (`packages/engine/src/semantic/symbol-table.ts`) takes "the
first var_section that's a direct member of the object", plus the sections inside an active `#if`
arm (R405 a). A second direct section is never read. So `resolveVarRef` returns null for every name
it declares, and R196's hang check (`classifyHangCapable` in `loop-hazard.ts`) declines the write as
a guess (spec 3.1). The report is indexed, so R-364's unindexed-object gate does not open, and the
write is not an implicit-record or `with` binding, so R458's gate does not open either.

**Minimal repro (offline, master 001d5c1b):**

```al
codeunit 50480 C
{
    procedure P()
    begin
        while B do
            B := false;
    end;

    protected var
        A: Boolean;

    var
        B: Boolean;
}
```

`resolveVarRef` on the `B` in `B := false` returns null; `globalsOf("codeunit:C")` holds `A` only;
`classifyHangCapable` answers null, so `remove-assignment` claims a write whose removal never ends
the loop.

**Scale (not measured as sites).** 655 BaseApp source files have both a `protected var` and a `var`
line at object indentation (a grep, an upper bound on the shape). Every name in such a second
section is unresolvable to every reader of the symbol table, not only the hang check: type-based
operators lose sites there (the safe direction), and the hang check misses refusals (the unsafe
direction). R458's census found one such hang row in BaseApp (this one).

**To close.** Index EVERY direct object-level var section as globals (in source order, beside
R405 a's active-arm sections); red test per direction (a write to a second-section global inside a
loop that reads it is refused; a second-section global the loop does not read is still claimed);
measure the exact site diff on BaseApp, CDO and the fixtures before landing (every operator, since
types change too); bump `IDENTITY_SCHEME`.
