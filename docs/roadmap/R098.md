**al-runner v2 does not run on Windows, and we are Windows.** Upstream `main` P/Invokes `libc`'s `mprotect` for page protection: `System.DllNotFoundException: Unable to load DLL 'libc'` at `AlRunner.Infrastructure.JmpHook.InstallIndirect`, thrown from `BcRuntime.EnsureApplied` before any test runs (measured 2026-08-05 on a local Release build of `main`). Upstream PR **#1657** ("feat(windows): real Windows support via VirtualProtect", OPEN, MERGEABLE, 4 files) adds the `VirtualProtect` path and a `File.Replace` fix for the Defender file-lock on the rewritten DLL. Verified here: with #1657 checked out, the same build runs `fixtures/sandbox-app` + `fixtures/sandbox-tests` to 2P/0F/0E, `exit=0`. Also note the release is not out — tag `v2.0.0` exists but NuGet `MSDyn365BC.AL.Runner` is still at 1.0.31 (two failed publish attempts, upstream PR #1656 fixes the workflow). So: no v2 adoption work lands until #1657 merges AND 2.0.0 publishes, and the first thing the adapter does is refuse a v2 build without the Windows fix rather than let it fail as an unexplained patch-time crash.
