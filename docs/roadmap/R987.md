Coord task R-972, from preproc's R-969 (Contoso Coffee Demo Dataset peaked at 18.3 GB, `/coord/handoff/R-969/contosocoffeed.rss.tsv`).
Related: [[R948]] (the daemon recycle bound), [[R953]] / [[R972]] (admission by memory).

**Which process, and why R948 did not catch it.** Re-run with every process of the tree sampled every 2 s
(`/coord/handoff/R-972/measure.sh`, `base.procs.tsv`; edge-c8fe56e05, the same source, tests and config): LethAL's own process stayed
at 0.5 GB; the one al-runner serve daemon grew from 1.6 GB to 21.2 GB inside single prefetch requests (about 0.6 GB a second) and
fell back after each. R948's recycle reads the daemon's RSS between requests, after it fell, so it never fired.

**How it scales (measured).** The same run with 64 entries per request instead of 256 (`cap64.procs.tsv`): daemon peak 6.3 GB, all
20,790 verdicts and killing tests identical, session 112 s instead of 220 s. Two points give about 1.35 GB plus 77 MB per entry,
3.7 KB per entry per deployed mutant at this size. R-969's other apps (160 to 2,188 deployed, 30 s samples) peaked at about 1 GB.

**Built.** `entriesChunkCapFor(guards)` (`al-runner-v3-entries.ts`): `ENTRIES_CHUNK_CAP` (256), lowered so one request's entries fit
4 GiB at 3,800 bytes per entry per guard (Contoso: 54; nothing changes below about 4,400 guards); at least 1. `deploy` sets it per
batch from the manifest; the prefetch chunks, R912's batch-refusal placement and R778's kill-pair batches use it; a lowered cap is
announced (`al-runner-v3-entries-cap-lowered`). Tests: the function's values, and a backend rig with the cap injected (1 splits the
prefetch into two requests and notes it; 256 keeps one and no note).

**Measured on the fix** (`fixed.procs.tsv`, the same run): cap 54 announced; daemon peak 5.5 GB (predicted 5.5), whole tree 6.0 GB;
all 20,790 verdicts and killing tests equal to the 256-entry run; session 94.5 s instead of 220 s.

**Not changed.** Admission's `--peak serve` stays 8: with the cap the tree stays under it (6.0 GB above), so R-972's interim
"`--peak 20` above 10,000 deployed mutants" is not needed once this lands. R948's between-request bound stays as it is.
