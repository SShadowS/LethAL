**Found by** lethal-bugs, running the gate table's `coverage-differential` leg for PR-505 (the table selects it for any
change to `packages/runner/src/orchestrator.ts`). Evidence: `/coord/handoff/PR-505/gates/covdiff/` (`fenced.log`,
`master-fenced.log`, `procedure.log`, `run.log`).

- **What fails:** `bun scripts/probe-r58-differential.ts --project fixtures/sandbox-app --tests fixtures/sandbox-tests
  --mode fenced --config fixtures/sandbox-app/lethal.config.bc2.json` exits 1, on the first unmutated dispatch of the
  mutant phase:
  - `NoBaselineWorkDateError: Sandbox Tests.OverBudgetDetected answered on start WorkDate 2026-10-01, but this batch has
    no baseline date to compare it with (no dated baseline call, and no reused snapshot). A mutant's answer never sets
    the batch's date (R1131).`
  - It is thrown in `workdate-guard.ts` (`check`), called from `bcdev-backend.ts` `run`, through the probe's own
    `run` wrapper, from `runSession`.
- **Not PR-505:** the same command at `origin/master` (670601710), on the same server under the same lease, fails the
  same way. None of the failing files is in PR-505's diff.
- **`--mode procedure`** ran to its end (rc 0) on the same server. So the break is specific to the fenced path through
  the probe.
- **Suspicion, not a finding:** the probe wraps the backend's `run` and drives `runSession` directly, so the baseline
  calls that would set the batch's WorkDate (R1131) may not reach the guard the way an ordinary run's do.
- **Why it matters:** the leg is the only gate that can show an attribution regression (the coverage-differential skill:
  the frozen gates have green baselines, so they are blind to it). Until the probe is fixed, every change that the gate
  table sends to this leg goes without it.
- **Related:** R1131, R175, R58, R986.
- **Cause and fix (PR-507, lethal-code, 2026-11-28).** Evidence: `/coord/handoff/PR-507/` (`covdiff-bc1/`, the
  final run; `covdiff-bc1-r1/`, the run before the build review's fix).
  - **When it broke:** 7acb40eb6 (PR-196, R1131, 2026-11-19), which added the optional `baselinePhase` bracket and the
    batch-WorkDate members to the backend. The probe's `CoverageRecordingBackend` forwarded a hand-picked list of
    members, and the list did not grow. So `runSession`'s `backend.baselinePhase?.(true)` found nothing, bcdev's
    WorkDate guard never saw a dated baseline, and the first mutant answer threw. Procedure mode was spared only
    because the guard is off there.
  - **Fix:** a Proxy forwards every member to the real backend; `activate`, `run` and `baselinePhase` are observed on
    the way, and a baseline is recorded only inside the `baselinePhase` bracket.
  - **A second, older defect, found by the build review:** the wrapper took every run after `activate(null)` as a
    baseline. The cold kill confirm, `confirmFoundNone` and the decision-11 reruns also run unmutated, with coverage
    `none`, so they overwrote a killing test's baseline set with an empty one. The first live run of the fix showed
    `OverBudgetDetected` as `[]` in both modes: the per-test oracle compared empty with empty. Procedure mode had it
    all along. Fixed in the same PR.
  - **The probe now takes the production path.** The old list also dropped `runMany`, `killsMustReproduce` and the
    other optional members, so the probe never used group runs or kill reproduction. Dumps from before this fix are
    not comparable with dumps after it.
  - **Tests, each red-checked:** a real `WorkDateGuard` behind the wrapper (red: the exact `NoBaselineWorkDateError`);
    a cold-confirm run after the bracket must not change the baseline record; every `BcDevMcpBackend` method is
    reachable through the wrapper.
  - **Live, on bc1, at 79728328c (sandbox-app):** all three modes ran to their end. Procedure vs fenced: no verdict
    move, no covering-set change, 6 attribution changes (object to exact). Fenced vs none (the ground truth): no lost
    kill; the 6 `no-coverage -> survived` moves are the 6 `Sandbox Pricing` mutants, which no test calls (the ordinary
    move). Both tests' baseline sets are member-level and equal in the two modes, so the gap since 2026-11-19 hid no
    coverage regression on this fixture.
