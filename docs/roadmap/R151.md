Of every subcommand, only `explain` writes machine-readable output (`cli.ts`, the single
`JSON.stringify` at the end of `explainFromCli`). `doctor`, `run`, `campaign` and the two `clear-*`
verbs render prose through `renderDoctorReport` and friends.

That is backwards for an agent consumer. `doctor` is the command an agent should run before
anything else: it is read-only, it takes seconds, it reports every pre-flight refusal in one pass
instead of one slow retry per fix, and its exit code already distinguishes pass from fail. What it
cannot do is tell the agent WHICH check failed in a form the agent can branch on. Today that means
either regexing `  [FAIL] <name>: <detail>` lines, which the help text does not promise is stable,
or treating every failure as the same failure.

The shape already exists in the code: `DoctorReport` is a structured object with per-check `ok`,
`name` and `detail`, and `renderDoctorReport` is a pure function from it to a string. A `--json`
flag would print the object instead of the rendering, with no new decision about what a check is.

**What shipped: `lethal doctor --json`.** It prints `DoctorJsonOutput` — `doctorSchemaVersion`,
`ok`, `checks` (each with `name`, `ok`, `detail`), `notChecked`, and a `caveat` when the config
shape triggers one. The exit code is untouched: the rendering changes, never the verdict, and a
test pins that.

Both open questions were settled:

- **The caveats are structured, not only prose.** `DOCTOR_NOT_CHECKED_TOKENS` gives the two
  universal omissions branchable tokens (`publish-ceiling`, `baseline-test-health`) and the
  sentence ships alongside them; a test asserts the sentence still names each token, so the two
  cannot drift apart. The conditional caveats carry a `kind` (`create-mode`, `al-runner-only`) with
  the prose as `note`. An unrecognised caveat string THROWS rather than shipping unlabelled — a
  warning invisible to a consumer's `kind` branch is a warning that silently stopped working.
- **`run` and `campaign` deliberately did NOT get `--json`.** `run` already has two machine
  surfaces (`--out`, `--progress-out`) and its console rendering is for a human watching a long
  job. `--json` on anything but `doctor` is REFUSED rather than ignored, and the refusal names
  those two plus `explain`, because a silently-dropped flag hands a caller prose while they believe
  they asked for JSON.

Evidence: `doctorJson`, `DOCTOR_SCHEMA_VERSION`, `DOCTOR_NOT_CHECKED_TOKENS` and
`DOCTOR_CAVEAT_KINDS` in `packages/runner/src/cli.ts`; the `doctorJson (R151)` and
`lethal doctor --json — the flag (R151)` blocks in `packages/runner/tests/doctor-cli.test.ts`.
Red-checked: forcing `ok: true` in the projection reddens two tests, one of them end to end.
