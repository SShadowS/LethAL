**Found 2026-10-03, preparing R-396 in the kraken (Linux) container.** Continia Document Output at
`5f2a71d` declares `"logo": "Images\\Logo.png"` in `Cloud/app.json`. The file exists
(`Cloud/Images/Logo.png`). The Linux `alc` (AL compiler 18.0.41.45789, under
`ms-dynamics-smb.al-18.0.2732683/bin/linux`) reads the backslash literally and stops before
compiling a line:

```
Cloud/app.json(13,5): error AL1001: Source file 'Images\Logo.png' could not be found
```

Measured offline: the unchanged project gives exit 1 with that single error. A scratch copy whose
only change is `Images/Logo.png` compiles with 0 errors. The Windows `alc` accepts either form, so
every project made on Windows can carry such paths.

**Closed.** The orchestrator ruled to normalise, not refuse, and never to touch the user's own
project. Plan: `docs/superpowers/plans/2026-10-03-R-422-app-json-backslash-paths.md`.

**Which fields.** From the alc schema (`syntaxes/appSyntax.json`, AL extension 18.0.2732683), three
top-level fields name a file or folder, each measured on the Linux alc: `logo` (one file, AL1001),
`screenshots` (a list of files, AL1001) and `resourceFolders` (a list of folders, AL0863). Every
`\` in them becomes `/`; in a list, each string element is treated so and any other element is kept.
Left alone on purpose: URL fields (`privacyStatement`, `EULA`, `help`, `url` and the like), names
and free text (`name`, `publisher`, `brief`, `description`), ids, versions and lists of names. The
schema has no app.json field for translations or layouts: those are found by convention or named
inside `.al` files, and are already copied with their relative path (R39).

**The fix.** `normaliseAppJsonPaths` (pure, exported, in `packages/runner/src/orchestrator.ts`) is
called from `writeStampedAppJson`, so the first stamp and the version-conflict re-stamp both write
`/`. It never mutates its input. `prepareBatchProject` and `prepareArtifactDir` now return the list
of changes (`{ field, from, to }`). A manifest with no `\` in those fields is written byte for byte
as before, which a test pins. The rule runs on every host, Windows too, since the Windows alc
accepts `/`.

**The warning.** Once per session (a local flag in `runSession`, not a global), a `warning` run
event with code `app-json-backslash-path`. It names each field with its old and new value and says
the project's own app.json was not changed and that writing `/` there removes the warning. No
`SessionReport` field was added. `scripts/campaign/compile-only.ts` calls `prepareBatchProject` too,
gets the normalised file, and ignores the changes (commented there).

**Proof.** Unit tests in `packages/runner/tests/batch-project.test.ts` and `orchestrator.test.ts`,
each red on the pre-fix code and red-checked by five reverts (helper call removed; re-stamp not
normalised; every string field normalised; no once-per-session flag; first `\` only). Live alc, after
the fix: `prepareBatchProject` run on a scratch project whose app.json has `"logo":
"Images\\Logo.png"` and `"resourceFolders": ["Res\\Sub\\"]`, then
`$LETHAL_ALC_DIR/alc /project:<batchDir> /packagecachepath:<symbols> /out:<o.app>` with the Linux
alc 18.0.41.45789 gave exit 0 (batch app.json held `Images/Logo.png` and `Res/Sub/`). The same
command on the unnormalised project gave exit 1 with AL1001 and AL0863. That run also covers the
trailing-`\` form, which the first measurement had not.

**Other backends.** al-runner needs nothing: R-396 run (i) deployed the unpatched copy without
tripping, and a scratch run on al-runner v2.12.0-main.c39ad5de with both a `\` logo and a `\`
resource folder passed with exit 0 and no AL1001 or AL0863. It does not resolve those paths, and it
receives the normalised copy anyway. `compile:fixtures` is not applicable: it compiles each fixture
in place and writes no app.json copy, so there is nothing LethAL writes to normalise; fixtures are
repo-owned, and a `\` path in one should fail loudly and be fixed there. No fixture has one.

**No identity effect.** app.json enters no mutant identity (`identityKeyOf`, `IDENTITY_SCHEME`
unchanged), no artifact hash (`.al` files only), no source hash (it reads the user's app.json,
which is untouched) and no build-inputs digest (`runtime`, `target`, `features`, `application`,
`platform`, `preprocessorSymbols`).
