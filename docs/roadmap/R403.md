**Found by the R-378 lane (lethal-preproc), 2026-10-02**, from the plan review (`H:/lethal-coord/reviews/R-378-plan/review-r1.md`, finding 1). Plan: `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md` §1 B1 to B3.

**What happens.** Three readers of the TEST app read whole bodies, including `#if` arms the test app's build compiles out:
- `packages/runner/src/testpage-scan.ts` (`:580-603`, `:769-831`, `:1855-1915`) refuses tests that may open a TestPage. Over-refusing is its safe direction.
- `packages/runner/src/discovery.ts` (`:139-175`) finds `[Test]` methods by regex. A `[Test]` that exists only in a compiled-out arm is discovered, and the run then asks BC for a method the published app does not have.
- `packages/runner/src/test-digest.ts` (`:182-225`) feeds verify's "was this test edited" digest. Over-including is its safe direction.

**Why R378 did not fix it.** R214 and R378 skip arms using the TARGET's effective symbol set: the config's `preprocessorSymbols` plus the target's `app.json`. LethAL does not model the test app's own set, so there is no correct range to skip.

**What would close it.** Compute the test app's effective set the way R214 does for the target, using its own `app.json` (and decide whether the config's `preprocessorSymbols` apply to it). Then skip inactive arms in `discovery` first, because it is the only one of the three whose wrong direction changes which tests run.

**Discovery: done by R-403** (plan `docs/superpowers/plans/2026-10-02-R-403-test-app-arms.md`;
phases A to C): discovery reads the test app's own build (`effectiveBuildSymbols(testDir, ...)`),
excludes a compiled-out `[Test]`, and on bcdev checks the published package's compiled membership.
Its §6 left `testpage-scan` and `test-digest` as they were, on the claim that both err only in their
safe direction. R-403b measured that claim.

**Ruling, 2026-10-06 (R-403b).** Closed without a code change. Each test app was read twice: as
today (every arm) and as its own build compiles it (its `app.json` symbols; each inactive arm and
each conditional directive line blanked, offsets kept). For every test the build compiles, the
digest walk's reach (procedures and objects, plus its whole-source fallback), the subscriber fold
and the TestPage refusals were compared. Tool and output: `/coord/handoff/R-403b/tools/arms.ts`,
`/coord/handoff/R-403b/out/`.
- **Population.** 183 test apps: BC.History 179, CDO 1, DC 1, DO 2; plus the 7 fixture test apps.
  Only 19 corpus apps and 1 fixture have a directive line in a test-app file; 0 files are undecided.
- **Unsafe direction (the build runs code a reader misses):** 0 everywhere, for reach, the subscriber
  fold and the TestPage scan. 0 procedures are declared twice in one object with a copy in an
  inactive arm (the shape in which a reader could resolve a call to the wrong copy).
- **Safe direction (over-wide):** 33 tests in one app, BaseApp `Tests-SCM-Manufacturing`, reach
  more when every arm is read; TestPage refusals and the subscriber fold do not differ anywhere.
- **Discovery** would still find 15 compiled-out tests in DC's test app and 7 in DO's when every
  arm is read; R-403's filter already excludes them.
- **Measurement note.** Blanking only the inactive arm made one BaseApp file unparsable (a procedure
  header split over `#if not CLEAN28` / `#else`, whose empty arm the grammar refuses), and that
  showed up as a false whole-source fallback on the build side for 4 tests; blanking the directive
  lines too, as alc sees the build, removed it.

Narrowing either reader would only remove over-wide reach and would move digests (a
`TEST_DIGEST_SCHEME` change), so it is not done. Reopen if a test app is found where a reader misses
code the build runs.
