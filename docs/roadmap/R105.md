**Two session-level bookkeeping structures in `runSession` are write-only and confirmed dead, kept only to avoid reopening a frozen contract.** `outcomes: SessionOutcome[]` (built by `record()`, `orchestrator.ts`) and `permissionRefusedTests`/`runnerDisagreementTests` (the two `Set<string>`s threaded through `RunMutantsOnBackendArgs`) were the event-stream refactor's (spec 2026-08-05 §A, `7449a89`) intended casualties — `buildReport` reads `collectedEvents` now, never `outcomes[]`, and the two report fields these Sets used to feed (`permissionsRefused`/`runnerDisagreement`) are folded from `mutant-scored.permissionRefusedTest`/`.runnerDisagreementTest` instead. Left in place deliberately: `record()`'s `outcomes` parameter is a Task 3 contract `events-orchestrator.test.ts` drives directly, and `RunMutantsOnBackendArgs`'s two Sets would need touching both its interface and its two call sites (sequential + worker fan-out) to remove — real surface area for zero behavioural gain. Confirmed genuinely dead (not merely believed so) during the whole-branch review: no consumer reaches either on any path to `buildReport`. Evidence: `packages/runner/src/orchestrator.ts` (the `outcomes`/`permissionRefusedTests`/`runnerDisagreementTests` declarations in `runSession`, each now documented in place as dead), `.superpowers/sdd/2026-08-05-event-stream/task-4-report.md` §"Residual dead code".

**CLOSED 2026-08-07, and the row's own verdict splits in two.**

**The two Sets are gone.** `permissionRefusedTests` / `runnerDisagreementTests` were written at three
sites and read by nothing — not `runSession`, not `buildReport`, not a test. (`report-fold.ts` has
same-named locals; they are its own and unrelated, which is itself a small trap.) Net 48 lines
deleted, 5 added.

This row argued against removing them as "real surface area for zero behavioural gain". That was
right about the behaviour and wrong about the gain. The cost was never runtime, it was that the code
lied to a reader: `args.permissionRefusedTests.add(...)` sat immediately beside
`permissionRefusedTest = ...`, one feeding the report and one feeding nothing, distinguishable only
by reading three paragraphs of comment that existed to say so. Deleting the Set deleted the
explanation with it.

**`outcomes` is KEPT, and this row is wrong to list it as equally dead.** It is no longer written
purely for durability: `events-orchestrator.test.ts` reads it as the SECOND VIEW `record()` writes
alongside each event, which is what proves the two cannot drift apart from a missed call site. R86's
own `killingTestFailure` assertion depends on it. Deleting it removes an agreement check rather than
dead weight.

**On verifying a deletion.** A red-check cannot work here — reverting code nothing reads reddens
nothing, and a suite that stays green is equally consistent with "it was dead" and "it was never
tested". What the claim rests on instead is that the report fields these Sets APPEARED to serve are
covered and still pass (`permissionsRefused` 8 pass, the R35 kill-confirmation path 21 pass), so the
event fold really does carry those facts independently.
