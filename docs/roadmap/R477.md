**What.** `validate-to-assign`'s bare form (`Validate(F, V)` with no receiver) writes the assignment
with a synthesized receiver prefix, and since R464 only where that prefix is PROVEN to bind the
call's record (`bareReceiverText` in `packages/engine/src/semantic/receiver.ts`). Where it is not
provable, the site is refused: 35 measured sites.
- 29 the tool mutated before: Intrastat 23 and SAF-T 3 (bare `Validate` in a tableextension of a
  table outside the project, so the extended table's fields are unknown), BaseApp 3
  (`IntrastatSetup.Table`: the table is not indexed; `SalesHeader.Table` x2: a `Rec :` declaration
  shape is visible in scope).
- 6 new claims not taken: CDO 2 (`CDO Update Customer Setup` report, dataitem over the dependency
  table `Customer`), Intrastat 4 (`with` over a dependency-table subject).

**Do not just emit a bare `F := V`** (sol's review of R-464 r3): an assignment's left side binds
differently from Validate's field designator. A parameter, a local, or a table/tableextension
global named like the field captures the bare assignment (`procedure P(Amount: Decimal)` then
`Amount := 1` writes the parameter); a page global alone does not (R294). And Validate's binding
of a shadowed first argument was never measured (R136).

**To close.** Prove the field name's ASSIGNMENT binding at the site instead of the receiver
name's (explicit `with` first, the most promising), measure the shadowing controls with `alc` and
at runtime, then re-measure how many of the 35 come back. All 35 recovering is not established.

**Closed 2026-10-06 (467e2faf, R-477)**: plan r2 in the coord handoff `R-477` (`plan.md`,

- **The rule.** Where `bareReceiverText` proves no spelling, `validate-to-assign` emits the bare
  `F := V` only if `bareFieldAssignable` (engine `semantic/receiver.ts`) holds: the call's
  innermost record scope has a table and F is PROVABLY undeclared at the call (`declarationAt`:
  trigger locals, locals, parameters, named return values and the enclosing object's globals,
  case-insensitive and quote-normalised; an `#if`-only, unindexed or symbol-less declaration is
  "unknown" and refuses). A proven spelling still wins; `targets()` and `generate()` agree.
- **Re-count: 49 refused on master 963ee476, not 35.** BC.History 45 (Intrastat tableextensions
  23, Intrastat `with` over a dependency record 16, SAF-T 3, `IntrastatSetup` 1, `SalesHeader` 2),
  CDO 2, DO 2, DC 0, fixtures and examples 0. The `with` group is 16 at R464's own commit too; its
  "4" counted the diff against the older base, not the refused population.
- **Result (exact site diff, HEAD vs master, every project of all five corpora):** +47 mutants,
  0 removed, 0 changed (apart from operatorVersion 1.1.0 -> 1.2.0 on every existing
  `validate-to-assign` spec), 0 existing keys moved. The two still refused are the
  `SalesHeader.Table` sites in `UpdateShipToSalespersonCode`, a `#if not CLEAN26`-wrapped
  procedure with no symbol: "unknown" is not proof of absence, so they stay refused (fixing that
  symbol gap is separate work).
- **The 47 fall into 5 shapes, each probed with `alc` 18.0.43 (original and mutant compile):**
  a tableextension procedure on a dependency table (24), a tableextension `modify` trigger (2), a
  project table's field trigger (1), a codeunit `with` over a dependency record (16), a report
  dataitem over a dependency table (4).
- **alc evidence (binding measured by ill-typed witnesses whose error names the bound type).** A
  local, parameter, named return value or trigger local captures a bare assignment everywhere but
  inside `with`; an object global captures it in a table or tableextension, not on a page, report
  or codeunit (R294). With nothing declared the name binds the innermost record's field: inside
  `with X do` that is X.F even where the implicit `Rec` has an F of another type (table, TableNo
  codeunit, page, pageextension), and nested `with` and dataitems bind the inner one. Not checked
  by the guard, and measured harmless: a field named like a system method (`Today`, `Count`,
  `CompanyName`, `UserId`, `WorkDate`) or like its enum type binds the field; a procedure named
  like the field (another tableextension, a dependency table) makes the ORIGINAL `Validate` fail
  too; a dependency table's or page's global does not capture. R136's open question is answered:
  `Validate(F, ...)` with a same-named local or tableextension global does not compile (AL0166).
  `NoImplicitWith` only removes sites (a bare `Validate` on a page or TableNo codeunit does not
  compile there).
- **Identity.** No key moved in any corpus, but one can: in a table with its own `Name`,
  `with Cust do begin Validate(Name, 'X'); end; Validate(Name, 'X');` gains the bare mutant at
  ordinal 0 and the old `Rec.Name := 'X'` moves to 1 (`r477-identity`), hence scheme 26.
- **Limit kept.** A call that is the whole un-braced body of `with ... do` is not a statement site
  at all, so it is neither claimed nor mutated: that is R286's closed ruling, unchanged here.
