## What breaks, and for whom

A mutant that never returns strands its tier and blocks every mutant behind it, on the default path
where `--stop-hung-sessions` is off because it ends a session on the user's own server. [[R164]]
found and fixed one such shape. [[R173]] measured a second at 7 sites. This is a third, it is bigger
than R173's, and nothing had counted it.

`empty-block` claims a loop's BODY. Where that body is what advances the loop's condition, emptying
it freezes the condition and the mutant cannot terminate:

```al
while Pos > 0 do begin           // original terminates: the body moves Pos
    Process(Pos);
    Pos := StrPos(S, Find, Pos); // <- emptied, Pos never changes
end;                             // mutant: `Pos > 0` forever
```

## Measured on `do-rel2/Cloud`

| | |
| --- | ---: |
| `while` loops in executable bodies | 33 |
| `repeat` loops | 334 |
| loop bodies `empty-block` claims | **138** |
| of those, condition FROZEN by an empty body | **25** (19 `while`, 6 `repeat`) |

The 113 that are safe have a **self-advancing condition**: `until Rec.Next() = 0`,
`while Reader.Read()`, `while not Stream.EOS`. The call in the condition moves the loop on its own,
so an empty body still terminates. That distinction is why the raw 138 is not the number, and an
earlier pass that reported 132 was wrong for exactly this reason and is recorded here rather than
quietly corrected.

**This is not a new bug and it is not a wrong verdict.** `itest:hang`'s M0007 is precisely this shape
(`empty-block` on `Advance`'s body, scored `timeout-killed`), chosen deliberately by R53 as one of
that fixture's hazards. What is new is the SIZE, and that it is the largest of the three.

## Why it is worse than R164's, in one respect

R164's hazard had a safe operator to cede to: `loop-truncate` asks the same question (`does anything
notice if this loop runs once?`) and cannot hang. `empty-block` on a loop body asks "does anything
notice if this body does nothing", and the terminating way to ask that at a `while` is
`while false`, which **no operator emits**. So today there is nowhere to cede.

## The candidate, and its honest sizing

`loop-skip`: `while <cond>` -> `while false`, so the body runs zero times.

- **33 raw sites**, all `while` loops (a `repeat` body always runs once, so `until true` is its
  analogue and `loop-truncate` already emits that).
- **28 of the 33 already carry an `empty-block` mutant on the body**, so on a naive count only 5 are
  marginal, well under R13's bar of 13.
- **But at 19 of those 28, the existing mutant does not terminate.** So `loop-skip`'s value is not
  new coverage, it is the same question asked in a way that finishes: exactly `loop-truncate`'s
  relationship to `negate-conditional`, which R164 accepted on the same grounds.

Sizing this on raw count alone would refuse it. Sizing it on "mutants that currently hang and would
stop hanging" justifies it. The bar was written for coverage, not for hazard, and which one applies
here is a judgement this row should not make silently.

## What to do, in order

1. **Decide whether the R13 bar applies to a HAZARD-motivated operator at all.** R164 shipped
   `loop-truncate` on 334 sites so the question never arose; here it does, and it decides the answer.
2. If yes, build `loop-skip` and cede `empty-block` at a `while` body whose condition it would
   freeze. The cession must be measured the way R164's was: score the hanging mutant BEFORE the
   cession, on a `sandbox-hang` arm, because afterwards it is unobservable.
3. The 6 `repeat` cases have no `loop-skip` analogue (`until true` still runs the body once, so it
   does not remove the body's effect). They need either a ruling or their own shape.

## Related

[[R173]] is the sibling hazard at 7 sites, in `conditional-boundary`, at the same `while` position.
If `loop-skip` is built, both cessions land together and `while` is settled in one pass. If it is
refused, both are accepted risks and should be documented as such in
`docs/using-lethal-from-an-agent.md`, which currently warns about neither.

**BUILT 2026-08-27.** Verdicts:
`docs/superpowers/specs/2026-08-27-r179-loop-skip-precommitment.md`.

**The ruling this needed, made explicitly.** R13's >=13-site bar was calibrated for a COVERAGE
candidate. `loop-skip` fails it (5 marginal of 33) and passes on hazard (19 non-terminating mutants
replaced). A candidate that swaps a hanging mutant for a terminating one adds little coverage BY
CONSTRUCTION, so the coverage bar would refuse it precisely because it does its job. **Hazard
candidates are judged on hazards removed.** R164 accepted `loop-truncate` on the same grounds without
having to say so, because its raw count was 334.

**The hazard is now OBSERVED, not just censused.** `itest:hang`'s `DrainQueue` arm scored
`empty-block` on the `while` body `timeout-killed`, running the full 20 s budget, in a stage taken
deliberately before the cession made it unobservable.

**The cession is POSITIONAL**: `empty-block` refuses any block whose parent is a `while_statement`.
The precise rule would be "refuse where the body advances the condition", which is an inference about
VALUES, the class of reasoning [[R175]] was. Cost: at the 9 `while` bodies where the mutant currently
terminates it is replaced by `loop-skip`'s, which asks nearly the same question.

**One prediction missed, and it corrects a belief worth correcting.** `remove-assignment` on the
advancing statement was predicted `timeout-killed` and measured `killed` in 4.4 s, by
`Arithmetic operation resulted in an overflow`. The loop DID freeze; it terminated by arithmetic
because the surviving `Drained += 1` overflowed Int32. **A frozen loop only strands when nothing
inside it accumulates.** This does not move R179's 25: that count is `empty-block`-specific, and
`empty-block` leaves nothing to accumulate. Every future "this will hang" claim in this repository
should be checked against it.

**Not addressed, deliberately:** the 6 frozen `repeat` bodies. A `repeat` body always runs once, so
`until true` does not remove its effect and `loop-truncate` is no substitute. They need their own
shape or a ruling.
