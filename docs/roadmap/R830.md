**Filed 2026-11-05 by lethal-bugs.** Related: [[R196]], [[R829]], [[R164]].

**What.** `lethal.void-method-call` deletes a statement call and asks no loop question at all, so a call that carries a loop's
progress is mutated. `loop-hazard.ts`'s header lists progress through a call as deliberately not seen. Two shapes, which need
different work:

1. **Receiver.** `while Items.Count() > 0 do Items.RemoveAt(1)`. The condition reads the receiver the call changes. A name walk
   can see this, and it leaves the hang gate's site alone.
2. **Bare call.** `repeat Advance(); until Counter >= Limit`, or a call that changes a by-var argument: `while Pos > 0 do begin
   Chop(Text, Pos); Pos := Text.IndexOf('x'); end`. Seeing it needs to know what the callee writes. Shape 2 is `itest:hang`'s own
   site in `fixtures/sandbox-hang` (`CountUpTo`), so refusing it needs a new way to make that gate hang.

**Why it is not part of R829.** R829 follows assignments by name. This is a different question, on an operator with no hang check.

**Next.** Count both shapes on CDO, DO, DC and BC.History. Then decide. The R196 rule was measured cost: a hang is a stranded
session, a quarantine, or on BC 29 on Linux the end of the run (#49).

- **Most of shape 1 is safe.** `repeat Rec.Modify(); until Rec.Next() = 0` steps in its own condition: deleting `Modify` ends the same.
  "Steps" means the condition calls `Next`, `Read` or `MoveNext` on the receiver.
- **The rest includes certain hangs.** `EOS` does not read, so deleting the `ReadText` in `while not S.EOS do S.ReadText(T)` never ends.
  The same goes for `while Rec.FindFirst() do Rec.Delete()` (7 in BC.History).
- **Shape 2(a) is a name match.** It does not know whether the parameter is by-var. 2(a) is an upper bound.
- **Shape 2(b) is out of reach by name.** It would take knowing what every callee writes. Loops holding such a site: 353, 1,307, 262 and
  9,728. They hold 1,267, 4,675, 900 and 30,558 sites.
- **No gate fixture holds a shape 1 site.** `sandbox-hang`'s two bare calls are 2(b), and the gate needs them to hang.

## Plan (R-833, draft 1, not reviewed)

1. **Shape 1: refuse.** `void-method-call` refuses a call inside a `while` or `repeat` when the nearest loop whose condition reads the
   call's receiver has no `Next`, `Read` or `MoveNext` on it there. Same scope as the census, so about 0.05% of DO's sites and 1.2% of
   in-loop sites in BC.History. By name, the safe direction for a refusal. It is refused at the operator, and reported the way R196's
   refusals are.
2. **Shape 2(a): not now.** Measure by-var with the semantic layer first. A refusal needs a new way to make the hang gate hang only if
   it reaches `sandbox-hang`'s sites, and the census says it does not.
3. **Shape 2(b): do not refuse.** Refusing by name would take most in-loop mutants of this operator (30,558 of BC.History's 35,453),
   and the hang gate needs these sites. The run's timeout and quarantine stay the guard. Needs the orchestrator's ruling, because it
   closes the shape without a fix.
4. **Identity.** A refusal changes which sites are claimed, and so ordinals on real projects. It needs an `IDENTITY_SCHEME` bump, and that
   waits for the orchestrator's word, after R-827's records at 44. Fixture figures should not move: pre-commit that.
5. **Red checks** per direction: each refused pair, each kept stepping method, and a near-miss where the condition reads another receiver.
