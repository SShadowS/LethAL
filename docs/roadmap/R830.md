**Filed 2026-11-05 by lethal-bugs.** Related: [[R196]], [[R829]], [[R164]].

**What.** `lethal.void-method-call` deletes a statement call and asks no loop question at all, so a call that carries a loop's
progress is mutated. `loop-hazard.ts`'s header lists progress through a call as deliberately not seen. Two shapes, which need
different work:

1. **Receiver.** `while Items.Count() > 0 do Items.RemoveAt(1)`. The condition reads the receiver the call changes. A name walk
   can see this, and it leaves the hang gate's site alone.
2. **Bare call.** `repeat Advance(); until Counter >= Limit`, or a call that changes a by-var argument: `while Pos > 0 do begin
   Chop(Text, Pos); Pos := Text.IndexOf('x'); end`. Seeing it needs to know what the callee writes. Shape 2 is `itest:hang`'s own
   site in `fixtures/sandbox-hang` (`CountUpTo`), so refusing it needs a new way to make that gate hang.

**Why it is not part of R829.** R829 follows assignments by name. This is a different question, on an operator with no hang check.

**Next.** Count both shapes on CDO, DO, DC and BC.History. Then decide. The R196 rule was measured cost: a hang is a stranded
session, a quarantine, or on BC 29 on Linux the end of the run (#49).

- **Most of shape 1 is safe.** `repeat Rec.Modify(); until Rec.Next() = 0` steps in its own condition: deleting `Modify` ends the same.
  "Steps" means the condition calls `Next`, `Read` or `MoveNext` on the receiver.
- **The rest includes certain hangs.** `EOS` does not read, so deleting the `ReadText` in `while not S.EOS do S.ReadText(T)` never ends.
- **The bold row overstates the gap.** The census saw the operator's `targets` only. Dispatch already refuses some (R531 refuses
  `while Rec.FindFirst() do Rec.Delete()`), and Tier 2 claims others. Real mutants a refusal takes: 12, 19, 9 and at most 333 (BC.History's
  dispatch check timed out, so its figure subtracts Tier 2 only). 127 of those 333 are in test code.
- **It also misses hangs (plan review).** The condition can read a value fed from the receiver, or the stepped object can be an argument
  of a call on another receiver (`S.ReadText(NewLine)` under `while NewLine <> ''`). Sites by name, most not hangs: fed 2, 64, 0 and 272;
  argument 2, 30, 1 and 152.
- **Shape 2(a) is a name match.** It does not know whether the parameter is by-var. 2(a) is an upper bound.
- **Shape 2(b).** Narrowed to a bare call with no argument the condition reads, no cursor method in the condition and nothing the body
  assigns that the condition names: 5, 23, 1 and 242 sites. `CountUpTo` and `SpinUntil` in `sandbox-hang` are this exact shape, and
  `itest:hang` needs them.
- **Gate fixtures.** Only 3 `void-method-call` sites sit in a loop: `gift-card`'s stepped `Modify` (kept) and `sandbox-hang`'s two.

## Plan (R-833, draft 2, after one adversarial review; rulings 2026-11-06)

Rulings: 2(a) is refused in the same clause. 2(b) is refused in R-833, with a new hang fixture first. The hold on identity is lifted:
measure, and bump only if an ordinal moves. Timeout and quarantine are not a guard on BC 29 on Linux until #49 lands.

1. **Where: `openItemHangRefuses`, not the operator.** A refusal in `void-method-call` leaves Tier 2's identical deletion in place
   (`remove-setrange` on the same node), the hang stays, and the report's "no mutant was made there" becomes false. This is the check
   every operator already passes. It takes any other operator on the same call node too (`swap-call-arguments`). That is expected.
2. **The rule, by name, the safe direction (R829: a wrong refusal loses one mutant, a miss can end a run).** Refuse a statement call
   inside a `while` or `repeat` when, in ANY enclosing such loop, `loopExitParts` reads the call's receiver or one of its plain-name
   arguments, and those parts call no `Next`, `Read` or `MoveNext` on it. `loopExitParts`, not the raw condition, so a fed value and a
   `while true` with an exit guard are seen. The optional list of calls that cannot change state (`TestField`, asserts) is left out
   until the dump shows it matters.
3. **Shape 2(a): the same clause.** By name it costs 0.14% to 0.39% of sites and reaches no fixture site.
4. **Shape 2(b): read a same-object callee's body, to any depth.** The call is refused when the chain assigns, calls a method on, or
   passes a global the loop's parts read. Known limits: another object's callee and an event ([[R839]]), and a site inside the callee
   ([[R837]]). `sandbox-hang`'s two sites were this shape, so its loops now call an `IntegrationEvent`, `OnAdvance()`, whose subscriber is
   `Advance`, in a `SingleInstance` codeunit. No line, operator or mutant count moves there. The version stays 1.0.0.4, because a bump
   needs a new symbol tar and nothing public changed.
5. **Measure first, R829's way.** Dump production identity keys for every operator against master with `scripts/prod-identity-keys.ts`, on
   the fixtures, CDO, DO, DC and BC.History. Commit specs, hang-refused, removed, ordinals moved and per-operator figures before building.
   This replaces the census figures above as the pre-commitment.
6. **Identity.** Ordinals moved (1 on DO, 5 on DC, 1 on CDO), so the scheme is 45. `void-method-call`'s `operatorVersion` stays: it is
   in the identity tuple and would move every key of that operator. 11 baselines stay lagged at 44 under [[R836]].
   `hang.single.baseline.json` is re-recorded here, because its fixture's text moved.
7. **Text.** The `hang-refused` lines now name a call. `explain.ts` withholds `unobservedBlock` for any file with a `hang-refused` row:
   that is correct, and goes in the pre-commitment.
8. **Gates on the final head:** v3, lend and hang, as R829 ran. `itest:hang`'s pin of one `hang-refused` row with 2 sites should hold.
9. **Red checks** per direction: each refused shape, each kept stepping method, any-enclosing against nearest loop, and a near-miss
   where the parts read another name.
