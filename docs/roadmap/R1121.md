Found by coord PR-68 (lethal-code) and classified by PR-137 (lethal-preproc), 2026-11-18, on `bc4` (BC 29 W1 on Linux).
Evidence (private, DO source stays under `/coord`): `/coord/handoff/PR-68/changed-v1/report.json`, `/coord/handoff/PR-68/v3-vs-bc-gap.md`
and `/coord/handoff/PR-137/result.md`. Related: [[R908]] (the same limit, for tests that fail at BASELINE), [[R227]].

**What happens.**
- In PR-68's changed arm (80 mutants of Continia Document Output 30, `--changed-since`), BC killed 22 and al-runner v3 killed 1.
- **11 of BC's 22 kills** carry the killing failure "The report could not be created as a Pdf document ... RDLC report rendering is
  not implemented on Linux BC" (the Linux BC build stubs out the Windows reporting service).
- **Why:** the mutants (in the service posting send path) route a document to direct processing, which renders a report. The test
  fails on the platform's stub, not on an assertion. On v3, 10 of the 11 killers pass with the asserted outcome, so the mutant
  survives there.
- Of the other 11 BC kills, 1 is also killed on v3, and 10 look real (another failure text); their killers are refused at v3's
  baseline.

**Why it matters.** Every BC gate server (`bc1`-`bc4`) and `bc5` runs BC on Linux. On any suite whose code paths can reach a report
render, a mutant that turns rendering on reads as killed: the score goes up, and the user is told the suite caught it. R908 noted
the baseline side (19 of BankDeposits' 75 tests red); the mutant side is silent, since a baseline-green test that fails under the
mutant is an ordinary kill.

**Possible fix.**
1. **In R72's form** (`platform-artifact-kills.ts`, which never moves a verdict, so frozen gate figures and baselines stay valid):
   recognise the Linux RDLC stub as its own mechanism, keyed on the killing failure text. List these kills under
   `platformArtifactKills`, kept `killed`, with a caveat that names how many kills rest on it.
   - Scoring them as not killed would override R72 for one server-specific text. That would need an owner ruling, and is not
     proposed here.
2. Name the limit in the report and in `docs/gates/servers.md`: on Linux BC, a mutant that reaches a report render cannot be
   scored honestly.

**To close:** (1), with a red test built from a recorded failure text, and a re-read of PR-68's changed arm that lists exactly
those 11 under the new mechanism.

**Done (coord PR-143, lethal-code, 2026-11-18).** Spec: `docs/superpowers/specs/2026-11-18-pr143-linux-rdlc-stub-screen.md`.
- **The screen:** `PLATFORM_FAILURE_TEXT_MECHANISMS` in `platform-artifact-kills.ts` keys `linux-rdlc-stub` on the killing failure
  text, "RDLC report rendering is not implemented on Linux BC".
  - A killed mutant carrying it is listed under `platformArtifactKills` with the `platform-artifact-kills` caveat. It stays killed,
    and `mutationScore` is unchanged.
  - A mutant listed under a site tag and the text appears under both, and is counted once.
  - The diagnosis, the banner and the field docs say that one mechanism is text-keyed.
- **The re-read of PR-68's changed arm** (`/coord/handoff/PR-143/reread-pr68.ts`) lists exactly the 11 PR-137 named: M0051, M0056,
  M0060, M0061, M0065, M0068, M0069, M0070, M0073, M0077, M0078. No other row carries the text.
- **Fix 2:** `docs/gates/servers.md` names the limit.
- **Known limits, stated in the code:**
  - a rewording in a later bc-linux build turns the screen quiet (it under-reports);
  - a test whose own assertion quotes the stub text would be listed too.
