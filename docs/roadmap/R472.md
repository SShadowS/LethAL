**Found 2026-10-05 in sol's review of the [[R459]] plan (finding 2).** R459 hands both Booleans
of a two-argument `Rec.Insert(RunTrigger, InsertWithSystemId)` to `lethal.flip-boolean-literal`.
The FIRST argument is RunTrigger and gets the RunTrigger tags. The SECOND gets NEITHER RunTrigger
tag, which is right, because it does not control a trigger. But "untagged" is not proof that the
flip is platform-neutral.

**The shape.** On a table with no `OnInsert`, code copies an existing row's `SystemId` into a record
with a fresh primary key and calls `Insert(false, false)`. With the second argument `false`, BC
assigns a fresh `SystemId`. Flipped to `true`, BC keeps the copied one, and the insert can fail on
the `SystemId` uniqueness constraint. The test then dies on the platform, not on an assertion, and
the mutant scores `killed` without the suite earning it.

**Not measured.** How often a test reaches such a site with a duplicated `SystemId`, on BC.History
or CDO. R459 ADDED 17 second-argument flips on BC.History (13 `true` in `Insert(true, true)`,
4 in `Insert(false, true)`), CDO 0, fixtures 0. That is the newly added population, not all
second-argument flips: `QltyCreateInspectionAPI.Page.al` already had three more `Insert(false, true)`
second-literal flips on unresolved `Rec` receivers. The opposite direction
(`true` -> `false`) writes a fresh id and should not collide; confirm that too.

**What to build.** Measure first: an `/al-probe` that runs both directions against a real BC, then
decide whether a new `PlatformKillMechanism` (for example `insert-systemid-collision`) is warranted
and what proof drops it (no `SystemId` assignment to the receiver in the procedure, say). Adding a
mechanism follows CLAUDE.md's `Caveat`/report ripple list.

**Closed 2026-10-05 as a ruling (R-472, orchestrator), on a live measurement.** Probe: `scripts/r472-probe/` (its README
records the run).
- **BC collides.** Measured on Cronus28, BC 28.4, over OData. A record whose `SystemId` is copied from an existing row
  of the same table, with a fresh primary key, fails `Insert(false, true)` with `DB:RecordExists`: "There is already a
  record in table … that has the same values in a unique index for the following fields: System ID='{…}'". Uncaught,
  OData answers HTTP 400 `Internal_EntityWithSameKeyExists`.
- **The controls succeed.** `Insert(false, false)`: BC ignores the copied id and writes a new one. A fresh
  `CreateGuid()` id with `Insert(false, true)` also succeeds.
- **No site can trigger it.** Only the `false` -> `true` flip of the second argument can collide, and no source writes a
  literal `false` there. That is 0 sites on fixtures, CDO and BC.History. The opposite flip, `true` -> `false`, has 20
  sites on BC.History (17 claimed, 3 on an unresolved receiver) and 0 elsewhere. It makes BC write a fresh id, so it
  cannot collide.
- **So no mechanism is added:** a tag on a flip that is never emitted is code with no site.
- **Reopen condition.** If an `Insert(X, false)` literal appears in a measured corpus or a user's project, its
  `false` -> `true` flip needs a declared `insert-systemid-preserved` PlatformKillMechanism. It is not provably safe
  to drop unless the procedure never assigns the receiver's `SystemId`.
