Found by PR-71's review (2026-11-16), walking examples/gift-card as a first-week user.

**What.** `lethal init --backend al-runner-v3` writes `packagesDir: <project>/.alpackages`. With both placeholders filled
but the folder absent (gift-card has no `.alpackages`: it has no dependencies, and the folder is git-ignored), `lethal doctor`
reports `[FAIL] al-runner-v3: ENOENT: no such file or directory, scandir '.../gift-card/.alpackages'`.

**Why it matters.** The fix is one command (`bun scripts/fetch-ms-symbols.ts 28 <folder>`, then set `bcVersion` to what it
prints), but the error names a system call, not the setting (`alRunnerV3.packagesDir`), what it must hold (Microsoft's System
Application at exactly `bcVersion`, `assertBcVersionMatchesPackages`) or how to fill it. Principle 5: refuse by naming the
setting and the one-line fix.

**Mitigated for now** by `init`'s printed next steps and docs/first-week.md (both now say the folder must hold the symbols
and how to fetch them).

**To close.** doctor (and run) refuse a missing or empty `packagesDir` by name, with the fetch command, and a test pins it.
