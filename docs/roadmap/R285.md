**Found by the issue #6 cross-check** (`docs/measurements/2026-09-27-gh06-grammar-crosscheck.md`, cluster C2).
The product risk is [[R214]]'s: tree-sitter parses both arms of a directive, the compiler builds one.
The new fact is the SHAPE. [[R214]] and the cross-check harness both recognise directive code by a
`preproc_conditional*` node. tree-sitter-al 4.x uses other containers too, `preproc_split_*` and
`preproc_fragmented_*`, and code inside them is recognised by neither.

**What happens.** When the `#if` arm and the `#else` arm of a `case` share one branch body (the
labels differ, the body after `#endif` is common), tree-sitter builds a
`preproc_split_case_extended` node. The statements in the inactive arm are ordinary nodes under it.
LethAL claims them as sites. The harness's R2 guard (a delta inside a `preproc_conditional*` span is
R214 and not a finding) does not fire, so they show up as UNEXPLAINED tree-sitter-only deltas. This
is not a grammar defect: parsing both arms is what tree-sitter does by design.

**Minimal reproduction** (hand-written, not corpus source), `scripts/lib/al-kind-mapping-split-case.al`:
```al
codeunit 50002 "Split Case Probe"
{
    procedure Route(Mode: Integer; Ready: Boolean)
    begin
        case Mode of
#if FASTPATH
            1:
                begin
                    if not Ready then
                        Prepare(Mode)
                    else
                        Launch(Mode);
                end;
            2:
#else
            1, 2:
#endif
                begin
                    Launch(Mode);
                end;
            3:
                Prepare(Mode);
        end;
    end;

    local procedure Prepare(Mode: Integer)
    begin
    end;

    local procedure Launch(Mode: Integer)
    begin
    end;
}
```
`FASTPATH` is not defined, so the compiler builds the `#else` arm. Harness output: tree-sitter-only
`unary_expression` [191,200], `call_expression` [230,243] and [293,305]; call probe tree-sitter-only
at 230 and 293; guarded 0. The container is `preproc_split_case_extended` [118,450].

**Measured.** do-rel2/Cloud (sha256 9a8e8831449208cc): 3 kind sites and 2 call-probe sites, all in
one file, `Al/Codeunit/Codeunit 6175280 CDO E-Mail.al`, at [5764,5784], [5815,5856], [5908,5933].
That is app code, not test code. Zero in the other six corpora under this container.

**The pipeline check: the over-claim SURVIVES.** `bun scripts/census-fixture-mutants.ts` on the
reproduction plants:
- line 9: `lethal.remove-not`, `not Ready` to `Ready`. Exact match with [191,200].
- line 10: `lethal.void-method-call`, `Prepare(Mode)` deleted. Exact match with [230,243].
- line 12: `lethal.void-method-call`, `Launch(Mode)` deleted. Exact match with [293,305].
- line 8: `lethal.empty-block` on the inactive arm's `begin ... end`. Not an audited kind, so not
  counted by this audit, but it is in the inactive arm too and has the same risk.

The other census lines are not cluster sites: `empty-block` on line 4 (the whole body), and
`void-method-call` on lines 19 and 22 (the active arm, where both parsers agree).

All four mutants sit in code the compiler does not build under these symbols. They can never be
killed, so each would be reported as a survivor.

**Also: the harness understates "guarded".** The same prefix gap means every corpus's "guarded"
counts miss directive code under `preproc_split_*` and `preproc_fragmented_*` containers, in both
directions. Recorded, not fixed: the pre-commitment defined R2 by `preproc_conditional*` before the
run, and changing it after reading the output would edit the rule to fit the data.

**What would close it.** Whatever closes [[R214]] must name these containers too, not only
`preproc_conditional*`. The cross-check's R2 guard should widen the same way in a future run, with a
new pre-commitment.

**Reproduce.** `bun scripts/probe-grammar-crosscheck.ts scripts/lib/al-kind-mapping-split-case.al`,
then copy that file alone into an empty directory and run `bun scripts/census-fixture-mutants.ts <dir>`.
