**Filed 2026-10-22 by coord task R-635** (lethal-code), from the R-635 live leg E0-S (`/coord/handoff/R-635/live/results.md`).

**What happened.** After a one-shot v3 leg (`itest:alrunner-v3` leg S1, on the edge build alpha.4+edge.20261022), an
untracked `coverage.cobertura.xml` appeared in the worktree root. Its mtime falls inside the run. The al-runner v3
binary writes its coverage file into the process's working directory. A user running LethAL from a project folder
would get the same stray file after every run, and a later dirty-tree check could refuse because of it.

**v2 does not do this.** For v2, `al-runner-transport.ts` already avoids it: `--coverage` alone would write
`./cobertura.xml` into the working directory, so the v2 transport names an explicit output path.

**To close.** Make the v3 backend name an explicit coverage output path (or run al-runner in a scratch working
directory, if v3 has no output flag). Add a unit test that the spawn's argv or cwd never points the coverage file at the
caller's directory, red-checked, and confirm it live with one v3 leg leaving the worktree clean.

**Closed.** v3 has no output flag for that file, so every v3 process LethAL starts now runs with its working
directory set to a scratch folder: the one-shot call and the `serve` daemon (the session's instrumented folder), and
the contract probe and its serve and predefined-symbols calls (the probe's own temp folder). The `--version` call stays
as it was. Because the folder changes, every path handed to v3 is made absolute (`alRunnerPath` when it names a path,
the coverage file, the package cache and `ALRUNNER_CACHE`). Unit tests pin the working directory for the one-shot call,
the daemon and the contract probe, and the absolute paths; each goes red when its line is removed. The live check (a
v3 leg leaving no `coverage.cobertura.xml` in the worktree) is the final `itest:alrunner-v3` run.
