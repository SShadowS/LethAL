**A batch whose TOTAL guard count exceeds the measured publish ceiling still pays for the failure — R90 refuses per FILE only.** R90's pre-flight (`assertUnderCeiling`, `packages/runner/src/publish-ceiling.ts`) is called once per file, deliberately: batches split at file granularity, and a file that alone exceeds the ceiling cannot be rescued by any flag. But the ceiling is a property of what gets PUBLISHED, and a batch publishes several files at once — so N files each comfortably under the bracket can sum past it and time out, with nothing said beforehand. **Refusing that case would be wrong** and is deliberately not the ask: `--max-guards-per-batch` is exactly the lever for a batch total, so a refusal would be the false-refusal direction R90 was careful to avoid, and the user has a fix the tool should not pre-empt. The gap is that nothing WARNS. R90's own complaint was "nobody can discover the ceiling before paying for it"; for the multi-file batch shape that is still true after R90. Fix: when a batch's summed guard count crosses the tier's `smallestFailure`, print a warning naming the batch total, the measured bracket, and `--max-guards-per-batch` as the lever — a warning, never a refusal. Filed 2026-08-05 from subsystem C's Task 3 review; both directions (single file over the bracket, batch total over the bracket) already have tests, so the behaviour is measured, not assumed.
