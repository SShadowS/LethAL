Found by coord task PR-02 (2026-11-14) with `scripts/refusal-family.ts --family dotnet-no-object`: one invented test per access
(property or method) on a DotNet variable declared and never assigned (what a mutant leaves when it removes the line that makes
the object), each in its own test codeunit of an OnPrem app, on `current` edge-a184cfc79. Types: Uri, UriBuilder, Regex,
StringBuilder, TimeZoneInfo, CultureInfo, MemoryStream, Encoding, XmlDocument. Results: 29 cells, 0 pass, 0 fail, 29 refused
(`/coord/handoff/PR-02/dotnet-current.json`). Related: [[R1010]], upstream #8036.

**Known class, 25 cells.** `DotNet <type>.<member>: '<type>.<member>' is an instance member and the variable holds no object`, the
text #8036 item 1 asked for (the old "not found on" text is gone for these). The generator folds a DotNet text of this shape to its
cause (`DotNet *: <cause>`), so they read as one known class. No sibling of these fails: properties, methods and `ToString()` alike.

**Wrong text, 2 cells (new).** `Regex.IsMatch('a')` and `Regex.Replace('a', 'b')` with no object read `... has no overload taking
1 argument(s) of the given types (String)` (Replace: 2, (String, String)). Both instance overloads exist: on a constructed Regex
(`RX := RX.Regex('a+')`) both calls pass on the same build (scratch probe, 2026-11-14). So it is the no-object cause with the wrong
text, for a method that also has static overloads.

**By policy, 2 cells.** `TimeZoneInfo.DisplayName` and `GetUtcOffset` are `refused by policy` (Windows zone data on a non-Windows
host), before any no-object check. Upstream's deliberate rule, not this item.

**Why it matters.** Each refusal costs a mutant its verdict. Upstream refuses only because BC's error text is not measured yet (its
probe is queued); a .NET call on no object is a null reference whatever the member, so one measured text should cover every type.

**Reported:** https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8036#issuecomment-6884611596 (the type table, the
Regex text, an invented repro; its first version wrongly said all 29 shared one text, corrected in place).
**Regression set:** `scripts/upstream-repros/u8036-dotnet-no-object` (StringBuilder.Append, MemoryStream.Length, Encoding.WebName,
XmlDocument.OuterXml and Regex.IsMatch under `asserterror`; BC's result inferred: an error, so each test passes).
BC's answer is inferred, not measured: an OnPrem DotNet probe on BC is not covered by the item-4 publish approval.

**To close.** The 27 non-policy cells run (fail like BC, or pass under `asserterror`) on `current`.
