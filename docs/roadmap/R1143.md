Filed by coord PR-225 (lethal-code, 2026-11-19) on the owner's ruling q-20261119T134404-d37c858b: build option A of
[[R1142]] (the recheck baseline runs only the candidate killers' codeunits), and keep repeat-run reuse filed as a task, not
built (principle 35). Evidence: `/coord/handoff/PR-225/spec-light.md`.

**What it would save.** With A, y3's recheck baseline is 497 isolated tests, about 895 s of wall. A run on the same
al-runner build, the same sources and the same test app as an earlier run would get the same baseline outcomes, so reuse
would save all of it on that run.
- y2 and y3 were such a pair: the same build, the same 757 `error` sites, the same verdicts.

**How:** as R192 does for the main baseline.
- Key the stored recheck baseline by the instrumented source hash, the test app hash, the al-runner build, and the
  recheck's test set.
- Reuse it only on an exact key match, and re-run on any difference.
- Rules (c) and (e) read it as they read a fresh one, and "unmeasured is never a kill" still holds: a test absent from the
  reused set is not passed.

**Trigger to build:** repeat DO runs on one build become common. That means more than one recheck-bearing run per build in
a week, or the owner's speed goal asks for the next 15 minutes per run.
