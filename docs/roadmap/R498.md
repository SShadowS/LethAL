**Found 2026-10-07 by R-496's plan** (`/coord/handoff/R-496/plan.md` r3, section 4, "Split"; review
r1 at `/coord/handoff/R-496/review-r1-gpt-6.1-sol.md`). Pre-existing under R492 and R495; R496 did
not change it.

**What.** An env-tool (hook) session reads its test app back after the hook. When that package is
readable but holds no `.al` entries, `reportPublishedTestApp` classifies it as `unavailable`, and
`proveReadBack` refuses `unavailable`. The run therefore records no proven identity: a later
`--resume`, `--skip-known-survivors` or R192 baseline reuse takes nothing from it, and it takes
nothing from earlier runs. This fails closed (a run that cannot resume), never as a false carry.

**What already works.** A NON-hook bcdev session with a source-less test app is proven: R495's
`provenWithoutHook` reads the package's own manifest, and R496 takes the dependency fingerprint from
that manifest too (F8; tested as T10 and T10b in `orchestrator.test.ts`). An offline al-runner run is
proven by construction.

**Why separate.** Proving a source-less read-back changes R492's `proveReadBack`. Its check that the
read-back's `.al` source set equals the `publishApps` file's would need a byte or manifest equality
instead, and whether the bytes BC serves equal the published file's bytes is not measured.

**To close.** Measure on a live container whether the served package of a source-less app equals the
published `.app` byte for byte. If it does, let `proveReadBack` accept a byte (or manifest) equality
with the `publishApps` file when the read-back has no `.al`; otherwise decide what evidence stands in.
Pin both directions with tests.
