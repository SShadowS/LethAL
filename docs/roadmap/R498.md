**Found 2026-10-07 by R-496's plan** (`/coord/handoff/R-496/plan.md` r3, section 4, "Split"; review
r1 at `/coord/handoff/R-496/review-r1-gpt-6.1-sol.md`). Pre-existing under R492 and R495; R496 did
not change it.

**What.** An env-tool (hook) session reads its test app back after the hook. When that package is
readable but holds no `.al` entries, `reportPublishedTestApp` classifies it as `unavailable`, and
`proveReadBack` refuses `unavailable`. The run therefore records no proven identity: a later
`--resume`, `--skip-known-survivors` or R192 baseline reuse takes nothing from it, and it takes
nothing from earlier runs. This fails closed (a run that cannot resume), never as a false carry.

**What already works.** A NON-hook bcdev session with a source-less test app is proven: R495's
`provenWithoutHook` reads the package's own manifest, and R496 takes the dependency fingerprint from
that manifest too (F8; tested as T10 and T10b in `orchestrator.test.ts`). An offline al-runner run is
proven by construction.

**Why separate.** Proving a source-less read-back changes R492's `proveReadBack`. Its check that the
read-back's `.al` source set equals the `publishApps` file's would need a byte or manifest equality
instead, and whether the bytes BC serves equal the published file's bytes is not measured.

**To close.** Measure on a live container whether the served package of a source-less app equals the
published `.app` byte for byte. If it does, let `proveReadBack` accept a byte (or manifest) equality
with the `publishApps` file when the read-back has no `.al`; otherwise decide what evidence stands in.
Pin both directions with tests.

**Done 2026-10-10 (e4907b30).** Plan: `docs/superpowers/plans/2026-10-10-r498-source-less-readback.md`.
- **Measured** on Cronus28 (`/coord/handoff/R-498/measure.md`): the dev endpoint serves back exactly
  the bytes that were published, on four variants, including a package published WITHOUT `.al`.
  `resourceExposurePolicy` never strips source, so a source-less read-back means the published file
  had none.
- **Change.** A readable package with no `.al` is now a `source-less` `PublishedTestSources` that
  keeps its bytes. `proveReadBack` runs it through the same identity, version and installed checks
  as `published`, then requires the served package's SHA-256 to equal the `publishApps` test-app
  file's. Bytes, not the manifest: an unbumped publish that was skipped keeps the manifest over a
  different body. With no `publishApps` file that is the test app, the installed checks alone prove
  it, as for `published`. It still records no digests, with the one "carries no AL source" warning;
  a dependency fingerprint that cannot be taken is named first.
- **Tests** H1 to H9 in `orchestrator.test.ts` (describe "R498: a source-less read-back after the
  hook is proven by byte equality"), each red-checked (`/coord/handoff/R-498/redcheck.md`).
- **Scope, and an open HOST step.** Only the dev-endpoint (`altool`) publish route was measured. The
  hook publishes through the env tool's own publish command (`makeEnvToolPublisher`). If that
  command repackages the file, served and file bytes differ and the run stays unproven: safe, but
  no gain on that route. Measuring it (publish a source-less test app through the env tool, read it
  back, compare SHA-256 with the file) is a host step for the owner, because the env tool is
  host-only. Until then the gain is proven for the dev-endpoint route alone.
