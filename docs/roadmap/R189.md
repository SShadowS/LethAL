**What broke.** [[R161]] let six deletion operators claim the un-braced body of a branch, and added
`emptiedSlotFiller` so that emptying such a slot leaves a legal empty statement rather than a
dangling `then`: `if Cond then Foo();` becomes `if Cond then ;`. Its comment records the four shapes
measured by `alc` before it shipped: then-branch, else-branch, case arm, while body.

The fifth shape is the ordinary one: `if Cond then Foo() else Bar();`. There the filler produced
`if Cond then ; else Bar();`, and the empty statement's `;` closes the `if` before its `else`. That
is AL0110 by its own description, *"an unnecessary semicolon placed just before the ELSE keyword"*.

**Where it was found, and why not earlier.** The R175 re-run of `do rung1`
(`docs/superpowers/specs/2026-09-02-r175-rung1-rerun-precommitment.md`) on Cronus28. Its
instrumented codeunit carried the shape at three sites (the `OnRun` trigger's feature switch and two
more), `alc` refused the artifact, bisection could not name a single culprit because there were
three, and **all 155 mutants scored `error`**. Not one gate fixture has a deletion site in a
then-branch followed by `else`, and the R161 proof script compiled only the four shapes its author
had measured. A `describe` block one screen up in `compile.test.ts` already pinned the REWRITE case
of this exact shape ("wraps a mutated then-branch in begin/end so a following else still binds"),
so the hazard was known; the deletion path just never met it.

**The fix.** `emptiedSlotFiller` returns `begin end` when the text following the slot inside the
component root starts with `else`, and `;` otherwise. An empty block is a statement in every slot
and closes nothing. It is used ONLY there, so the four measured shapes keep the emission the proof
script compiled.

**Evidence.**
- `scripts/r161-emit-proof.ts`: the then-else shape FAILED with AL0110 before the fix and compiles
  after; a case-arm-before-case-else shape was added at the same time (compiles, needs no block,
  since the arm's own `;` survives the splice). A second negative control swaps the block back to
  `;` and must be REJECTED, so the block is proven load-bearing rather than the shape merely passing.
  7/7 shapes compile, both negatives rejected.
- `packages/schemata/tests/compile.test.ts`, "fills an emptied then-branch with an empty BLOCK when
  an else follows": red with the fix reverted, green with it.
- The re-run itself, after the fix, is the OUTCOME section of the R175 pre-commitment above.

**What this says about the gate fixtures.** Every fixture that a live gate scores lacks this shape.
The `sandbox-data` arm that would carry it is cheap (one procedure, one `if/else` with a call in each
branch) and would make a regression here a per-mutant baseline change instead of a customer-run
failure. Not built in this commit, so it is recorded here rather than assumed.

score, and its report's `validity` said `narrowed` with no caveat for the errors. That is [[R190]].
