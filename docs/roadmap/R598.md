**Filed 2026-10-21 by R-592** (lethal-preproc; from the final-pass review, `/coord/handoff/R-592/review-opus-final.md` I1).

**What.** `scripts/bc-linux-setup.ts` hard-codes `const LANE = "code"` and passes it to `kraken coord lease
<server> <lane>`. Any lane that runs the setup script therefore holds the bc server's lease as `code`. That
breaks the coord rule "held by another lane: wait", because the holder shown is wrong, and it makes a stale
lease left by the script look like lane `code`'s.

**Evidence.** `LANE` and its use in the lease call in `scripts/bc-linux-setup.ts` (master 60e60bfd).

**To close.** Take the lane from the caller (an argument, or the lane the session runs in) and refuse to run
without one. CLAUDE.md's own lease line already says `kraken coord lease bcN <your lane>` (R-592).

## Done (2026-10-21, R-598)

- **The lane source.** `bc-linux-setup.ts` no longer has `const LANE = "code"`. `resolveLane` takes the lane from
  `--lane <lane>`, else from the kraken agent identity. `KRAKEN_AGENT` is mapped as `scripts/coord-join-role.ts` maps
  it: `lane-<x>` is lane `<x>`, `orchestrator` is `orchestrator`.
- **The refusal.** With neither, or an identity that names no lane, the run refuses by name (`LaneUnknownError`).
  The lane is decided before the secret is read or anything is written. A `--lane` that is an agent name
  (`lane-preproc`) is refused too, and the error names the lane to pass: kraken itself accepts any holder name, so that
  slip would show the wrong holder again (build review I1).
- **The lease.** `krakenLeaseFor(lane, run)` builds the lease calls through the kraken-call seam.
- **Unchanged command.** CLAUDE.md's documented command, `bun scripts/bc-linux-setup.ts --server bc1|bc2|bc3|all`,
  keeps working unchanged inside the container, through the identity fallback.
- **Tests,** through the seam, with no server call:
  - no lane and no identity refuses;
  - `--lane` reaches the lease call and wins over the identity;
  - the identity fallback reaches the lease call;
  - heartbeat and release carry the token;
  - argument parsing, with a flag refused as a lane value.
- **Red checks:**
  - a hard-coded lane in the lease call: 2 tests red;
  - a silent default lane: the refusal test red;
  - the identity winning over `--lane`: the precedence test red;
  - the agent-name refusal disabled: its test red.
- **Checked by reading, not by a test** (build review I2):
  - `setupServer` takes its lease through `krakenLeaseFor(lane)` with the lane `main` resolved;
  - `main` resolves the lane before it reads the secret.
  A test of those two would need the whole setup run faked (secret file, configs, alc, server). The helpers are
  tested.
- **Not in scope, filed separately:** the lease-token file (`TOKEN_DIR`, `lease-<server>.txt`) is still shared by
  every lane.
- **Docs updated:** `docs/gates/servers.md`, the autonomy runbook and `fixtures/README.md`. Not CLAUDE.md, which only
  the owner edits.
