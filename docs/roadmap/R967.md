Found by coord task R-954 (2026-11-13), in VERIFY FULL on lethal/r954 and again on lane-preproc's master code (`CI=true bun test
scripts/heavy-slot-class.test.ts`: 1 or 2 failures in 3 runs on each; R965 does not touch `scripts/`).
Related: [[R952]] (the FIFO queue the test covers).

**What happens.** The test runs `heavy-slot.sh` against its own lock folder, holds two of three slots, and expects a plain `other`
caller to take the third. It gets exit 75 instead (the assertion on `plain.exited`). The guard (`heavy-slot-guard.ts`) also
counts heavy jobs it finds among the container's live processes, by process group; at the time another lane's BaseApp corpus
job and an al-runner `serve` run were up, so the guard saw the container at its cap and refused. The test's premise, that the
third slot is free to an `other` job, depends on what else runs in the container. On CI (no such jobs) it should pass.

**Why it matters.** A full VERIFY on a busy container fails by a test, not by the code under review, and every lane has to
decide that by hand.

**To fix.** Let the test give the guard an empty process view (an override the guard reads only under a test, or a seam that
injects the process list), so the test measures the queue logic alone; then check it still goes red when the queue lets a
refused waiter block the slot.
