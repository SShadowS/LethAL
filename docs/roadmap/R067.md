**A plain `page`'s implicit `Rec` is refused, though its `SourceTable` is declared in the page itself.** `resolveReceiver` (`packages/builtin-tier2/src/receiver.ts`) resolves an implicit `Rec`/`xRec` for a `table` (its own name) and for a `tableextension` (the header's `base_object`), and returns `unresolved` for every other kind — including `page`, whose record is named by its own `SourceTable = "X";` property, in the same file, with nothing to guess. Measured 2026-07-31 with `scripts/probe-r30-pageext.ts` on Continia Document Output Cloud: **66 Tier-2-shaped calls on a page's implicit `Rec`** (against 210 on record vars declared in the same page, which DO already claim). Safe direction — a missed site costs one operator's signal and Tier-1 `void-method-call` still covers it. Two things to get right if it is built: `SourceTable` is a page PROPERTY, not a grammar field the symbol table indexes today, and rule 3's `projectDeclaresProcedureOnTable` must then be applied to the resolved table exactly as the `tableextension` path does, or the shadowing guard is bypassed for a whole object kind. Found while measuring R30's remaining `pageextension` hole; NOT the same item (R30 is extension objects).
