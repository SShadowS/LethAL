---
id: "R245"
title: "Reach is measured only at a mutant's own statement: a call or block alone in a branch or case arm reports no reach"
section: "product-gaps"
status: "open"
order: 953
---

**Found 2026-09-26, while building GH-24's reach grain.** A mutant's reach marker is written at the
level `reachGrainOf` in `packages/schemata/src/dispatch.ts` resolves for it, using `REACH_MARKER`,
`findEnclosingStatement` and `isStatementSlot` in `packages/engine/src/ast/tree-walks.ts` to decide
where the marker can sit. When the mutant's own node is not itself a statement slot occupant, in
Business Central AL that means a single call or expression alone in an unbraced `then`/`else` arm,
or a single statement alone in a `case` arm, the tool cannot place a marker for that exact node. It
falls back to marking the whole enclosing statement instead, which reports "the branch was taken"
rather than "this mutant's own site executed". A mutant one level further down, a call nested
inside its own `begin ... end` block, has the same problem for the same reason: the block is the
statement slot occupant, not the call inside it.

**The measured shape.** `Data Reach Ops` (`fixtures/sandbox-data/src/DataReachOps.Codeunit.al`,
codeunit 79334) is the live control. Its second `if` guards a bare `Touch()` call with no braces:

```
if Amount > 1000 then
    Touch();
```

The `void-method-call` mutant that deletes `Touch()` cannot get its own marker: there is no statement
slot for the call alone, only for the `if` itself. It carries `reachGrain: "enclosing"`, no marker
and no `guardReached` at all. No covering test passes an Amount above 1000, so this mutant sits at
`no-coverage` and a false "reached" on it would be visible, not merely wrong, but on a fixture where
such a branch WAS exercised, the report would say the branch was reached without saying whether the
mutated call's own site ran.

**Measured grain counts per fixture** (statement / enclosing / unplaced), from the Task 2 enumeration
test: sandbox-app 19/0/0, sandbox-data 380/7/0 (371/6/0 before the `Data Reach Ops` arm), sandbox-hang
40/0/0, gift-card 55/5/0, credit-limit 41/1/0. Every fixture has at least one enclosing-grain mutant
except sandbox-app and sandbox-hang; none has an unplaced one yet.

**A second shape with the same cause.** On the vendored grammar, a `repeat` body's occupant is a
`statement_block` whose own parent is the `repeat_statement`, and a call alone inside it (or a
`begin ... end` written inside it) still resolves to the whole `repeat`, not to the call: the
enclosing walk stops at the nearest statement slot, and the repeat body is that slot regardless of
what sits inside it (see [[R244]] for the grammar shape this rests on).

**What closing it needs.** A marker inside the branch SLOT itself, not at the enclosing statement:
wrap the slot occupant, for example `then begin Reached(); Foo() end`, rather than wrapping the
statement that contains the slot. This means the component builder that emits the guarded call must
know which slot a mutant's node sits in, not only which statement encloses it. Two ceilings remain
after that: expression grain (today reach says a statement began, never a sub-expression within
it), and al-runner, which has no channel to report reach at all, so this closes only the bcdev path.

Evidence: `reachGrainOf` and `REACH_MARKER` in `packages/schemata/src/dispatch.ts`;
`findEnclosingStatement` and `isStatementSlot` in `packages/engine/src/ast/tree-walks.ts`; the grain
counts the Task 2 enumeration test prints per fixture; the `Data Reach Ops` enclosing mutant
(`void-method-call` deleting `Touch()` in `Classify`).
