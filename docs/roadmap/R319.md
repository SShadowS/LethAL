**Found by R-316's plan (2026-09-28)**, `docs/superpowers/plans/2026-09-28-R-316-preamble-member.md`,
"Review r1 measurements", I3, while measuring [[R316]]'s coverage attribution on the `--server` path.

**What breaks.** `AlRunnerBackend.ensureServerSuite` (`packages/runner/src/al-runner-backend.ts`)
sends `server.runTests` the source paths, the package paths, the isolation mode and the coverage
flags, but no preprocessor symbols. The one-shot path sends one `--define` per symbol
([[R101]] (c)). So with `serverMode` on, al-runner always compiles and runs the NO-symbol build,
whatever `preprocessorSymbols` says, and the verdicts belong to a build the user did not ask for.
The report still records the symbols as if they were used ([[R101]] (c)), so nothing says so.

**Measured** at R-316 plan time on al-runner v2.11.0, repro `p12-mixed-scope` (a preamble whose
`CLEAN27` arm is `local`), coverage on:

- one-shot leg, subset `[CLEAN27]`: 4 `no-coverage` (no test can call a local procedure), which is
  the `CLEAN27` build's result;
- `--server` leg, subset `[CLEAN27]`: 3 killed, 1 survived, `exact`, which is the no-symbol build's
  result.

No fixture defines a symbol, which is why `itest:alrunner`'s server legs still match the one-shot leg.

**What would close it.** Pass the symbols in the server request, if al-runner's server accepts them,
or refuse `serverMode` together with `preprocessorSymbols` until it does. Either way, with a
two-build test: the same project under two symbol sets must give each build's own verdicts on the
server leg.

**Closed 2026-09-28 (R-319).** Fixed per
`docs/superpowers/plans/2026-09-28-R-319-server-symbols.md`. Measured on al-runner v2.11.0: the
server reads preprocessor symbols only as start-time `--define` flags, fixed for the whole life of
the daemon; a symbols field sent in the `runTests` request (tried both as `preprocessorSymbols` and
as `defines`) is silently ignored, no error and no acknowledgement. The fix starts the daemon with
one `--define` per symbol, added in `AlRunnerServer`'s constructor and passed from
`AlRunnerBackend`'s constructor as `cfg.preprocessorSymbols`, the same form the one-shot argv
already sends ([[R101]] (c)). The resource selector leg (`selectorMode: "resource"`) runs through
the same daemon, so it had the same gap and needed no code of its own; Task 1's tests pin both
selector modes against the same fix.

Three tests in `al-runner-backend.test.ts`, describe `AlRunnerBackend serverMode (R220)`: the
daemon's argv carries the same `--define` list as the one-shot argv, checked for both selector
modes, and with no symbols configured the daemon's argv is exactly `["al-runner", "--server"]`.
Each was red-checked: removing the `--define` line from `start` failed both symbol tests and left
the no-symbol test passing; passing `[]` instead of `cfg.preprocessorSymbols` in the backend
constructor failed both symbol tests; replacing the per-symbol spread with an unconditional
`--preprocessor-symbols <joined>` flag failed all three, including the no-symbol test, which is
what catches a session that defines nothing still getting extra flags.

No AL was edited by this fix, so no offline `alc` compile check applies. The al-runner probe
evidence above is scratch: hand-written repros, not a committed gate, run locally against al-runner
v2.11.0, no BC container. The wire probe measured the contract directly (the table now recorded in
`docs/measurements/README.md`, section "al-runner v2"). A separate equality probe ran 7 hand-written
repros, every symbol subset, three legs (one-shot, `--server`, `--server` with the resource
selector), comparing verdict and killing test per mutant: all 7 gave equal results across all three
legs in every subset, and `s1-clean-rate` and `p12-mixed-scope` also matched selected witnesses
taken from the one-shot leg, values only the right build gives. The checker itself was red-checked
on the real fixed logs: 14 cases, all as wanted.

`itest:alrunner` passed unchanged: al-runner v2.11.0, 3 killed / 12 survived / 4 no-coverage, all
four legs (two one-shot, `--server`, `--server` with the resource selector) with identical
per-mutant verdicts. The fixture defines no symbol, so the daemon's argv on this gate is
byte-identical to before the fix, and this gate alone cannot see the defect this item fixes; that
gap is why [[R321]] files a symbol-defining fixture leg for `itest:alrunner` separately, not built
here.

Filed upstream: StefanMaron/BusinessCentral.AL.Runner#4952,
https://github.com/StefanMaron/BusinessCentral.AL.Runner/issues/4952, 2026-09-28, asking that the
server either accept symbols per request or reject an unknown request field outright, instead of
accepting and silently ignoring one. Related and already closed upstream: #4064.
