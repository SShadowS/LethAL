**BC-measured facts worth knowing** (al-runner matches each):
- `HasCollectedErrors()` answers true with `GetCollectedErrors().Count()` 0, in a test with nothing collected. Two other
  fields read it, so they carry no information: the last field of `Collect.AndClear` and the second field of
  `Collect.Outside`. Whether this comes from the test runner's scope is not measured.
- A TryFunction cannot write to a real table at all on either runtime (the write is refused).
- AutoIncrement does not number a temporary table: the second insert fails at Id 0.

**Cells that stop before their target on BOTH runtimes**, so the named behaviour is unmeasured:
- `Try.InsertThenError` and `Try.InsertOk`: whether a try rolls back real writes. Both are refused before that.
- `Run.FailAfterWrite`: whether a failing Run rolls back an earlier write. The Run itself is refused, as in
  `Run.OkAfterWrite`, so these two cells measure the same rule.
- `Collect.KeepGoing`: "ET g1" is the answer whether or not execution continues after the error. `Collect.AndKeep`'s
  "Multiple errors ..." shows that it does continue.
- The two call-stack cells check only "non-empty".

**Measured since** (coord PR-500, lethal-preproc, 2026-11-28; family `errors-temp-2`, 45 cells, BC-check 32; al-runner
edge-e5176a9fd and BC 28.4 on bc1). Evidence: `/coord/handoff/PR-500/errors-temp-2/` (`v3.json`, `bc/errors-temp-2.bc1.tsv`,
`joined.tsv`). Spec: `docs/superpowers/specs/2026-11-28-pr500-followup-differentials.md`.
- **Join: 44 equal, 1 different.**
  - The difference: `ErrorType::Internal`'s generic message carries a random correlation id. al-runner writes it in braces
    (`{guid}`), BC without.
  - A test can see that (`StrPos(GetLastErrorText(), '{')`, or the text's length), and no open issue covers it, so it is
    **filed as #9409** (a follow-up of the closed #5766).
- **Settled (equal on both runtimes):**
  - **item 3, TryFunction:** with the return value unused, a TryFunction is an ordinary call. Its write is allowed and stays
    (`Try.WriteUnused` 1), and its error goes up. Whether a try rolls back writes cannot be measured: with a used return value
    the write is refused, and with an unused one there is no try. A Commit inside a try is refused ("Call to the function
    'COMMIT' is not allowed inside the call to 'RootMethodScope' when it is used as a TryFunction."). A try calling
    Codeunit.Run, and a failing one, both answer;
  - **item 4, Codeunit.Run:** the last error is NOT cleared by a successful Run and is visible inside its target; nested Run
    and nested-fail; Run after a Commit (ok and fail); a Commit inside the target;
  - **item 5, in part:** `ErrorType::Internal` (the generic message, with the difference above); RecordId, TableId and FieldNo
    on the variable; the format-9 ordinals (Internal 1, Warning 3). `.AsInteger()` on ErrorType and Verbosity does NOT compile
    (AL0132), so that part is closed by that fact;
  - **item 6, in part:** `GetCollectedErrors(true)` (2|false|0);
  - **item 7:** a Commit inside an asserterror body keeps the committed row (1);
  - **item 8, temporary-record triggers:** the row after a failing `Insert(true)`; `Modify(false)`/`Delete(false)` of a bad row;
    `DeleteAll(true)` and `(false)`; Validate; OnRename ok and bad (`RenameBad` reads the variable's key only, not where the
    stored row is);
  - **item 9:** Copy shared: filters stay on their own side, and the data is shared;
  - **item 10:** a real record to a temporary parameter (0); a temporary record as a return value: the assignment does not copy
    its rows (0|true; into a real record 7|false);
  - **item 11:** AutoIncrement: an explicit Id on a temporary table (5|1, then 0|2); a rolled-back insert on a real table uses up
    an Id (2).
  - `HasCollectedErrors` reads `true|0` across a Codeunit.Run boundary too. The test is always on the call stack, so whether this
    comes from the test runner stays unmeasured.
- **Still open, because six cells stopped early on BOTH runtimes** (review, PR-500): `Collect.KeepGoingCount`,
  `Collect.CountInRun`, `Info.CollectedTitleDetail`, `Info.CollectedRefs`, `Collect.Nested` and `Collect.TryInScope`.
  - Each helper ends an `ErrorBehavior::Collect` procedure with errors still pending, so the runtime raises them at the scope's
    end, and the cell's answer is that error's text, not its payload.
  - Open, therefore: item 2 (KeepGoing's count, the count through Run), item 5 (Title, DetailedMessage and the refs through
    GetCollectedErrors), item 6 (nested scopes, a collectible error in a try in a scope).
  - **The fix for a next family:** store the payload, clear with `GetCollectedErrors(true)`, then exit, as `Collect.GetClear` did.
