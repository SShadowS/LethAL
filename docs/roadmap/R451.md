**Where this came from.** [[R213]] closed by ruling: the reverse direction, `ModifyAll(F, V, true)` to
`ModifyAll(F, V, false)`, is already a `flip-boolean-literal` mutant, so it adds nothing. The forward
direction is different: adding a `true` third argument to a two-argument call is an edit no other
operator makes, the same shape as `swap-modify-flag`'s forward direction for `Modify` ([[R165]]).

**Counts (2026-10-05, `claimsRecordMethod` plus an argument count).** Forward candidates are
`ModifyAll(F, V)` calls whose table is declared in the project and has an `OnModify`:
CDO `Cloud` **0**, CDO `Cloud` + `Test` 0, BaseApp `Source` **186**, BaseApp `Source` + `Test` **287**.
It fails R13's bar on the calibration corpus (CDO) and clears it only on BaseApp.

**Before building.** Measure on a corpus the product is aimed at, not on BaseApp alone. A new edit
means a new mutant per site and an identity scheme bump ([[R193]] ordinals do not move, since no
`true` literal is removed, but check). Any question about tagging a skipped or forced trigger follows
[[R452]], not this item.

**Closed 2026-10-06 as a ruling (R-451, orchestrator): not built.** Measured offline on master b8db5ea8 (coord
handoff `R-451`, recommendation and survey; app projects; test projects are reported separately there).
- **Sites:** a two-argument `ModifyAll(F, V)` on a proven Record. CDO 74, DC 40, DO 69, BaseApp Source 566.
- **Where an `OnModify` or observer can run:** CDO 0, DC 0, DO 1, BaseApp 257. Building only there would add about
  one mutant across the three product corpora.
- **The rest:**
  - mostly base-app tables the project cannot see (CDO 68, DC 25, DO 57);
  - otherwise tables with no trigger at all, where the mutant is EQUIVALENT (6, 15, 11).
  Microsoft's `Record.ModifyAll` documentation states that `ModifyAll` never runs `OnValidate`, so there is no
  validation path either.
- **The tag would separate nothing:** under [[R457]]'s rule, 68/25/58 product-corpus sites would carry
  `run-trigger-forced`, about 90% of them.
- **Cost was not the reason.** bcdev takes 1.1-10.5 s per mutant, so this is minutes in total.
- **No value found:** only 2 committed-report mutants sit within 3 lines of a site, both no-coverage.
- Side finding, filed as [[R485]]: 301 BaseApp forced tags come only from `forceCanRaise`'s text check on unindexed
  objects.
