Found by coord task R-975 (2026-11-14), recorded in `/coord/handoff/R-975/findings.md` ("A slip of mine"); fixed by R-986.
Related: [[R886]] (the sidecar setting), [[R996]].

**What happened.** Bank Deposits' config, written in R-886, named a hand-built `AlDotNetSidecar.dll` from another lane's scratch
folder. That sidecar speaks protocol 5. When `current` moved to edge-847b1fa5a (protocol 6), every .NET call in its tests failed with
`DotNet new System.Text.UTF8Encoding: protocol mismatch: the sidecar speaks version 5, the host version 6`, and 13 green tests became
refused. Nothing in LethAL's output pointed at the config: by R886's rule the named file simply wins over the build's own sidecar.

**Fix (R-986).** `resolveDotnetSidecar` still uses a named file (the config wins, R886), but when the al-runner build ships its own
sidecar (`.gated`) and the named file's sha256 differs, it returns a warning that names both files and both hashes and says what
breaks; the backend prints it as the `al-runner-v3-dotnet-sidecar-unusable` notice before any test runs. A copy of the build's own
sidecar, or a build that ships none, gives no warning. Red both ways (`al-runner-v3-backend.test.ts`, "R886: the default is the pinned
build's own sidecar").

**Not done.** Refusing the run instead of warning: a named, newer sidecar can be deliberate (R886), so the setting stays the user's.
