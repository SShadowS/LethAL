**Found by the R-214 lane (lethal-preproc), 2026-10-01.** Plan: `docs/superpowers/plans/2026-09-29-R-214-symbol-aware-site-enumeration.md`. Pre-commitment: `docs/superpowers/specs/2026-09-29-r214-precommitment.md`.

**What happened.** al-runner predefines the symbols `CLEANSCHEMA1` to `CLEANSCHEMA25`, and alc does not. R214 evaluated arms the way alc does, so on al-runner a `#if not CLEANSCHEMA<n>` arm (n up to 25; 35 occurrences in BaseApp) was still generated as a mutant and then compiled out by al-runner.

**Measured 2026-10-01 against al-runner v2.12.0.** Method: a probe project whose test raises an `Error` naming, for each candidate symbol, whether its own one-arm `#if <symbol>` block compiled in. Run with no `--define` and no `preprocessorSymbols` in `app.json`. Result: exactly `CLEANSCHEMA1` to `CLEANSCHEMA25` are defined. `CLEANSCHEMA26` and up, `CLEANSCHEMA`, other `CLEAN*` names, `FEATURE_CLEAN` and `NOTCLEANSCHEMA25` are not. alc (the bcdev backend) predefines nothing. Evidence: `H:/lethal-scratch/R-214/cleanschema/` (`out-none.txt`, `out-cs25.txt`, the `wide/` sweep), local to this machine.

**Fix (0a9ba1d7).** `AL_RUNNER_PREDEFINED_SYMBOLS` in `packages/runner/src/preprocessor-symbols.ts` is the one list, and names the version it was measured on. `effectiveBuildSymbols` now takes the build's backend. `runSession` decides the backend once and passes the same value to `generateMutationSet`, so an al-runner run enumerates arms, and records `runs.build_symbols` (the run row's recorded build symbols), the session fingerprint, history, resume and marks scoping, and the compiled-out detail, under that set. There is no separate report field for it. A bcdev run keeps alc's set. `lethal run --dry-run` reads an optional `--backend`; absent lists alc's build. The symbols are never passed to al-runner as `--define`. Tests: `packages/runner/tests/r214-al-runner-predefined.test.ts`.

**Still open.** The list is a fact about v2.12.0, and nothing re-checks a newer al-runner per session: R392.
