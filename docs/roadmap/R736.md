**Found by coord task R-727 (2026-10-24).** R727 added a warning (`installed-dependents`) that fires on `itest:harden`
(2 published dependents vs 1 accounted for). The harden itest passed and its log showed nothing, because it calls
`runSession` without an event emitter, so warning events never reach it. R-727 had to prove the warning by
running `checkDependents` directly against bc3.

**What.**
- Of the itests that call `runSession`, only `itest:hang` collects `warning` events and compares their codes with an
  exact list (check 11 in `packages/runner/itest/hang-baseline-leg.ts`). `itest:lend` filters by a regex.
- harden, bcdev, bcdev-names, bcdev-wrapped, tables, chunked, lease, stale-publish, verify, test-app-publish,
  verify-agreement, envtool and the al-runner-v3 gate collect nothing.
- So a change that adds a warning to a gate's run, or loses one that should fire (a refusal reason, a narrowed-run
  notice, a dependents warning), passes every gate silently.

**To close (coord task R-736).**
- Each BC gate and the v3 gate passes an emitter and asserts its warning-code set EXACTLY against a committed
  expectation, as hang's check 11 does.
- The expectation is recorded by a deliberate step, never by the gate itself (R332's rule), from one measured run
  per gate.
- The expected sets are pre-committed on master before the recording run.
- Red tests per direction: an extra warning fails, and a missing one fails.
- harden's set must contain `installed-dependents`.

**Measured and pinned.** The sets in `GATE_WARNINGS` (`packages/runner/itest/gate-expected.ts`) were measured by one
observe run per gate and pre-committed on master as 59225044
(`docs/superpowers/specs/2026-10-24-r736-gate-warning-sets-precommitment.md`, one reason per code).
- **envtool is not pinned.** It is host-only, so its key stays absent and `itest:envtool` refuses by name. The owner's
  host run (R683) also does one `LETHAL_ITEST_OBSERVE_WARNINGS=1` run to record its set.
- **verify-scale is exempt by name.** It is a measurement script (R270), not a gate, and `selectLegs` never picks it.
  The wiring test names the exemption.
- Legs that throw by design (lend RN3, RN1d, RN2, RN4; v3 N1E) are never asserted.

**Proven 2026-10-24 on head f7c0890f, in normal mode** (logs in `/coord/handoff/R-736/proof/`). Every pinned set
that ran matched, and these gates passed:
- bc1: bcdev, lease, tables, chunked, harden, verify, testapp, agreement, bcdev-names, bcdev-wrapped and lend;
- bc3: hang, all four legs;
- al-runner-v3: legs C through K. **D1, D1c and T did not run** (`alrunner-v3.log` ends "update-gate outcome
  infra-fail"; their warning sets had no pin yet, which [[R744]] then recorded and proved).
- **Correction (R-755 audit, 2026-10-25):** this row said "al-runner-v3: every leg" when it was merged. That was an
  overclaim made at merge (the orchestrator's slip, by its own account); the log above shows the three legs absent.

**Not covered here** (from the R-736 build review): `console.warn` lines inside a session that never become `warning`
events (the lease path, backend notices), and the warning events of `runVerify` / `runNamedMutants`, which the
verify, testapp and agreement gates call outside `runSession`.
