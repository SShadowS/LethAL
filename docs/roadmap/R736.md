**Found by coord task R-727 (2026-10-24).** R727 added a warning (`installed-dependents`) that fires on `itest:harden`
(2 published dependents vs 1 accounted for). The harden itest passed and its log showed nothing, because it calls
`runSession` without an event emitter, so warning events never reach it. R-727 had to prove the warning by
running `checkDependents` directly against bc3.

**What.**
- Of the itests that call `runSession`, only `itest:hang` collects `warning` events and compares their codes with an
  exact list (check 11 in `packages/runner/itest/hang-baseline-leg.ts`). `itest:lend` filters by a regex.
- harden, bcdev, bcdev-names, bcdev-wrapped, tables, chunked, lease, stale-publish, verify, test-app-publish,
  verify-agreement, envtool and the al-runner-v3 gate collect nothing.
- So a change that adds a warning to a gate's run, or loses one that should fire (a refusal reason, a narrowed-run
  notice, a dependents warning), passes every gate silently.

**To close (coord task R-736).**
- Each BC gate and the v3 gate passes an emitter and asserts its warning-code set EXACTLY against a committed
  expectation, as hang's check 11 does.
- The expectation is recorded by a deliberate step, never by the gate itself (R332's rule), from one measured run
  per gate.
- The expected sets are pre-committed on master before the recording run.
- Red tests per direction: an extra warning fails, and a missing one fails.
- harden's set must contain `installed-dependents`.
