**Why this family.** After families 1-5, the largest open issue by standing sightings (R1036's corrected count over all v3 stores)
is #8002, 1,121, which is a single isolation cause and is family 7 (coord PR-27). Next come #8013 and #7480, but they are not
coherent families: #8013 is eight unrelated causes, and #7480 is a Confirm callback, which is family 5's shape. Next is #7586,
`GetUrl`: 213 standing sightings, and these refusals cost covered tests (VAT Group Management: 41 of 82 tests stop at one 5-argument
call).

**What was built.**
- **The family:** `scripts/refusal-family.ts` family `get-url`. It has 11 client types (Current, Default, Web, Windows, Tablet,
  Phone, Desktop, SOAP, OData, ODataV4, Api) by 9 forms:
  - the client type alone, or with the company;
  - with an object type and id: Page, Report, Codeunit, Query, Table;
  - with a page and a record;
  - with a page, a record and UseFilters.

  Each cell fails on purpose with `GETURL <url>`, so a run carries the URL each runtime builds.
- **Classes:** `classOf` folds a `GetUrl` text's client type, argument count and object type, and keeps the reason.
- **Tests:** the family's shape, the class rule (red when the rule is removed), and the BC-check app id pinned as 6.

**Measured on edge-5a58a0f16.** 60 cells return a URL and 39 are refused, by reason:
- 12, "this object type or argument list": the issue's own wording, which this build drops "(not pinned)" from;
- 8, Default or Windows with an object type other than Page or Report, or a page with a record (NEW);
- 15, Phone, Tablet or Desktop with Codeunit, Query or Table, or a page with a record (NEW);
- 4, SOAP, OData, ODataV4 or Api with only a company: "a company of other characters than letters, digits and space" (NEW). The
  same company is accepted in a 4-argument call of those client types with a page.
