call).

**What was built.**
- **The family:** `scripts/refusal-family.ts` family `get-url`. It has 11 client types (Current, Default, Web, Windows, Tablet,
  Phone, Desktop, SOAP, OData, ODataV4, Api) by 9 forms:
  - the client type alone, or with the company;
  - with an object type and id: Page, Report, Codeunit, Query, Table;
  - with a page and a record (PageRecord, 5 arguments);
  - with a page, a record and UseFilters (PageFilters, 6 arguments).

  Each cell fails on purpose with `GETURL <url>`, so a run carries the URL each runtime builds.
- **Classes:** `classOf` folds a `GetUrl` text's client type, argument count and object type, and keeps the reason.
- **Tests:** the family's shape, the class rule (red when the rule is removed), and the BC-check app id pinned as 6.

**Measured on edge-5a58a0f16.** 60 cells return without a refusal and 39 are refused.

**The 60.** 42 return a URL and 18 return an empty string:
- Codeunit under Current and Web;
- Page, Report, Codeunit and PageFilters under SOAP;
- Page, Report, Table and PageFilters under OData;
- Page, Report, Codeunit, Query and PageFilters under ODataV4;
- Page, Report and PageFilters under Api.

**The 39, by reason:**
- 12, "this object type or argument list (not pinned)": the issue's own wording. (`refusalText` strips "(not pinned)" before it
  prints; the build still prints it, and my first upstream comment wrongly said it did not. Corrected there.)
- 8, Default or Windows with Codeunit, Query or Table, or PageRecord (NEW);
- 15, Phone, Tablet or Desktop with Codeunit, Query or Table, or PageRecord or PageFilters (NEW);
- 4, SOAP, OData, ODataV4 or Api with only a company: "a company of other characters than letters, digits and space" (NEW).
  - Only that 2-argument form raises it.
  - With a page, those client types return an empty string, so it is not shown that they accept the company. My first upstream
    comment said so wrongly, and it is corrected there.
