**Seen 2026-10-02 by the orchestrator**, running `bun scripts/verify.ts` on the R-378 merge
(b4ad8a0a) while three lanes ran corpus captures and live gates. One test failed:
`scripts/snapshot-late-write.test.ts`, "R393 late snapshot write > (b) control, CI unset: the
wrong entry IS written under B's key". The marker read:

    A late call reached; CI=undefined
    A late toMatchSnapshot THREW: Snapshot matchers are not supported in concurrent tests

The control expects "A late toMatchSnapshot returned OK". Run alone, the file passed 3 of 3 times
straight after. So the late call from test A depends on timing: under load it can land while bun
treats the run as concurrent, and bun then refuses the snapshot matcher outright instead of
writing under B's key. The guard (case a) was not affected; only the control that shows the
defect exists can fail.

**To close.** Make the control independent of timing: for example, hold test B open on a promise
that A's late call releases, so A's write always lands inside B. Or accept either "returned OK
and wrote under B" or this named refusal as the control's outcome, stating why. Red-check that the
control still fails when the late write cannot happen.
