**Found 2026-10-03, running R307's unit suite in the kraken (Linux) container for the first time.**
The test `R307: sandbox-data is byte-identical with the trial in place` in
`packages/runner/tests/per-file-refusal.test.ts` pins two sha256 hashes of
`writeInstrumentedProject`'s output for `fixtures/sandbox-data`. Both were recorded on the Windows
host, where the test passes. On Linux both differ:

| | Windows (pinned) | Linux (measured) |
|---|---|---|
| `mutant-manifest.json` | `b03f52f2d9b2442098380746c8b4c6a8eb8dde17e49e5229cb5c66b31bcfa20f` | `b754095f8aebddf35074c5d032bdac8692076e3e9c1b015d6810bc0ec0ff588e` |
| all files, sorted by name | `e889a463…` | `9abd8f06e020d8f0fa0113b1534f70927664f1c0383540fd958dec19b7fa73c6` |

Linux gives the SAME manifest hash at `d1438ade` (the commit the pin names as its base, before R307's
trial existed), at `297a30f6` (the last commit whose full suite passed on Windows) and at the R307
branch head. So no R307 commit changed the output. The pin has never matched Linux.

**Ruled out, measured:** locale (`en_US`, `da_DK`, `C.UTF-8` all give `b754…`), line endings (all 32
fixture files are LF, `.gitattributes` forces `eol=lf`), path separators (the manifest's `file`
fields already use `/`).

**Not yet known:** which field or ordering differs. There is no Windows manifest to diff against
yet. The suspects, found by reading only, are the `localeCompare` sorts in
`packages/schemata/src/ids.ts` and `packages/schemata/src/project.ts`, because ICU collation can
differ between builds.

**Why it matters.** If the difference is in mutant ORDER, ids or identity fields, the same project
gets different mutant numbering, or different manifest content, on Windows and Linux. That would
make a baseline, a `--resume` store or a `--skip-known-survivors` list recorded on one platform
wrong on the other. If the difference is cosmetic, the risk is only to byte pins.

**Consequences now (orchestrator ruling, 2026-10-03).** The pin is NOT changed. R307 cannot merge
while the Linux CI job would fail on it, so this item blocks R307's merge until the cause is known and
ruled on. R307's option-3 amendment records its O1 reference hashes on Linux, labelled as Linux;
whether pins are carried per platform is decided here.

**To close.** Find the differing field (diff a Windows dump of the same write against Linux; probe
in the coord handoff `R-307/winprobe/`), fix the cause if it is ordering or identity, then rule on
per-platform pins and re-record deliberately.
