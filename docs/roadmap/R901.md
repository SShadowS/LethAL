Found by coord R-893, building BC.History's System Application from source on Linux. Related: [[R422]] and [[R811]] (the same alc behaviour for paths in `app.json`, fixed there only), [[R900]].

**What.** A `controladdin` names its files relative to the declaring `.al` file: `Scripts = 'Resources\OAuthIntegration\js\Startup.js';`. alc on Windows treats `\` as a separator. alc on Linux looks for ONE file whose name holds the backslashes, finds none, and gives `error AL0327: Missing file 'Resources\OAuthIntegration\js\Startup.js'`. The file is there, at `Resources/OAuthIntegration/js/Startup.js`.

**Measured.** System Application 28.6: 21 AL0327 errors, from 17 distinct files, all present with forward slashes. In a scratch copy, a copy of each file under its literal backslash name, next to the declaring `.al` file, made all 21 go away. Script: `/coord/handoff/R-893/backslash-fix.ts`.

**Why LethAL is affected.** A batch project on Linux, the container and CI, compiles with the Linux alc. A target or test project written on Windows with backslash controladdin paths therefore fails every batch with AL0327, before any instrumentation is judged. R422 rewrites `app.json` paths only. The batch's controladdin resource copies (issue #8, `prepareBatchProject`'s rebased copy) keep the backslash names unresolved.

**To close.** Make the batch hand alc a name it resolves on Linux. Either rewrite the controladdin path strings to `/` in the batch copy, which is plain text in the property list and is what R422 does for `app.json`; or copy each named file under its literal backslash name, as the workaround did. Rewriting is cleaner, but it moves the emitted text of those `.al` files. Refuse by name when a named file is missing in both spellings. Test with an invented controladdin naming `Res\a.js`.
