Filed by coord PR-113 (lethal-code, 2026-11-17). The trace is `/coord/handoff/PR-113/trace/split.md`. It is PR-112's 735fb42
`--changed-since` arm on DO, edge-4ebfe7913, whose baseline phase took 142.7 s:
- the daemon's 74 per-codeunit baseline requests: about 108 s, about 1.5 s each, against about 11 s of the tests' own row time;
- R948's 9 one-shot cross-check samples: 33.3 s, run sequentially (running them concurrently is [[R1107]], designed but not built);
- compile: about 1%.
- company login (#8211): at most about a fifth.

So about 95 s is per-request overhead that baseline requests do not show yet. PR-113 adds `serve-request-timed` with `kind:
"baseline"` and al-runner's `timings`.

**The candidate lever.** Several codeunits per baseline request, so the per-request setup and baseline cost is paid once per
batch. It must keep:
- R948's cross-check: samples by codeunit;
- per-test coverage collection;
- R998's left-out run;
- R1001's uniform-refusal rule;
- the per-codeunit order the later phases read (`baselineRows`).

Decide from the new events which part of the ~1.3 s per request is fixed: setup, baseline, other.

**Not pursued: reusing a stored baseline for a PR run** (measured by PR-113, `/coord/handoff/PR-113/baseline-analysis.md`):
- **(A), the base commit's stored baseline.** L5/R1033's key (the instrumented tree hash) follows the mutant set, so it never
  matches across a PR. Coverage line numbers also shift between commits (10 and 60 tests that touched no changed object showed
  shifted coverage), so a line-level reuse is unsound and only an object-level one is possible.
- **(B), baseline only the covering tests.** It saves 2-8% of the baseline: 273-434 tests after R1094's prefix closure, and
  nearly every test codeunit still runs. The tests' own time is only about 11-15 s of the 135-158 s.
