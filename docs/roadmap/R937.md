Filed by coord task R-929 (2026-11-12), from [[R922]] item 3. Related: [[R761]], [[R763]], [[R916]].

**What.** Since R-929 a test codeunit's NAME never falls the serve-entries default back to one-shot: serve addresses codeunits by
id and LethAL matches rows by id and method. A METHOD name is sent and read, so a method outside the proven shape
(`V3_SERVE_PROVEN_NAME_SHAPES.method`) still sends the whole session to one-shot (`unproven-test-name-shape`, now also a report
caveat), not only that method's codeunit.

**Measured reach** (`/coord/handoff/R-929/method-scan.ts`, a text scan of `[Test]` method names, with a `.` between letters or
digits counted as proven as on a #5798-fixed build):
- BC.History: 519 projects, 176 with tests, **0** with an unproven method name. Every BC.History app that lost serve to a name in
  R-902 to R-917 (EU 3-Party Trade Purchase, PayPal, E-Document Core, Subcontracting, SAF-T, Withholding Tax) lost it to the
  codeunit name, which R-929 removed.
- DC: 1 test app, **13 of 1,906** tests with a method name starting with a character other than a letter or digit.
- DO: 0 of 2 test apps. LethAL's fixtures: 0 of 16.

**To build, if wanted.** Run the odd method's codeunit one-shot inside a serve session (every serve phase routes that codeunit's
calls to the one-shot path), proven per mutant equal to an all-one-shot run on an invented app; or measure the odd shapes under
serve (as R763 did for others) and admit them. The second is smaller; for DC's shape (a leading character) it may be enough.
