Found while specifying PR-51 (R1057; `docs/superpowers/specs/2026-11-16-pr51-timeout-class-stable.md`, "Not in scope").

**What.** The covering loop ends a mutant at its first non-pass step in R197's order. PR-51 makes the walk go on after a timeout,
so killed vs timeout-killed no longer depends on the order. But a non-terminal `error` met before a fail, with or without a held
timeout before it (PR-51 ends the walk there and scores the held timeout), still decides the class: for example `session-reused`,
an `unstable` or `warm-prefix-unstable` confirm, a permission refusal, a runner refusal that is not after a stop. So a mutant with one test that errors and another that fails is `error` in a session that meets the error first and
`killed` in one that meets the fail first. R197's order depends on the session's kill history, so the class can differ between
runs.

**Not measured.** No pair of runs is known to show it yet; it follows from the same mechanism as R1057.

**Possible fix.** The same as PR-51's step 2 applied to a held error: hold a non-terminal error, walk on, score `killed` on a
confirmed kill, else the held error. Cost: the rest of the covering set for every such mutant (errors are far more common than
timeouts on DO: 184 in R-984 run 8), so it needs its own cost measurement first. It also needs what PR-51's review found
for walking past an error: the mutant re-activated after each error's confirm (today's error branches leave none active, which
only does not matter because they end the walk), and the error's fields kept off a later kill.

**Fixed (PR-81).** The covering walk holds a non-terminal error (a closed list of causes: `session-reused`, `unstable`, the warm
causes, and a `runner-refused` not after a stop) and goes on. A confirmed, reproduced kill later in the walk makes the mutant
`killed`; otherwise the first held error stands (or a held timeout's result, as PR-51 scores it). The error's fields are restored
from the step's start, the mutant is re-activated only when the step deactivated it, and v3's pending kill pair is dropped first
(new `dropPendingPair` hook, required on `V3LaneView`). Spec and measurements:
`docs/superpowers/specs/2026-11-16-pr81-held-error.md` (addendum A). Tests: `packages/runner/tests/pr81-held-error.test.ts`.
