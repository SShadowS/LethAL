**Found during R307 option (3) (throw-site table, 2026-10-03), measured the same day.**
`maskAlNonCode` (`packages/engine/src/ast/mask.ts`) builds its output with `Array.from(source)`,
which has one element per CODE POINT, but scans `source` and blanks `out[k]` by UTF-16 index. A
character outside the Basic Multilingual Plane (an emoji, some CJK) is two UTF-16 units and one
code point, so every such character shifts all later blanking one place to the left.

Measured on this branch with a scratch probe (no repo edit):

- `"x := '😀'; // note\n..."` (both policies): the comment's first `/` survives the mask.
- `"// 😀😀\n/* a */ codeunit 5 Foo\n"` (both policies): output is `" *       odeunit 5 Foo"`; the
  `c` of `codeunit` is blanked and a stray `*` survives. The object header no longer matches, which
  is the silent header loss R79/R80 exist to prevent: in discovery (`blankStringContents: true`) the
  object vanishes, in schemata attribution (`false`) it can become a wrong `no-header` refusal.
- `"x := '😀abc';\n..."` with `blankStringContents: true`: output is ONE character shorter than the
  input, so every offset after it is off by one for any caller that maps masked offsets back to the
  source.

AL source files are UTF-8 and may contain emoji in comments and string literals, so a real project
can hit this. R80's 717-file equality measurement would not have seen it unless one of those files
held a non-BMP character.

**To close.** Index by UTF-16 unit throughout (e.g. `source.split("")`, or blank a surrogate pair
as two spaces so the output keeps `source.length` and every offset), and add tests that pin output
length equal to input length and a header after a commented emoji still found. Red-check each test
against the current implementation. Re-run R80's equality check on the corpus to show only
non-BMP-containing files change.

**Closed 2026-10-03.** Fix and IDENTITY_SCHEME 5 -> 6 in cd6e14e2. Scope of the key move: only
`codeunitName` is in the identity tuple (`objectType` is not), and it can move in ANY file holding a
non-BMP character anywhere before a later comment or blanked string, in code, a quoted name, a
comment or a string, in a file of one object or several. The run-001 review measured a phantom
`codeunit 51` in a ONE-object file whose quoted name held 35 emoji; that shape is now a test.

wrong codeunit, and the id-collision scan no longer misses a real id or reports a phantom one. R80's corpus re-run (717 files, Continia Document Output Cloud + Test) was NOT done.
