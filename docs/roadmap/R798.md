**Evidence:** `/coord/handoff/R-798/measure.md`, A/B runs `/coord/handoff/R-798/ab`, `ab2`, `ab3` and
`/coord/handoff/R-798/r790-ab/`. Related: [[R790]], [[R800]].

**Measured (D1, R790 on, against before).** deploy grew 7.6 s to 10.9 s. About 55-60% is alc running slower beside the
speculative al-runner call (+1.5 to +2 s; filed as [[R800]]); about 30% is extra work before alc starts (the `alc-src`
copy 0.54 s, the sync `boundKey` 0.26 s, small walks); about 0.2 s is extra work after alc. Hashing itself is not the
problem. The call saves a 2.6 s baseline, so R790 nets 0.6-1 s at best on a quiet D1.

**Tried.** `nice` plus a reorder (alc started first), as A/B runs ab2 and ab3 (three before/after pairs each, load
3-9): no clear gain.

**Ruling (orchestrator): (c), no code for the nice or the reorder.**

**What R-798 shipped.** R790's speculative baseline is OFF by default and opt-in only; there is no auto-enable.
- Option: `speculateBaseline` on the backend config (internal, not a user config key).
- Env: `LETHAL_V3_SPECULATE_BASELINE=1` (`SPECULATE_BASELINE_ENV`), read at construction. Unset or empty is off. Any
  other value throws `al-runner-v3-speculate-baseline-refused`.
- Every R790 guard is unchanged when on.
- The A/B that decided it is in [[R790]] (section "R-798").
