**Found by the code lane while building R353's live driver (2026-09-30).** `AlRunnerBackend`
creates one `lethal-alrunner-cov-*` directory in the system temp folder for its `--coverage-out`
Cobertura files, on the first run that reads coverage. `close()` does not remove it. Every session
that reads al-runner coverage therefore leaves one directory, holding one Cobertura file per
one-shot invocation, behind in temp. R353's scratch driver deleted the directories it saw; nothing
in the product does.

**Size.** Small per session (one XML file per al-runner call), but unbounded over many sessions,
and on a shared CI agent it never shrinks.

**To close.** Remove the directory in `close()` (and on a failed `deploy()` path if one exists),
with a unit test that a backend which read coverage leaves no `lethal-alrunner-cov-*` directory
after `close()`, red-checked by removing the cleanup.

**Closed 2026-09-30 (0924cd93).** Root cause: `coverageOutPath()` creates the directory with `mkdtemp` on the
first coverage run, and `close()` only closed the transport and the server. Every Cobertura file is parsed inside
`run()`, so nothing reads the directory after `close()`. `close()` now removes it in a `finally` (rm recursive,
force, maxRetries 3, retryDelay 100, as `deploy()` does) and clears the field, so it also runs when the transport
close throws. `cli.ts` calls `backend.close()` in its cleanup `finally`, and the orchestrator closes worker
backends the same way, so a failed run or deploy after the directory exists still reaches it.

Tests (`al-runner-backend.test.ts`, R356 block): a backend that read coverage has its exact scratch path gone after
`close()` (and a second `close()` is harmless); a run whose spawn throws after the directory was made does not leak
it. Both were RED before the fix; with the cleanup removed both go red again; restored, 47 pass.

Other al-runner temp directories: `lethal-alrunner-canary-*` and `lethal-alrunner-contract-*` are both removed in
a `finally` (with the same retry), and the server/daemon client and resource selector create none. Measured today
under the system temp folder, NOT deleted: `lethal-alrunner-cov-*` 682 directories, 22,817,520 bytes;
`lethal-alrunner-canary-*` 3,369 directories, 4,600,068 bytes; `lethal-alrunner-contract-*` 91 directories,
107,100 bytes. The cov count includes leftovers of unit tests and killed sessions. The canary count is large despite
its `finally`; likely killed processes or test runs with a stubbed `rm`, not investigated here.
