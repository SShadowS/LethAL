**Found by the R-214 lane (lethal-preproc), 2026-10-01.** Plan: `docs/superpowers/plans/2026-09-29-R-214-symbol-aware-site-enumeration.md`. Pre-commitment: `docs/superpowers/specs/2026-09-29-r214-precommitment.md`.

**What happens.** Some analyses read a whole member, not a site: the write-transaction tag and the hang tag. They read the text and tree of the member including arms the build compiles out, so a compiled-out `Commit` or loop can tag a member the build never runs that way. R214 drops sites in such arms but did not touch these analyses.

**What would close it.** Make each analysis skip nodes in an inactive range (the ranges are already computed by `evaluateArms`), then add a repro per analysis.

**Closed 2026-10-02 (1d9cbe64, a6ce4d40). Plan r3: `docs/superpowers/plans/2026-10-02-R-378-member-wide-inactive-arms.md`.**
- **Arms once, shared.** `generateMutationSet` evaluates every parsed file's arms once, before the context is built, and passes the map to `buildSemanticContext`. `SemanticContext.armOf(node)` answers `active`, `inactive` or `undecided`. It throws for a tree the map does not hold. A context built without a map has no `armOf`, and callers read that as active. The R214 site loop reads the same map.
- **Three tags fixed.** Each skips nodes the build compiles out:
  - `write-txn-codeunit-run` (`remove-commit`);
  - `run-trigger-skipped-insert` (`swap-modify-flag` on `Insert(true)`). The primary key is the first COMPILED key;
  - `run-trigger-forced` (`swap-modify-flag` forward).
- **Uncertainty keeps a tag.**
  - A receiver table whose file is undecided keeps both trigger tags.
  - A compiled key with no readable field list keeps `run-trigger-skipped-insert`.
  - A table with no compiled `OnInsert` gets no skipped-insert tag, as before. The corpus check caught 21 BaseApp sites on a table with no keys and no `OnInsert`, where an earlier ordering tagged them.
- **Tests.** `packages/runner/tests/r378-member-wide-arms.test.ts` checks both builds for every row, after first asserting that the mutant exists, plus the undecided controls (resolved table, `evaluateArms` undecided, and the same table without the directive untagged). Each guard is red-checked.
- **Measured (§4).** `scripts/r214-capture.ts` on DC, System Application, Business Foundation and BaseApp, sets S0 and S1, master b1bc7e2e against the branch:
  - 0 mutants gone, 0 appeared, 0 identity keys or ordinals moved, 0 `plat=` and 0 `hang=` changes;
  - peak memory 84% to 106% of master's;
  - so no `IDENTITY_SCHEME` bump.
  - **This is MEASURED on those four corpora, not proven.** The forced-trigger lookup can still drop a forward `swap-modify-flag` mutant, and so renumber a same-tuple twin in the same member, on a project where every direct table-level trigger of that name sits in an arm the build compiles out. No such trigger exists in the four corpora, and the grammar wraps an object-level `#if` trigger so that it is not a direct member (the "A3-gone" pin).
  - Every pinned `fixtures/r214/expected` capture, including `p11-tier2`, is unchanged. No gate fixture is affected.
- **The hang tag was not changed.** It walks ancestor loops only, and no shape was found where an INACTIVE condition operand reaches it. That is a measured limit, not an invariant. The ACTIVE-arm miss found on the way is R402.
