**Found 2026-10-05 by R464's final code review** (minors 2 and 3; review kept in the coord handoff
for R-464, not in the repo).

**What.** Two record scopes that `recordScopesAt` in `packages/engine/src/semantic/receiver.ts`
does not list, so the prefix proof behind `validate-to-assign`'s bare form never checks them:
1. **A reportextension's `add(X)`.** The base dataitem `X` behind it is not added as a scope
   (`types.ts` does treat `dataset_section` as one). If `X`'s table, from a dependency, has a field
   named like the added dataitem, the emitted `<dataitem>.F := V` names that field and does not
   compile.
2. **A namespace-qualified tableextension base** (`extends Microsoft.Sales.Customer`). The
   `mayHaveMember` and `extendsIt` checks compare the base name as written, so such an extension
   is skipped and its fields and procedures are not checked against the prefix. The worst case is
   the same: a mutant that does not compile.

**Why it is a gap, not a correctness risk.** Both cases fail at compile time, so they cost a site
(bisection drops the mutant); neither can produce a wrong verdict. Neither shape was measured in the
R464 corpora.

**Closing it.** Add the `add(X)` base dataitem to `recordScopesAt`; match a tableextension's base by
its last name segment (or through the symbol index's namespace resolution). Each with a red test,
then an exact site diff on BaseApp and CDO.

**Ruling, 2026-10-05 (R-478).** Closed without a code change: neither shape can emit a mutant today,
and neither occurs in BC.History, CDO, DC or DO. Probes: `/coord/handoff/R-478/tools/probe.ts`
(generate, splice each `validate-to-assign` mutant, compile with `alc`), `why.ts` (the scopes and
guards at each call) and `ext-parse.ts` (how each base spelling is read).

1. **Reportextension.** First a correction: `add(X)` adds only columns (`alc` AL0104 on a dataitem
   inside it). A nested dataitem comes from `addfirst(X)` / `addlast(X)`, and the missing scope is
   the same there. But `bareReceiverText`'s only caller is `validate-to-assign`, which runs it only
   after `claimsRecordMethod` claims the call, and that refuses every call inside a reportextension:
   `enclosingObject` reads `OBJECT_KINDS`, which does not list `reportextension`. Probe shape 1 (an
   `addlast(Head)` dataitem `Extra` whose base table has a field `Extra`) emits nothing, and so does
   its control without the field. Corpus: 25 reportextensions, all in BC.History; 8 have an `add`
   form, and none holds a bare `Validate(`.
   **If reportextensions are ever claimed**, add the `addfirst`/`addlast` base dataitem to
   `recordScopesAt` (with an unknown table, so the proof refuses) in the same change.
2. **Namespace-qualified base.** The grammar does not parse it (filed as [[R483]]), but the symbol
   table still records the base as its last segment (`R478 NT`), so `extendsIt` matches; the object
   is also in `unparsedObjects`, which `mayHaveMember` reads too. Probe shape 2 (a qualified
   extension declaring a field `Rec`) emits no mutant; without the extension, or without the
   namespace, the same site emits `Rec.Amount := 1`, and `alc` compiles it. Corpus: 0 qualified
   bases among 508 files with a tableextension.
