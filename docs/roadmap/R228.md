**Found by reading, while threading R227's line filter through the same path.** `runSession`
passes `exclude` to `sessionFingerprint` (orchestrator.ts, next to the comment "R221: in the
fingerprint for exactly the reason `only` is"), but `SessionFingerprintInput` has no `exclude`
field and `sessionFingerprint`'s canonical object in `packages/runner/src/resume.ts` never reads
one. The key arrives through a conditional spread, so TypeScript's excess-property check does not
fire, and the value is silently dropped.

**Consequence:** two runs that differ only in `--exclude` (or the config's `exclude`) get the same
fingerprint, so `--resume` accepts one as the continuation of the other and reports verdicts from a
different mutant set as this run's own measurement. The comment claims the opposite.

**Fix shape:** add `exclude` to `SessionFingerprintInput` and to the canonical object as a
CONDITIONAL key, exactly as R127 did for `operators`, so runs recorded without exclusions keep
their digest. Then red-check: a test asserting two fingerprints differ by `exclude` alone.

Not measured live.
