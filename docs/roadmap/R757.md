**Seen on CI run 40164361934 (2026-10-25, branch `lethal/r756`, Windows `check` job).** The R622 watchdog test
"isChildOf: a live child of this process is one; this process and a dead child are not" in `scripts/verify.test.ts`
timed out at its 30 s limit. Every other test passed (10877 pass / 118 skip / 1 fail), and the `unit-linux` job was
green.
- The commit changed only a warning string and a test comment; the commit before it passed the same job (run
  40164070664). A re-run of the failed job passed. So it is a timing flake, not a defect in the change.
- The test makes four `isChildOf` calls, each a PowerShell/CIM query on Windows; its own comment says "1 to 3 s each
  when cold". Four cold calls plus a spawn on a slow runner can reach 30 s.
- A red CI run emails the owner, so a flake costs attention every time it fires.

**To close.** Make the Windows cost bounded: one process query for all four checks (a seam that reads the process
table once), or a per-test timeout that matches four cold CIM calls with margin, as R726 did for the per-test default.
Keep the reused-pid direction tested. Prove it with a few Windows CI runs.

**Built (2026-10-25, not yet proven on Windows CI).** `scripts/verify.ts` gained `parentTable(pids)`, which reads the
OS once for all the pids (Linux: `/proc`, zombies left out; Windows: ONE PowerShell `Get-CimInstance` call), and
`parseCimParents(stdout)`, the pure parser of its output. `isChildOf` is now `parentTable([pid]).get(pid) === parent`,
so `execWatched` is unchanged. The test reads the table once for the child and this process (the child's parent is
this process; this process's parent and the child's own pid are not the child's parent), then makes two `isChildOf`
calls (live wrong parent, dead child): three PowerShell calls on Windows instead of four, the 30 s limit kept. Unit
tests for `parseCimParents` run on every OS. Red checks: empty table, `isChildOf` ignoring the parent, a table that
maps every pid to this process, and a swapped-column or loose parser each turn the specific test red. Still to do:
re-run the Windows `check` job twice with no timeout.
