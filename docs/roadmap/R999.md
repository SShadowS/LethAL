Split from R979 by coord task R-968 (2026-11-14). Related: [[R979]], [[R969]] (batched into the same control-app bump).

**What happens.** On BC, LethAL's injected Mutation Selector (`emitMutationSelector`) delegates `Active` and `Reached` to LethAL
Control's codeunit "LC Control State". R979 gave the selector `InherentPermissions = X`, but a codeunit that has the property and
calls another codeunit that lacks it is still denied under an exact permission set (`Permissions Mock.SetExactPermissionSet`):
measured on bc1 (BC 28.4 W1) with an invented probe, within one app (`/coord/handoff/R-968/state.md`, case C). LC Control State
declares no `InherentPermissions` (its tables do: RIMD), so on bcdev a test that narrows to an exact set fails at the first guard,
for LethAL's sake. al-runner runs the static or resource selector, which calls nothing, so v3 is not affected.

**Fix.** `InherentPermissions = X;` on "LC Control State" (and on any other control codeunit the target's injected code calls), in
the batched control-app version bump (kraken q-20261114T110356-6ee35c8d), then republish to bc1-bc3 and re-prove their gates.
Measure the cross-app call itself once the bump is in (the probe only had one app).

**Built (coord R-990, 2026-11-14).** `InherentPermissions = X;` on "LC Control State" in LethAL Control 1.0.0.26. It is the only
control codeunit the injected code calls (`selector.ts`: the delegating selector, the register-install path and the reach latch all
call "LC Control State"). Compiled clean with alc 18.1.43. The cross-app measurement waits for the republish.
