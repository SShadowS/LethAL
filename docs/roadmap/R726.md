**Found 2026-10-24 (R-724 part 2).** CI run 40105067954 (attempt 1, Windows `check`) failed 27 tests, all in
`packages/runner/tests/resume.test.ts` (R389 16, R512 8, R514 3). Each said `this test timed out after 5000ms`. The
rerun passed. Linux passed. The tests took 205 s that run against 113 s on the rerun. No lock or EBUSY line was found.

**Cause.** Not a test bug. Locally the slowest test in that file takes under 0.1 s (244 tests in about 5 s). Verify
keeps bun's 5 s default on Windows, because `/proc/pressure` cannot be read there. A slow runner stalled a few tests
past 5 s. The failure text was only in the `verify-logs` artifact, not the console.

**Done.**
- `resume.test.ts` sets `setDefaultTimeout(30_000)`, with a comment citing this item. Verify's global default is unchanged.
- `scripts/verify.ts` (`failureDetails`, used by `testStep`) now prints each failing test's error text (up to 12 lines, each
  cut to 300 characters) under its `(fail)` line on the console. `scripts/verify.test.ts` pins it.
