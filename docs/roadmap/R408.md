**Found by the R-402 lane (lethal-preproc), 2026-10-02.** Plan: `docs/superpowers/plans/2026-10-02-R-402-hang-tag-active-arm-operands.md` (r3).

**What happens.** In this code:

```al
repeat
    A := A + 1;
until (A > 10)
#if LETHALX
    or (B > 5)
#endif
;
```

the `#if` arm continues the `until` condition. The grammar (tree-sitter-al 4.4.1) cannot attach such a tail to `repeat_statement`. It parses the tail as the NEXT statement instead: a statement-level `preproc_conditional_statement` holding a `call_expression` named `or`. `void-method-call` and the comparison operators then claim the bogus call, and the dispatch emits an `if`/`else` where the source needs a condition continuation.

Measured on master 0ef6652f with `scripts/r402-shape-sweep.ts`: the unmutated source compiles under every build, but the INSTRUMENTED artifact fails alc under `[LETHALX]` (`AL0111: Semicolon expected`, or `AL0104: 'end' expected` for a nested arm). That takes down every mutant in the batch. The same holds for an empty `#else`, a nested `#if`, a comment before the `#if`, and an `#elif` arm. A `while` condition's tail does not have the problem: it parses as a `preproc_conditional_expression_tail` beside `condition`.

**What R402 did instead.** `evaluateArms` (`packages/engine/src/ast/preproc-arms.ts`, `continuationRefusal`) refuses any file where a statement-level `#if` continues an unterminated statement. The file is reported `preproc-undecided` with the reason `directive-continues-statement at line N`, so it is still compiled and published, but never mutated. The rule is separator-aware. It admits:
- a statement followed by `;`, or one whose last leaf is `;`;
- empty, trivia-only and `;`-first arms;
- `#if` blocks after keywords and after other `#if` blocks.

Those controls compile, and they are pinned in `packages/runner/tests/r402-hang-active-arm.test.ts`.

**Reach (R-308 measure, 2026-10-23).** Files refused for `directive-continues-statement`: BaseApp 0 of 9,995, other BC.History 0 of 9,512, CDO 0 of 677, DC 0 of 1,773, DO 0 of 814. The detector refuses a made-up R408 shape by name. The grammar defect still reproduces on tree-sitter-al 4.4.1 (the `#if` tail after `until` becomes a sibling `preproc_conditional_statement`). This item stays open, upstream-only: no LethAL change. Filed upstream 2026-10-25 by the owner: https://github.com/SShadowS/tree-sitter-al/issues/38 (from the draft `/coord/handoff/R-308/upstream-r408.md`).

**What would close it.** A grammar that owns the tail: the condition of `repeat_statement` (and of any other statement whose last token is an expression) can take a `preproc_conditional_expression_tail`, as `while_statement`'s already does. Then remove the refusal, and pin the S4 shapes as mutated, with the hang tag reading the tail and the artifact compiling. This is an upstream change to tree-sitter-al.

**Fixed for a tail that ends the condition, checked 2026-11-06 (coord task R-835).** On tree-sitter-al 4.5.0 ([[R796]]) that tail is a `preproc_conditional_expression_tail` of `repeat_statement`, with no statement-level `#if` and no parse error. [[R796]] already admitted these shapes and pinned the hang refusal reading the tail by arm (`r402-hang-active-arm.test.ts`). The full sweep is [[R801]]'s: 212 cases, 208 artifacts, 4 refused, 0 problems. A re-check on this head compiled 24 of 24 cases on `s4_repeat_tail`, `s4b`, `s4c`, `s4d`, `c8_s4_elif` and `c7b`; the full sweep timed out under load, so that re-check is partial.

**Not everything is fixed: a tail in the MIDDLE of a `repeat` condition, followed by more condition, is [[R841]].** That one fails alc in the artifact and passes the refusal.

**The refusal stays, on purpose.** `continuationRefusal` is not dead. `if Flag then Bar()` `#if X` `;` `#else` `else Foo(1);` `#endif` parses clean, is refused by name, and its source compiles. It is now fixture `c9_else_split_by_arm`, which pins the refusal through `evaluateArms`; only a hand-built tree pinned it before. Upstream issue #38 can be closed for the `repeat` case.
