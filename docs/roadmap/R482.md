**Ruling, 2026-10-05 (R-482).** Closed without a code change. The evidence:

- **The message, recovered.** The failing run's log (`/tmp/lethal-verify-test-1791238699794.log`,
  22:18:19 UTC) shows the test hit R428's 15 s per-test starvation guard: `timed out after 15000ms`,
  at 15005 ms. It was the only failure in that run. Alone, the whole file runs in 1.0 to 1.3 s.
- **The machine was starved, not the test.** Two other full verify runs started within two minutes
  of that one (logs `...1791238711798` and `...1791238805504`). Each also had exactly one timeout,
  each in a DIFFERENT test: two `runFromCli` preprocessor-symbol tests, at 18.5 s and 6.2 s against a
  5 s guard. Three suites timing out on three unrelated tests at the same time points at the shared
  CPU, not at any one test's code.
- **Not shared temp state.** The test preload gives every bun process its own private temp
  directory, so one run's `afterAll` sweep of `lethal-r214-hist-*` cannot reach another run's files.
  That rules out the R449 family on this platform.
- **Not reproducible.** 20 runs of the file while two copies of the runner suite loaded the host
  (load average 5.7 to 9.4 on 32 cores): 0 failures. Three full runner suites at once: 0 failures,
  4559 tests each. The repro script is `/coord/handoff/R-482/tools/repro.sh`.

No timeout was raised and nothing was skipped. If it recurs, capture the log first: a failure
OUTSIDE an overlap with another full verify run would reopen this item.
