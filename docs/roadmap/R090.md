**A single file whose instrumented form exceeds the publish budget cannot be measured at all, and `--max-guards-per-batch` cannot rescue it.** R44 shipped the flag and correctly reports an oversized batch rather than dropping it, but **splitting is at FILE granularity** — so a file that alone exceeds the budget becomes its own oversized batch and the flag is powerless. **Measured 2026-08-05** on Continia environment `f5f11bf2`, DO pinned at `5f2a71d3`, one file per publish: **176 guards publish (36–97 s)** · **229 publish** · **331 TIMES OUT** · **660 TIMES OUT**. The failure is `continia publish` returning `{"success": false, "message": "The operation timed out."}`, after which the deployment verifier correctly reports an artifact identity mismatch. So the hosted ceiling sits between **229 and 331 guards in one file**, and `Codeunit 6175296 CDO E-Mail Template Management` (660 sites) is **unmeasurable on a hosted environment** — not slow, not partial: it cannot be published. This bounds what LethAL can say about a real app far more sharply than R40's object-kind gap: DO has 85 codeunits, and the largest are exactly the ones worth mutating. **What is missing is not a fix but a REFUSAL**: nothing warns before the run that a file is over the ceiling, so the user pays generate + instrument + compile + publish before learning it was impossible. A pre-flight check against a configurable per-file guard ceiling would cost nothing and fail in milliseconds.
