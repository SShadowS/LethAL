listed that no container lane can re-record.

**What.** `packages/runner/itest/envtool.baseline.json` predates [[R556]]: a bare array with no `identityScheme` and no
`mutatedTextSha256`. `itest:envtool` still compares it per mutant and passes on matching verdicts, but prints that a
mutant changed under an unchanged key is UNVERIFIED. The env tool (`continia.exe`) runs only on the Windows host, so
the kraken lanes cannot run the gate.

**Also due on the same run:** the gate page (`docs/gates/envtool.md`) says the baseline predates R197, so the next live
run should expect differences in `killingTest` only. Both changes go into ONE re-record.

**To close (host only).** Use the R332 procedure, after a pre-commitment that names both expected changes (the scheme
and hashes added, and any `killingTest`-only differences, each confirmed against `itest:bcdev` on the same day):
1. delete the file;
2. run `itest:envtool` once with `LETHAL_ITEST_RECORD_BASELINE=envtool.baseline.json` (it exits 3);
3. re-run without the variable and confirm a pass with no UNVERIFIED line;
4. review the diff: verdicts byte-identical, only `identityScheme`, the hashes and the pre-committed `killingTest`
   changes;
5. update the page, and commit.

The gate refuses RECORD mode while `UNVERIFIED_MOVES` is non-empty (CLAUDE.md).
