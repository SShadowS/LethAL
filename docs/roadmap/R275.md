**What.** C02-07 documents a gap recipe, the one `lethal verify` line a gap's `artifactId` and
`gapId` fill in (`lethal verify --db <project>/lethal.sqlite --artifact <artifactId> --survivors
<gapId> --tests <tests-dir>`), and C02-09 gives every `ExplainGap` both inputs. But nothing in
`explain`'s own output assembles and prints that line: a user with a gap in hand still has to know
the recipe exists and build the command by hand.

**Who hits it.** Anyone using `explain` to go straight from a gap to a `verify` run: today that is a
two-step lookup (find the recipe in the docs, fill it in) rather than a line to copy.

**Evidence.** C02-07's recipe line.

**What would close it.** Render the filled-in recipe line as part of a gap's printed output (or as a
field on `ExplainGap`), using the same `<project>`/`<tests-dir>` the CLI already knows for the run.

**Found by.** C02-09's own review of GitHub issue #11 (point 6), filed as a follow-up rather than
folded into this task's scope.
