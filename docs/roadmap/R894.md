Filed from SShadowS/LethAL#28 (owner, 2026-11-09). Related: [[R826]], [[R671]].

**What.** On bcdev, LethAL runs one mutant at a time per BC server. The active mutant is a single row in the control
app's `LC Mutation Active` table (shared by every company), and the control app holds one lease per server. So a
suite whose survivors are expensive takes as long as the sum of their covering tests. #28's reporter measured it:
killed mutants took a median of 0.4 s, but each survivor ran every test that reached it (80 to 192 tests, about
1,000 to 1,200 s each), so 1,022 mutants were estimated at about 45 hours.

**Why not parallel sessions on one server.** Tests in different sessions on the same database interfere even with
test isolation: an open test transaction holds locks that another session's test waits on or deadlocks with
(number series, ledger entries, setup records), some BC reads can see another session's uncommitted rows, and
data shared across companies, isolated storage and committed data are shared too. That risks false kills and
false survivals. Separate companies in one database only half help.

**The idea.** Split one run's mutants (or a mutant's tests) across several BC servers, each with its own
database, the target published to each, and one store and report at the end. Verdicts must equal a one-server run
per mutant (the chunked gate's rule: a cost knob, never a semantic one).

**Questions to answer first.** How the mutants are split (by cost, from the baseline's per-test times and each
mutant's covering tests); what happens when one server hangs or is quarantined mid-run; how `--resume` and history
work across servers; whether each server needs the same app versions and data (a proof per server, as the gates
require).

**Not started.** The owner deferred it on 2026-11-09. Coord task R-892 measures where #28's time goes first.

**What R-892 found in the code (2026-11-09).** One server, one mutant at a time, is enforced: `runSession` refuses `--workers` above
1 for bcdev, because the control app's single `LC Mutation Active` row is not lease-protected per mutant, so two sessions racing
activate and run could credit a verdict to the wrong mutant (the "5C-B" note at that refusal). Several servers sidestep that row (one
row per server), which is why this item, and not parallel sessions, is the route. The measured cost it would cut: survivors took 85% of
the mutant time on PaymentPractices (al-runner v3, one-shot), and #28's reporter sees the same shape on BC. Evidence:
`/coord/handoff/R-892/result.md`. A time cap with a "not decided" verdict is the other lever: [[R898]].
