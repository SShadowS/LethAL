Found by PR-34 (lethal-bugs, 2026-11-15; `/coord/handoff/PR-34/bc/run.md`), a bcdev run on a copy of System Application's Filter
Tokens module on bc2 (BC 28.4 W1 on Linux).

**The shape.** In `FilterTokensImpl`, a `while Length <> 0 do` loop advances only when the local procedure `ReadUntilCharacter`
moves its `var Position` argument forward. LethAL refuses deleting the call (R830: a call the loop's progress may rest on), and that
site was hang-refused. But `lethal.empty-block` on `ReadUntilCharacter`'s own body (mutant M0332) has the same effect from the
callee's side, and nothing refused it. al-runner v3 scored it timeout-killed. The pre-commitment meant to leave it out by line
scope, but `--lines` keeps a mutant that touches an allowed line, and its span did.

**What happened on BC.** The run had no `--stop-hung-sessions` (opt-in, default off, by design: R053, R191), so the control app's
stop was never asked for. LethAL's own 180 s timer aborted RunMutantMany ("our timer, not BC's stop"), quarantined the test
(in-flight-unknown) and left the control app's lease orphaned. The doctor's recovery is an NST restart, then
`lethal force-reset-lease`, so it needed the owner (kraken q-20261115T185041-55e86d96). This is the outcome `itest:hang`'s OFF leg
produces on purpose. **The stop did not fail**: it was not on. `itest:hang` covers the stop; it does not cover this refusal gap,
because its fixture has no callee-side shape.

**Why it matters.** A real project's helper that steps a caller's loop through a `var` parameter, emptied by `empty-block` (or by
removing its assignment, the R196 operators inside the callee), can strand a server for anyone running without
`--stop-hung-sessions`.

**Possible fix** (not designed): extend R830's analysis one step across a call. When a loop's progress rests on a `var` argument of
a call to a procedure in the same object, treat the writes to that parameter inside the callee (and an `empty-block` of its body)
as hang-capable sites, as R196 does for the loop's own body.

**To close.** An offline test with the invented shape (a loop stepped only by a local procedure's `var` write) shows the callee's
`empty-block` and its `remove-assignment` sites hang-refused, and red-checks when the cross-call step is removed.
