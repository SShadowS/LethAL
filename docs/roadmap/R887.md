Found by coord task R-881 (PaymentPractices, BC.History, on al-runner v3 edge-05d692e5e). Evidence: `/coord/handoff/R-881/`
(`pp.*`, `pp1.*`, `result.md`).

**What.** On BC, LethAL publishes the instrumented target once, with no mutant set, so its install code runs under NONE. Mutants are
switched on only for the tests. al-runner v3 runs the target's install code inside each run, and that code reads LethAL's selector
resource like any other code. So the mutant chosen for the run is already active while install runs.

**Seen.**
1. One-shot (`pp1`): 6 mutants in table code that the app's install routine reaches are scored `error`: "install routine codeunit ...
   OnInstallAppPerCompany could not run: failed (behaviour not pinned): <the mutated check's error>". On BC those mutants would run
   their tests normally.
2. The serve-entries default (`pp`, round 1): the warm-up refused every entry with "the install code read a resource file, and an entry
   with resource files of its own would need an install baseline of its own". `batchRefusalReason` turns that into
   `al-runner-v3-entries-batch-refused`, and the run stops in the mutant phase. R786's one-shot fallback does not apply, because the
   one-shot baseline held passing rows there (31 of 36), not the same refusal. Setting `"transport": "one-shot"` runs the app.

**The risk not yet measured.** A mutant in install-reached code that does not make install fail can change the rows install creates.
Tests then run on data BC would never have, and a kill or a survival can differ from BC's. How many of `pp1`'s 310 kills are of this kind
is not measured.

**Directions (not chosen).** The emitted selector could answer NONE while the session runs install or upgrade code
(`GetExecutionContext()`), which BC also passes through unchanged; that changes emitted AL for every backend, so the frozen gates' goldens
move and it needs a pre-commitment. Or al-runner could take resources that apply only after install, an upstream request. Either fix
should also let serve-entries keep its daemon.
