**Filed 2026-10-25 by lethal-preproc, from coord task R-790.** Related: [[R586]], [[R769]], [[R780]], [[R734]].

**What.** The v3 backend proves every batch with alc before al-runner runs it (R586 plan §3; R769: al-runner runs some AL
that alc rejects). On D1 at 6aa7700c (`/coord/handoff/final-timing/6aa7700c/timing.md`, D1 #2), deploy is 7.6 s, of
which the alc batch compile is 6.2 s. The baseline takes 2.6 s and the mutant loop 6.1 s, in a wall of 20.8 s. The
owner's idea: run alc at the same time as the tests, and throw the tests' results away if alc rejects. That could
save about 6 s on D1. The gift card's alc takes 0.7 s.

**Constraints found reading the code (2026-10-25).**
- **The error's path.** alc's rejection (`AlcCompileError`) must still come out of `deploy()`: the orchestrator's
  deploy step routes it to R734's redeploy and to bisection, which reads ONLY that error as "subset does not
  compile". If it came out of a later `run()`, it would be scored as a test failure instead.
- **Results are written at once.** The orchestrator writes each baseline and mutant result to the store, and emits
  its events, as soon as the backend returns it (`recordTestResult`, `recordBaselineSnapshot`, `recordMutant`).
  "No result committed before alc joins" therefore means either:
  - (A1) the backend runs work SPECULATIVELY inside `deploy()` while alc compiles, keeps the results private, and
    serves them after alc passes; or
  - (A2) the shared orchestrator buffers every write and event from the deploy to the join. That is the path bcdev
    uses too.
- **alc writes into the test dir.** With `features: ["TranslationFile"]`, real alc writes `Translations/<App>.g.xlf`
  during the compile (R780). An al-runner run that reads the test dir at the same time could read a half-written
  file, and the proof (read after the compile) would not describe what that run read. Any overlap must compile a
  COPY of the test dir, or prove that alc writes nothing there.

**To close.** The orchestrator rules on A1 or A2 (see the coord task). Then build it with red tests per direction,
pass the full v3 gate per mutant, and add a timing receipt from `scripts/v3-timing.ts`.
