title: "lethal verify cannot see an edit to a helper, handler or library procedure a test calls, because the per-test digest covers the test method only"
section: "product-gaps"
status: "done (ecf0f1d1, 4ee63129)"

**What.** R-278 and R258 made `lethal verify` treat a test as new when its source digest differs
from the one the source run recorded (`packages/runner/src/test-digest.ts`). The digest covers the
test method's own span only: its attributes and its procedure. An edit to a helper procedure in the
same codeunit, to a handler function named by `[HandlerFunctions]`, or to a library codeunit the
test calls leaves the digest unchanged. Verify then treats the test as old: a covering one skips the
new-test checks (the double freshness-checked unmutated run and the flakiness gate), and a
non-covering one is not selected at all. An agent that strengthens a shared assertion helper to kill
a survivor sees verify ignore the change for every test that does not also change.

**Why it was not built with R-278.** A reachable-set digest (every procedure a test can reach,
which `testpage-scan.ts` already walks) would close it, but an edit to a helper that many tests
share would then make all of them new, and every new test joins every survivor's request. That cost
needs measuring on a real suite before it is chosen.

**Evidence.** `testDigestsOfSources` in `packages/runner/src/test-digest.ts` (the span), the
reachable-call walk in `packages/runner/src/testpage-scan.ts`, and the plan
`docs/superpowers/plans/2026-09-30-R-278-verify-edited-tests.md` section 5.

**What would close it.** Digest each test over its reachable test-app procedures (the walk
`scanTestPageTests` already does), after measuring how many tests one shared-helper edit turns new
on a real suite.

**Closed by R-371 (2026-10-01).** The digest (`v2:`) now covers every test-app procedure and object
part a test can reach, its handlers, every event-subscriber codeunit and what those reach, the
dependency fingerprint and the build inputs. An edge the walk cannot follow adds the whole test-app
source, so an unresolved edge can only make a test new. Verify refuses a v1 digest once
(`source-predates-verify`) and refuses above `--max-new-tests` (`too-many-new-tests`). Two limits
are filed: R384 (the per-survivor filter that large suites need) and R385 (Microsoft dependencies
by declared version).
