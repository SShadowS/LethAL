Found by running the PUBLISHED Linux binary in a stock container (`scripts/clean-room.sh`), which is
the closest thing to a stranger this repository had until now.

`lethal doctor --config <path>` is the first command the quick start tells a new user to run. Point
it at a path that does not exist yet — a typo, or simply running it before writing the config — and
the released binary answered:

```
Error: cannot read config file at /tmp/nope.json: ENOENT: no such file or directory, open '/tmp/nope.json'
    at loadLethalConfigFile (/$bunfs/root/lethal-0.1.0-alpha.2-linux-x64:34129:20)
    at async doctorFromCli (/$bunfs/root/lethal-0.1.0-alpha.2-linux-x64:34887:48)
    at async main (/$bunfs/root/lethal-0.1.0-alpha.2-linux-x64:35014:31)
    at processTicksAndRejections (native:7:39)
```

The same shape answered `lethal run` with a missing `--tests`, and an unknown subcommand.

**The message was never the problem** — it names the file, and the usage refusals name the flag.
`main`'s catch printed `err.stack` for every error, so a refusal and a crash were typographically
identical. That matters more here than in most tools: the whole product claim is that it fails
loudly and says what to do, and four frames of `/$bunfs/root/...` say "this tool is broken" over the
top of a sentence that says "that file is not there".

**Fixed:** the message by default, the full stack behind `LETHAL_DEBUG=1`, and a printed line saying
where the detail went, because an unexplained absence of detail is its own problem when someone is
filing a bug. Nothing is swallowed, the exit codes do not move, and a non-`Error` throw still prints
verbatim.

`packages/runner/tests/cli-error-rendering.test.ts` drives the real CLI as a subprocess — the thing
under test IS the top-level handler, so calling `main` directly would test the wrong layer. It pins
the absence of `at ` frames on three refusal paths, the presence of the `LETHAL_DEBUG` hint, and
that the flag restores the stack. Red-checked: restoring `err.stack` reddens three of the five.

Evidence: the clean-room run against `lethal-0.1.0-alpha.2-linux-x64`, and the test above. The fix
ships in the next release; the published alpha.2 binary still prints stacks, which is why the
clean-room step for it is version-gated rather than deleted.
