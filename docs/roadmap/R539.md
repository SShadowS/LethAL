**Priority.** Filed 2026-10-09 by the R534 build (plan r2, roadmap item 3). An upstream request;
it costs LethAL lost kills, never a false kill.

**What.** Two gaps in al-runner's output (measured on `2.12.0-main.43f76177`):
1. A pass row's `durationMs` is the test BODY only; the test codeunit's `OnRun` trigger runs under
   the same stop but its time is reported nowhere (66 ms body beside a 4 s OnRun). So [[R534]]
   confirms an OnRun-trigger timeout on the confirm's WALL clock, which on one-shot includes the
   compile and on `--server` the whole suite. Where the budget is twice the baseline wall, that
   confirm is a coin flip and a genuine OnRun hang can come back `timeout-unconfirmed`.
2. `errorKind` (`timeout`, `setup`, `runtime`, ...) is written only by `--server`'s test event. The
   one-shot `--output-json` row has no such field, so LethAL classifies one-shot rows by their
   message text alone.

**Evidence.** `/coord/handoff/R-534/measure.md` sections A, B and "What the source says"
(`TestExecutor.RunOne`, `ServerProtocol.TestEvent`); the onrun branch of the cold confirm in
`runMutantsOnBackend` (`packages/runner/src/orchestrator.ts`).

**To close.** File both upstream. When a build reports the OnRun's time, judge an `onrun` timeout
on body plus OnRun instead of the wall clock; when the one-shot row carries `errorKind`, cross-check
it against the message decode.
