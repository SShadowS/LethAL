**Filed 2026-10-22 by lethal-preproc** during the R-654 inventory (`/coord/handoff/R-654/inventory.md`), and
confirmed by reading the code. Related: [[R565]], [[R654]].

**What.** `cli.ts`'s dry-run call builds `dependencyPackageDirs` from `parsed.backendKind`:
- `"al-runner"` (v2) gets `alRunner.packagesDir`;
- every other kind, `al-runner-v3` included, gets bcdev's `packageCachePathDefault(...)`.

So a v3 dry run lists the Microsoft reports and refusals against bcdev's symbol cache, not against the
folder a real v3 run reads. The refused set it shows can differ from what the real run refuses, and nothing warns.
R565's warning covers only v2.

**Why it matters.** A user who checks a v3 run's scope with `--dry-run` sees a different refused set from what
the run applies. This is a listing gap, not a verdict: the real run is unaffected.

**To close.** Give `al-runner-v3` its own branch (`alRunnerV3.packagesDir`, or say plainly that it has none), with
a test per backend kind. Do it together with [[R654]]: removing v2 rewrites this branch anyway.

**Closed 2026-10-23 (0ea0a076):** `dryRunDependencyPackageDirs` (cli.ts) gives al-runner-v3 `[alRunnerV3.packagesDir]`
as `AlRunnerV3Backend.dependencyPackageDirs` does, or none when the config has none (the real run refuses), with a
test per kind in `r656-dry-run-package-dirs.test.ts`; v2 is retired (R654 S3), and its dry run is refused by name.
