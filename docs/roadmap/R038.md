**The codeunit selector var is anchored before the object's PROPERTIES, so any codeunit that declares one does not compile once instrumented.** `injectSelectorVarIntoObject` (`packages/schemata/src/compile.ts`) anchors at `members[0]` for a codeunit. AL requires object properties (`Permissions`, `Access`, `Subtype`, `SingleInstance`, `EventSubscriberInstance`, `TableNo`, …) BEFORE any `var` section, so `{ var MutationSelector … Permissions = …` makes alc read `Permissions` as a variable name and the parse never recovers. The doc comment's "in a codeunit, `var` before the first member compiles clean" was measured against fixture codeunits, which declare no properties — the table branch already skips section-like members for exactly this class of reason; the codeunit branch needs the same treatment. Measured 2026-07-27 on the real Continia Document Output app (551 `.al`, 162 instrumented): **19 of 162 instrumented files, 246 alc errors, whole-app compile fails ⇒ zero mutants runnable.** Root cause proven, not inferred: hand-reordering the injected `var` below the property in ONE file took that file from 41 errors to 0 (246 → 205 total, 19 → 18 affected files) with nothing else changed.
