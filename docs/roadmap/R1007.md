Found by coord task R-993 (2026-11-14), the serve vs one-shot differential over BC.History (`/coord/handoff/R-993/result.md`),
master 507164ea, al-runner edge-a184cfc79. Related: [[R948]], [[R951]], [[R896]], [[R678]].

**What happens.** In the per-test daemon fill (`fillIsolatedBaseline`), a daemon row that is a named refusal (`notRun`) is read
as `daemon-odd-row`: the answer is not kept, and when that test is a cross-check sample the sample is skipped and replaced. In a
codeunit where most tests are refused, the replacements run out too, the fill ends with "too few clean cross-check samples", and
the session drops the daemon baseline (R948) and runs every codeunit one-shot. Measured with a temporary print of `noteSkip`
(removed): BC.History project 65 (Camera, 3 tests, 1 refused) and project 24 (File Accounts, 28 tests, 16 refused) skip every
refused test as `daemon-odd-row`, and both drop the daemon baseline on every run.

**How often.** 11 of about 180 BC.History serve runs (R-975 sweep 8 of 96, R-993 3 of 80, R-982 0 of 6) dropped the daemon
baseline as "too few clean samples"; none dropped it because the daemon and a fresh process disagreed.

**Why it matters.** Cost only: the dropped fill's rows are never used, so no verdict moves; the session pays a second, one-shot
baseline. Also, the session never says which samples were skipped or why: `sampledSkipped` reaches `daemonBaselineReport()` (read
by the itests) but neither stderr nor the report, so the cause above needed a code edit to see.

**Possible fix (not decided).** Compare a refused daemon row with the fresh process's row like any other (same refusal, same
first line = clean; R678 already treats a refusal as a verdict), instead of skipping it; and print the skip reasons in the drop
warning. A test: a codeunit with refused tests keeps its daemon baseline when daemon and one-shot refuse alike, and drops it by
name when they differ.

**Live prediction (coord PR-04, committed before the run).** BC.History project 65 (Camera), R-993's serve config
(`/coord/handoff/R-993/cfg/65.serve.json`, `--only src/Camera.Codeunit.al`), on the fix's head and al-runner `current`:
- before the fix, R-993's run printed `al-runner-v3-baseline-daemon-dropped: too few clean cross-check samples: 1 of 2`;
- with the fix, the run prints no `al-runner-v3-baseline-daemon-dropped`;
- its baseline outcomes equal R-993's one-shot run (`65.oneshot`) per test.

**Fixed (coord PR-04; split agreed with lethal-code, whose R-998 reads the same refusal helpers, which keep their meaning).**
- In the per-test fill, a refused daemon row of a cross-check sample is compared with the fresh process's row like any other.
- Any other test's refused row is kept only when `serveDaemonReusable` says the daemon may keep that refusal, as on the live path;
  otherwise it is `daemon-odd-row`, as before.
- `compareBaselineAnswers` compares a refusal on notRun plus its first line (R678), since the rest of the text can differ by path.
- The "too few clean cross-check samples" drop names the skipped samples and their reasons.

Tests in `al-runner-v3-entries.test.ts` ("R1007: ..." and the R951 too-few-samples case), each red when its part is reverted
alone, in both directions for the skip rule.

Build review (Opus) fixes:
- A cascade refusal ("an earlier test of this codeunit ...", `cascade`, `cascade-existing-state`) is never kept in the per-test
  fill. Each request there runs one test, so such a row can only mean state crossed requests. It re-runs one-shot as before (a
  test, red when removed).
- The drop names only the samples the dropping fill skipped. The skip list is cumulative over the whole-codeunit and the
  per-test fills. This one is untested: no rig runs both fills in one session, and it changes only the warning's text.
- The "kept" test's one-shot rows refuse alike.
- `textOf`'s comment cites R1001's first-line key, not R678.

Live, as predicted (`/coord/handoff/PR-04/camera.*`): Camera kept its daemon baseline (no drop), and its 3 baseline outcomes equal
R-993's one-shot run per test. The full v3 gate passes unchanged.
