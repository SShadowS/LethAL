(16681485). Concerns [[R586]]'s update gate, `scripts/al-runner-v3-update.ts`.

**The two wrong verdicts.**
- **alpha.3: `infra-fail` for the wrong reason.** `gateOne` did not pass `LETHAL_ITEST_V3_CDO` to the gate.
  `realDeps().runGate` passed it only when the caller's environment set it, and the daily caller did not. So the
  itest ran neither D1 nor D1c, and `gateOutcome` read the missing legs as `skipped`, which is `infra-fail`.
  `readReceipt`'s `why` listed only the legs that were present, so the log never said that two were missing.
  Without the D legs, this would repeat every day. The pre-commitment expects alpha.3 to `gate-fail` on the D
  legs (#5606).
- **alpha.4 and edge-7739d8132: `gate-fail` for the wrong reason.** Upstream PR #5622 fixed #5613, the defect
  LethAL filed (R586's defect table, row 13). Now exit 6 writes an `--output-json` document with 0 rows. But the
  probe coded the fact `none-selected-exit` as a CONTRACT fact, so the fix read `diverged`, and `classifyLegC`
  turned that into `gate-fail`. That broke ruling I-2, under which a fixed defect is `held`, never a
  blacklisting. Both builds went to `failed/<tag>@8a71e87d…`.

**The evidence loss.** `gateOne` wrote the receipt inside a temporary folder and deleted that folder in its
`finally`. It never logged the receipt's `lines`. So no leg's own message survived, and the diagnosis had to work
from the code and the upstream release notes.

**The fix (R-632, A to D).**
- **A.** `gateOne` passes `LETHAL_ITEST_V3_CDO` itself. The default is `V3_CDO_DEFAULT`
  (`/work/lethal-wt/cdo-r396`, the gate page's checkout), and the caller's environment can override it.
  `readReceipt`'s `why` names every leg of `V3_GATE_LEGS` that the receipt lacks (`missing legs D1,D1c`).
- **B.** Pre-commitment r7: `none-selected-exit` is now a DEFECT fact, and it is in `V3_DEFECT_FACTS`, leg C's
  list (moved from the itest to `al-runner-v3-gate.ts`):
  - exit 6 with no document is `defect-present`;
  - exit 6 with a document of 0 rows is `gone`, so leg C is `held`;
  - anything else, including output that does not parse, is `diverged`, which refuses the session and makes
    leg C `gate-fail`.
  - Leg C still has 23 facts: now 8 defect facts and 15 contract facts.
- **C.** Before the cleanup, the receipt is copied next to the outcome it gave: `failed/<tag>@<commit>/receipt.json`,
  `held/<tag>/receipt.json` or `infra/<tag>.receipt.json`. A `--regate` receipt goes to
  `regate/<commit>.receipt.json`. The log line now carries the receipt's `lines`.
- **D.** The `failed/` early return logs a line with the `--regate` hint. The alpha path and `--regate`
  (`updateOnce`) now apply the same heavy-job and memory guard as `edgeOnce` (`skippedForTheDay`), because once
  the D legs run, every gate is a corpus job.

**The build review's fixes (Opus review, `/coord/handoff/R-632/review-build-opus.md`).**
- **I1.** `realDeps().runGate` writes the itest's stdout and stderr to `gate.log` beside the receipt, on every
  exit (`runToLog`). `gateOne`'s `keep` copies `gate.log` next to the receipt (`infra/<tag>.gate.log`,
  `regate/<commit>.gate.log`, and `gate.log` in `failed/` and `held/`), even when there is no receipt.
  `gateOne` now logs the gate's error text instead of dropping it. `classifyLegC` adds each non-passing fact's
  `measured` value to its line, so the receipt itself shows what v3 returned. A `refusal-row-shape` divergence
  therefore reaches the log with its evidence.
- **I2.** A skipped `--regate` exits 2 (`updateExitCode`), so a `&&` chain after it stops.
- **I3.** The gate page `docs/gates/alrunner-v3.md` describes the kept evidence, the CDO default, the guard, the
  8/15 split and this history.
- **M2.** Each copy is in its own try/catch and a failure is logged, so keeping evidence never blocks the verdict,
  `.gated` or the count.
- **M5.** `HEAVY_JOB` also counts bun started by a full path (`(^|/)bun …`).
- Left as they are, by the orchestrator's ruling:
  - M1: a missing CDO checkout infra-fails with a stack, not a named refusal. It is loud and never a pass.
  - M3: `infra/` and `held/` keep only the latest receipt; the log keeps each day's lines.
  - M4: the A test reads `process.env.LETHAL_ITEST_V3_CDO`, so a machine that sets it could hide a revert; CI does
    not set it.
  - M6: kept receipts and logs can carry Continia source text. They live outside the repo; redact before copying
    one in.

**An open risk of the same kind: `refusal-row-shape` (#5608), not measured.** This contract fact sits next to a
filed defect that #5622 also closed. The probe's `HttpGet` calls `http://localhost:1/x`. #5622 says a request
that BC fails without a connection, for example to an internal address, now fails with BC's error instead of
being refused. If v3 treats `localhost:1` that way, the fact reads `diverged` on alpha.4, which is the same
wrong-reason `gate-fail`. alpha.3 read `matches`. If leg C's per-fact output on alpha.4 shows it `diverged`, the
report names it, and it gets its own pre-commitment delta. A `held` leg C must not hide it. In code it cannot: a
`diverged` contract fact makes leg C `gate-fail`, which outranks `held`. In that case the backend also refuses
every session, so the other legs infra-fail as a knock-on effect, and #5641 stays unmeasured on alpha.4.
