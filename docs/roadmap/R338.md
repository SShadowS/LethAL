**Found 2026-09-29** when the orchestrator updated the global tool from 2.11.0 to **2.12.0** and ran
`itest:alrunner` on master `bd491fd`: the gate FAILED with `no execution context carries a bcBuild`
([[R129]]). Every per-mutant verdict was unchanged (both one-shot legs 3 / 12 / 4); only the BC-build
record broke.

**Measured on the sandbox-app pair.** Without `AL_RUNNER_VERBOSE`, 2.12.0 prints NO `[bc] selected BC
...` line on either stream; stderr carries only `[bc] warning: the shipped 28.1 engine variant was built
against 28.1.49838.55333, not the selected 28.1.49838.54487 ...`. With `AL_RUNNER_VERBOSE=1` it prints
the familiar `[bc] selected BC 28.1.49838.54487 (<artifact dir>)` plus two new `[bc]` lines: `no
--bc-version given, selecting BC ...` and `selecting engine variant 28.1.49838.55333 for BC
28.1.49838.54487 (this process is currently running the 28.5... variant), re-execing.` The parsers are
`al-runner-transport.ts` (`/^\[bc\] selected BC .../m`, two places).

**Why it matters.** `bcBuild` is how a report says which BC runtime produced its verdicts ([[R129]]),
and the R147 / R200 platform-app pin derives its directory from the same line.

**What would close it.** Read the build without depending on verbose-only output: either request
`AL_RUNNER_VERBOSE=1` on the calls whose output is parsed (as [[R235]] already does for provisioning),
or also accept 2.12's default-output `[bc] warning ... not the selected <build>` sentence, pinned by
tests against captured 2.11 AND 2.12 output. Re-run `itest:alrunner` on 2.12.0 (all four legs plus the
[[R321]] symbol legs) and sweep the al-runner prose per CLAUDE.md. Do not pin al-runner to 2.11.

**Closed 2026-09-29 in `01230c5c`.** `parseAlRunnerBcBuild` now reads, after `[bc] selected`, 2.12's
default `[bc] warning ... not the selected <build>` line and its `al-runner <ver> · BC <build> · <n>
apps` banner (the one line printed on every run). Verbose was NOT requested on mutant calls: it adds
about a hundred lines per invocation and the daemon keeps only a bounded stderr tail. The platform-app
pin was never broken, because the provisioning call was already verbose ([[R235]]). Tests pin 2.11 and
2.12 (default and verbose) output and the new `selecting engine variant` line as a non-announcement,
red-checked. `itest:alrunner` on 2.12.0: PASS on all four legs (3 / 12 / 4 per mutant) and both
[[R321]] symbol sets (5 / 8 / 0 on every leg).
