**Found by R-729** (2026-10-24), the second `scripts/r315-dc-compile.ts` run on DC master c895a7d `Cloud`, after
[[R729]]'s fix. alc reached binding and reported **2 x AL0402** ("Expression ... cannot be specified more than
once in a 'case' statement") in `CDCSecureArchiveManagement.Codeunit.al` (emitted lines 10707 and 10709, one mutant,
M41951 of that run; original `case true of` at lines 782 to 785). The un-instrumented control compiles with 0 errors,
so the error is LethAL's.

**The shape.** `case true of` with two labels that compare the same variable to two integer literals, `X = 0:` and
`X = 1:`. `lethal.shift-integer` shifts the first literal by one, so the label becomes `X = 1:`, the same expression as
the second label. AL requires distinct case expressions, so the mutant is not a valid program and alc refuses the whole
artifact. The operator is correct for the original, but the result collides with a sibling label.

**What a real run does.** Same as [[R731]]: bisection, then "not attributable to a single mutant" when another culprit
exists, and every mutant in the batch scores `error`.

**Fix direction.** When the literal is a `case` label (a comparison inside a `case_branch` label), refuse a shift whose
result text equals a sibling label's text, or refuse shifts on case labels. Check the other value-changing operators
for the same collision (`conditional-boundary`, `flip-boolean-literal` on `case true of` labels). Test: a fixture in
the R402 sweep and a unit test, red before the fix; then re-run `scripts/r315-dc-compile.ts`.

## Done (69478059; the test pins re-recorded in b4bb3759)

**Cause.** `shift-integer` claims the integer in `X = 0` inside a case label, and nothing checked the changed label
against its siblings; other operators can do the same.
**Fix.** ONE central check, `caseLabelCollides` (`packages/engine/src/ast/case-labels.ts`), called in
`generateMutationSet` beside `validateSpec`. It builds the changed label, normalises it and every other label of the
SAME case statement (nested cases excluded, `A, A:` included) and drops the spec on equality. Each file with a drop
gets one `case-label-collision` warning with the count; no `SessionReport` field.
**Offline alc probes (2026-10-24, invented AL).** AL0402 for: the same text, `A, A:`, a trailing comment difference,
`case N of 1:` beside `0 + 1:` (constants fold: `1`, `01`, `2 - 1` all equal), the same value in two branches. NOT
equal to alc: `1 = X`, `X = 0 + 1`, `X <> 0` vs `not (X = 0)`, `'A'` vs `'a'`, a nested case, `(X = 1)`, `x = 1`,
`X=1`, `X > 5` vs `5 < X`. alc compares the label's own text, keeping inner spacing and case, and folds integer
constants. The normaliser strips comments, spacing, identifier case and outer parentheses and folds integers, so it
refuses a superset of alc (an extra refusal costs one mutant, a miss costs the batch).
**Cost, measured** (DC): 1 `shift-integer` tuple removed (`CDCSecureArchiveManagement`, the reported one); no other
operator lost a tuple to this check. Fixtures: identical.
**Tests.** `packages/engine/tests/ast/case-labels.test.ts` and
`packages/runner/tests/r732-case-label-collision.test.ts`, red per direction (guard off: 2 red in the orchestrator
test, 7 in the helper test; refuse-all: 2 and 7). R402 sweep shape `x2_case_true_dup`: on master the artifact fails
AL0402, now compiles in all four builds (10 specs to 9).
