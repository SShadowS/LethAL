**Found by the R-463 plan review (opus spec-adversary, adversary-r1 finding 5c, 2026-10-09).** Not caused
by R-463 and not changed by it.

Inside an open `reportextension` block (`insideOpenItem` in `packages/builtin-tier1/src/loop-hazard.ts`
answers true: an extension of a dependency report, or an anchor item that is open), a bare call `BaseProc()`
to a procedure the BASE report declares reaches R-500 shape 2's one-hop follow (`callTargets` in
`loop-hazard.ts`) through its on-table branch, which looks the name up on the innermost data item's table.
It never looks at the base report, so `BaseProc` is not followed, and the mutants inside `BaseProc` are not
hang-refused through this caller. When `BaseProc` iterates or writes a loop's exit state, a mutant there can
hang the session that runs the report.

**To build it.** In `callTargets`' bare branch inside a reportextension, also resolve the name on the base
report when the project declares it (unique by name), and red-test both directions: an open block's bare
`BaseProc()` refuses `BaseProc`'s mutants; the same call from a closed block does not. Count the sites on
BaseApp first (the 4 BC.History projects with reportextensions).
