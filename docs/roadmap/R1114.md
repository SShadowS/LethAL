Filed by coord PR-133 (lethal-preproc, 2026-11-17), from DO window x2's events
(`/coord/handoff/R-984/x2.run.events.ndjson`, seq 33892-33896).
- **What happened:**
  - On daemon request 129 (a prefetch of 77 entries), the kept refusal `RecordRef.Duplicate on a RecordRef that is not
    open` (keep entry `recordref-method-not-open`) was followed by `CreatePDF_WithValidData_ShouldCreatePDF`, which
    passed. Its baseline row is `fail`.
  - `serve-drift-after-kept-refusal` fired, the daemon was closed (`kept-refusal-drift`), and the request re-ran on a
    fresh daemon. The verdict was protected.
- **Why it matters:**
  - The drift check compares only rows that cannot differ under the mutant (a NONE entry, or tests before the first
    covering test). So this drift is not a mutant effect.
  - It is either state left by the kept refusal (or by an earlier request in that daemon), which would make the keep
    false; or a test whose answer varies; or a coverage gap.
  - The drift check does not see contamination in a covering test, so a false keep could move a verdict where the check
    is blind.
- **The events cannot settle it.** They do not record the fresh re-run's rows. The re-run raised no second drift.
- **Next:**
  - Re-run that request's codeunits in the same order, on a daemon kept after a `RecordRef.Duplicate` refusal and on a
    fresh daemon, and compare the row.
  - If the kept daemon gives `pass` and the fresh one gives `fail`, narrow `recordref-method-not-open` (Duplicate out)
    and re-census it.
  - If both give the same row, record the test as one whose answer varies.
