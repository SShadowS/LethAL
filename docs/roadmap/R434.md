**Found by R-385 (limit L0 of `docs/superpowers/plans/2026-10-04-R-385-resident-microsoft-dependencies.md`).**

## What

R-385 fingerprints, by the bytes the server holds, every app in the test app's dependency closure,
plus `System`, `Application` (when declared) and the control app's dependencies (Test Runner). Two
things are still outside the fingerprint:

1. **An installed app outside the closure**, from any publisher, that changes what a test does: for
   example an app with a global event subscriber on a table the test writes, or one that changes a
   setup record. No test app declares it, so nothing reads it. A new version of it, or installing it
   for the first time, leaves every test digest unchanged.
2. **The installed check for non-Microsoft dependencies.** R-385 requires each Microsoft package it
   hashes to have exactly one installed row at the downloaded manifest's version (D2). A
   non-Microsoft dependency is still hashed from `dev/packages` with no such check, so during a
   staged upgrade (two versions published, the older one installed) the hashed package may not be
   the one that runs. Ruled out of R-385's scope (plan section 7, ruling 2).

## What the reader sees

`lethal verify` reports the affected tests as OLD: not re-run, no cause, no warning. Only the docs
(`docs/using-lethal-from-an-agent.md`, the CHANGELOG, the module comment of
`packages/runner/src/digest-inputs.ts`) say it can happen.

## What would close it

- Part 2 is small: run `checkInstalled` (in `digest-inputs.ts`) for every dependency, not only
  Microsoft ones. It costs one per-id read (about 45 ms on Cronus284) per non-Microsoft app. Measure
  first that every real closure has exactly one installed row per app.
- Part 1 needs a list of installed apps, and the automation `extensions` list must never be asked
  for unfiltered (R433: it hung BC 28.4 and took the service tier down). A by-id read cannot find an
  app nobody named. A safe source of the installed set has to be found and measured first (for
  example the control app reporting installed apps through `NavApp`/`Module Info` from AL, under a
  new control version).

## Closed 2026-10-23 by ruling (R-434, lethal-bugs)

**Part 2 was done by [[R496]] (47179723).**
- `dependencyFingerprint` (`digest-inputs.ts`) calls `checkInstalled` for EVERY extension it hashes, partner and
  transitive ones included: exactly one installed row, at the hashed manifest's version.
- Pinned by tests T5 (a direct partner dependency served at 1.0.0.0 while 0.9.0.0 is installed) and T6 (the same,
  transitive) in `orchestrator.test.ts`.
- Each read is the per-app filtered one (`extensions-query-refusal.test.ts`).
- The module comment already said so. The agent guide still listed it as unseen, and is corrected.

**Part 1 is measured, and is a stated limit by the orchestrator's ruling.**
- **The measurement** is in `docs/measurements/r434/`, under pre-commitment
  `docs/superpowers/specs/2026-10-23-r434-installed-apps-probe-precommitment.md` (master 1b8a7973) and delta 1
  (2f4a8933).
- **The source:** an AL read of `NAV App Installed App`, through a throwaway web-service app, on bc1, bc2 and bc3.
  The automation `extensions` list was never asked for (R433).
- **It works:** the whole list is 117 to 122 rows, takes 1-6 ms in AL and 60-160 ms over HTTP, and is the same rows
  on every read.
- **What is installed:** 100 Microsoft apps on each server, 5 Continia apps on bc3, and the LethAL apps.
- **The limit, in a real case:** ALDirectCompile's "Test Runner Extension" 3.2.0.0 is installed on all three servers
  and is outside every test app's closure.
- **Why not fold it now:**
  - It needs a new LethAL Control procedure: a control-version bump, every gate re-proved on all three servers
    (R604), and every user upgrading.
  - Every gate run republishes its target under a minted version (bc1 held 8), so a raw list would change on every
    run of every project. That switches verify off on a shared server unless LethAL's own instrumented targets are
    left out.
- **The ruling:** state the limit.
  - The agent guide's "what verify still does NOT see" now gives it with these numbers, and with what to do
    (re-run `lethal run` after installing or upgrading an app). So does the CHANGELOG.
  - The fold is [[R687]], after the release.
