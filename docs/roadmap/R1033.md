**The 655 s.** DO's baseline (PR-18) showed about 655 s of gaps between serve requests. R-984's process samples (`t3.procs.tsv`)
show 12 one-shot `al-runner test` processes in t3's baseline, about 53 s each: R948's cross-check of the daemon baseline (the 2nd, the
last and every 10th of 110 codeunits). 593 of the 596 s of gaps fall on one daemon; the serve trace cannot see one-shot processes.

**What was built.** On a resume, a serve session may reuse R192's snapshot (R1008 kept it from doing so) when every key matches and
the snapshot carries the backend's own baseline state (`baseline_snapshots.backend_state`: each codeunit's rows in run order, the
seed, the .NET sidecar's content hash). Before anything is served from it, `recheckReusedBaseline` runs every codeunit once unmutated
on the daemon and compares every row (failure text with only the target app's minted version masked), and three codeunits with
coverage (each test's coverage map); any difference, another seed or sidecar, a codeunit run alone, one-shot or under method
isolation, or no backend state re-runs the baseline as before, by name (`resume-baseline-not-reused`). R948's one-shot cross-check
does not run on a reused baseline. Re-checked reused rows count as this session's line evidence for R926 and R975 (addendum 2).

**Measured.** DO's three stored baselines and lethal-bugs' fourth (2026-11-14 to 15) agree on all 1,979 tests: outcome, coverage, and
every field but the minted version in 42 failure texts. Service Declaration (isolation test, `--only GetServiceDeclarationLines`):
- first attempt (build ff9748ea): reuse worked, but `report-diff A B2` gave 2 differences (trigger mutants, R926/R975 line
  evidence); the same 2 on the one-shot transport, so not L5's ([[R1034]]);
- second attempt (build d6ea8535): B2 reused (`resume-baseline-reused`), report IDENTICAL to A (222 mutants), baseline phase 2.6 s
  against B1's 6.6 s (39%, limit 50%);
- B3 (one test-file comment changed): the resume is refused before any baseline step, naming the test app (an existing guard;
  stronger than the predicted re-run).

**To close.** The next DO window after t4: a resumed window's baseline phase at most 300 s, with the window's verdicts as
pre-committed by its own windows.
