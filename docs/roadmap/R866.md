**Filed 2026-11-07 by lethal-bugs.** Related: [[R857]].

**What.** An `entries` request refuses `coverage` (measured on `6bb821b98`), so `--isolate-tests` runs the baseline as one v3 process per test. On CDO's D1 slice that was 75.4 s for 21 tests against 4.8 s, on a loaded machine. At that rate CDO's whole Test app, 1,238 tests, would take over an hour per batch, and a resume runs the baseline again. Not measured on that set.

**Where the time goes (R-866, CDO D1's 21 tests, edge `6bb821b98`).** A process with coverage took 3.2 to 3.8 s. A plain daemon request per test took 1.2 to 1.6 s with coverage, about half of it the install baseline and a quarter setup, and 0.34 s without. So coverage is most of a request's cost, and a daemon would save about 2 to 3 times. Load average 87 to 139, so read the ratios, not the figures. No quiet machine came.

**The fix.** The processes stay, and run four at a time: each holds one test, so what it isolates does not change. An answer stands only under R790's rule, so a duration measured beside the others cannot move a budget; anything else runs alone as before. Baseline: 75.4 s before, 24.6 s and 38.9 s after, on a machine at load 27 to 228. Default-mode baseline in the same session: 2.9 s. D1 verdicts: 0 of 65 move.

**The cost that stays, documented.** Each process peaked at about 1.6 GB on CDO, so a baseline needs about 6.4 GB at once, and more on a larger project. At 3.4 s per process, CDO's whole Test app would take about 18 minutes per batch four at a time. Not measured on that set. A resume runs the baseline again.

**Not done.** A daemon request per test needs a daemon before the baseline has rows to warm it up with, so the warm-up's comparison must move: not small. It would save memory as well as time, so it is the next step if the mode is used on a large suite. Or upstream lets `entries` carry coverage.
