**Found 2026-10-21** by the second Opus delta review of [[R586]] (`/coord/handoff/R-586/review-build-delta2.md`, G5).

**What.** The update gate's worktree preparation (`gatePreparation` in `scripts/al-runner-v3-update.ts`) checks
the fixture symbol tar's sha256 (`FIXTURE_SYMBOLS_TAR_SHA256`) only when it EXTRACTS it, that is when the fixture
`.alpackages` folders are absent. Folders already present, from an older tar or copied by hand, are used without
any check.

**Effect.** None on a verdict measured so far: stale symbols give an alc failure (`infra-fail`) or M8's
`al-runner-v3-system-application-not-found` / version refusal, not a wrong verdict. It would matter only if the
Microsoft apps differed at the same System Application version.

**To close.** On extraction, write the tar's sha256 to a marker file beside the extracted folders, and on a later
run require that marker to equal `FIXTURE_SYMBOLS_TAR_SHA256` before using folders already there (otherwise
re-extract or refuse by name). Unit-test the preparation decision in both directions.
