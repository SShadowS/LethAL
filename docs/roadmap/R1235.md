**Filed 2026-11-27 by lethal-preproc, from PR-472 (ruling by lethal-orchestrator).**

**What is true today.**
- The default tries a mutant's covering tests in R197's order: earlier kills in the procedure first, then the narrowest test,
  then the name. R1174 re-walks a survivor whose order crossed test codeunits.
- PR-472's `--no-kill-ledger` drops the ledger. The order is then fixed: fewest covered members first, then the name
  (`orderCoveringTests` with an empty ledger).
- Neither is the order in which the test codeunit declares its methods, which is what a project's CI runs (a Test Runner
  walks a codeunit's methods in their declared order).

**Why it can matter.** Tests whose outcome depends on which tests ran before them in the session (shared state inside one
codeunit, or across codeunits) can give a different verdict in a different order. PR-472's caveat says verdicts with the
flag may differ from the default in either direction for that reason.

**Trigger.** A user asks for CI-faithful order. For example, DOTests wants verdicts that match its CI run for a file whose
tests share state.

**What a build would need.**
- The declared order per codeunit, from test discovery; methods in declaration order; codeunits in the order the project's
  CI runs them.
- Its own pre-commitment, review, and verdict-equality on the bcdev gates.
