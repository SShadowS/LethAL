**Found 2026-10-06 in the post-merge gpt-6.1-sol review of R-484** (`/coord/reviews/postmerge-R-484/sol.md`). Static
review: no corpus count yet. Same family as [[R484]] and [[R487]].

**What.**
1. **A literal exit guard (important).** In a data item's `OnAfterGetRecord`, `if true then CurrReport.Break();` lets
   `flip-boolean-literal` emit `true -> false`. `hasEnclosingLoop` sees only `while`/`repeat`, so on an unbounded
   Integer data item the mutant can traverse without end.
2. **reportextension `modify(<dataitem>)` triggers (important).** `enclosingExitParts` looks for a `report_dataitem`
   ancestor. A guard and its write inside a `modify_modification` of an unbounded base data item collect no exit
   parts, so a flipped or removed write is emitted.
3. **Parent filter bounds set from a nested data item (important, needs a BC check).** The nested collector gathers
   only report-exit guards, not range arguments. A child's `OnPreDataItem` that narrows the PARENT's `SetRange` through
   a variable (`Upper := 3`) can have that assignment removed, which widens the parent's range. Whether BC really
   re-reads the parent filter at that point must be measured.
4. **Over-refusal (minor).** A write in `OnPostDataItem` to a flag that an earlier guard reads is refused, but it runs
   after the iteration ends and cannot hang that data item.

No identity change outside scheme 28 was found.

**To close.** Count each shape on BaseApp, CDO, DC and DO first. Then refuse 1-3 (3 only if BC confirms it) and
release 4, under one IDENTITY_SCHEME bump if keys move. Map each shape against R487's items first, since some may
already be covered there.
