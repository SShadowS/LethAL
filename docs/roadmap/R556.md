**Filed by R-340 (2026-10-09), its plan review r2 Minor-2.** `IDENTITY_SCHEME` exists because a mutant can change under an
unchanged identity key (R468's pair change, [[R340]]'s again: a newly typed argument makes `swap-call-arguments` pick
another pair at the same call). Every path that CARRIES a verdict or a mark refuses across a scheme change. Two
comparisons do not read the scheme or the mutated text:

- `campaign compare` (`compareCampaignStage`, `diffMutants` / `keyOf`), and
- every frozen `packages/runner/itest/*.baseline.json` gate comparison.

Neither carries a verdict (both sides really ran), so no false kill. But a mutant that changed under the same key with
the same verdict reads as "identical", and one whose verdict changed reads as a regression in the code under test: a
wrong diagnosis. Measured for R340: 0 fixture sites touch a trigger header name, so no gate is affected; the DO/CDO
campaign stages were not measured.

**To close:** have `campaign compare` report "identity scheme changed, UNVERIFIED" when the archived stage report's
`identityScheme` differs from the new one (the R355 pattern for coverage mode), and make the gate comparisons include
the mutated text (or refuse a baseline recorded under another scheme by name).
