**Owner ruling, 2026-09-25: the RULE is right and the PRACTICE was wrong.** The doc comment on
`EXPLAIN_SCHEMA_VERSION` (`packages/runner/src/explain.ts`) says a value domain that changes needs
a bump, because a strict consumer validating against the published schema rejects a value it does
not know. Five commits added values to `$.caveats[].caveat` and `$.notMeasured[].cause` under v4
without one: `41daa29`, `3923862`, `0451532`, `59081aa`, `80eb608`.

**What is NOT done:** v4 is not relabelled. Relabelling outputs already written and archived as v4
would be a worse lie than the drift, the same reasoning R157 recorded for report v2. v4 is on
record as having more than one value set.

**What is done from here:**
1. GH-24b bumps to v5 for its new `reach` value, as its plan says
   (`docs/superpowers/plans/2026-09-25-GH-24-active-guard-reach.md`, Task 8).
2. A test pins every value domain in `schemas/explain-v<N>.schema.json` (the `enum` sets for
   caveat, cause, reach and the like) against a literal list, next to R157's root-required pin in
   `packages/runner/tests/schemas.test.ts`. Adding a value then reddens a test whose message names
   this rule, instead of shipping silently. Red-check: add a value to one enum without changing the
   pinned list.
3. The doc comment on `EXPLAIN_SCHEMA_VERSION` gains one sentence naming this item and the drift.

Items 2 and 3 are small and can ride with GH-24b, or land alone first; the orchestrator decides
when planning.

**Done 2026-09-26 (GH-24b, 83c5839).** `EXPLAIN_SCHEMA_VERSION` is 5, for GH-24's new `reach` value
`reached-unnoticed` and the changed meaning of the two unreached values, and its doc comment now
names this item and the v4 drift. `schemas/explain-v5.schema.json` is new and `explain-v4` is left
as it was published, as `schemas/README.md` promises. The test "every enum value set in the
published explain schema is pinned (R233)" in `packages/runner/tests/schemas.test.ts`, beside
R157's root-required pin, compares every `enum` in the current explain schema against a literal
list, and its failure message names this rule. Red-checked: adding `expression` to the `reachGrain`
enum without touching the list failed that test and only that test.
