**What.** A reader mark's key is the serialized R166 identity, `astHash|codeunitName|procedureName|operatorName|operatorMajor`
(`parseEquivalenceMarks`, `packages/runner/src/equivalence-marks.ts`). Neither `lethal run --dry-run`
nor `lethal explain` prints it. To hand-write a mark today, a reader has to compute the key
themselves through `identityKeyOf` and `serializeKey` (`packages/runner/src/selection.ts`), the same
two functions the report uses internally but never surfaces.

**Found by.** The C02-03 `sandbox-harden` fixture, which had to build its planted equivalent's key
this way rather than read it off any CLI output. R229 already shows what goes wrong when a key is
assembled by hand instead: a trigger mutant's key was built with the wrong field and the mark never
matched.

**What would close it.** Print the serialized key per survivor in `explain` (or per site in
`--dry-run`), built by calling the same two functions rather than re-deriving the format.
