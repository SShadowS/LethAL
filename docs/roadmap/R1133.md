Found in coord PR-187 (2026-11-18/19). Related: [[R938]], [[R917]], [[R266]].

**What happened.** PR-187 smoke-tested three runs with `--dry-run` before a long measurement.
- PaymentPractices' dry run, on R890's config, exited 0 (`/coord/handoff/PR-187/dry-pp.txt`: "83 deployed mutant(s)").
- The real runs, with the same project, tests and config, refused in 1 s: `V3EnvironmentUnknownError: al-runner-v3: the
  target's environment is unknown (no alRunnerV3.environment in the config, no environmentType in the target's
  .vscode/launch.json)` (`/coord/handoff/PR-187/pp/opt.stderr.txt`).
- R890's configs predate R938, which made the environment required.

**Why.** `--dry-run` parses, generates and lists mutants, but never builds the backend. So every refusal the backend
makes from config alone, before it executes anything, is skipped: the v3 config validation, the environment, the pinned
binary (R814) and the paths it names, and bcdev's config checks. A user (or a lane) who checks a command with
`--dry-run` learns nothing about the config the real run will refuse.

**To close.** `--dry-run` runs the same config pre-flight refusals as a real run, by the same error names, without
spawning al-runner or calling a server:
- a test per refusal shows the dry run refusing it by name;
- a test shows a config the real run accepts still passes the dry run;
- the help text says which checks a dry run makes and which it cannot (anything that needs the binary or a server).
