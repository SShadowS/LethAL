**The prepublish step and the control-app republish both happen BEFORE the lease is acquired.** (Reworded 2026-07-28 — the original framing was wrong in three ways, corrected by external review and verified here.) **What is NOT the problem:** publishing `publishApps` in reuse mode. `fixtures/README.md` states the contract as "Reuse-mode ignores it **if absent**", so publishing when PRESENT is documented behaviour, and a reuse-mode config that lists apps is the user explicitly delegating test-app publication to LethAL. Skipping it would re-open the R31/R56 staleness class — observed TWICE, badly disguised, two lost debugging sessions — to close a race never once observed. Trading a measured cost for a theoretical one is the wrong direction, and a `publishAppsOnReuse` knob would restate what the existing key already says while silently breaking configs that work today. **Also not available:** verify-before-publish per app. The control app earns it via `HarnessInfo`'s protocol/version surface (R28); a test app has none, `EnvToolPublisher.publishFile` only hashes the bytes it READS with no server-side digest to compare against, and `.app` files are gitignored local builds — so version-equal/content-different is routine and a version check would skip the publish exactly when the app is stale. **The real residual hazard**, narrower than the original text: both publishes happen outside the lease window, so a concurrent session's test app can change mid-run (invisible to the attestation fence, which covers only the TARGET artifact), and repeated interrupted publishes are what R44 measured driving a tenant to `503`. Note the original entry's rationale was borrowed from the control app — republishing the TEST app does not run `LethAL Control`'s install/upgrade codeunits and does not touch the lease or `serverGeneration`. **Fix**: move both under the lease. Real plumbing — `startEnvToolSession` returns before `leaseSessionFor` runs, so prepublish must become a post-lease step or the session needs a post-lease hook. Low priority: never observed, and the common concurrent case publishes identical bytes.
