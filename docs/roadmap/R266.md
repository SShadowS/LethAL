id: "R266"
title: "`lethal run --dry-run` accepts and ignores its 19 execution flags (`--out`, `--progress-out`, `--tests`, `--backend` and more)"
section: "product-gaps"
order: 968
status: "open"
---

**What.** C02-07 made every subcommand refuse every flag it does not read (owner ruling, 2026-09-26),
with one exception: `lethal run --dry-run` still parses its execution flags and does nothing with
them, because it executes nothing. The 19 are `--tests`, `--backend`, `--out`, `--progress-out`,
`--workers`, `--compile-concurrency`, `--keep-env`, `--allow-expiring-env`, `--selector-id`,
`--control-id`, `--table-id`, `--skip-known-survivors`, `--max-guards-per-batch`,
`--max-methods-per-call`, `--request-ceiling-ms`, `--no-group-runs`, `--retry-stranded`,
`--stop-hung-sessions` and `--allow-large-run`.

**Why it matters.** `--out` is the sharp one: a dry run given `--out plan.json` completes and writes
nothing, which is the R176 shape (`run --report`) in a narrower mode. A script that adds
`--dry-run` to a real run command also gets no warning that half its flags stopped meaning anything.

**What would close it.** Refuse each one in the dry-run branch of `parseCliConfig`, or make `--out`
write the dry-run listing. The exemption list may only shrink.

Evidence: `DRY_RUN_IGNORES` and the test "the dry-run exemption is exact" in
`packages/runner/tests/cli.test.ts`, which measures the set against the parsed config.
