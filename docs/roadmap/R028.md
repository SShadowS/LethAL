**Nothing detects a stale `LethAL Control` build.** `HarnessInfo` hardcodes `semver '1.0.0.0'` (`ControlApi.Codeunit.al`), so `HarnessVerifier` cannot tell a current control app from one several versions behind. Consequence seen immediately: until 1.0.0.5 is published on a given container, every bcdev session there prints an inconclusive 404 canary line at startup — correct and actionable, but the harness itself should say "your control app predates this client" instead of leaving each new action to fail its own way. Report the real version and compare it.
