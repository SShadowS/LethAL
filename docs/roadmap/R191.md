**What happened.** `do rung1`'s re-run reached its baseline and the 22nd test,
`CDO Aut Stat Bal Check Tests.LegacySystem_CustomerWithBalance_ShouldCreateJournalLine`, came back
`error` with *"RunMutant 2xx body could not be read: TimeoutError: The operation timed out."* Its
recorded `durationMs` is **2,800**, but the baseline phase took **278 s** for 22 tests whose recorded
durations sum to 6.2 s. The tier was quarantined (`in-flight-unknown`), exit 3, and
`--stop-hung-sessions` was on and never fired.

**Why the numbers disagree.** In `run-mutant-transport.ts` the per-test budget timer, the R53 stop
hook timer and the hard-cap abort are all cleared in the `finally` that follows `fetchFn`
resolving, and `durationMs` is taken right after it. `fetch` resolves when the response HEADERS
arrive. The body is then read with `res.text()` with no LethAL timer at all, so a stall there runs
until the runtime's own fetch timeout throws, which is what the ~272 s were. The stop hook, whose
whole purpose (R53) is to turn a hung run into a scored `timeout-killed` instead of a quarantine,
was never given the chance, because from LethAL's point of view the request had already succeeded.

**What is NOT established.** Whether BC genuinely sends headers before the AL finishes on this path
(streaming), or sent the whole response at 2.8 s and the read stalled for a transport reason. The
container showed no lingering session afterwards and no server error in the event log. The test
itself fails in 489 ms under bc-dev's runner with *"App Document Output is not activated"*, raised
through a `Message` the test runner treats as a failure; in LethAL's non-GUI fenced session that
`Message` is a no-op and the code continues into the activation path, so the stall is most likely
an outbound HTTP call from Continia Core waiting on a network the container does not have. That is
an environment fact about Cronus28, not a LethAL defect, and it is why the re-run is blocked
(see the R175 pre-commitment's attempts log). The LethAL defect is that a stall of THIS shape is
invisible to the machinery built for stalls.

**What would close it.** Keep the budget running across the body read: take `durationMs` after
`res.text()`, keep the R53 timer alive until the body is in hand, and make the abort controller's
signal cover the read (Bun's `fetch` honours the signal for the body stream). Then a body-phase hang
takes the same path as a header-phase hang, the stop hook fires, and BC's 408 scores it. A unit test
with a fake `fetchFn` whose `text()` never resolves would pin it; none exists today because every
fake resolves its body immediately.

## OUTCOME, 2026-09-02

**Fixed.** `dispatch` no longer clears its timers when `fetch` resolves. A `settleTimers` helper is
called on every exit that has the body in hand (or has given up on it), and `abortedVerdict`
answers an abort in either phase with the same `deadline-exceeded` / `in-flight-unknown` shape,
the R53 stop detail included, naming the phase (`before headers` / `after headers`). `durationMs`
for a scored run is taken after the body is read, so the 2,800 ms that hid a 272 s stall cannot
recur. Measured first: Bun rejects an in-progress `res.text()` with `AbortError` when the fetch
signal aborts, which is what makes one controller enough.

**Proof.** `run-mutant-transport.test.ts`, "the budget covers the BODY phase too": a 200 whose
body never completes (a stream that honours the signal) hits a 30 ms budget and comes back
`deadline-exceeded` / `in-flight-unknown` / "after headers" with a duration that includes the
stall; with a stop hook wired the hook fires ONCE during the body phase and the hard cap ends the
wait; a body that arrives in time scores normally and leaks no timer. Red-check: against the
committed transport those three tests never finish (killed at 90 s), which is the row's own symptom
reproduced in a test. Full suite 2647 pass.

**What is still not established** is the same as before: whether BC streams headers before the AL
finishes on this path, or the 2.8 s response was complete and the read stalled in transport. Either
way the stall is now inside the budget.
