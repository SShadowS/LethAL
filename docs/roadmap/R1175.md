**Found by** PR-331 step 0 (`/coord/handoff/PR-331/findings.md`), from PR-299's v3 client baseline. The cause was already
named in R982: Continia Core's online module activation.

**The size:**
- 29 tests in 5 test codeunits (68857: 11, 68934: 7, 68859: 5, 68874: 3, 68929: 3);
- all fail "Unhandled UI: Confirm ... has not been activated", raised in Core's activation check (codeunit 6192833).

**Why it matters:**
- On v3 these tests are red in the baseline, so every mutant they would cover loses them as covering tests.
- On BC (bcdev, headless) they pass only because the headless session answers the Confirm by default.
- DO's own CI (a client session, R1166) passes all 2,154 tests, because its environment is activated.

**What to find out first, offline:** what DO's CI does to activate the product, and whether a v3 run could do the same in
its baseline setup (a setup codeunit, a dependency's own state, or an al-runner option). Only then pre-commit a fix and
measure it.

**The offline look (PR-331, 2026-11-22). Read from source only, not measured:**
- DO's tests do not activate the product for real. A test library codeunit (68895) is `SingleInstance`. When a test
  switches its flag on, it answers Core's "is in test mode" event, so the activation check passes without the online
  service.
- About 25 test codeunits switch the flag on, and a few switch it off. None of the 5 failing codeunits switches it on
  before its failing tests. 68857, 68874, 68929 and 68934 never do. 68859 does only in a helper that its two later SendMail
  tests call, not its 5 failing ones.
- In BC's test runner, one session runs every codeunit, so SingleInstance state carries from one codeunit to the next. An
  earlier codeunit (the lowest is 68850) leaves the flag on, and the 29 pass.
- al-runner v3 gives each covering test codeunit a fresh session, so the flag is off and Core asks.
- **So this is R1173's carry shape,** and LethAL's baseline setup cannot fix it alone: LethAL does not own the test app.
  - **The al-runner fix:** the one-session carry mode already asked for under R1173.
  - **The project's fix:** switch the mock on in each codeunit's own setup.
- **To measure next:** run one failing codeunit on v3 behind an enabler codeunit in one request, once the carry mode
  exists, or on BC with a client session.
