**What.**
1. **False carry (important).** In `runSession`, `test_app_hash`, history matching and the resume guard use
   `after.packageHash` BEFORE the installed version is proven. A failed proof only withholds the digests. The sequence:
   1. The server serves package P2 while P1 is still installed, so the run measures P1 but records P2.
   2. Later P2 is installed.
   3. Both pre and post reads return P2, so `--resume` carries P1's kills and survivors into a P2 run.
   4. Finished runs seed `--skip-known-survivors` the same way.

   A new test in R-373b explicitly blesses hash P2 with P1 installed.
2. **A legitimate resume is refused (important).** `resolveResume`/`assertSameTestApp` compare against the PRE-lease
   identity. Suppose a prior run measured P2, another session then installed P3, and this session's hook would restore P2.
   The resume is refused before the hook runs. Compare against the proven post-hook identity instead.
3. **Weak hook test (minor).** `envRun`'s `afterLeaseAcquired` does no awaited work, so a fire-and-forget hook call
   would pass the post-hook digest assertions. Add a promise-gated hook, and assert that no read-back happens before release.

**To close.** Reproduce item 1 offline with a fake env tool (served and installed hashes differ). Then record the
hash only from a proven installed identity, refuse resume and history when it is unproven, and red-check each direction.
