**What.** The c02 epic asks for "wall time of verify under 20% of the full run it replaces". The
owner ruled (2026-09-26, before the C02-08 spec was written): record the ratio now, gate it later.
`itest:agreement` asserts per-mutant agreement between `lethal verify` and a fresh full run, and
asserts `verify.timings.totalMs < B.timings.totalMs`, but does not assert the ratio against 0.20.
No file or comment from C02-08 may say the 20% goal was met.

**Measured (Cronus28, 2026-09-26, `fixtures/sandbox-harden`).** Run 1: verify 5812 ms / fresh full
run B 10366 ms = 0.561 (verify `compileMs` 999, `publishMs` 978). Run 2: verify 5747 ms / fresh full
run B 10613 ms = 0.542 (`compileMs` 1065, `publishMs` 874). Both runs also printed verify against the
SOURCE run A: 0.661 and 0.677 (A is not the intended denominator; only B, the fresh full run, is).

**Earlier, on `sandbox-app` (C02-06b, cited by the plan's ruling).** 0.389 and 0.351 (3297 / 9384 ms,
merged tree `06805a0`), and 0.148 with a cold full run as the denominator. Both sandbox-harden
figures and two of the three sandbox-app figures (0.389 and 0.351) are above 0.20. The third, 0.148,
is below it, but its denominator was a COLD full run, which inflates the full run's time; that is why
it does not count against the ruling.

**Why a small fixture cannot close this on its own.** Verify's fixed costs, a test-app compile, one
publish, a lease, a baseline read, and the second unmutated run, do not shrink as the fixture shrinks.
`sandbox-harden` has 21 mutants against `sandbox-app`'s 19, in one batch, and verify does MORE work
per mutant there (four survivors, each with its own covering test plus five new tests, every new test
run twice unmutated), yet the ratio is still well above 0.20. A full run large enough for its variable
cost to dwarf verify's fixed cost has not been measured.

**What would close it.** A gate that asserts the ratio at or under 0.20, run against a fixture or a
real campaign project large enough to measure how the ratio scales, with a WARM full-run denominator
(a cold denominator inflates the ratio's apparent margin, as the 0.148 figure shows).

**Found by.** C02-08 Task 7, per the owner's ruling in
`docs/superpowers/plans/2026-09-26-C02-08-verify-agreement-gate.md` (Open question 1).

**Measured at scale (2026-09-28, sandbox-data, 407 sites, all 68 survivors).** Full pre-commitment
and results: `docs/superpowers/specs/2026-09-27-r270-verify-scale-precommitment.md`. Two live sessions
on Cronus28, `itest:verify-scale` (measurement mode, not gated). Session 1: worst ratio 0.2670
(max V 64415 ms / min B outer 241245 ms), spread max(V)/min(V) 1.014. Session 2: worst ratio 0.2548
(max V 61314 ms / min B outer 240676 ms), spread 1.048. Both NOT under 0.20: the epic's 20% criterion
is still not met on this fixture. Verify's fixed cost F, fit by least squares through the k=1/5/16
scaling points plus the all-survivor point: 6.47 s (session 1), 6.81 s (session 2). Scaling ratios
rise with k in both sessions (session 1: k=1 0.0311, k=5 0.0460, k=16 0.0798, k=68 0.2670; session 2:
k=1 0.0331, k=5 0.0464, k=16 0.0756, k=68 0.2548). Library `runVerify` timeline for one call, labelled
library (not `lethal verify`'s wall time): session 1 totalMs 65858 (baselineMs 11591, mutantsMs 51126,
postMutantsMixedMs 645 mixed, unattributedMs 287); session 2 totalMs 61214 (baselineMs 11749,
mutantsMs 46251, postMutantsMixedMs 544 mixed, unattributedMs 276). Workload limit: the five new tests
measured here are no-ops on one fixture; this says nothing about verify's wall time with real answer
tests or on a real project. No gate was added; status stays open.

**Fixed cost alone cannot reach 0.20 on this fixture (review r1, 2026-09-28).** Formula: remove the
whole fitted intercept F from the slowest verify, `(max V - F) / min(B outer)`. Session 1:
(64415 - 6469.5) / 241245 = **0.2402**. Session 2: (61314 - 6807.1) / 240676 = **0.2265**. Both stay
above 0.20. Reaching 0.20 needs `max V <= 0.20 * min(B outer)`, a cut of 16166 ms (session 1) and
13179 ms (session 2), which is more than each session's whole F (6470 ms and 6807 ms). F is a fitted
intercept, not a measured removable cost, so this is an upper bound on what cutting fixed cost could
buy: the per-survivor cost (845 and 777 ms per survivor) is what decides this fixture's ratio.

**Closed 2026-09-28, owner ruling.** The c02 epic's "verify under 20% of the full run it replaces"
is measured against a hardening round's survivors: the ones an agent wrote tests for, which is what
`lethal verify` replaces a full run for. On that workload it holds by a wide margin (about 0.03 at
k=1, 0.05 at k=5 and 0.08 at k=16, both sessions). Verifying EVERY survivor of a fixture is not the
target, and its measured cost is recorded here as a limit: 0.267 and 0.255 on sandbox-data. The
reason it is higher is the per-survivor cost, since a survivor runs its whole covering test set with
no early kill, and cutting fixed cost cannot close it (above). No gate is added. Merged as the R-270
measurement.
