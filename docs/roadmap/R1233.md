**Filed 2026-11-27 by lethal-preproc, from alrunner's PERF-37 follow-up (al-runner #9232, measured 3 of 3 by alrunner).**

**What happens.** `AlRunnerServer.close()` (`al-runner-server.ts`) writes the shutdown command, waits at most
`SHUTDOWN_REPLY_WAIT_MS` (500 ms) for the reply, then always calls `terminate()`, which SIGTERMs the daemon. With al-runner's
workspace cache (#8446, on main since 2026-11-26, not yet in `current`), serve writes the compiled workspace after it
answers; the SIGTERM right after the reply drops that write.

**Measured on DO (PR-467, main 80960b023):** in a scoped run with 5 lanes, lane 0's mutant daemon built the workspace and
left no `.alcw` entry, whether it was recycled at once or lived about 38 minutes to session end; its recycled successor built
again (`workspaceCache` = `built`).

**Why it matters.** R1183 measured daemon-start compiles at about 10% of DO's serve wall. alrunner measured a cached start at
2-5 s against about 35-70 s compiled. Every recycle, refusal close and session end pays the compile again.

**The fix (PR-470).** After the shutdown reply, wait (bounded) for the process to exit, and SIGTERM only past the bound. The
bound is pre-committed from a measurement on DO. No SIGKILL change. The speed win lands with the first gated `current` that
carries #8446.

**Done (PR-470).** `SHUTDOWN_EXIT_WAIT_MS` = 5 s in `AlRunnerServer.close()`; only EOF or a JSON line that is not a running
request's row counts as the answer (`isShutdownAnswer`).
- **The probe on DO:** 26 closes exited by themselves 2-859 ms after the reply.
- **The measured arm** (main 80960b023, a fresh cache):
  - 26 closes, all exited by themselves, median 161 ms, none at the bound;
  - every lane-0 daemon after the first build read the cache (compile 0.43-0.47 s, against 1.8-5.5 s per rebuild with the
    old close);
  - all 5 restarted daemons read it;
  - verdicts equal, 1121/1121.
