**An env-tool publish that EXITS 0 while reporting failure in its body is invisible to us — and that is R90's measured mode.** `env-tool.ts`'s only post-spawn failure gates are a spawn throw, LethAL's own timeout abort, and `exitCode !== 0`; on exit 0 the sole processing is `reads`-path extraction, and `READS_KEYS` cannot even NAME a `success` field, so no config can express the check today. `deployment-verifier.ts:53` therefore maps such a publish to `indeterminate` (never `failed`), which means `PublishFailedError` is unreachable **by construction** for a tool that exits 0 — R90's documented reproduction is `continia publish` exiting 0 with `{"success": false, "message": "The operation timed out."}`. Consequence: R90's per-tier publish ceiling records an `indeterminate` row rather than a `failed` one for the hosted tier — the exact tier the ceiling exists for — so it never learns that ceiling. The other failure modes DO reach it (exit-non-zero, hang past `envTool.timeoutSeconds`, spawn failure, container-path altool failures); the empty slice is precisely exit-0-with-a-failure-body. Fix: a **config-declared publish success predicate** on env-tool blocks. Three constraints the design must hold. (1) **Vocabulary-neutral** — `env-tool.ts:29-34` states LethAL hardcodes no vendor's status vocabulary, so no hardcoded `success` field name; the config declares path and value, with `requireStatus`/`readyWhen` as the precedents. (2) **Positive-evidence polarity** — a `successWhen` (declared ⇒ absence of the marker is FAILURE) fails closed; a `failWhen` fails open the moment the tool's output shape drifts, which is this project's signature bug wearing a new hat. (3) The thrown error must **carry the tool's stdout verbatim**, because R23's version-conflict recovery parses BC's rejection text out of publish output (`env-tool.ts:271-287`). Acceptance is measurable without a live tier: a stub env-tool exiting 0 and printing a failure body must move its `publish_outcomes` row from `indeterminate` to `failed`; that flip in the store IS the close. Scope: `env-tool.ts` validation + `run()`, `fixtures/README.md`, and a rerun of `itest:envtool`. Filed 2026-08-05 from subsystem C's Task 2 review; one link is inferred rather than recorded — no campaign doc captures the exit code, but `docs/campaign/2026-08-03-do/rung2.result.md` shows the failure surfacing with no cause text, which an exit-non-zero path would have carried verbatim.
