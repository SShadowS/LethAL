**Found 2026-10-09 by R546** (`docs/measurements/2026-10-09-r546-alrunner-bc-agreement.md`,
"Deviations").

**What.** Before compiling, the bcdev backend copies the control app's symbol package into
`bcdev.packageCachePath` as `lethal-control.app` (`BcDevMcpBackend`, the `cp` of
`controlSymbolPath` beside its `mkdir`). It is never removed. R546 pointed `packageCachePath` at a
project's `Test/.alpackages`, which is also the al-runner `packagesDir`: after one bcdev run that
folder held an 18th package that no one put there, and anything that pins the folder by hash or by
count (R396's addendum, R546's slice gate) sees it change. Whether al-runner loads an undeclared app
found there was NOT measured: its verbose log resolves packages by declared dependency (`[dep]`), and
`stageForCompile`'s own comment calls an unused symbol harmless.

**Who hits it.** A user who reuses the project's own `.alpackages` as the bcdev cache, which is the
obvious choice when compiling a real project. Not a verdict risk on its own.

**To close.** Stage the control symbol in a LethAL-owned directory passed to `alc` as a second
package-cache path (alc accepts several), or document that `packageCachePath` must be a dedicated
folder and warn when it holds an `app.json`'s sibling `.alpackages`.

## Fixed (R-553, 2026-10-09)

Built with R553 (plan `docs/superpowers/plans/2026-10-09-r553-r552-screen-prefix-and-control-staging.md`,
predictions `docs/superpowers/specs/2026-10-09-r553-r552-precommitment.md`, Prediction 4).

- **Where the symbol goes.** `stageForCompile` copies `lethal-control.app` into
  `<instrumentedDir>-staged/.lethal-symbols` (`CONTROL_SYMBOL_DIR`), inside the private compile copy
  that `deploy()` and `compileCheck()` already remove. `CompileInput.extraPackageCachePath` carries
  it, and `ArtifactCompiler.compile` sends ONE `/packagecachepath:<packageCachePath>;<that dir>`.
  Without the extra path the argv is byte-identical to before; `compileProject` (the test-app
  compile, the R461 plain check) is unchanged.
- **The user's cache is only read.** Nothing is copied into `packageCachePath` (its `mkdir` stays).
  `scripts/campaign/compile-only.ts` does the same with its own temp copy and `--package-cache`.
- **A leftover gets one warning and is never touched.** A `lethal-control.app` an older LethAL left
  there (nearly every existing user's cache has one; env-tool defaults to `<project>/.alpackages`)
  is named by ONE `console.warn` per backend, which says it is safe to delete. It is never deleted or
  overwritten: two sessions sharing a cache would race, a user's own copy would be lost, and a
  killed process would leave it anyway.
- **Fail loudly.** A `;` or `,` in either path is refused with `ArtifactPrepareError` before any
  spawn (alc splits on both, silently). Never `AlcCompileError`: alc did not run.
- **A leak that predated this.** A throw inside `stageForCompile` after the staged copy existed (an
  unreadable `app.json`, say) left the copy behind, because the callers' `finally` covers only the
  compile. Its body is now wrapped and removes the copy before rethrowing.

**Residual risk.** A leftover stays until the user deletes it. alc resolves the highest version
whatever the order (measured on Linux alc 18.0.2732683, `measure.md` section 4), so an OLDER leftover
loses to LethAL's copy, but a NEWER one would win over `controlSymbolPath`. The selector uses only
`LC Control State`, and the harness verifier checks the server's control version before every
deploy. **The Windows host's alc (18.0.2668733) was NOT measured with a two-path
`/packagecachepath:` list**; every bcdev gate run from the kraken container uses the Linux alc.

**Offline evidence.** `compile-only.ts` with Linux alc (18.0.2819426) on `fixtures/sandbox-app`,
against a scratch copy of that fixture's `.alpackages` with `lethal-control.app` removed and a
`lethal-control.app` 1.0.0.20 built offline into scratch as `--control-symbol`: exit 0 (19 raw specs
compiled), and the copy's listing (6 files; name, size, sha256, mtimeMs) identical before and after,
with no `lethal-control.app`. Live evidence is Prediction 4 step 3 (`itest:bcdev` with the fixture
cache's leftover moved aside), run by the lane.
