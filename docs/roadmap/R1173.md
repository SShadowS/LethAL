**Reported by** GitHub #53 (an external user). **Reproduced** in PR-327 with an invented probe
(`/coord/handoff/PR-327/probe/`, findings in `/coord/handoff/PR-327/findings.md`):
- a `SingleInstance` flag that test codeunit A sets and resets;
- test codeunit B, which expects the plain answer and also calls the reset, so it covers it.
- The `empty-block` mutant on the reset **survived on al-runner v3 (main-ccd0f823d) and was killed on bcdev** (bc2, BC 28.4).

**Where the state stops crossing codeunits (LethAL's side):**
- every covering test codeunit is sent as its own entry, which starts fresh;
- LethAL's v3 capability contract requires `batch-no-cross-singleinstance` (`al-runner-v3-contract.ts`, BATCH_FACTS);
- al-runner offers a SingleInstance "lane": with `strictOrder`, a writer and reader across codeunits share the state.
  Without it, the lane only returns `orderHints` (fact `batch-lane-hint-only`).
- LethAL never sends `strictOrder` for mutant runs (PR-114a: alpha.12 refused it).

**The size on c2** (DO, numbers only):
- 157 of 8,536 survivors have their site in one of DO's 10 `SingleInstance` codeunits;
- **90** of those are covered by 2 or more test codeunits, where the carry-over can matter.
- That is an upper bound: not every one is a false survivor.

**The plan:**
- (a) a by-name note on such v3 survivors: "survived; touches SingleInstance state; cross-codeunit carry-over not
  observable on al-runner-v3";
- (b) the fix: send those mutants' covering codeunits as one `strictOrder` lane request, pre-committed and measured on
  the probe and then on c2's 90.
