Found by coord PR-391 (lethal-bugs, 2026-11-23); the cause was read from the code by lethal-code. Evidence:
`/coord/handoff/PR-391/` (`ab-P1`, `ab-offP`, `ab-probeM`, `probe-lines.txt`, `ab.sh`). Related: [[R1151]].

**The rule, which is correct.** `orchestrator.ts` (`runMutantsParallel`, PR-241):
`budgeted = args.timeBudget !== undefined && Number.isFinite(args.timeBudget.seconds)`, and
`packCap = split && !budgeted ? owner.packEntryCap?.() : undefined`. Under a budget, R912 clamps each prefetch request's
deadline to the time left, and a stop must lose at most one window's request, never a packed one.

**What goes wrong: the run says the opposite.**
- The backend still prints `[lethal] al-runner-v3 pack-entries 64 (PR-241 A/B; experimental)`, read from
  `LETHAL_V3_PACK_ENTRIES`, whether or not the orchestrator then packs.
- Nothing in stderr, the report or the events says packing was switched off by the budget.

**What it cost.**
- PR-391's driver passed `--time-budget 10800` as a safety cap. PR-241's and PR-267's original driver deliberately passed none.
- So all four arms (P1 and offP on master b521dd2b7, M1 and the probe on lethal/pr-267) ran unpacked.
- The results read as if packing were broken: the same 76 prefetch requests over the same 63 units with and without
  `LETHAL_V3_PACK_ENTRIES`, and every prefetch call holding exactly 1 unit.
- R1151's A/B therefore measured nothing about its lever, and R1151 stays open.
- Real DO runs (c3, c4, the combined runs, PR-359) pass no budget, so they are not affected.
  - Measured on c4 (PR-379, 2026-11-23, no budget, `LETHAL_V3_PACK_ENTRIES=256`): the main run prefetched 1,390 units in
    897 prefetch requests, about 1.55 units per request. So packing engages there.

**The fix (lethal-code, PR-395):** the notice names the switch-off. For example: "pack-entries 64 set, but packing is OFF in
this run: a finite --time-budget turns it off (R912)", once per session, wherever the cap is read and the budget is finite.
- A unit test asserts the text in both directions: budgeted gives the OFF wording; unbudgeted gives today's line.
- An A/B driver for packing caps its time with an outer `timeout`, never `--time-budget`.

**The re-measure (PR-391's no-budget re-run, after PR-394 and before PR-359):** offP, P and M again with no
`--time-budget`, capped by an outer `timeout`, on CPUs 0-11. It answers both R1151 and the packing check: offP and P must
differ in prefetch requests, or packing really does not engage.
