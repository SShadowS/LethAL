**Filed by the orchestrator's ruling on the R-323 plan (2026-09-29), Decision 3.**

**The gap.** Since [[R330]] any name a trigger declares in its own header (parameters, plain `var`
locals, `#if` locals) is unknown to type resolution, and since [[R323]] so is a trigger's named
return. The receiver path is different for plain `var` locals: `triggerScopeVar` in
`receiver.ts` reads the trigger's plain `var` section, so Tier-2 claims still reach those. That is the safe direction: no mutant is built on a wrong type. The cost is
under-generation: typed operators (`swap-additive`, `swap-call-arguments` and others) find no site
that involves those names. Recovery of such sites is also the subject of [[R333]] and [[R334]].

**Size.** At least 46 BaseApp triggers declare a named return (R-323 plan, Decision 3). The full
count of affected sites is not measured.

**Fix direction.** Type trigger header names from their own declarations, with the same
hide-a-global rule that procedures use. Closes with that change, repros for parameter, local and
named return in a trigger, `alc` on each, and a per-mutant diff on BaseApp showing only added,
compiling mutants.

**Fixed (R-340, 2026-10-09; plan `docs/superpowers/plans/2026-10-09-r340-trigger-header-names.md` r2, two opus plan
reviews, `/coord/handoff/R-340/`).**
- **Typing:** inside a trigger, a header name (parameter, plain `var` local, named return) is typed by its own
  declaration, read from the ENCLOSING trigger node (by position, so a trigger name repeated across an object cannot
  mix headers), before the implicit record's fields and the globals. A `#if`-declared header name stays unknown, and a
  trigger that parsed with an ERROR types nothing. Why R330's and R323's reasons no longer hold: R330 made these names
  unknown because a name LOOKUP could answer with another trigger's declarations or fall through to the globals; this
  reads the trigger's own node and still finds the header first. R323's trigger rule was parity with R330.
- **Precedence measured with alc** (the collision matrix, `scripts/r340-probe/`): a header name beats a same-named field
  of the implicit record in table, page, page/table extension, report data item, request page, xmlport and TableNo
  `OnRun` triggers; instrumenting the 12 emitted `Z - Z` mutants into one project compiles (it would fail AL0175 had
  alc resolved `Z` to the Text field).
- **Hang safety (review C1, r2 Important-1):** a loop write to a trigger header name the hang path does not resolve
  (parameter, named return; repeat/while/for; a header record parameter's field) is refused by name. This also closed a
  master door: hang-capable `remove-assignment` there (0 instances found in any corpus). And `swap-call-arguments` now
  refuses a swap whose argument an enclosing loop reads by name (`Dec(Steps, One)` -> `Dec(One, Steps)` compiles and
  never ends), in triggers AND procedures. Residual, an existing documented exclusion now also in triggers: a target
  read only in the loop BODY (an indirect flag such as `Done := Left <= 0; until Done`).
- **Measured, final build vs master 97d295c7** (`/coord/handoff/R-340/`, census scripts in `scratch/`):

  | corpus | trigger files: sites added | whole project swap-call-arguments: added / REFUSED / pair changed |

  No other operator lost a site. The site and identity-key diffs cannot see a swap that changes PAIR under an unchanged
  key (BaseApp has 2 by mutated text), which is why the scheme bump is unconditional.
