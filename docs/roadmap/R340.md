**Filed by the orchestrator's ruling on the R-323 plan (2026-09-29), Decision 3.**

**The gap.** Since [[R330]] any name a trigger declares in its own header (parameters, plain `var`
locals, `#if` locals) is unknown to type resolution, and since [[R323]] so is a trigger's named
return. The receiver path is different for plain `var` locals: `triggerScopeVar` in
`receiver.ts` reads the trigger's plain `var` section, so Tier-2 claims still reach those. That is the safe direction: no mutant is built on a wrong type. The cost is
under-generation: typed operators (`swap-additive`, `swap-call-arguments` and others) find no site
that involves those names. Recovery of such sites is also the subject of [[R333]] and [[R334]].

**Size.** At least 46 BaseApp triggers declare a named return (R-323 plan, Decision 3). The full
count of affected sites is not measured.

**Fix direction.** Type trigger header names from their own declarations, with the same
hide-a-global rule that procedures use. Closes with that change, repros for parameter, local and
named return in a trigger, `alc` on each, and a per-mutant diff on BaseApp showing only added,
compiling mutants.
