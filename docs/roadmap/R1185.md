**Found by** lethal-code, 2026-11-23, drafting R1182's adoption plan (`/coord/handoff/R1182/adoption-plan.md` §0).

**The hazard:**
- PERF-01 step 3's ask (`/coord/handoff/from-alrunner/PERF-01-step3-ask.md`) says the replay is "ON by default;
  ALRUNNER_LOGIN_REPLAY=0 turns it off".
- LethAL passes the parent's environment to every al-runner child (`mergeChildEnv`). It pinned only the seed (R807), and
  dropped only an ambient `AL_STRICT_SEQUENTIAL` (PR-340).
- So a build with the replay whose update-gate readings equal the pin's would become `current` mechanically, and turn the
  replay on in every run before R1182's pre-committed DO A/B. An ambient `ALRUNNER_LOGIN_REPLAY_CHECK=1` left in a shell
  would reach every daemon too.

**The fix (PR-360, pre-commitment `docs/superpowers/specs/2026-11-23-pr360-login-replay-off-pin.md`):**
- `v3ChildEnv` sets `ALRUNNER_LOGIN_REPLAY=0` after the extras, so no caller turns it on; `v3MutantDaemonEnv` builds on
  it, and `v3UnpinnedEnv` (O1) sets it too.
- `mergeChildEnv` drops every ambient name starting with `ALRUNNER_LOGIN_REPLAY` unless the extras set that name.
- The Opus build review's LOW items: the contract probe and leg C's fact servers now pass their own variables INTO
  `v3ChildEnv`, so they cannot override its pins (a source guard pins this). `scripts/keep-census.ts` and
  `scripts/upstream-repros.ts` start al-runner with `mergeChildEnv(v3ChildEnv())`, LethAL's own pins, instead of the
  shell's environment plus the seed.
- 0 moves: no binary under `/work/tools/al-runner-v3/` carries the variable's name (PR-320's replay build does, the
  control).

**Related:** R1182 (adopting the replay behind a measured flag replaces this pin for the daemons it covers), R807, PR-340.
