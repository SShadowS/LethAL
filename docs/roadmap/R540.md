**Priority.** Filed 2026-10-09 by the R534 build (plan r2, roadmap item 4; review I2). A FALSE KILL
is possible: a row whose only evidence is al-runner refusing a surface is scored `killed`.

**What.** [[R534]] (D3) scores a row `runner-refused` only when its message has
`<Type>: out-of-scope: ` at the type position (`RUNNER_REFUSAL` in
`packages/runner/src/al-runner-backend.ts`). al-runner has other refusal kinds that do not carry
that prefix: `BcShapeGapException` and `BcAppSymbolReadException`. And a refusal raised inside a
`[TryFunction]` (`[oos-in-try]`) is trapped by the AL code, so the test sees a `false` return
instead of the refusal: depending on what the test asserts, that is a kill or a pass, and neither
says anything about the mutant on BC.

**Evidence.** `/coord/handoff/R-534/review-plan-opus.md` I2; `/coord/handoff/R-534/measure.md`
"What the source says"; al-runner source at 43f7617 (`OutOfScopeMessage.Prefix`, the exception
types named above).

**To close.** Measure each kind's row on the current build (message and status). Extend the match
to the measured refusal kinds, each with a near-miss test. For the trapped refusal, which leaves no
trace in the row, decide whether al-runner can report it (an upstream request) or whether LethAL
can only say the backend is not authoritative there.

**v2 retired (R654); re-measure on v3.** The refusal kinds above are the .NET al-runner's, deleted in R654 S3
(35f3c67f). `RUNNER_REFUSAL` still exists (now in `al-runner-rows.ts`), and the Rust al-runner reaches it through
`verdictFromRunnerTest`. Which refusal texts v3 writes, and whether any of them can still score a kill or a pass,
is not measured. The v3 gate's contract facts cover some v3 refusals (`refusal-row-shape`, #5608, #5623), but not
this list.

**Closed 2026-10-23 by ruling (coord task R-540, lethal-code): v3 cannot score a refusal as a kill.** Measured
offline on alpha.2 (91253f2d6) and edge (57f1e4f98); the evidence is in `/coord/handoff/R-540/`.
- **How a v3 row is scored.** In `v3RowVerdict`, a `notRun` row is never a kill. K1(a) turns any pass/fail row
  that holds `NotRun: out-of-scope:` into `error` (R675). Only a plain `status: "fail"` row can still be a kill,
  through `verdictFromRunnerTest`. `RUNNER_REFUSAL` is effectively dead for v3: the one row it could match is a user
  `Error('X: out-of-scope: …')`, which it turns into `error`, the safe direction.
- **v3 writes every refusal as not run.** By the upstream source (93415c0) and by both binaries, every refusal,
  unpinned error text and unsupported surface is written as `notRun: true`, so LethAL scores it `error`. Only an AL
  error, BC's "UI handlers not executed" rule, and an internal signal case that no AL can reach are written as a
  fail.
- **A trap does not swallow a refusal.** An invented probe (codeunits 50980-50986) ran a runtime refusal (`Round`
  with direction `'q'`) inside a `[TryFunction]`, under `asserterror` and in a guarded `Codeunit.Run`, and alone.
  All four are `notRun`, so `error`, identical on both builds. A v3 refusal ends the whole test, unlike v2's
  `[oos-in-try]`.
- **Stored v3 reports:** 0 of 8,275 kills carry any refusal, not-pinned, unsupported or not-trusted wording.
- **v3 difference from BC, filed upstream:** `Round` with an invalid direction is refused instead of raising BC's
  error, so a trap cannot catch it:
  [aldevtools/BusinessCentral.AL.Runner#5746](https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5746).
  It is safe for LethAL (a not-run row is an error), but it differs from BC.
