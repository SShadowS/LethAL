**Found 2026-10-05 under R-469** (an alc probe for R469's protected-var question). A consequence of
R254, which made `reportextension` a carrier kind.

**What.** PLAN's `injectSelectorVarIntoObject` (`compile-plan.ts`) declares
`MutationSelector: Codeunit "Mutation Selector"` in EVERY object that carries a mutant. A report's
globals are visible to its reportextension, so when a report and a reportextension of it sit in
the SAME project and both carry mutants, the instrumented project declares the same global twice.
MEASURED with alc 18.0.43 on a self-contained probe (a report and a reportextension of it, each
with `var MutationSelector: Codeunit "Mutation Selector";`): `error AL0155: A member of type
GlobalVariable with name 'MutationSelector' is already defined in Report 'R' by the extension ...`,
on both declarations. It needs no `protected`: a plain `var` on both sides fails. Tables with
tableextensions and pages with pageextensions do NOT collide (the extension's own declaration
shadows the base's, even a protected one of another type, measured in the same probe).

**What a run does today (traced, not run live).**
- bcdev: the deploy throws `AlcCompileError`; R461's plain build compiles (the unmutated target
  has no selector), so bisection runs. No single mutant breaks the compile (it is a pair
  condition), so `bisectFailingMutant` cannot confirm a culprit and answers `environmental`.
  Every mutant in the batch's execute set is then recorded `error` with that note, and the batch
  is abandoned. With one batch, that is the whole run. Loud, not a silent wrong verdict.
- al-runner: `al-runner <bundle>` on the same probe compiles and exits 0, so al-runner accepts an
  artifact BC rejects. Both declarations have the same type, so gating is most likely unaffected
  there, but the two backends disagree about whether the run is valid at all.

**Why no gate caught it.** `itest:tables`' R254 arm keeps its base report `Data Band Report` code
free (so the arm measures the extension's own coverage), so the base never gets a selector. R254's
BaseApp count (+543 reportextension mutants in 13 files) counted sites and never compiled a project
in which a base report and its extension both carry mutants (confirmed by R254's author).

**To close.** Census the same-project report/reportextension pairs where both carry deployed
mutants (BaseApp, CDO). Fix in PLAN: give a reportextension's selector a name that cannot collide,
or reuse the base report's visible one; prefer the variant with the least state. Pin it with a
fixture-free unit test of the emitted text AND an alc probe of the emitted pair. Say whether keys
move.
