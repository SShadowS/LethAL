Found by the opus build review of coord task R-901 (R895), 2026-11-10. Filed at the orchestrator's word (R-902).

**What.** `buildExecutionContexts` (report.ts) gives a carried group the `guiAllowed` and `clientType` of
`measuredExecutionContext(runner, caps)`, where `caps` is THIS session's backend. Since R895 those differ by backend: bcdev's fenced path
says `GuiAllowed=No`, al-runner v3 says Yes. A verdict carried from a run on one backend into a session on the other would be labelled
with the branch it did NOT run.

**Why it is closed, not open.** A carried verdict comes only from `--resume` or `--resume-run`, and both refuse another backend:
- `--resume`: `findResumableRun` searches by project, backend and configuration fingerprint (and, on v3, the runner build), so a run on
  another backend is never found. Pinned since coord R-943 by `resume.test.ts` ("R903: a run on ANOTHER backend is never found"): a
  v3 run searched from bcdev, where only the backend key can exclude it.
- `--resume-run`: `runSession` throws "ran on backend X, but this session uses Y — verdicts are not interchangeable across backends",
  pinned by `r619-one-lend.test.ts`.

So every carried group is labelled by the backend that measured it. The same holds within v3 across builds (the search keys on the build).

**Reopen when** any change lets verdicts cross backends (a resume, a history carry, a merge of two runs): the carried group must then
take its label from the prior run's recorded backend, not from `caps`.
