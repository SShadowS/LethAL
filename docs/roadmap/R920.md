Found by coord task R-915 (BC.History E-Document Core on al-runner v3, 2026-11-11). Evidence: `/coord/handoff/R-915/edoc.s1.*`. Related: [[R580]], [[R602]], [[R907]], [[R918]].

**What happened.** E-Document Core's report says `al-runner-v3-coverage-off`, naming one file: `src/Integration/EDocumentIntegration.Enum.al`. That file is an outer `#if` around an enum whose HEADER differs per arm (`#if CLEAN26 enum ... #else enum ... implements ... #endif`). The parser makes the header a `preproc_split_declaration`. R580 admits a wrapper holding only code-free objects, but a split declaration is never in `CODE_FREE_KINDS`, so the file counted as an unadmitted wrapper. One enum, with no code and no mutants, turned coverage off for all 15,287 mutants. Each mutant then ran against all 223 green tests: about 850 s each, 19 mutants in a 4-hour session.

**Invented repro.** A file `#if not X` / `#if Y` `enum 50100 "E"` `#else` `enum 50100 "E" implements "I"` `#endif` `{ value(0; A) { } }` `#endif`, next to any codeunit with tests. `lethal run --backend al-runner-v3` warns `al-runner-v3-coverage-off` naming the enum file.

**Fix (this task, branch `lethal/r915`).** `alRunnerAdmitsWrappedFile` reads a split declaration as code-free when every arm's keyword names a code-free kind, and `holdsCode` still holds. Tests: an enum with a split header is admitted; a split header whose arms mix an enum and a codeunit stays refused; a codeunit with a split header stays refused.
