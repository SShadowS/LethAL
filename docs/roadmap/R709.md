**Filed 2026-10-24 by lethal-preproc during R-707.** Evidence: `/coord/handoff/R-707/measure.md` (bc2, step 4),
`scripts/r707-probe/`. Related: [[R605]], [[R707]].

**What was measured (bc2).** Target A 1.0.0.1 and a dependent B were installed. A was upgraded to 1.0.0.2 with a
procedure removed that B calls. BC recompiled B, found the break, and refused with 422:

> `error AL0132: 'Codeunit "R707 Target"' does not contain a definition for 'Answer'`. **The original extensions
> could not be restored** due to Cannot install the extension R707 Probe Target ... 1.0.0.1 because a newer version
> 1.0.0.2 was already installed. Extensions that were previously installed but could not be reinstalled. These
> extensions should be manually reinstalled ...

State after: A had one row, 1.0.0.1, `isInstalled = false`. B had no row at all, and its web service answered 404.
So the refusal removed the dependent and left the target uninstalled. A refused publish of the SAME version, in
place (step 3), did restore. The cause BC names is the installed-version record from [[R605]]: the failed upgrade
raised the record to 1.0.0.2, so the old 1.0.0.1 cannot be put back.

**Why.** BC recompiles an INSTALLED dependent from the source inside its RESIDENT package, not from the new
source a script has on disk (measure.md: the AL0135 is from the dependent's own source).

**Who can trigger it.**
- BOTH `scripts/bc-linux-setup.ts` and `scripts/bc-republish.ts` could, before R-707, on a CO-CHANGE: a target
  change that compiles with the NEW tests source (which both scripts checked) but breaks the RESIDENT tests
  source. Publishing the new tests app together with the target does not help, because BC checks the resident one
  first. Both now read each installed dependent's resident source, compile it against the new target build, and
  refuse `resident-dependent-breaks` before anything is sent. A dependent that is not installed has no resident
  source and is not checked. A check that fails for another reason (a symbol download, no alc) is refused as
  `dependent check failed (not a compile result)`. Only FIXTURE dependents are checked: an ad-hoc app that
  depends on a fixture target is not.
- Anyone publishing by hand over the dev endpoint, or a future script that skips the check.
- A run's own minted target deploy under an old tests app CAN trigger it. Traced by R-709 (part 1 below), and a run now
  refuses it by name.

**How to recover a stripped server.** See docs/gates/servers.md (R-709, part 1 below). The setup script refuses
the stripped row, so on bc1-bc3 the owner restarts the server and setup is run.

**Closed by R-709 and R-709b (as ruled), with these limits left open elsewhere:**
- Only an AL compile break was measured as a cause of the refusal. A run refuses on BC's "could not be restored"
  wording whatever the cause.
- Clearing the version record without a restart stays [[R605]]'s open question.
- A script that removes the dependent first is [[R711]].
- Prevention for non-fixture dependents is [[R727]].
- The list's format through altool is [[R728]].

**R-709 (lethal-preproc, 2026-10-24), part 1: a run no longer carries on.** Evidence:
`/coord/handoff/R-709/measure.md`.
- **Read:** every `lethal run` publishes the instrumented target as an upgrade over the installed tests app. So a user
  who changes a target procedure and its tests, and runs before republishing the tests app, reaches this state.
- **The old behaviour:** `parseVersionConflict` read BC's restore sentence (it embeds "a newer version X was already
  installed") as an ordinary downgrade conflict. The run re-stamped, published the target AGAIN (it succeeds once the
  dependents are gone), and the baseline then refused with the wrong cause, `StaleTestAppError`. LethAL never said that
  BC had removed the tests app and every other installed dependent.
- **Now:**
  - `restoreFailed` recognises the restore text, and `parseVersionConflict` returns null on it.
  - `runSession` refuses with `UpgradeNotRestoredError`, after the first publish and after a conflict retry, with no
    retry. The error keeps BC's text verbatim (it names the removed apps) and prints the recovery steps, which are also
    in docs/gates/servers.md.
  - Recovery is NOT a script run: `decideApp` refuses the stripped target row (not installed) as `content-unknown`,
    so setup and bc-republish stop and publish nothing. On bc1-bc3 the owner restarts the server, then setup is run.
- **Limits:**
  - A SECOND run on the stripped server is accepted by BC, because nothing depends on the target any more. It then
    refuses at the baseline with `StaleTestAppError` ("found 0"), which is a refusal but names the stale tests app,
    not the removal.
  - The env-tool path keeps only 200 characters of a non-JSON tool answer, so BC's phrase can be cut off there. That
    run still stops, but on a generic publish error.
- **Part 2** (below): BC's list of removed apps is now parsed.
- **Prevention** for non-fixture dependents is filed as [[R727]].

**R-709b (lethal-preproc, 2026-10-24), part 2: BC's list, measured and parsed.** Evidence:
`/coord/handoff/R-709b/measure.md` (bc2 probe `scripts/r709-probe/`, full bodies, pre-commitment
`docs/superpowers/specs/2026-10-24-r709b-restore-list-probe-precommitment.md`).
- **The format:** after "... you can use the 'Full Dependency Publishing' command to do so:" BC writes one
  `<name> by <publisher>` per line, then a blank line. The TARGET comes first, then the dependents. Their order is not
  established (publish, name and id order all agreed). BC gives NO versions. It was measured with two dependents and
  with one, over a DIRECT HTTP publish. Through altool, as a real run publishes, the format is not measured
  ([[R728]]). Every plausible altool shape (escaped CRLF, BC's trailing blank lines dropped, altool's own stderr line
  after the list) makes the parser fail closed, so the refusal then says the list could not be read and shows BC's
  text.
- **Post-state:** this differs from R-707. One dependent had no row, while the other kept its row, published but not
  installed. Neither was installed, and the text lists both.
- **Built:** `notReinstalledApps` reads that list. It accepts real or escaped (`\n`) line breaks, and is fail-closed:
  null, never `[]`, when the list is missing or a line is not in the form. `UpgradeNotRestoredError` names every
  listed app ("name by publisher"), or says the list could not be read, and keeps BC's text either way.
- **Leftovers on bc2** until a restart (R605): installed-version records for `R709 Probe Target` (9ff560dd…) and
  `R709 Probe Target Solo` (4ccbac7b…) at 1.0.0.2. Nothing is installed.
