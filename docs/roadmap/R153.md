LethAL is unusually well shaped for an agent to drive: one binary, flags rather than prompts, exit
codes that separate ok from error from quarantined (0 / 1 / 3), a read-only pre-flight in `doctor`,
`--dry-run`, a versioned JSON report, an NDJSON stream flushed per event, and a projection whose
whole purpose is telling a consumer what the data means. What it does not have is anything that
says so to a consumer that has not read the source.

- `.claude/skills/` holds skills for developing THIS repository (al-compile, live-gate,
  measurement-campaign, ...). None of them is about using the tool.
- `README.md` is written for a human developer. It documents `--progress-out` as "a structured feed
  for agents/CI" in one table cell and stops there.
- There is no MCP server exposing LethAL. The `@modelcontextprotocol/sdk` dependency in
  `packages/runner` is a CLIENT, used to reach `bc-dev-mcp`.

So an agent author has to derive the contract by reading `cli.ts` and `explain.ts`. Everything they
would derive is already decided and already documented in the help text; it is simply not collected
anywhere they will look.

What such a document has to carry, because each of these is a wrong answer an agent would otherwise
reach on its own:

- The exact argv for a scoped run, and that an unscoped run on a real project is refused by default
  above 1,000 mutation sites.
- Exit codes 0 / 1 / 3, and that 3 means the run refused to vouch for its own verdicts — not that
  the tests failed.
- Which file answers which question: `--out` for the record, `--progress-out` to follow a run,
  `explain` for what it means.
- That verdict lines in the NDJSON stream are PROVISIONAL until `session-finished`, because a later
  `batch-invalidated` can supersede one already written.
- The two interpretation rules the help text already states: read `validity` before quoting
  `mutationScore`, and a survivor is a lead, not a proven test-suite gap.
- That `explain --top` bounds the output and that `survivorSelection` says what was dropped
  ([[R150]]).

**What shipped.** Two documents, and a test that keeps them true:

- `docs/using-lethal-from-an-agent.md` — the reference. Every bullet above, plus the three output
  surfaces and what each one answers.
- `skills/lethal-mutation-testing/SKILL.md` — the same contract as a copyable skill, with
  frontmatter, deliberately standalone: a skill that only points elsewhere is useless the moment it
  is copied out of this repository.
- `packages/runner/tests/agent-contract.test.ts` — the anti-drift guard. Every `--flag` either
  document names must exist in `RUN_FLAGS`; the exit codes must equal `QUARANTINED_EXIT_CODE`; the
  four schema versions the reference states must equal the constants; and each of the four rules
  must still be present. Red-checked: adding `--fast-mode` to the skill reddens the flag test.

That guard matters more here than for most docs precisely because these are meant to be COPIED. A
stale claim keeps working for whoever pasted it long after this repository has moved on, so the
promises are asserted against constants rather than reviewed by reading.

An MCP server exposing LethAL was NOT built and is not filed: the CLI contract is the thing people
asked for, and an MCP surface would be a second contract to keep in step with it. Worth revisiting
only if someone actually needs it.

Evidence: the two files above, `agent-contract.test.ts`, and the README's new "Driving it from an
agent, a script or CI" section. Related: [[R151]] (the pre-flight, now parseable), [[R152]] (no
schema to validate against yet), [[R150]] (the output an agent can now bound).
