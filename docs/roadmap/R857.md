Measured in [[R856]]: `/coord/handoff/R-856/day/result.md`. A test that calls `WorkDate(D)` leaves `D` set for the tests after it in the same codeunit on al-runner v3, which sends a whole codeunit. bcdev runs one test method per call, so the date is gone on BC. A verdict can differ for a test that reads a date after an earlier test set it.

Upstream #7207 records the single-method side of the difference.

The `sandbox-dates` fixture does not exercise this: each test that sets a date sits alone in its codeunit. The limit is named in the header of `packages/builtin-tier2/src/swap-workdate-today.ts`.

**Ruling (owner, 2026-11-07).** A mode, off by default: `--isolate-tests`, on v3 only. A default run keeps its whole-codeunit calls and its speed, so a default run can still differ from BC this way. The mode is the answer; the default does not change.

**What the mode does.** Every test runs alone: one entry per test with `runSelectedOnly`, and at the baseline one process per test, as an entry carries no coverage. `Codeunit1.Alpha` also selects `AlphaTwo` (measured), so an entry excludes the longer names. It needs serve-entries and is refused by name where that is unavailable. A run with it and a run without it share nothing: the mode is in the fingerprint and in `runner_build`, which every lend (resume, history, baseline snapshot) reads. It is refused on bcdev.

**What BC does, measured on bc1 (28.4.53241.56590, `/coord/handoff/R-857/plan.md`).** The mode matches one `RunMutant` call per test on every kind probed. It does not match BC's grouped path: there `GlobalLanguage` and a SingleInstance codeunit carry from one test to the next, even across codeunits, while under the mode they are fresh. So it removes one source of false readings; it does not make v3 equal to BC. Probes 6 and 7 (CDO's codeunits 68901 and 68911, bc3) were not run, as neither answer would change the design.

**Two corrections, kept as the record.**
- *Speed.* I first told the owner about +30% on the test phase. As a single figure that was wrong. Re-measured on `6bb821b98`, the test phase was between about the same (one 21-test codeunit) and about twice (all of CDO's Test app), with low confidence on a loaded machine. Neither figure holds for a whole run, as neither counted the baseline. The first real run below took 2.8 times the default, nearly all of it the baseline.
- *The flag pattern.* I predicted that BC's whole-codeunit call would fail a second test that skips `Initialize` on an `IsInitialized` flag, as v3 does. It passes on every BC path. BC rolls back after the codeunit, so the first test's row is still there; v3 under `testIsolation: test` rolls back after each test, so the flag says set and the row is gone. A whole-codeunit run on v3 can therefore report a failure BC does not. The mode removes it, as each test runs its own `Initialize`.

**Per mutant, one real suite (R-864).** CDO's D1 slice, 65 mutants, build `edge-6bb821b98`, both coverage modes: 0 verdicts, 0 killing tests and 0 covering sets move, and the 53 state notes go to 0. That is one suite, whose 21 tests pass both ways at baseline. On the whole CDO Test app 10 of 1,238 baseline rows move, 9 of them because a refused test no longer stops the rest of its codeunit. Per-mutant moves on that set are not measured. Evidence: `/coord/handoff/R-864/`.

**Speed, on a loaded machine (load average 8 to 15), records, not comparisons with any talk figure.** D1 with coverage: 39.7 s default, 113.1 s with the mode, after the kill-pair fix; baseline 4.8 s and 75.4 s; mutants 7.0 s and 11.1 s. Before that fix the same run took 127.9 s. D1 without coverage, also before that fix: 22.3 s and 135.1 s, about 6 times. So a run costs roughly 3 to 6 times the default here, and more where a baseline is a larger share. [[R866]] is the baseline's cost.

**What pins it.** Leg ISO of the v3 gate: a whole-codeunit entry must leak a date to a reader, and the same reader run alone must not, so a build that accepted `runSelectedOnly` and ignored it fails the gate. It is outside `V3_GATE_LEGS`, so `current` stays gated. A report carries `isolateTests` on its execution context, and a default report has no such key. `--resume` across the flag reads "no unfinished run", without naming the mode: refused, not named.
