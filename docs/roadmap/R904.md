Found by coord task R-902 round 1 (2026-11-10), question from the orchestrator. Evidence: `/coord/handoff/R-902/r1-sa.*`,
`r1-eu3.*`, `r1-sbi.*`. Related: [[R885]] (the warning and the no-green note).

**What.** With `downloadDemoData: false` and no demo data in `cacheDir`, al-runner v3 runs with test data off: a test that reads the
CRONUS rows the dependency apps create fails. R885 made LethAL say so in two places: a stderr warning
(`al-runner-v3-test-data-off`), and the note on every mutant when NO baseline test is green. Measured in round 1:
- **0 green** (EU 3-Party Trade Purchase 0/14, Simplified Bank Statement Import 0/6): fine. Nothing is scored, every mutant is
  `error` with the note, exit 4.
- **Partly green** (Statistical Accounts 2/18): the run scored 410 mutants against the 2 green tests, and printed "score 2.2%, 401
  survived, 1004 no-coverage". The report's caveats and the console summary never mention test data. The 16 red tests fail with
  ordinary text ("There is nothing to register.", "Queue is not empty"), not with a refusal, so nothing in the report points at the
  cause. The survivors and no-coverage counts describe the missing setup, not the suite.

**Fix.** When v3 says test data is off and any baseline test did not pass, stop the run by name before any mutant, naming the two
ways out (fill the cache, or let al-runner download it). The 0-green case keeps R885's per-mutant note.
