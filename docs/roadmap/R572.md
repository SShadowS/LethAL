**Filed 2026-10-10 by coord task R-570** (shape I3a of the plan review, `/coord/handoff/R-570/review-opus-plan-r1.md`;
measured in the build, `/coord/handoff/R-570/scratch/i3.ts`, outputs `out-i3/`). A plausible hang that is NOT
refused.

**What.** [[R570]] refuses a cursor-shaped procedure in another project object when the loop's EXIT calls it (its
condition, or a body exit guard). The usual iterator idiom stores the callee's result in a flag first: the body
assigns `More := X.GetNext()` and the condition reads only `More`. R570 does not follow the flag to the call, so the
callee's sites stay deployed.

**Measured price** (deployed mutants in the extra callee procedures, on the R570 r2 build `001c5cbc`, before I3b, over R480's
`indirectFeeds` of the loop's exit parts, chains followed as in R570):

|---|---|---|---|
| DC | 192,462 | 84 (DC Cloud, 21 loops, 7 procedures) | 0.044% |
| DO | 78,545 | 0 | 0 |

| fixtures | 1,745 | 0 | 0 |

CDO is over the 0.05% bar, so R570 did not build it. No sample was read: the hang rate is not known.

**To close.** Read a sample (the CDO procedure first, since it alone sets the price), then refuse it with a narrower
rule (for example only flags whose every write in the body is the callee's result) or close it with a ruling.
