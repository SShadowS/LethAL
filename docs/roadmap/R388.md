**An idea from al-runner's author, 2026-10-01; nothing built.** Few partners run Microsoft's test
apps, but those tests exercise exactly the base code an extension changes: a `tableextension` or
`pageextension` trigger, or an event subscriber, runs inside Microsoft's own flows. A mode that picks
the Microsoft tests reaching the objects and events an app touches, and runs those against the app,
would give a real suite where the app's own suite is thin. For mutation testing, it would let a
mutant in a subscriber be killed by a Microsoft test.

Nothing in the roadmap covers it (searched 2026-10-01; R077 is about LethAL's own test runner).

**Open questions, none measured:**
- Selection: the call-path walk R-371 builds for test digests already follows subscribers and
  extension triggers; whether it can run in the other direction (from the app's objects to the
  Microsoft tests that reach them) at BaseApp scale is unknown. A BaseApp-scale walk has cost
  about 18 GB of RAM in the owner's other tool.
- Execution: Microsoft's test apps need their test libraries and a company with demo data; al-runner
  and bcdev differ in what they can run.
- Cost: Microsoft's suites are large, so this only makes sense with selection.
