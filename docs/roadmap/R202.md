**Measured 2026-09-03.** `scripts/r198-group-runner-probe/drive.ps1` E8 (second run) and
`drive-stop-race.ps1` (10 rounds): a 45 s bounded hang in a test method, ended from a second
session by `StopSession`. Twelve times the held request came back **HTTP 408** with "The session was
stopped by an AL StopSession call", which `isAlStopResponse` recognises and
`run-mutant-transport.ts` scores `timeout`. Once it came back **HTTP 400** with "Cannot establish a
connection to the SQL Server/Database", 3.9 s after the stop, and the session was just as dead
(its progress row never advanced, its inserted row was rolled back). Which error the stopped
thread hits first is a race inside the NST.

**Today's consequence.** `run-mutant-transport.ts` scores `timeout` only for `stopFired && 408 &&
isAlStopResponse`; any other non-2xx after the stop falls to `in-flight-unknown`. The orchestrator
reconciles: the stop tombstoned the op, so rule 1 says `completed` and retries ONCE as a fresh
attempt, which re-runs the hang, burns another budget, and ends in `result-lost` or a quarantine.
`itest:hang` pins the 408 path and has never seen the other.

**What must NOT fix it, twice refused.** "A confirmed stop plus ANY non-2xx in the grace window
scores `timeout`" was refused by the R198 revision-1 review: `stopped: true` means
`TryStopHungRun` reached `StopSession`, and its own comment says that proves nothing about the
session ending; a gateway 502 on a slow-but-passing method would become a false kill. "A confirmed
stop plus a progress row that has not advanced across two polls" was refused by the revision-2
review: a session still alive INSIDE the stopped method does not advance the row either, so "no
progress for 5 s" is what a dead session and a slow passing method look like identically. The
converse this rule needs (a row that has not advanced implies death) is false. The obvious
strengthening, asking the server whether the session is alive, is ruled out by `Lease.Table.al`'s
measurement that a web-service session cannot read `Active Session`.

**What would.** A discriminator that only BC can produce: measure whether the 400's body is an
NST error payload for OUR request (distinguishable from any gateway page), and whether the
occurrence needs a fresh publish. Until measured, `--stop-hung-sessions` keeps a ~1-in-34 chance
per hang of quarantining instead of scoring, and R198 lands without touching this path.
