**Filed 2026-11-05 by lethal-code, from R-811's plan ([[R813]] §2).** Found by reading the code, not by a run as a user. The
orchestrator re-read `checkGated` and confirmed it. Related: [[R586]], [[R813]].

**The gap.** Someone who follows upstream's install (`mise use`, or `install.sh`) and then runs `--backend al-runner-v3` is
refused.
- `alRunnerV3.path` defaults to `/work/tools/al-runner-v3/current/al-runner`, which exists only in the kraken container. A
  user can point `path` at their own binary, but that alone is not enough.
- `checkGated` (`al-runner-v3-pin.ts`) refuses any binary with no `.gated` beside it, or whose `.gated` names another
  sha256 or version line, with `al-runner-v3-ungated-build`. The backend and `lethal doctor` both call it.
- Only `scripts/al-runner-v3-update.ts` writes `.gated`, and a user cannot run that script. It hard-codes `/work/tools`,
  `/coord` and `/work/lethal-wt`, and its gate needs the pinned, private CDO checkout.
- The only ways round it are to write `.gated` by hand, or to set `LETHAL_ALRUNNER_V3_CANDIDATE=1`, which is the update
  gate's own switch. Neither is documented for users, and neither is a supported path.
- `README.md`'s Installation section does not mention al-runner, and no LethAL build bundles it. Bundling has a licence
  question: see [[R813]] §3.

**Why it matters.** The check is doing its job: it stops an unmeasured build from giving verdicts that look measured. The
gap is that no route exists for a user to get a measured build. On Windows v3 refuses anyway (`refuseV3Platform`), so
this concerns Linux and any other platform v3 is later measured on.

**What a fix must decide** (not designed here; it depends on [[R813]]'s ruling):
- **Which builds a user may run.** Pins match on version line AND sha256 (`findV3Pin`), so a user's binary is pinned only
  if it is the exact release asset we gated. Edge builds are replaced nightly, so a user cannot fetch an old one.
- **How the record reaches a user.** For example, ship the gated versions and sha256s of numbered releases inside LethAL,
  and have `checkGated` accept those, in place of a `.gated` file on disk.
- **What an unknown build does.** It must stay refused, or run with a loud, report-visible caveat. It must not run silently.
- **Whether a user can fetch the build.** `lethal doctor` could name the exact release to install, with its sha256.

**To close.** A user on Linux, in a clean environment with no `/work` or `/coord`, installs the named release, and
`lethal doctor` and a `--backend al-runner-v3` run on the gift card both pass. A gate or test pins that an ungated build
is still refused. Do this before any LethAL release offers v3.
