**Found 2026-10-05 by the post-merge gpt-6.1-sol review of R-473** (`/coord/reviews/postmerge-R-473/sol.md`;
static review, not run). R-473 itself is clean: no regression, no key move.

`receiverUnresolved` (`packages/engine/src/semantic/receiver.ts`) rejects every receiverless call, and
`claimsRecordMethod` refuses implicit calls inside a `pageextension` by design (R30/R67: the extended
page's `SourceTable` is usually in another app). So a bare `Insert(true)`, `Modify(true)` or
`Delete(true)` in a pageextension stays with `flip-boolean-literal` and its true -> false flip carries
NO `run-trigger-skipped-*` tag, while `Rec.Insert(true)` there gets the tag through R-473. That is
the under-tag direction, and `runTriggerTag` in `flip-boolean-literal.ts` inherits it.

**To close.** Measure the bare shape in pageextensions (and anywhere else an implicit receiver is
refused) on BaseApp and CDO. Then treat a receiverless RunTrigger call whose implicit record is
refused as unresolved FOR TAGGING ONLY (keep the tag; the claiming refusal stays), the same rule
R-364, R-460 and R-473 apply. Tag-only, so no key should move; prove it with an exact site diff. Pin
both directions, red-checked. Check the overlap with [[R464]] (the implicit-record resolver) first.

Also noted, minor, no action: a parenthesised literal (`X.Modify((true))`) is untagged by design and
pinned by "does NOT tag a parenthesised (true) RunTrigger".
