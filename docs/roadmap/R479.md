`receiverUnresolved` (`packages/engine/src/semantic/receiver.ts`) rejects every receiverless call, and
`claimsRecordMethod` refuses implicit calls inside a `pageextension` by design (R30/R67: the extended
page's `SourceTable` is usually in another app). So a bare `Insert(true)`, `Modify(true)` or
`Delete(true)` in a pageextension stays with `flip-boolean-literal` and its true -> false flip carries
NO `run-trigger-skipped-*` tag, while `Rec.Insert(true)` there gets the tag through R-473. That is
the under-tag direction, and `runTriggerTag` in `flip-boolean-literal.ts` inherits it.

**Done (2026-10-05, 9d34135a).** Evidence: the coord handoff `R-479` (`survey.md`, `plan.md`,
`build.md`).

*Cause.* `receiverUnresolved` returned `false` at its first check for any call with no receiver.
A bare call whose implicit record could not be proven was therefore "not claimed" but never
"unresolved", and `runTriggerTag` dropped the tag. `Rec.Insert(true)` in the same pageextension
reaches the qualified resolver, finds the pageextension scope with no table, counts as unresolved
and keeps it.

*Fix.* `receiverUnresolved` sends a bare call to `implicitRecordUnresolved`, which reads the same
`recordScopesAt` that R464 built. It is true when the innermost record scope exists and either its
table is unknown or the call sits in a reportextension (outside the object kinds Tier 2 claims in).
Contexts covered: a pageextension's `Rec`; a reportextension's `modify(X)` trigger, request page
and added dataitem; a `with` whose subject does not resolve to a known table. It stays false where
the object itself declares a procedure of that name, where a `with` subject resolves to a
non-record (a codeunit), and where there is no record scope at all (a page without `SourceTable`,
a codeunit outside a TableNo `OnRun`): there the call is not a record method. Contexts R464
already resolves (table, tableextension, page with `SourceTable`, TableNo `OnRun`, report
dataitems, `with` on a known record) are unchanged. Claiming is unchanged, so `swap-modify-flag`
still does not claim these calls. Both directions: `true` keeps the skip tag of its kind, `false`
gets `run-trigger-forced` (R460's branch).

*Measured* (complete spec dumps, every operator at every node, master 2bced9a6 against the branch,
by identity key): 0 added, 0 removed, 0 changed, so 0 keys moved, on the fixtures (17 projects,
1,612 rows), examples (4, 177), CDO (6, 57,755), DC (14, 193,011), DO (7, 81,503) and BC.History
(519, 2,298,868). No corpus has the shape: a text search finds no bare RunTrigger call in any
pageextension or reportextension there. A scratch probe project shows the change, 10 rows retagged
(pageextension 7, reportextension 3), with no other difference and 0 keys moved. No fixture row
moves, so no gate pin (`itest:tables`' `platformArtifactKills` included) changes, and no identity
scheme or operator version changes.

*Why build it with an empty diff.* A bare `Modify(true)` in a pageextension trigger is ordinary
customer code; these corpora simply lack it. And this is the under-tag direction: an untagged flip
whose kill came from a skipped trigger would be counted as an honest kill.

*Tests* in `flip-boolean-literal.test.ts`: "tags a bare RunTrigger call on a pageextension's
implicit Rec, both directions" (also: no claim, and a reportextension `modify` trigger) and "keeps a
bare call untagged where its binding is known". RED-CHECKED, each revert red then restored green:
bare branch back to `false` (the first test); drop the unknown-table check, the own-procedure
guard, or the non-record `with` check (the second test, one assertion each); stop ceding a claimed
sole `true` (the second test, plus R473's test and "still cedes a sole Insert(true)").
