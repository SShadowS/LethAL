title: "Fallback 2 scores a trigger mutant `survived` when its only covering test is red, where member-level attribution declines"
section: "correctness-risks"
status: "open — measured 2026-08-13 on the R136 trio's first live run"

Coverage attribution has two paths, and they disagree about what to do when an object's only covering
tests fail at baseline.

The member-level path DECLINES. A mutant whose covering tests are all non-green is recorded
`no-coverage` (or `error` with a note naming the red test), which is honest: we cannot know.

The trigger path does not decline. When a table trigger mutant cannot be coverage-matched, FALLBACK 2
runs it against every green test instead, and whatever comes back is scored. If the object's only
covering test is the red one, the green set by construction excludes every test that could kill the
mutant, so the mutant reliably comes back `survived`.

**Measured 2026-08-13.** One root cause (a stale primary key in a fixture loop, see the measurements
index) made a single test red at baseline. That one failure produced two different reporting outcomes
from the same underlying ignorance:

- five mutants in a PROCEDURE recorded `error`, each with the note `unsupported test type: mutant
  covered only by test(s) that did not pass at baseline`, naming the red test. Correct and legible.
- two mutants in that table's `OnInsert` TRIGGER recorded `survived`, via FALLBACK 2, against a green
  set that excluded the only test able to kill them. Both had been pre-committed `killed`, and the
  pre-commitment was right; the observation simply did not test it.

Why this matters more than an ordinary attribution gap: **`survived` is a finding, not a neutral
result.** A user reads it as "your suite executes this line and does not catch this mutation", which is
exactly the claim a campaign is bought to make. A false `survived` therefore does not merely lose
information the way `no-coverage` does, it manufactures a defect report against the user's tests. It
is also silent: nothing in the record distinguishes a `survived` earned against a covering test from
one scored against a set that could never kill the mutant.

What this row asks for:

1. FALLBACK 2 should DECLINE, the way member-level attribution already does, when every test that
   covers the mutant's object is non-green. `no-coverage` under the existing `baseline-red` caveat is
   the honest answer.
2. If declining is judged too blunt, then at minimum the verdict must carry a caveat naming the
   condition, so a `survived` produced this way is never readable as an ordinary survivor.
3. Either way, `untargetedTriggerCount` already counts the mutants that took this path. It was 2 on
   the measured run. The tally exists; the verdicts it covers are what need the treatment.

Related: R55 records the general rule that tests failing at baseline are dropped from the green set and
mutants covered only by them become non-findings. This row is the narrower case where the same
condition produces a WRONG finding rather than a lost one.
