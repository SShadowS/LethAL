**Found by the code lane closing R358 (2026-09-30).** `scripts/test-preload.ts` hides the real
home (USERPROFILE, HOME) and, since R358, points TEMP, TMP and TMPDIR at a private directory, by
assigning `process.env` inside the running `bun test` process. Measured on Bun 1.3.14: a child
started with `Bun.spawn`, `Bun.spawnSync` or `node:child_process` (`execFileSync`) WITHOUT an
explicit `env` sees the environment the parent process STARTED with, so `os.tmpdir()` in the
child printed the real temp folder after the parent had changed TEMP. Passing `env: process.env`
gave the child the new value.

**What it breaks.** A unit test that spawns a child (a `bun` CLI run, a git call, a fake
al-runner script) lets that child read or write the developer's real home and temp folder, which
is exactly what R264 and R358 exist to prevent, and neither guard sees it: `real-home-guard`
checks only the test process, and the R358 temp check only the private directory. A full run on
2026-09-30 left nothing in the outer temp folder, so no child leaks temp files today; whether any
child reads the real home has not been checked.

**To close.** Either start `bun test` with the variables already set (a wrapper that makes the
private directory and then runs `bun test`, so every child inherits it), or make each spawn in the
tests pass `env`. Then a check that fails when a child sees the real home, for example a unit test
that spawns `bun -e` and compares its `os.homedir()` with `LETHAL_TEST_FAKE_HOME`.

**Done (R-359b).** Re-measured on Bun 1.4.2 (2026-10-06): `Bun.spawn` and `Bun.spawnSync`
without `env` still gave the child the real HOME and TMPDIR; `node:child_process`
(`execFileSync`, `spawnSync`) and `Bun.$` now pass the current `process.env`. So the fix is one
place: `scripts/test-preload.ts` replaces `Bun.spawn` and `Bun.spawnSync`, for the test process
only, with versions whose `env` defaults to the current `process.env` (both call forms; an explicit
`env` still wins). Every child of a unit test, product code under test included, now sees the fake
home and the private temp folder. The full suite passes with it (6978 pass), so no test relied on
the real home in a child. Pinned by `real-home-guard.test.ts`, "R359: a child process sees the fake
home and the private temp folder, whichever spawn form" (four spawn forms plus the explicit-env
control). Red-checked: without the replacement it goes red.
