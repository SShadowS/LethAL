**What happened.** The DO 29 run finished at 15:26 (score 64.0%, 435 / 245 / 48 over 680 scored,
`narrowed`: 4 of 572 files, 407 of 1,790 tests). Within half an hour the operator's session had
run `lethal export --format mutation-elements`, inlined the Stryker viewer into a single HTML file,
opened it, and found three things a reader of that page is not told:

1. **The page looks like a full-project report.** The schema describes mutants, not the run, so
   the four-file, quarter-of-the-suite scope is invisible. R178 stated this as a loss on stdout,
   and stdout is gone when the page is opened. The session added a banner by hand.
2. **The viewer's headline score disagrees with LethAL's.** "Of total" counts `no-coverage`
   against the suite (59.8%); "Of covered" matches LethAL's 64.0%. Neither is labelled as the one
   LethAL means.
3. **Status mapping needs a key.** The 13 stranded mutants show as "Runtime errors", the two
   declarative sites as one "Ignored" entry, and `projectRoot` stripping changed the file routes.

**Done now.** `config.lethal` carries `validity`, `counts`, `mutationScore` and the report schema
version verbatim, and `framework` names LethAL with its version; both validate against the real
schema package in `mutation-elements.test.ts`. The `losses` line now says the facts travel in the
file and are not rendered, and names the "of total" difference.

**Still open.** A page that SHOWS the banner. R178 ruled that the signed binary does not embed
third-party JavaScript, so the route is either `scripts/export-mutation-elements.ts --html`
(local, `node_modules` present) learning to inject a scope header from `config.lethal`, or a
documented recipe for the viewer's own `<mutation-test-report-app>` element with a title. Either
way the banner text should be generated from `validity.scoreDescribes`, not written by hand.
