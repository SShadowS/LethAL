**Found 2026-10-07 while building [[R487]]** (plan `/coord/reviews/R-487-plan/plan.r7.md`, section "Known
exclusions"; measurements in `/coord/handoff/R-487/survey.md`). R487 refuses every hang-capable site in an OPEN
`Integer` report data item's code, its child items and its same-object callees. These shapes are outside that rule.
Each is a known exclusion, and none is shown safe.

1. **Code that runs before the item, outside it.** `OnPreReport`, and an earlier sibling item that sets a flag a
   later item's guard reads (R196's preheader exclusion). The blanket rule reads only code inside the item or
   reached from it, so `Done := true` in `OnPreReport` or in an earlier sibling is still emitted.
2. **Procedures in OTHER objects.** Reachability follows calls by name inside one object only. A codeunit method
   that an open item calls, and that writes a value the loop depends on, is not refused.
3. **Items over ordinary tables.** They end when their records end. A trigger that inserts into the temporary set
   it walks can keep that set growing. The r1/r2 census found 0 self-inserts on BC.History (10 read: 0 hang, 1
   data-dependent, 9 no).
4. **`Date` items.** BC drives them like `Integer` items over a date range; R484's certificates read only
   `Integer`. BaseApp has 4 (2 sites; 2 read, 0 hang).
5. **XMLport `tableelement` over `Integer`.** BC.History has 50 in 11 files (PEPPOL, E-Document, contact export),
   with 29 exit guards; 0 writes in their triggers are read by those guards, so 0 sites under R484's rule. The
   blanket rule does not extend to XMLports.
6. **Reportextensions outside the project.** A view or SetRange certificate is trusted when no reportextension in
   the PROJECT extends the report, but another app can extend it and widen the filter. Voiding those certificates
   in every report would cost 1,727 more BC.History sites than R487 (6,737 against master `155c4dd8`). LethAL never
   treats a report as proven bounded in deployment.
7. **A reportextension inside an ERROR node** (unparsed) is not found, so it does not void the base certificate.
8. **A `while`/`repeat` inside a bounded item's code.** `MaxIteration` caps BC's record loop, not an AL loop in a
   trigger or callee; those get only R196, R446 and R480's loop rules.

9. **Call shapes reachability does not follow** (from the R-487 final review, 2026-10-08). A same-object call
   without parentheses inside an expression (`if IsOk then`, `X := GetVal;`) and a call through
   `CurrReport.MyProc()` are not followed, so the callee's sites are not refused. BC.History has 0 of either in
   open-item code.

The census zeros above are qualified: `census8.ts` follows calls by name, not through aliases.

**The rule.** Every addition goes through R501's ONE dispatch check, `openItemHangRefuses` in `loop-hazard.ts`, so it
covers every operator:
- **Shape 1, a stated LIMIT** (`writesPresetExitName`). A report global that an open item's exit guard or
  SetRange/SetFilter argument reads (in the item's triggers, Date items included, or a procedure they reach), and
  that open-item code never writes, is fixed for the walk. Outside open-item code, its writes, the guards around
  them, and an early exit before them in the same scope are refused. Not seen: [[R532]].
- **Shape 2, option A, one hop** (`inOneHopCallee`). A procedure in another project object that open-item code
  calls, with its same-object closure: codeunit callees, record callees (the table and its tableextensions),
  interface implementers, and event subscribers (of an event open-item code raises, or a refused callee raises).
  Receivers are typed from the declaration's type node or through `resolveReceiverTable`; names compare in full,
  never by splitting text. Subscribers are read from the attribute's nodes, including an integer object id and a
  namespace-qualified reference.
- **Shape 3, a stated LIMIT** (`altersSelfInsertFilter`): the OnPreDataItem filter call of a data item that inserts
  into the table it walks (through a typed record, an unqualified `Insert`, or the item's own name). Reading the
  item's own name (`Entry.Insert()`, the build review's F1) was added after the measurement below; re-run on every
  project it can touch, it moves 0 mutants and 0 keys (`scratch/f1-remeasure.log`).
- **Shape 4**: a `Date` item is open unless `MaxIteration` bounds it.
- **Shape 5**: an XMLport `tableelement` over `Integer` is a loop item (`SourceTableView` and `OnPreXmlItem`
  certificates). DORMANT: the orchestrator asks the check only in a file that can carry the selector var, and
  xmlport cannot, so `skipped` is unchanged (`r500-dispatch.test.ts` pins this). It still seeds shape 2: the
  PEPPOL subscribers are refused through it.
- **5b**: a filter call on an open item's record made from outside its code. **7**: an unparsed or `#if`-split
  reportextension extends every report. **9**: `CurrReport.P()` and a bare procedure name in an expression are calls.
- **RULINGS.** 6: a reportextension outside the project cannot reach this project's open items; nothing to refuse
  here. 8: a `while`/`repeat` inside a BOUNDED item is an ordinary AL loop and keeps R196/R446/R480's rules; the
  shape that hangs (a loop ending only by consuming its set, 1 of 12 sampled) is product-wide and filed as [[R531]].

**The record-callee share is kept for uniformity.** Record callees cost 3,622 deployed mutants on BC.History
(0.16% of master's 2,249,668; measured against master 15c3a620) and no measured hang is of that kind. They stay because a table procedure called
from open-item code can hold its own `FindNext` loop, exactly like a codeunit callee, and 0.16% is cheap.

**A latent BaseApp hazard, no mutant needed.** In `Finance Charge Memo - Test` and `Reminder - Test`, DimensionLoop
breaks on a `Continue` flag it never writes; a sibling item's backward line scan sets it. The unmutated reports
already loop forever on a document whose lines are all blank. LethAL refuses the mutants that could reach that
state (shape 1); the hazard itself is BaseApp's.
