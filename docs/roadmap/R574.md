**Filed 2026-10-10 by the [[R571]] measurement** (`/coord/handoff/R-571/measure.md`, coord task R-571; orchestrator
ruling of the same day). A possible UNDER-refusal: a mutant that can hang may be deployed. The orchestrator ruled it
lethal-code's next task after R-571.

**What.** R531 refuses the consumers of a cursor loop's record inside the loop body. When it follows a call into a
procedure of the same object, it refuses that procedure's consumers, the sites that contain them, and their
guards. It does NOT refuse an `exit` or `Error` that comes BEFORE the callee's last consumer, nor that early exit's
guard. A mutant that makes the callee leave before it consumes the row (for example `remove-not` on
`if not Rec.FindLast() then exit;`) leaves the row in place, so the loop can run for ever.

**Seen.** R-571's cross-object hop refuses these early exits, together with their guards, because
`CDC Message Bus Socket`.Pop needs exactly that: a guarded `exit` before its `Delete`. The same-object hop has the
same shape and was not changed.

**Sample size: none yet.** The R-571 measurement did not census or read same-object callees for this shape.

**To close.** Census the same-object hop's callees that have an early exit or Error before their last consumer, on
every corpus. Read a sample by hand. Then extend the refusal to the same-object hop, reusing R571's code, or close
the item by ruling. Measure per mutant, and say whether any ordinal moves.

**Related.** [[R576]]: a same-object callee that consumes only through a bare helper call (`Remove()`) has no
consumer the hop can see, so its early exit has nothing to come before. R571's rule also refuses a `break` that
leaves a callee loop holding a consumer; reuse that too.

## Built (branch `lethal/r574`, coord task R-574)

**The rule.** In `r531AnalyzeOnce`, every SAME-object hop (a same-object callee, or a table procedure on R) is
now built by [[R571]]'s `r571Hop`, the one function the cross-object hop uses. So a same-object callee's refused
set gains: every `exit` or raised `Error` that starts before its last consumer, or that sits in a callee loop
whose body holds a consumer; every `break` that leaves such a loop; the guards of all of these; and the
assignments in the callee body that feed any of the hop's guards (R531's FEEDS). There is no copy of `r571Hop`.
R562's filter hop (`r562FilterHop`) already refused its own early exits and is unchanged.

**The seam.** `r574Seam = { on: true }` in `loop-hazard.ts` switches the same-object use alone. Off, the hop is
`r531CalleeHop`'s, as before. Tests: `packages/builtin-tier1/tests/r574-same-object-early-exit.test.ts`, T1 to T7,
each reading one site with the seam off and on, each red-checked alone (`/coord/handoff/R-574/build.md`).

**No scheme bump.** R562's precedent is applied: 0 tuples and 0 ordinals measured on every project the census
flags, so there is no bump. The census compares hop guard sets with the seam on and off, which is the only way this
change can refuse a site (`/coord/handoff/R-574/measure.md`).

**Stated limit.** A same-object callee that consumes only through a bare helper call (`Remove()`) still refuses
nothing: the hop sees no consumer, so its early exit has nothing to come before. That is [[R576]] (helper chains),
not built here.

**Named over-refusals** (refused, but cannot hang):
- BaseApp `Date Compress General Ledger`.DeleteCompressedEntries, **6**: two `Error` calls and their guards. A
  raised Error ends the loop, and there is no TryFunction on the path.
- BaseApp Apply Vendor (3), Apply Customer (5) and Serv. Apply Customer (5) Entries pages
  (ExchangeLedgerEntryAmounts, CalcOppositeEntriesAmount), **13** guard feeds (remove-assignment 11,
  flip-boolean-literal 2). The caller deletes the row on every pass, so the loop advances without the callee. The
  Apply Employee Entries page has the same callee shape, but its exit yields no mutant.

**Measured catch.** Data Search.StartSearchInBackground, **5** refused, split by mutant:

- `shift-integer` hangs only if table id 1 is queued.
- `remove-not` depends on BC's background-task limit, which was not measured.
- `return-value` and `flip-boolean-literal` on `exit(false)` cannot hang: they are over-refusals.
