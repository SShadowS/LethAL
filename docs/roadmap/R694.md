**Filed 2026-10-23 by coord task R-435** (lethal-code). Evidence: `/coord/handoff/R-435/trust-probe/results.md`
(offline probe, `--isolation test --test-timeout-secs 2`, invented app) and the Opus plan review
(`/coord/handoff/R-435/review-plan.md`, B1). Upstream: https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5776

**What.** v3 runs the tests of a codeunit in one call. After a test that was refused while it ran, v3 marks a
later FAILURE in that call as not trusted ("... an earlier test of this codeunit was refused while it ran ... this
failure is not trusted"). It does not mark a later TIMEOUT: that row is a plain timeout. Measured on alpha.2 and
edge: test A refused mid-run, test B loops, test C fails. B is a plain timeout row, and on alpha.2 C is marked.

**Why it matters.** A refusal can leave partial state. A test that loops only because of that state, plus the
mutant, is not a real timeout kill. LethAL's checks do not see it: the cold confirm runs the test alone and
unmutated, and the R577 re-run repeats the same sequence. So `timeout-killed` could be false.

**Fixed (this item).** `AlRunnerV3Backend.run`: with a mutant active, a timeout row that has ANY earlier row in the
same call that is `notRun` (a refusal or another timeout) or holds v3's refusal marker is scored `error`, row
`runner-test-error`, with a note naming the earlier tests. The baseline call is unchanged. A timeout with no
earlier refusal or stop is still a timeout. Tests: the cases under "R-435" in
`al-runner-v3-backend.test.ts` (including `B1b`, the whole sequence refusal, flag, then the guarded timeout), and
`O8` in `orchestrator.test.ts` (the orchestrator half, with the backend's answer injected).

**Cost.** A mutant whose only detection was such a timeout is now an `error`, not `timeout-killed`. That is the safe
direction. No frozen v3 figure holds a `timeout-killed`, so none should move; the v3 gate confirms it.
The guard is wider than v3's own rule: every earlier `notRun` row counts, including a test refused BEFORE it starts
(such as the always-refused Commit tests, R612), which leaves no state. So in a codeunit that holds such a test,
every hang in a test after it becomes `error`, never `timeout-killed`. Also safe, but read the rows before calling
a missing `timeout-killed` a miss.

**Limit.** This is measured on the pinned alpha.2 and on edge alpha.4 only. The upstream issue asks v3 to mark the
timeout itself; when it does, this guard can be narrowed.
