**Found by the R-214 audit (lethal-preproc, 2026-09-29).** Evidence:
`H:/lethal-coord/tasks/R-214/audit.md`, new finding 2. Repro and output:
`H:/lethal-scratch/R-214/c/r298/` and `c/sites.ts`.

**What happens.** The repro is a codeunit wrapped in `#if` whose procedure contains `exit(A + B)`.
That wrapped codeunit loses `lethal.swap-additive` at L8:14, measured against the same file without
the directives. A two-arm wrapper loses it at L14:14 too. The symbol table (`buildSymbolTable`'s `unindexedObjects` loop in `symbol-table.ts`) routes a
`preproc_conditional_object`'s objects into `unindexedObjects` instead of indexing them. R331 did
this on purpose, so that a wrapped procedure cannot be mistaken for a built-in. The consequence is
that every operator which needs a type misses every site in a wrapped object.

**Why it matters.** The loss is silent: no caveat, warning or refusal names it. A codebase that
wraps whole objects in `#if CLEAN<n>` (BaseApp's obsoletion pattern) gets a lower site count with
no report of why.

**Fix direction.** Either index wrapped objects per arm (with the build's symbols, once the R214
plan threads them into enumeration) or report the refusal by name. Until then, this item is the
record that the loss is deliberate.

**R214 count (2026-10-01).** The R343 exclusion in R214's pre-commitment: dc.0: 9, sysapp.0: 55, bcf.0: 2, baseapp.0: 392, p13: 1 under `[]`.

**The loss is not only missing sites: it hid a hang hazard (R-364, 2026-10-05).** Inside a wrapped
object the hang check (`classifyHangCapable`, R196) could not resolve a variable, so it skipped,
and hang-capable mutants were deployed there. The R-364 census (BaseApp, the 203 `app.json`
projects of BC.History w1-28, under `[]`, the shipped build) found 7 such mutants
(`remove-assignment` and `shift-integer`) in 4 Base Application reports wrapped in
`#if not CLEAN28`, and one dropped `run-trigger-skipped-delete` tag (`CalculateSubcontracts`). R-364
makes the hang check REFUSE by name there: when a target does not resolve and its own enclosing
object is unindexed, a loop condition that reads the same name refuses the site, and the site is
counted in `hang-refused`. An unresolved receiver now keeps the run-trigger tag. The same census
counts this item's other losses: 473 sites lost in 41 files and 165 wrong-tier rows, BaseApp only.
