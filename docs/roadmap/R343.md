**Found by the R-214 audit (lethal-preproc, 2026-09-29).** Evidence:
`H:/lethal-coord/tasks/R-214/audit.md`, new finding 2. Repro and output:
`H:/lethal-scratch/R-214/c/r298/` and `c/sites.ts`.

**What happens.** The repro is a codeunit wrapped in `#if` whose procedure contains `exit(A + B)`.
That wrapped codeunit loses `lethal.swap-additive` at L8:14, measured against the same file without
the directives. A two-arm wrapper loses it at L14:14 too. `symbol-table.ts:426` routes a
`preproc_conditional_object`'s objects into `unindexedObjects` instead of indexing them. R331 did
this on purpose, so that a wrapped procedure cannot be mistaken for a built-in. The consequence is
that every operator which needs a type misses every site in a wrapped object.

**Why it matters.** The loss is silent: no caveat, warning or refusal names it. A codebase that
wraps whole objects in `#if CLEAN<n>` (BaseApp's obsoletion pattern) gets a lower site count with
no report of why.

**Fix direction.** Either index wrapped objects per arm (with the build's symbols, once the R214
plan threads them into enumeration) or report the refusal by name. Until then, this item is the
record that the loss is deliberate.
