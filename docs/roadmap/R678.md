**Filed 2026-10-23 by lethal-code**, from R-677's build review (`/coord/reviews/R-677-build/`). Related: [[R677]],
[[R192]].

**What.** `AlRunnerV3Backend.baselineRefused` is filled only by a baseline call (`noteBaselineRows`). A batch that
reuses its baseline snapshot under `--resume` (R192) runs its baseline loop over `[]`, so it makes no backend call. R677
ruled the set session-wide, so a refusal that an EARLIER batch in the same process saw still reaches later batches.
But if EVERY batch in the session reuses its snapshot, nothing is ever recorded, and no survivor gets its
`[v3-refused-test-nearby]` note, even when a covering codeunit holds a test v3 refuses.

**Why it is small.** It is a NOTE only, never a verdict. The note is missing, not wrong, and the gap predates R677.

**To close.** Either:
- store the baseline's refused tests with the snapshot (R192), and re-seed `baselineRefused` from a reused
  snapshot; or
- report plainly that refusal notes are unmeasured for a run whose baselines were all reused.
Add a test that goes red when the re-seed is removed.

**Done 2026-10-23 by lethal-code (3d78e671).** Measured first (`/coord/handoff/R-678/measure.md`):
- A snapshot stores each whole `TestVerdict`, and a v3 refusal's verdict carries `runnerRow: "runner-refused"`
  and the v3 notRun suffix, both since v3's first commit.
- `runnerRow` alone was NOT the exact set: a non-notRun `X: out-of-scope:` row is `runner-refused` too, and
  `noteBaselineRows` also counted a notRun row with status `pass` or `fail` (a contract error), which a stored
  verdict cannot tell apart. So `noteBaselineRows` now counts a notRun row only with status `error`; that set is
  exactly a stored verdict that is `runner-refused` AND ends in the v3 notRun suffix.
- **D1 (ruled by the orchestrator):** no lendable snapshot can lack the record: a v3 session lends only from a v3
  run of the same runner build, under `IDENTITY_SCHEME` 41, which postdates both. So no "no record" note was
  added. It is not left silent by assumption: a reused verdict that holds the v3 notRun suffix without
  `runnerRow: "runner-refused"` throws `AlRunnerV3ReusedBaselineUnclassifiedError`. The suffix is one shared
  constant, and its comment says a change to its text needs an `IDENTITY_SCHEME` bump.
- **D2 (accepted at build review):** the narrowing of `noteBaselineRows` to status `error`. A notRun `pass` or
  `fail` row is already the loud `al-runner-v3 contract ...` runner-test-error, not a refusal, so it loses only a
  note.

The fix: the orchestrator calls an optional backend hook, `noteReusedBaseline`, with the reused verdicts inside
the baseline bracket; the v3 backend re-seeds `baselineRefused` from them. Pinned by "R678: a session whose every
batch reuses its snapshot ..." (`tests/resume.test.ts`, red without the hook call) and the four "R678:" tests in
`tests/al-runner-v3-backend.test.ts` (red without the re-seed, with the rule reduced to `runnerRow`, without the
`status` check, and with the throw made silent or made to fire on every verdict).
