**Why it happens.**
- Isolation "auto" first runs every codeunit under per-test rollback. Here that gives the same 213 refusals of #8002's kind in all
  five runs ("an earlier test of this codeunit ... changed number sequence ..."). Auto then re-runs those codeunits one test at a
  time, and they pass.
- In the three "cut" runs, the budget ran out during that re-run (`timeBudget.baselineStopped.inAutoRebaseline: true`), so the
  re-run was cut short. The stored baseline then holds whatever the cut re-run reached, with the rest left as the first pass.
- The two finished runs, one per build, are identical test by test.
- A cold cache only makes the setup slower (deploy 30-46 s against 13 s), so the budget runs out sooner.

PR-15 first took this for a cold-cache effect in al-runner and told lethal-code so. It corrected that the same day.

**The gap.** LethAL itself names the cut ("TIME BUDGET REACHED IN THE AUTO ISOLATION RE-BASELINE ... Every codeunit stayed on
test"). `triage-baseline.ts`'s summary line does not: it said "TRIAGE STOP fallback-unchecked: 318 of 526 green ...". The stored
baseline then gets read as the project's baseline. PR-05's re-run and PR-15's first compare both did this, and 38 tests looked like a
build change.

**To close:** make `triage-baseline.ts` name a cut re-baseline in its summary line and exit code ("baseline is the first pass only:
raise --budget-s"), with a red check each way.

**Fixed (coord PR-23, 81dcad58).**
- **The new stop.** `scripts/triage-baseline.ts` stops with `rebaseline-cut` (exit 17), whose summary line says "the stored
  baseline is the first pass ... raise --budget-s".
  - It reads the report's `timeBudget.baselineStopped.inAutoRebaseline`, or LethAL's own stderr line when there is no report.
  - It is checked after `fallback` and `no-license` (config faults) and before the rules that judge the baseline.
- **Tests.** Two tests in `scripts/triage-baseline.test.ts`. Six reverts were each red and restored green: no rule, the rule
  placed late, the rule placed first, the report branch ignoring `inAutoRebaseline`, the report ignored, and the stderr branch
  dropped.
- **Real data** (`/coord/handoff/PR-23/replay.ts`): the three cut Sustainability triages now read `rebaseline-cut`, and the two
  finished ones are unchanged.
