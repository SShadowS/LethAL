**Found while planning C02-04 (2026-09-25), confirmed by reading.** `runSession` calls
`await cfg.afterLeaseAcquired()` in `runSession` (`packages/runner/src/orchestrator.ts`), and the `try` whose
`finally` releases the lease opens only after it, above the R26 permission canary. The comment directly above the call says the
opposite: "Inside the same try/finally as everything else the lease guards: a publish that throws
must release the lease rather than leave it held for the full ttl."

**Consequence:** when the R19 test-app publish inside `afterLeaseAcquired` throws, the lease is
never released. Every other session on that container (LethAL or CentralGauge, which share leases)
is refused until the ttl lapses. No test covers it.

**Fix shape:** move the call inside the `try`. Test with a stateful fake whose `afterLeaseAcquired`
throws, asserting release is called (a call counter, not timing); red-check by moving the call back.
Planned as its own commit in C02-04 part A (`docs/superpowers/plans/2026-09-25-C02-04-run-named-mutants.md`, Task 4). C02-05 relies on this hook.

Not measured live.
