**Found by R-316's plan (2026-09-28)**, `docs/superpowers/plans/2026-09-28-R-316-preamble-member.md`,
Decision 2. Sibling of [[R301]] and [[R316]].

**What breaks.** Both split-header shapes can rename the procedure between arms (`procedure Pick`
under `#if`, `procedure Choose` under `#else`): `preproc_split_procedure` ([[R301]], one shared `var`
section) and `preproc_split_procedure_preamble` ([[R316]], one `var` section per arm). Before
R-318 such a member got `procedureName` `""` and no line-map span (see the R-318 record below:
narrowed). With coverage on, nothing attributes a covered line
to it, so every mutant of a PUBLIC renamed member reads `no-coverage`, although its tests run it.
For a public one this never makes a false kill or a false survivor; it drops live sites from the
score. (Corrected 2026-09-30: this text once said an all-local renamed member takes the ordinary
unnamed-local object-grain path in `selection.ts`. That holds only on the hub. Measured on `r5`, on
the fenced and al-runner legs it read `no-coverage` like a public one, and R318 fixes it.)

**Measured** at R-316 plan time on al-runner v2.11.0, hand-written repros:

- `p10-renamed` (a renamed preamble): 4 `no-coverage` with coverage on; 3 killed and 1 survived with
  coverage off.
- `p9-all`, member `Pick2` / `Choose`: 1 `no-coverage` with coverage on, scored with it off.
- The same on the `--server` leg.

**Why no name is given.** Which arm is compiled depends on preprocessor symbols LethAL does not
evaluate when it names members, so either arm's name may be the inactive one. A guessed name would
attribute coverage to the wrong member, which is worse than none. A joined name (`Pick|Choose`) was
rejected in R-316's Decision 2: `|` is the identity key's separator and no coverage source reports it.

**What would close it.** Either pick the compiled arm's name from the run's own preprocessor symbols,
which every session knows (`preprocessorSymbols`, [[R101]] (c)), or attribute by the name the
coverage source reports, which al-runner's `--server` path already carries per statement
(`st.scope`). Either needs a two-build test: each symbol set must attribute to its own arm's name.

**Size.** 0 corpus sites seen ([[R301]]'s note; R-316's census found 0 preambles in DC/Cloud,
System Application, BusinessFoundation and BaseApp). [[R301]] closed with this gap in its "Still
open" list but moved it to neither [[R302]] nor [[R309]]; this item is its home.

## R-318 record (2026-09-30): narrowed, still open

Plan: `docs/superpowers/plans/2026-09-29-R-318-renamed-split-members.md`. Commits, in order:
`cb01e679`, `3c4afc02` (the arm-name rule), `79596906`, `44421712` (the manifest field),
`889e9aee`, `2074c6fa`, `c7ff7e96` (the line map), `561cacbe` (the hub lookup), `14554ac7`,
`d752e874` (the `--server` re-key), `64fc932d` (resume guards), `e8d28341` (identity scheme 4).

**Design.**

1. The names live in a new optional manifest field, `coverageArmNames`, on the mutants of a renamed
   member. `procedureName` stays `""`, so no identity key tuple moves and no other member's ordinal
   is renumbered. The field is absent everywhere else, so every other manifest is byte-identical.
2. A name goes in the list only if no other declaration of the object carries it: any arm of any
   other procedure, wrapped, swallowed or trigger. In any one build exactly one arm is compiled, so
   a name that no other declaration carries can only be this member.
3. Fenced bcdev and al-runner one-shot (Cobertura) name a line from our line map, so the map spans
   the member under its first coverage name in every build. The `--server` and resource legs re-key
   a statement to that name when its line lies in exactly one span and the producer's own scope is
   one of the member's arm names. This is the own-arm rule. The orchestrator accepted it on the
   condition that every declaration span counts (wrapped procedures, swallowed members, triggers),
   not only indexed members. The line-only lookup counts them the same way.
4. The hub matches by name, so `coverageFilter` unions every name in the list.
5. Position, not symbol evaluation: no `#if` evaluator exists, and the session's symbols are not the
   whole symbol set (`app.json` symbols, `#define`).

**Collision rule and position re-key: why neither can borrow.** A dropped name is never used to
attribute. A re-key needs the line inside the member and no other span, and the producer's scope to
be the member's own. So a statement the producer credits to another name, such as a neighbour on a
line the two share, stays with that name. A line inside more than one span names nobody.

**Identity.** No key tuple moved: the ten repro key digests were re-measured at the last commit and
equal the plan's literals (99 mutants, same tally). `IDENTITY_SCHEME` is now 4, because the verdict an
unchanged key carries changed (a pre-R318 `no-coverage`, or the `survived` that `r3` build `[]`
carried on the wrapped procedure). History, both resume forms and equivalence marks already refuse a
scheme change by name (R325). Un-bumping the constant turns five tests red. The two resume guards
stay: a carried `no-coverage` on a renamed member is re-scored, and a batch holding one never reuses a
baseline snapshot. Cost: 0 known sites. Baseline-snapshot reuse is also bound to the current scheme
(final review I1): a snapshot is found by its two hashes, R-318 leaves the emitted AL
byte-identical, so a scheme-3 run's snapshot matched a scheme-4 resume and carried the old
shared-line attribution. A snapshot recorded by a run of another scheme is now never reused.

**Shared lines.** Census: 0 shared lines in the fixtures and the four corpora. The rule is general:
two procedures on one physical line, and that line names nobody. Tests cover a line shared with a
wrapped procedure and one shared with a trigger. On a line the member shares with a neighbour, the
legs can differ: the `--server` and resource legs credit the member's own compiled-arm statement
through the producer's scope, which is truthful because a coverage name belongs to that member
alone, while the Cobertura and fenced legs credit nobody. No measured repro has such a line, so a
future differential that finds one should read it as this, not as a regression.
