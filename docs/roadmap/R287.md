**Found by the issue #6 cross-check** (`docs/measurements/2026-09-27-gh06-grammar-crosscheck.md`,
clusters C5, C6 and C7, filed as one item because they share one container family). **A stated
exception to the filing rule:** the pre-commitment says one context item per container, and these
are three containers. The lane ruling allowed one item for the family, since one fix (teaching
`isStatementSlot` the split-`if` family) closes all three; each container keeps its own cluster,
reproduction and count below, so none is hidden by the grouping. This is
[[R214]]'s "loses sites" half in containers that row never named, and more evidence for [[R217]]:
the slot list is hand-kept and keeps missing containers.

**What happens.** BaseApp retires code with `#if not CLEAN<n>` around the HEADER of an `if` statement
while the last branch statement sits after `#endif`, shared by both builds. tree-sitter-al 4.3.0 parses
that into split containers. Three shapes were found:

| cluster | shape | where the lost statement sits |
| --- | --- | --- |
| C5 | `#if not SYM` / `if C then X else` / `#endif` / `Y;` | `preproc_split_if_else_statement.then_branch` or `.else_branch` |
| C6 | `#if not SYM` / `if C then` / `#endif` / `Y;` | `preproc_split_if_statement.then_branch` |
| C7 | `#if not SYM` / `if C then begin ... end else begin` / `#endif` / shared statements / `#if not SYM` / `end;` / `#endif` | direct children of `preproc_fragmented_else_tail` |

None of these `<parent>.<field>` pairs is in `SINGLE_STATEMENT_SLOTS`
(`packages/engine/src/ast/tree-walks.ts`), and in C7 the statements have no statement-list parent at
all. So `isStatementSlot` answers false, and `void-method-call` and `remove-assignment` skip them.
The compiler (no symbols defined) builds these statements as ordinary statements. These are sites in
the ACTIVE build that LethAL loses; tree-sitter's shape is honest, so the gap is LethAL's.

**What would close it.** Teach `isStatementSlot` the three containers (two `then_branch` / `else_branch`
fields, and "direct child of `preproc_fragmented_else_tail`"), measured the R161 way. Any fix for
[[R214]] must also treat these as directive containers. [[R217]]'s options 1 and 2 would have caught
all three.

**Reproduce.** `bun scripts/probe-grammar-crosscheck.ts scripts/lib/al-kind-mapping-split-if.al`, and
the same for `al-kind-mapping-split-if-no-else.al` and `al-kind-mapping-split-else-tail.al`.
