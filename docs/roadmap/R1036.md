Found by coord task PR-26 while ranking refusal families. Evidence in `/coord/handoff/PR-26/`: `ledger-compare.ts` and `.txt`
(all stores, by issue), `sustainability-rows.py` and `.txt` (one run), `isolation-breakdown.py` and `.txt` (by isolation choice).
Related: [[R1031]] (the same first-pass rows misread by a triage), R921 and [[R890]] (isolation auto's
re-baseline), [[R1013]] (the ledger).

**What.** `readStore` took every baseline row of the run whose outcome was a refusal. Under isolation "auto", a codeunit's first
pass runs under per-test rollback. The codeunits whose rows need it are then re-baselined one test at a time, and the test's LAST
row is its baseline (`triage-baseline.ts` reads it so). So a first-pass refusal the re-baseline replaced with a pass was counted as a
sighting, although it cost no covered test. Measured on a finished Sustainability run (R-925 `sus`, edge-5a58a0f16): 412 refusal
rows, 119 tests still refused. #8002's number-sequence refusal: 213 rows, 0 standing.

**Fixed (6f4b96b9, and the review's ordering fix).**
- **The rule:** `readStore` keeps each test's last baseline row (by codeunit id and method) and counts it only if it is a refusal.
- **Row order:** the rows are read in the order they were written (`order by test_results.id`). The query had aliased the codeunit
  as `id`, so `order by id` sorted by codeunit and kept a test's rows in order only because SQLite keeps ties stable in practice.
  No test pins this.
- **Test:** a first-pass refusal replaced by a pass is not a sighting, and a refusal in both passes counts once. Red when the
  rule is reverted to every row.
- **Over all 774 v3 stores under `/coord/handoff`:** 166,464 sightings before and 156,454 after. The issues that moved most, open
  sightings before -> after (the full table is `ledger-compare.txt`; #8013 3,139 -> 3,120 and #7480 2,290 -> 2,290 barely moved):

  | issue | before | after |
  |---|---|---|
  | #7775 | 8,385 | 7,487 |
  | #7854 | 4,021 | 3,515 |
  | #8002 | 1,981 | 1,121 |
  | #8028 | 1,158 | 1,030 |
  | #7819 | 706 | 408 |
  | #7837 | 760 | 380 |
  | #7586 | 390 | 213 |

**What is still counted.** #8002's number-sequence refusals that stand in the last row, by the run's recorded isolation choice
(`isolation-breakdown.txt`). That script walks the stores with its own depth limit, so it read 674 stores, not 774:
- 720 come from runs that recorded no choice: an explicit isolation "test", or runs from before auto;
- 398 come from runs that recorded a choice (isolation auto).

So the refusal costs covered tests under the default too. Which codeunits those auto runs kept on per-test rollback was not read.
The finished Sustainability run (auto) has 0.
