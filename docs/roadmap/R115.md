**`lethal explain`'s output guard is DATA-derived, not TYPE-derived, and the checks that would close the gap are inert under `bun test`.** Subsystem B built `EXPLAIN_LEAF_PATHS` to pin every leaf path the projection may emit, so a new prose field fails by construction rather than by phrasing — the fix for a measured hole where a top-level `summary` and per-survivor `advice` reading *"the weak spots in this suite ... deserve attention first"* shipped into the real rung1 artifact at 35 pass / 0 fail. Two residual gaps, both measured. (1) **The pin observes only paths the fixture and the six committed reports actually provoke.** A field emitted under a condition none of them reaches is invisible in BOTH directions — no unpinned leaf AND no dead entry. Proved with `...(survivors.length > 200 ? { summary: "..." } : {})`: **43 pass / 0 fail**, because the largest corpus report has 125 survivors. "Only summarize on a big run" is a natural thing to write, so this is reachable rather than contrived. Closing it means deriving the pinned set from the OUTPUT TYPE rather than from observed data. (2) **A family of type-level guarantees is invisible to the test runner**, and one of them is a smuggling route rather than a maintenance nicety: `runner-disagreement` is a `Caveat` no committed report emits, so adding `advice: "these are the weak spots in this suite and deserve attention first"` to its interpretation passes the path pin, the identity test AND the banned-phrase test at **59 pass / 0 fail** — `tsc`'s excess-property check (`TS2353`) is the only thing between it and shipping. The same holds for `satisfies Record<MutantVerdict, 0>` and for `Record<Caveat, …>`, `Record<CoverageAttribution, …>`, `Record<GuardEvidence, …>`, `Record<MutantErrorCause, …>`. This matters because **CLAUDE.md's own build order runs `bun test` as a step separate from `bun run typecheck`**, and a session or CI job that runs only tests would land any of these. The thread that found it: an implementer disclosed that `bun test` was green while `MutantVerdict` was unimported, leaving its `satisfies` clause entirely inert. (3) **A NEW GLOBAL, report-content-independent field ships green with four small coordinated edits** — two lines in `explain.ts`, one entry in `EXPLAIN_LEAF_PATHS`, one in `PROJECTION_AUTHORED_STRINGS` — dodging identity (not `Interpretation`-shaped), the leaf pin (path admitted), provenance (string admitted) and the banned-phrase regex (phrasing): **45 pass / 0 fail**. The realistic route is not malice but an author whose new field reddens two tests and who "fixes" them by adding the two entries. Note the asymmetry that makes this the case worth closing: for a PER-ITEM field the same route is impractical, because the mandatory six-real-report test forces enumerating every distinct real value and that enumeration is itself the tell — only the global case yields an unremarkable-looking diff. All three gaps have the same root and the same fix: derive the pinned set from the OUTPUT TYPE rather than from observed data. Filed 2026-08-06 from subsystem B's Task 4 re-review.
