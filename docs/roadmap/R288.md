**Found by the issue #6 cross-check** (`docs/measurements/2026-09-27-gh06-grammar-crosscheck.md`, cluster P1).
A PARSE HEALTH finding: tree-sitter reports ERROR on a file the AL compiler parses without error.

**What happens.** A page control property whose value is a comparison that starts with the bare
identifier `Type` (`Visible = Type = Type::Alpha;`, also `Editable = Type <> Type::Beta;`) is read
down the `link_value` path. tree-sitter emits `link_value_list > link_value` with an ERROR node
spanning `Type::`. The same value with any other leading name (`Kind = Kind::Alpha`) or with a
qualified receiver (`Rec.Type = Rec.Type::Alpha`) parses as a `comparison_expression`, which is what
the compiler builds. This is close to the inverse of closed upstream #20, where a single-entry
`Implementation` value was read as a comparison instead of the `link_value` shape.

**Minimal reproduction** (hand-written, not corpus source), `scripts/lib/al-kind-mapping-type-property.al`:
```al
page 50006 "Mode Card Probe"
{
    PageType = Card;
    SourceTable = "Mode Probe";

    layout
    {
        area(Content)
        {
            field(Kind; Rec.Kind)
            {
                ApplicationArea = All;
                Enabled = Kind = Kind::Alpha;
            }
            field(Type; Rec.Type)
            {
                ApplicationArea = All;
                Visible = Type = Type::Alpha;
            }
        }
    }
}
```
The source table is not needed: both parsers read syntax only. Harness output: `files: listed 1,
comparable 0 (tree-sitter unhealthy 1, compiler parse errors 0)`, the file excluded with tree-sitter
ERROR 1 MISSING 0, verdict inconclusive (exit 2). The `Kind` field's identical property does not
error.

**Measured.** DC/Cloud (sha256 dcad155c4ecdb38e): 2 files, 6 ERROR nodes, 0 MISSING
(`Modules/Purchase Contracts/Base/src/Pages/CDCPurchContractCard.Page.al` 4,
`CDCPurchContrArchCard.Page.al` 2). The compiler reports no parse error in either. Zero unhealthy
files in the other six corpora.

**Why it is a risk, and what is not known.** By the pre-commitment's rule R1, the two files were
removed from BOTH sides of the site comparison, so none of their sites were compared. That is the
real gap this row records: the audit says nothing about those files. No product code path in
`packages/*/src` checks for ERROR nodes, so LethAL still enumerates sites in such a file. The ERROR
sits inside a declarative property value, where no mutant is emitted (see [[R144]]),
but whether the error recovery mis-shapes anything else in those two files was not measured.

**What would close it.** A grammar fix upstream (U2), a vendored bump, and a re-run of the cross-check
on DC/Cloud, which should then list 475 comparable files instead of 473.

**Reproduce.** `bun scripts/probe-grammar-crosscheck.ts scripts/lib/al-kind-mapping-type-property.al`
