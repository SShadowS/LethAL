**Found by** PR-447's delta review (N4; lethal-code, 2026-11-25). Spec:
`docs/superpowers/specs/2026-11-25-pr447-login-scoped-selector.md` r3.

- **The door, in the survivor direction.**
  - With al-runner's read-keyed login replay (#9074, main c854feb1f) and PR-447's login-scoped selector, a login image
    is found by the resource texts its login READ.
  - If the login's path depends on the date (Today, WorkDate) or on data, a login on day 2 may reach a mutated site
    that day 1's login did not reach.
  - A mutant at that site keys equal to day 1's image, because its bucket was not read on day 1. It replays day 1's
    login, so its login-time effect is lost, and it may be scored survived.
- **Why nothing catches it.** Kill pairs (R653, and R1223's replay-off routing) confirm KILLS only, and they never
  re-check a survivor. R1223 covers the kill direction.
- **Why two runs on two days cannot test it.** Each run records its images on its own day. The door needs the read set
  to change WITHIN one daemon life.
- **Fix shapes (not chosen here):**
  - restart every replay-on daemon when Today or WorkDate changes, which closes the date part;
  - a leg-C case that changes the date inside one daemon life and requires per-mutant equality with replay off;
  - for data the login reads, which no daemon restart closes, state the case and argue it: under kept isolation the
    login reads the install baseline. Measure this.
- **Status:** a precondition of PR-402's flag beside R1223 (spec r3, F7/N5): `alRunnerV3.loginReplay` needs the
  login-replay fact, PR-447's facts, R1223 and this item.
