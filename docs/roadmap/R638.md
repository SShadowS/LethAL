**Filed 2026-10-22 by coord task R-612** (measure step, finding F1). Upstream:
https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/5698.

**What.** `--test-timeout-secs N` stops a loop in a test method (a `notRun` row "Test exceeded Ns timeout."). The
same loop in the test codeunit's `OnRun` trigger is not stopped. It runs to its end, or forever.

**Measured** (invented repro, `/coord/handoff/R-612/onrun-repro/`, `results.txt`): with `--test-timeout-secs 2`,
a 400,000,000-step loop in `OnRun` ran to its end (about 5.4 s) and the codeunit's test passed (exit 0). The same
loop in a test method was stopped at 2 s. Present on alpha.2 (91253f2d6), alpha.3 (c893e3633) and alpha.4
(7739d8132). In `serve` an `OnRun` loop with an overflowing counter ran 53 s under a 3 s limit
(`/coord/handoff/R-612/probe/main.stdout`, kind "OnRun-trigger CPU timeout").

**Effect on LethAL.** Time only, never a verdict: a mutant that makes an `OnRun` loop forever holds a v3 call
until LethAL's own deadline, which ends it as `error`. On a future serve transport ([[R635]]) that deadline
throw also closes the daemon (R517 C1), so it is safe there too.

**To close.** When upstream applies the limit to `OnRun`, the update gate (`itest:alrunner-v3`, leg C) can pin it
as a contract fact. Until then nothing in LethAL changes.
