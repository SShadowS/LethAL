**`--test-isolation method` silently stopped meaning per-method isolation.** We pass `method` and comment that it "forces the advertised full-reset capability" (`packages/runner/src/al-runner-transport.ts:51-54`), and `capabilities()` advertises `isolation: "full-reset"` (`al-runner-backend.ts:117`). v2 accepts `method` only as a **v1 alias for `codeunit`** — state shared inside a codeunit, reset between codeunits (upstream `AlRunner/Program.cs:296-299`). Real per-test reset is `--isolation test`. On v2 the flag is accepted, nothing warns, and one test's residue can decide the next test's verdict inside the same codeunit while the report still claims full reset. Server mode inherits the daemon's own CLI flags (one shared `TestExecutor`, `Program.cs:620`), so `--server --isolation test` is the fix there too.
