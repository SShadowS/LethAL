**Filed 2026-11-06 by preproc.** Related: [[R830]], [[R572]], [[R570]].

**What.** [[R830]] reads a same-object callee's body. It cannot see a call into another object whose receiver no exit part reads, when the
state lives in a table or a single-instance codeunit, nor an event publisher, whose body is empty while its subscribers step. Deleting
either call can hang, and timeout and quarantine are not a guard on BC 29 on Linux until #49 lands.

**`itest:hang` rests on the event shape.** `OnAdvance()` in `fixtures/sandbox-hang` is what keeps its hangs since R830. Refusing it needs
yet another way to make that gate hang.

**Closed by ruling, 2026-11-06 (orchestrator, coord task R-842).** Counts on master f901f666, fixtures / CDO / DO / DC / BC.History:
- Claimed calls of either shape: 2 / 17 / 24 / 69 / 2,043. The 2 in fixtures are `OnAdvance()` in `CountUpTo` and `SpinUntil`.
- Real loop steps among them: 2 / 0 / 0 / 0 / 1. Cross-object: 2 table hits on BC.History, neither a real step.

**Since 2026-11-07:** #49's fix landed, so a hang costs a timeout on BC 28 and BC 29 alike, and the lines about #49 here are the record of their day.

**The limit.** A loop whose only progress runs through an event subscriber or another object's state stays claimed. Such a mutant costs a timeout, and on BC 29 on Linux it can end the run until SShadowS/LethAL#49 lands. In the README's Limits.

**Reproduced, still a limit (2026-11-10).** lethal-bugs' invented `/coord/handoff/R-895/fixture2/` (`while I < 3 do I := Stepper.Next(I);`,
`Next` in another codeunit) reproduces the class: 4 mutants inside `Next` loop forever and are not refused. Since R-895 (coord), a
hung mutant on v3 serve costs about one time limit, not the 90 minutes measured before it. On BC, the control app's stop handles it.
Kept closed (orchestrator, 2026-11-10): the measured share is tiny (11 specs in 2.3M, about one real site). Reopen only if a real
corpus shows more sites.
