**Filed 2026-10-24 by lethal-code during R-708.** Evidence: `/coord/handoff/R-708/flake-rootcause.md`, `/coord/handoff/R-708/ci-attempt1.log`.

**What happened.** CI run 40072847202, attempt 1, Windows `check` job: `reclaims the staged compile copy even when
compile() throws` (packages/runner/tests/bcdev-backend.test.ts) failed, plus one `(unnamed)` hook failure. The re-run
passed. No failure text was kept.

**Root cause (inferred, not reproduced).** `deploy()`'s `finally` made one `rm` call with `maxRetries: 3` and threw
away any error (`.catch(() => {})`). On Windows a virus scanner or indexer can hold a freshly copied file for longer
than that budget (R375 measured the same class on this runner). The `-staged` folder then stayed, and the test's `stat`
found it. The test's own `rmStaged` had no retries, so the folder leaked past the file and the R358 leak check in
`scripts/test-preload.ts` reported it: that is the likely `(unnamed)`. Whether Bun honours `maxRetries` is
unmeasured. There is no Linux repro (10/10 alone, 5/5 at parallel 4), and no failure text exists. The new CI upload
step below is how the next one is caught.

**Fix.** `removeWithRetry` (packages/runner/src/artifact.ts) retries EBUSY, EPERM, ENOTEMPTY and EACCES in our own
loop with a growing delay (about 4.5 s in all), then throws. It is used at `deploy()`'s `finally`, `compileCheck()`'s
`finally`, `stageForCompile`'s error path, `stageForCompile`'s own clearing of a stale copy (which now refuses with
`ArtifactPrepareError` if the folder is still there), `buildPackageCacheCopy`'s error path and
`removePackageCacheCopy`. A copy that still cannot be removed gives a
`console.warn` naming the folder and never masks the compile result. The test's `rmStaged` uses it too. CI: both jobs
upload `lethal-verify-*.log` on failure.

**Tests.** `removeWithRetry (R708)` in packages/runner/tests/artifact.test.ts (retry then remove; give up and throw;
non-lock error not retried), plus call-site tests in packages/runner/tests/bcdev-backend.test.ts through the
`removeDir` seam on `BcDevDeployment`.
