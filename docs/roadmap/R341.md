**Found by the review of R-323 run 001 (2026-09-29).** Review:
`H:/lethal-coord/reviews/R-323-001/review.md`, minor 1.

**What happens.** Since R323 the symbol table stores a named return value with its quotes stripped,
and the receiver classifier recognises a quoted identifier. But `computeType` in
`packages/engine/src/semantic/types.ts` handles `identifier` nodes, not `quoted_identifier`, and its
record-field and call paths also require an unquoted identifier. So a procedure declared
`Pick() "My Result": Integer` that uses `"My Result"` in its body gets no type there.

**Why it is low risk.** The use reads as unknown, so a typed operator emits nothing at that site.
That LOSES sites; it never uses a same-named global's type, which was R323's unsafe case. The same
gap applies to any quoted local or global, not only a named return.

**To close.** Type `quoted_identifier` the same way as `identifier` (quotes stripped, compared
without case), with a repro per path (plain use, record field, call), and a census of how many
sites it adds on the corpora. Keys move only if an existing mutant changes, so measure that first
and bump `IDENTITY_SCHEME` if any do (R325's rule).
