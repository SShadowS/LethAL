**The control app exposes no read-only peek at the lease, so nothing can answer "is this tier held?" without taking it.** `TryAcquire` (`extensions/lethal-control/.../ControlState.Codeunit.al`) mutates on grant — epoch++, token, `Commit` — so probing by acquiring is not an option for a read-only caller, and `HarnessInfo` (`ControlApi.Codeunit.al`) returns no holder, op kind or expiry. Measured consequence: `lethal doctor` (R109) cannot check the lease at all, and its first implementation shipped a `lease` check hardcoded to `"clear"` — a check that could not fail on any input, rendered as `[ok]`, advertised in `README.md`, and confidently green in exactly the stranded-lease scenario the recovery tooling exists for. That was caught in review and the check was withdrawn into doctor's "not checked" list rather than shipped. **This is "not implemented yet", not a platform limit**, and the control app already contains the precedent: `CurrentServerGeneration()` (`ControlState.Codeunit.al`) is documented as a read-only accessor added for the same reason — *"a plain informational read, not part of any mutating critical section, so it never takes a lock"*. Surfacing `Owner` / `Op Kind` / `Expires At` on that same read is the identical shape of change. Fix: extend `HarnessInfo` with those fields behind a `MIN_CONTROL_VERSION` bump, then restore doctor's lease check and move it back out of `DOCTOR_NOT_CHECKED`. Acceptance: a fixture holding a lease must make `lethal doctor` non-green — the property the withdrawn check could not have had. Filed 2026-08-05 from subsystem C's Task 4 review.

**Closed 2026-08-07, and the live run changed the design — which is the part worth reading.**

**Shipped.** `ControlState.CurrentLeaseSnapshot` is a read-only accessor in the shape
`CurrentServerGeneration()` already established (Get('') + fail loud, no `LockTable`, not part of
any mutating critical section). `HarnessInfo` carries its four values, so no new endpoint and no
second round trip: every client already calls `HarnessInfo` before it can acquire anything.
`MIN_CONTROL_VERSION` 1.0.0.14 → **1.0.0.16**, both containers republished. Doctor's `lease` check
is back in `checks` and out of `DOCTOR_NOT_CHECKED`.

**ONE Get, four out-parameters, deliberately.** Three separate accessors would each re-read the row
and could return values from three different lease states — a self-inconsistent snapshot is
precisely what a diagnostic must never hand an operator.

**What the live run found, and why 1.0.0.15 was wrong.** The first build surfaced
`Owner`/`Op Kind`/`Expires At` — exactly the three fields this row names — and `checkLease` treated
a non-empty `Owner` as "held". Run against a healthy Cronus281 immediately after a green
`itest:bcdev`, doctor reported:

```
[FAIL] lease: held by SShadowS-PC:199012:probes (op kind none, no expiry recorded).
```

`TryRelease` clears `Token`, `Expires At` and `Client Nonce` but **deliberately leaves `Owner`
populated**, so a cleanly released lease still names whoever last held it. An owner-keyed check
reports every healthy container as stuck, forever — the false-ALARM direction, and as useless as
the false-green the withdrawn check had. **This row's own prescription (`Owner` / `Op Kind` /
`Expires At`) is therefore incomplete**: it names no field that distinguishes held from released.

1.0.0.16 adds `leaseTokenPresent`, and the predicate is `tokenPresent || opKind !== "none"`. `Owner`
survives as INFORMATION — a green report now reads `no lease held (no live token, op kind none; last
held by …)`, which is strictly more useful than silence.

**The token itself is never transmitted, only whether one exists.** Handing out the lease credential
would let any caller impersonate the holder; a boolean answers the diagnostic question and leaks
nothing.

**Acceptance, measured live rather than argued.** Against an idle Cronus281:

```
ok: every check passed
  [ok] lease: no lease held (no live token, op kind none; last held by SShadowS-PC:199012:probes)
```

and against Cronus283 WHILE `itest:tables` genuinely held it:

```
[FAIL] lease: held by SShadowS-PC:153148:165 (live token, op kind publish,
       expires 2026-08-07T20:01:55.51Z). If no session is actually running, recover it with
       `lethal force-reset-lease …`.
```

That is the property the withdrawn check could not have had — and the read ran concurrently with a
live session without disturbing it, which is the other half of the contract.

**Red-checked at the predicate, not the function:** removing the op-marker half of the green
condition (so `owner === ""` alone passes) reddens the "an op marker with NO owner still fails"
test — the shape a killed session leaves behind.

**Also fixed on the way:** `doctor.test.ts` pinned the literal `"1.0.0.14"` in eight fixtures, so a
`MIN_CONTROL_VERSION` bump turned every green fixture red for a reason unrelated to what each test
was about. They now track the constant.
