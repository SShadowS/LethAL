**The control app exposes no read-only peek at the lease, so nothing can answer "is this tier held?" without taking it.** `TryAcquire` (`extensions/lethal-control/.../ControlState.Codeunit.al`) mutates on grant — epoch++, token, `Commit` — so probing by acquiring is not an option for a read-only caller, and `HarnessInfo` (`ControlApi.Codeunit.al`) returns no holder, op kind or expiry. Measured consequence: `lethal doctor` (R109) cannot check the lease at all, and its first implementation shipped a `lease` check hardcoded to `"clear"` — a check that could not fail on any input, rendered as `[ok]`, advertised in `README.md`, and confidently green in exactly the stranded-lease scenario the recovery tooling exists for. That was caught in review and the check was withdrawn into doctor's "not checked" list rather than shipped. **This is "not implemented yet", not a platform limit**, and the control app already contains the precedent: `CurrentServerGeneration()` (`ControlState.Codeunit.al`) is documented as a read-only accessor added for the same reason — *"a plain informational read, not part of any mutating critical section, so it never takes a lock"*. Surfacing `Owner` / `Op Kind` / `Expires At` on that same read is the identical shape of change. Fix: extend `HarnessInfo` with those fields behind a `MIN_CONTROL_VERSION` bump, then restore doctor's lease check and move it back out of `DOCTOR_NOT_CHECKED`. Acceptance: a fixture holding a lease must make `lethal doctor` non-green — the property the withdrawn check could not have had. Filed 2026-08-05 from subsystem C's Task 4 review.
