**Found 2026-10-06 by the R-373b plan review** (opus adversary standing in for sol;
`/coord/handoff/R-373b/review-r1.md`). A false-kill path that already existed; not introduced by
R-373b.

**What.** R247 refuses to resume (or to skip known survivors from) a run measured against another
test app, by comparing the run's recorded `testAppHash` with this session's. That hash comes from
`reportPublishedTestApp`, the published test app read BEFORE the lease. An env-tool session then
publishes its own test app (`envTool.publishApps`) in the lease-held hook. So:

1. Run 1 (env-tool) is measured with test app P1, records `testAppHash` P1 and some kills, and
   aborts.
2. The user weakens or deletes a test and rebuilds the published file as P2.
3. Run 2 with `--resume`: the pre-lease read is still P1, which matches, so the resume is accepted.
4. The hook publishes P2, and the carried kills are reported `killed` although the suite now
   running (P2) may not catch them: a false kill. Run 2's row also records P1 for a run measured
   under P2.

With `--skip-known-survivors` the same mechanism skips survivors (the safe direction).
Baseline-snapshot reuse is not affected: `scoreBatch` re-hashes the test app per batch, after the
hook.

**To close (R-373b, plan `docs/superpowers/plans/2026-10-06-R-373b-envtool-post-hook-digests.md`).**
After the hook, the published test app is read again. When a resume or `--skip-known-survivors`
baseline was resolved, the session proceeds only if that post-hook hash is DEFINED and EQUAL to the
pre-lease one (fail closed: an unreadable read-back refuses). The row's `test_app_hash` is rewritten
to the post-hook hash (NULL when unreadable).

**Closed (R-373b, 2026-10-06).** As built, after the final-diff review (`/coord/handoff/R-373b/review-final.md`):
- **`--resume` / `--resume-run`** (resolved before the lease): the session proceeds only if the
  post-hook hash is DEFINED and EQUAL to the pre-lease one; otherwise `TestAppRepublishedError`
  (`test-app-republished`) before the first baseline. Fail closed, red-checked both ways.
- **`--skip-known-survivors`**: narrowed from a guard (orchestrator, 2026-10-06). The history lookup
  itself (`priorSurvivorKeys`, re-read per batch) uses the post-hook hash; an undefined one matches
  no run, so nothing is skipped. This closes a concurrent-finish gap a one-time guard left, keeps the
  ordinary edit-and-rerun flow (warn, skip nothing), and only ever skips less.
- Every env-tool run's `test_app_hash` is rewritten after the hook to the post-hook hash, or NULL
  (`setRunTestAppHash`), so it records the test app that ran.

**Residuals, recorded.** (1) Env-tool rows written BEFORE this change hold the pre-lease, possibly
outgoing, hash; a false kill from one needs an external republish of the old package, a local file
reverted to match it, and an old crashed run holding kills: contrived, no code change. (2) Not
measured live (the env-tool environment is gone): whoever restores one runs `itest:envtool` with a
`--resume` leg before trusting this closure live.
