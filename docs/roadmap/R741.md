**Filed 2026-10-24 by lethal-preproc during R-738** (opus build review). Related: [[R738]], [[R740]].

**What.** [[R738]] refuses when BC's "The object with ID <id> does not have a member with that ID." names one of the
target's declared object ids. The target can also add members to ANOTHER app's object through a `tableextension` or
`pageextension` (for example a procedure on `Customer`). If this run's build removes or re-signs such a member, BC may
name the BASE object (`Customer`, 18), not the extension's own id. In that case R738 reads it as a non-target object.
Since [[R740]] the run still REFUSES, but with R740's dependency wording ("a member that a dependency no longer has";
the remedy, recompiling the tests app, still works because the target is one of its dependencies), so the cause is
misattributed, not silent. Not measured: BC may name the extension instead.

**To close.** Measure on bc2 under a pre-commitment, as R-738's probe did: a target with a tableextension procedure
that a test calls, a run whose source removes it, and the recorded baseline message. If BC names the base object,
extend `targetObjectIdsOf` with the ids of the objects the target EXTENDS, as base ids that mean "a member the target
added", test-first.
