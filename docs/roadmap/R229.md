title: "A reader mark on a TRIGGER mutant never matches: the report joins marks on `procedureName ?? triggerName`, and a trigger's `procedureName` is `\"\"`"
section: "correctness-risks"
status: "open"
order: 941
---

**Found by reading, while planning C02-01 (2026-09-25).** `buildReport` builds each mutant's mark
identity with `procedureName: m.procedureName ?? m.triggerName ?? ""`
(`packages/runner/src/report.ts:2127`). For a trigger mutant `procedureName` is the empty string,
not `undefined`, so `??` never falls through to `triggerName`. `identityKeyOf`
(`packages/runner/src/selection.ts:43`) uses `||` and does fall through.

**Consequence:** a `lethal.equivalent.json` mark written from a trigger mutant's key (which is built
the `identityKeyOf` way) never matches in the report, and is listed under
`readerMarkedEquivalent.stale` as if the mutant had gone away. The reader's ruling is silently lost.

**Fix shape:** build the identity through `identityKeyOf` (or use `||`) at that site so there is one
definition. Red-check: a test marking a table-trigger mutant that goes red with `??` restored.

Not measured live.
