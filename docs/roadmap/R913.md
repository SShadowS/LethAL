Found by lethal-code, 2026-11-10 (coord R-912's follow-up). Related: [[R912]], [[R602]].

**What happened.** R-912's v3 gate on b85e3851 printed `al-runner-v3 itest: PASS` and was cited as "the full v3 gate". It was run without
`LETHAL_ITEST_V3_CDO` and `LETHAL_ITEST_V3_TABLES`, so the D legs (D1, D1c) and leg T never ran. R912 had added a warning that leg D1 does
not allow, and lethal-bugs' gate, run WITH the D legs, failed on it. The failure reached master because the PASS did not say what it had left out.

**Why.** The legs are opt-in by environment variable (`al-runner-v3.itest.ts`: the D legs refuse with `LETHAL_ITEST_V3_CDO unset` only when
asked to run; otherwise O1 prints that the CDO set "is skipped"). The final PASS line (`gate-warnings.ts`) names no skipped leg.

**To fix.** Either:
- the PASS line names every skipped leg, for example `PASS (D1, D1c, T skipped: LETHAL_ITEST_V3_CDO, LETHAL_ITEST_V3_TABLES unset)`; or
- the gate refuses to say PASS without them unless an explicit flag allows a partial run, for example `LETHAL_ITEST_V3_PARTIAL=1`.

Lanes should also check their recent gate receipts for D-leg and T-leg coverage. The full form in use: `LETHAL_ITEST_ALRUNNER_V3=1
LETHAL_ITEST_V3_TABLES=1 LETHAL_ITEST_V3_CDO=/work/lethal-wt/cdo-r396`, where `/work/src/do-lethal` lacks the pinned `Test/.alpackages`.
