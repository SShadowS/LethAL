**Found by the R-323 plan's hunt (2026-09-29).** Plan:
`docs/superpowers/plans/2026-09-29-R-323-named-return.md`.

**What breaks.** A preprocessor block that covers only PART of a procedure header, the named return
value and its type, does not parse in tree-sitter-al. The whole member becomes an `ERROR` node that
starts at `procedure`, and nothing after it in the member is structured, so the engine emits no
mutant for it. `alc` accepts the same source under every symbol subset.

**Repro.** Hand-written `n10` in the R-323 scratch set: a procedure with `#if CLEAN27` / `Result:
Text` / `#else` / `Result: Integer` / `#endif` between the parameter list and `begin`. `alc` passes
under both subsets. The same happens when only the type is conditional.

**Size.** 0 such `ERROR` nodes in DC/Cloud, System Application, BusinessFoundation and BaseApp. A
completeness gap, not an urgent one.

**Fix direction.** Upstream, in `SShadowS/tree-sitter-al`: a procedure node (or a split shape like
`preproc_split_procedure`) whose `return_value` / `return_type` sit inside the arms. The issue draft
is in the R-323 plan, section "Notes: upstream grammar observations". File it upstream with the
hand-written repro (project rule: grammar bugs get filed on `SShadowS/tree-sitter-al`), then link it
here. Closes when the grammar parses it and a fixture or repro pins one mutant in such a member.
