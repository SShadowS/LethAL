**Filed by R384 (its plan's Finish task, 2026-10-04).** `lethal verify` runs every new test twice
unmutated (baseline and rerun) to check it is stable before any mutant runs. R384's reach filter
then decides, per survivor, which new tests to send. A new test the filter sends to NO survivor
still pays both unmutated runs, so the cost is 2N runs even when nothing is left to measure.

The budget R384 uses (`too-many-new-tests` as a run budget) counts those 2N runs, so an edit that
makes many tests "new" but reaches few survivors can still be refused on the stability runs alone.

**To close.** Skip the rerun for a test the filter sends to no survivor (the baseline run is still
needed: it is where the coverage comes from). That needs a new `NewTestState` value so the report
says the test was not rerun rather than calling it stable; check the verify schema and rule on the
version bump first. Pin with a test that a reach-nothing test runs once, and that a test reaching
one survivor still runs twice.

**Closed 2026-10-04** (plan `docs/superpowers/plans/2026-10-04-R-427-skip-rerun-unreached-tests.md`).
No phase moved: the reach filter already decides before the first mutant, and the stability rerun
runs after the last one. A new test the filter sends to no survivor now runs once, the baseline that
supplies its coverage, and the report gives it the new `NewTestState` `not-rerun`, never `stable` or
`flaky`; no verdict depends on it, so it exits 0. Every fail-closed test is still rerun: filter off,
the filter never called (session latched), and red, infra-failed, not fresh or empty-coverage tests,
which join every survivor. `verify.ts` checks that the not-rerun tests are exactly the ones no
survivor received, and `applyNarrow` refuses a not-rerun test with an invalid baseline before any
mutant runs. The budget refuses only less: check 1 (before the lease) is now N > B, check 2 counts
N + R + P with R the reruns actually planned, and its text is unchanged when every new test is
rerun. The verify report is schema v6 (v5 kept as published, since a new enum value changes its
value domain).

Measured on Cronus28 at commit 8f74a681: `itest:agreement` and `itest:verify` pass, and every value
matches the addendum committed BEFORE the run (`docs/superpowers/specs/2026-10-04-r427-not-rerun-precommitment.md`):
`Harden Verify Answers.BonusForTwiceOnOneInstance` (K5, whose only survivor is skipped as
equivalent) is `not-rerun` with one run, everything else unchanged. With the skip disabled, the
agreement gate fails on that K5 assertion (`stable`, two runs). R-384's old check-2 fixture, three of
four new tests reaching no survivor, is kept as a positive test: it now passes check 2 where it used
to refuse.
