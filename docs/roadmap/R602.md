**Found 2026-10-21** while building [[R586]]'s al-runner-v3 backend (plan
`docs/superpowers/plans/2026-10-21-r586-alrunner-v3-backend.md`, M1). Closed by coord task R-602 (2026-10-24).

**What it was.** With coverage on, the v3 backend refused a batch holding a multi-object file
(`AlRunnerCoverageFrameError` in `AlRunnerV3Backend.deploy`), and the CLI turned v3's coverage off
(`al-runner-v3-coverage-off`) for any project holding a multi-object or an `#if`-wrapped object file. The refusal
was built for the retired v2, which reported every object after a file's first in the wrong frame (R383, R407).

**Measured (R-602, 2026-10-24; `/coord/handoff/R-602/measure.md`).** On the pin (alpha.2, 91253f2d6) and the edge
(alpha.4, 57f1e4f98), with identical output, v3 reports every statement in its own file's frame, per object:
0 lines outside a statement and 0 scope mismatches on `sandbox-multiobject`, `sandbox-wrapped`, and a synthetic
app (enum, table, page, codeunit mixes; a multi-object file with an `#if` around its middle object; `#if/#else`
without the define; a multi-object test-app file; a codeunit and a table in one file). A per-mutant differential
against `--mode none` (the ground truth), 0 join mismatches:
- `sandbox-multiobject`: 0 lost kills; 5 `no-coverage` -> `survived`, all in procedures no test calls.
- `sandbox-wrapped`, index admitted AND the selection rule `al-runner-index`: 95 of 98 mutants match `none`; the
  3 that move are the two-arm control `WrappedArms` (2 kills lost, 1 survived -> no-coverage), refused by name.

**What changed.**
- The index always indexes a multi-object file (`admitMultiObjectFiles` is deleted); the `deploy` throw is gone;
  the CLI guard no longer names multi-object files (`v3CoverageMode`).
- `wrappedRuleFor("al-runner-v3")` is `al-runner-index`, so selection and the index apply one rule
  (`alRunnerAdmitsWrappedFile`); `carryBarredFiles` follows (an admitted wrapped file takes no carried verdict).
- Coverage stays OFF, by name, for any other wrapper shape: two-arm `#if/#else`, `#elif`, nested, or a
  multi-object file holding a wrapper. The warning and the per-object refusal sentence say that the index has no
  rule for the shape; v3's frame is not blamed (measured correct).
- For an admitted wrapped file, a `scope` that disagrees with its position now THROWS `AlRunnerCoverageFrameError`
  instead of warning and dropping the line (0 mismatches measured, so it costs nothing on measured shapes). Its text and the
  frame errors name `"alRunnerV3.coverage": "none"` and cite this measurement.
- Gate legs `MO` and `WR` in `itest:alrunner-v3`, each with a durable killer constant (every mutant `none` kills must
  be killed by the same test) that record mode never writes. (At the build they were default legs outside
  `V3_GATE_LEGS` with pending baselines. Since then both are in `V3_GATE_LEGS`, `PENDING_FIRST_RECORD` is empty, and
  `al-runner-v3.multiobject.baseline.json` and `al-runner-v3.wrapped.baseline.json` are recorded, pre-committed in
  c2f67f0a and recorded in 0c6eb0b2; updated by the R-755 audit.)

**A user-visible correction, not only a speedup.** Before this change, a v3 project whose `#if`-wrapped files were
all single-wrapper shapes kept coverage ON (the CLI guard listed nothing) while selection refused every wrapped
object by name (`refuse-wrapped`). Their mutants read `no-coverage`: 32 of 98 on `sandbox-wrapped` were kills that
`--mode none` finds. So "v3 projects with single-wrapper #if files reported killed mutants as no-coverage" (fixed
here; ruled 2026-10-24 to stay in this branch), and the earlier wording of this item ("the refusal costs speed
only") and of the gate page ("by design") were wrong for those projects. Verdicts change: multi-object files go from
`survived` to `no-coverage` for code no test calls; single-wrapper files go from `no-coverage` to `killed` or
`survived`.

**Stated limits (still refused by name or stopping the session).**
- An admitted wrapped file whose INSTRUMENTED text re-parses undecided is refused by name after deploy
  (`undecidedArmsReason`); a key declared in two files is refused by name (`duplicateObjectRefusals`).
- A label outside the bundle, or a scope its position contradicts, in a multi-object or admitted wrapped file stops
  the session (`AlRunnerCoverageFrameError`, R407).
- Not measured: the `serve-entries` transport (the index reads only baseline calls, and the baseline stays
  one-shot), `#elif`, a nested object wrapper, a wrapper with objects of different ids in its arms, tables with
  many triggers, a large project. One BC version string, one fixture size.
