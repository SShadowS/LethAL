**Found 2026-10-21** while building [[R586]]'s al-runner-v3 backend (plan
`docs/superpowers/plans/2026-10-21-r586-alrunner-v3-backend.md`, M1).

**What.** With coverage on, the v3 backend builds the same coverage index the .NET al-runner uses
(`buildAlRunnerCoverageIndex`) and REFUSES a batch holding a multi-object file
(`AlRunnerCoverageFrameError` in `AlRunnerV3Backend.deploy`). The CLI turns v3's coverage off, with the
warning `al-runner-v3-coverage-off`, for any project holding a multi-object or an `#if`-wrapped object
file (`buildAlRunnerV3Backend` in `cli.ts`). There is no v3 frame probe (R407's probe speaks v2's CLI),
so no v3 build can be admitted.

**Measured 2026-10-23 (coord task R-435; probes in `/coord/handoff/R-435/probe/multi/` and `wrapped/`).** v3 does
not share v2's defect in the two shapes probed, on alpha.2 (91253f2d6) and edge alpha.4 (57f1e4f98):
- two codeunits in one file, the test calling the second: both builds give file-relative lines in the right file
  (the second codeunit's lines hit 1 per test, the first's hit 0);
- a codeunit inside `#if X ... #endif` with `--define X`: both builds count the `#if` line and give the
  codeunit's lines hit 1.

So the refusal costs speed only: every mutant of such a project runs against all green tests. The code is
unchanged and stays, because the shapes are not all probed.

**Not probed.** `#if/#else` with objects in both arms; `#if` without the define; multi-object files in the test
app; an enum then a codeunit in one file; tables and pages; LethAL's own parse of a wrapped file (`evaluateArms`).

**What lifting it needs.** A pre-committed per-line expectation for `fixtures/sandbox-multiobject` and
`fixtures/sandbox-wrapped`; an alrunner-v3 gate leg for each (the gate page lists them under "Legs ruled out");
then admit the shapes (`admitMultiObjectFiles` exists in the coverage index). Status stays open for that.

**Why it may be unnecessary (the original reasoning).** The refusal exists for v2's mixed-frame defect: v2 reported every object
after a file's first in a frame LethAL cannot undo (R383, R407). v3 reports statements with a
FILE-relative `line` and a `scope` per statement in `--coverage-json`. If it never shares the defect, the refusal costs every multi-object or wrapped project its
coverage on v3 (every mutant then runs against all green tests: slower, never a wrong verdict).

**Not a correctness gap.** The refusal is the safe direction for selection. The Sleep rule (R586 §6)
does not depend on it: every v3 call requests `--coverage-json` and the rule matches RAW lines whatever
the session's coverage mode (pinned by the `item 6` test in
`packages/runner/tests/al-runner-v3-backend.test.ts`).

**To close.** Measure v3's coverage frame on `fixtures/sandbox-multiobject` and on the wrapped fixture
(the shapes R383 and R-300b measured on v2), per object and per line. If v3 reports every object in the
instrumented file's own frame, admit those shapes on v3 by a pre-committed rule and its own gate leg;
otherwise state the measured defect here and file it upstream.

**Since R654 (2026-10-23).** The .NET al-runner was deleted in R654 S3 (35f3c67f), with `itest:alrunner`'s
multi-object and wrapped legs and R407's frame probe. So no backend measures this frame live any more: the refusal
rests on v2 measurements alone. The code is unchanged. `buildAlRunnerCoverageIndex` and `AlRunnerCoverageFrameError`
stay in `al-runner-coverage.ts`, and `alRunnerCoverageSupport` still turns v3's coverage off (`al-runner-v3-coverage-off`).
`fixtures/sandbox-multiobject` and `fixtures/sandbox-wrapped` are kept for this measurement. The v3 gate rules the two
shapes out as legs for now ("Legs ruled out" in `docs/gates/alrunner-v3.md`).
