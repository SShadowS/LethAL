Until 2026-08-16 the repository had no `.github/` directory at all: nothing ran `bun run typecheck`,
`bun test` or the roadmap-index check on a push, on a repository that is public and about to be
shown to strangers.

Two workflows now exist:

- `.github/workflows/ci.yml` — push and pull request. Typecheck, remove `packages/*/dist`, unit
  tests, in that order (the order is the one CLAUDE.md gives, and the clean sits between the two
  because `tsc --build` regenerates the stale compiled `*.test.js` that produce ~21 phantom
  failures).
- `.github/workflows/release.yml` — on a `v*` tag. Refuses a tag that disagrees with the root
  `package.json` version, runs the same gate, builds all five targets, smoke-tests the Windows
  binary with `--version`, and opens a DRAFT release with the binaries attached.

**Neither has ever executed.** They were written from the local build loop, not derived from a
green run, so every claim in them is untested: the `oven-sh/setup-bun` pin, whether the unit suite
is green on a hosted `windows-latest`, whether `bun run build:binaries` can cross-compile five
targets inside an Actions runner's disk and time budget, and whether the release action's glob
matches. Treat the first push and the first tag as the test.

Three known limits, deliberate rather than overlooked:

- **windows-latest only.** This is a Windows-first tool and the unit suite has never been run on
  Linux. Adding `ubuntu-latest` is worth doing and will probably surface path assumptions; it is
  not a blocker for the binaries, which cross-compile from one machine.
- **No `biome check .`.** Repo-wide it fails on pre-existing organizeImports and format debt in
  `engine`/`builtin-tier1`, so adding it would fail every build and teach everyone to ignore the
  job. Cleaning that debt is the prerequisite.
- **`lethal-control.app` is not attached by CI.** Building it needs `alc` from the AL VS Code
  extension, which no hosted runner has, and `*.app` is gitignored so no committed copy exists to
  attach. This is why the release is a draft: a human attaches the control app and names its
  version before publishing.

Evidence: the two workflow files, and `docs/releasing.md` §"Tagging a release", which states the
same "never run" warning where someone cutting a release will actually meet it.
