**Found by the R-302 plan's review r1 (2026-09-29), finding C2**, and measured on PLAIN procedures
at `00e514c4`. Plan: `docs/superpowers/plans/2026-09-28-R-302-split-semantics.md`, "Revision r2".

**What breaks.** `resolveIdentifierType` (`packages/engine/src/semantic/types.ts`) finds a local,
parameter or global by `v.name === node.text`. AL names are case-insensitive. So a reference spelled
`Y` to a parameter declared `y` misses the parameter; if the object declares a global `Y`, the
reference takes the GLOBAL's type. The two operators that read types (`swap-additive`,
`swap-call-arguments`) then decide on the wrong type. `lookupVar` (`semantic/receiver.ts`) already
compares case-insensitively, so the receiver path is not affected.

**Measured** (hand-written repro `e1-case-plain`, a plain procedure `Pick(X: Integer; y: Text)`,
global `Y: Integer`, body `Show(X, Y)` with overloads `Show(Integer; Integer)` and
`Show(Integer; Text)`): HEAD emits `swap-call-arguments` there, and the instrumented project FAILS
`alc`, `AL0133: Argument 1: cannot convert from 'Text' to 'Integer'`. A whole-project compile failure
after the expensive part of a run. Without a same-named global the miss is silent under-generation
instead (repro `e3-case-adds`: `Amount + rate` against `amount` and `Rate` gets no `swap-additive`).

**Size** (a read-only census of HEAD at the positions the two operators read): 0 triggers in every
fixture, BusinessFoundation and the BaseApp scratch project; 7 in DC/Cloud and 19 in System
Application, none of the wrong-global kind. Applying the fix's rule to those corpora changes DC/Cloud
by 0 mutants and adds 5 in System Application (pre-committed in the plan).

**Closing.** Fixed in R-302 (it hits the split-member resolver the same way): the lookup compares
case-insensitively. Closes with that commit and a test that goes red on the case-sensitive compare.

**Done (2026-09-29, R-302, `db641338`):** variable names compare case-insensitively (`sameName`, `types.ts`). The unit test goes red when the fix alone is
reverted, and the pipeline pins in `packages/runner/tests/preproc-instrumentation.test.ts` do too.
Pre-committed corpus effects matched (see [[R302]]'s closing record).
