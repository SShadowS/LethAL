**Filed 2026-10-25 by lethal-preproc, from coord task R-773.** Related: [[R635]], [[R651]], [[R761]], [[R774]].
Evidence: a gift-card run of `scripts/v3-timing.ts` under `/coord/handoff/R-773/`. The serve daemon ran, but
`stderr.txt` holds no `serve-entries (R635)` counters line.

**What.** The `run` subcommand's cleanup in `packages/runner/src/cli.ts` closes the backend only when it is a
`BcDevMcpBackend`. `AlRunnerV3Backend.close()` is never called from the CLI, so on every v3 run:
- the serve-entries counters line (requests, kill pairs, and the wall split into warm-up, live, windows and bound)
  is never printed. That split is exactly what the owner's timing table needs, and today only the itest prints it,
  because the itest calls `close()` itself;
- the serve daemon is not shut down by `closeDaemon()`. It ends only because the process exits;
- `<instrumentedDir>/cov` is not removed.

Verdicts are unaffected: the session has already scored every mutant by then.

**To close.** Close any backend that has a `close()`, not only bcdev, with the same best-effort guard. Add a test
that a v3 backend built by the CLI is closed after the session.

**Done (2026-10-25).**
- `ExecutionBackend` has an optional `close()`.
- The cleanup of both `run` and `verify` closes any backend that has one. It stays in the `finally`, and a failing
  close is warned about, never thrown.
- Tests in `cli-envtool.test.ts` ("R775: runFromCli closes the al-runner-v3 backend"):
  - a successful run and a run that throws both close the v3 backend;
  - a failing close does not replace the run's own error;
  - a real serve-entries backend prints its counters line and removes `cov/`.
- Red-checked both ways: with the bcdev-only gate back, all three go red; with a close that rethrows, the
  error-path test goes red.
