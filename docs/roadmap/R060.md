**Every LethAL verdict describes the app's NON-GUI branch, and nothing says so.** Measured under R57: the fenced `RunMutant` path — the source of every verdict LethAL produces, on every backend and in both coverage modes — runs as **`GuiAllowed=No`, `ClientType=ODataV4`**. A developer running the same suite from VS Code runs GUI-allowed. So any AL guarded by `GuiAllowed`, or branching on `Confirm`/`Message`/`Page.RunModal`, takes the non-interactive path during mutation testing, always. Consequences: **(a)** a mutant inside a GUI-only branch can never be killed, because that branch never executes — it will be reported `survived` or `no-coverage`, and both readings are wrong ("your tests are weak here" when in truth LethAL never ran it); **(b)** a suite whose tests exercise UI handlers is measured against different behaviour than it was written for; **(c)** the mutation score's denominator silently includes code that was unreachable by construction. None of this is stated anywhere in the README, `design.md`, or the report's `validity` block. At minimum it belongs in Limits and probably wants a `guardObserved`-style signal, since R46 already proved this project cannot distinguish "ran and survived" from "never ran" without attestation. Not measured yet: how much real AL sits behind such guards — worth counting on Document Output before deciding how loud this needs to be.
