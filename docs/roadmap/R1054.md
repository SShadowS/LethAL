Filed by coord PR-40 (2026-11-15), found while building that task's copies of four System Application modules. Evidence:
`/coord/handoff/PR-40/src/` (the copies; their 27 glued headers were rewritten with a space before LethAL would run them).

**What.** `alc` compiles a header written `codeunit 50100"Name"` (no whitespace between the object id and a quoted name), and the
native parser parses it without an error node (probe: `codeunit 50100 "Spaced"`, `codeunit 50100"Glued"` and `codeunit 50100Bare`
all parse). `discovery.ts`'s `CODEUNIT_HEADER_GLOBAL` requires `\s+` between the id and the name, so such a header is not matched.
For a test file, R79's guard (`assertEveryTestConsumed`) turns that into a loud refusal, not a silent loss of the suite; the
tool still refuses a project that the compiler accepts.

**Fix.** Allow no whitespace before a quoted name (`\s*` before `"`, `\s+` before a bare name), on every header regex that
reads object ids (the codeunit header and the id-listing helper beside it), with a unit test for the glued shape. Check the other
object kinds' header readers for the same assumption.

**How often.** Rare in hand-written AL (the formatter inserts the space); it arises from generated or rewritten source, as here.
