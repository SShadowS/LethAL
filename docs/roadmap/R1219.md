**Found by** PR-436 (lethal-code, 2026-11-25). Evidence: `/coord/handoff/PR-436/findings.md`, `scaled.py`. The figures
are lane-seconds of c5 (PR-422), which ran under load.

- **What was measured:** of the 83,736 lane-s that c5's prefetch and live requests spent in al-runner's `tests` timing,
  about 42,000 are in no test row.
  - Over about 157k entries, that is about 268 ms each.
  - A fit over 3,655 requests gives `testsMs ≈ 524 ms × entries + 2.1 ms × tests` (R² 0.74). Its entry term holds about
    265 ms of rows, which leaves about 260 ms fixed.
  - m1's single-test requests (PR-434) show the same cost directly: 483.3 s in `tests` against 83.6 s of rows, about
    200 ms per request.
- **Where it likely sits:** the start and reset of each entry's codeunit run under `--isolation test` (OnRun, the
  rollback point, the runner). Nothing LethAL can see splits it.
- **Next:** al-runner's serve `timings` would split `tests` per request into entry start/OnRun, reset/rollback and test
  bodies (asked through the orchestrator). Then choose: a cheaper reset upstream, or fewer entries (R1220).
- **Bound:** about 43% of the mutants phase. That is the whole fixed cost; only part of it is likely removable.
- **Attributed by PR-439 (lethal-code, 2026-11-25; `/coord/handoff/PR-439/findings.md`).**
  - **The run:** alrunner's measurement build (fork branch `measure-tests-split`, 75946a31f), built from a clean clone and
    gated privately (PR-226's route). One scoped DO mutant run (one file, 3 workers, mean load1 89). Every request
    carried `testsParts`.
  - **Per codeunit (one per entry):** `loginMs` 240 ms in prefetch and 256 ms in live, which is 29% and 46% of `testsMs`.
    `onRunMs` ~0.1 ms, `sessionMs` ~1 ms, resets a few ms. The per-test rollback sits inside the rows.
  - **So the fixed cost is the login and company open of each entry's fresh codeunit run** (alrunner's C2: install
    steps, then the login).
  - **Who can cut it:** al-runner, through login replay (PR-402, R1182; the switch #8665 merged upstream on 2026-11-25;
    coord PR-420). LethAL-side, only fewer entries (R1220, R1221).
  - **Not measured:** the replay saving on DO. LethAL refuses `alRunnerV3.loginReplay` without the build's
    `login-replay` fact, and no build records it yet. Also not measured: the split inside C2.
- **Related:** R1216, R1220, R1221, PR-436, PR-439, PR-402, PR-420, PR-113 (the request timing events).
