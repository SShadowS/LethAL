**Filed 2026-10-24 by lethal-preproc during R-707.** Related: [[R707]], [[R709]], [[R605]].

**What.** Since R-707, `bc-linux-setup.ts` and `bc-republish.ts` REFUSE a target change that breaks an
installed dependent's resident source (`resident-dependent-breaks`). The operator then follows the safe manual
sequence: (1) uninstall and unpublish the dependent; (2) publish the target (after a gate run, with `--mint`,
R605); (3) publish the new dependent build. Option B would do those three steps in the script, behind an explicit flag, so a signature-changing target
change needs no manual work.

**Not built.** Build it only if a lane needs it. It must not run without the flag, because it removes an
installed app.

**Needs first.** A measurement of the whole three-step sequence behind a flag. R605 records that a single
same-version test-app republish after an unpublish was accepted on bc3 (the restore); the sequence as a whole
(remove the dependent, publish the target, republish the dependent) is not measured. Also decide the failure path: if step 2 or 3 fails, the
dependent is already gone, so the script must say so and name the recovery.
