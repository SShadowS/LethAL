**Found by R-297 Task 6 (2026-09-28)**, plan
`docs/superpowers/plans/2026-09-28-R-297-instrumentation-real-corpora.md`, "Root causes" and Task 6.
A defect in the product today, not only in a corpus run: any mutant in such a member that needs a
reach latch makes the whole instrumented project fail to compile.

**The shape.** BaseApp retires a local variable by putting the member's whole `var` section inside a
directive, `#if not CLEAN<n>` / `var` / declarations / `#endif`, sometimes with an `#else` arm holding
a second `var` section, then `begin`. The parse is `preproc_conditional_var_block` between the
header and the `code_block`.

**What goes wrong.** The reach latch (`injectReachLatches`, `packages/schemata/src/compile.ts`)
finds no plain `var_section` on the member, so it emits its own `var LethALReachLatch: Boolean;`
right before `begin`, after `#endif`. In any build where an arm contributes a `var` section, the
member now has two `var` sections, which AL does not allow.

**Measured on hand-written repros** (Task 6 scratch, invented names), one per member kind, each with
a de-preprocessed twin:

| repro | instrument | sites vs twin | alc, symbol absent | alc, symbol defined |
| --- | --- | --- | --- | --- |
| procedure, `#if` arm only | no throw | equal | FAIL (AL0104) | PASS (no `var` in that build) |
| trigger, `#if` and `#else` arms | no throw | equal | FAIL (AL0104) | FAIL (AL0104) |

The un-instrumented sources compile under both symbol sets, so the failure is LethAL's. The site set
and manifest fields are right (checks a to c pass); only the emission is wrong.

**Corpus counts** (Task 0's census): BaseApp 12 files, 14 members (11 procedures, 3 triggers,
among them `GetUnplannedDemand`'s `OnRun` and procedures in `MfgCreateInventoryPutaway`,
`ProdOrderComponent`, `ProdOrderWarehouseMgt`, `MachineCenter`, `WorkCenter`). Zero in dc, sysapp
and bcf, and zero in every `fixtures/*` project, which is why no gate has seen it.

**Why it is not a small fix.** The latch must go into EACH arm's `var` section, and into a new
`var` section for an arm that has none, so both builds declare it exactly once. That is a per-arm
edit and a new placement rule, not one condition.

**Reproduce.** Write a codeunit with `procedure P(X: Integer): Integer`, then `#if not SYM` / `var`
/ `L: Integer;` / `#endif`, then a body with an `if`, instrument it, and compile the target with
`SYM` absent.

**2026-09-28: the hoist lands (`9a308e1`), R-303 Tasks 2-4. Closed.**

**The rule.** `splitVarHoistAnchor` (`packages/schemata/src/dispatch.ts`) admits a member only when
the token right before its `preproc_conditional_var_block` is the header's actual end, computed by
`headerEndOf`: the parameter list's closing `)`, else the return type after it when the header has
one (plain or named), and then a `;` directly after that end, when the header has one
(`s3-semicolon-comment`, and the `local procedure ... r: Integer;` probe). `injectReachLatches`
then writes ` var <latch>: Boolean;` once, right after that anchor, and blanks each arm's own `var`
keyword to
the same number of spaces, so the arms' declarations simply continue the one already-open var
section instead of opening a second one.

**Why not duplicate the latch into each arm instead.** An arm that declares nothing (an empty
`#else`, or a member with only one populated arm) has no `var_section` of its own to write a latch
into: giving it one would need a brand-new line, and the fix must not add or remove lines (see
next point). Hoisting one latch onto the header's own line, and only blanking existing `var`
keywords in place, adds no line anywhere.

**The anchor holds under attributes and multi-line parameters** because `headerEndOf` walks the AST
to the header's real structural end rather than guessing from text position: an attribute before the
member (`s9-attribute-before`) and a parameter list spanning several lines (`s10-multiline-params`)
both anchor correctly and both alc-PASS.

**Only LINE numbers are preserved; offsets and later columns move.** The insertion adds characters
to an existing line, never a newline, so every line number in the file stays what it was; any node's
byte offset past the insertion point shifts, and columns on the header's own line change after the
insertion point.

**Two shapes stay refused by name, both with zero corpus members:** a pragma-only `#if` block
sitting before the var block (`r1-pragma-first`), and a split-header procedure followed by one
(`r2-split-header`), neither has the anchor `splitVarHoistAnchor` requires. **A third, separately
named refusal, filed as [[R313]]:** a member whose var section tree-sitter-al cannot parse cleanly

ever runs. All three refusals are named in the `reach-latch-refused` warning and leave the member's

**A third refused shape.** A `preproc_split_procedure_preamble` (a split-header procedure whose

**2026-09-28: directives around the var section, R-303 run 002 (review r1 finding 1).** `#pragma`,
`#region` and `#endregion` are grammar extras, and the latch writer treated any last non-comment
child of a var body as a declaration, so a trailing directive could in principle receive the latch
on its own line. Measured on hand-written repros (`d1-trailing-pragma`, `d2-trailing-endregion`,
`d3-trailing-region`, `d4-if-then-pragma`, `d5-pragma-then-if`, `d6-header-pragma-var`,
`d7-pragma-only-var`, `d8-split-then-pragma`, `d10-novar-pragma`, and the refused control
`d9-header-region-split`):
tree-sitter-al 4.4.1 attaches a TRAILING directive to the member, not to the var section, in every
shape tried (and in seventeen more parse-only variants), so HEAD already put the latch on the last
declaration's line, before the directive, and alc PASSED `d1` to `d9` under every symbol subset
at HEAD. The rule is now an allowlist anyway (`latchAnchorInVarSection`,
`packages/schemata/src/compile.ts`): only a `variable_declaration` as the last child keeps the
declaration anchor, and anything else takes R312's anchor after the `var` keyword. Emission is
byte-identical to HEAD on `d1` to `d9`. `d10` (a `#pragma` right before `begin`, no var
section) was measured after the change only; its path, a new `var` written before `begin`, is not
touched by it. The alc and al-runner proofs (v2.11.0, every subset,
every mutant `reachGrain=statement`, `d9`'s `unplaced`) are scratch evidence, not committed gates;
the committed pins are structural, in `packages/schemata/tests/compile.test.ts` (the `R-303 run 002`
describe, and HOIST_CASES `S6` and `D8`).
