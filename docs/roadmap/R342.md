**Found 2026-09-29, while closing [[R242]].** After provisioning, `runSession` re-runs the R149
contract probe with `--package-cache <pin>`, because that is the argv every one-shot mutant uses.
Since R242 a `--server` backend declines the pin, yet the re-probe still runs whenever provisioning
reported a directory.

**What is wrong.** On a server session the probe measures a one-shot command line that no mutant
runs, and it can refuse the session on what it finds. The cost is one extra al-runner invocation
per session. No verdict is affected.

**Fix.** Run the pinned re-probe only when the session backend consumed the pin (the same answer
`usePlatformAppsDir` gives). Whether the server transport needs a contract probe of its own is a
separate question.

Evidence: `runSession` in `packages/runner/src/orchestrator.ts`, the R149 block right after
`pinPlatformAppsDir(cfg.backend, ...)`.
