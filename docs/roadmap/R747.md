**Found by R-746's plan review (2026-10-24).** `warnOnThinFencedCoverage` in `packages/runner/src/bcdev-backend.ts`
only looks at the whole test: it warns when the test has no member entry at all.
- LethAL's own generated objects (the selector codeunit, whose `Active` procedure runs on every instrumented call)
  are declared in the artifact and covered by nearly every test. Each gives a member entry.
- So on a full (not narrowed) run the check stays quiet even when every row on the user's own target objects landed
  in the wrong place. It can only fire for a test that reaches no instrumented site, which in practice means a
  narrowed slice such as chunked's `--only` run.
- Measured: in a full `sandbox-data` run the selector's `Active` procedure (codeunit 79399) is covered, so
  `memberEntries` is at least 1 and the warning never fires.

**Choice (2026-10-24, coord task R-747): option (b), judge per object.** The check now warns for each declared,
unrefused object that has a naming gap and no member row in the test, and names those objects.
- No list of generated objects is needed: the selector's own rows always name `Active`, so it never masks a target and
  never warns itself.
- Strictly more precise than leaving generated objects out: a correct object no longer masks a shifted one.
- Attribution is unchanged (warning only). The gate warning pins are NOT moved here; an observe pass decides that.

**Known blind spots.**
- (i) An object with member rows plus gap rows stays quiet, though that is the likeliest real 1-2 line shift
  signature. Filed as R748.
- (ii) An R318 renamed split member with no coverage name sits in `unnamed`, which `isNamingGap` does not consult. A
  test covering only such a member, with nothing named in that object, now warns with a false frame blame. In practice
  only the symbols fixture has this, and only al-runner v3 gates run it, not bcdev.
- (iii) BC rows on report column, page field and property expressions are unmeasured on real projects.

**To close (original wording).** Leave LethAL's generated objects out of the member count, or judge the check per target object. Add a
unit test with a selector row plus a shifted target row that warns, and red-check it. This will change which gates see
the warning, so pre-commit the pin moves first.
