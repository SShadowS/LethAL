**Filed 2026-10-22 by lane bugs during R-647** (diagnosis `/coord/handoff/R-647/diagnosis.md`, delta review
`/coord/handoff/R-647/review-r10-delta.md`). Related: [[R641]], [[R639]], [[R586]]; follow-up [[R649]].

**What (leg T).** In `legT` (`packages/runner/itest/al-runner-v3.itest.ts`), `assertCounts(r, "T", 290, 57, 59, 406)`
runs before `classifyLegT`. Every move r9 §7 holds changes a count, so the count check always fires first and r9 §7's
`held` is dead code. The edge rejudge of `57f1e4f98` at 711c94d9 gate-failed leg T on counts 290 / 50 / 59 (errors 7).
Run offline on R-635's E0-T reports (same binary), `classifyLegT` reads `held`. Exactly the 7 pinned #5603 rows
(M0157-M0159, M0161-M0164, covered only by `DoubleInsertWithoutKeyTriggerRaises`) go `survived -> error /
runner-refused` through PR #5623's refusal, and nothing else moves. The leg also prints no per-mutant row, so the 7 ids
had to come from another lane's report. The same order also hides a held move, because the `unsupportedTests` check
runs before the classification too.

**What (X (d)).** On the same rejudge all five X (d) mutants read `no-coverage`. The inferred cause: on edge a `Sleep`
counts toward the time limit (leg C reads `sleep-is-noop = gone`), so the `Sleep(600000)` in `SleeperDoubles` times out
at the 120 s baseline and covers nothing. This is toward BC, and `no-coverage` is safe for a user's score. But the Sleep
rule's only live control no longer runs, and the log does not print the baseline verdict that would prove the cause.
Re-casting X (d) for builds that carry #5605's fix is [[R649]].

**Who it hurts.** The update gate. A build that moves only known rows toward a named refusal is reported as an
unexplained count failure, and every rejudge needs a manual cross-reference to read it.

**To close.** Pre-commitment r10 (`docs/superpowers/specs/2026-10-22-r586-alrunner-v3-precommitment-r10-legt-order.md`,
7bc0a1a5). It covers the leg-T order, the row printing, the X (d) printing and the test list:
- Leg T computes its classification and `compareMutants` against its own baseline, prints every differing row (mutant
  code, key, verdicts, `errorClass`, killing test), and only then judges, in order: the Sleep index, then
  `unsupportedTests`, then the pinned 52.
- On `pass`, it requires 0 compare differences and the counts 290 / 57 / 59.
- On `held`, it requires the compare's key set to equal the held key set.
- X (d) stays a gate-fail on a timed-out baseline and prints SleeperDoubles's `baseline-batch-finished` verdict.
- Red tests for each direction.

Then run `--regate` on alpha.2 (unchanged) and `--edge-rejudge 57f1e4f98` (T `held`, overall `gate-fail` from C and X).
