**A false kill is now visible in the record but nothing classifies it.** R86 closed the READ: every
killed mutant carries `MutantOutcome.killingTestFailure`, the failing run's own text, so a reader who
looks can tell BC's *"The length of the string is 18, but it must be less than or equal to 10
characters"* apart from `Assert.AreEqual failed`. What LethAL still does not do is say which is which,
so nothing counts them, nothing warns, and R85's kill-rate split (a real kill rate versus a
platform-artifact one) has no input.

**The obvious rule is measured WRONG and must not be revived.** R86 first proposed that a top
callstack frame inside the TARGET app identifies a platform artifact. Classified over all 109
mutant-attributed failing rows in run 148: **4 rows matched, and only ONE was arm E.** The other
three (M0059, M0062, M0066) are ordinary kills where the target's own `TestField`/`Get` raised —
*"Category must have a value in Data Main"*, *"The Data Main does not exist"* — which R82's spec §4
insists must read as REAL kills, because production validation catching a bad state is exactly what a
test suite is entitled to credit. **75% false-positive rate on the only run the rule has ever been
checked against.** Shipping it as a `cause` would have been worse than the silence it replaced.

**The candidate that the data does support, and which is not yet measured:** the failing frame's
statement is not the MUTATED statement, AND the message is a platform-class error. Both halves need
their own measurement before either is written down as fact. The first half needs the mutated
statement's location compared against the top frame, which the record now has on both sides; the
second half needs a closed list of platform-raised message shapes, and that is where the trouble is.

**Two structural obstacles, both measured elsewhere:**

- **The message is PROSE and it localises.** R66 measured that class. An English-sentence detector is
  an English-only detector, and BC ships in dozens of languages. Anything keyed on message TEXT has
  that ceiling by construction; anything keyed on structure (which frame, which statement) does not.
- **The fixture cannot stand in for a real suite.** All 22 tests in `fixtures/sandbox-data-tests`
  raise via bare `Error(...)`. Continia Document Output's suite uses Microsoft's Library Assert
  ~1,886 times, which puts a THIRD app on top of the callstack — a shape no gate here has ever seen.
  A rule tuned on the fixture would be tuned on the wrong stack shape.

**`lethal explain` still projects no kills at all**, and deliberately so: it lists survivors and
`error` outcomes because "nothing keys a kill beyond the verdict word itself". A classifier would be
the first thing that does key one, so the explain surface belongs with the rule and not before it —
adding a kills section now would mean projecting free text the contract forbids consumers to parse.

Per R72's discipline a diagnosis must NOT move a verdict, whatever the rule turns out to be: a killed
mutant stays killed, this is a `cause`-shaped annotation, never a re-scoring. Changing that would
invalidate every frozen gate figure in `CLAUDE.md` and every committed baseline under
`docs/campaign/`.

Evidence: `docs/roadmap/R086.md` (the falsification, re-measured independently by an adversarial
review of the landed work); `docs/measurements/README.md` §"R82 live". Filed 2026-08-07 when R86
landed the record without the classifier.

**THREE WORKED EXAMPLES NOW EXIST, from shipped third-party code (2026-08-07).** The R85 instrument-(b)
run scored three swap mutants and all three were false kills — see
`docs/campaign/2026-08-07-r85-swap-rate/rung1.result.md` for the full text and callstacks. Each is
BC's field-length validation rejecting the mutated data:
`The length of the string is 87, but it must be less than or equal to 80 characters.`

Two things that matter for building the classifier:

- **All three have the TARGET app on top of the callstack** — `CDO Essential Module License` raising
  inside `RegisterModuleFeatures`. So they are three more counterexamples to the falsified
  top-frame-in-target rule, on top of the four already measured, and they fail it in the opposite
  direction from M0059/M0062/M0066: those were real kills the rule called artifacts, these are
  artifacts the rule would also call artifacts, for the wrong reason.
- **The candidate rule this row proposes looks right on them.** The failing frame's statement
  (`RegisterModuleFeatures line 42`) is not the mutated statement, and the message is a platform
  class (length overflow). Three instances is not a measurement, but it is three more than the rule
  had.

The suite's own assertion in all three cases is unrelated — the killing test is about feature-enabled
messaging and asserts nothing about names or descriptions — which is exactly the reader judgement the
classifier would have to automate.
