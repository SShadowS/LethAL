**Found 2026-10-21** by the Opus build review of [[R586]] (`/coord/handoff/R-586/review-build-opus.md`, Minor 10).

**What.** Before every `run()`, the v3 backend checks that what v3 will read is what alc proved: the `.al` bytes
of `active/` and of the test dir, both `app.json` files, the `<deps>` file list (sizes and times, sha256 when
they move) and the selector bytes. Three inputs are outside that binding:
- any non-`.al` file in `active/` or the test dir (resources, for example);
- `<testDir>/.alpackages`, if v3 reads it;
- a subfolder of `<deps>`: `listDeps` skips directories.

**Effect.** None measured: no gate fixture changes any of them between the proof and a run. A residual, stated
rather than closed.

**To close.** Hash the non-`.al` files of both folders into the proof, bind `<testDir>/.alpackages` when it
exists, and make `listDeps` refuse (or recurse into) a subfolder. A red-going unit test per input, like T22's
c1-c5.
