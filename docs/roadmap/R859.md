**What.** A manifest row in `packages/runner/src/al-runner-v3-gated-builds.json` binds to its hand pin by `readingsDigest`. A batch that adds mutants to a v3 fixture moves leg T's counts, so the digest moves, though no build read anything new, and `r814-gated-builds.test.ts` fails until a person deals with the rows.

**Why the script cannot.** `--regate` takes only `current`, and refuses a commit off master. `publishToMaster` adds each id once (`gated-builds.published`), so it will not replace a row. The failing test is on the branch, so the branch cannot merge first. That is a cycle.

**R-855 hit it** and took a hand route, on the orchestrator's approval: each row's own full gate at the branch's head, then an Edit of that row. See the addendum of `2026-11-07-r855-operator-batch-precommitment.md`. The next batch that moves a v3 fixture's counts hits it too.

**To close.** A script step, on a branch, that re-gates each listed row's kept binary at the branch's head, by the row's pin, and writes the digest and commit only on that row's pass; or split the digest, so a fixture's count does not move a build's readings. Check that the daily update's rows and this step do not collide.
