**Filed 2026-11-05 by lethal-preproc, from coord task R-825.** Related: [[R826]], GitHub #28.

**What.** `lethal.empty-block` claims a procedure's whole body. `findEnclosingStatement` returns that body as the root, and
`buildComponents` then folds every mutant inside it into one component. `emitDispatch` writes one branch per member, and each
branch repeats the root's whole text. So the emitted size grows about as guards x body size, which is quadratic.

**Measured offline, real generator, one synthetic flat procedure, no server (2026-11-05):**

| statements | guards | with `empty-block` | without it |
|---|---|---|---|
| 40 | 141 / 140 | 1 component, chain 141, 288 KB | 60 components, chain 3, 28 KB |
| 150 | 526 / 525 | 1 component, chain 526, 3.8 MB | 225 components, chain 3, 106 KB |
| 300 | 1051 / 1050 | 1 component, chain 1051, 15.3 MB | 450 components, chain 3, 211 KB |

One extra mutant, 72 x the code at 300 statements. Spread over small procedures the effect is far smaller: 1200 guards in 60
procedures is 516 KB, and each chain is 20.

**Why it matters.**
- It is the lead suspect for #28's crash ([[R826]]). Every run that passed there was one operator other than `empty-block`,
  and the crash run had all 19. That is an inference, not a measurement.
- Even with no crash, it inflates every publish and compile for procedures with many mutants.

**A possible fix, not designed or measured.** An emptied block does not need the block's text: the branch could be a guard with
an empty body beside the original, so the other mutants need not sit inside it. Whether that keeps the verdict and the
coverage rules is not known. It changes emitted AL for nearly every project, so it needs a plan, a pre-commitment and every
gate. Measure [[R826]] first.
