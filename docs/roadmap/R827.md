**Filed 2026-11-05 by lethal-preproc, from coord task R-825.** Related: [[R826]], GitHub #28.

**What.** `lethal.empty-block` claims a procedure's whole body. `findEnclosingStatement` returns that body as the root, and
`buildComponents` then folds every mutant inside it into one component. `emitDispatch` writes one branch per member, and each
branch repeats the root's whole text. So the emitted size grows about as guards x body size, which is quadratic.

**Measured offline, real generator, one synthetic flat procedure, no server (2026-11-05):**

| statements | guards | with `empty-block` | without it |
|---|---|---|---|
| 40 | 141 / 140 | 1 component, chain 141, 288 KB | 60 components, chain 3, 28 KB |
| 150 | 526 / 525 | 1 component, chain 526, 3.8 MB | 225 components, chain 3, 106 KB |
| 300 | 1051 / 1050 | 1 component, chain 1051, 15.3 MB | 450 components, chain 3, 211 KB |

One extra mutant, 72 x the code at 300 statements. That is a worst case built for it. Spread over small procedures the effect is
far smaller: 1200 guards in 60 procedures is 516 KB, and each chain is 20.

**Measured on real code (offline, 22 of DO's codeunits of 1,000 to 1,700 lines, all operators, 2026-11-05).** The real effect is
**1.8 to 7.6 x, usually 3 to 6 x.**
- With `empty-block`: 309 to 813 guards, 237 KB to 2.4 MB emitted, longest chain 14 to 127.
- Without it: 88 KB to 842 KB, longest chain 2 to 56. So `empty-block` is the largest source of folding, not the only one.
- Script: `/coord/handoff/R-825/real-sizes.ts`. It prints sizes only, no source.
- So #28's 907 guards in 1,342 lines is an ordinary size for a real codeunit, not an extreme one.

**Why it matters.**
- It is the lead suspect for #28's crash ([[R826]]). Every run that passed there was one operator other than `empty-block`,
  and the crash run had all 19. That is an inference, not a measurement.
- Even with no crash, it inflates every publish and compile for procedures with many mutants.

## Landed (R-836, 2026-11-06)

**What changed.** A procedure or trigger body's `empty-block`, when the body holds no directive and no other member resolves to it, is now one guard around the body instead of a chain that repeats it:
`begin if Sel.Active('E') then begin <marker> end else begin BODY end end`. Two insertions, no newline. Inside such a body a mutant in a loop is rooted at the outermost loop, so no guard runs per pass.
The rule is one definition, in `buildComponents`. Spec: `docs/superpowers/specs/2026-11-05-r827-empty-block-guard-precommitment.md`, Addenda 2 to 7.

**What it does for size.** A typical real file shrinks about 3-fold: on 10 DO codeunits, 10,863 KB became 3,303 KB, where leaving `empty-block` out gives 2,721 KB. **The worst files hardly change:** `CDOEMailTemplateImportExport`
goes from 46.1 MB to 44.3 MB, and the longest chain across DC and DO is 461, from 496. So #28 is not fixed by this. [[R826]] stayed open then; [[R828]] has since closed at a named limit, and #28 is still not fixed.

**What did not move.** No verdict, count, id, ordinal or killing test on any gate. Only `Grow`'s `#pragma` line moves a baseline row: 5 rows re-key, recorded by R332 and R849's route. That line keeps `Grow`
a chain, as long as `itest:bcdev-wrapped` and the v3 layout leg need, and puts the directive rule on a live gate. On real code one thing can move: a statement under `asserterror` or `with` becomes its own root, so its reach
goes from `unplaced` to `statement`.

**The proof.** `r827-residual.test.ts` folds every mutant of every fixture project (776, the sum of its `MUTANTS` table) and compares each with the mutant written by hand, and checks that no guard sits inside a loop under a free
guard. DC and DO: 164,520 mutants, 0 throws, 0 overlaps, 0 grain moves (`/coord/handoff/R-836/review-figures.txt`). `itest:hang` took about 15 minutes, as before (`docs/gates/hang.md`, logs under `/coord/handoff/R-658/`).

## The fix as planned and reviewed (R-825, 2026-11-05; superseded by the above)

**Ruling (orchestrator).** The emitter change waits for evidence: it is a large change on the hottest path, for a cause that is not
proven. It is picked up when #28's reporter answers, or a crash is measured. No crash runs meanwhile. What landed instead: the
residualising test, and a warn-only check in `--dry-run` and the run banner.

**The candidate.** For a free `empty-block`, two insertions, so the block's text appears once:
`begin if Sel.Active('E') then begin <marker> end else begin BODY end end`. Nested mutants keep their own components. Pre-commitment:
`docs/superpowers/specs/2026-11-05-r827-empty-block-guard-precommitment.md`. Impact: `/coord/handoff/R-825/r827-impact.md`. Offline
proof of the shape: `/coord/handoff/R-825/prove/`: alc accepts it, 12 behaviour tests pass under al-runner, and a planted wrong
binding compiles and fails 2 of them.

**The plan review found it not safe as specified. A pick-up must do all of this; the pre-commitment needs an addendum first.**
1. **A verdict risk.** Today a body-level E folds a loop's statements into a chain tested once at entry. The fix would run guards on
   every pass, active mutant included, and [[R246]] measured such calls turning a kill into a race with the budget. A slow survivor
   could score `timeout-killed`, so "time may move" in the pre-commitment understates it. An offline measure is not BC. Proposed: inside
   a free E, root a loop's mutants at the outermost loop statement, so guards stay at loop entry. Its size cost is not measured.
2. **"Free" must be one rule.** Decide widest-first, equal spans included, using the block for a free container. As first written,
   three documents meant three things, and two cases would refuse a whole file (`rewrite.overlap`): a chain-rooted E with a directive,
   and a mutant that resolves to the block itself. A case-arm E resolves to `case_statement`, and must stay marker-less.
3. **A block with a preprocessor directive stays a chain.** Its closing `end` can lie inside a `#if` arm, where one insertion reaches
   only one build. That form compiles in both builds as written.
4. **A gate would go silently blind.** `Grow`'s instrumented span must cover `Twice`'s original lines (R300b), and the fix shrinks it:
   modelled, `Twice` moves from line 46 to 31. `itest:bcdev-wrapped` would stay green and test nothing. It needs a new pre-commitment,
   a re-padded fixture and its red check redone. `LayoutBeta`'s comment and the page's 71/73/79 go stale too.
5. **Gates do not reach these shapes.** No `if`-branch E is gated, so a fixture arm is needed.
6. **The pre-commitment's list misses:** callstack line numbers in `killingTestFailure`, `planFile`'s and `design.md`'s "never nested
   guards", and R318's `shared` rule, which could turn an E-only member's verdict into `no-coverage`.
7. **The size is larger than first quoted:** about 150 to 250 lines, plus a fixture re-pad and a re-publish on every server.

**What survived review:** the shape, reach grains (0 moves on 8 fixtures, modelled), a block straddling `#if` arms always holding a
directive, `Active` being stable, tie order failing loudly, and refusals reading specs, not text.
