**The difference.**
- LethAL's bcdev backend runs tests with `GuiAllowed() = false` (ODataV4).
- al-runner v3 defaults to `true`; `alRunnerV3.noClient: true` (al-runner `--no-client`) makes it false (R895/R907).
- DO's code and its Continia dependencies have 111 GuiAllowed / CurrentClientType sites (53 in DO, 58 in the Continia apps). A
  Message or Confirm behind `if GuiAllowed` feeds a test's handler only in a client session.

**The ruling: DO's CI runs WITH a client (CONFIRMED, 2026-11-21).**
- **Evidence:** kraken read DO's Azure DevOps CI for the owner: pipeline "Document Output - Current", build 828949 (master,
  2026-11-21 13:09Z), test run 1344043: **2,154 of 2,154 tests passed**. That includes the decisive test in codeunit 68992,
  which passes only when GuiAllowed is true (bc4, headless, fails it with "UI handlers were not executed").
- An earlier answer ("headless", q-20261121T194603-e01cc807) was withdrawn as not sure before this check, and is replaced by it.
- **Consequences:**
  - al-runner's DEFAULT (client) session matches DO's CI, so DO's v3 verdicts (y3, c1, c2) describe the same branch CI does.
  - `--no-client` is not needed for DO, so upstream #8273 does not block DO.
  - **LethAL's bcdev harness (headless) is the one that differs from DO's CI.** On DO's session-dependent tests, a bcdev verdict
    is NOT CI's oracle, and a bcdev / al-runner disagreement there is not an al-runner bug.

**The prediction** (parsed, pre-committed): of DO's 1,979 baseline tests, 163 change with the session kind, 334 unknown,
1,482 unchanged. The 163 split as:
- 114 refused under --no-client (TestPage use, or page handlers): irrelevant now that DO does not need --no-client;
- 29 unhandled Confirms;
- 20 handlers fed only by GUI-guarded calls.

**Measured:**
- **al-runner with --no-client on `current` (ccd0f823d): EVERY test refused** (upstream #8273; LethAL stopped by R1001).
  Moot for DO after the ruling.
- **al-runner with a client vs bcdev headless** (PR-287's baselines on bc4, 422 tests):
  - 160 differ;
  - **60 are session-kind differences, all 60 predicted.** Here al-runner's answer is CI's:
    - 39 pass on v3 / fail on BC (mostly "UI handlers were not executed");
    - 16 pass / skip;
    - 5 fail / pass (an unhandled Confirm that headless BC answers by default; in CI's client session it is raised).
  - 100 are v3 refusals (89 pass on BC, 11 fail): those are real al-runner limits, measured elsewhere (R1163).
  - 0 tests predicted "unchanged" differ.
- **The client baseline on `current`:** 1,734 of 1,979 green, 238 refused.

**Which tests' bcdev verdicts are off-CI** (PR-299's narrowing to the CI question): 134 tests:
- 20 handlers fed only by GUI-guarded calls (bcdev fails them; CI passes them);
- 29 unhandled Confirms (bcdev passes them; CI's client session raises the Confirm);
- about 85 GUI-branch state or skipped-GUI-call tests (direction not measured).
In c2 terms: 7,693 mutants have such a covering test, 1,735 have only such tests, and 1,027 c2 kills rest on one.

**What is left:**
- When a bcdev run of DO (or any app with GuiAllowed branches) is used as an oracle, label the verdicts of mutants whose deciding
  test is session-dependent as "headless: not CI's session", rather than treating a disagreement as an al-runner defect.
- A product question for LethAL in general: bcdev's ODataV4 session is headless by construction. An app whose CI runs with a
  client is measured on the other branch there. A session-kind note in bcdev reports, or a client-session harness, is a
  separate item if wanted.
- The earlier proposal (leave tests out of DO's v3 runs, label v3 verdicts) is WITHDRAWN: it assumed headless CI.
