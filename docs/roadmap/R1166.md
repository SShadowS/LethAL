Found by coord PR-299 (lethal-bugs, 2026-11-21), from PR-287's M8062. Evidence: `/coord/handoff/PR-299/`
(`prediction.tsv`, `bc-crosscheck.tsv`, `triage-client/`, `triage-noclient/`). Pre-commitment: master d7f4b087a.

**The difference.**
- LethAL's bcdev backend runs tests with `GuiAllowed() = false` (ODataV4).
- al-runner v3 defaults to `true`; `alRunnerV3.noClient: true` (al-runner `--no-client`) makes it false (R895/R907).
- DO's code and its Continia dependencies have 111 GuiAllowed / CurrentClientType sites (53 in DO, 58 in the Continia apps). A
  Message or Confirm behind `if GuiAllowed` feeds a test's handler only in a client session.

**The prediction** (parsed, pre-committed): of DO's 1,979 baseline tests, 163 change with the session kind, 334 unknown,
1,482 unchanged. The 163 split as:
- 114 refused under --no-client (TestPage use, or page handlers);
- 29 unhandled Confirms;
- 20 handlers fed only by GUI-guarded calls.

**Measured:**
- **al-runner with --no-client on `current` (ccd0f823d): EVERY test refused.** The first 10 codeunits came back uniformly refused,
  and LethAL stopped by R1001. The text: `the login: which login events BC raises in a session without a client (--no-client) is
  not pinned, and this test codeunit can see what the login leaves`. That is upstream #8273 (OPEN): DO's login subscriber leaves
  state the tests can see. So the per-test prediction cannot be checked on al-runner today, and `noClient: true` is not usable
  for DO.
- **al-runner with a client (the default) vs BC** (bcdev on bc4, GuiAllowed false; PR-287's baselines, 422 tests):
  - 160 differ;
  - **60 are session-kind differences, and all 60 were predicted** (39 pass on v3 / fail on BC, mostly "UI handlers were not
    executed"; 16 pass / skip; 5 fail / pass, an unhandled Confirm that BC answers by default);
  - 100 are v3 refusals (89 pass on BC, 11 fail).
  - 0 tests predicted "unchanged" differ.
- **The client baseline on `current`:** 1,734 of 1,979 green, 238 refused.

**What it means:**
- DO's v3 verdicts (y3, c1, c2) describe the GUI branch, and bcdev's the non-GUI one. For the tests above, they measure different
  code.
- A mutant behind `if GuiAllowed` is reached by v3 and not by bcdev, and the other way round for `if not GuiAllowed`.

**Owner question:** which session kind does DO's real CI run its tests in? If a web-service or no-client session, then v3's
GUI-branch verdicts are off-target for those tests until #8273 lets `--no-client` run. If a client session, then bcdev is the
one off-target.

**The ruling (owner, 2026-11-21, q-20261121T194603-e01cc807):** DO's real CI runs its tests headless (GuiAllowed false).
- So LethAL's bcdev harness matches CI, and al-runner's default client mode is the one that differs.
- al-runner's `--no-client` would match CI, but it refuses every DO test until upstream #8273 is fixed.

**Which tests differ from headless CI in al-runner's client mode** (PR-299's parsed prediction, narrowed to the CI question):
- **Not the TestPage / page-handler tests** (114 of the 163 "change" tests). Those change only because al-runner refuses them
  under `--no-client`; on headless BC they run normally.
- 134 tests whose client-mode outcome can differ from CI, in three directions:
  1. **Pass on v3, fail on CI:** a handler fed only by GUI-guarded calls (reason a), 20 tests. Measured on BC: all 20 fail there.
  2. **Fail on v3, pass on CI:** an unhandled Confirm that headless BC answers by default, 29 tests (5 measured passing on BC).
  3. **GUI-branch state or a skipped GUI call, direction not measured** (reasons b and e), about 85 tests.
- **c2's mutants (current, 43,511):**
  - 7,693 have at least one such covering test;
  - **1,735 have ONLY such covering tests** (1,223 survived, 487 killed, 24 error, 1 timeout-killed);
  - **1,027 c2 kills rest on such a killing test**, of which 108 are by reason-a tests and 146 by unhandled-Confirm tests.

**Proposal (lethal-bugs) until #8273 lands, for the orchestrator's ruling:**
- **(1) Leave the reason-a tests OUT of DO's v3 runs** (`--tests-exclude`, or a pinned exclusion list in DO's config).
  - Headless CI counts them as failing, so CI would never use them to kill a mutant.
  - Keeping them makes 108 c2 kills that CI cannot make.
  - Leaving them out matches CI exactly, at the cost of the coverage CI does not have either.
- **(2) The unhandled-Confirm tests:** no change. v3 already leaves them out at baseline (they fail there); CI runs them.
  - The report should say so: a known coverage loss on v3, not a verdict difference.
- **(3) The GUI-branch tests (direction unknown): keep them, with a known-difference LABEL in DO's report.**
  - Mark a mutant whose killing test is one of them as "killed in the client session (GUI branch)" (1,027 minus (1)'s 108).
  - Mark a mutant whose every covering test is one of them as "measured on the GUI branch only" (1,735 at most).
  - The label keeps every fact (no deletion) and lets a reader separate them. A bcdev spot-check of a sample would size how
    many really differ.
- **Rejected:** dropping all 134 tests (loses 7,693 mutants' coverage for differences mostly not measured), and switching DO
  to `--no-client` (every test refused today).
