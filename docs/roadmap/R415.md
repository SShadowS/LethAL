**Found reading the Windows CI job of `lethal/kraken-move` (kraken-move Task 6, 2026-10-03).** On a
GitHub Windows runner `bun test` starts from PowerShell, so `tar` is Windows' own bsdtar, which ends
each listed name with `\r\n`. The test splits on `\n`, so every entry keeps a trailing `\r` and no
expected name matches. The product (`tarProblems` in `scripts/kraken-secrets.ts`) already splits on
`\r?\n`; only the test did not. It passes from Git Bash, where `tar` is GNU tar.

Failing test (run 37129055253, job `check`): `CLI > all inputs valid: every from-name is written, and
the tar holds relative .alpackages entries` (`scripts/kraken-secrets.test.ts`). Evidence line:

```
[ "fixtures/alpha/.alpackages/\r", "fixtures/alpha/.alpackages/sym.app\r", ...
```

**To close.** Split the listing on `\r?\n`, as the product does.
