**Filed by coord task R-654f (2026-10-24), from its opus build review.** [[R654]] F2 refuses a lethal.config file
with a top-level `alRunner` key (the retired .NET al-runner's section) in `loadLethalConfigFile`. Every user command
that loads a config goes through it. Two developer-side readers do not:

1. **The live itests** read their fixture config with their own `readJson<LethalConfigFile>` plus
   `validateBcDevConfig`: bcdev, names, wrapped, hang, harden, chunked, tables, lend, lease, verify, stale-publish,
   test-app-publish and envtool. `itest/config-path.ts` reads only the `bcdev` fields. A fixture config with an
   `alRunner` section is therefore accepted by the gates, silently. Today `bc-linux-setup.ts` writes those configs
   without the section, so no gate is affected.
2. **`scripts/kraken-secrets.ts`** copies an `alRunner` section from a host template into a container config
   unchanged. F2 removed its path mapping, so a host path inside the section now stops the run as a "leftover host
   path", but `alRunner: {}` (or a section with no host path) is copied silently. The loader refuses it at the next
   `lethal` command, so nothing uses it. But the provisioning step itself does not say "retired section".

**To close.** Call `refuseRetiredV2ConfigSection` (`packages/runner/src/v2-retired.ts`) in both places:
- the itests' shared config read (one helper, if they share one; otherwise in `config-path.ts`'s reader);
- kraken-secrets' read loop.

For each, write a test that goes red when the call is removed.
