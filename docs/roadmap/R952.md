Coord task R-934 (owner, 2026-11-12: "do them all now"), from the lanes' time breakdown: slot waits cost 1-2 h per task. Related:
[[R905]], [[R930]], [[R948]].

**1. A FIFO queue.** `scripts/heavy-slot.sh --wait <class> <cmd>` takes a numbered ticket in `<lock dir>/heavy-queue/` and waits in
order: only the oldest live ticket tries for a slot, every `LETHAL_HEAVY_POLL_S` seconds (default 5). A ticket whose pid is gone is
dropped, so a dead waiter never blocks the queue, and a caller without `--wait` exits 75 while a live waiter queues. The class caps are
the guard's, unchanged. Both guards trust a `--wait` holder and count a waiter that holds no slot as no job: without that, a waiter for
a BC.History job read as a foreign BaseApp job.

**2. The slot class, measured (passive: every held slot's process tree, every 30 s, 6 h on 2026-11-12;
`/coord/handoff/R-934/rss.peaks.json`).**
- How the class is set: a job under `heavy-slot.sh` has the class its caller passes. The `/work/src/BC.History` path rule decides only
  for processes outside `heavy-slot.sh`. So module runs over copies under `/coord/handoff` (R-932, R-933) were always `other`; the
  claim that every BC.History job counts as BaseApp-class held only for unslotted processes.
- A System Application module pool build (the hunt driver: one alc compile at a time) peaked at 0.37-0.55 GB; one alc compile of a
  large app at 0.33-0.44 GB as a single process. So it is `other`; R-933's pool build was restarted as `other` on this measurement.
- v3 runs of BC.History apps under the `baseapp` class (R-938): 3.8-5.3 GB. The v3 gate: about 2.0 GB.
- v3 serve runs under `other`: Subcontracting up to 15.7 GB, Sustainability up to 12.4 GB, the serve daemon being most of it
  (R948). So the class no longer tracks memory: the largest jobs are long serve runs classed `other`.
- The caps are unchanged, as ruled. The container now has 98 GB, against the 24 GB the BaseApp cap was set for.

**3. A repro scaffolder.** `scripts/repro-scaffold.ts new <dir> [--target f.al] [--test f.al]` writes the sandbox target plus the
given AL, a test app with the fixture symbols, configs for the default transport and one-shot, and a `run.sh` that runs both through
`heavy-slot.sh --wait` and compares per mutant (`compare <dir>`).
