**Noted by lethal-bugs while fixing GH-24's latch naming (2026-09-26); pre-existing, UNVERIFIED.**
`injectMutationSelectorVar` (`packages/schemata/src/compile.ts`) decides which object already received
the selector variable by comparing tree NODES by identity. In the implementer's scratch script, specs
found by two SEPARATE walks over the same object (one with a global `var` section) produced two
overlapping edits for that one object.

The real pipeline may never reach this: it walks each file once, so the specs share node objects. That
is why it is filed and not fixed. R209 set the rule that positions, not node identity, decide sameness;
this call site may not follow it.

**To decide it:** write the smallest test that feeds `compileSchemataForFile` specs from two walks of
one object with a global `var` section, and check whether the output has one selector variable or two.
If two, key the check on the object's start/end position (R209) and red-check.
