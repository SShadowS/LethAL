**Filed 2026-10-22 by lethal-bugs during R-599** (the delta build review's M1, `/coord/handoff/R-599/review-build-delta.md`).
First written as R626 on `lethal/r599`; renumbered at the merge of master, where R626 had been taken concurrently.

**What.** To normalise them, `normalisedEntries` in `scripts/bc-app-content.ts` decodes the two entries it rewrites,
`NavxManifest.xml` (the build timestamp) and `navigation.xml` (`normaliseNavigation`), with `toString("utf8")`, and
encodes the result again with `Buffer.from(..., "utf8")`. The decode replaces every invalid UTF-8 sequence with
U+FFFD, so it is not one-to-one: two different byte strings can come out as the same bytes, and `contentDigest`
then calls two different packages the same content.

**Repro (the reviewer's, offline).** Two `navigation.xml` entries that differ only in one byte, 0x80 against 0x81
(each an invalid lone continuation byte), give the same `contentDigest`. The same holds for the manifest.

**Who hits it.** Nobody today: alc writes these entries as UTF-8 with a BOM (`efbbbf` in all six committed real
builds under `scripts/testdata/`), and the BOM and every valid sequence survive the round trip. It needs a resident
package whose XML is not valid UTF-8 (edited by hand, or written by some later tool).

**To close.** Decode and encode both entries as `"latin1"` instead: that mapping is one byte to one character and
back, so it is lossless. `TIMESTAMP`, `CONTROL_GUID` and the two element patterns in `bc-app-content.ts` are pure
ASCII, so they match the same way. Add the 0x80 / 0x81 pair as a test that the digests differ, red-checked by
putting `"utf8"` back. R599 left it alone on purpose: changing the digest code after R-599's live proof on d89d6eb4
would need that proof again, for a case today's alc cannot produce.

**Fixed.** Not latin1 (it would change every digest by turning the BOM and non-ASCII text into other bytes).
`normalisedEntries` now decodes both entries with `new TextDecoder("utf-8", { fatal: true, ignoreBOM: true })`
and throws `ContentUnknownError("<entry> is not valid UTF-8")`. `ignoreBOM` keeps the BOM in the text, so every
valid file re-encodes to the same bytes and every digest is unchanged (pinned for all 12 builds under
`scripts/testdata/`). A refused resident package gives `refuse content-unknown` in `decideApp`; a refused local
package throws. Tests in `scripts/bc-app-content.test.ts` ("R627"), red-checked.
