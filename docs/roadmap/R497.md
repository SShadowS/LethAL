[[R383]]'s (R383's multi-object rule is al-runner only): `refusedObjectsOfFile` refuses every object of a file that holds

every wrapped file is refused on bcdev in every set. A top-level split declaration followed by an object occurs nowhere.

(BaseApp 301 files, 6,914 master mutants; DC 24 files, 320). Script and outputs: `/coord/handoff/R-497/`.

**Fixed (R-497, 2026-10-08; plan r2 `/coord/handoff/R-497/plan.md`, opus plan review applied).**
- One arm-aware predicate, `bcWrappedShapeRefusal`, read by the fenced line map, the hub's refusal set and
  selection: one top-level object wrapper, no `#elif`, no nested wrapper, one object per arm (one or two arms, one
  key), exactly one arm compiled, at most one bare object before and one after. The probe measured W1, E1, Q, P and R

  bare object BEFORE a two-arm wrapper whose `#else` is compiled, and a second top-level `#if` holding no object), and
  no corpus file has either today. Wrapped tables and pages are admitted on the codeunit measurement ([[R536]]). Every
  other shape is refused by a sentence naming it (`refusedBcShapeReason`).
- H1a, with the build's arms: an object's base is one past the last line of the previous COMPILED object; inactive-arm
  declarations get no entry and no refusal key. Pinned offline against BC's own numbers for the R-300b probe
  (`r497-bc-wrapped.test.ts`: W1 10/14/18, E1 18/22/27, Q 8/12/16, R 18/22/26), and through the real instrumented
  path. Without symbols (`lethal verify`, which hands none over) every path refuses as before.
