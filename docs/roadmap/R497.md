`/coord/handoff/R-300b/precommitment.md` (committed ee2fe651). The results and raw outputs are in the
coord handoff for R-300b: `bc-results.md`, `bc-raw/`, `bc-classify.txt`. Follows [[R300]].

**What was measured.** Two rounds, identical. Controls correct; no hit lands in a `Miss` procedure.
- **Fenced (BC Code Coverage, object-relative line numbers): consistent, H1a.**
  - Lines hit: W1 (one arm, namespace inside) 10/14/18; E1 (two arms, `#else` compiled, inner `#if`) 18/22/27;
    Q (wrapped in the middle, inactive `#else`) 8/12/16; R (bare object after a wrapper) 18/22/26.
  - BC's own text for each hit line matches the source file under H1a.
- **Hub (procedure coverage): consistent, HUB-A.** For every test the coverage names exactly the compiled arm's reached
  procedure (`Hit`, `AElseHit`, `QIfHit`), never an inactive-arm name and nothing else.
- **bcdev `line` coverage:** gives no line rows (procedure-level payload only), so it is not a coverage source.

**The defect.** Today's line-map rule (H1b) is WRONG for a bare object that follows a wrapper in the same file. H1b
predicts 7/11/15 for R; BC reports 18/22/26, an 11-line shift. BC gives the wrapper's directive and inactive-arm lines to
the object that FOLLOWS it.
