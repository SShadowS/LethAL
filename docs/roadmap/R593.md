**Filed 2026-10-21 by coord task R-588** (lethal-code), from the owner's speed request of the same day.

Two waits set the pace of most items, and neither has a tool:

- **Master corpus dumps.** BaseApp generation takes 30 to 35 minutes per leg, and items re-dump
  master again and again. `/coord/cache/dumps/` held one entry on 2026-10-21. Each hang item builds
  its own added/removed/tuples/ordinals/tags report by hand from throwaway scripts (the R-572 tools
  `prod-identity-keys.ts` and `prod-keydiff.ts`, branch `lethal/r572`, never merged).
- **`bun scripts/verify.ts`** runs the whole unit suite (about 8,400 tests) on every check, even
  when a change touches one package that nothing depends on.

**To close:**

1. A committed corpus snapshot tool in `scripts/`: `snapshot <set> --master` writes
   `/coord/cache/dumps/<master sha>/<set>/` with a `DONE` file, refuses to overwrite a `DONE`
   entry, reuses an older cached sha when no commit since then touched generation code (and prints
   why), and refuses to start a third heavy job. `diff <set> --branch <worktree>` re-dumps only the
   named or affected projects and prints the report against the cached master. Unit-tested on fixtures.
2. `verify.ts --changed` / `--packages <list>`: run only the touched packages and their dependents.
   The receipt names the mode, and a partial run can never be read as a full one. The full verify
   stays mandatory for submit and merge.
3. Optional: keep al-runner's compile cache warm between runs, only if measured cheap.

Evidence: the measurement and plan at `/coord/handoff/R-588/measure.md` and
`/coord/reviews/R-588-plan/plan.r1.md`.
