**Found by** the Opus build review of PR-387 (lethal-code, 2026-11-23), NIT 6. Evidence: `/coord/handoff/PR-387/result.md`.

- **What breaks:** PR-387 marks a bcdev baseline row whose test body never ran (`TestVerdict.bodyNeverRan` on the hub's
  tool-error and no-result rows) and counts it in `notRunAtBaseline`. An R192 snapshot stores the baseline rows as JSON and
  is recorded whenever every test reached a verdict, a hub `error` row included. A snapshot written before PR-387 has no
  flag on such a row, so a `--resume` that reuses it under-counts the not-run caveat. No verdict moves.
- **The fix (PR-392, spec `docs/superpowers/specs/2026-11-23-pr392-snapshot-payload-format.md`):** a
  `baseline_snapshots.payload_format` column (`SNAPSHOT_PAYLOAD_FORMAT` = 2), written on every new snapshot and required by
  `findBaselineSnapshot`; NULL on older rows, which are never reused, so their batch re-runs its baseline once.
- **Related:** R192, R1197 (PR-381), PR-387.
