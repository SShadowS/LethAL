**Nothing detects a stale published test app, and it has now cost two debugging sessions.** The gate publishes the instrumented *target* on every run but never the test app — by design, since "publishing the test app is the user's own workflow". The failure mode is badly disguised: the runner discovers tests from source, the server has an older set, the baseline goes red, and dozens of mutants fall to `no-coverage`, which reads as a mutation-scoring problem rather than "your published test app is older than your source". Hit twice on 2026-07-26/27. The harness knows both the discovered test list and what the server actually ran; comparing them and saying so is cheap.
