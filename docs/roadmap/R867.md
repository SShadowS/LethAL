A lane ran `lethal doctor` from a config dated 26 October and reached an unleased old host. Gates cannot do this: `printItestTarget` calls `bcHostMismatch` (R783) and throws before any lease or server call. `doctor` never calls it, and neither does anything else outside the itests. Related: [[R783]], [[R669]].

**Stale configs found 2026-11-07, by file date only, none read.** 16 task worktrees and `lane-code` held `lethal.config.bc*.json` older than 2026-11-05. `r783` was lane preproc's and is removed. The other 15 are lane bugs' and all merged; 6 are clean, 9 are not. `lane-preproc` is refreshed.

## Plan

**1. `doctor` refuses first (about 10 lines, the real fix).** In `cli.ts`, on the doctor path, before the deps are built and `runDoctor` is called: `DoctorConfig` has no server field, so it cannot be done inside `runDoctor`. Take the hostname from the config's `bcdev.server`, call `bcHostMismatch(hostname)`, and throw `BcHostMismatchError` on an answer. It reads one field and no password, from a config `cli.ts` already parsed. Print the fix, naming `--write-config-only`.

Move the throw into one helper, `refuseStaleBcHost(server, env)` in `bc-host.ts`, so `printItestTarget` and `doctor` cannot drift. `lethal run` can call it too, at the same place: that closes the same hole for a lane's by-hand run. It stays narrow on purpose: `bcHostMismatch` answers only for a KNOWN Linux host that is not in use, so a customer's server, Cronus28 or an envtool environment is never refused.

**What it will not catch.** A host in no list: an address nobody recorded. "Refuse anything not in the current servers list" is not an option, because `lethal doctor` is a product command that real users point at their own servers. A list of hosts LethAL's lanes have used is what `BC_HOSTS` is. So a retired host must be added to it when it retires, and not removed. Check which host the 26 October config named before building: if it is not in `BC_HOSTS`, add it. That needs a read of one field by the owner or a script that prints only the hostname.

**2. A lane refreshes its configs at start (one command, no code).** `bun scripts/bc-linux-setup.ts --server all --write-config-only` makes no server call and prints no secret. It belongs in the lane start procedure, which lives in `.kraken` and the kraken skills: a lane may not edit those, so the owner or the orchestrator adds that line. Not a repo change.

**3. Not planned.** A date check on configs: a fresh file can name the wrong host, and an old one can be right. Sweeping every worktree at start: a merged worktree is removed instead.

## What was built

This differs from the plan in three ways. The helper is `refuseRetiredBcHost` in `bc-host.ts`, called from `loadLethalConfigFile` in `cli.ts`, so every command that reads a config is covered, not only `doctor` and `run`. `printItestTarget` calls it too.

It fires only in our own environment, where `LETHAL_COORD_ROOT` is set. A private address such as docker1's, or a name such as Cronus28, can be a user's own server, so without that variable the helper does nothing. Besides `BC_HOSTS`' other host, it refuses Cronus28 (parked) and Cronus284 (CentralGauge's) by name. `printItestTarget`'s own `bcHostMismatch` check still fires everywhere. The test preload clears `LETHAL_COORD_ROOT`, so a unit test sees what CI sees.

The start steps are in `docs/superpowers/runbooks/autonomy/lane.md`, so the refresh line went there, as a repo change.

**Tests.** A stale host refuses before any server call, proved by a counting `fetchFn` (`cli.ts` takes one as a dep). The host in use and a customer host pass. `LETHAL_BC_HOST` set to the other host flips the answer. Red-check each direction.
