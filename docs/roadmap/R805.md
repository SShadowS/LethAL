**Filed 2026-10-26 by lethal-spare** (orchestrator request). Related: [[R804]], [[R633]], [[R639]].

**The gap.** In `scripts/al-runner-v3-update.ts`, `gateOne`'s `keep()` copies the receipt and the gate's own output
(`gate.log`) only for these outcomes:
- `--regate` (`regate/<commit>.`);
- `--edge-rejudge` (`rejudge/<name>@<commit>/`);
- infra-fail (`infra/`), gate-fail (`failed/<name>@<commit>/`) and held (`held/<name>/`).

On a PASS of a release-path or `--edge` candidate, it copies only the binary into the new build folder and writes
`.gated`. The work folder that holds `gate.log` is then removed.

**What it cost.** On 2026-10-26 the v3.0.0-alpha.6 release passed at 68568a19 and became current. lethal-bugs could
not audit that run against R804 addendum 2:
- O1's commit kind, N1E 36/0/0, T 318/70/18, and D1/D1c with 0 differences were all out of reach.
- Only the summary line in the update log survived.
- The K run on the new current (`/coord/handoff/lethal-spare-edge/a6/k-run.log`) stood in, because it is the same
  binary, the same commit and all 18 legs.

**The fix.**
- On a pass, `keep(dest)` copies `receipt.json` and `gate.log` into the new build folder, beside `.gated`
  (`/work/tools/al-runner-v3/<version>-<commit>/`).
- That folder is created at that point anyway. Nothing old is moved or rewritten, as R639 §6 requires.
- A failed copy is logged and never blocks `.gated` or `current` (R633 M2), as for the other outcomes.
- Test: a fake passing candidate leaves both files beside `.gated`. Red: drop the `keep(dest)` call.
- No gate figure moves, and no regate is needed (R777): the leg set and the verdicts are unchanged.
