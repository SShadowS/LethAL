Found by lethal-code, 2026-11-12 (coord R-936 follow-up, on the orchestrator's warning). Related: [[R936]].

**What happened.** R-936 cached the LLVM 23.1.2 install in CI, keyed by version, OS, architecture and the install script's hash. GitHub
scopes caches by branch: a branch reads its own and master's, but saves its own. After R-936 merged, `gh cache list` holds four LLVM
entries: Linux 2.77 GB and Windows 1.08 GB for `master`, and the same pair for `lethal/r936`, 7.52 GB in all, beside 1.16 GB of the
`native-*` (addon build) caches: 8.68 GB of the 10 GB repo limit. A third branch that runs CI would push the total over, and GitHub then
evicts the least recently used entries, which can be the native caches or master's own LLVM.

**Invented repro.** Push two task branches that each run CI once: each saves a fresh LLVM pair (3.85 GB), and `gh cache list` then
exceeds 10 GB, with older entries gone.

**Wanted.** Restore the LLVM cache on every branch, but save it only on `master` (`actions/cache/restore` everywhere, and
`actions/cache/save` under `if: github.ref == 'refs/heads/master'`, same pinned action version), so one pair exists. A branch then hits
master's entry and saves nothing; a branch that changes `install-llvm.sh` misses, installs and still saves nothing. Delete the
`lethal/r936` pair once the change lands.
