**What.** `scripts/tsconfig.json` lists its files explicitly, and the grammar cross-check harness
`scripts/probe-grammar-crosscheck.ts` is not in the list. Its logic module
`scripts/lib/grammar-crosscheck.ts` is (GH-06 Task 3 added it, because `probe-grammar-corpus.ts`
imports it). So `bun run typecheck` checks the module but not its main caller. Measured (GH-06 Task
3, fix round 1): changing `splitArgs`'s return shape, a field only the harness reads, leaves
typecheck green.

**Why it is not a one-line fix.** Adding the harness also needs `corpus-fingerprint.ts` and
`lib/al-kind-mapping.ts` in the list (mechanical), and then fails with `TS7016` on the harness's
deep import of `web-tree-sitter/tree-sitter.js`. That import is deliberate: its comment says it
keeps `scripts/` from taking a direct `web-tree-sitter` dependency. Closing this needs a choice:
a declaration shim for that path, or importing through `packages/engine`.

**Who it hurts.** Whoever next bumps the grammar and runs the harness (the vendor README uses it).
A type break shows up as a runtime crash of a hand-run script, not at typecheck. The harness is not
a gate, so no verdict depends on it.

**Evidence.** GH-06 Task 3 report, fix round 1 (branch `lethal/lane-bugs`).
