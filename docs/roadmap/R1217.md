**Found by** PR-435 (lethal-code, 2026-11-25), measured on c5's events. Evidence: `/coord/handoff/PR-435/findings.md`.
The figures are shares, because c5 ran under load.

- **What was measured:**
  - c5's baseline phase took 1,627.8 s of a 23,860.6 s run (6.8%).
  - All 104 baseline serve requests ran on lane 0, one after another (1,403.0 s; al-runner inside them: compile
    413.8 s, coverage 431.0 s, tests 97.1 s).
  - The 12 R951 cross-check one-shots (997.1 s) overlapped them (PR-119). The other lanes were idle for the whole
    phase.
- **The lever:** spread `fillDaemonBaseline`'s requests over the lanes' daemons. At 5 lanes the bound is about 4-5% of
  the run's wall. Each extra lane pays a first daemon start, which the bound does not yet subtract.
- **Design to start from:** R1190's parked r2 (`docs/superpowers/specs/2026-11-25-pr434-per-test-baseline-spread.md`)
  was written for the per-test fill, and most of it transfers:
  - one tree for every baseline daemon;
  - kept-form outcomes only;
  - PR-98's admission after lane 0's first answer;
  - in-flight-safe closes and ordered throws;
  - per-lane samples and a laned gate leg.
  The whole-codeunit fill adds PR-115's batching and PR-119's concurrent samples, which the spread must keep.
- **Why this is new:** R1190 was parked because DO's MAIN baseline is session-isolated and never takes the per-test
  path. This item is that same main baseline's own one-lane cost.
- **Related:** R1190, PR-434, PR-115, PR-119, R951, R1216.
