**Coord task R-788 (owner request, 2026-10-25).** Related: [[R635]], [[R761]], [[R777]], [[R784]].

**What.** `itest:alrunner-v3` ran every leg on one-shot unless `LETHAL_ITEST_V3_TRANSPORT` was set (`v3ItestTransport`
returns `{}`), so the gate got none of the serve-mode speed-ups. D1 (532 s), D1c (462 s) and T (161 s) were 84% of a
22 min 56 s update-gate run (`--regate a0b6e49c`, 16:44-17:07Z, current `edge-dcdf9e821`), and an al-runner switch is
two or three gate runs.

**The transport per leg** (`V3_GATE_SERVE_LEGS`, `v3ItestLegTransport` in `packages/runner/itest/al-runner-v3-gate.ts`):

| Leg | Transport |
|---|---|
| D1, D1c, T | serve-entries (the users' default since R761) |
| S1E, N1E, N1S, O1 | serve-entries (as before, by construction) |
| K | the CLI's own default (serve-entries for sandbox-app since R761) |
| C, S1, S3, N1, X, L1, Y-A, Y-B, MO, WR | one-shot (S1, N1, MO and WR keep the one-shot path covered) |

`LETHAL_ITEST_V3_TRANSPORT`, when set, still names the transport for every flag-following leg, so `one-shot`
reproduces the old gate. D1, D1c and T print their `entries` counters and split line. A T baseline re-record
(`LETHAL_ITEST_RECORD_BASELINE=al-runner-v3.tables.baseline.json`) now records from a serve session unless
`LETHAL_ITEST_V3_TRANSPORT=one-shot` is set; the rows were measured identical on both transports.

**R777.** Changing a leg's transport changes what the update gate measures, so `current` is regated after the merge,
once, together with R-784 (leg O1) and the R-771 pin fix (orchestrator sequencing).

**Measured** (`/coord/handoff/R-788/observe.log`, current `edge-dcdf9e821`, against the one-shot a0b6e49c regate log):
D1 532 -> 32 s, D1c 462 -> 31 s, T 161 -> 30 s. Counts, per-mutant rows, D state notes, Sleep index, T's notes and
pinned rows, and the gate warnings are identical on both transports. Pre-commitment
`docs/superpowers/specs/2026-10-25-r788-serve-big-legs-precommitment.md` (master 1d6474bb).

**Pinned serve counters** (`assertServeCounters`): on each serve leg `pairRequests` equals the killed count (D1 and
D1c 51, T 290 on a pass) and `echoMismatches`, `pairFallbacks1`, `pairFallbacks2`, `pairBatchRefused` are 0. A held
T keeps its own outcome (the check runs only on a pass). Red-checked: D1 with 52 pre-committed reads GATE-FAIL
(`/coord/handoff/R-788/red-d1.log`).

**Proven** (`/coord/handoff/R-788/gate.log`, driver `gate.sh`): the full v3 gate (`TABLES=1`, CDO) on 9cd4ab8b (master
with R-784's O1 merged in), current `edge-dcdf9e821`, no other v3 job running, 19:14-19:19Z: every leg pass (O1
included), update-gate outcome `pass`, the pinned serve counters as pre-committed. Wall **331 s** (5 min 31 s), against
22 min 56 s for the one-shot `--regate a0b6e49c`; the sum of leg walls went from 1376 s to 327 s (D1 44 s, D1c 43 s,
T 38 s, under load 7-16).
