**Found by the R-302 run 002 review (2026-09-29), minor R2.** Split out of [[R330]], which is
closed, because open work belongs in an open item.

**What happens.** Tier 2 claims a record call like `R.SetRange(...)` only when the receiver's table
does not declare a procedure of that name itself (rule 3, `declaresProcedure` in
`packages/engine/src/semantic/receiver.ts`). That check reads the object's direct members and, since
[[R327]], a split member swallowed by the global `var` section. It does NOT read a procedure wrapped
whole in `#if ... #endif`. So a table that declares `SetRange` inside `#if` does not stop the claim.
The Tier-2 mutant (`remove-setrange`, say) then mislabels the site and, by precedence, displaces the
Tier-1 `void-method-call` there.

**Severity.** A mislabel, not a compile failure: the Tier-2 mutant deletes or changes a call that
exists either way, so the build still compiles. [[R330]]'s fail-safe covers the typed operators,
which could emit code that does not compile. This guard was left as it was, because changing it can
move Tier-2 counts that the R-302 addenda did not pre-commit.

**Fix direction.** Read the same list [[R330]] introduced (`allProcedureLikes`: every
procedure-like declaration of an object, wherever the grammar put it) in `declaresProcedure`, with
any arm's name counting, as for a split member. Pre-commit the corpus effect first, since it can
remove Tier-2 claims.

**Correction and closing (2026-09-29, R-302 run 003, `84f38b9f`; pre-committed in the plan's
addendum 3, `bc9ffa0f`).** The "Severity" paragraph above was wrong. The gap is not only a mislabel:
`validate-to-assign` relies on rule 3, and it rewrote a custom `R.Validate(N, 5)` (a `#if`-wrapped
table procedure) into `R.N := 5` where no field `N` exists. That fails `alc` with AL0132 in every
build (review R-302-002 r1, C2). It also happens on `master`.

Fixed:
- `declaresProcedure` reads every procedure-like declaration of the object (`allProcedureLikes`).
- Rule 3 also reads a table or `tableextension` wrapped whole in a `#if` object region
  (`SymbolTable.unindexedObjects`).

Three repros (the wrapped procedure, the wrapped table and the wrapped `tableextension`) each lose
exactly their `validate-to-assign`, and they now compile under every symbol subset. Each fix goes red
when it is reverted alone. It changes no COMMITTED corpus count. The full-BaseApp removals that
run 003 made are not split between this fix and [[R330]]'s run 003 fix. Every one was attributed
to an unindexed member, and none was measured for this fix alone.

**Qualified, then re-closed (run 004).** Review R-302-003 found that rule 3 still missed a case.
`Record 50101` (by number) named a table that was wrapped whole in `#if`, and a `tableextension`
extended it by NAME. The guard compared only the reference `"50101"`, so it never matched the
extension, and `validate-to-assign` could emit `R.N := 5` with no field `N` (AL0132).

**The fix.** It collects every spelling of the table before comparing extensions: the reference,
plus the name and id of every project table it matches, indexed or wrapped. That was chosen over
"treat a receiver of an unindexed table as unknown" because it is exact and removes no other site.

**The mirror case needed more than aliases.** A `tableextension ... extends 50101` (by number) is
valid AL that `alc` accepts, but the grammar does not parse it: the whole object becomes a root
ERROR node, which no structural check can read. So rule 3 also reads the TEXT of every unparsed
root object that starts with `table` or `tableextension`. If that text declares a procedure of the
call's name, the claim is refused.

**Repros.** There are five (numeric or named receiver, wrapped or indexed table, extension by name
or by number). The four that claimed before the fix emitted AL0132 on this branch and on `master`
alike. All five now compile under both subsets, and each fix goes red when reverted alone. Measured:
no count or key moves in any committed corpus, in all of BaseApp or in any fixture. The grammar
defect (`extends <number>` does not parse) is filed as [[R336]].

**Made conservative (run 005).** Review R-302-004 showed the run 004 text rule was a small parser
and missed two valid shapes: a comment between `procedure` and the name, and an extension wrapped
whole in `#if` (its ERROR node sits below the wrapper, not at the root). The fallback is now a
CONSERVATIVE check, not a parser. Any ERROR node, at any depth, that could be a table or
`tableextension` (the keyword as a token, or a table-like ancestor) and that holds the call's name as
an identifier token once `//` and `/* */` comments are stripped, refuses the claim. Over-refusal
costs one site; a wrong claim costs the build. Three repros (block comment, line comment, `#if`
wrapper) each emitted a `validate-to-assign` that failed `alc` before and compile after. Measured:
no count or key moves in any committed corpus, in all of BaseApp or in any fixture.
