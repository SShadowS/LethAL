**Found by** lethal-preproc on PR-479's forced leg 4 (2026-11-28; amendment 9 of
`docs/superpowers/specs/2026-11-28-pr479a-bcdev-client-driver.md`).

- **What:** after a client op, the backend joins the page's results with the declared methods both ways. A declared
  method with no result is `client-incomplete`: the op ended normally, but a method did not run. Page 130455 is read
  only in its first viewport (amendment 6), so this join is the only check that every method of a longer codeunit ran.
- **Never seen live:** forced leg 4 tried to make a method skip by setting its Run flag off beyond the first viewport.
  Measured on bcwin, the driver's set-up rebuilds every Run flag on before each op, so that fault cannot reach an op.
  The join is covered by a unit test only (the fake driver's `hidden-run-false` mode). The orchestrator ruled not to
  build a proxy just to force it.
- **Next:** when a real client run first ends `client-incomplete`, check by hand that the named method really did not
  run (the page's results, the attestation rows, the test codeunit), so the join is confirmed on live data once.
- **Related:** PR-479, R1244.
