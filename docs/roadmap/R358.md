**Found by the code lane closing R356 (2026-09-30).** Under `%TEMP%` there were 3,369
`lethal-alrunner-canary-*` directories (4.6 MB), and the count went from 3,369 to 3,377 during one
full `bun test` run. By date they grow on every day the suite ran since 2026-07-26 (340 on 09-26,
242 on 09-29). The canary code removes its directory in a `finally`, so the leak is likely a unit
test, or a path with a stubbed `rm` or an early return, that creates one and never reaches it.
Also measured then, not deleted: 682 `lethal-alrunner-cov-*` (22.8 MB, the R356 leak, now fixed)
and 91 `lethal-alrunner-contract-*` (0.1 MB).

**Not audited yet:** the other `mkdtemp` users outside `al-runner-*.ts` (`cli.ts`,
`campaign-freeze.ts`, `env-tool-session.ts`, `test-app-publish.ts`).

**To close.** Find which test or path creates a canary directory without removing it (run the
suite file by file and count), fix it, and add a guard that fails when a test file leaves a
`lethal-*` temp directory behind (for example an after-all check in the test preload). Audit the
other `mkdtemp` users the same way.
