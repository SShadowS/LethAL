**Filed 2026-10-11 by R-394** (`/coord/handoff/R-394/measure.md` §1).

**What.** The al-runner coverage guard (R298/R300, `applyAlRunnerCoverageGuard`) refuses coverage for a project
holding any `#if`-wrapped object of a shape it does not admit. 42 refused files in 12 BC.History projects wrap a
single CODE-FREE object: an enum, interface, permission set, control add-in, dotnet block or enumextension inside
`#if not ...`. Such an object has no lines al-runner reports, so it cannot misplace coverage. Yet each one turns
coverage off for the whole project.
- Together with [[R579]], admitting these would cut BC.History's coverage-off set from 15 projects to 2: BaseApp
  and EU 3-Party Trade Purchase, the only two with code-bearing nested wrappers ([[R535]]).
- CDO, DC and DO are not affected.

**To close.** Admit a wrapped file whose objects are all code-free (`alRunnerAdmitsWrappedFile`). Test each kind.
Re-measure which projects keep coverage on.

**Since R654 (2026-10-23).** `applyAlRunnerCoverageGuard` was the .NET al-runner's guard and was deleted with it in
R654 S3 (35f3c67f). The same wrapped-file rule (`fileHoldsWrappedObject` and `alRunnerAdmitsWrappedFile`, in
`line-map.ts`) now feeds `alRunnerCoverageSupport`, which turns the Rust al-runner's coverage off
(`al-runner-v3-coverage-off`). So this item now applies to `al-runner-v3`. One more limit there: on v3 ANY
multi-object file also turns coverage off, and an admitted wrapped file is still refused whole ([[R602]]). So fixing
this item alone does not give these projects coverage on v3 until R602 is measured. The BC.History counts above are
from the v2 guard and need re-measuring under `alRunnerCoverageSupport`.

## Done by R-579

`alRunnerAdmitsWrappedFile` also admits a file whose every wrapped object (all wrappers, arms and nested wrappers) is
a `CODE_FREE_KINDS` object holding no code, with no bare top-level object and at least one such object. Several
code-free wrappers in one file are admitted. `enumextension`, `controladdin` and `dotnet` joined `CODE_FREE_KINDS`
(see [[R383]], section "R-579"). Result (post-build census, `BC.History.json`): 3 of 258 BC.History source projects are
off (Base Application, E-Document Core, EU 3-Party Trade Purchase, all code-bearing), down from 14, together with
[[R579]]. CDO, DC and DO were 0 before and after.
