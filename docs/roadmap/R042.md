**Instrumentation multiplies ONE existing diagnostic ~18×, and introduces none.** Measured on Continia Document Output, same symbols and compiler, baseline vs instrumented: **201 → 2,995 warnings**, but the composition is the finding — **zero warning IDs appear that the baseline did not already have, and zero are lost**. Exactly one multiplies: `AL0432` (deprecated member) 167 → 2,961 (×17.7). `AL0920`, `AL0729`, `AL0749`, `AL0254`, `AL0685`, `AL0468`, `AL0482`, `AL0523` are all ×1.0. The cause is structural rather than app-specific: `AL0432` fires per OCCURRENCE, and the wrap-lift-duplicate emission repeats each guarded statement once per mutant, so a deprecated call inside a mutated site is re-reported per branch. **Consequence: the extra warnings are provably signal-free** — they say nothing the developer's own baseline build does not already say. A plain build is unaffected (alc does not fail on warnings; the instrumented DO artifact compiled with 0 errors). What remains is (a) noise, and (b) a real break for a project wired to warnings-as-errors or a CI warning budget. Suppressing `AL0432` on the instrumented compile would be SAFE by this measurement but trades away the ability to notice if instrumentation ever did introduce one, so it is deliberately not done unquestioned — the documented rule is **compare warning counts against a baseline compile, never against zero**. Re-measure with `docs/measurements/` style if the emission shape changes.
