Found by coord task R-932 (2026-11-12, BC.History batch 6 on v3). Evidence: `/coord/handoff/R-932/findings.md`, `dn-excel-*.json`,
`dn-crypto-*.json`. Related: [[R900]] (the probing paths, alc only by design), [[R936]] (the first measurement, which found no win). The same gap as [[R941]] (Sustainability: Newtonsoft.Json); this item
records the fix for both.

**What.** `assemblyProbingPaths` (config, `.vscode/settings.json` or `./.netpackages`, R900) reach alc only. al-runner's own
`--dotnet-assembly-dir` is not set, so its .NET helper finds only the runtime's assemblies, and a test that creates a type from a BC
service folder's DLL is refused (`DotNet new ...: assembly '...' could not be loaded`).

**Measured** (al-runner edge-42af5d384, the module's whole test app, run directly with and without
`--dotnet-assembly-dir /coord/cache/bc28-service-windows`):
- Edit in Excel: 6 pass without, **11** with (the Office integration assemblies load; the rest stop on a `Dictionary` member gap).
- Cryptography Management: 44 pass without, **53** with (`System.Security.Cryptography.Xml` loads; one test then fails).
- Performance Profiler (R-928, [[R936]]): Newtonsoft loads, but its tests stop on the next refusal: no win there.

**Fixed (coord R-933, 450c1d83).** With a .NET sidecar, every resolved probing path reaches al-runner as its own
`--dotnet-assembly-dir` (measured: the flag repeats and searches every folder; a comma-joined value is not split), absolute, in
order, on one-shot and serve calls, baseline and mutant alike. The paths were already in the resume fingerprint and the test-app
cache key. Pre-commitment 4614445e; results `/coord/handoff/R-933/results.md`. Sustainability (40 mutants, the baseline's 526
tests): exactly the 4 `Sustainability API Tests` moved, from the Newtonsoft load error to a separate refusal (`Api Web Service`
has no provider; [[R941]]'s "separate refusal"); a second before-run agreed with the first on every test; the 40 verdicts are
identical. No gate figure moves (no fixture has probing paths).

**To build.** Pass the resolved probing paths to al-runner as `--dotnet-assembly-dir` (one per folder, if it takes several), on the
one-shot and serve paths, with the paths in the resume fingerprint as for alc. Check first that a type loading changes no verdict
that the gates pin (a v3 gate leg with a DotNet fixture, if any); measure an app's baseline before and after.
