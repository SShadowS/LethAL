**Why this family.** After #7854 (family 4), the ledger's largest open issue is #7819 (541 sightings), but its 20 causes are
unrelated, and its largest group (system-table read permission) is family 4's. The next is #8028: 429 sightings over six causes,
all "... in a session without a client (--no-client): what BC does there is not pinned". LethAL runs al-runner with
`--no-client` because BC's web-service path, where LethAL runs tests on BC, has no client.

**What was built.** `scripts/refusal-family.ts`:
- family `no-client`: one cell per call that asks the client something or shows UI (`CurrentClientType`, `DefaultClientType`,
  `GuiAllowed`, `Confirm`, `Message`, `StrMenu`, `Dialog.Open`, `Page.Run` with and without a record, `Page.RunModal`,
  `TestPage.OpenView`, `Report.Run`, `Report.RunModal`, `Report.RunRequestPage`, a `ReportHandler`, `Notification.Send`,
  `Hyperlink`), with its handler bound and without;
- `Cell.handlers` (whole handler procedures, bound with `[HandlerFunctions]`), `Family.args` (al-runner arguments), and no
  `var` block for a cell that declares nothing;
- `--emit-bc-check <dir>`: a family's app under its own id and name, for a BC run (`bcCheckApp`, `bcCheckFamily`).

**Result on edge-5a58a0f16** (28 cells): 7 pass, 11 fail, 10 refused.
- Refused, known to #8028: `CurrentClientType`, `Page.Run` with a record, `Page.RunModal`, a request page with a handler bound.
- Refused, NEW: `Report.RunRequestPage` (with or without a handler). It passes without `--no-client`.
- Failing, al-runner's own answer: `Confirm`, `StrMenu` and `Page.Run` of a page id fail with the platform's client-callback
  error even with their handler bound; `Message`, `Notification.Send` and `Hyperlink` with a handler bound fail with "The
  following UI handlers were not executed". BC's answer in a session without a client is not measured.
- Measured already, and different (review): `TestPage.OpenView` passes on al-runner under `--no-client`, but on BC's
  web-service path any `TestPage` fails with `NotSupportedException ... NavSession.CreateNavTestService()` ([[R69]], measured
  2026-07-31). A handler that takes a `TestPage` or `TestRequestPage` may meet the same refusal on BC (inferred). Reported:
  https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8028#issuecomment-6893463973.
- Upstream: https://github.com/aldevtools/BusinessCentral.AL.Runner/issues/8028#issuecomment-6893410659 (the new refusal with an
  invented repro, and the handler question).
- Regression set: `u8028-run-request-page` (run with `--no-client`, expected pass, inferred); still refused. 100 tests: 0 flipped,
  0 regressed, 66 still differ.

**BC-check apps (task part 2).** Every generated cell's BC answer is inferred today, except `TestPage.OpenView` (above). `/coord/handoff/PR-17/bc-check/` holds one
invented app per family (untouched-handle 59 cells, dotnet-no-object 29, platform-table-read 376, permission-denial 332,
no-client 28), each with its own app id. Each compiles with the Linux `alc` 18.1 against the bc2 server's own System symbols (plus
Permissions Mock): 0 errors, warnings only. Its README says how to run them and what to compare. lethal-bugs runs them on BC
under its standing approval; lethal-code published nothing.
