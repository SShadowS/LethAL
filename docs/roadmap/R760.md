**Filed 2026-10-25 by lethal-preproc (coord task R-760, an owner request).** Measured, nothing changed. Findings
and evidence paths: `docs/measurements/2026-10-25-r760-v3-time.md` (opus-reviewed); raw data under
`/coord/handoff/R-760/`.

**What.** The owner expected one test to take milliseconds, and it does: 0.01-0.03 s per call. But with the default
one-shot transport, each of D1's 166 al-runner calls takes about 3.3-3.7 s. The calls are 1 baseline, 63 mutants,
and a confirm plus R577's reproduction per kill. Each call spends about:
- 1.8 s recompiling the 555-file instrumented project (a new selector file per mutant);
- 0.95 s reading the dependency compile cache;
- 0.8 s writing coverage.

LethAL also spends about 0.36 s between calls (very likely `assertBound`'s re-hash).

| part of D1's 667 s | share |
|---|---|
| project compile | ≈ 41% |
| dependency-cache read | ≈ 21% |
| coverage | ≈ 19% |
| between calls | ≈ 9% |
| alc proof compiles | ≈ 3% |
| the tests | < 1% |

serve-entries pays the compile and the dependency read once per daemon: D1 193 s, with 0 differences. Gift card:
19.2 s one-shot (the contract probe is about 45% of it), 12.8 s serve, 20.6 s on bcdev. Today's absolute times are
1.4-2.3 times R-653's on the same slice, likely machine load, so read the proportions.

**To close (for a ruling, not built).**
- (A) serve-entries as the campaign default (blockers: R722 #5798, and the MO and WR legs' one-shot
  pre-commitment);
- (B) a cheaper per-kill confirm and reproduction in one-shot (≈ 190 s; touches R577);
- (C) cache `assertBound`'s hashes (≈ 55 s one-shot);
- (D) upstream, incremental workspace compile and a cheaper dependency-cache read for one-shot users (repro in the
  findings).
