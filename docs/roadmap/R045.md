**The baseline runs the WHOLE test suite, so `--only` narrows cost by far less than it appears to.** Measured on the first live Document Output run: total 1065 s = generate 0.7 s + deploy 40.8 s + **baseline 863.8 s (81%)** + mutants 151.9 s + overhead 8.5 s. `--only` (R41) scoped the run to 163 mutant sites in one codeunit out of 551 files, but the baseline still executed all **1,246** discovered tests once, because narrowing selects MUTANTS, not TESTS. Two consequences. Cost: a narrowed first run on a real project is dominated by a phase the narrowing does not touch, so "run one codeunit to try it out" is nearly as expensive as running far more. Risk: baseline duration is also the exposure window for R44's proxy timeout — the run that quarantined did so during baseline. A `--tests-only <glob>` (or reusing the covering-test set from a prior run) would cut both. Note a subtlety: narrowing the test set CHANGES coverage attribution and therefore verdicts, so it is not a free optimisation and must not be compared against an unnarrowed baseline as though it were. Evidence: `docs/benchmarks/runs.jsonl`, `SessionReport.timings`.
