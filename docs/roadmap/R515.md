**Priority.** Filed 2026-10-08 by R514's build, from decision (3) of the R-514 plan (r2,
`docs/superpowers/plans/2026-10-08-R-514-reused-baseline-confirm.md`, option C). A cost and
verdict-quality gap, not a false-kill risk: [[R514]] already refuses every kill this item is about.

**What.** On a batch that reused a stored baseline (R192), [[R514]] confirms a position-1 `timeout`
by running the test once with no mutant, and scores the mutant `error` with cause
`reused-budget-stale` when that run takes more than half the budget. The confirm MEASURES the test's
duration today, but the measurement is thrown away: `budgetOf` in `runMutantsOnBackend` keeps reading
the reused snapshot's duration from `baselineDuration`. So every later mutant covered by the same
test pays the same cost again (a full budget to time out, plus one unmutated confirm) and ends
`error` again, where a budget set from today's duration would have given it a real verdict.

**Evidence.** The R514 tests in `packages/runner/tests/resume.test.ts` (describe "R514: a reused
baseline's durations set today's budgets"): in "R514 fixed (a), single path" every scored mutant
covered by `BSlow` ends `reused-budget-stale` with one confirm each, although the first confirm
already measured `BSlow` at 5000 ms.

**Proposed fix (option C).** Feed the confirm's measured duration back into later budgets for that
test, for the rest of the batch. It needs a duration map that can change during the mutant loop and
is shared across worker shards (`executeCovering`), and a rule for which measurement wins (the
largest seen is the safe direction for a budget). It changes no false-kill behaviour: [[R514]]'s 2x
rule still decides every kill.

**To close.** An offline test: a reused batch, a test slower today, two mutants covered by it; the
second mutant's budget is set from the first confirm's duration and it gets a real verdict. Red-check
it against the unchanged map.
