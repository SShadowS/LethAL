**Found by the opus review of coord task R-327b (2026-10-24); not probed.** [[R720]] and [[R721]] showed that
`resolveVarRef` returns null both for a name that is provably undeclared and for one the engine refuses to resolve
("unknown"):
- a member swallowed into the global var section;
- a global declared inside a var-section `#if`;
- an every-arm-ambiguous name (R302).

R720 fixed `classifyHangCapable` by asking `declarationStateAt`, which tells the two apart. Other readers in
`packages/builtin-tier1/src/loop-hazard.ts` still read null as "absent", and their direction is unknown:

1. **The r531 write collectors** (`r531Implicit`, and the two collectors that push a write when `key === ""` or
   `recvs.has("")` and `resolveVarRef(left, ctx) === null`).
   - These take a bare unresolved name to be a field of the implicit `Rec`.
   - Where the name is really an "unknown" local or global, a write to it may be counted as a `Rec` field move, which
     can make a loop look like it advances.
   - Or, through the same mix-up, a real `Rec` move may be missed.
   - Which of the two can decline a hang refusal has not been worked out.
   - The R696 collector built on the same rule has the same question.
2. **R572's var-out flag** (`r572LoopRows`). An argument handed by `var` counts as a loop flag only when
   `resolveVarRef(a, ctx)` finds a declaration of a simple type. An "unknown" flag returns early, so the call is not
   recorded as feeding the loop. That is the decline direction: a loop fed by another object's stateful procedure
   through such a flag may not be refused.

**To close.** For each reader, build the three R720 shapes (scripts/fixtures/r402/w4/w5/w7 are the templates) with the
reader's own loop pattern. See whether a hang-capable site deploys. Where it does, use `declarationStateAt` the way
R720 did (an "unknown" name refuses, or counts by name), test-first, and red-check in each direction. R-327b's corpus
diff found 0 deployed changes for the `classifyHangCapable` fix, so the reach here is likely small, but it is
unmeasured.

**Done 2026-10-24 by R-725 (lethal-preproc).** Tests: `r725-unknown-readers.test.ts`. Each reader's own loop shape was
built with a declared control and the three unknown forms (offline, R164):

| reader | var-section `#if` global | every-arm-ambiguous | swallowed member | verdict |
|---|---|---|---|---|
| R572 var-out flag | missed | missed | missed | **real**: the stateful callee feeding the flag was emitted |
| R696, unknown SECOND variable | missed | missed | refused | **real**: `r696Table` returned no table, so no mover |
| R696, unknown WALKED variable | missed | missed | refused | **real**: the walk was skipped |
| R531 consuming loop (the write collectors) | refused | refused | refused | safe: an unresolved bare name counts as a `Rec` field, which only refuses MORE |

- **The fix,** fail-closed as R720, behind `r725Seam`:
  - `r696Table` gives a receiver whose declaration is "unknown" (`declarationStateAt`) a wildcard table that matches
    every table (`sameTable`), so it can be the walked record or a mover, and its keys are "all". It still needs a key
    write to move a walk (twin test).
  - R572 counts an "unknown" var-out argument as a flag.
  - From the opus build review: `r696Writes` reads an "unknown" `R2 := X` both as R2's whole-record write and as an
    implicit-Rec field write; R572's statefulness check no longer takes an "unknown" local (which `r531Declares`
    reads by text) for a simple-type variable; R530's `selfInserts` counts an Insert on an "unknown" receiver;
    `r696Inserts` matches the wildcard (its own test). Each has a test that went red before the fix.
- **Note:** `declarationStateAt` answers "unknown" for EVERY name in an XMLport, query or enum (the engine indexes
  codeunits, tables, pages and reports only), so there these readers refuse more. Fail-closed, and it costs 0.
- **Left open:** an "unknown" CALLEE receiver is never followed at all (`declaredType` skips preprocessor nodes).
  Filed as [[R734]]. The swallowed-member R696 rows were already refused by R696 itself, through `declaredType`'s
  text fallback.
- **Cost by parse** (`scripts/r725/cost.ts`, `/coord/handoff/R-725/cost/`): 0 specs on BaseApp, DC, DO and CDO.
