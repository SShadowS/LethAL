**Filed 2026-10-24 by R-586c (lethal-bugs).** Evidence: `/coord/handoff/R-586c/design.md` section 7 item 4; the alpha.5 gate log
`/work/tools/al-runner-v3/failed/v3.0.0-alpha.5@6eddda0bc744b5397dc11c5edc34fc841d065e47/gate.log`.

**What is wrong.** The per-build pin ([[R586]], `packages/runner/itest/al-runner-v3-pins.ts`, moved to `src/` by R719) lets the update gate accept alpha.5's
seven known readings. The pin is used by the gate only. A normal session on alpha.5 still runs the contract probe's `status()`
check, which prints six `al-runner-v3-defect-gone` lines and one `al-runner-v3-defect-refused` line (for `none-selected-exit`,
`quoted-name-unselectable`, `refusal-cascade`, `sleep-is-noop`, `upstream-compile-errors`, `refusal-row-shape`, and
`duplicate-key-insert-raises`) every time. They are warnings, never refusals, and the pin has already read each one.

**What to do.** Let the session-time check (`v3DefectWarnings` in `al-runner-v3-contract.ts`) ask the pin table whether the fact
reads exactly as pinned, and print nothing (or one summary line) for those. A fact that does not read as pinned keeps its warning.
Keep it a separate change: the session-time check and the gate must not drift, so the pin lookup has to be the same function.
