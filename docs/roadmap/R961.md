Found by lethal-code, 2026-11-13 (coord R-942, Continia Document Output x its Test app, al-runner v3 edge-2bd87774f, master 81c59409,
`alRunnerV3.license` set). Related: [[R866]], [[R890]], [[R896]], [[R921]], [[R955]], [[R956]].

**What happened.** The fresh window 1 (with the license) was SIGKILLed by the container's OOM killer 2 h 27 min into its baseline,
at a 30.8 GB peak (its tree's RSS; the cgroup recorded `oom_kill 1`). A diagnosis run with `--time-budget 1200` (R955 stopped it in the
baseline and wrote the report, `/coord/handoff/R-942/df.*`) shows why:
- **Per-codeunit one-shot baseline.** The baseline ran `al-runner test --output-json --isolation test --codeunit <id>` one codeunit at
  a time, each a fresh process of about 2-3.3 GB taking about 45-70 s (each re-loads the whole app): 264 of 1,979 tests in 1,142 s,
  about 2.4 h for the suite. No serve daemon. One plain `al-runner test` process (default isolation, the same license) runs the
  whole suite in 14 s.
- **Cascade refusals under `--isolation test`.** 160 of the 264 were refused by cascade, "an earlier test of this codeunit, <test>,
  changed an isolated storage key or a number series", which is R890's refusal; under al-runner's default isolation those tests pass
  (1,805 of 1,979 green in the plain run). R896's `auto` then moves each such codeunit to `method` and re-baselines it one test per
  process (`fillIsolatedBaseline`, four at a time, about 3 GB each): the memory growth that ended in the OOM kill.

**Why it matters.** A real ISV test app cannot get through LethAL's v3 baseline in a working day, and the attempt can OOM-kill other
lanes' jobs. The verdict machinery is not wrong (refused tests are not scored), but no mutant is ever reached.

**To decide.** The cheap shapes, in order of effort: (1) run the baseline on serve, one daemon for the suite, instead of one process
per codeunit (why serve was not used here is the first thing to find: the slice of 38 tests did use a daemon); (2) run `method`
codeunits as per-test requests to that daemon (`--isolation codeunit` per request) instead of one process per test (R866's own
ponytail note); (3) a memory guard inside LethAL (stop scheduling new processes above a bound, report why), since an external watchdog
is what kept the diagnosis safe. Measure each on DO's slice and on the full baseline under a watchdog.
