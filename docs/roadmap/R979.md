Found by coord task R-962 (2026-11-13), BC.History batch 10 on al-runner edge-c8fe56e05 (`/coord/handoff/R-962/findings.md`).
Related: [[R083]] (`InherentPermissions` as a mutation target), [[R001]].

**What happens.** Microsoft's No. Series tests narrow the session with `Permissions Mock.SetExactPermissionSet('No. Series Test')`.
An exact set denies every object it does not list, codeunit Execute included. The instrumented No. Series code calls LethAL's
injected Mutation Selector, which no set lists, so 35 of the 90 tests fail at baseline with "Sorry, the current permissions
prevented the action. (CodeUnit <id> Mutation Selector Execute: No. Series)". A failing baseline test is dropped, so every mutant
those 35 tests cover loses them. This is LethAL's doing: the unmutated app passes them.

**Measured (al-runner, invented repro `/coord/handoff/R-962/repro-perm/`).** Under `SetExactPermissionSet` of a set that grants
the calling codeunit but not the called one, the call fails with that exact message; the same call to a codeunit that declares
`InherentPermissions = X;` passes. With `Permissions Mock.Set` (not exact) both pass.

**Not measured.** BC's behaviour under an exact set. R083 found deleting `InherentPermissions = X` from a codeunit to be a no-op on
Cronus281, but not under an exact set, so it does not decide this. Microsoft's own permission sets list their codeunits, which
suggests BC does check Execute there.

**Fix.** Emit `InherentPermissions = X;` on every codeunit LethAL injects that instrumented code calls (the Mutation Selector, and
the static selector with it: `emitMutationSelector` and `emitStaticSelector` must keep the same shape), then re-run No. Series on v3
and prove the bcdev gates unmoved.
