Found by coord task R-962 (2026-11-13), BC.History batch 10 on al-runner edge-c8fe56e05 (`/coord/handoff/R-962/findings.md`).
Related: [[R083]] (`InherentPermissions` as a mutation target), [[R001]].

**What happens.** Microsoft's No. Series tests narrow the session with `Permissions Mock.SetExactPermissionSet('No. Series Test')`.
An exact set denies every object it does not list, codeunit Execute included. The instrumented No. Series code calls LethAL's
injected Mutation Selector, which no set lists, so 35 of the 90 tests fail at baseline with "Sorry, the current permissions
prevented the action. (CodeUnit <id> Mutation Selector Execute: No. Series)". A failing baseline test is dropped, so every mutant
those 35 tests cover loses them. This is LethAL's doing: the unmutated app passes them.

**Measured (al-runner, invented repro `/coord/handoff/R-962/repro-perm/`).** Under `SetExactPermissionSet` of a set that grants
the calling codeunit but not the called one, the call fails with that exact message; the same call to a codeunit that declares
`InherentPermissions = X;` passes. With `Permissions Mock.Set` (not exact) both pass.

**Measured on BC (coord task R-968, 2026-11-14, bc1, BC 28.4 W1).** One invented probe app (owner-approved, published, run
through `LethALControl_RunMutant`, then uninstalled and unpublished; `/coord/handoff/R-968/state.md`), under
`SetExactPermissionSet` of a set that lists only one codeunit: an unlisted plain codeunit is DENIED Execute with the same message;
the same codeunit with `InherentPermissions = X` runs; a codeunit with the property calling an unlisted plain one is still denied.
al-runner edge-847b1fa5a gives the same answer for every case on the same app, so this is BC's behaviour, not an al-runner one.

**Fix (R-968).** `emitMutationSelector`, `emitStaticSelector` and `emitResourceSelector` each emit `InherentPermissions = X;`
(`SELECTOR_INHERENT_PERMISSIONS`); red both ways in `selector.test.ts`. The five fixtures' selector pins and R307's digest moved by
that line only.

**What it does NOT recover.** No. Series on v3 went from 39 to 40 green tests, not the 74 the pre-commitment predicted (36bd0a70; the
prediction is recorded as failed): 47 of the tests fail one step later on Microsoft's own "No. Series - Setup", which declares no
`InherentPermissions` and is called from code that does, the chain the BC probe shows denied on BC too. So those tests fail on BC as
well under that exact set; not a LethAL or al-runner difference.

**Still open on BC: R999.** On BC the selector calls LethAL Control's "LC Control State", which declares no `InherentPermissions`, so
that call is denied under an exact set even with this fix (the probe's chain, measured within one app). That needs a control app
change; R999 carries it into the batched control-app bump.
