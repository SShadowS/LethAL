**Filed 2026-11-27 by lethal-preproc, from PR-478's bc2 and bc3 proofs under LethAL Control 1.0.0.31.** Evidence:
`/coord/handoff/PR-478/prove/bc2/` and `prove/bc3/` (`run.log`, `bcdev.log`, `bcdev-rerun1.log`, `tables.log`); the
readers `/coord/handoff/PR-478/r1241-runs.ts` and `r1241-rows.ts`.

**What happened.** Both proofs ran at once in ONE worktree (`/work/lethal-wt/pr-478`), so both servers' gates wrote to
the same fixture stores (`fixtures/sandbox-app/lethal.sqlite`, `fixtures/sandbox-data/lethal.sqlite`).
- **bc3, `itest:bcdev`, 17:41Z:** `assertSessionLiveness` failed with `... (20 minus 0); got 8`. Verdicts matched, and no
  `session-reused` refusal fired. A re-run passed.
- **bc2, `itest:tables`, 18:14Z:** the same invariant failed with `... (459 minus 0); got 322`. Verdicts matched.

**The cause, measured from the stores** (which persist: they are the project's own store, not the deleted scratch dir).
- **sandbox-app store:**
  - run 2 (bc3's failed run, 17:41:43-17:42:20) has 20 grouped rows, **20 distinct ids**, 20 mutants;
  - run 3 (bc2's `itest:bcdev`) started at 17:41:53 in the same store;
  - no session id appears in two runs.
- **sandbox-data store:**
  - run 1 (bc2's failed tables run) has **459 distinct ids**, exactly its 459 grouped calls;
  - run 2 (bc3's tables run) started at 17:56:03 and was still running when bc2's check read the store.
- **The mechanism:** each itest takes its run id as `SELECT MAX(id) FROM runs`. That is `latestRunId` in
  `itest/kill-reproduction.ts` (used by bcdev, chunked and hang); tables, lend and test-app-publish inline the same query.
  - So the failing check read the OTHER server's run, part-written at that moment (8 of its 20, 322 of its 408 grouped
    rows).
  - **The guard did not fail open, no session id repeated, and 1.0.0.31 is not involved.**
- **Controls:**
  - three `itest:bcdev` runs on bc2 from a separate worktree (its own store) at load 173-253 all passed;
  - 20 sequential OData calls on bc3 got 20 distinct, rising ids.

**Why it matters beyond these two failures.** The same wrong run id feeds `killReproductionFailures` (R582) and the
liveness check. A gate whose run overlapped another server's in one store can therefore pass for the wrong reason: its
checks read another run's rows. A run checked while it was the newest read its own rows, and its result stands. The
overlaps are named per gate from `run.log` times.

**Rule (orchestrator ruling, 2026-11-27): never delete a store from a failed gate run.** The stores that settled this were
the persistent project stores. The itests' scratch dirs, which they delete in `finally`, held no results.

**The fix (to build):**
- each itest takes its own run's id from the session, never `MAX(id)`. The report or the session result can carry it, or
  the itest records `MAX(id)` before `runSession` and requires exactly one new run after it;
- a gate refuses to start while another live process holds the same fixture store, naming the other process;
- red-checked by two concurrent runs in one store.

**Operating rule until the fix (kept after it):** concurrent proofs on different servers each run in their OWN
worktree. Since PR-495, a second gate on the same fixture store is refused rather than corrupting the check; it is
not queued.

**The fix (coord PR-495, lethal-code, 2026-11-27).** `packages/runner/itest/fixture-store.ts`:
- **The hold, `holdFixtureStore`.** A gate takes it once, at the start of `main`: before both of its legs, and,
  for envtool, before the environment tool provisions anything.
  - It writes `<store>.itest-holder` (gitignored), complete to a temp file, then links it into place, so no
    reader sees it half-written. The file records the pid and, on Linux, the process start time from
    `/proc/<pid>/stat`.
  - A second gate is refused while the holder runs (`FixtureStoreHeldError`), naming its pid and, on Linux, its
    command line. The refusal says how to clear a stale holder.
  - A holder whose process is gone, or whose pid was reused (another start time), is taken over. The dead holder
    is renamed aside, which only one process can do, and deleted only if it is the one that was read.
  - An unreadable holder file is refused by name, never guessed at.
  - Release removes the file only if it still names this process.
- **The run's own id, `openFixtureStore`.** It runs per leg and refuses unless this process holds the store. The
  mark is the store's newest run id at open. `ownRunId()` requires exactly one run after it, so a run another
  writer added is refused by name, never read. That covers a writer the hold cannot see, such as a hand
  `lethal run` on the fixture.
- **Used by** the three gates on a fixture's shared store: `itest:bcdev`, `itest:tables`, `itest:envtool`. A
  static test fails if any `*.itest.ts` opens a fixture's store with `new ResultsStore(join(PROJECT_DIR, ...))`,
  or opens it without taking the hold.
- **`assertKillsReproduced`** now takes the run id from its caller. The scratch-store gates pass `latestRunId`,
  which is right for a process-private `mkdtemp` store and is documented as only for one. Those gates are
  bcdev-names, bcdev-wrapped, harden, verify, verify-agreement, verify-scale and testapp; chunked, hang and lend
  are scratch stores too.
- **Red-checked** (`itest/fixture-store.test.ts`, 9 tests), each guard broken then restored. Each break turns
  its test red:
  - the live-holder refusal;
  - a dead pid read as alive;
  - the start-time comparison;
  - an unreadable holder taken over;
  - release without its pid check;
  - open without the hold;
  - a gate that skips the hold (the static test);
  - `ownRunId()` reading `MAX(id)` or without its mark: the two-concurrent-runs test (both orders: the other run
    written before and after this gate's) and the one-own-run, two-legs test.
- **Live check, bc3, 2026-11-27 20:58Z** (BC 28.4, LethAL Control 1.0.0.31, the build preproc was proving
  there; this branch pins 1.0.0.30). Evidence: `/coord/handoff/PR-495/live-bc3/`.
  - Gate A (`itest:bcdev`) took the hold.
  - Gate B, the same gate started in the same worktree, was refused 2 s later, naming A's pid and command line,
    before it reached its session. It exited 1.
  - A then passed in full: verdicts, per-mutant baseline, liveness and the protocol probes.
  - The holder file was gone afterwards. Doctor showed ok before and after.
