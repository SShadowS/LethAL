**Found by R-318 (2026-09-29).** Not a LethAL defect. Upstream issue:
https://github.com/StefanMaron/BusinessCentral.AL.Runner/issues/4990 (it references upstream #2754).

**What happens.** Run one byte-identical app and test-app pair under one `--define` set, then under
another. al-runner reuses the FIRST build. On al-runner v2.12.0 a probe compiled once with no
symbols, then run with `--define R318A`, failed with AL0132 (a procedure that only exists under
that symbol was "not found"). `--no-cache` compiles correctly every time. `--print-cache-key` prints
different keys for the two symbol sets on the target, so the stale entry is keyed somewhere else.
That was not isolated further.

**Narrowing.** It bites when the dependency's DECLARATIONS differ between symbol sets. A minimal
pair whose dependency declares one procedure under `#if FLAG` and another under `#else` fails with
AL0132 on the second run and passes with `--no-cache`. A pair whose dependency differs only in a
procedure BODY does not reproduce. That fits a cached symbol package of the dependency that is keyed
without the symbols.

**Why LethAL is safe.** Every instrumented target embeds a random artifact id, so its bytes, and the
pair's cache key, differ in every session. A tool or probe that runs one UNCHANGED pair under two
symbol sets is not protected and needs `--no-cache`. R318's own raw probes used it.
