## 1. The question

Today every mutant of an object wrapped in `#if ... #endif` reads `no-coverage` on every
attributing path, because nobody has measured where the compiled arm's lines are numbered from.
BC numbers coverage lines OBJECT-relative, with base "previous object's last line + 1" (first object:
base 1; measured, `LineMapEntry.baseLine` in `line-map.ts`). al-runner reports FILE lines (R383).
The open part: do the directive lines (`#if`, `#else`, `#endif`) and the inactive arm's text count?

## 3. Hypotheses

For a statement on FILE line L of object O, with `prev` = the last line (`}`) of the previous
COMPILED object in the same file (0 if none):

- **H1a** (original file lines; directive lines and disabled text count, and belong to the object
  that FOLLOWS them, like blank and comment lines do today): BC line = L - prev. al-runner: L (H1).
- **H1b** (today's `fileLineMapEntries` rule, as it would answer if the refusal were lifted: a
  wrapper is one unit, so an object after it is based at the `#endif` line + 1). Differs from H1a
  only for R.
- **H2** (directive lines removed, disabled text kept): H1 minus the directive lines between prev
  and L.
- **H3** (compiled text only: directive lines AND inactive-arm lines removed).
- **H4**: anything else, including no row at all, or a hit row outside the reached procedure.

Where two hypotheses give the same numbers for an object they are one class (written `H1a=H1b`).

## 6. Expected outcome (my prediction, committed now)

- **Fenced: H1a** for W1, E1, Q and R. Reason: BC's existing measured rule already gives leading
  comment and blank lines to the FOLLOWING object, and R-318 (2026-09-30, Cronus28) measured that a
  compiled `#if` arm inside an object is numbered by the file's own lines, inactive first arm
  included. Directive lines and disabled text are trivia like comments. The consequence that matters:
  for **R, today's line-map rule (H1b) is predicted WRONG by 11 lines** (the `#else`, the 9 inactive
  lines and the `#endif` belong to R, not to the wrapper), so lifting the refusal without changing
  `fileLineMapEntries` would name the wrong lines for an object after a wrapper. Confidence: high for
  W1/E1/Q, moderate for R.
- **bcdev line: same as Fenced**, or "unparsed".
- **Hub: HUB-A** for all six tests (a name-based path; the compiled symbols hold only the compiled arm).
- **al-runner one-shot and `--server`: H1** for W1, E1, Q, R (file lines of the original source);
  `--server` scopes `Hit`, `AElseHit`, `QIfHit`. Confidence: moderate (al-runner compiles with BC's
  own compiler, so positions should be original-file positions).

## 7. Decision rule

- **Rounds.** Two rounds per path (round 1, round 2), same apps, nothing republished between them.
- **Validity first.** The run is INVALID (measure nothing, find the cause) if any control reads other
  than its single class (C1 10/14/18, P 7/11/15 on every path), if any Reach test fails, if any Fence
  test fails with text other than `MEASURED ...`, or if a hit row lands in a `Miss` procedure under
  the class that otherwise fits.
- **A path is "consistent"** only if, in every round, every wrapped object (W1, E1, Q, and R as the
  after-wrapper case) fits EXACTLY ONE class (all three marker lines present, no hit row outside the
  reached procedure's span under that class), and the class is the same in both rounds. A path whose
  object fits zero classes (H4) or two is NOT consistent; it keeps refusing by name.
- **What gets scored.** A consistent path may score wrapped objects ONLY under its measured class, and
  only for the shapes measured here (one arm with namespace inside; two arms with the second compiled;
  wrapped in the middle; bare after a wrapper). A shape not measured keeps its refusal.
- **Hub** is consistent if all six tests read HUB-A in both rounds.
- **al-runner symbol fallback.** If either al-runner leg fails to compile the tests because W1/Q
  are missing (`AL0185`/`AL0118`/`AL0132`), al-runner did not read `app.json`'s symbols: record that,
  then run round `1D`/`2D` with `--define PROBESYM`, and classify those. It is then a finding by
  itself: a LethAL session passes only the CONFIG's symbols, so the plan must decide where the
  symbols come from before any al-runner path can score a wrapped object.
