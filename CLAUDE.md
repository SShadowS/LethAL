## The roadmap — `docs/roadmap/` is the record, `ROADMAP.md` is a generated index
Open work, measured-but-unclosed correctness risks, and known product gaps live **one item per file** in `docs/roadmap/R<nnn>.md` (zero-padded), each with a stable `R<n>` id, a `status` and an evidence pointer. Repo-root `ROADMAP.md` is a GENERATED index — never hand-edit it; `bun scripts/roadmap-index.ts` rebuilds it and `scripts/roadmap-index.test.ts` fails if the two disagree.
- **Reading:** the index answers "is this already filed?"; reading one item is reading its file.
- **Adding:** **file an item the moment you discover one** (a limitation you hit, a gap a real project would trip on) — write `docs/roadmap/R<nnn>.md`, then regenerate.
- **Closing:** mark `status` `done (<commit>)` as it lands, then regenerate. A row closed by a RULING rather than code may say `closed <date> — <the ruling>`; both count as closed, and a "how many are open" count must accept either. Session ledgers under `.superpowers/` are scratch; the roadmap is the durable record.
- **Re-check the next free id immediately before writing** (`ls docs/roadmap/`), because other sessions commit here concurrently and HEAD can move mid-session.
- Check it before starting new work: what you are about to build may already be filed, or blocked on something that is.

## Build / test loop (order matters — the dist trap bites every session)
0. `LLVM_BIN="C:/Program Files/LLVM/bin" bun scripts/build-native-parser.ts` (inside the kraken container `LLVM_BIN` is already set, to `/opt/llvm-23.1.2/bin`: run `bun scripts/build-native-parser.ts`) — on a fresh checkout or worktree, and after any change under `packages/engine/native/` (needs Rust stable (1.96 or newer) and clang/LLVM 23.1.2, installed on this machine; elsewhere `bash scripts/install-llvm.sh <platform-key>`). The unit tests parse through the addon, and the loader refuses a missing or stale one (`NativeParserMissingError`, `NativeParserStaleError`); there is no WASM fallback. The built `.node` is gitignored.
1. `bun run typecheck` — `tsc --build --force`. SEPARATE from tests; run explicitly.
2. `rm -rf packages/*/dist` — **AFTER typecheck, BEFORE any `bun test`**: `tsc --build` regenerates `packages/*/dist`, and its stale compiled `*.test.js` get picked up by `bun test` as phantom failures.
3. Run the unit suite as `bun scripts/verify.ts` (one package: `bun scripts/verify.ts <pkg>`), from the repo root. It does steps 1 and 2 first, then runs `bun test` with `CI=true`. The root `bunfig.toml` preloads `scripts/test-preload.ts`, which hides the real home directory from every test, and `real-home-guard.test.ts` fails if it did not load. Never a bare `bun test`: it does NOT type-check, and it lets a timed-out test write its snapshot under the NEXT test's name, while verify.ts refuses new snapshots and fails if any `.snap` changed. Add a snapshot on purpose with `bun test --update-snapshots <file>`. `CI=true bun test` runs the tests alone, after you did steps 1 and 2. verify kills and names any test file that runs over 180 s, and logs each run to `/coord/locks/verify-ledger.tsv` with how many other verifies overlapped it. (PostToolUse hooks clean dist after a typecheck and format touched `*.ts`; see `.claude/settings.json`.)
4. `bun run compile:fixtures` — offline `alc` compile of every `fixtures/*` AL project. Run it after touching ANY `.al` under `fixtures/`. Nothing else compiles them: LethAL publishes the target on every run but treats publishing the TEST APP as the user's own workflow, so a broken test fixture leaves the live gate measuring the previously published build (R56).
- `bun run mutate`: StrykerJS over our own TypeScript. Optional, never gates. **Read `docs/mutation-testing-ourselves.md` before reading a score.**
- Lint: `biome check .` is noisy (pre-existing debt). Run biome **only on files you touched**: `bunx biome check <paths>`.

## Conventions (enforced — CI will fail otherwise)
- No `!` non-null assertions (biome `noNonNullAssertion: error`). Destructure then check `undefined`.
- `exactOptionalPropertyTypes`: build optional props with `...(v !== undefined ? { k: v } : {})`.
- Typed error classes extend `Error` **directly**, never each other — `AlcCompileError` (deterministic alc rejection) vs `ArtifactPrepareError` (spawn/IO/hash/manifest) vs `DeploymentError`. Bisection reads ONLY `AlcCompileError` as "subset does not compile"; anything else aborts. Preserve this separation.
- Fail loudly on caller-contract violations (bad artifact-id, corrupt manifest, echo mismatch) — throw, never return a plausible empty default. Empty-vs-empty "matches" is this project's signature bug.
- Generated AL: web-service `ObjectType` exactly `CodeUnit` (capital U). `emitMutationSelector` and `emitStaticSelector` must expose the identical procedure set. Artifact id: 32 lowercase hex, random per artifact.
- Assert phase ordering with call counters on stateful fakes, never wall-clock timing.
- Adding a `SessionReport` field ripples, and several guards fail far from the change: `events.ts`, then `report-fold.ts`'s accumulator, then `report.ts`'s type/builder/banner, then `bun scripts/generate-schemas.ts`, then `tests/schemas.test.ts` (the pinned root-required list AND the older-reports expectation), then `bun test <file> --update-snapshots` for `report-equality`, then every committed sample report REGENERATED live, since `schemas.test.ts` asserts gift-card's validates. A new `Caveat` also needs `CAVEAT_INTERPRETATIONS` plus the counts in `interpretation.test.ts` and `report.test.ts`.

## The recurring hazard: "test passes for the wrong reason"
A test asserts the right thing but passes whether or not the code is correct. Reading the diff does not catch it; only mutation does. **Red-check every fix**: revert the specific fix, confirm the specific test goes red, restore — report both. Use the `mutation-red-checker` subagent. Gate on per-mutant equality, not aggregate counts.

## Committing a campaign report — this repo is PUBLIC
A `SessionReport` from a real project carries that project's AL source in every mutant's `originalText`/`mutatedText`. **Run `bun scripts/redact-campaign-report.ts <report.json>` BEFORE committing one**; `--check` exits 1 on an unredacted file and `scripts/redact-campaign-report.test.ts` asserts both committed reports stay clean. The ruling it implements: **filenames, paths, procedure names and test names are fine to publish; source code is not.** `killingTestFailure` is deliberately KEPT (callstacks are names and line numbers, and its text is the corpus `scripts/r121-classify-eval.ts` scores false-kill rules against). Redaction after a push changes only what a fresh clone sees, so redact first.
Re-freezing a stage: `campaign compare` REFUSES an uncommitted baseline (the pre-commitment rule in code, not a bug), and `freeze` will not overwrite `<stage>.report.json` on a per-mutant mismatch; it archives to `<stage>.mismatch.report.json`. To re-freeze deliberately: delete `<stage>.baseline.json`, re-run `freeze`, review the diff, commit. Coverage-mode refusals: the `measurement-campaign` skill.

## Environment
Git bash on Windows; use bash syntax with Windows paths. **Never `2>nul`** (creates undeletable files) — use `2>/dev/null`. Search a named directory. **Never put a password on a command line** (`curl -u user:pass`): it lands in the session transcript; read it from the config file inside a script.
